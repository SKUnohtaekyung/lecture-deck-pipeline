# 콘텐츠 초안 — 바이브코딩 강의덱 (입력 템플릿)

> 이 형식으로 슬라이드 내용을 채워 주시면 **HTML 웹덱으로 조립**합니다.
> **원칙: 콘텐츠·비유·멘트는 당신이 / 레이아웃·시각화·디자인은 스킬이.**
> 표 1행 = 슬라이드 1장. CSS·클래스명·시각화 형식은 몰라도 됩니다 — **화면에 올라갈 글과 강사 멘트만** 적어주세요.

---

## 읽고 시작해 (작성 규칙)

- **표 1행 = 슬라이드 1장.** 채우는 건 **① 슬라이드에 올라갈 글, ② 비유·멘트**까지. 레이아웃·차트·이미지는 스킬이 정합니다.
- **`본문 문구` = 슬라이드에 실제로 올라갈 글.** 이대로 화면에 얹힙니다. **핵심 한마디**만 크게.
- **`비유·멘트` = 강사가 말로 풀 부연 + 가벼운 농담.** 아이콘으로 종류를 표시합니다(아래 범례). 전부 다 채울 필요 없음 — 있는 것만.
- **실습 슬라이드 원칙(중요):** 완성된 프롬프트(요청문)를 `본문 문구`에 **그대로 주지 않습니다**(수강생 복붙 방지). 본문은 *무엇을 담아 써야 하는지*를 **유도**하고, 완성 예시는 `🗣`로만 둡니다 — 화면에서는 **접힌 힌트**로 들어가 "막힐 때만" 펼쳐집니다.
- **톤 원칙:** 한 장에 개념 하나 / 쉬운 말 / 겁주지 않기 / 가끔 웃기기. 대상은 40~50대 초보자입니다.

### 아이콘 범례 — `비유·멘트` 칸에 표시

| 아이콘 | 뜻 | 덱에서 어떻게 처리되나 |
|---|---|---|
| `💬` | 강사 농담·애드리브 | **발표자 노트로** 빠짐 — 화면엔 안 보이고, 별도 발표자 노트 HTML에 정리 |
| `👀` | 강사 시연·관찰 유도 장면 | **발표자 노트로** 빠짐 — 화면엔 안 보임 |
| `🗣` | (막힐 때만 보여줄) 완성 요청문 예시 | **화면에 접힌 힌트로** — 클릭하면 펼쳐짐. 발표자 노트에도 정리 |

> 아이콘 없는 일반 멘트는 발표자 노트로 정리됩니다. 한 칸에 아이콘이 여러 개 섞여도 됩니다(각각 알맞게 처리).

## 0. 덱 기본 정보 (한 번만)

| 항목 | 값 |
|---|---|
| 강의명 | *(미정이면 비워두세요)* |
| 주차 / 회차 | (예: 1주차) |
| 발표자 | *(선택 — 표지에 넣을 이름)* |
| 대상 | 40~50대 초보자 *(고정)* |
| 톤·용어 수준 | (예: 전문용어 최소·실생활 비유 적극) |

> **로고·브랜드**는 고정 자산(`kit/starter/logo.svg` V-마크 + "VIBECODING")이라 따로 적지 않아도 됩니다.
> **팀명은 넣지 않습니다** — 본문 슬라이드 우측 상단은 파트 진행률(`PART n/N`)로 자동 표시됩니다.

### 파트 구조 *(여기서는 비워두세요)*

교시(1~6)를 몇 개의 PART로 묶을지는 **조립 직전에 스킬이 확인 질문**합니다. 여기 미리 채우지 않아도 됩니다.
만약 원하는 묶음이 이미 있다면 아래에 적어주세요 — 그러면 그대로 씁니다.

| 파트 | 묶는 교시 | 제목 | 한 줄 설명 |
|---|---|---|---|
| PART 1 | | | |
| PART 2 | | | |
| … | | | |

> 파트를 나누면 각 파트 **맨 앞에 "파트 전환" 슬라이드가 자동으로** 들어갑니다. (파트 수 = 전환 슬라이드 수)

## 1. 슬라이드 내용 (교시별 표)

교시(또는 섹션)마다 아래 **4열 표**를 만들고, 슬라이드 수만큼 행을 추가합니다.

- **`#`** — 슬라이드 번호(예: `3-7` = 3교시 7번째). 순서·라벨로 씁니다.
- **`슬라이드 제목`** — 그 장의 제목. *(질문형·주제형이어도 그대로 씁니다 — 스킬이 결론형으로 고쳐 쓰지 않습니다.)*
- **`본문 문구`** — 화면에 올라갈 실제 글. `**굵게**`·`<br>`(줄바꿈) 그대로 반영됩니다.
- **`비유·멘트`** — 강사 멘트. 아이콘(💬/🗣/👀)으로 종류 표시. 비워도 됩니다.

```
# 3교시 · Codex로 폴더와 파일 다루기

| # | 슬라이드 제목 | 본문 문구 (슬라이드에 올라갈 글) | 비유·멘트 |
|---|---|---|---|
| 3-1 | (간지) 3교시 | **Codex로 폴더와 파일 다뤄보기** | |
| 3-7 | 실습 ③ 첫 파일 만들기 | Codex에게 **첫 파일 하나를 만들어 달라**고 요청합니다. | 🗣 요청문: "현재 폴더에 첫메모.txt 파일을 만들고, 첫 줄에 'Codex 첫 연습'이라고 써 주세요." |
| 3-9 | 허용창이 뜨면? | 연습 폴더 안 작업 → **확인하고 진행** | 💬 "낯선 팝업이라고 겁먹지 마세요." |
```

> `(간지)`·`(표지)`·`(마무리)` 같은 표시는 그 슬라이드가 고정 슬라이드(파트 전환·표지·마무리)임을 뜻합니다. 스킬이 알아서 해당 고정 레이아웃으로 배치합니다.

---

## 2. 작성 팁 (40~50대 대상)

- **한 줄에 개념 하나.** 본문 문구는 크게 올라갈 핵심 한마디만. 부연은 `비유·멘트`로.
- **쉬운 말 + 친숙한 비유.** (예: 프롬프트 = 요청서, 폴더 = 서류철)
- **실습 완성 프롬프트는 `본문`이 아니라 `🗣`로.** 화면엔 접힌 힌트로만 노출돼 수강생이 스스로 써보게 유도합니다.
- **분량이 많은 장은 그대로 두세요.** 스킬이 수용량을 넘긴다고 판단하면 조립 전에 분할을 제안합니다 — 임의로 나누지 않습니다.
- **정보의 "모양"은 안 골라도 됩니다.** 스킬이 본문을 보고 비교·흐름·수치·관계 등을 판단해 레이아웃·차트를 자동으로 고릅니다.

---

## 3. (참고) 이 초안이 조립으로 이어지는 방식

1. **0번 기본 정보** → 표지·헤더(로고·주차·발표자) 자동 채움. 팀명 없음.
2. **교시 → PART** → 조립 직전 스킬이 묶음을 확인받고, 파트마다 전환 슬라이드 자동 삽입.
3. **각 슬라이드 본문의 "정보 모양"** → 스킬이 판단해 레이아웃·차트·다이어그램 결정(코드 시각화 우선).
4. **`💬`/`👀`** → 발표자 노트(화면 비노출) + 별도 발표자 노트 HTML. **`🗣`** → 화면 접힌 힌트 + 발표자 노트.
5. **슬라이드 결정표**(슬라이드별 정보 모양·PART·힌트 유무)를 먼저 보여드리고 **확인받은 뒤** 조립 → 브라우저 검증 → 배포.
