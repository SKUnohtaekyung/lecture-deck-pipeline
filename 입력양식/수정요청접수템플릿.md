# 수정요청 접수 템플릿 (P3 — 쪽번호 → ID 정규화)

> 왜: 쪽번호는 재구성마다 밀려 같은 「46p」가 시점마다 다른 슬라이드를 가리킨다
> (`plans/system-improvement/ANALYSIS.md` §2-기제4 — 오병합·확인불가 25%의 구조 원인).
> **사용자는 지금처럼 쪽번호로 말해도 된다 — 번역은 기계가 한다.**
> 접수자는 아래 절차대로 접수 시점의 쪽↔ID 매핑을 고정하고, **이후 처리·보고·검증은
> ID로만 지칭한다.**

## 접수 절차 (스크립트 1회 실행이 전부다)

1. 요청 원문을 `courses/<과목>/sessions/<주차>/개정이력/`에 그대로 저장한다(수정 금지).
2. 같은 폴더에 매핑 스냅샷을 만든다:
   ```
   python scripts/map_slide_pages.py <주차>
   ```
   같은 덱(sha 동일)이면 기존 스냅샷을 그대로 쓴다(멱등).
3. 이 템플릿을 복사해 아래를 채운다. 파일명: `<주차>_수정요청_<차수>_접수.md`.

---

## 머리 (필수)

| 항목 | 값 |
|---|---|
| 접수일 | YYYY-MM-DD |
| 요청 원문 파일 | `개정이력/<원문 파일명>` |
| 기준 덱 | `강의덱.html` · **N장** · sha256 `<앞 8자>` |
| 매핑 스냅샷 | `개정이력/쪽ID매핑_<sha8>.md` |

> 기준 덱 식별자(장수 + sha 앞 8자)는 매핑 스냅샷 머리의 값을 그대로 옮긴다.
> 접수 후 덱이 재구성됐다면 **쪽번호 좌표는 이 스냅샷 기준으로만 해석한다** —
> 현행 덱에서 다시 세지 않는다.

## 항목 표 (요청을 ID 좌표로 번역)

| # | 쪽(원문 표현) | data-slide | 요청 요약 | 처리 |
|---|---|---|---|---|
| 1 | 46p | `C4-12` | (원문 취지 한 줄) | 대기 |

- **쪽(원문 표현)**: 사용자가 말한 그대로 적는다(«46p», «뒤에서 세 번째» 포함).
- **data-slide**: 매핑 스냅샷에서 찾은 ID. 표에 없거나 특정 불가면 `(소재불명)`으로
  적고 사용자에게 되묻는다 — 추측으로 채우지 않는다.
- **처리**: 대기 → 반영 / 보류(사유) / 철회(사유). 완료 보고·검증·커밋 메시지는
  이 열의 ID로 지칭한다(쪽번호 병기는 자유, 단독 사용은 금지).

## 규약

- 전역 규칙(«전 슬라이드», «전부») 항목은 쪽 열에 `전역`이라 적고 ID 열은 비운다.
- 커밋 메시지에 대상 ID를 병기한다(예: `fix(3주차): V4-06 겹침 해소`) — 관례이며
  기계 강제는 아직 없다(오탐 위험으로 관측 단계 — PLAN P3 리스크 절).
- 개정이력 폴더 규약의 정본은 `sessions/README.md` 「개정이력 폴더 규약」.
