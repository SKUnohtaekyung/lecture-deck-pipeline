## §2. 5·6교시 연결과 의존성 위반 해소 여부 (D2)

**기존 위반**: 3교시 실습⑥(세 파일+첫 작동)이 분리파일·상대경로·브라우저직접실행·기술제한 4개를 전제하는데 이 넷은 5교시(5-2~5-5)에서야 정의된다(`week2_curriculum_options.md:19-22`, "3교시 학생은 '왜 세 파일인지, 왜 `./`인지, 왜 더블클릭이 되는지' 모른 채 파일을 만든다"). 균형안은 이미 수정안을 제시했다 — **분리파일·상대경로를 3교시로 승격**, 심화만 5교시 유지(`week2_curriculum_options.md:32` "균형안...분리파일·상대경로를 3교시로 승격"). `week2_module_plan.md:76` 모듈3 실습⑥ 직전에 "핵심개념⑤ 분리 파일 소개(index/style/script 역할)"가 이미 삽입돼 이 승격이 실행됐음을 확인했다(`week2_module_plan.md:66,76`).

**판정: 새 구조는 이 해소를 자동으로 보존하지 않는다 — 명시적 재확인 없이는 오히려 악화될 위험이 있다.**

근거:
1. 신4교시가 화면구조 내용을 전부 밀어내고 AI 작업 시스템으로 전면 교체되므로(§1), 균형안이 분리파일·상대경로를 3교시로 승격한 결정은 이 교체 작업과 **별개**로 유지돼야 하는데, 새 구조 설계 문서(`AGENT_DISPATCH_SPECS.md:104-106`) 어디에도 이 승격을 "그대로 가져간다"는 명시가 없다. 재설계자가 신3교시를 "AI에게 전달할 작업 자료"(prd.md·AGENTS.md 중심)로 재정의하면서 분리파일·상대경로를 다시 5교시로 되돌릴 위험이 실재한다.
2. §1에서 확정한 대로 신5교시는 화면구조(레퍼런스·DESIGN.md) + 하네스 구현 실습 + 구모듈5 전체(분리파일심화·상대경로심화·브라우저vs서버·기술제한·마지막작동보호·리팩터링, `week2_module_plan.md:118`)를 모두 떠안는다. 이 상태에서 3교시 실습⑥이 승격분(분리파일·상대경로 원리) 없이 진행되면, 위반이 **원래보다 더 크게** 재발한다 — 5교시가 이미 과밀해 원리 설명을 뒤로 미룰 유인이 커지기 때문이다.
3. 새로 생기는 순서 자체(4교시 AI시스템 → 5교시 구현)는 위반이 아니다 — 4교시가 5교시보다 먼저 오므로 "하네스 개념 정의 → 하네스로 구현"의 순서는 논리적으로 맞다.

**권장 배치(해소 유지안)**:
- 균형안의 3교시 승격 결정(`week2_curriculum_options.md:32`, `week2_module_plan.md:76`)을 신3교시("AI에게 전달할 작업 자료") 설계에 **명문으로 이관**한다. 신3교시 실습⑥ 직전에 분리파일·상대경로 원리 미니 정의(현재도 `week2_module_plan.md:76` "핵심개념⑤"로 존재)를 그대로 유지.
- 신5교시는 심화(왜 나누나·파일명 문제·이식성)만 다루고 원리 재설명은 "앞서 배운 원리 그대로" 한 줄 포인터로 축소한다(이미 `week2_extension_plan.md:55` EXT5-1 리스크 검토가 이 패턴을 제안해 뒀다 — 그대로 재사용 가능).
- 결론: **새 구조는 이 위반을 해소하지도 자동 악화시키지도 않는다 — 해소 여부는 전적으로 "균형안의 3교시 승격을 신3교시 설계에 명시적으로 보존하는가"에 달려 있으며, 현재 산출물 어디에도 이 보존이 명문화돼 있지 않으므로 지금 상태로 진행하면 악화 쪽으로 기운다.**

| ⑥⑦(즉시 수정 시도 또는 생략+3주차 차이 정리) | 1분(생략 가능) | 3분 |
| **합계** | **8분** | **15분** |

FAST는 6교시 QA·마무리 8분 버퍼(`week2_module_plan.md:161`) 안에서 소화 가능하고, NORMAL은 버퍼를 초과하므로 6교시 전체 시간표 재산정이 필요하다(§6과 연동).

**완료 기준**: 관찰 기록지에 최소 1개 항목(막힌 지점/예상과 다른 행동/혼란 문구 중 하나)이 실제로 기입되면 완료. "특이사항 없음"도 유효한 결과로 인정(짝이 실제로 안 막혔을 수 있음 — 날조 방지).

**12명 교실 운영 방식**: 6쌍으로 나눠 **전원 동시 진행**(순차 발표 아님 — 순차로 하면 6쌍×15분=90분이 되어 시간표가 성립하지 않음). 짝 배정은 강사가 사전에 무작위 또는 자리 기준으로 고정해 즉흥 배정 시간을 없앤다. 1라운드(A 시연·B 관찰)와 2라운드(교대)를 전원이 동시에 밟으므로 교실 소음(6쌍이 동시에 말하며 관찰)은 예상된 정상 상태로 사전 공지한다. FAST 시에는 라운드 교대를 생략하고 편도 관찰(한 사람만 시연, 관찰자만 기록)로 축소해 8분 안에 맞춘다.

**실습예제 mvp 5종 CSS 실측(렌더링 없이 코드만 확인)**:
- 5개 파일(`anchor_활동기록/style.css`·`calc_가상예산/style.css`·`convert_단위변환/style.css`·`pick_선택추천/style.css`·`timer_집중타이머/style.css`)이 전부 동일 골격을 쓴다: `.card { width:100%; max-width:520px }`(예: `anchor_활동기록/style.css:15-21`), `.field`/`.input-row { display:flex; flex-wrap:wrap; gap:10px }`(`anchor_활동기록/style.css:36-42`, `calc_가상예산/style.css:36-42` 등 5개 파일 공통), `input { flex:1; min-width:140~160px }`. **미디어 쿼리는 5개 파일 어디에도 없다**(전수 확인).
- `flex-wrap:wrap`이 이미 미디어쿼리 없이도 좁은 폭에서 요소를 자동으로 줄바꿈시키는 역할을 한다 — 즉 **가로 넘침(overflow)이 구조적으로 잘 일어나지 않는다.** 예: 375px 뷰포트에서 `body padding:24px`(양쪽 48px) + `.card padding:28px`(양쪽 56px) = 콘텐츠 폭 약 271px, 여기에 `min-width:140px` 입력 2개(`calc_가상예산` 지출추가 행처럼)가 들어가면 280px+gap10px=290px로 271px를 넘지만, `flex-wrap:wrap`이 즉시 다음 줄로 내려 겹침·가로 스크롤 없이 세로로 쌓인다.
- **"카드 쌓임" 학습 결과는 현재 자산으로 시연 불가능하다** — 5개 파일 전부 `.card`가 **단일 인스턴스**뿐이고(그리드·다중 카드 레이아웃 없음), 여러 카드가 좁은 화면에서 쌓이는 현상 자체가 애초에 존재하지 않는 구조다.
- `timer_집중타이머/style.css:84-90`의 `#time-display { font-size:52px }`(고정 px, 미디어쿼리 없음)이 유일하게 폭이 매우 좁은 기기(320px급)에서 여백이 빠듯해질 후보지만, "25:00" 같은 5자 표시는 폭 216px 안에서도 넘칠 정도는 아니라고 추정된다(추정 — 렌더링 미실시, `모름` 처리).
- **결론**: 이 5개 CSS는 미디어쿼리가 없다는 점에서 "반응형 설계는 아님"이 맞지만, `flex-wrap`·`max-width:100%` 패턴 덕에 "확 깨지는" 시연 재료로는 약하다. 텍스트 겹침·가로 넘침을 극적으로 보여주긴 어렵고, 버튼 크기(터치 타겟)와 "줄바꿈 발생 자체"(의도치 않은 세로 확장)는 관찰 가능하나 실제 렌더링으로 재확인이 필요하다. **"카드 쌓임" 항목은 이 자산으로 대체 불가 — 다른 예시가 필요하거나 학습 결과 표현을 조정해야 한다.**

**주의**: 69분/모듈 개념 자체가 "실제 수업 시간"이 아니라 "FAST 페이스에서도 소진되지 않을 준비 콘텐츠 분량"이라는 점(`FINAL_DECISION_PACKET.md:94` "용량 산식")을 재차 확인한다 — 6교시×45분=270분이 실제 수업 시간이고, 414~420분은 그보다 많은 "준비량"이므로 남는 것이 정상이다. 이 구분을 혼동하면 "6시간을 넘겨야 한다"는 잘못된 결론에 이를 수 있다.
