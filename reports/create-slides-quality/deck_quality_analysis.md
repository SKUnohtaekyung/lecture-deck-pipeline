## 1. 파서/분류 방법

- **슬라이드 경계**: `<section class="slide` 정규식 매치 → 다음 매치 전까지를 그 슬라이드의 원문으로 취급. 4개 덱 전부에서 슬라이드 안에 슬라이드가 중첩된 사례 없음을 확인.
- **본문 글자수**: 공백 제거 후 문자 수(한글 1자=1). 제외 대상: `<script>`/`<style>`, `<header>`(=`.s-head`: 로고·브랜드·교시 라벨), `aria-hidden="true"` 전체, 클래스가 `nav|header|footer|pagenum|logo|progress|pd-dots|s-head|s-team|s-brand|s-line|s-logo`에 매치하는 요소. 4개 덱 전체에서 별도 footer/페이지번호 DOM 요소는 발견되지 않음(JS/CSS 카운터로 렌더링되는 것으로 추정) — 이 제외 경로는 실제 데이터로 검증되지 않았다.
- **의미 블록(container)**: 클래스가 `card|box|panel|-row|-col|-case|-step|-side|-note|-item|-tile|-cell|-slot` 패턴에 매치하는 요소 + **클래스 없는 `<article>` 태그**(카드형 관용구로 자주 쓰이는 것을 스팟체크로 발견해 추가). "container_count" = 텍스트를 가진 leaf가 귀속된 서로 다른 container 수, "blocks"(text_leaf_count) = 8자 이상 직접텍스트를 가진 leaf 노드 총수.
- **시각자료(설명기능)**: `viz-*` 클래스(카탈로그 정본 `kit/charts/by-shape.md` §"element 목록"에서 확인 — 모든 차트/다이어그램 element는 `.viz-<slug>` 하나의 프리픽스로 통일됨) + `<canvas>` + 장식이 아닌(비-`aria-hidden`, 로고 아닌) `<img>`. 순수 로고·화살표·장식 SVG는 제외.
- **빈/거의빈 컨테이너**: 과제 스펙 그대로(0자, 또는 <10자이면서 동일부모·동일클래스 형제 ≥2) 적용하되, 시각자료 보유 여부로 사후 태깅해 분리 보고(§6 캐비어트).

## 2. 슬라이드 유형 분류 규칙

class 토큰을 `-`로 분해한 형태소 집합에 대한 **정확 일치**만 사용한다(원문 전체에 대한 부분문자열 검색 금지 — 아래 버그 참고). 우선순위 순서:

1. `idx==0` 또는 형태소에 `cover` → **표지**
2. `thank`/`closing` → **요약**(클로징)
3. `divider`/`roadmap`/`agenda` → **구간전환**
4. `practice-intro`(전체 토큰 일치) → **실습대기**
5. `annex`/`recovery`/`pitfalls`/`privacy` → **참고·보조**
6. `compare` → **비교**
7. `flow`/`cycle`/`stage`/`lifecycle`/`gantt`/`proc` → **프로세스**
8. `practice`/`todo`/`workspace` → **실습지시**
9. `result`/`report`/`showcase`/`readiness`/`inspection` → **결과확인**
10. `summary`/`recap`/`wrap` → **요약**
11. `w2-slot` 토큰, 또는 제목이 `?`/`일까`/`일까요`로 끝남 → **질문·환기**
12. 기본값 → **개념설명**

표지·전환 슬라이드는 밀도로 판단하지 않았다(과제 지시대로 클래스/제목 규칙만 사용).

**정밀도 스팟체크**: `random.seed(42)`로 12장(덱당 3장) 추출해 수작업 대조. **11/12 일치**(스팟체크 도중 분류기 버그 2건을 발견해 수정한 뒤 수치). 남은 2건은 개념설명 vs 실습지시 경계가 모호한 사례(가르는 클래스가 없어 휴리스틱의 구조적 한계).

- **버그1(발견 즉시 수정)**: family 문자열 전체에 대한 부분문자열 검사 `"cover" in family`가 `is-recovery`(복구/트러블슈팅 부록 슬라이드)를 "recovery" 안의 "cover" 부분문자열 때문에 표지로 오분류했다. → 하이픈 분해 후 정확 일치로 교체.
- **버그2(발견 즉시 수정)**: `index-entry-slide`를 범용 `index` 키워드로 구간전환에 매칭시켰으나, 실제 내용은 "index.html이 뭔지" 설명하는 개념설명 슬라이드였다. 코퍼스 전체에서 `index` 키워드가 매치한 사례는 이 1건뿐이고 그마저 오분류였으므로 키워드를 제거, 기본값(개념설명)으로 떨어지게 함 — 이게 맞다.

## 6. 측정 정직성 — 반드시 읽을 캐비어트

- **글자수=품질 아님.** 슬라이드 목적에 비해 정보가 충분한지가 기준이지, 글자수 자체가 목표가 아니다. 표지·전환·질문 슬라이드는 원래 짧아야 하며(밀도로 판단 안 함), 아래 수치는 **개념설명으로 분류된 슬라이드에 한정**한다.
- **"빈 컨테이너" 79건(W2) vs 39건(W1_FINAL)은 겉보기와 다른 의미다.** 원인 분해:
  - W1_MID: 39건 전부 `empty-image-slot`(예: `asset-slot--hero`) — 실제로는 서술적 alt 텍스트를 가진 `<img>`를 담은 정상 이미지 슬롯이다. 결함이 아니다.
  - W1_FINAL: 39건 중 34건이 같은 `empty-image-slot`(정상), 4건만 `empty-no-text-no-visual`(진짜 빈 컨테이너), 1건이 `near-empty-sibling-text-only`.
  - **W2_CURRENT: 79건 전부 `near-empty-sibling-text-only`** — 이미지 슬롯 패턴은 전무하고, 전부 "형제 카드가 2개 이상인데 그중 한 칸이 10자 미만인 텍스트 카드" 패턴이다. 이게 실제로 개선 대상이다.
  - 즉 W1의 "빈 컨테이너 39건"은 거의 다 정상 이미지 자리이고, W2의 "79건"은 거의 다 진짜 텍스트 밀도 문제다 — 원시 합계만 보면 반대로 읽힌다.
- **C1-7("주제는 이렇게 고릅니다") 사례**: empty=8이지만 실제로는 "①~⑧ 번호가 붙은 8개 선택 기준"을 각 카드에 1줄씩 담은 의도된 디자인이다(스팟체크로 원문 확인). 과제가 정의한 "<10자& 형제≥2" 규칙을 문자 그대로 적용하면 이런 "짧지만 유의미한 목록형 카드"도 걸린다 — "근접-빈(near-empty)"은 "깨짐"이 아니라 "낱말 카드형 밀도"로 읽어야 한다.
- **컨테이너 수 중앙값 산정에서 발견한 파서 버그**: 초기 버전은 `<article>` 태그를 클래스명 매치로만 컨테이너로 인식해, W1_FINAL의 밀도 높은 개념 슬라이드(예: `S3CE`, `S39A`)가 카드 클래스 없는 순수 `<article>` 그리드를 쓴다는 걸 놓쳐 컨테이너 수를 1로 과소산정했다. `<article>` 태그 자체를 암묵적 컨테이너로 인식하도록 고친 뒤 W1_FINAL 중앙값이 1→4로 바뀌었다(이 정정 전 수치를 쓰면 "W1이 컨테이너 구조가 빈약하다"는 반대 결론이 나올 뻔했다).
- **"한 설명단위 평균 분할 장수"는 1.0으로 4개 덱 전부 동일하게 나왔는데, 이는 측정 방법의 한계이지 실제로 "분할이 없다"는 근거가 아니다.** 연속 슬라이드를 제목 앞 6글자로 스테밍해 묶는 방식을 썼는데, 이 코퍼스의 한글 제목은 같은 주제를 이어가도 표현이 매번 바뀌어(예: "PART 1"·"이어서" 같은 표식이 없음) 스테밍 매치가 전혀 발생하지 않았다. **사실상 확인불가로 취급할 것.**
- 분류 정밀도는 12장 스팟체크 기준 11/12(§2)이며 자동 분류이므로 경계 사례 오분류 가능성이 남아있다.

## 10. 파서 알려진 실패 모드 (요약, 전체는 JSON `parser_known_limitations`)

1. 컨테이너 인식은 클래스명 패턴 + `<article>` 특례에 의존 — 그 외 무클래스 반복 태그 관용구(예: 무클래스 `<li>`/`<div>` 그리드)는 놓칠 수 있음.
2. "family"는 실제 코드상 class 문자열 그대로이며 `kit/layouts/families/`의 8종 표준 분류와 다르다(운영 덱은 표준 family 클래스명을 그대로 쓰지 않고 슬라이드별 고유 클래스를 짓는다) — family 반복률은 "표준분류 반복"이 아니라 "리터럴 CSS 클래스 반복"을 잰다.
3. "빈 컨테이너"는 과제 스펙을 문자 그대로 적용했지만 이미지 슬롯과 텍스트 카드를 혼동할 위험이 커서 사후 태깅으로 분리했다(§6).
4. "평균 분할 장수"는 사실상 확인불가(§6).
5. footer/페이지번호 DOM이 4개 덱 전부에 없어 그 제외 규칙은 실제 데이터로 검증되지 못했다.
6. 슬라이드 유형 분류는 클래스+제목 휴리스틱이며 스팟체크 11/12 일치, 개념설명/실습지시 경계에서 오분류 가능성 잔존.
