## A. 최종 목표

- **사용자가 원하는 2주차 상태**: 1주차 최종본(`sessions/1주차/강의덱.html`, 2026-07-26 동결 해제 후에도 정본 지위 유지)과 **동등한 화면 품질**의 2주차 강의덱. 슬라이드 수·레이아웃·부록 구조는 목표가 아니라 수단이며, 사용자는 "107장/108장을 유지하라"거나 "특정 장수에 맞추라"고 요구한 적이 없다.
- **1주차 최종본의 지위**: 화면 품질의 **정본(기준선)**이다 — 참고자료나 스타일 샘플이 아니라 "이 정도는 되어야 통과"의 합격선이다. 이번 표본 작업이 실패한 핵심 이유 중 하나가 바로 이 지위를 "참고"로 낮춰 취급한 것이다(§D 5행).
- **현재 표본이 실패한 이유**(사용자 직접 관찰, 2026-07-27): 기존 레이아웃을 유지한 채 문장만 추가함·짧은 내용을 표로 바꿔 글자수만 늘림·장식 아이콘과 캡션을 "시각자료"로 계산함·의미 있는 화면 구성 없이 블록 수만 늘림·1주차 최종본과의 직접 시각 대조 없이 개선을 판정함·107장 구조와 슬라이드 경계를 사실상 그대로 둠. → **자세한 실패 목록과 재발 방지는 §D.**
- **이번 단계의 성공 상태**: 표본(초기 6장, 이후 확대 가능)이 1주차 최종본과 **나란히 렌더링해 직접 비교했을 때** 동등한 화면 품질을 사용자가 인정하는 것. 글자수·블록수·시각자료 개수·게이트 통과 여부는 성공의 증거가 **아니다**(§B 참고).
- **전체 적용 전 승인 조건**: 표본이 사용자 승인을 받기 전까지 나머지 슬라이드(부록 33장 포함)에 같은 방식을 확대 적용하지 않는다. `week2_remediation_plan.md` §D 실행순서 4번("표본 재생성 → 품질·회귀 이중 검토 게이트 → 통과 시에만 B1~B6 전체 적용")이 이미 이 게이트를 계획에 명시했고, 이번 표본은 그 게이트를 **통과하지 못했다**(FAILED_SAMPLE_V1) — 따라서 전체 적용은 아직 조건 미충족 상태다.
- **이미지 격차가 화면 품질 격차의 최대 단일 원인이다**: 1주차는 66개 이미지 에셋(대부분 paper-cut 일러스트 스타일)으로 화면을 구성했으나 2주차는 이미지 0장이다. 이 격차와 그에 대응하는 계약·금지 사항·판정 기준은 **§I(이미지 활용 계약)·§J(금지된 보정 방식)·§K(시각 판정 14문항)·§L(설계 하드 게이트 15항목)**에 신설했다 — 표본 재설계(§G 순서 6 이후)는 반드시 이 4개 절을 먼저 적용한다.

## B. 사용자의 절대 조건

1주차 동등 화면 품질을 만족해야 하며, 다음 12개 조건은 협상 대상이 아니다. (조건 9~12는 2026-07-27 신설 — §I~§L 참고.)

1. **1주차 최종본과 동등한 화면 품질**이어야 한다.
2. **글자 수·블록 수 증가 자체는 개선의 증거가 아니다.** 이 지표들이 늘었다는 사실만으로 품질이 좋아졌다고 주장할 수 없다.
3. **기존 카드에 문장이나 아이콘만 추가하는 방식은 허용되지 않는다.** 레이아웃·구도 자체를 다시 설계해야 하는 경우 그렇게 한다.
4. **화면이 의미 있는 정보·시각 구조로 충분히 구성되어야 한다** — 장식용 요소가 아니라 실제로 이해를 돕는 구조.
5. **발표자 노트 없이도 화면만으로 핵심을 이해할 수 있어야 한다.**
6. **107장(또는 현재의 부록/CORE/FLEX 레이아웃 구조)을 보존할 의무는 없다.** 필요하면 슬라이드 수·구조·부록 배치를 다시 설계한다.
7. **전체 적용 전에는 반드시 표본에 대한 사용자 승인**을 받아야 한다.
8. **사용자의 가설보다 실제 파일과 렌더링 결과가 우선한다** — 어떤 판단도 실제로 파일을 열어 보고 브라우저로 렌더링해 본 결과로 검증되어야 하며, 추정이나 지표만으로 "개선됐다"고 결론 내지 않는다.
9. **전체 적용은 사용자 명시 승인 전까지 절대 금지**다(§A "전체 적용 전 승인 조건"과 동일 게이트를 여기서도 절대 조건으로 재확인한다).
10. **이미지를 적극 활용한다** — 이미지 생성 도구가 없다는 제약(§I 참고)을 이유로 카드·표·아이콘으로 조용히 대체하지 않는다. 대체 경로(1주차 기존 asset 재사용·실습예제 실제 화면 캡처·직접 제작 SVG)를 우선 검토한다.
11. **표본 6장 중 최소 3장은 실제 설명용 이미지를 주요 화면 요소로 포함**해야 한다. 단, 1주차 Part 3(§G 순서 4)의 실제 이미지 활용 비율이 이보다 더 높게 확인되면 그 실측 비율을 기준으로 삼는다.
12. **동일 표본이 같은 원인으로 2회 실패하면 3회차 자동 수정을 금지**한다 — 이 경우 재시도 대신 사용자에게 결정 1건을 요청한다.

> 이 8개 조건에 비추어 **"글자수 증가/블록수 증가/시각자료 수 증가/테스트(게이트) 통과/저밀도 비율 감소/창작 없이 출처만 보존"은 그 자체로 품질의 증거가 될 수 없다.** 8장 표본 작업(`sample_before_after.md`)이 정확히 이 기준들로 "성공"을 자체 보고했으나(글자수 증가·게이트 WARN 불변·62 tests OK·출처 verbatim 인용), 사용자가 실제 화면을 본 결과는 전면 FAIL이었다 — 이 문서 §D가 그 간극을 기록한다.

다음 방식은 "보정"으로 인정하지 않는다: 기존 카드에 문장 한두 줄 추가 · 아이콘+캡션 추가 · 기존 내용을 표로 변환 · 하단 콜아웃만 추가 · 빈 공간에 카드 배치 · 노트를 그대로 본문 이동 · 레이아웃 유지한 채 글자수만 증가 · 데이터 속성으로 예외 처리 · `data-intentional-minimal`로 설명형 슬라이드 통과 · 실제 이미지가 필요한 장면을 이모지·범용 아이콘으로 대체 · 무의미한 스톡 이미지 배치 · 이미지를 장식처럼 붙이고 활용했다고 보고.

각 표본은 **기존 레이아웃 유지 근거가 명확하지 않으면 DOM을 폐기하고 재설계**한다.

> §D 신규 행·"페이지 7·13·35 보정 실패" 행이 기록한 FAILED_SAMPLE_V1의 실제 실패 양상(dl-list 유지+캡션 추가, `center-msg`→`ct-figure` 전환은 있었으나 여전히 라벨 수준)은 이 목록의 "기존 카드에 문장 추가"·"아이콘+캡션 추가" 항목과 정확히 일치한다 — 새 규칙이 아니라 이미 확인된 실패 패턴의 명문화다.

## K. 시각 판정 14문항 하드 게이트

다음 14문항 중 하나라도 애매하면 PASS가 아니라 `확인 필요`로 판정한다.

1. 같은 시리즈로 보이는가
2. 화면 대부분이 의미 있는 정보 전달에 쓰이는가
3. 화면만 보고 핵심 개념 설명 가능한가
4. 정의 외 관계·사례·비교·적용 기준 중 필요한 요소가 있는가
5. 시각 요소와 이미지가 실제로 설명하는가
6. 이미지가 장식·빈공간 채우기가 아닌가
7. 이미지와 텍스트가 서로 다른 정보를 주는가
8. 이미지 크기가 설명 요소로 충분한가
9. 하단 결론이 상단 반복이 아닌가
10. 기존 수정본과 구조적으로 달라졌는가
11. 노트 없이 이해 가능한가
12. 학습자가 판단·행동할 수 있는가
13. 1주차 이미지 활용 슬라이드보다 현저히 빈약하지 않은가
14. 사용자가 전면 개조하지 않아도 되는가

정량 지표(글자수·블록수·카드수·표 셀수·아이콘수·시각자료수·이미지 파일수·점유율·저밀도 비율·WARN 감소·테스트 PASS)는 **보조 증거일 뿐**이며, 실제 렌더링이 부족하면 수치와 무관하게 FAIL이다.

## L. 설계 하드 게이트 15항목

HTML을 쓰기 전에, 표본 슬라이드마다 다음 15항목을 담은 설계 스펙이 먼저 있어야 한다: 학습 목적 / 현재 실패 원인 / 화면 필수 정보 / 노트에만 둘 정보 / 대응 1주차 기준 슬라이드 / 추출한 설계 원리 / 시각 구조 / 이미지 사용 여부 / 이미지 유형과 설명 목적 / 기존 레이아웃 유지·폐기 판정 / 인접 병합·삭제 여부 / 예상 화면 구성 / 이미지·텍스트 배치 / 실패 위험 / FAIL 조건.

**"카드를 추가한다"·"아이콘을 넣는다"·"텍스트를 보강한다"·"표로 정리한다"·"비유를 추가한다"·"관련 이미지를 넣는다" 수준의 설계안은 승인 불가.**
