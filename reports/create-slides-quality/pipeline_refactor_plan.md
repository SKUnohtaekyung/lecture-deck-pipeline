## 감사자 경고 3건 (전 절 공통 — 협상 불가 제약)

아래 3건은 이 계획의 모든 변경안이 지켜야 하는 상한선이다. 각 절의 "위험" 항목이 이 경고와의 충돌 여부를 다시 확인한다.

1. **개념당 고정 슬라이드 수 하한을 만들지 않는다.** `skills/콘텐츠/SKILL.md:36`(R-PLAN-01)이 이미 "시간예산 역산으로 장수를 정하지 않는다"는 안티패턴을 금지했다 — "개념 하나엔 최소 N장"이라는 새 규칙은 방향만 반대일 뿐 같은 실패(장수를 내용보다 먼저 고정)를 반복한다. 이 문서의 모든 "클러스터" 관련 변경안은 **장수를 강제하지 않고, 필요한 재료(정의·오해·사례)가 있는지만 확인**한다.
2. **G8 필드를 전 청크로 확대하지 않는다.** `skills/리서치/SKILL.md:94`(G8)는 이미 P0=2필드·P1=1필드·P2=0(권장)으로 우선순위별 차등을 뒀다 — 이는 `§0.5`(실행 예산)의 조사 시도 상한과 직결된 설계다(`skills/리서치/SKILL.md:128-176`). 아래 §리서치의 변경안은 신규 필드를 **P0 청크에만, 선택 항목으로** 추가한다.
3. **이 깊이 계약을 기존 시각 품질 게이트(`verify_deck_quality.py` R-QC 시리즈)와 같은 게이트로 합치지 않는다.** 시각 밀도(카드 면적·근-빈 컨테이너·family 반복)와 교육 깊이(정의+오해+사례 존재)는 다른 축이다 — 실제로 `verify_deck_quality.py:74-81`이 R-QC-05(family 반복)를 방향 역전으로 `[사람검토]` 강등한 사례가 "밀도·반복 지표 하나로 품질 전체를 재려던 시도"의 실패 사례다(`WORKING_CONTEXT.md` §D). 새 검사는 **별도 규칙 ID(R-QD/R-QC 계열이 아닌 새 접두어 또는 명시적 신규 번호)**로 분리한다.

## 정정 사항 (오케스트레이터 이전 진술 정정)

**R-QD-04는 "교시당 8~11장 이탈"만으로 FAIL하지 않는다.** 이 세션에서 `scripts/verify_draft_quality.py:343-358` 원문을 직접 확인한 결과, 실제 판정 로직은:

```
deviations = {교시별 8~11장 규약 이탈 목록}
if deviations:
    if note_exists(집필노트):   → WARN(이탈은 있으나 집필노트가 있어 사유 확인 가능)
    else:                        → FAIL(이탈했는데 사유 기록 자체를 확인할 방법이 없음)
else:
    → PASS
```

즉 FAIL 조건은 **"이탈 + 집필노트 파일 자체가 없음"**의 조합이지, 이탈 자체가 아니다(`scripts/verify_draft_quality.py:23-25` 주석도 "이탈했는데 사유 기록조차 없음"만 FAIL한다고 명시). 오케스트레이터의 이전 진술("이탈만으로 FAIL")은 부정확했다 — 이 문서와 이후 산출물은 이 정정된 동작을 기준으로 삼는다.

## /리서치

### 현재 책임
`sessions/N주차/자료/`에 기본 5파일(콘텐츠리서치결과·개념KB·출처레지스트리·실습안검증결과·결정요청사항)을 산출한다. 사실의 정본은 개념KB 청크 1개=개념 1개이며, 코어 청크 템플릿은 **정의(정확)·초보자문장·비유①②·워크드예시·비교표·사례(실무)·대안·비교·한계·반론·흔한오해→교정×2·verbatim·PPT소재·피해야할표현** 15개 필드로 구성된다(`skills/리서치/references/chunk-schema.md:52-68`). G8 관점 게이트가 `사례·대안·한계` 3필드 중 P0=2개↑·P1=1개↑를 요구한다(`skills/리서치/SKILL.md:94`).

### 결손
1. **「왜 필요한가」·「나쁜 예」·「적용 판단 기준」 구조화 필드가 없다.** `chunk-schema.md:52-68` 템플릿 전문 확인 결과 이 3종은 명시적 필드로 존재하지 않는다. "흔한 오해→교정"이 나쁜 예 역할을 부분적으로 하지만(`오해 ✗ → 교정 ✓`), **판단 기준**(예: PM_2의 "좋은 Pain Point 판단 3기준: 빈도/강도/대안", `reference_pedagogy_audit.md:18`)에 대응하는 필드는 전무하다.
2. **핵심 개념 자체의 예상 질문이 범위 밖이다.** G9(인접 개념)는 "이 개념을 배운 직후 학생이 물을 **다른** 개념"만 다룬다(전제·후속·혼동, `skills/리서치/SKILL.md:100-115`) — "이 개념 자체에 대해 학생이 흔히 묻는 질문"(예: module_plan의 "예상 QA" 항목, `week2_module_plan.md:32` "타깃을 너무 좁히면 사람이 없지 않나요?")을 청크 안에 구조화해 담을 자리가 없다.
3. **클러스터(개념 묶음) 단위 신호가 없다.** 청크는 1:1(개념=청크)로만 존재하고, "이 개념 3개는 PM처럼 한 시퀀스로 묶여 사례를 공유해야 한다"는 신호를 리서치 산출물 어디에도 남길 수 없다.

## /콘텐츠

### 현재 책임
리서치 5파일을 근거로 `sessions/N주차/N주차_초안.md`(4열 표: `#`·`슬라이드 제목`·`본문 문구`·`비유·멘트`)를 집필한다. 골격설계(§3)는 "슬라이드별 핵심 한마디"를 슬라이드 단위로 짠다. R-PLAN-01(시간예산 역산 금지)·R-PLAN-02(CORE 깊이 삭감 금지)·R-DENS-02(화면:노트 배분)·R-ANNEX-01(부록 강등 금지)·R-COMP-01(목적별 구성)이 이미 있다(`skills/콘텐츠/SKILL.md:36-41`).

### 결손
1. **골격설계(§3)가 슬라이드 단위 계획만 하고 개념 묶음 단위 계획이 없다.** "1개념=1슬라이드" 관성을 명시적으로 금지하는 규칙도, 반대로 명시적으로 권장하는 절차도 없다 — S4(개념 묶음 로직 0건)가 이 단계에서부터 시작된다.
2. **시간/목적 배분을 기록할 자리가 없다.** `입력양식/콘텐츠초안템플릿.md`의 4열 표(58-75행)를 확인한 결과 시간(분)이나 슬라이드 목적(정의/오해/사례/시연/실습/QA)을 기록하는 열이 전혀 없다 — `week2_module_plan.md`가 만든 "오해 교정 6분(2%)" 같은 배분 붕괴 진단을 초안 단계에서는 아예 할 수 없다(조립된 덱이나 별도 계획 문서를 따로 만들어야만 보임).
3. **콘텐츠 초안 형식은 불변 규칙(§0-1)이라 새 열을 추가할 수 없다.** "형식 = 콘텐츠초안템플릿.md 그대로"이고 "`분할 허용` 필드는 없다"(`skills/콘텐츠/SKILL.md:25-26`) — 표 구조 자체를 확장하는 변경안은 이 불변 규칙과 충돌한다.

## create-slides

### 현재 책임

### 결손
1. **개념 묶음(클러스터) 단위 검사가 검증 스크립트 3종에 0건이다(S4).** `verify_deck.py`·`verify_deck_quality.py`·`verify_draft_quality.py` 전부 슬라이드 단위(개별 family·개별 밀도)만 본다 — "이 클러스터 5장이 PM처럼 정의+오해+사례+비교+적용기준을 갖췄는가"를 보는 검사가 없다.
2. **비연속 고빈도 레이아웃 재사용을 못 잡는다(S5).** `family_signature()` 기반 검사는 "인접 3연속 동일 family" 예외 처리(`data-series`)까지만 다룬다 — 덱 전체에서 같은 family가 비연속으로 반복 사용되는 비율(2주차 24.0% vs 1주차 2.7%, 오케스트레이터 판정)은 원리적으로 이 인접 검사로 잡을 수 없는 별도 지표다. ⚠️ 이 세션은 이 수치를 독립 재계산하지 않았다(§파일1 ⑧ 위험 참고).
