## §1. 이 구간의 학습 결과 (완료 시점에 학습자가 할 수 있어야 하는 것)

1. 내가 맡기려는 일이 **순서가 정해진 일인지 판단이 필요한 일인지** 구분해 말한다.
2. **규칙 파일에 적는 것과 장치로 막는 것을 구분**해, 자기 프로젝트의 항목을 두 갈래로 나눈다.
3. AI에게 규칙·완료 기준 **초안을 시키고, 최소 한 군데를 자기 손으로 고쳐** 파일로 저장한다.
4. "일을 나눌수록 좋다"가 **왜 항상 참이 아닌지** 근거를 들어 설명한다.
5. 승인 창이 뜨는 순간이 **무엇을 뜻하는지** 말하고, 누르기 전에 확인할 것을 안다.

⚠️ **학습 결과에 "하네스의 정의를 말한다"를 넣지 않았다.** 용어가 반년 된 신조어라 정의 암기는 가치가 낮고, 합의 수준 미달 자체를 아는 것이 더 중요하다.

## §2. 개념 배치와 순서

순서에는 의존성이 있다. 화살표는 "앞을 모르면 뒤가 이해되지 않는다"는 뜻이다.

```
[에이전트 vs 워크플로]  ← 이 구간 전체의 프레임
        ↓
[에이전트 구성요소] · [자율성 정도]  ← 무엇으로 이뤄지고 얼마나 맡길 수 있나
        ↓
[하네스 엔지니어링] → [하네스 구성요소]  ← 모델 밖을 설계한다는 관점
        ↓
[규칙 vs 기술적 강제] ★ 이 구간의 핵심 교육 포인트
        ↓
[인간 승인·감독]  ← 실제 강제가 일어나는 지점
        ↓
[서브에이전트] → [멀티에이전트] → [멀티에이전트 한계] ★ 두 번째 핵심
        ↓
[LLM과 대화해 하네스 만들기]  ← 5구간으로 넘어가는 다리
```

기존 `[C-Skill]`·`[C-AGENTS문서]`(P0 심화)는 **「규칙 vs 기술적 강제」 직전**에 붙인다 — 두 파일이 무엇인지 알아야 "그런데 그게 강제가 아니다"가 충격으로 작동한다.

**인접 청크 6종은 본문 슬라이드로 만들지 않는다.** 학생이 물었을 때 강사가 꺼낼 답이다(멘트·발표자 노트).

## §3. 클러스터별 화면 설계 — §0.3E 원리 적용

각 클러스터에 **어떤 원리를 왜 적용하는지**를 명시한다. "카드를 추가한다" 수준의 설계는 승인 불가(§L).

### 클러스터 A — 에이전트 vs 워크플로 (P0)

| | 내용 |
|---|---|
| 정보 모양 | **두 대상 비교** |
| 적용 원리 | **S3HUM** — 독립 카드 2장이 아니라 **가운데 "제어권을 누가 갖나" 라벨을 붙인 연결자**로 관계를 강제 |
| 보강 원리 | **29** — 각 측이 최소 3개 병렬 주장(제어·예측가능성·비용), 하단 종합 한 줄로 닫음 |
| 앞 장 대비 진전 | 프레임 도입 → 판별 기준 확보 |
| FAIL 조건 | 두 카드를 나란히만 놓고 관계선이 없으면 FAIL. 한쪽 주장이 3개 미만이면 FAIL |

### 클러스터 B — 하네스 엔지니어링 (P0)

| | 내용 |
|---|---|
| 정보 모양 | **과정(용어의 형성 과정)** |
| 적용 원리 | **S3ITR** — 타임라인 앞에 **"왜 이걸 먼저 말하는가"(경고)를 먼저** 둔다. 정설로 가르치면 안 된다는 판단이 시점보다 앞선다 |
| 화면 필수 정보 | 2026-02 등장 → 04 정리 → 05 "합의 없음" 선언 → 06 최초 정의 시도 |
| 노트에만 둘 것 | 각 출처의 저자·URL 세부 |
| FAIL 조건 | 타임라인만 있고 경고가 없으면 FAIL(용어를 정설로 심는다) |

### 클러스터 C — 규칙 vs 기술적 강제 ★핵심 (P0)

| | 내용 |
|---|---|
| 정보 모양 | **오해 교정** |
| 적용 원리 | **S3CE/S3PE** — 정의 상자 → 판단기준 병렬 카드 → **나쁜예(코랄)/좋은예(민트) 3단 스캐폴드** |
| 화면 필수 정보 | 공식 문서가 스스로 "컨텍스트일 뿐 강제가 아니다"라고 밝힌 문장(verbatim) + **우리 저장소가 그 간극을 인정한 실제 사례**(`skills/README.md:45`) |
| 이미지 사용 | **예 — "부탁 메모 vs 잠금장치"**. 이건 장식이 아니라 개념의 핵심 대비다 |
| FAIL 조건 | 나쁜 예가 화면에 없으면 FAIL. 로컬 사례가 텍스트 인용만으로 처리되면 약함 |

### 클러스터 D — 인간 승인·감독 (P0)

| | 내용 |
|---|---|
| 정보 모양 | **두 축 × 각 3~4값** |
| 적용 원리 | **S3PRV** — 3개 이상 범주는 **표가 아니라 색 분류 카드 + 하단 판단원칙 배너** |
| 이미지 사용 | **예 — 실제 승인 다이얼로그 스크린샷**(D15, 강사 재캡처). 공식 문서에 화면 인용이 없어 이것 외엔 대체 불가 |
| FAIL 조건 | 값 목록을 표로만 나열하면 FAIL. 스크린샷 없이 문구를 단정하면 FAIL |

### 클러스터 E — 서브에이전트·멀티에이전트·한계 ★핵심 (P0)

| | 내용 |
|---|---|
| 정보 모양 | 구조 + **비교(부정적 결과)** |
| 적용 원리 | 구조도는 **S3MAP**(번호+제목+**설명문** 3요소 — 제목만이면 미완성). 한계는 **29**(각 측 3개 병렬 주장 + 종합 한 줄) |
| 화면 필수 정보 | **"우리 프로젝트에서 3회 일어난 완료보고 실패"** — 실제 사고 로그를 그대로 화면에. 학습자는 규칙을 설명하는 실패를 기억한다 |
| 보강 원리 | **S3ITR** — 위임 절차 앞에 "왜 검증이 먼저인가"를 둔다 |
| FAIL 조건 | 부정적 결과 없이 구조만 그리면 FAIL(이 클러스터의 존재 이유가 사라진다) |

### 클러스터 F — LLM과 대화해 하네스 만들기 (P0, 5구간 다리)

| | 내용 |
|---|---|
| 정보 모양 | **순환 과정** |
| 적용 원리 | **S3ITR + S3MAP** — 순환 앞에 "왜 고정해야 하는가"(대화만 하면 휘발된다)를 두고, 각 단계 카드는 3요소 |
| 화면 필수 정보 | 7단계 순환이 **4→5→6구간과 겹쳐 보이게** 배치 |
| FAIL 조건 | "사람이 검토한다" 단계가 시각적으로 강조되지 않으면 FAIL |

## §4. 실습 배치

**실습 8 — AI와 대화해 작업 하네스 만들고 파일로 고정하기**(13항목 완비, `2주차_실습안_검증결과.md`).

- 필수 단계: **3단계(학습자가 초안을 직접 고침)에 최소 4분.** 이 단계를 건너뛰면 실습의 학습 목표가 통째로 사라진다.
- 완료 기준: 파일이 실제로 저장돼 있고 / 학습자가 고친 흔적이 최소 1군데 있고 / 기준 1개로 실제 점검을 돌렸다.
- 상태: **실행 `[미검증]`** — 12명 교실 조건 리허설로 3단계 소요와 "파일 미생성" 오류 발생률을 실측할 것.
