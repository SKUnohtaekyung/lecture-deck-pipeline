## 고정 슬라이드 (구조 그대로, 텍스트만)
`kit/starter/deck-template.html`에 이미 들어 있다.

| 슬라이드 | 클래스 | 채우는 것 |
|---|---|---|
| 표지 | `slide cover` | 주차·한글 제목·발표자·브랜드/팀명·로고 + 3단 큐브 스택(3큐브·9면) |
| 도입 | `slide s02-slide` | eyebrow·주제 한 줄·리드·소개 문단 (+선택 페이퍼 컷 이미지) |
| 아젠다 | `slide s03-slide` | 제목·소개 + 번호 N항목(`.an-item` 반복 — 파트 수 또는 여정 단계 수, 3~6 권장·본문 짧게) |
| 파트 전환 | `slide part-divider` | 진행 도트·`PART n / N`·파트 제목·한 줄 설명 |
| 마무리 | `slide concept-recap` | 요약 리드·플로우 칩·N카드·배너 — **풀폭 상하 밴드**(v2). `.concept-panel`이 세로 flex로 메시지·플로우·카드·배너 4밴드를 쌓고 캔버스 전체 폭(1152px)을 쓴다. 플로우 칩(`flex:1`)·카드 그리드(`auto-fit`/`minmax`)는 개수(N)에 자동 대응해 3~6개 어느 쪽이든 CSS를 손대지 않는다. 좌측 컬럼에 콘텐츠를 몰아넣지 않는다. |
| (선택) 다크 마무리 | `slide closing` | 한 줄 요약 — recap 뒤에 추가 |

## 본문 슬라이드 골격
```html
<section class="slide <레이아웃클래스>" data-slide="B01">
  <header class="s-head">
    <svg class="s-logo" viewBox="0 0 96 96" aria-hidden="true"><line x1="28.8" y1="28.7" x2="49" y2="70" style="stroke:var(--mint)" stroke-width="18" stroke-linecap="round"/><line x1="70.9" y1="25.1" x2="49" y2="70" style="stroke:var(--blue)" stroke-width="19" stroke-linecap="round"/><circle cx="49" cy="70" r="9.5" style="fill:var(--ink)"/></svg><span class="s-brand">바이브코딩</span>
    <span class="s-line"></span><div class="s-team">팀명<br>부제</div>
  </header>
  <!-- .s-body-wrap(좌 컬럼) / .s-full(풀폭) / .center-msg(중앙) 중 레이아웃에 맞게 -->
  <div class="s-full">
    <p class="s-eyebrow">PART n · 파트명</p>
    <h2 class="s-title">이 슬라이드의 <span class="hl">결론</span></h2>
    ...
  </div>
</section>
```
- `data-slide`는 라벨(선택). 네비게이션은 DOM 순서로 동작.
- **헤더 우측 슬롯**: 위 `.s-team`(팀명) 마크업은 **고정 슬라이드**(표지·도입·아젠다·마무리)에서만 유지된다. **본문 슬라이드는 우측이 파트진행으로 대체** — JS가 `.s-part`(`PART n/N` + 진행 도트, 현재 파트=민트)를 자동 주입한다. 조립 시 본문 헤더에 팀명을 손으로 넣지 않는다.
- **하단 페이지네이션**: `n/전체` 페이지 번호를 JS가 `.s-pageno`로 자동 주입한다(표지·마무리 제외). 손으로 넣지 않는다.
- 본문 컨테이너 3종이 구도를 가른다: `.s-body-wrap`(좌 560px = split), `.s-full`(풀폭 = top-down/grid/diagram), `.center-msg`(중앙 = centered). 치트시트 참조.

## 발표 내비게이션
- 기본 바는 **고투명 Liquid Glass 재질**과 **반투명 회색 버튼**이다. 배경이 실제로 비쳐야 하며, blur·채도·밝기·빛 테두리·안쪽 하이라이트·다층 그림자가 함께 있어야 한다. 이전·다음·상세 메뉴·전체화면만 항상 보이고, 현재 페이지 숫자를 누르는 것도 상세 메뉴 열기로 연결한다.
- **리모컨은 마우스를 움직일 때만 나타난다.** 슬라이드 전환(방향키·PageUp/Down·Space·Home/End)으로는 리모컨을 띄우지 않는다 — 발표 중 화면을 깨끗이 유지하기 위해서다. 마우스 이동 시 나타나고 1초 뒤 사라진다(`mousemove→poke`). 마우스로 넘김 버튼을 누르는 경우는 이미 마우스가 화면에 있으므로 그대로 유지된다. 스타터 JS(`kit/starter/deck-template.html`)의 keydown 분기에는 `poke()`를 넣지 않는다.
- 상세 메뉴는 **옅은 쿨그레이 반투명 유리**로 기본 바보다 재질을 두껍게 표현한다. 메뉴에는 **홈(표지)** · **페이지 번호 이동** · **전체 슬라이드 목록** · **PDF 출력** · **단축키 안내**를 둔다. PDF 출력은 메뉴에서만 실행하고 인쇄 시 발표 UI는 숨긴다.
- `G`는 메뉴, `B`는 청중용 화면 가리기, `?`는 단축키 안내, `F`는 전체화면, `Esc`는 열린 창/가리기를 닫는다. 현재 위치는 URL `#slide=N`에 기록해 새로 열어도 같은 장으로 돌아간다.

## 파트 구조 (§0-3 필수)
- 각 파트는 **첫 슬라이드 앞에 `part-divider`** 를 반드시 둔다 — 맨 앞 1파트 포함. **파트 수 = divider 수.**
- 진행 도트(`.pd-dot`)는 파트 수만큼, `is-active`는 현재 파트. `PART n / N`의 N은 전체 파트 수.
- 본문 `.s-eyebrow`는 `PART n · <파트명>`으로 위치를 상기.

## 두 횡단 규칙
1. **색은 장식이 아니라 의미다** — 색을 아무 데나 예쁘라고 쓰지 않는다. 역할별로 못박는다:
   - **구조**(헤더 선·`.accent-bar`·`.s-eyebrow`·다이어그램/플로우 노드·표 헤더·UI)는 `--blue`.
   - **강조어**(제목·본문에서 결론·핵심이 되는 단어)는 **민트 계열을 문맥에 맞게** 고른다: `.hl-mint-text`(민트 글자 — 기본) · `.hl-mint-underline`(민트 밑줄 — 한 구절을 죽 그을 때) · `.hl-mint-mark`(글자폭 배경 — 가장 센 한 방). 강조는 민트가 기본값이다.
   - ⚠️ **블루 글자 강조(`.hl`)는 절제** — 구조와 직접 얽힌 주강조에만. **한 화면을 파란색으로 도배하지 않는다**: 제목 강조·본문 강조·배지·선이 전부 블루면 색이 의미를 잃고 눈이 피로하다. 강조가 파란색 일색으로 보이면 민트로 바꾼다.
   - `--blue-soft`=연한 배경 · `--periwinkle`=비강조 데이터 · 코랄=주의·경고 · 레드=오류·오답 · 민트=행동·안전·강조.
   - ⚠️ **navy 금지** — `var(--navy)` 사용 0. 어두운 배경/텍스트는 `--ink`(정의만 남김).
   - ⚠️ **그라데이션 금지** — 템플릿 전반 단색(표지 cover 포함).
   - ⚠️ **민트·코랄 fill 위 흰 글자 금지** → `--on-mint`/`--on-coral` 짙은 글자. 단, 글자폭만 감싸는 `.hl-mint-mark`은 흰 글자 허용 예외다.
   - ⚠️ **박스 표면 흰색-온-흰색 금지(2026-07-16)** — 흰 캔버스 위 카드/박스는 ① 의미 틴트 fill(구조=`--blue-soft` 기본 / 행동·성공=`--mint-soft` / 주의=`--coral-soft`) + 같은 계열 틴트 보더, 또는 ② 흰 fill + 명확한 유색 보더(`--blue-line-strong`/`--mint-line`/`--coral-line`) 중 하나로 구분한다. **흰 fill + `--line`(#E5E8F0) 근백색 보더 단독 조합은 verify FAIL.** `--line`은 표 셀선·`border-top`류 내부 구분선 전용. 예외: 코드/터미널 표면(`.viz-code`·`.cover-terminal`·`.co-bar`)·주석 스크린샷 창(`.shot-*`)·`.pd-dot`·표(`table.t`).
   - ⚠️ **넘버 행 수직 중앙(2026-07-16)** — 원형 배지+텍스트 행(`.work-step`·`.agenda-item`)은 텍스트를 배지 기준 수직 중앙에 둔다(`align-items:center`, verify 강제). 예외: `.s03-slide .an-item`(커넥터 좌표가 상단 정렬 전제).
2. **가운데 커넥터** — 두 요소를 이을 땐 파란 기호로 관계 명시: 흐름 `→` · 포함 `⊃` · 대비 `≠` · 검증/아래 `↓`.

## 리듬 규칙 (덱 전체 — 다양성)
- **직전 콘텐츠 슬라이드와 같은 구도 패밀리를 피한다**(같은 패밀리 3연속 절대 금지). 설명형(centered·top-down·grid)과 참여형(full-bleed·vertical-flow·diagram-centric) 교차.
- **split(좌우 비대칭)은 희소하게 · 연속 금지.** 역인덱스에서 후순위이며, 정보가 진짜 "글 주 + 시각 보조"일 때만.
- **제목은 주제명이 아니라 결론.** ("에이전트란?" ❌ → "에이전트는 말이 아니라 행동한다" ✅)
- 계획서의 슬라이드 묶음이 우선이다. 본문 줄 수와 레이아웃 capacity는 오버플로 경고 기준이며, `분할 허용`이 아니면 자동 분할하지 않는다.
- 활동 슬라이드엔 `.timing` 배지(예: `팀 실습 · 22분`).
- **세로 균형 — 하단 여백을 크게 남기지 않는다.** 콘텐츠를 캔버스 위쪽에 몰아 아래를 텅 비우면 미완성처럼 보인다. 정보가 적으면 ① 세로 중앙정렬(`.center-msg`는 이제 자동 중앙정렬)하거나 ② 요소를 키워/펼쳐 남는 세로를 채운다: `.s-full.fill`(격자·표가 남는 높이를 채움) · `.s-full.solo`(콜아웃 하나를 제목 아래 공간 **중앙에 크게**). 캔버스 720 전체를 균형 있게 쓴다.
- **박스 크기 = 정보량.** 카드·박스·콜아웃의 크기는 담긴 정보량에 비례해야 자연스럽다. 내용이 한 줄인 박스를 억지로 크게, 서너 줄인 박스를 억지로 작게 만들지 않는다. 한 격자 안에서 항목별 정보량이 크게 다르면 균일 그리드 대신 bento(대표 1 크게 + 보조 작게)나 행높이 가변으로 균형을 잡는다.
  - **패딩은 절대 기준으로도 점검한다** — 격자 안 상대 비교와 별개로, 박스 하나(배너·단일 콜아웃 등)만 있어도 패딩이 내용보다 크면 안 된다. 세로 패딩 합이 콘텐츠 자체 높이의 1/3을 넘으면 과하다: 1~2줄 배너/콜아웃은 세로 패딩 12~14px, 3줄 이상은 16~20px을 기준으로 삼는다. 완성 직후 "이 패딩, 안의 글자보다 커 보이나?"를 스스로 확인한다.
  - **폭도 절대 기준으로 본다(높이와 대칭)** — 짧은 문장 하나 담은 단독 박스를 컨테이너 폭에 맞춰 억지로 늘리지 않는다. 텍스트만큼만 폭을 잡고 `.hug-center`(`kit/styles/deck.css`)로 가운데 모은다. 진행 단계 칩(`.concept-flow` 등, 폭 전체가 "단계 사이 거리감"이라는 의미)이나 대비·체크리스트 격자 안 짝 콜아웃은 예외 — 그대로 폭을 채운다. `flex-direction:column` 부모 안에서는 `width`만으로 안 줄어들고 `align-self`도 같이 바꿔야 한다(`.hug-center`에 포함).
- **줄바꿈은 문맥 경계에서.** 수동 `<br>`은 단어를 끊지 않고 의미 단위(구·절) 경계에 넣는다 — 조사·어미가 앞줄에 매달리게 끊지 말 것(⭕ `확인할 수 있는<br>조건이 있는 요청` · ❌ `확인할 수 있는 조건이<br>있는 요청`). `word-break:keep-all`이 자동 줄바꿈의 단어 끊김은 막지만, 수동 줄바꿈의 위치는 가독성과 디자인(양쪽 줄 길이 균형)을 함께 보고 정한다.

## eyebrow / 제목
- eyebrow = 파트·맥락 **태그**(pill, `--blue-soft` 배경, 블루 글자, 작게). **본문 슬라이드만**(고정 슬라이드는 plain). 활동이면 `.timing` 추가.
- 제목(`.s-title`) = 결론을 1~2줄로 권장한다. 일반 강조는 `<span class="hl">`, 민트 강조는 `.hl-mint-text`·`.hl-mint-underline`·`.hl-mint-mark` 중 문맥에 맞게 선택한다.

## 접근성
- 색만으로 의미 전달 금지 → 아이콘/라벨 병행. PDF에서 색 이모지가 깨지므로 모노크롬 심볼(◆ ★ ◎ ※ ▲ ▷ ↓ ✓) 권장.
- 코드 시각화 element는 `role="img"` + 서술형 `aria-label`(값·관계를 문장으로).
