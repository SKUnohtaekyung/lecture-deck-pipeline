# 콘텐츠 초안 입력 형식 (교시별 표) · 아이콘 라우팅 · PART 매핑

> 워크플로우 1단계에서 참조. 스킬의 **공식 입력 템플릿**은 [`../입력양식/콘텐츠초안템플릿.md`](../입력양식/콘텐츠초안템플릿.md)이다. 이 문서는 그 형식을 **읽어 조립으로 옮기는 절차**를 상세히 규정한다.
> (옛 13라벨 `시각화 의도` 폼은 폐기 — `_dev/설계기록/폐기된-슬라이드계획서템플릿.md`.)

## 1. 인식 신호 (이 형식인지 판별)

아래를 만족하면 "콘텐츠 초안" 입력으로 본다:
- **아이콘 범례를 정의하는 서두**("읽고 시작해" 류) — 💬/🗣/👀의 뜻을 표로/불릿으로 정의.
- 교시(또는 섹션) 단위 헤딩 아래 **정확히 4열 마크다운 표**: `#` · `슬라이드 제목` · `본문 문구` · `비유·멘트`.
- **`시각화 의도` 열이 없음** — 정보 모양을 사람이 지정하지 않는다(스킬이 판단).
- 덱 메타(강의명·주차·발표자)는 별도 "덱 기본 정보" 표에 있거나, 없으면 조립 전 확인.

실례: `sessions/1주차/초안.md`(주차별 입력·산출은 `sessions/N주차/` — 규약 `sessions/README.md`).

## 2. 컬럼 매핑

| 열 | 조립에서의 쓰임 |
|---|---|
| `#` | 슬라이드 순서·라벨. `data-slide` 후보(예: `3-7`). `(간지)`·`(표지)`·`(마무리)` 표시는 고정 슬라이드 신호. |
| `슬라이드 제목` | 슬라이드 제목. **원문 그대로.** |
| `본문 문구` | 화면에 올라갈 실제 글. **원문 그대로.** `**굵게**`·`<br>` 등 마크다운 경식은 마크업으로 반영. |
| `비유·멘트` | 아이콘으로 라우팅(§3). 아이콘 없는 텍스트는 발표자 노트로. |

> **밀도 인지**: `본문 문구`는 이제 슬라이드당 정보 단위 3~6개(개념·비유/예시·비교·오해→교정·체크)로 조밀해질 수 있다(밀도 정본=콘텐츠 SKILL §0-6). 물리 한도(548px·22px 하한) 초과가 예상되면 재작성이 아니라 **PART 매핑처럼 조립 직전 분할 제안**(수용량 초과 시)·발표자 노트 이관을 검토한다. 소유권 경계(§2)는 그대로 — 본문 문장 자체는 재작성하지 않는다.

### 콘텐츠 소유권 경계 (SKILL.md·CLAUDE.md와 동일 원칙)
`슬라이드 제목`·`본문 문구`는 **콘텐츠팀 소유물이라 재작성하지 않는다.** 오타·명백한 마크다운 깨짐 정도만 손대고, 문장·표현·강조는 그대로 옮긴다.

## 3. 아이콘 라우팅 (고정 규칙)

| 아이콘 | 의미 | 목적지 | 화면 표시 |
|---|---|---|---|
| `💬` | 강사 농담/애드리브 | HTML 주석 `<!-- 발표노트: … -->` + 발표자 노트 HTML | **아니오** |
| `👀` | 강사 시연·관찰 유도 | HTML 주석 `<!-- 발표노트: … -->` + 발표자 노트 HTML | **아니오** |
| `🗣` | 막힐 때만 보여줄 완성 요청문 예시 | `.hint-reveal`(접힘 힌트) + 발표자 노트 HTML | **예 — 기본 접힘, 클릭 시 펼침, 인쇄해도 접힘** |
| (없음) | 일반 부연 | HTML 주석 + 발표자 노트 HTML | 아니오 |

- **한 셀에 아이콘이 여럿**이면(실제로 4-6·6-6 등) 아이콘 단위로 분리해 각각 독립 라우팅.
- 괄호 안 부가 텍스트("(막힐 때만)"·"(참고)"·수식어 없음 — 원본에 3가지 변형 모두 등장)는 라우팅 판단에 **영향 없음**. **아이콘 자체만 판별자.**
- **이모지 문자는 원고 마커일 뿐 — 최종 HTML에 그대로 노출 금지**(PDF 색-이모지 깨짐, `조립-리듬-불변요소.md` 접근성 절과 동일 이유). `.hint-reveal summary`엔 모노크롬 기호(▸/▾)나 "힌트 보기" 텍스트만. `verify_deck.py`가 이모지 누출을 **FAIL**로 잡는다.

### 🗣 → `.hint-reveal` 배치
`kit/styles/deck.css`의 `.hint-reveal`(네이티브 `<details>/<summary>`)을 본문 슬롯 안에 얹는다. 레이아웃 패밀리에 종속되지 않는 범용 마이크로 컴포넌트라 어떤 구도에도 삽입 가능. 안전망 예시 원문은 `.hr-body` 안에 **그대로**.

```html
<details class="hint-reveal">
  <summary>힌트 보기 <span class="hr-tag">막힐 때만</span></summary>
  <div class="hr-body"><p>현재 폴더에 첫메모.txt 파일을 만들고, 첫 줄에 'Codex 첫 연습'이라고 써 주세요.</p></div>
</details>
```

### 💬·👀 → HTML 주석
해당 `<section>` 안에 `<!-- 발표노트: (원문) -->`로 심는다 — 소스엔 남지만 화면·인쇄 어디에도 안 보인다. 같은 내용이 발표자 노트 HTML(§5)에도 정리된다.

## 4. PART 매핑 절차

- 콘텐츠 초안엔 **교시(1~6)만** 있고 PART 구조가 없다. PART는 구조·연출 결정이라 스킬이 임의로 정하지 않는다.
- **조립 직전 항상 사용자에게 확인**: "교시를 이렇게 N개 PART로 묶을까요?" 형태로 제안하고 승인받는다.
- 사용자가 지시문·템플릿에 **이미 매핑을 줬으면 그대로 수용**하고 재질문하지 않는다.
- 확정되면 파트마다 전환 슬라이드(`part-divider`)를 앞에 배치(§0-3 불변요소).

## 5. 발표자 노트 HTML 산출

콘텐츠에 💬/👀/🗣가 하나라도 있으면, 덱 조립 후 **별도의 `<덱이름>_발표자노트.html`**을 함께 만든다(스타터: `kit/starter/presenter-notes-template.html`).
- 슬라이드 순서대로 번호·제목 + 그 슬라이드의 💬·👀·🗣 멘트를 나열.
- **🗣는 펼쳐진 상태로** — 강사는 안전망 예시를 미리 다 봐야 하므로(수강생 화면과 반대).
- 메인 덱과 무관하게 열람 가능한 독립 문서. 1280×720 캔버스 제약 없이 읽기·인쇄 친화적으로.

## 6. "제목은 결론으로" 예외

`조립-리듬-불변요소.md`의 "제목은 결론으로"는 **스킬이 직접 짓는 제목**(형식 없는 브리프·추론 경로)에 대한 권장이다. 콘텐츠 초안의 `슬라이드 제목`이 질문형("AI가 뭐예요?")이어도 **스킬이 결론형으로 고쳐 쓰지 않는다** — 콘텐츠 소유권 경계(§2)가 우선.

## 7. 정보 모양 판단 (시각화 의도 필드 없음)

이 형식엔 `시각화 의도`가 없으므로 **모든 슬라이드에서** `kit/guide/정보모양-taxonomy.md`의 "미지정 추론 절차"로 정보 모양을 스킬이 직접 분류한다(SKILL.md §2). 판단 결과는 **슬라이드 결정표**(정보 모양·PART·힌트 유무)로 정리해 사용자 확인을 받은 뒤 조립한다 — 확인 없이 즉흥 조립하지 않는다.
