# 이미지 파일 · 주석 스크린샷 · 배포

> 워크플로우 6·9단계에서 참조한다. 이미지 필요성·`IMAGE_MODE`·`paper-cut-v1` 공통 프롬프트·역할·재사용·QA의 정본은 [`이미지-디렉션-프롬프트.md`](이미지-디렉션-프롬프트.md)다. 이 문서는 파일 배치와 화면 캡처·배포만 다룬다.

## 1. 이미지 파일 배치
- 시각화 기본은 코드 차트·다이어그램([`../kit/charts/`](../kit/charts/))이다. 이미지 정본에서 `IMAGE_EXPLANATORY`·`IMAGE_MNEMONIC` 또는 승인된 `IMAGE_DECORATIVE_OPTIONAL`로 판정한 슬롯만 파일을 연결한다.
- 세션 덱의 최종 이미지 경로는 `sessions/N주차/자료/images/`다. HTML에서는 덱 파일 기준 상대경로(예: `자료/images/sNN_<concept>.png`)를 사용한다.
- **`generate_now`**: 생성 원본이 외부 기본 폴더에 생겼다면 최종 선택본을 세션 폴더로 복사·이동하고, 투명화·QA를 통과한 PNG만 참조한다. 기존 파일을 덮어써야 한다는 지시가 없으면 `-v2`, `-v3`처럼 버전 파일명을 쓴다.
- **`prompt_only`**: 깨진 `<img>`를 만들지 않는다. `sessions/N주차/자료/이미지-프롬프트.md`·`이미지-에셋.json`과 같은 예상 경로를 `data-expected-src`에 기록한 `<figure data-image-state="expected">`만 둔다. 개발 덱에서는 예정 슬롯으로 보이지만, 필수 설명·기억 슬롯이 이 상태인 채로 배포되면 실패한다.

```html
<figure class="asset-slot asset-slot--hero" data-image-purpose="explanatory"
  data-image-state="expected" data-expected-src="자료/images/asset-001.png"
  role="img" aria-label="작은 요청 카드가 AI를 거쳐 완성된 웹페이지로 확장되는 관계"></figure>
```
- 도입(`s02`)이나 마무리도 자동 이미지 대상이 아니다. 이미지 정본의 필요성 판정과 역할·안전 여백 규칙을 동일하게 적용한다.

## 2. 주석 스크린샷 (화면 조작 안내)
- 정보 모양이 `screen-operation`이면 실제 화면 **캡처는 사용자가**, 번호·테두리 **overlay는 킷이 코드로**.
- element·CSS·배치법: [`../kit/screenshots/주석스크린샷.md`](../kit/screenshots/주석스크린샷.md). host 레이아웃은 `L-dc-annotated`(한 화면 여러 지점)·`L-vf-numbered-stack`(여러 화면 단계)·`L-dc-hero`(단일 화면).
- "여기" 대신 실제 버튼명·위치를 번호로. 캡처는 느리고 불안정하니 최소로.

## 3. 배포 — 단일 파일 (선택)
개발용은 `img/`·CSS 링크 참조(가벼움). 학생 배포·오프라인은 단일 HTML:
- `deck.css` + `legibility-40s.css` + kit-additions CSS를 `<style>`로 **인라인**.
- 이미지가 있으면 base64로 인라인(용량 크면 다운스케일). 목표 3~8MB(메일·USB).
- 유일한 외부 의존 = Pretendard 폰트 CDN. 완전 오프라인이 필요하면 폰트도 인라인하거나 시스템 폰트(맑은 고딕) 폴백 허용.
- 원본(dev)은 불변, `<덱>_배포.html`을 새로 생성.

## 4. 왜 코드 우선인가 (재확인)
코드 차트·다이어그램은 — 수정 즉시 반영 · 배율·인쇄에 항상 선명 · 파일 용량 0 · 텍스트라 접근성/검색 가능. 이미지는 설명이 꼭 필요하거나, 드물게 장식 목적의 시각적 리듬을 위한 스팟에만 — 기본값은 여전히 `NO_IMAGE`·코드 시각화다(장식 목적 채택 기준은 [`이미지-디렉션-프롬프트.md`](이미지-디렉션-프롬프트.md) §3 참고).
