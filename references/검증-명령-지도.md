## 1. 조립과 배포

```powershell
python scripts/assemble_deck.py courses/<과목>/sessions/N주차/강의덱.초안   # shard → 강의덱.html 재생성(덮어씀)
python scripts/inline_deck.py <덱>.html --offline                        # base64 단일파일 배포본
python -m http.server                                                   # file:// 금지, 로컬 HTTP로 검증
```

⚠️ **`courses/<과목>/sessions/N주차/강의덱.html`은 생성물이다.** 정본은 `강의덱.초안/`의 `shell.html`(head·고정 슬라이드·`<!-- ::PARTS:: -->` 마커·JS) + `part-NN.html`이고, `assemble_deck.py`가 이를 합쳐 덱을 **덮어쓴다**. 덱을 직접 고치면 다음 조립 때 유실되고, 생성물에만 있는 슬라이드는 조립 즉시 사라진다. 수정은 shard에 하고 조립한다. 규약 상세는 `sessions/README.md`.

- 이 규칙은 이제 **기계로 검출된다** — `hook_slide_guard.py --mode generated-guard`(양 플랫폼 PreToolUse)와 `.githooks/pre-commit`. 긴급 편집이 정말 필요하면 `DECK_EMERGENCY_EDIT=1`로 빠져나가되, 같은 내용을 shard에도 반영한다.
- 생성물과 shard가 어긋났다면 shard를 하나씩 맞추지 말고, 완성된 `강의덱.html`을 파트 경계로 잘라 shard를 재생성한 뒤 조립 결과를 조립 전 사본과 diff해 검증한다. **조립 전에는 반드시 현재 덱 사본을 떠둔다.**

## 2. 덱 검증 (정적)

```powershell
python scripts/verify_deck.py <덱>.html --parts N   # N = 그 덱의 part-divider 수(슬라이드 총수 아님 — 1·2주차 모두 6)
python scripts/verify_deck_quality.py <덱>.html     # 저밀도·근-빈 컨테이너·시각자료 비율·부록 강등 + 문체 규칙(R-COPY-01~04·R-DECO-01 — 3층 정본 kit/guide/문체-원칙.md · 임계는 과목 프로필 §3-G)
python scripts/verify_draft_quality.py <주차>       # .md 초안 단계: 저밀도·노트과다·교시당 장수·필수 산출물
python scripts/check_title_survival.py <주차>       # 초안 제목이 덱 화면에 살아남았는가(--strict로 exit 1)
python scripts/report_draft_sync.py <주차>          # 초안-덱 대조 리포트(--strict: 초안에만/덱에만 >0 → exit 1)
python scripts/verify_report_freshness.py <주차>    # 보고·결정표 신선도 — 기준 덱 식별자·[시점 스냅샷] 선언 대조(--strict: 위반 >0 → exit 1)
python scripts/verify_notes.py <덱> <노트> --snapshot|--baseline   # 노트 회귀 (R-NOTE-02)
```

> 내용 품질 게이트 2종(`verify_draft_quality`·`verify_deck_quality`)은 **기본 WARN**이고 `--strict`로 FAIL 승격한다. 2주차 저밀도 사고 이후 신설된 것이라 회귀가 아니다. 임계값 도출 근거는 `_dev/설계기록/품질감사-2026-07/`.

### ★ 러너 — 조립 이후 검사를 한 명령으로 잇는다

```powershell
python scripts/run_deck_checks.py <주차>                    # 정적 게이트 + 노트 + 렌더 증거 판정
python scripts/run_deck_checks.py <주차> --assemble --parts N
```

**덱을 고쳤으면 이걸 돌려라.** 렌더 증거가 없거나·덱보다 낡았거나·INVALID면 종료코드 1이다. 「필수」를 사람 기억에 맡기지 않기 위한 장치다.

배치1(P1 · 2026-08-17)부터 러너가 함께 강제하는 것 — ① verify_deck의 **보존 게이트**(계약 공동화 금지 · intro∪sequences ↔ 덱 data-slide 양방향 완전성 · must_keep 절대사수, waiver 규약은 `sessions/README.md` 「주차 구조 계약」) ② `check_title_survival`·`report_draft_sync`·`verify_notes MISMATCH`의 **count 래칫**(계약 waiver의 count 초과만 FAIL) ③ **구조 WARN 래칫**(요약 최상단에 총계 노출 · 계약 `warn_baseline` 대비 증가 FAIL). 무사유 waiver는 작동하지 않고 pre-commit(`verify_contract_waivers.py`)이 커밋을 차단한다.

배치3(P4 · 2026-08-17)부터 **렌더 수치도 판정한다** — ④ 결함형 6종(바닥선초과·이탈·겹침·어절잘림·오버플로·빈슬롯)은 계약 waiver `render_<지표>` 베이스라인(없으면 0) 초과 시 FAIL ⑤ 타이포·정렬류(폰트하한·자간·정렬충돌)는 **렌더 WARN 래칫**(계약 `warn_baseline.render` 대비 증가만 FAIL — WARN 시작·오탐률 실측 후 승격). 임계값은 러너에 없다 — 집행은 `audit_render.js`(BODY_*), 선언 정본은 `kit/guide/한장-참조표.md`(회귀 테스트가 쌍을 고정). 밀도 계열은 계속 사람검토다(R-DENS-03).

배치4(2026-08-17)부터 ⑥ **품질 WARN 래칫** — `verify_deck_quality`의 품질 WARN 총계도 계약 `warn_baseline.quality` 대비 증가만 FAIL(규칙 임계는 불변 — 프로필 §3-G). 1·2·3주차 베이스라인은 검출분 전량 분해(실위반/예외/오탐) 후 사유와 함께 확정 등재됐다(D-2) — 분해는 각 계약 warn_baseline.note가 정본.

**A-1 판정 — 렌더·품질 WARN 래칫의 FAIL 승격은 «보류»다(2026-08-18 · 감상이 아니라 수치가 근거다).**

1~3이 남은 차단 사유이고, **4는 같은 날 반복측정으로 해소했다**(처음엔 차단 사유로 올렸다가 실측이 뒤집었다).

## 3. 브라우저 렌더 감사 (필수 — 종료코드가 못 보는 것을 잡는다)

```powershell
python -m http.server 8799
```
브라우저에서 덱을 열고 콘솔에서:
```js
await document.fonts.ready;
await Promise.all([...document.images].map(i => i.complete ? null : new Promise(r => { i.onload = i.onerror = r; })));
await eval(await (await fetch('/scripts/audit_all.js?v=' + Date.now(), {cache:'no-store'})).text())
```
출력 JSON을 `sessions/_verify/<주차>/deck-audit.json`으로 저장하면 `run_deck_checks.py`가 그것을 증거로 판정한다(없으면 통과시키지 않는다).

**출력 JSON은 바이트 그대로 저장한다 — 콘솔 출력을 손으로 옮겨 적지 마라**(9KB+ 이스케이프 문자열의 전사는 오류 위험이다). 에이전트 세션(인앱 브라우저)의 안전한 경로(2026-08-17 1주차 측정 실증):

1. 결과를 변수에 보관: `window.__audit = await (await fetch('/scripts/audit_all.js')).text().then(eval)` — 인앱 브라우저의 javascript 실행 도구에서 top-level `await`가 구문 오류를 내면 `(async () => { … })()` IIFE로 감싼다.
2. **1회용 POST 수신기**를 백그라운드로 띄운다(요청 1건 받고 종료 · CORS 허용):
   ```powershell
   python scripts/receive_audit.py <주차>
   ```
3. 콘솔에서 전송: `await fetch('http://localhost:8798/', {method:'POST', body: window.__audit})` → `POST 200` 확인.
4. 수신기가 저장하며 `schema=deck-audit/1`·`INVALID`를 자체 점검한다 — `slideCount`=덱 계수까지 본 뒤 `run_deck_checks.py <주차>`로 판정한다.

⚠️ **창을 1280×720 이상으로 열어라.** 작으면 덱 JS가 `--scale`을 0으로 계산해 전 장이 0으로 나오고, 그 상태의 「결함 0」을 통과로 오판한 사고가 있다(2026-08-03 재현). 이제 두 감사기가 fail-closed assert로 막고 `{ INVALID:[...] }`를 돌려준다.

| 감사기 | 검출 |
|---|---|
| `audit_render.js` | 잉크 점유율 · 바닥선(666) 초과 · 슬라이드(720) 이탈 · 요소 겹침 · 단어 중간 줄바꿈 · 박스면적÷글자수 · 빈 asset-slot · 껍데기 컨테이너 |
| `audit_typography.js` | 역할별 폰트 하한 · 자간 광학 보정 누락(≥32px) · 행간 normal 잔존 · 근-미스 앵커(지배값 ±1~5px) |
| `audit_all.js` | 위 둘을 함께 돌려 러너용 압축 증거 생성 |

## 8. 사고 이력 — 왜 이 게이트들이 있는가

이 절은 **규칙의 근거**다. 값이 아니라 이유를 담으므로 과목이 바뀌어도 유지된다.

### 8.1 종료코드가 통과했다고 화면이 멀쩡한 것이 아니다 (2026-07-31)

`verify_deck`·`verify_deck_quality`가 FAIL 0으로 통과한 덱에서 실제로는 단어 중간 줄바꿈 250건, 한 문장이 48px 칸에 갇힌 사례 13건, 22px 하한 미만 242건, 슬라이드 밖으로 480px 밀려난 요소, 빈 이미지 슬롯 24개가 화면에 있었다. **조립 후에는 반드시 브라우저에서 전수 측정한다.** 정적 검사로 승격할 수 있었던 것은 `R-QC-18`(빈 슬롯)·`R-QC-19`(격자 안 맨 텍스트)로 `verify_deck_quality.py`에 넣었다.

### 8.2 검출기의 「0」이 눈먼 범위 안의 0일 수 있다 (2026-08-03)

`audit_render.js`가 ① `hasOwnText` 조건 때문에 `<img>`·`<figure>`·`<svg>`를 바닥선·이탈 검사에서 **통째로 빼고** ② 겹침을 `.s-full` 2단계까지만 봐서 최소 17장은 아예 검사하지 않았다. 둘 다 고친 뒤 재측정하니 1주차 바닥선 초과가 **17 → 25건**으로 늘었다(전부 이미지 계열).

**검사 범위를 넓힐 때는 오탐률을 함께 재라.** 겹침 검사를 깊이만 풀었더니 2주차에서 잡힌 7건이 전부 오탐이어서(인라인 요소의 합집합 상자) 인라인 제외 + 절대배치 분리로 좁혀야 했다. — 이 원칙 때문에 `generated-guard`·`tmp-guard`도 **관측 모드로 먼저 돌린 뒤** 차단으로 승격한다.

**2026-08-18 실측 — 범위를 «좁힐» 때도 같은 규율이 걸린다.** `audit_typography.js`의 코드 티어 셀렉터에 `.terminal-bar`를 더해 검출 1건을 걷어냈다. 좁히는 변경은 「오탐이 줄었다」가 아니라 **「눈이 멀었다」가 될 수 있으므로** 전후를 함께 쟀다: 2주차 폰트하한 183→**182**(제거 1건 = C3-N3 터미널 창 제목줄), 자간 11·정렬충돌 1·렌더 결함형 6종 **전부 변동 0**, 1주차 57→**57**(변동 없음), 3주차 0→**0**. 부수 제거 0을 확인한 뒤에만 반영했다.

**오탐률 실측(전 주차 폰트하한 239건 기준)** — 승격 판정의 분모다:

| 분류 | 건수 | 비율 | 성격 |
|---|---:|---:|---|
| 실위반 | 223 | 93.3% | 하한 미달이 맞다 |
| 규칙 공백 | 16 | 6.7% | 1주차 S05A 축소 재현 mock — R-TYPE-01에 티어가 없어 감사기가 **원리적으로** 구분 불가 |
| 감사기 오탐 | 0 | 0% | 1건 있었고(터미널 크롬) 이번에 고쳤다 |

⚠️ **배치4가 계약에 적었던 「오탐 75」는 현물 재측정으로 폐기됐다** — 그 76건(클래스 계열 실계수)은 전량 20px·25~101자 한국어 산문 문장이었다. **오탐률을 「세어 본 수」가 아니라 「그럴 것 같은 수」로 적으면 그 수치가 waiver 사유가 되어 규칙을 갉아먹는다.**

### 8.3 장을 지우거나 옮기면 6종이 딸려 온다

노트 밀림 · divider 번호 단조성 · family 오판 · 목차 세로 예산 · 실습 번호 · 이미지 매니페스트. 정본은 `references/phases/04-조립.md` `R-MOVE-01`. 노트를 건드리는 작업은 `verify_notes.py --snapshot`/`--baseline`으로 감싼다(`R-NOTE-02`). **2026-08-03 실측: 1·2주차 노트가 둘 다 FAIL 상태였고 아무도 안 돌리고 있었다** — 그래서 지금은 `.githooks/pre-commit`이 노트 변경을 잡는다.

### 8.4 규칙 문서를 고쳤으면 집행부도 고쳤는지 확인한다 (유형⑤)

「정본표에 값을 적었다」와 「kit CSS가 그 값을 낸다」는 다른 일이다. 실측: 정본표가 선언한 값 중 **8건이 kit에서 실현되지 않고** 각 주차 shell 오버라이드에만 있었다 — kit을 직접 쓰거나 다른 과목에 배포하면 원상복귀하는 상태다. 못 고치는 사정이 있으면 **사유와 함께 등재**하고, 등재 없는 새 불일치는 FAIL이다(`verify_declared_vs_enforced.py`).

⚠️ **불일치를 없애려고 문서 쪽 값을 낮추지 마라** — 규칙을 현실에 맞춰 깎는 것이다.

### 8.5 수정 라운드를 마칠 때 규칙층 승격을 판정한다 (R-FEEDBACK-01)

같은 지적이 2회 이상이면 슬라이드 문제가 아니라 규칙 문제다. **등재 위치를 반드시 적는다** — 「고쳤다」로 끝내면 그 주차 shell에만 남아 다음 주차가 상속하지 못한다. 승격 전에 기존 지표와 충돌하는지 함께 본다. 정본 `references/phases/08-검증.md`.

> 실측된 실패율: 사용자가 준 §0 전역 규칙 11건 중 스킬층으로 올라간 것은 **2건뿐**이었다. 환류 규칙이 문장으로만 있고 집행 절차가 없어서다.
