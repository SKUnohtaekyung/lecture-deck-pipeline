# 7단계 — 발표자 노트 HTML
> 이 문서는 7단계에서만 로드한다. 정본 규칙은 규칙 ID로 참조한다.

참조: `kit/starter/presenter-notes-template.html` — 7단계, 발표자 노트 HTML 복제 원본.

## 발표자 노트 HTML 산출 (R-NOTE-01b)

초안에 `💬`/`👀`/`🗣`가 하나라도 있으면 `kit/starter/presenter-notes-template.html`을 복제해 **`<덱이름>_발표자노트.html`**을 만든다 — 슬라이드 순서대로 번호·제목 + 그 슬라이드의 멘트를 종류별로 나열. **`🗣`는 펼쳐진 상태**로(강사는 안전망 예시를 미리 다 봐야 하므로 — 수강생 화면과 반대). 메인 덱과 별개 파일(같은 폴더에 둔다 — 세션 폴더면 `courses/<과목>/sessions/N주차/`). (R-NOTE-01b)

## pn-no 재번호·기계 대조 (R-NOTE-01c)

- **발표자 노트(`강의덱_발표자노트.html`)는 멘트가 있는 장만 담고, `pn-no`는 보이는 페이지 번호와 일치해야 한다.** 구성 변경 시 삽입 지점 이후를 다시 매기고, 노트에는 이모지·힌트가 허용되며 `🗣`는 펼친 상태로 둔다(학생 덱과 반대). (R-NOTE-01c)
## 노트 작업 전후 스냅샷 (R-NOTE-02 · 2026-08-03 신설)

> **왜 필요한가**: `scripts/verify_notes.py`에 `--snapshot`/`--baseline`이 **이미 구현돼 있는데 언제 쓰라는 절차가 없었다.** 이 저장소의 반복 패턴이다 — 도구는 있고 배선이 없다. 그 결과 2주차에서 덱만 고치고 노트를 두고 가 **MISMATCH 101건**이 됐고, 3-way 병합에서 **살아 있는 장의 강사 멘트 4건이 유실**됐다.
>
> **2026-08-03 실측: 1·2주차 노트가 둘 다 `verify_notes` FAIL 상태다.** 아무도 이 검사를 돌리지 않고 있었고, 신설 러너(`run_deck_checks.py`)가 처음 표면화시켰다.

**노트나 덱의 장 구성을 건드리는 작업은 이렇게 감싼다:**

```bash
# 착수 전 — 현재 멘트 총량을 기록
python scripts/verify_notes.py <덱>.html <노트>.html --snapshot tmp/notes-before.json
#   … 작업 …
# 종료 후 — 멘트가 줄거나 사라졌는지 대조
python scripts/verify_notes.py <덱>.html <노트>.html --baseline tmp/notes-before.json
```

- ⚠️ **설계상 트레이드오프 — 제목을 고치면 「소실」로 오탐한다.** 식별자가 «`pn-no` + 제목»이라 제목 수정이 곧 짝의 상실이다. 그런데 제목 수정은 사실상 매 라운드 발생한다. **별칭 없이 이 검사를 의무화하면 상시 FAIL이 된다.**
- **그래서 제목을 바꿀 때는 별칭을 남긴다**: 그 라운드의 작업 기록에 «옛 제목 → 새 제목» 한 줄. 대조 시 이 표를 먼저 적용하고 남은 것만 소실로 판정한다.
- **덱에서 장을 지우거나 옮겼으면 같은 작업에서 노트를 반드시 재조립한다**(R-MOVE-01의 1번 항목).

- **재번호는 손으로 하지 말고 스크립트로 일괄 처리한다** — 삽입 지점 이후 전부 시프트라 손으로 고치면 중간에 충돌한다. `re.sub(r'<span class="pn-no">(\d+)</span>', lambda m: ... n+시프트 if n>=기준 else n, s)` 한 번으로 끝내고, 끝나면 **덱의 N번째 `data-slide`와 노트 `pn-no`를 기계적으로 대조**해 검증한다(순서 단조·범위 확인 포함). (R-NOTE-01c)
