# 6단계 — 이미지 판정·모드 실행
> 이 문서는 6단계에서만 로드한다. 정본 규칙은 규칙 ID로 참조한다.

참조: [`references/이미지-디렉션-프롬프트.md`](../이미지-디렉션-프롬프트.md) ★ — 4·6단계, 이미지 필요성·`IMAGE_MODE`·paper-cut-v1·프롬프트·에셋 재사용·QA 정본. [`references/이미지-스크린샷-배포.md`](../이미지-스크린샷-배포.md) — 6·9단계, 이미지 파일 배치·주석 스크린샷·단일파일 배포.

## 이미지 판정·모드 게이트 (R-IMG-01)

**이미지 판정·모드 게이트** — `정보 모양·시각 element 결정 → 이미지 목적 판정 → 중앙 레지스트리에서 승인 에셋 재사용 검색 → generate/transform 수 산출 → 필요한 경우 IMAGE_MODE 확인` 순서를 지킨다. 판정은 `NO_IMAGE | IMAGE_EXPLANATORY | IMAGE_MNEMONIC | IMAGE_DECORATIVE_OPTIONAL` 네 가지다. (R-IMG-01)

## 재질문 최소화 (R-IMG-01a)

승인 에셋 재사용만으로 충족되거나 신규 작업이 0장이면 질문하지 않는다. 신규 생성·변형이 있어도 사용자가 자율 실행을 요청했거나 명확한 계획에서 생성·삽입을 지시했다면 `generate_now` 권한이 주어진 것으로 보고 재질문하지 않는다. `generate_now | prompt_only` 선택이 모호하고 실제 산출물을 바꿀 때만 한 번 묻고, 답 전에는 해당 이미지 작업만 보류한다. 세부 계약은 [`references/이미지-디렉션-프롬프트.md`](../이미지-디렉션-프롬프트.md)를 따른다. (R-IMG-01a)

## 이미지 판정 시점·모드 질문 (R-IMG-01b · R-IMG-01c · R-IMG-01d)

- 시각 element 후보까지 결정한 뒤 [`references/이미지-디렉션-프롬프트.md`](../이미지-디렉션-프롬프트.md)의 기준으로 네 상태 중 하나를 판정한다. 장식 이미지는 사용자가 시각적 풍부함을 명시한 경우에만 `IMAGE_DECORATIVE_OPTIONAL` 후보가 되며, 파트당 최대 1장·비연속·차트/다이어그램과 동시 사용 금지다. 이어 `kit/images/paper-cut-v1/registry.json`에서 `approved` 에셋을 먼저 찾는다. 재사용으로 충족되지 않는 generate/transform이 있고 사용자가 자율 실행·생성 계획을 주지 않았으며 모드에 따라 산출물이 달라질 때만 아래 두 선택지를 제시한다: (R-IMG-01b)

> 이미지가 필요한 슬라이드는 N장입니다. 어떤 방식으로 진행할까요?
> 1. 이미지 바로 생성 — 생성·투명화·검수 후 덱에 삽입
> 2. 프롬프트만 제작 — 파일명과 슬롯, 생성용 프롬프트 시트만 작성

(R-IMG-01c)

- 모드 질문이 필요한 경우에도 답을 기다리는 동안 이미지에 의존하지 않는 조립·점검은 계속할 수 있다. 신규 생성·변형이 0장이거나 자율 실행 권한이 명확하면 슬라이드별 판정과 재사용 Asset ID 또는 `NO_IMAGE` 이유를 결정표와 `자료/이미지-에셋.json`에 남기고 질문 없이 진행한다. (R-IMG-01d)

## 이미지 슬롯 계약 (R-IMG-02a)

이미지 슬롯은 `<figure class="asset-slot asset-slot--hero" data-image-purpose="explanatory" ...>` 계약을 사용하고 활성 역할은 `hero | support | spot`뿐이다. 설명·기억 이미지는 관계를 설명하는 한국어 `alt`가 필수이며 장식 이미지는 `alt="" aria-hidden="true"`다. `prompt_only`는 `<img>`를 만들지 않고 figure에 `data-image-state="expected" data-expected-src="…"`만 둔다. `cover-object`·`section-overlay`는 승인된 별도 템플릿 변형이 없으므로 사용하지 않는다. (R-IMG-02a)

## 이미지 실행 정본 3계층 (R-IMG-01e)

이미지 판정·의미 브리프·출력 경로별 프롬프트·재사용·투명 PNG QA는 [`references/이미지-디렉션-프롬프트.md`](../이미지-디렉션-프롬프트.md)를 따른다. 중앙 승인 정본은 `kit/images/paper-cut-v1/registry.json`, 세션 실행 정본은 `courses/<과목>/sessions/N주차/자료/이미지-에셋.json`, 사람용 대응 문서는 `이미지-프롬프트.md`다. 상세 계약을 이 문서나 플랫폼 어댑터에 복제하지 않는다. (R-IMG-01e)

## 표지·기본 이미지 (R-IMG-05)

기본 표지는 스타터의 큐브 구도를 사용하고 생성 이미지는 S02부터 검토한다. 다만 사용자가 표지 구도·장식 변경을 명시하면 엔진 hook·브랜드·안전영역을 지키며 바꿀 수 있다. `paper-cut-v1`은 투명 오브젝트 전용이며 사진·풀블리드는 사용자 제공 자산 또는 별도 승인 스타일을 사용한다. (R-IMG-05)

## generate_now 절차 (R-IMG-06)

**`generate_now`**: 에셋별 초기 생성은 한 번씩 별도 호출한다. built-in 경로는 **균일 마젠타 배경만** 요구하는 크로마 원본 프롬프트를 쓰며 native alpha 문구를 섞지 않는다. 승인된 native-alpha 경로는 **진짜 투명 배경만** 요구하고 크로마 문구를 섞지 않는다. 의미·스타일 교정은 1회, 알파 후처리 재시도는 1회까지다. 이후 설명·기억 이미지는 중단·보고하고, 장식 이미지는 반려 기록 후 생략한다. 통과한 최종 PNG만 `courses/<과목>/sessions/N주차/자료/images/`에 저장·등록·연결한다. (R-IMG-06)

## prompt_only 절차 (R-IMG-07)

**`prompt_only`**: `courses/<과목>/sessions/N주차/자료/이미지-프롬프트.md`와 `이미지-에셋.json`에 의미 브리프·역할·예상 파일·프롬프트를 기록한다. HTML figure는 `data-image-state="expected"`와 `data-expected-src`만 가지며 실제 `<img src>`는 두지 않는다. 개발 덱에서는 깨진 이미지가 없어야 하고 배포는 unresolved 설명·기억 슬롯 때문에 실패해야 한다. (R-IMG-07)

## 화면 조작 안내 (R-SHOT-01)

화면 조작 안내(`screen-operation`)는 이미지 모드와 별개다. 실제 화면은 사용자가 캡처하고, 번호·테두리 overlay는 **주석 스크린샷** 킷([`kit/screenshots/`](../../kit/screenshots/))으로 구현한다. 파일 배치·캡처·배포 상세는 [`references/이미지-스크린샷-배포.md`](../이미지-스크린샷-배포.md)를 따른다. (R-SHOT-01)
