# 5단계 — 시각화 element 선택
> 이 문서는 5단계에서만 로드한다. 정본 규칙은 규칙 ID로 참조한다.

참조: **마크업 복사**: `kit/layouts/catalog.html`·`kit/charts/catalog.html`(코드 코어) — 없는 구도만 `데모_제작규칙.html` (C4).

## 본문 슬라이드 element 검토 (R-ASM-02)

본문 슬라이드: [`kit/layouts/catalog.html`](../../kit/layouts/catalog.html)·[`kit/charts/catalog.html`](../../kit/charts/catalog.html)의 코어를 우선 검토하되, 카탈로그가 정보량·이미지 크기·결과 품질을 제한하면 토큰·가독성·안전영역 계약만 지키는 독립 구도를 설계할 수 있다. 정보량이 부족하면 빈 카드나 과도한 여백 대신 GUI·다이어그램·실제 캡처·설명 이미지 중 정보 모양에 맞는 수단으로 보강한다. 코드 시각화는 유력한 선택지이지 절대 우선 규칙이 아니다. (R-ASM-02)

## 카탈로그는 "코어 + 변형" 설계 (R-ASM-03)

**카탈로그는 "코어 + 변형" 설계다.** `by-shape.md`의 레이아웃 54·element 23은 **추천 어휘집**이고, 실제 마크업은 **코어 12(레이아웃)·8(차트)**만 둔다. 역인덱스가 고른 ID의 마크업이 없으면 가까운 코어가 정보 모양과 품질을 보존할 때만 변형한다. 코어가 결과를 제한하면 앞 절의 독립 구도를 사용하고 근거를 결정표에 한 줄 남긴다. (R-ASM-03)

## 환류 규칙 (R-LAYOUT-03)

⚠️ **환류 규칙(재사용 가능한 신규 구도)**: 새 구도가 다른 주차에서도 반복 사용할 수 있는 일반 패턴이면 그 `<section>`을 해당 `catalog.html`에, CSS를 `kit/styles/patterns.css`에 환류하고 `python scripts/verify_kit.py`로 확인한다. 특정 슬라이드의 인상적인 결과물처럼 맥락 의존적인 독립 구도는 data-slide/전용 클래스에 좁게 스코프한 세션 CSS로 유지해 카탈로그를 오염시키지 않는다. (R-LAYOUT-03)

## R-D3-01 D3.js 조건부 도입 정책

**HTML/CSS 우선.** 비교·단계·개념도·3~7항목 플로우·단순 막대는 D3를 쓰지 않는다.

**D3 검토 조건**(아래 중 하나에 해당할 때만 검토):
- 데이터 포인트가 8개를 넘고 정확한 스케일이 필요하다
- 노드가 10개 이상인 관계·계층을 그린다
- 데이터가 바뀌면 자동 재배치가 필요하다

**도입 시 의무**:
- CDN 금지 · 로컬 벤더링(`kit/vendor/d3.min.js` — 첫 실수요 시 추가한다. 지금은 벤더 파일을 만들지 않는다)
- 정적 폴백 필수
- `aria-label` 필수
- 슬라이드당 복잡 시각화 1개
- 1280×720 고정
- 렌더 완료를 실측으로 확인
