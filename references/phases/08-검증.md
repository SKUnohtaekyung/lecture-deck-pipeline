## 정적 검증 스크립트로 어서션 자동 채점 (R-VERIFY-01)

**① 정적 검증 스크립트로 어서션 자동 채점**: `python scripts/verify_deck.py <덱>.html --parts N` — 슬라이드·고정슬라이드·**part-divider=파트수**·네비/PDF·deck.css+legibility·**코드시각화 vs 이미지**·**구도 다양성·같은 구도 연속**·토큰(raw #hex)·**아이콘 마커 누출(💬/🗣/👀)**·**힌트 리빌 `<summary>`**를 한 번에. (R-VERIFY-01)

## 브라우저 전수 검사 (R-VERIFY-01a)

**② 브라우저로 전체 장수 오버플로·콘솔·가독성 검사**(스크립트가 못 재는 것): 로컬 http 서버로 서빙하고, 완료 전 **모든 슬라이드**를 1280×720과 실제 인앱 브라우저 크기에서 각각 순회한다. 활성 슬라이드의 모든 descendant `getBoundingClientRect()`가 캔버스 안에 있고 형제 정보 요소가 교차하지 않는지, 이미지 computed `object-fit:contain`과 의도하지 않은 crop이 없는지, `scrollWidth/Height ≤ client`인지 확인한다. 콘솔 에러 0 · Pretendard 로드 · 본문 22px · 모든 `.s-head`의 표준 로고 · 검정 터미널 본문 `var(--white)`(프롬프트·커서만 민트)도 함께 검사한다. 학생 덱의 `.hint-reveal`·강사용 문구는 0이어야 한다. **박스 패딩 과다도 이 단계에서 확인**: 배너·콜아웃·카드가 눈에 띄면 `offsetHeight` vs `padding:0` 임시적용 시 높이를 비교해 패딩 비중을 재본다(1/3 넘으면 줄임 — §핵심 규칙 참조). (R-VERIFY-01a)

## 한 명령으로 잇기 (R-VERIFY-01a2 · 2026-08-03 신설)

```bash
python scripts/run_deck_checks.py <주차> --parts N
```

조립 → 정적 게이트 → 노트 → **렌더 증거 판정**을 한 번에 돈다. 렌더 증거(`sessions/_verify/<주차>/deck-audit.json`)가 **없거나 · 덱보다 낡았거나 · INVALID거나 · 장수가 다르면 exit 1**이다. 증거는 브라우저에서 만든다:

```bash
python -m http.server 8799
# 브라우저(창 1280x720 이상)에서 덱을 열고 콘솔:
#   await (await fetch('/scripts/audit_all.js')).text().then(eval)
# 출력 JSON을 sessions/_verify/<주차>/deck-audit.json 으로 저장
```

- **왜 러너가 필요한가**: 문서 네 곳이 렌더 감사를 「필수」라 적었지만 **어떤 실행 경로에도 배선돼 있지 않았다.** `assemble_deck.py`는 `verify_*`를 호출하지 않고, 유일한 훅은 스스로 "실패해도 도구 호출을 막지 않는다"고 적었다. 결과가 규율에만 좌우됐다 — 2026-07-31 사고는 그 규율이 실패한 경우다.
- **부분 실행은 exit 3**(`--skip-render`·`--render-only`). 0과 구분되는 이유는 **부분 실행이 완전 통과로 읽히는 것**이 이 저장소가 반복해서 겪은 사고이기 때문이다.
- ⚠️ **감사기의 「0」을 곧이곧대로 믿지 마라.** 2026-08-03에 `audit_render.js`의 사각지대 2건(이미지가 바닥선 검사에서 통째로 빠짐 · 겹침을 2단계까지만 봄)을 고쳤더니 1주차 바닥선 초과가 **17 → 25건**이 됐다. 검사 범위를 넓힐 때는 **오탐률을 함께 재라**.

## 측정 우선 (R-VERIFY-01b)

스크린샷은 정적이라 불안정·느림 → **측정 우선, 스크린샷은 증빙 최소**. (R-VERIFY-01b)

## scale 환산 (R-VERIFY-01c)

**`getBoundingClientRect()` 값은 `--scale`로 나눠 덱 좌표(1280×720)로 환산한 뒤 판정한다.** 덱 루트에 `--scale = min(w/1280, h/720)` 변환이 걸려 있어, 창이 작으면 모든 rect가 축소돼 **하단 666px 기준을 자동으로 통과한다**. 실측 사례(2026-07-22): 같은 스크립트가 축소 뷰포트에서 "문제 0"을 냈고, `scale=1`에서 다시 재니 30장이 잡혔다. 스크립트 반환값에 `scale`을 같이 실어 1인지 확인하라. (R-VERIFY-01c)

## 래퍼 제외 (R-VERIFY-01d)

**래퍼를 빼고 말단 요소만 잰다.** `.s-full`·`.dv-hero` 같은 전면 배경 래퍼는 원래 720px까지 차지하므로 그대로 재면 전부 오탐이다. 자식 엘리먼트가 있으면서 자기 텍스트가 없는 노드는 제외하고, 텍스트를 가진 노드와 `IMG`만 판정 대상으로 삼는다. (R-VERIFY-01d)

> ⚠️ **「텍스트를 가진 노드와 IMG」의 뒷부분이 오래 구현되지 않았었다**(2026-08-03 규명·수정). `audit_render.js`의 판정 조건이 `hasOwnText` 하나뿐이라 `<img>`·`<figure>`·`<svg>`는 아무리 아래로 내려가도 **영원히 잡히지 않았다.** 그래서 「이탈 0」이 이미지에 대해서는 아무것도 증명하지 못하는 값이었다. 고친 뒤 1주차 바닥선 초과가 **17 → 25건**이 됐다(늘어난 8건이 전부 이미지 계열).
> **전면 배경 예외는 「폭 95% 이상 + 상단이 0에 붙음」으로 좁힌다** — 히어로 삽화까지 면제하면 다시 눈이 먼다.

## 라운드 종료 — 지적을 규칙으로 회수한다 (R-FEEDBACK-01 · 2026-08-03 신설)

> **왜 규칙층에 올렸나**: 환류 규칙(«같은 지적이 2회 이상이면 규칙 문제로 판정해 승격»)이 **문장으로만 있고 집행 장치가 없었다.** 실제 결과: 사용자가 준 §0 전역 규칙 중 스킬층으로 올라간 것이 극소수였고, 나머지는 그 주차 shell에만 남아 다음 주차에 상속되지 않았다. **「같은 지적이 매 주차 반복된다」의 기계적 원인이 이것이다.**

**수정 라운드를 마칠 때 아래 표를 산출한다.** 산출물이 없으면 그 라운드는 끝나지 않은 것이다.

| 이번 라운드 지적 | 반복 횟수 | 판정 | 등재 위치 | 기존 규칙과 충돌? |
|---|---|---|---|---|

- **판정 기준**: 서로 다른 슬라이드에서 **2회 이상** 나왔으면 슬라이드 문제가 아니라 **규칙 문제**다.
- **등재 위치를 반드시 적는다.** 「고쳤다」로 끝내면 그 주차 shell에만 남는다. 규칙층(`references/phases/`·`kit/guide/`) 또는 신규 주차 템플릿(`sessions/_template/`)에 올려야 다음 주차가 상속한다.
- **⚠️ 충돌을 함께 본다.** 선례: 사용자 지시 §0-1(「문장 — 부연」을 별도 줄로 분리)과 `R-QC-15`(하단 콜아웃 비율 상한)는 **지시를 이행할수록 지표가 나빠진다.** 충돌을 안 보고 올리면 서로 당기는 규칙이 쌓인다. 충돌이 있으면 승격하지 말고 사람에게 회부한다.
- **⚠️ 자동 승격으로 만들지 않는다.** DOM만 봐서는 「변주 실패」와 「사용자가 확정한 서식」이 갈리지 않는다. 이것은 **체크 항목**이지 검사기가 아니다.
- **⚠️ 로드량을 늘리지 마라.** 이 저장소는 로드량 78% 감축 리팩터링을 한 적이 있다. 규칙을 통째로 복사하지 말고 **요지 + 포인터**로 등재한다.

**회귀인지 원래 그런지는 기준선과 대조해서만 말한다.** `git show <착수전커밋>:<덱경로> > courses/<과목>/sessions/N주차/_baseline_tmp.html`로 같은 폴더에 뽑아(상대 CSS 경로가 살아야 한다) 동일 스크립트로 재고 슬라이드 ID 집합을 비교한 뒤 임시 파일을 지운다. (R-VERIFY-01e)

## 렌더 실측 실행 절차 (scripts/measure_render.js)

위 ②·01c·01d를 코드화한 것이 `scripts/measure_render.js`다. 헤드리스 도구는 도입하지 않는다 — 인앱 브라우저에서 손으로 돌린다.

1. **로컬 http 서버로 서빙한다.** `python -m http.server` — `file://`로 열지 않는다.
2. 인앱 브라우저로 덱을 연다. CSS를 캐시하므로 변경 확인 때는 `deck.css` 링크에 `?v=` 를 붙인다.
3. 콘솔에 `scripts/measure_render.js` 전체를 붙여넣어 주입한다.
4. **반환값의 `scale`이 1인지 먼저 확인한다.** 1이 아니면 창을 1280×720 이상으로 키우고 다시 잰다 — 축소 뷰포트에서는 모든 rect가 줄어 666px 기준을 **자동으로 통과**한다(R-VERIFY-01c). `scaleIsOne:false`면 반환 객체에 `WARNING`이 함께 실린다.
5. `measureRender({all:true})`로 **전 슬라이드를 순회**한다. 순회 모드는 발견이 있는 장만 `results`에 담고, 숨은 장은 실측 후 원래 `display`로 되돌린다.
6. 결과 4종(`belowFloor`·`overlaps`·`figureMismatch`·`overflow`)을 **주차 계약의 `known_violations`와 대조**한다. 계약에 등재된 기존 결함은 그대로 두고, 목록에 없는 항목만 이번 변경의 회귀로 본다(R-VERIFY-01e).

이 스크립트는 **판정하지 않는다 — 목록만 낸다.** 통과 여부는 사람이 계약과 대조해 정한다. 정적 검증(`verify_deck.py`) PASS를 이 단계의 대체로 쓰지 않는다.
