# 이미지 디렉션과 프롬프트 정본 — `paper-cut-v1`

이 문서는 `vibecoding-deck`에서 사용하는 강의 이미지의 단일 정본이다. 코드 차트·다이어그램으로 설명하는 것이 우선이며, 이미지가 설명력을 실제로 높이는 슬라이드에만 이 규칙을 적용한다.

기본 스타일은 `paper-cut-v1`이다. 사용자가 다른 스타일을 명시적으로 요청한 경우에만 아래의 **스타일 변경 워크숍**을 거쳐 새 버전을 승인한다. 승인 전 후보 스타일을 실제 덱 에셋에 섞지 않는다.

기준 보드: `kit/images/paper-cut-v1/designboard.png`

## 1. 불변 조건

- 결과물은 `.png`이며 실제 알파 채널이 있는 완전 투명 배경이어야 한다.
- 흰 배경, 단색 배경, 체크무늬를 그린 배경은 투명으로 인정하지 않는다.
- 프롬프트는 영어로 작성한다.
- 기본적으로 읽을 수 있는 텍스트, 글자, 숫자, 타이포그래피, 로고, 워터마크를 넣지 않는다. 한글은 예외 없이 금지한다.
- 제목·본문·캡션은 이미지에 굽지 않고 슬라이드 HTML의 텍스트로 배치한다.
- 표지·본문·섹션 이미지 모두 동일한 스타일 계약과 투명 PNG 조건을 따른다. 역할에 따라 크기, 비율, 구도, 여백만 달라진다.
- 이미지 프롬프트의 hex 값은 생성 모델의 색 재현을 위한 지시다. HTML/CSS에서는 raw hex가 아니라 기존 색 토큰만 사용한다.

## 2. `paper-cut-v1` 스타일 계약과 공통 프롬프트

아래 블록은 고정한다. 슬라이드마다 대괄호 필드만 구체화한다.

```text
[STYLE CONTRACT: VIBECODING PAPER-CUT v1]

Use case: stylized-concept
Asset type: transparent lecture-slide illustration

Create a premium editorial paper-cut illustration for an adult-beginner
AI and vibecoding lecture deck.

Use thick fine-fiber paper, crisp die-cut edges, shallow layered relief,
and restrained internal contact shadows only where paper layers overlap.
Keep the geometry clean, modular, calm, confident,
and readable at slide-thumbnail size.

Color system:
- Cool paper white #F4F8FB and light surface #F3F5F8: approximately 60%
- Royal blue #1D4ED8 and pale blue #EEF3FE: approximately 25%,
  used for structure, containers, and connectors
- Teal mint #14B8A6 and deep teal #0F766E: approximately 10%,
  used for action, progress, and successful states
- Coral #F97360: less than 5%, used only for small error or caution accents
- Near-black #141821: sparse structural anchors only

SUBJECT: [slide-specific subject or metaphor]
ROLE: [cover-object | hero | support | spot | section-overlay]
COMPOSITION: [object placement, hierarchy, and component relationship]
TEXT_SAFE_SIDE: [left | right | top | none]

Build one coherent metaphor from a small set of coordinated paper components.
Preserve generous negative space on TEXT_SAFE_SIDE.
Use a strong silhouette and avoid unnecessary decoration.

Final output requirement:
transparent PNG with genuine alpha, clean anti-aliased edges,
no backdrop, canvas, floor, frame, card,
or cast shadow outside the object.

Avoid people, faces, hands, readable text, letters, numbers, logos,
watermarks, arrows, checkmarks, conventional UI glyphs,
decorative leaves, organic backdrop blobs, robots, brains,
circuit-board motifs, neon, glossy plastic, glassmorphism,
photorealism, gradients, white-background cutouts,
and simulated checkerboards.
```

`SUBJECT`에는 하나의 명확한 시각적 비유를 쓴다. `COMPOSITION`에는 위치, 크기, 방향, 구성요소의 관계를 쓰고 `TEXT_SAFE_SIDE`와 충돌하지 않게 한다. 한 이미지에 서로 무관한 비유를 여러 개 넣지 않는다.

## 3. 슬라이드별 이미지 필요성 판단

레이아웃과 element를 결정한 뒤 각 슬라이드를 `NO_IMAGE` 또는 `IMAGE_REQUIRED`로 판정하고 이유를 기록한다.

다음 중 하나면 `NO_IMAGE`를 우선한다.

- 차트, 코드, 프로세스 다이어그램만으로 핵심 정보가 충분히 전달된다.
- 이미지가 본문을 장식적으로 반복한다.
- 정보 밀도가 높아 이미지가 시선 경쟁을 만든다.
- 이미 승인된 에셋으로도 설명력을 더할 수 없다.
- 이미지가 개념을 지나치게 단순화하거나 오해를 만든다.

다음 중 하나면 이미지를 고려한다.

- 추상 개념을 하나의 명확한 비유로 압축할 수 있다.
- 표지나 섹션 전환에 기억 가능한 시각 앵커가 필요하다.
- 비교, 변화, 관계를 코드 시각화보다 더 빠르게 이해시킨다.
- 학습자가 이후 내용을 회상할 수 있는 반복 모티프가 필요하다.

`NO_IMAGE`도 정상 결과다. 장식을 채우기 위해 판정을 `IMAGE_REQUIRED`로 바꾸지 않는다.

## 4. 이미지 역할 프리셋

| 역할 | 용도 | 구도 계약 |
|---|---|---|
| `cover-object` | 표지의 대표 오브젝트 | 큰 단일 실루엣, 제목 영역 반대편에 넉넉한 여백 |
| `hero` | 핵심 개념 설명 | 하나의 강한 비유, 본문 반대편에 충분한 여백 |
| `support` | 본문 보조 | 중간 크기, 텍스트보다 낮은 시각 우선순위 |
| `spot` | 작은 강조 | 단순한 단일 오브젝트, 넓은 투명 여백 |
| `section-overlay` | 섹션 전환 | 가로로 넓은 투명 오브젝트 군집, 배경은 이미지에 포함하지 않음 |

모든 역할은 실제 투명 PNG다. 이미지 안에 슬라이드 제목·레이블을 넣지 않는다.

## 5. 이미지 모드 게이트

필요 이미지 수를 확정한 뒤 `IMAGE_REQUIRED`가 한 장 이상이고 사용자가 방식을 미리 지정하지 않았다면 반드시 한 번 질문하고 멈춘다.

> 이미지가 필요한 슬라이드는 N장입니다. 어떤 방식으로 진행할까요?  
> 1. 이미지 바로 생성 — 생성·투명화·검수 후 덱에 삽입  
> 2. 프롬프트만 제작 — 파일명과 슬롯, 생성용 프롬프트 시트만 작성

```text
IMAGE_MODE = generate_now | prompt_only
```

- 요청에 모드가 이미 명시되어 있으면 다시 묻지 않는다.
- 필요 이미지가 0장이면 질문을 생략하고 각 슬라이드의 `NO_IMAGE` 사유를 남긴다.
- 답변을 받은 뒤 선택한 모드의 산출 분기부터 실행한다.
- 직접 생성 기능을 사용할 수 없으면 `prompt_only`로 조용히 바꾸지 말고 사용자에게 알린다.

### `generate_now`

- 에셋마다 이미지 생성 도구를 한 번씩 개별 호출한다. 서로 다른 에셋을 한 호출의 변형 수로 대체하지 않는다.
- Codex에서는 기본적으로 built-in `$imagegen` 경로를 사용한다.
- 투명 이미지의 built-in 원본은 피사체에 쓰지 않는 완전 균일한 마젠타 `#ff00ff` 크로마키 배경으로 생성한다. 배경에는 그림자, 그라데이션, 텍스처, 반사, 바닥면, 조명 변화가 없어야 하고 피사체 외부 그림자도 없어야 한다.
- 생성 원본을 프로젝트 작업공간으로 복사한 뒤 설치된 `$CODEX_HOME/skills/.system/imagegen/scripts/remove_chroma_key.py`를 사용한다. `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill`을 기본값으로 쓴다.
- 최종 파일은 `sessions/N주차/자료/images/`에 저장한다. 프로젝트에서 참조하는 이미지를 `$CODEX_HOME/generated_images/`에만 남기지 않는다.
- 알파 채널, 투명 모서리, 피사체 면적, 키 컬러 프린지, 금지 요소, 슬라이드 충돌을 검수한 파일만 HTML에 연결한다.
- 얇은 프린지는 `--edge-contract 1`로 한 번 재시도할 수 있다. 복잡한 반투명 소재이거나 로컬 투명화가 실패하면 CLI `gpt-image-1.5`로 자동 전환하지 않는다. true native transparency와 `OPENAI_API_KEY`가 필요한 모델/경로 변경임을 설명하고 사용자 승인을 받은 뒤에만 전환한다.

### `prompt_only`

- 산출물은 재현 가능한 프롬프트 패키지와 대응 이미지 슬롯이다.
- `sessions/N주차/자료/이미지-프롬프트.md`에 슬라이드 ID, 판정 이유, 역할, 권장 화면비, `SUBJECT`, `COMPOSITION`, `TEXT_SAFE_SIDE`, 재사용 후보 ID, 예상 파일명, 완성 프롬프트를 기록한다.
- HTML에는 동일한 예상 경로를 사용하는 이미지 슬롯만 둔다.

## 6. 에셋 재사용과 레지스트리

새로 생성하기 전에 승인 에셋을 검색한다. 비유, 스타일 버전, 역할, 화면비, 텍스트 안전 영역이 맞으면 재사용하거나 비파괴 변형한다.

- 승인 에셋 ID: `ASSET-001`부터 순차 부여
- 탐색 후보 ID: `CANDIDATE-<style>-01`
- 권장 파일명: `asset-001-concept-name-paper-cut-v1-transparent.png`
- 상태: `candidate | approved | retired | rejected`
- 승인 원본은 주차별 `자료/images/`에 두고, 재사용 시 원본 ID와 사용 슬라이드를 기록한다.
- 새 스타일 버전이 승인되어도 기존 에셋의 ID와 생성 당시 스타일 버전을 바꾸지 않는다.
- `retired`와 `rejected`는 삭제 대신 이유를 기록해 재생성 낭비와 같은 실패의 반복을 막는다.
- 모든 검수 뒤 승인 또는 반려 결과와 사유를 해당 에셋 행에 기록한다.

레지스트리의 최소 필드:

| Asset ID | 파일명 | 스타일 버전 | 비유 | 역할 | 화면비 | 안전 영역 | 사용 슬라이드 | 상태 | 비고 |
|---|---|---|---|---|---|---|---|---|---|

## 7. 생성 전·후 품질 검수

### 생성 전

- 현재 승인된 스타일 버전이 `paper-cut-v1` 또는 사용자가 명시적으로 승인한 후속 버전인가?
- 시각 비유가 슬라이드의 핵심 메시지와 직접 연결되는가?
- 역할, 구성요소 관계, 화면비, `TEXT_SAFE_SIDE`가 구체적인가?
- 실제 알파 PNG와 글자 금지 조건이 포함되었는가?
- 같은 용도로 재사용 가능한 승인 에셋이 없는가?

### 결과 파일

- PNG 파일에 실제 알파 채널이 있고 네 모서리가 투명한가?
- 흰색·단색·체크무늬 배경이나 외부 그림자가 남아 있지 않은가?
- 가장자리에 흰 테두리, 검은 할로, 키 컬러 번짐, 거친 프린지가 없는가?
- 한글 및 승인하지 않은 텍스트·글자·숫자·로고·워터마크가 없는가?
- 재료, 가장자리, 깊이, 색 비율이 현재 스타일 계약과 일치하는가?
- 축소했을 때도 핵심 실루엣이 읽히는가?
- 슬라이드에 배치했을 때 제목·본문·컨트롤과 충돌하지 않는가?

하나라도 실패하면 승인 에셋으로 등록하거나 HTML에 연결하지 않는다. 검수 결과와 승인·반려 사유는 레지스트리에 남긴다.

## 8. 명시적 스타일 변경 워크숍

사용자가 `paper-cut-v1`과 다른 이미지 무드를 명시적으로 요청한 경우에만 수행한다.

1. 강의 주제와 한 문장 핵심 메시지, 대상과 숙련도, 기대 감정, 텍스트·차트 비율, 선호 매체, 인물 사용 여부, 참고/회피 이미지, 친근함·실험성·고급감 우선순위를 작은 질문 묶음으로 확인한다. 한 번에 모두 묻지 말고 앞선 답에 따라 다음 질문을 좁힌다.
2. 팔레트만 다른 유사안이 아니라 매체, 질감, 시각 언어, 정서가 분명히 다른 후보 3–5개를 만든다. 각 후보 카드는 이름, 핵심 인상, 팔레트, 매체·질감, 조명, 구도, 인물 처리, 장점, 위험, 샘플 프롬프트를 포함한다.
3. 메시지 적합성, 학습자 친화성, 슬라이드 가독성, 여러 장 확장성, 시각 차별성, 생성 안정성, 투명 PNG 적합성을 항목별 1–5점과 한 줄 근거로 비교한다.
4. 사용자가 한 후보를 명시적으로 승인한 뒤에만 `mood-vN` 스타일 계약과 공통 프롬프트를 확정한다. 승인 기록에는 선택 후보, 선택 이유, 유지할 요소, 수정할 요소, 탈락 후보와 이유, 사용자 승인 문장, 승인 날짜를 남긴다.
5. 버전형 스타일 계약에는 팔레트, 매체·렌더링, 재질·질감, 조명, 카메라·시점, 형태 언어, 인물 처리, 시각 은유, 피사체 복잡도, 여백, 금지 요소를 통제 필드로 둔다. 재현 기준에는 반드시 반복할 요소, 슬라이드별 가변 요소, 허용 변형, 스타일 이탈 조건, 승인 대표 이미지 경로를 기록한다.
6. 후속 버전은 바뀐 필드와 기존 승인 에셋의 호환 여부를 명시한다. 승인 전 후보는 현재 계약을 덮어쓰지 않는다.
