# 3주 바이브코딩 아카데미 — 6대목차 구조와 1주차 상세안 v2

## 1. 운영 구조

- 전체 과정: 3주 × 주 6시간
- 주차별 구성: 6개 대목차
- 기본 리듬: 50분 수업 + 10분 휴식
- 원칙: 한 교시에 하나의 분명한 학습 경험과 결과물을 남긴다.
- 현재 설계 우선순위: 1주차를 먼저 세밀하게 확정한 뒤 2·3주차를 구체화한다.
- 제외 사항: 3주차 AI API 연결 수업은 진행하지 않는다.
- 앱 기준: 새로운 ChatGPT 데스크톱 앱 안의 Chat·Work·Codex 구조를 기준으로 설명한다.
- 접근성 원칙: Work가 보이지 않는 계정도 있을 수 있으므로 필수 실습은 Codex만으로 완주할 수 있게 한다.

### 한 교시의 공통 구성

각 50분은 대체로 다음 흐름을 따른다. 세부 시간은 콘텐츠와 실습이 확정된 뒤 조정한다.

1. 앞 교시와 연결하고 이번 교시의 질문 제시
2. 꼭 필요한 개념 설명
3. 강사 시연 또는 사례 비교
4. 수강생 실습·토의·관찰
5. 결과 확인과 다음 교시 연결

# 2. 3주 전체 6대목차

## 1주차 — AI와 협업해 첫 웹페이지 만들기

> AI에게 어떻게 요청하고 수정해야 내가 원하는 웹 결과물을 만들 수 있을까?

| 교시 | 대목차 | 핵심 경험 | 교시 결과 |
|---:|---|---|---|
| 1교시 | 바이브코딩 과정 이해하기 | 3주 과정의 목표와 AI 협업 방식 이해 | 개인 학습 목표 |
| 2교시 | AI에게 제대로 요청하기 | 좋은 요청과 나쁜 요청을 비교하고 수정 | 첫 개발 요청문 |
| 3교시 | Codex와 첫 작업 준비하기 | 폴더를 열고 AI가 파일을 만들고 수정하는 과정 경험 | 연습 폴더와 첫 파일 |

| 5교시 | 대화하며 화면과 기능 발전시키기 | 디자인 수정과 간단한 동작 추가 | 개인화된 자기소개 페이지 |

- 개인화된 자기소개 웹페이지

- 수정 전·후 비교 결과
- 오류 또는 예상과 다른 결과를 고친 경험

## 2주차 — 아이디어를 기획하고 작동하는 서비스로 만들기

### 주차 핵심 질문

> 내 아이디어를 누구를 위한 어떤 서비스로 정의하고, 핵심 기능이 작동하게 만들려면 어떻게 해야 할까?

| 교시 | 대목차 | 핵심 경험 | 교시 결과 |
|---:|---|---|---|
| 1교시 | 아이디어를 사용자 문제로 바꾸기 | 대상·상황·문제·해결 방식 정의 | 서비스 한 줄 소개 |
| 2교시 | 서비스 범위와 이용 흐름 정하기 | 핵심 기능과 제외 기능, 사용자 흐름 결정 | 간단한 기획 문서 |
| 3교시 | 화면 구조와 디자인 방향 정하기 | 랜딩과 핵심 화면의 정보 순서 설계 | 화면 구성안 |
| 4교시 | AI와 서비스 첫 화면 만들기 | 기획을 실제 랜딩페이지로 변환 | 서비스 첫 화면 |
| 5교시 | 핵심 기능이 작동하게 만들기 | 입력·선택·버튼·결과 중 핵심 흐름 구현 | 작동하는 MVP |
| 6교시 | 다른 사람에게 사용시키고 개선하기 | 사용자 테스트와 우선순위 수정 | MVP 1차 완성본 |

### 2주차 대표 산출물

- 서비스 한 줄 소개
- 간단한 서비스 기획 문서
- 화면 구성과 디자인 방향
- 랜딩페이지
- 핵심 사용자 흐름 하나가 작동하는 MVP
- 사용자 테스트 결과와 수정 목록

## 3주차 — 서비스를 완성하고 인터넷에 공개하기

### 주차 핵심 질문

> 내 컴퓨터에서 만든 결과물을 어떻게 다른 사람이 접속하고 사용할 수 있는 서비스로 완성할까?

| 교시 | 대목차 | 핵심 경험 | 교시 결과 |
|---:|---|---|---|
| 1교시 | 최종 범위 확정과 프로젝트 정리 | 기능 추가를 멈추고 완성 기준 결정 | 최종 작업 목록 |
| 2교시 | 저장 기능과 재방문 경험 만들기 | 필요한 데이터 저장·불러오기 | 저장 가능한 서비스 |
| 3교시 | 사용성과 완성도 높이기 | 빈 입력·오류·모바일·문구·디자인 점검 | 배포 전 완성본 |
| 4교시 | 프로젝트를 온라인에 보관하기 | 파일 정리와 온라인 저장소 활용 | 온라인 프로젝트 저장소 |
| 5교시 | 인터넷에 배포하고 실제 환경에서 검수하기 | 공개 URL 생성과 다른 기기 테스트 | 최종 공개 URL |
| 6교시 | 결과물을 소개하고 공유하기 | README·QR·대표 화면·발표 구성 | 공유 패키지와 발표 |

### 3주차 대표 산출물

- 저장 기능이 포함된 최종 서비스
- 정리된 프로젝트 파일 또는 온라인 저장소
- 인터넷 공개 URL
- QR 코드
- 프로젝트 소개 문서
- 대표 화면
- 1분 프로젝트 발표

### 3주차 도구 선택 원칙

- GitHub, Vercel 등은 현재 가능한 후보 도구이지 교육 목표 자체가 아니다.
- 실제 강의 환경과 수강생 수준에 따라 더 단순한 저장·배포 방식으로 바꿀 수 있다.
- 중요한 것은 특정 서비스를 익히는 것이 아니라 프로젝트를 보관하고, 공개하고, 다른 환경에서 검수하는 경험이다.
- AI API 연결은 이번 과정의 목차와 필수 산출물에서 제외한다.

# 3. 1주차 상세 설계

## 1주차 전체 학습 목표

1주차가 끝나면 수강생은 다음을 할 수 있다.

1. 바이브코딩의 기본 과정을 자신의 말로 설명한다.
2. Chat·Work·Codex의 역할 차이를 구분한다.
3. 목적·조건·완료 기준이 포함된 개발 요청을 작성한다.
4. Codex가 생성한 파일을 찾고 변경 결과를 확인한다.
5. 화면과 문구를 자신의 의도에 맞게 수정한다.
6. 간단한 버튼 동작을 추가한다.
7. 예상과 다른 결과를 설명하고 한 단계씩 고친다.

## 1주차 전체 스토리라인

> AI와 생성형 AI를 이해한다 → Chat·Work·Codex의 역할을 파악한다 → 바이브코딩의 의미와 과정을 이해한다 → 요청하는 법을 배운다 → Codex와 파일 작업에 익숙해진다 → 첫 화면을 만든다 → 대화하며 발전시킨다 → 오류를 고치고 학습 경험을 정리한다.

## 1교시. AI와 바이브코딩 이해하기

### 교시 핵심 질문

> AI는 무엇이며, AI와 함께 코딩한다는 것은 어떤 과정일까?

### 학습 목표

- AI와 생성형 AI의 기본 개념을 이해한다.
- 바이브코딩의 정의와 기본 과정을 설명한다.
- 전통적인 코딩 학습과 바이브코딩 학습의 차이를 안다.
- AI와 사람의 역할을 구분한다.
- 이번 과정에서 필요한 학습 태도를 이해한다.

### 세부목차

1. AI란 무엇인가
2. 생성형 AI란 무엇인가
3. 바이브코딩이란 무엇인가
4. 바이브코딩의 기본 과정
   - 원하는 결과 생각하기
   - AI에게 요청하기
   - 결과 생성하기
   - 직접 실행하고 확인하기
   - 수정하고 다시 확인하기
5. 전통적인 코딩 학습과의 차이
6. AI가 잘하는 것과 사람이 판단해야 하는 것
7. 하나의 ChatGPT 앱 안에서 만나는 세 가지 작업 방식
   - Chat: 빠른 질문과 대화
   - Work: 조사·분석·문서와 결과물 제작
   - Codex: 로컬 파일과 코드를 다루는 소프트웨어 개발
8. 이번 과정에서 중요하게 보는 태도
   - 완벽한 첫 결과보다 빠른 확인
   - 한 번에 많이 요청하지 않기
   - 결과를 직접 실행하고 검증하기
   - 막히면 증상을 설명하기
9. 수강생의 현재 경험과 기대 확인

### 포함할 콘텐츠 후보

- AI·생성형 AI·바이브코딩의 관계를 보여주는 간단한 개념도
- 바이브코딩의 기본 과정을 보여주는 순환 그림
- 전통 코딩과 바이브코딩의 비교표
- 하나의 ChatGPT 앱 안에 Chat·Work·Codex가 있는 구조를 보여주는 화면 또는 역할 지도
- AI가 만든 결과에서 사람이 확인해야 할 사례
- 수강 전 자기진단 또는 손들기 질문
- 완성된 결과물 짧은 티저 또는 수업 후반 예고 화면

### 실습·참여 후보

- 내가 AI로 해본 일 한 가지 공유하기
- 제시된 사례가 일반 AI 활용인지 생성형 AI 활용인지 구분하기
- 바이브코딩의 다섯 단계를 올바른 순서로 배치하기
- 제시된 작업을 “AI가 잘할 일 / 사람이 판단할 일”로 분류하기
- 전통 코딩 학습과 바이브코딩의 차이를 한 문장으로 정리하기

### 교시 산출물

- AI와 바이브코딩의 차이를 정리한 한 문장
- 바이브코딩 기본 과정 순서

### 오프닝 연출 선택지

완성 결과물을 시작부터 길게 보여주는 것은 필수로 두지 않는다. 다음 두 방식 중 전체 PPT 스토리라인에 맞춰 선택한다.

1. **개념부터 시작:** AI와 바이브코딩을 먼저 설명하고, 1교시 마지막에 오늘 만들 결과물을 짧게 보여준다.
2. **짧은 티저 후 개념 시작:** 설명 없이 완성 화면을 30초~1분만 보여준 뒤 “이 결과를 만드는 방식이 바이브코딩”이라고 연결한다.

현재 권장안은 **AI 개념부터 시작하고, 바이브코딩의 정의와 기본 과정을 설명한 뒤 결과물을 짧게 보여주는 방식**이다. 수업의 논리적 출발점을 AI에 두면서도, 개념 설명이 길어지기 전에 실제 결과로 연결할 수 있다. 완성 결과물은 기능을 자세히 시연하기보다 “이런 결과를 AI와 함께 만들어 간다”는 수준의 짧은 예시로 사용한다.

### 다음 교시 연결

> AI와 함께 만들 수 있다는 것은 확인했다. 그렇다면 AI에게 무엇을 어떻게 말해야 원하는 결과가 나올까?

## 2교시. AI에게 제대로 요청하기

### 교시 핵심 질문

> AI가 내 의도를 알아서 맞히기를 기다리지 않고, 원하는 결과를 분명하게 전달하려면 어떻게 해야 할까?

### 학습 목표

- 막연한 요청과 실행 가능한 요청의 차이를 구분한다.
- 개발 요청에 필요한 핵심 정보를 안다.
- 큰 요청을 작은 단계로 나눈다.
- 첫 생성 요청과 수정 요청을 구분한다.
- AI가 생성한 결과를 검토하고 사용하는 사람의 책임을 설명한다.

### 세부목차

1. 같은 AI가 서로 다른 결과를 만드는 이유
2. 나쁜 요청과 좋은 요청 비교
3. 좋은 개발 요청의 기본 구성
   - 만들고 싶은 것
   - 사용할 사람
   - 필요한 내용 또는 기능
   - 원하는 분위기나 제약
   - 완료 여부를 확인할 기준
4. 추상적인 표현을 구체적인 조건으로 바꾸기
   - “예쁘게 만들어줘”
   - “전문적으로 만들어줘”
   - “사용하기 쉽게 만들어줘”
5. 한 번에 모든 것을 요청할 때 생기는 문제
6. 큰 목표를 작은 요청으로 나누는 방법
7. 처음 만드는 요청과 수정하는 요청의 차이
8. AI의 결과를 확인하기 전에 다음 요청을 하지 않는 원칙
9. AI를 사용할 때의 책임의식
   - “AI가 만들었다”는 말이 결과에 대한 책임을 대신하지 않음
   - 제출·공개·사용하기 전에 사람이 직접 확인해야 함
   - 모르는 내용을 아는 것처럼 단정하지 않기
   - AI의 결과를 그대로 복사하기보다 목적에 맞게 검토·수정하기
10. AI 결과를 사용할 때 확인할 항목
   - 사실과 숫자가 정확한가
   - 개인정보나 민감정보가 포함되지 않았는가
   - 다른 사람의 저작물이나 표현을 무단으로 사용하지 않았는가
   - 특정 사람이나 집단을 차별하거나 해칠 수 있는 내용이 없는가
   - 코드와 링크가 안전하고 실제로 작동하는가
   - 내가 다른 사람에게 설명할 수 있는 결과인가
11. AI 사용의 최종 원칙
   - 생성은 AI가 도울 수 있지만 판단과 사용 결정은 사람이 한다.

### 포함할 콘텐츠 후보

- 동일한 주제의 나쁜 프롬프트와 개선된 프롬프트 결과 비교
- 요청 구성 요소를 블록처럼 보여주는 도식
- 모호한 표현을 확인 가능한 조건으로 바꾸는 사례
- 과도한 요청과 단계별 요청의 결과 비교
- 수강 중 계속 사용할 공통 요청문 골격
- “AI가 만들었으니 그대로 제출해도 될까?” 상황 사례
- AI 결과를 공개하기 전 확인해야 할 책임 체크리스트
- 잘못된 정보·개인정보·출처 불명 이미지·위험한 코드가 포함된 사례

### 실습·참여 후보

- 모호한 요청문 고쳐 쓰기
- 다섯 가지 요구사항 중 빠진 요소 찾기

- 자기소개 웹페이지를 위한 첫 요청문 작성하기
- 자신의 요청문에 완료 기준이 보이는지 체크리스트로 확인하기
- AI가 만든 결과에서 사용 전 확인해야 할 위험 요소 찾기
- “이 결과를 그대로 공개해도 되는가?” 사례별 판단 활동

### 교시 산출물

- 자기소개 웹페이지 첫 개발 요청문

- AI 결과물 공개 전 확인할 개인 체크리스트

### 책임의식 핵심 문장

> AI는 결과를 만드는 일을 도울 수 있지만, 그 결과를 믿고 제출하고 공개하고 사용하는 결정은 사람이 한다. 따라서 최종 결과를 확인하고 설명할 책임도 사용자에게 있다.

이 문장은 법적 책임의 범위를 단정하는 표현이 아니라, 수강생이 AI 결과를 무비판적으로 사용하지 않도록 만드는 교육 원칙으로 사용한다.

- 초보자가 쉽게 이해할 수 있는 AI 오정보·개인정보·저작권·코드 안전 사례는 무엇인가?
- 책임의식을 겁을 주는 방식이 아니라 좋은 사용 습관으로 전달할 비유는 무엇인가?

## 4교시. AI와 첫 웹페이지 만들기

### 교시 핵심 질문

> 내가 작성한 요청을 실제로 작동하는 웹페이지로 바꾸려면 어떤 순서로 진행해야 할까?

### 학습 목표

- 바탕화면에 웹페이지 제작용 빈 폴더를 직접 만든다.
- 첫 개발 요청을 Codex에 전달한다.
- AI가 만든 파일과 변경 내용을 확인한다.
- 결과를 브라우저에서 실행한다.
- 첫 결과를 완료 기준과 비교한다.

### 세부목차

1. 3교시 연습 폴더와 실제 웹페이지 폴더를 구분하기
2. 바탕화면에 자기소개 페이지용 새 빈 폴더 만들기
3. 새 빈 폴더를 Codex에서 열기
4. 실제 자기소개 페이지의 최소 구성 확인
   - 이름 또는 활동명
   - 한 줄 소개
   - 관심사·활동·경력 영역
   - 연락 또는 링크 영역
5. 자기소개에 넣을 정보 자유롭게 선택하기
   - 이번 결과물은 외부에 배포하지 않는 개인 로컬 연습물임을 안내하기
   - 실제 정보 또는 연습용 정보를 수강생이 편한 범위에서 선택하기
6. 자기소개에 넣을 내용을 짧게 정리하기
7. 첫 개발 요청 전달하기
8. AI가 제안하는 작업 내용 읽기
9. 빈 폴더에 생성된 파일 확인하기
10. 브라우저에서 첫 화면 실행하기
11. 요청한 내용이 들어갔는지 확인하기
12. 빠진 내용과 예상과 다른 부분 표시하기
13. 첫 결과를 성공으로 보는 기준

### 포함할 콘텐츠 후보

- 자기소개 페이지의 최소 와이어프레임
- 서로 다른 직업·관심사를 반영한 자기소개 사례
- 바탕화면에 빈 폴더를 만들고 Codex에서 여는 단계별 화면
- 빈 폴더가 웹페이지 프로젝트로 바뀌는 전·후 비교
- 첫 생성 전·후 화면 비교
- 결과 확인 체크리스트

### 실습 후보

- 바탕화면에 개인별 자기소개 페이지용 빈 폴더 만들기
- 빈 폴더를 Codex에서 열기
- 실제 자신의 정보 또는 편하게 사용할 연습용 정보를 골라 요청문에 넣기
- 직업·관심사·활동 목적이 반영된 실제 자기소개 페이지 만들기
- 빈 폴더에 새로 생긴 파일과 첫 화면 확인하기

### 확정된 실습 방식

- 실습 대상은 가상 인물이 아니라 수강생 본인의 실제 자기소개다.
- 공통 스타터나 미리 만들어진 웹 파일을 제공하지 않는다.
- 수강생이 바탕화면에 새 빈 폴더를 만들고 그 폴더를 Codex에서 연다.
- 첫 요청을 통해 빈 폴더 안에 필요한 웹페이지 파일을 처음부터 생성한다.

### 아직 결정할 사항

- 빈 폴더에서 생성 성공률을 높이기 위해 첫 요청문에 반드시 포함해야 할 조건은 무엇인가?

- 수정 후 기존 기능이 유지되는지 확인한다.

1. 첫 결과에서 수정할 항목 찾기

4. 문구와 정보 개인화하기
5. 색상과 분위기 정하기
6. 글자 크기·간격·카드·버튼 수정하기
7. 모바일에서도 보기 좋게 요청하기
8. 간단한 기능 후보 이해하기
   - 버튼을 누르면 메시지 표시
   - 소개 내용 펼치기·접기
   - 관심 분야 필터 또는 탭
   - 배경 또는 테마 변경
   - 연락 링크 동작

10. 수정 전과 수정 후 비교하기

- 초보자도 결과를 바로 확인할 수 있는 간단한 상호작용 사례
- 수정 전·후 비교 체크리스트

### 실습 후보

- 동일한 기본 페이지를 서로 다른 세 가지 분위기로 변경하기
- 자신의 목적에 맞는 색상·문구·구성을 선택해 개인화하기
- 기능 후보 중 하나를 골라 추가하기
- AI가 임의로 변경한 부분을 찾아 원래대로 되돌리기

### 아직 결정할 사항

### 교시 산출물

- 개인 정보와 목적이 반영된 자기소개 페이지
- 화면 수정 최소 두 가지
- 작동하는 상호작용 기능 한 가지
- 수정 전·후 비교 결과

### 콘텐츠 리서치 담당자가 확인할 질문

- 20분 내 구현과 검수가 가능한 기능 후보는 무엇인가?
- 기능별 실패 가능성과 복구 난이도는 어느 정도인가?
- 화면 결과 차이가 크게 보이는 디자인 수정 예시는 무엇인가?
- 접근성과 모바일 화면에서 최소한 확인해야 할 항목은 무엇인가?

### 다음 교시 연결

> 화면과 기능을 추가했다면 이제 예상대로 작동하는지 검수하고, 문제가 있을 때 AI와 함께 해결하는 법을 익힌다.

## 6교시. 오류를 해결하고 학습 정리하기

### 교시 핵심 질문

> 결과가 예상과 다를 때 어떻게 설명하고 고치며, 오늘 배운 과정을 내 것으로 정리할까?

### 학습 목표

- 오류와 단순한 취향 차이를 구분한다.
- 증상과 기대 결과를 AI에게 설명한다.
- 한 번에 한 가지 원인을 수정하고 재확인한다.
- 자기소개 페이지를 최종 검수한다.
- 1주차에 경험한 바이브코딩 과정을 자신의 말로 정리한다.
- 2주차에 진행할 서비스 기획과 제작의 흐름을 가볍게 이해한다.

### 세부목차

1. 오류, 불편함, 디자인 취향의 차이
2. 문제가 생겼을 때 먼저 확인할 항목
   - 파일이 저장됐는가
   - 올바른 파일을 열었는가
   - 화면을 새로고침했는가
   - 버튼과 링크가 연결됐는가
3. AI에게 오류를 설명하는 기본 구조
   - 어느 화면에서
   - 어떤 행동을 했고
   - 실제로 무엇이 일어났으며
   - 원래 무엇을 기대했는가
4. 한 번에 한 가지 수정하기
5. 수정 후 같은 과정을 다시 실행하기
6. 전체 페이지 최종 체크
   - 내용
   - 화면
   - 버튼과 링크
   - 모바일
   - 개인정보
7. 수강생 본인이 완료 체크리스트로 전체 화면 점검하기
8. 강사가 순회하며 막힌 부분과 필수 동작 확인하기
9. 이번 주에 배운 AI 협업 흐름 회고
10. 내가 가장 효과를 본 요청과 수정 방식 정리하기
11. 2주차 수업 예고
   - 관심 있는 주제에서 아이디어 찾기
   - 사용자의 문제 정의하기
   - 서비스의 핵심 기능 정하기
   - 실제로 작동하는 서비스 만들기
12. 원한다면 다음 시간까지 생각해 볼 질문 안내
   - 평소 불편했던 일은 무엇인가
   - 반복해서 하는 일은 무엇인가
   - 다른 사람을 도와주고 싶은 일은 무엇인가

### 포함할 콘텐츠 후보

- 초보자가 자주 만나는 오류 화면과 원인
- 나쁜 오류 보고와 좋은 오류 보고 비교
- 오류 해결 순서도
- 완성 체크리스트
- 1주차 전체 학습 흐름 회고 도식
- 2주차에서 하게 될 활동을 보여주는 간단한 예고 화면

### 실습·참여 후보

- 강사가 준비한 오류를 보고 좋은 오류 보고문 작성하기
- 자신의 페이지에서 실제 문제 한 가지 찾아 수정하기
- 자기 페이지를 처음부터 다시 열어 보고 완료 체크리스트 확인하기
- 강사에게 막힌 부분을 질문하고 수정 전·후 확인하기
- 오늘 사용한 요청 중 가장 효과적이었던 것 한 개 고르기
- 요청→생성→확인→수정 과정을 자신의 사례로 정리하기

### 교시 산출물

- 최종 자기소개 웹페이지
- 오류 또는 불편함을 개선한 기록
- 1주차 AI 협업 과정 회고

### 콘텐츠 리서치 담당자가 확인할 질문

- 1주차에서 의도적으로 보여줄 오류 사례는 무엇이 좋은가?
- 초보자가 직접 해결할 수 있으면서 학습 효과가 큰 오류는 무엇인가?
- 수강생 혼자서도 따라 할 수 있는 최종 자기 점검 체크리스트는 어떻게 구성할 것인가?
- 강사가 12명의 필수 완료 상태를 빠르게 확인할 방법은 무엇인가?
- 1주차 전체 과정을 짧게 회고하게 할 가장 효과적인 형식은 무엇인가?
- 2주차 예고를 어느 정도까지 보여줘야 부담 없이 기대감을 만들 수 있는가?

### 1주차 종료 메시지

> 나는 AI에게 웹페이지 제작을 요청하고, 결과를 확인하고, 원하는 방향으로 수정하고, 문제가 생기면 다시 설명해 해결할 수 있다.
