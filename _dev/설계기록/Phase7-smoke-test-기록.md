## 5. 🔴 이 실행이 찾아낸 명세 결함 2건 (둘 다 수정)

### 결함 ① 허용목록이 기계적으로 충족 불가능했다

**3/3 워커가 `ToolSearch`를 호출**해 감사에 걸렸다. 원인은 워커가 아니라 명세다 —
이 환경에서 `WebSearch`·`WebFetch`는 **deferred**(이름만 노출·스키마 미로드)라
`ToolSearch`로 스키마를 먼저 로드하지 않으면 **호출 자체가 불가능**하다.
Phase 2의 허용목록 5개는 조사를 수행할 수 없는 목록이었다.

→ **수정**: `ToolSearch`를 허용목록에 추가하되 **전제 조건**임을 명시했다.
허용 범위는 `WebSearch`·`WebFetch`의 **스키마 로드까지**이며, `ToolSearch`로 다른 도구를 불러
실제로 쓰면 **그 도구 이름으로 감사에 잡힌다.** `Bash`·`PowerShell`·`Write`·`Edit`·`Agent` 불허는 그대로다.

### 결함 ② §0.5 「동일 URL 재호출 1회」 중단선이 감사에 없었다

규칙만 있고 검사가 없었다. 추가하자마자 **실제 위반 1건**이 잡혔다 —
P0 워커가 빈 응답을 받은 `scrum.org`를 재시도해 **동일 canonical URL 2회 재호출**(중단선 1).

→ **수정**: 감사에 canonical 정규화 기반 재호출 검사를 추가(위반 시 종료코드 3). 회귀 테스트 3건 추가.
