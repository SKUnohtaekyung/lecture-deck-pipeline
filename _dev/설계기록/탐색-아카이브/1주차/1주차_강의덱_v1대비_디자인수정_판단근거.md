# 1주차 강의덱 v1 대비 디자인 수정 판단 근거

> 대상: `sessions/1주차/강의덱.html` 최종 69장  
> 작성 목적: 최초 검수본(v1)에서 현재 덱으로 바꾸면서 각 슬라이드의 레이아웃·박스·카드·라운드·이미지·타이포그래피를 어떻게 판단했는지 재현 가능한 형태로 남긴다.

## 1. 비교 기준과 한계

- 이 저장소에는 최초 65장짜리 v1 HTML이 별도 파일로 보존되어 있지 않다. 따라서 이 문서의 v1 비교는 **최초 브라우저 주석 56건과 저장된 마커 스크린샷**, 당시의 65장 번호 체계, 초기 설계 결정표, 현재 69장 HTML/CSS를 교차해 복원했다.
- `[직접]`은 v1 마커 스크린샷이나 사용자 주석에서 형태와 문제가 직접 확인된 항목이다.
- `[구조]`는 v1의 클래스·설계표·연속 슬라이드 패턴에서 복원한 항목이다. 확인되지 않은 픽셀값을 사실처럼 단정하지 않고, 어떤 구조적 문제가 있었는지만 기록한다.
- `[신규]`는 v1에 없고 표지 뒤에 추가된 3장 또는 마지막에 추가된 THANK YOU 장이다.
- 번호는 **현재 69장 기준**이다. 현재 2~4번이 새로 들어가면서 v1의 2~65번은 현재 5~68번으로 이동했다.

## 2. 덱 전체에 공통 적용한 판단

### 2.1 안전영역이 장식보다 우선

- 모든 슬라이드는 1280×720 캔버스 안에서 제목·본문·이미지·페이지 번호가 잘리지 않는 것을 첫 번째 조건으로 삼았다.
- `overflow:hidden`으로 문제를 숨기지 않고, 이미지와 텍스트를 별도 grid track에 두거나 요소의 실제 크기를 줄여 교차 원인을 제거했다.
- 박스를 좁혀 문장을 여러 줄로 만드는 대신 먼저 가로폭을 주고, 수동 줄바꿈은 구·절 경계에서만 넣었다.

### 2.2 박스와 카드의 형태

- 큰 카드의 기본 라운드는 `--r-lg` 20px, 일반 카드·콜아웃은 `--r-md` 14px, 작은 UI는 `--r-sm` 10px, 태그·칩은 `--r-pill`을 사용했다.
- 박스가 많다는 이유만으로 모두 둥글게 만들지 않았다. 비교·단계·터미널처럼 경계가 명확해야 하는 화면은 각진 면이나 상단 컬러 바를 사용했다.
- 흰 배경 위 흰 카드와 연한 회색 테두리 조합을 피했다. 구조는 블루 틴트, 행동·확인은 민트 틴트, 위험·금지는 코랄 틴트와 같은 계열 보더로 구분했다.
- 카드 크기는 정보량에 비례시켰다. 한 줄을 담은 박스를 화면 너비 전체로 늘리지 않았고, 여러 줄을 억지로 작은 카드에 넣지도 않았다.

### 2.3 색의 역할

- 블루는 구조·순서·개념, 민트는 행동·확인·성공, 코랄은 위험·금지에 사용했다.
- 제목의 핵심어는 민트 글자·밑줄·마크 중 하나를 선택했고, 화면 전체가 파란 글씨로 보이지 않도록 강도와 면적을 분산했다.
- 검정 화면은 `--ink`, 본문은 흰색을 사용했다. 터미널에서만 프롬프트와 커서를 민트로 남겨 입력 위치를 보여 줬다.

### 2.4 이미지 판단

- 이미지가 정보를 설명해야 할 때는 충분히 크게 두고 `object-fit:contain`으로 전체가 보이게 했다.
- 실제 프로그램 조작은 실제 캡처나 그 캡처를 담은 GUI 프레임을 사용했다. 생성 이미지를 실제 프로그램 화면처럼 위장하지 않았다.
- 정보량이 부족한 장은 빈 카드로 채우지 않고 관계 다이어그램, 브라우저 프레임, 폴더 트리, 터미널, 설명 이미지를 사용했다.

### 2.5 레이아웃 리듬

- v1은 세로로 긴 카드, 중앙 3단계 흐름, 좌측 설명·우측 작은 이미지가 반복돼 덱이 단조롭게 보였다.
- 현재 덱은 선언형 중앙 장면, 편집형 비대칭, 가로 밴드, 넓은 비교, 실제 GUI, 브라우저 프레임, 폴더 트리, 터미널, 지그재그 흐름을 교대했다.
- 같은 split 구도를 연속 사용해야 하는 실습 구간도 이미지 비율, 설명 방향, 프레임 종류, 배경 면을 바꿔 같은 템플릿처럼 보이지 않게 했다.

## 3. 슬라이드별 판단 근거

## 도입부

### 01. 표지 — AI 코딩 에이전트와 협업해 첫 자기소개 웹페이지 만들기 `[직접]`

- **v1 상태**: 표지의 터미널이 검정 표면이라 시작부터 무겁고, 뒤에 이어지는 밝은 교육 덱과 재질이 단절돼 보였다.
- **현재 설계**: 표지 터미널을 흰 배경·유색 보더·짙은 글씨로 복원하고, 표지의 큐브·브랜드 구조는 유지했다.
- **박스·라운드 판단**: 터미널은 카드가 아니라 도구 화면이므로 카드용 틴트 대신 흰 표면과 명확한 유색 외곽선을 사용했다. 라운드는 UI 창 정도만 적용했다.
- **근거**: 첫 화면에서는 콘텐츠의 난이도를 낮게 느끼게 해야 하며, 검정 터미널은 뒤의 35·39·44·55번처럼 실제 프롬프트를 보여 주는 장에 의미를 남겨 두는 편이 낫다.

### 02. AI, 어떻게 사용하고 계신가요? `[신규]`

- **v1 상태**: 존재하지 않았다. 표지에서 바로 수업 목표로 넘어가 사용자의 현재 AI 경험을 환기하는 장면이 없었다.
- **현재 설계**: 질문을 왼쪽 상단의 큰 제목으로 두고, 한 문장이 AI를 거쳐 글·이미지·코드·웹 화면으로 펼쳐지는 설명 이미지를 오른쪽에 배치한 비대칭 편집형 구도다.
- **박스·라운드 판단**: 결과물은 네 개의 작은 모듈로 보이지만 전체 이미지를 다시 큰 카드 안에 가두지 않았다. 제목의 `AI`만 블루·볼드로 처리해 질문의 주체를 즉시 읽게 했다.
- **근거**: 카드형 좌우분할보다 질문→확산 관계가 먼저 보여야 한다. 이미지와 문장이 교차했던 초안을 수정해 두 영역의 안전 간격을 확보했고, 불필요한 eyebrow도 제거했다.

### 03. 해줘. `[신규]`

- **v1 상태**: 존재하지 않았다.
- **현재 설계**: 검정 배경에 `해줘.` 한 문장만 가장 밝고 선명한 민트로 배치한 declaration 장이다. 가로·세로 중앙을 캔버스 기준으로 맞췄다.
- **박스·라운드 판단**: 박스·카드·로고·페이지 설명을 모두 제거했다. 메시지 자체가 화면이므로 외곽 형태를 추가하면 집중이 약해진다고 판단했다.
- **근거**: 한 문장으로 AI를 사용하는 현재 습관을 극단적으로 축약해 다음 장의 반전을 만들기 위함이다. 민트는 행동 신호이므로 `해줘`라는 행동어와도 일치한다.

### 04. “해줘”로 시작은 됩니다. `[신규]`

- **v1 상태**: 존재하지 않았다.
- **현재 설계**: 3번의 검정 배경을 이어받되 제목 크기를 줄이고, 후킹 본문과 `오늘, 그 방법을 배웁니다.` 결론을 세로로 쌓았다.
- **박스·라운드 판단**: 카드 없이 텍스트 계층만 사용했다. `해줘`와 결론만 선명한 민트, 나머지는 흰색으로 두어 시작과 학습 목표를 연결했다.
- **근거**: 동일한 검정 선언 장면을 두 번 쓰되 3번은 한 단어, 4번은 논리 전개라는 다른 밀도로 구성해 반복이 아니라 전환으로 느끼게 했다.

### 05. 오늘의 목표 — 내 소개 페이지를 열고, 한 곳을 직접 고칩니다 `[직접, v1 02]`

- **v1 상태**: `오늘의 도착점`과 추상적인 문장 세 줄이 큰 텍스트 덩어리로 모여 있었고, 목표와 행동 순서가 분리되지 않았다. 우측 이미지는 제목 영역과 가까웠다.
- **현재 설계**: 왼쪽 720px에는 제목·리드·4단계 목표를 두고, 우측 하단에는 400×362px 설명 이미지를 독립 배치했다. 행동은 `열기 → 확인 → 수정 → 새로고침`의 2×2 순서로 보인다.
- **박스·라운드 판단**: 네 행동은 `--r-md` 14px 카드다. 앞 두 개는 블루 틴트, 뒤 두 개는 민트 틴트로 `이해 → 행동·확인`의 변화를 표현했다.
- **근거**: 학습 목표는 추상 명사보다 수업 후 직접 할 수 있는 행동으로 써야 한다. 가로폭을 유지해 문장을 억지로 줄바꿈하지 않고, 이미지와 목표 카드가 겹치지 않는 별도 영역을 만들었다.

### 06. 오늘 배우게 될 것 `[직접, v1 03]`

- **v1 상태**: 번호와 긴 제목이 가까워 2번·5번 문구가 겹치고 6번이 화면 밖으로 나갔다. 왼쪽 소개 문장도 수업 내용을 요약하지 못했다.
- **현재 설계**: 왼쪽 386px에 한 문장 학습 요약, 오른쪽에 명시적인 2열×3행 agenda grid를 사용했다. 번호는 56px 원형 배지, 글은 별도 컬럼이다.
- **박스·라운드 판단**: 각 agenda는 `--r-lg` 20px 카드이며 번호와 텍스트를 수직 중앙 정렬했다. 교대 카드에 블루·민트 틴트를 사용하고 연결선은 제거했다.
- **근거**: 여섯 항목은 flow보다 classification에 가깝다. 연결선을 따라 읽게 하기보다 여섯 학습 묶음을 안정적으로 훑게 하는 편이 적합하며, 2열로 폭을 확보해야 제목을 단어 중간에서 내리지 않는다.

## PART 1 — AI에서 코딩 에이전트까지

### 07. PART 1 — AI → 코딩 에이전트 `[직접, v1 04]`

- **v1 상태**: 한때 큰 원과 좌측 정렬 텍스트를 둔 별도 간지로 바뀌어 다른 PART 전환장과 불일치했고 본문이 원에 닿았다.
- **현재 설계**: 여섯 파트 공통의 아이소 큐브, 진행 도트, 중앙 제목·설명을 사용하는 표준 `part-divider`로 복귀했다.
- **박스·라운드 판단**: 카드가 아니라 풀캔버스 선언 장이다. 도트만 원형이고 텍스트를 둘러싼 박스는 없다.
- **근거**: 파트 전환은 다양성보다 반복되는 길찾기 장치가 우선이다. 동일한 템플릿이 학습자가 현재 파트를 즉시 인지하게 하며, 장식 원보다 제목 가독성을 보호한다.

### 08. 첫 웹페이지에서 MVP와 공개까지 `[직접, v1 05]`

- **v1 상태**: 3주 카드의 이미지가 낮은 높이에 잘렸고, 하단 설명이 카드와 너무 붙거나 화면 아래의 빈 공간과 균형을 이루지 못했다.
- **현재 설계**: 동일한 3열 여정 구조를 유지하되 각 카드의 이미지 행을 174px로 확보하고, 카드와 하단 노트 사이에 22px 간격을 뒀다.
- **박스·라운드 판단**: 세 주차는 `--r-lg` 20px 카드로 통일하되 1주차 블루, 2주차 민트, 3주차 코랄 틴트를 사용했다. 이는 좋고 나쁨이 아니라 단계 구분이다.
- **근거**: 세 주차는 동급 classification이면서 시간 순서이므로 같은 크기 카드가 적합하다. 이미지가 먼저 보이고 그 아래 제목·설명이 읽히도록 카드 내부를 `이미지 174px + 가변 본문`으로 나눴다.

### 09. 오늘의 결과물 — 내 이야기를 담은 첫 포트폴리오 페이지 `[직접, v1 06]`

- **v1 상태**: 단순한 프로필 카드와 빈 우측 패널, 동작하지 않는 테마·접기 버튼이 있어 실제 결과물보다 와이어프레임처럼 보였다.
- **현재 설계**: 31:69 비율의 독립 쇼케이스다. 좌측에는 결과물 선언, 우측에는 브라우저 바·내비게이션·히어로·프로필 그래픽·관심사·프로젝트·푸터가 있는 완성형 사이트를 넣었다.
- **박스·라운드 판단**: 외곽 브라우저만 `--r-lg` 20px과 진한 보더·큰 그림자를 사용한다. 내부 섹션은 카드 모음이 아니라 웹사이트의 면·선·타이포그래피로 나눴고, 관심사만 pill을 사용했다.
- **근거**: 이 장의 목적은 설명이 아니라 학생의 기대 수준을 끌어올리는 결과물 시연이다. 기존 카탈로그 패턴보다 실제 웹사이트처럼 보여야 하므로 페이지 전용 레이아웃을 만들고 가짜 인터랙션은 제거했다.

### 10. AI에서 코딩 에이전트까지 `[직접, v1 07]`

- **v1 상태**: 중앙에 `AI → 생성형 AI·LLM → 에이전트` 카드만 있었고 왼쪽 설명이 없어 단계의 의미가 부족했다. 하단 경고 문장은 시각적으로 떠 있었다.
- **현재 설계**: 왼쪽 292px의 읽는 법과 오른쪽의 역할 흐름을 결합한 2단 구조로 바꿨다. 하단 결론은 본문 흐름 안에 포함했다.
- **박스·라운드 판단**: 흐름 노드는 구조를 나타내므로 블루 계열, 행동하는 코딩 에이전트는 민트 계열로 차이를 줬다. 노드 라운드는 일반 카드 수준으로 제한했다.

- **v1 상태**: 오늘 한 행동과 완료 기준의 대응이 글 목록으로 분리돼 있었다.
- **현재 설계**: 세 행동을 다섯 확인 기준으로 연결하는 mapping 구도를 사용했다.
- **박스·라운드 판단**: 대응 행은 구조용 블루, 확인 결과는 민트로 구분했다.
- **근거**: 수업 초반의 목표를 마무리에서 다시 매핑해 회상하게 한다. 새 정보를 추가하기보다 행동과 기준의 연결을 닫는 장이다.

### 67. 개인정보·권리·사실을 다시 확인합니다 `[구조, v1 64]`

- **v1 상태**: 최종 점검 항목이 작은 카드에 몰려 중요도 차이가 없었다.
- **현재 설계**: 개인정보·권리·사실 세 범주와 실제 확인 예시, 보조 이미지를 배치했다.
- **박스·라운드 판단**: 위험 범주는 코랄, 확인 행동은 민트, 구조 라벨은 블루다. 카드 라운드는 표준 20px을 유지한다.
- **근거**: 최종 점검은 개념 설명이 아니라 행동 checklist다. 범주와 예시를 같이 보여 줘 학생이 자신의 페이지에 직접 적용하게 했다.

### 68. 오늘 다섯 가지를 확인합니다 `[직접, v1 65]`

- **v1 상태**: 브랜드 글씨가 배경과 대비되지 않았고, 상단 요약이 아래로 내려가며 패널 여백이 불균형했다.
- **현재 설계**: 브랜드 대비를 복구하고 상단 요약을 올렸다. 다섯 단계 흐름, 세 보조 카드, 다음 시간 배너를 균등한 네 밴드로 구성했다.
- **박스·라운드 판단**: 흐름 칩은 진행 거리 자체가 의미라 전체 폭을 쓰고, 짧은 배너는 과도하게 높이지 않았다. 카드 라운드는 공통 20px이다.
- **근거**: recap은 덱 전체를 다시 스캔하는 장이므로 특정 좌측 컬럼에 몰면 안 된다. 캔버스 전체 폭을 사용해 상하 정보 리듬을 균등하게 만들었다.

### 69. THANK YOU `[신규]`

- **v1 상태**: 존재하지 않았다. 초기 추가본에는 큰 파란 원·외곽 테두리가 THANK YOU와 경쟁했다.
- **현재 설계**: `--ink` 단색 배경, 화면 정중앙의 `THANK YOU`, 위의 작은 브랜드, 아래의 다음 시간 문장만 남겼다. 제목은 174px로 덱에서 가장 크다.
- **박스·라운드 판단**: 카드와 외곽 테두리를 모두 제거했다. 중앙의 매우 옅은 세로 선만 축을 잡고, 제목을 감싸는 도형은 없다.
- **근거**: 감사 장의 정보 모양은 declaration이다. 장식 원이나 파란 테두리가 메시지와 경쟁하면 안 되며, 가로·세로 중앙 정렬과 가장 큰 볼드 타이포그래피가 종결감을 가장 직접적으로 만든다.

## 5. 이후 수정 시 지켜야 할 판단 순서

1. 슬라이드의 정보 모양을 `declaration·concept·comparison·flow·containment·mapping·classification·checklist·screen-operation` 중에서 먼저 고른다.
2. 이미지가 핵심이면 이미지가 읽힐 크기를 먼저 확보하고, 남는 영역에 설명을 둔다.
3. 카드가 필요한지 판단한다. 단순히 정보를 나누고 싶다는 이유만으로 카드를 만들지 않는다.
4. 카드가 필요하면 정보량에 맞춰 폭·높이·패딩을 정하고, 라운드는 `20/14/10/pill` 토큰 중 역할에 맞춰 사용한다.
5. 색은 의미에 맞게 하나씩 배정한다. 한 화면에서 블루·민트·코랄이 모두 강하게 경쟁하지 않게 한다.
6. 긴 문장은 박스를 좁히기 전에 가로폭을 늘린다. 수동 줄바꿈은 의미 경계에서만 한다.
7. 마지막으로 1280×720과 실제 인앱 브라우저에서 DOM 경계·스크롤·텍스트 잘림·이미지 crop·콘솔 오류를 확인한다.
