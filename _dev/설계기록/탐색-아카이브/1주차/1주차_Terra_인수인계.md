## 4. 61장 최소 재구성 원칙

58장 유지 제약은 해제됐다. 최소 3장을 추가해 61장 이상으로 재번호를 전면 동기화한다. 새 단계는 한 슬라이드에 한 행동만 둔다.

### PART 2에 반드시 독립시킬 새 조작

1. `내 PC`에서 로컬 디스크 `C:` 열기
2. `C:\VibeCoding` 만들기
3. 파일 확장명 표시 켜기

기존의 “연습 폴더 만들기”는 `C:\VibeCoding\Codex_연습` 만들기로, 기존의 “프로젝트 폴더 만들기”는 `C:\VibeCoding\내_자기소개` 만들기로 바꾼다. 피드백의 흐름대로 두 하위 폴더를 준비한 뒤 요청 설계와 프로젝트 작업으로 이동하는 구성이 자연스럽다.

### 재번호·참조 동기화 의무

- 초안 표, 콘텐츠 결정표, 집필노트, 덱 결정표, 리뷰 HTML, 발표자 노트, HTML 목차와 PART divider, `n/전체` 페이지네이션을 같은 최종 번호로 맞춘다.
- 기존 번호를 본문에 직접 참조한 문장(예: 29→34, 50→51~55)은 새 번호로 바꾼다.
- 새 슬라이드는 고정 슬라이드가 아니며 일반 콘텐츠/조작 슬라이드 집계에 포함한다.
- 화면 조작 host는 `L-dc-annotated` 또는 `L-dc-hero`만 쓴다. 조작 단계 전체 개요에만 `L-vf-numbered-stack`을 허용한다.

## 6. Terra의 실행 순서

1. 이 문서의 확정값을 읽고 기존 `D1~D6` 문서·초안·결정표의 오래된 후보와 차이를 표로 확인한다.
2. 콘텐츠 원본과 결정표를 61장 이상으로 재구성한다. 제목·본문을 무단으로 미화하지 않고, 새 경로·새 조작 단계·재번호만 필요한 범위에서 동기화한다.
3. 모든 슬라이드의 정보 모양, 레이아웃, element, 이미지 판정, 캡처/HTML 시각화, 힌트·노트 라우팅을 덱 결정표에서 새 번호로 검증한다.
4. 캡처가 없는 조작은 `USER_CAPTURE 필요`로 남기고 임시 생성 이미지나 가짜 UI로 대체하지 않는다. 브라우저 흐름만 명시적으로 HTML 시각화다.
5. 사용자에게 갱신된 결정표와 캡처 결손 목록을 보여 준다. 이때 D2 최종 요청문 전문 후보, D5 공통 필수 수정 1개, 이미지 생성 모드를 함께 확인한다.
6. 이미지 모드가 `generate_now`이고 캡처·결정표가 승인된 뒤에만 12개 투명 PNG를 생성·QA·등록한다.
7. 그 뒤 `sessions/1주차/강의덱.초안/` 조각 구조로 HTML을 조립하고 발표자 노트를 만든다.
8. 조립 후 정적·브라우저·오프라인 검증을 모두 수행한다.

## 7. 구현 규칙과 금지 사항

- 정보 모양 → 역인덱스 → 레이아웃·element 별도 선택 순서를 지킨다.
- 레이아웃과 element를 하나로 뭉개지 않는다. 카탈로그 코어 12 레이아웃·8 차트에서 먼저 해결하고, 변형은 근거를 남긴다.
- 콘텐츠 슬라이드에서 직전과 같은 구도 패밀리를 피한다. split은 희소·비연속이다.
- 실제 조작 화면의 host는 `L-dc-annotated`/`L-dc-hero`만. 단계와 화면의 주석 지점 1~3개를 혼동하지 않는다.
- `💬`·`👀`는 학생 화면 비노출, `🗣`는 원문 그대로 `.hint-reveal`에 둔다.
- 토큰만 사용한다. raw hex, navy, gradient, 장식 이모지, 흰색-온-흰색 카드, 민트/코랄 fill 위 흰 글자를 금지한다.
- 새 공통 CSS가 정말 필요하면 덱 로컬 style이 아니라 `kit/styles/patterns.css`와 카탈로그로 환류하고 `verify_kit.py`를 실행한다.
- 기존 dirty 파일을 되돌리거나 무관한 파일을 편집하지 않는다. 커밋하지 않는다.
