- PART 순서: ① AI → 코딩 에이전트 ② Codex·폴더·파일·작업 범위·권한 ③ 자기소개 재료·첫 요청 ④ 첫 페이지 생성·브라우저 실행 ⑤ 유지 → 변경 → 확인 ⑥ 오류 대응·최종 점검·2주차 연결.
- PART 2의 필수 순서: **작업 환경과 폴더 준비 → 실제 프로그램과 작업 범위 확인 → 제작 요청문 작성**. 14~16은 각각 `내 PC`에서 C: 열기, `C:\VibeCoding` 만들기, 파일 확장명 표시다. 구 14~58은 모두 +3이다.
- 화면 조작은 한 슬라이드 한 조작, 주석 1~3점, `L-dc-annotated`/`L-dc-hero`만 사용한다. 연속 조작은 두 host를 교대한다.
- 💬·👀는 HTML 주석+발표자 노트, 🗣는 원문 그대로 접힌 `.hint-reveal`+발표자 노트다. 학생 화면에 기능 마커 문자는 남기지 않는다.
- 실제 Windows·Codex는 수업용 실제 캡처만 쓴다. `win05_vibecoding-index-root.png`, `codex_vibecoding-workspace-index.png`, `reference_capture-worklist.png`는 최종 사용 금지. `16-01.png`은 참고 전용이며 학생 덱에 삽입하지 않는다.
- 이미지 12장은 모두 투명 PNG `paper-cut-v1`, 설명/기억용이다. 같은 슬라이드에서 차트·다이어그램 element와 병용하지 않는다. 중앙 approved asset은 0개이며 생성·QA·등록 통과 후에만 연결한다.

### 0.1 표기

- `I:` 정보 모양 / `L:` 레이아웃 / `E:` element / `A:` 이미지 / `C:` 캡처·정적 시각화 / `M:` 기능 마커 / `R:` 직전 콘텐츠와의 리듬 근거 / `D:` 결정 영향.
- 캡처 대기 상태는 제작 문서에만 남기며 학생 화면에 표시하지 않는다. 임의 제품 UI는 금지하고, 브라우저 5단계는 제품 UI가 아닌 학습용 HTML 정적 시각화다.

### 0.2 학생 화면 노출 잠금

- `MAPPING`, `STRUCTURE`, `FLOW`, `CLASSIFICATION`, `SCREEN OPERATION`은 이 결정표의 정보 모양 메타데이터일 뿐 학생 화면의 eyebrow·토글·카드 제목으로 출력하지 않는다.
- `한 행동`, `유지`, `성공`을 학생에게 직접 라벨로 보이지 않는다. 필요하면 “이번에는…”, “그대로 둘 부분”, “화면에서 다시 볼 점”처럼 문장 안에 자연스럽게 쓴다.
- 캡처 파일이 아직 없다는 알림과 `USER_CAPTURE` 계열 표기는 학생 화면에 0건이다. 실제 캡처는 원본 전체를 `contain`으로, 캡션까지 온전히 보이게 배치한다.
- 강조는 핵심 명사 `.hl-mint-text`, 결론·확인 기준 `.hl-mint-underline`, 짧은 행동·결과 `.hl-mint-mark`로 분산한다. mark는 한 장에 하나 이하이며 민트 일반 fill에는 `--on-mint`를 쓴다.
