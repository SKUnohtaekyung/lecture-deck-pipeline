# 슬라이드 계획서 — 바이브코딩 강의덱 (콘텐츠 입력 템플릿)

> 이 문서를 채워서 주시면, **레이아웃·시각화·디자인은 스킬이 전부 알아서 판단**해 HTML 웹덱으로 조립합니다.
> **원칙: 무슨 내용을 말할지는 당신이 / 어떻게 보여줄지는 스킬이.**
> **레이아웃·차트 종류·색상 등은 몰라도 되고, 적지 않으셔도 됩니다.** "무슨 내용이 들어가야 하는지"만 적어주세요.
> 채우기 애매하면 `알아서`라고 쓰면 내용 보고 판단합니다.

## 1. 슬라이드별 계획

> 아래 **블록을 슬라이드 수만큼 복사**해서 채웁니다. **필수 = ★**, 나머지는 선택.
> **레이아웃·차트·색은 적지 않아도 됩니다** — 목적과 본문만 보고 스킬이 알아서 정보 모양을 판단해 고릅니다.

### 슬라이드 N  *(파트: __)*
- **★ 슬라이드 목적·전달 목표**: 이 장에서 함께 이해시킬 결론·질문·근거 묶음. 관련 정보는 여러 개여도 됩니다.
- **★ 제목(헤드라인)**: 화면에 크게 뜰 문장. 결론형을 권장하지만 적어주신 제목을 우선합니다.
- **★ 본문 내용**: 실제 들어갈 텍스트·불릿·근거·사례·비교 기준·수치 등. 적어주신 정보 묶음을 유지합니다.
  > **분량 가이드**: 불릿은 **4~6개 내외**, 한 줄은 **20~25자 내외** 권장. 넘으면 화면에 다 안 들어가 스킬이 분할 승인을 다시 요청할 수 있습니다.
- **묶음 유지/분할 허용(선택)**: `유지` *(기본)* / `분할 허용`. 유지인데 화면에 다 안 들어가면 조립 전에 승인을 요청합니다.
- **데이터(수치·차트가 필요할 때)**: 실제 값으로 적어주세요.
  - 단순 비교: `항목 = 값` (예: 기획 40% · 개발 35% · 검증 25%)
  - 추세: `시점 = 값` (예: 1월=40 · 2월=55 · 3월=70)
  - 여러 안 비교: 안(시리즈)별로 구분 (예: A안 - 기획40%·개발35%·검증25% / B안 - 기획20%·개발50%·검증30%)
- **화면 캡처가 필요할 때**: 어느 화면의 어느 단계인지 + 강조할 위치(번호). (실습·조작 안내 슬라이드용)
- **이미지가 필요할 때(선택)**: 필요할 때만 적어주세요. 그리고 싶은 **장면 한 줄**만 적으면 되고, 배치·스타일은 스킬이 결정합니다.
- **주의·강조(선택)**: 오개념 방지 포인트, 강조할 단어.
- **발표 노트(선택)**: 말로 풀 설명(화면엔 안 나옴).

### ✍️ 작성 예시 — 슬라이드 7 *(파트: 1)*
- **슬라이드 목적**: AI는 '답'이 아니라 '행동'을 하게 시킬 수 있다.
- **제목**: 물어보기만 하던 AI, 이제 '일'을 시킨다
- **본문 내용**: 지금까지 = 질문하고 답 받기 / 이제 = 파일 만들고·고치고·실행까지
- **주의·강조**: "크기가 아니라 '행동하느냐'가 진짜 차이" 강조

### ✍️ 작성 예시 — 슬라이드 15 *(파트: 3, 실습)*
- **슬라이드 목적**: 바탕화면에 새 폴더를 만들고 Codex에서 연다.
- **제목**: ① 바탕화면에 새 폴더 만들기
- **본문 내용**: 바탕화면 우클릭 → 새로 만들기 → 폴더 → 이름 입력
- **화면 캡처**: Windows 바탕화면 우클릭 메뉴, "새로 만들기 > 폴더" 위치에 ①②③ 번호

### ✍️ 작성 예시 — 슬라이드 22 *(파트: 4, 수치 비교)*
- **슬라이드 목적**: 프로토타입 방식을 바꾼 뒤 검증 단계 비중이 늘었다.
- **제목**: 검증에 쓰는 시간이 25%에서 40%로 늘었다
- **본문 내용**: 예전 방식 대비 개발 시간은 줄고 검증 시간은 늘어난 이유 설명
- **데이터**: 이전 - 기획30%·개발45%·검증25% / 현재 - 기획25%·개발35%·검증40%

## 2. 작성 팁 (40~50대 대상)

- **계획서의 정보 묶음이 우선입니다.** 한 장에 관련된 여러 개념·근거·카드·차트를 둘 수 있습니다. 분량 가이드를 넘길 것 같으면 `분할 허용`으로 표시하거나, 스킬의 분할 제안에 승인해 주세요.
- **레이아웃·차트·색은 신경 쓰지 마세요.** 목적과 본문만 명확히 적으면 스킬이 정보 모양을 판단해 알아서 고릅니다.
- **숫자·비교·추세가 있으면 반드시 데이터 항목에 실제 수치로.** "많이 늘었다" 대신 실제 값을 적어야 차트로 만들 수 있습니다.
- **조작 설명은 실제 화면 캡처 + 번호로.** "여기" 대신 실제 버튼명·위치.
- **이미지는 "꼭 필요할 때"만 장면 한 줄로.** 배치·톤은 스킬이 덱 전체와 맞춰 처리합니다.
- **쉬운 말 + 친숙한 비유.** (예: 프롬프트 = 요청서, 폴더 = 서류철, 프로토타입 = 모형)
- **제목은 결론으로.** ("에이전트란?" ❌ → "에이전트는 말이 아니라 행동한다" ✅)

## 3. (참고) 이 계획서가 조립으로 이어지는 방식
1. **0번** = 표지·아젠다·파트전환·헤더(로고·팀명) 자동 채움
2. **각 슬라이드의 목적·본문** → 스킬이 정보 모양을 판단해 레이아웃/차트 자동 결정
3. **데이터** → CSS/SVG 코드 차트·다이어그램으로 제작
4. **화면 캡처·이미지 필요에 적힌 것만** → 스크린샷/이미지 핸드오프
5. 브라우저 검증 → base64 단일파일 배포
