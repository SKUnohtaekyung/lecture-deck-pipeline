# 카탈로그 규격 (Catalog Spec)

> 레이아웃·차트/다이어그램 카탈로그를 만들고 검증하는 **규칙**. P0에서 동결, 이후 전 Phase가 이걸 따른다.
> 판단 축은 [`정보모양-taxonomy.md`](정보모양-taxonomy.md).

---

## 1. "no default" 헌장 (원칙 A·B·C)

- **A. 동급.** 모든 레이아웃·차트·다이어그램은 **동등한 도구**다. **어떤 레이아웃도 "기본/가장 흔한/주로 쓰는/go-to 레이아웃"으로 서술하지 않는다** — 특히 좌우분할(split)을 기본으로 프레이밍 금지. (주의: '기본'이 *CSS 기본 스타일*을 뜻하거나 *이 헌장 자체*를 가리키는 등 **레이아웃 우위와 무관한 용례는 허용**. 금지 대상은 *레이아웃을 기본/최다로 규정하는 문장*이다.)
- **B. 판단 먼저.** 레이아웃을 고르기 전에 **정보 모양을 분류**하고, `by-shape.md` 역인덱스로 후보를 뽑는다. 즉흥 선택 금지.
- **C. 대안 공급.** 좌우분할이 아닌 구도를 대거 확보(§3 균형표) + 코드 차트/다이어그램 라이브러리로 도망갈 이유를 없앤다.

> 단조 방지는 **금지 조항이 아니라 공급 + 측정**으로 한다. split은 캡으로 희소하게, 역인덱스에서 후순위, 산출 덱은 분포를 측정.

## 2. 8 구도 패밀리 (composition family)

패밀리는 **연구·빌드 단위이자 균형 감사 단위**다. 각 레이아웃은 정확히 한 패밀리에 속한다.

| 패밀리 | 정의 (무엇이 구별하나) | deck.css 기반 |
|---|---|---|
| `full-bleed` | 여백 없이 화면을 꽉 채우는 **단일 요소**(큰 문장·큰 숫자·인용·풀블리드 배경). 컬럼 분할 없음. | `.s-full` 확장 · `.cover`류 |
| `centered` | 중앙 무대에 **하나의** 메시지/다이어그램. 좌우 대칭 여백. | `.center-msg`/`.cm-title` |
| `top-down` | **상단 타이틀 밴드 + 하단이 콘텐츠를 꽉 채움**(세로 분할, 좌우 아님). | `.s-full` + `.canvas-fill` |
| `grid-mosaic` | 동급 카드 **격자**(2×2·3×2·4×2·bento·gallery). | `.grid-2/3` · card-grid |
| `diagram-centric` | **시각물이 주인공**, 텍스트는 라벨/캡션 최소. | `.s-full` + 코드 다이어그램 element |
| `vertical-flow` | 세로로 흐르는 **스텝/타임라인**(위→아래). | 세로 스텝 스택 |
| `comparison-symmetric` | **2~3개 동등 패널**(주/부 강조 없음). | 대칭 grid |
| `split` | **좌우 비대칭**(한쪽 글·한쪽 시각). ⚠️ 드물게·연속 금지. | `.s-body-wrap`(좌 컬럼) + 우 시각 |

## 3. 구도 균형 목표 (50 콘텐츠 레이아웃)

고정 구조 슬라이드 6종(표지·도입·아젠다·파트전환·클로징·리캡)은 **별도**로 세지 않는다.

| 패밀리 | 목표 수 |
|---|---|
| full-bleed | 7 |
| centered | 7 |
| top-down | 8 |
| grid-mosaic | 8 |
| diagram-centric | 6 |
| vertical-flow | 5 |
| comparison-symmetric | 5 |
| **split** | **4 (≈8% 캡)** — 좌글 2 + 우글 2 |
| **합계** | **50** |

> split 4개는 방향(좌/우)까지 분산해 "항상 우측 시각" 편향을 원천 차단.

## 4. 레이아웃 항목 스키마 (families/*.md)

각 항목은 아래 필드를 **모두** 갖는다(검증 대상):

| 필드 | 뜻 | 예 |
|---|---|---|
| `id` | 고유 ID `L-<family>-<slug>` | `L-fullbleed-statement` |
| `name` | KO / EN 이름 | 큰 선언 / Full-bleed Statement |
| `composition_family` | 8패밀리 중 1 | `full-bleed` |
| `info_shapes[]` | 이 레이아웃이 맞는 정준 모양(역인덱스 구동) | `[declaration]` |
| `when_to_use` | 언제 쓰나 | 한 문장으로 좌중을 멈출 때 |
| `when_to_avoid` | **언제 쓰지 마나(필수 — no default 강제)** | 항목이 2개↑거나 데이터가 있을 때 |
| `capacity` | 담을 수 있는 양(40~50대 폰트 하한 기준) | 제목 ≤12어, 콜아웃 ≤1 |
| `built_on` | 사용하는 deck.css 프리미티브 | `.s-full`, `.cm-title` |
| `content_slots[]` | 채우는 이름난 슬롯 | title, sub, callout |
| `sketch` | ASCII 와이어프레임 | (아래 예 참조) |
| `coded` | 코드 구현 여부 + catalog.html 앵커 | `yes #L-fullbleed-statement` |
| `density_note` | 가독성 하한 준수 메모 | 본문 22px에서 3줄까지 |

`sketch` 예:
```
┌──────────────────────────┐
│                          │
│     큰 선언 한 문장       │   ← full-bleed, 중앙
│     [보조 콜아웃 1]       │
│                          │
└──────────────────────────┘
```

## 5. 차트/다이어그램 항목 스키마 (charts.md · diagrams.md)

레이아웃 스키마 + 아래 추가 필드:

| 필드 | 뜻 | 예 |
|---|---|---|
| `kind` | chart \| diagram | `diagram` |
| `data_shape` | 어떤 데이터/관계에 맞나 | pie=3~6 항목·합≈100 / venn=포함 1~2겹 |
| `element_vs_slide` | **(필수)** 재사용 **fragment 마크업**을 whole-slide와 **분리** 선언 | fragment=`.viz-concentric`, 데모 슬라이드=별도 |
| `placement[]` | 어느 레이아웃 패밀리에 얹히나 | `[centered, diagram-centric, split]` |
| `capacity` | 가독성 붕괴 전 최대 계열/조각 | bar ≤6, pie ≤6 |
| `a11y` | `role="img"` + aria-label 패턴 | `role=img aria-label="..."` |

> **핵심(옛 `.venn-slide` 문제 해결):** 차트/다이어그램은 **element(요소)** 이지 whole-slide 클래스가 아니다. `element_vs_slide`로 fragment를 독립 선언하고, 레이아웃은 카탈로그에서 따로 골라 그 안에 **얹는다**. "레이아웃 ≠ 다이어그램."

## 6. 역인덱스 포맷 (by-shape.md)

12 모양 각각에 대해 **후보를 순위**로 나열 + 한 줄 구분자:

```
## containment (구성·포함)
1. D-concentric — 한 요소가 다른 것에 완전히 속할 때(오늘의 주제 강조)
2. D-venn — 두 집합이 부분 겹칠 때
3. D-tree — 부분-전체가 여러 계층일 때
(레이아웃 후보) L-centered-diagram, L-diagramcentric-hero
```

**규칙: split 패밀리 레이아웃은 어떤 모양에서도 1순위로 랭크하지 않는다**(원칙 A를 순서로 구현).

## 7. 검증 체크리스트

### 항목별 (P2/P4 검증 서브에이전트 — 대부분 정적 grep)
- [ ] 격리 렌더 1280×720에서 콘텐츠 rect ≤ 슬라이드 rect (오버플로 0)
- [ ] 토큰만 사용: `:root` 밖에 raw `#hex` 없음, deck.css 프리미티브 + 선언된 추가분만
- [ ] 스키마 필드 전부 존재, `info_shapes[]` 값 ∈ taxonomy 12개
- [ ] `by-shape.md`에 각 주장 모양 아래 등재됨
- [ ] `composition_family` 라벨 = 파일명, 패밀리 수 = §3 균형표
- [ ] (차트/다이어그램) `role="img"` + 비어있지 않은 aria-label, `element_vs_slide` fragment 존재
- [ ] **no-default 감사(의미 기준)**: 어떤 레이아웃도 "기본/가장 흔한/주로 쓰는/최다/default/go-to 레이아웃"으로 규정하지 않음. (정규식 예: `(기본|가장 흔한|주로 쓰|최다|default|go-to)\s*(레이아웃|구도|슬라이드)`. '기본 스타일'·'no-default 원칙' 등 레이아웃 우위와 무관한 용례는 통과.)

### 덱별 (P6 eval 어서션)
- [ ] part-divider 수 = 파트 수 · 콘솔 에러 0 · Pretendard 로드 · 네비 동작
- [ ] 콘텐츠 슬라이드 가독성 하한(본문 ≥22px, 표 ≥17px)
- [ ] **균형: split ≤ 캡% · 연속 2슬라이드 같은 패밀리 금지 · 서로 다른 패밀리 ≥ N**
- [ ] **코드-viz(‹img› 아님)**: numeric/structure 슬라이드는 `.code-*`/SVG 사용
- [ ] 스크린샷은 `screen-operation` 요청 슬라이드에만

## 8. 소스 정확성 규칙 (리서치 단계)

- 항목당 **열리는 신뢰 소스 ≥ 1** — 리서치 에이전트가 `WebFetch`로 실재 확인, 못 여는 소스는 항목 **기각**.
- 웹 소스는 **영감**일 뿐 — 원본 복제 금지. deck.css 토큰으로 **재표현** + adaptation note 필수.
- 차트 적합성 규칙 준수(예: pie는 부분-전체 ≤~6조각, line은 시계열/연속량).
