## [C-마지막작동상태보호] 마지막 작동 상태 보호
<!-- 구간:5,6 | 유형:실습연계 | 우선:P0 | 출처:S-700,S-701,S-703,S-704,S-705,S-706 | 태그:안전,복구,되돌리기 -->

- **정의(정확):** 핵심 기능이 처음 작동한 직후, 다음 수정으로 그 기능이 깨질 경우 되돌아갈 "마지막으로 잘 되던 상태"를 미리 남겨 두는 운영 안전 행동이다 [S-000].
- **초보자 문장:** 무언가를 고치기 전에, 지금 잘 작동하는 상태를 그대로 한 벌 남겨 둡니다. 고치다가 잘못되면 남겨 둔 그 상태로 돌아오면 됩니다.
- **비유①:** 문서를 크게 고치기 전에 '다른 이름으로 저장'해 원본을 남겨 두는 것. [매핑: A=지금 작동하는 프로젝트 폴더=원본 문서·B=앞으로 할 수정=편집본] (오해 위험: 자동으로 남는 게 아니라 사람이 직접 한 번 남겨 두어야 한다)
- **비유②:** 등산 중간 갈림길마다 리본을 묶어 두는 것. [매핑: A=마지막 작동 상태=리본 묶은 지점·B=수정하다 길을 잃음=리본으로 되돌아갈 지점]
- **워크드 예시:** '오늘의 활동 기록 도구'에서 활동 입력 → 기록하기 → 오늘 기록 표시가 처음 성공한다(입력: "산책 30분" → 결과: 목록에 "산책 30분" 추가). 여기서 프로젝트 폴더 전체를 복제해 '활동기록도구_백업'으로 남긴다 → 이후 '기록 삭제 버튼'을 추가하다 목록이 안 뜬다 → 남겨 둔 백업 폴더의 상태와 비교하거나 그 상태로 되돌린다. (창작, 조작 근거 [S-706])
- **비교표:** | 구분 | 앱 되돌리기·변경검토(a·b) | 폴더 복제(c) | 형식 — | Git 필요 | 변경 검토(diff) 화면은 Git 저장소 필요 [S-700] | 불필요, 탐색기 복사·붙여넣기만 [S-706] | / | 조작 위치 | ChatGPT 앱 안 | Windows 탐색기 | / | 보고된 위험 | 되돌리기 관련 오작동 보고 있음 [S-703][S-705] | 원본·백업 폴더 혼동 가능 |
- **사례(실무):** Codex의 되돌리기(Undo)가 되돌린 파일을 곧바로 Git에 staging해 버려 문제라는 개발자 보고가 있다(VS Code 확장 v0.4.19 기준) [S-703 | 경험 진술]. 또 변경 검토 화면의 diff 목록이 잠깐 떴다 사라지고 되돌리기 버튼이 아무 동작도 하지 않아 4~5회 재시도가 필요했다는 보고도 있다(VS Code 확장, Codex 0.4.69) [S-705 | 경험 진술].
- **대안·비교:** 마지막 작동 상태를 남기는 방식은 세 가지가 비교된다 — (a) Codex 앱의 되돌리기(undo/revert), (b) 앱의 변경 검토(diff) 화면에서 되돌리기, (c) Windows 탐색기로 프로젝트 폴더를 통째로 복제. 앱은 개별 청크·파일 단위로 stage·revert를 앱 안에서 할 수 있으나 [S-701], (b) 변경 검토(diff) 화면 자체가 공식 문서상 Git 저장소가 있어야 열리며 없으면 앱이 Git 저장소를 만들라고 안내한다 [S-700]. (c)는 Git 없이 탐색기 복사·붙여넣기(Ctrl+C/Ctrl+V)만으로 되고 앱과 무관하다 [S-706]. (어느 방식을 채택할지는 총괄 결정 대기 — D10.)
- **한계·반론:** 되돌리기 기능은 인접 표면(VS Code 확장·CLI)에서 Git 흐름에 묶여 있거나(되돌리면 Git에 staging됨 [S-703]) 동작이 불안정하다는 보고 [S-705], 심지어 되돌리기·다시하기 기능을 되살려 달라는 CLI 요청 [S-704]까지 있어, Git을 쓰지 않는 로컬 폴더 초보자가 되돌리기만 믿기 어려운 국면이 있다. 이 수업은 Git·GitHub를 다루지 않으므로 [S-000], Git이 전제되는 변경 검토(diff) 화면은 기본 흐름에서 바로 쓰기 어렵다 [S-700].
- **흔한 오해→교정:** "되돌리기 버튼만 누르면 언제든 안전하게 원래대로 온다" ✗ → 되돌리기가 파일을 Git에 staging하거나 실제로는 되돌려지지 않는 사례가 보고돼 있어, 별도 백업 없이 되돌리기만 믿는 것은 위험하다 ✓ [S-703]
- **흔한 오해→교정:** "폴더를 복제하면 그게 곧 인터넷에 올릴 배포본이다" ✗ → 복제본은 되돌아갈 안전용 사본일 뿐이고, 3주차 배포 대상 폴더와는 명확히 구분해야 한다 ✓ [S-000]
- **verbatim:** "The review pane requires a project inside a Git repository." (S-700, 2026-07-21 확인)
- **PPT 소재:** 3후보(앱 되돌리기·변경 검토·폴더 복제) 비교표에서 'Git 필요/불필요' 열을 강조; 폴더 복제 전후 탐색기 화면(원본 폴더 + '_백업' 폴더 두 개) 캡처.
- **피해야 할 표현:** "되돌리기는 항상 안전하다", "이 방식이 정답이다"(D10 미확정이라 단정 금지), "백업=배포".

## [C-3주차인수상태] 3주차 인수 상태
<!-- 구간:6 | 유형:개념 | 우선:P0 | 출처:S-707,S-503 | 태그:인수,정적,폴더자립 -->

- **정의(정확):** 2주차 프로젝트를 3주차에 그대로 이어받아 저장·배포·공유할 수 있도록, 프로젝트 루트에 prd.md와 세 웹 파일(index.html·style.css·script.js)이 있고 외부 서버·빌드·절대경로·프로젝트 밖 파일에 의존하지 않으며 폴더를 다시 찾아 열 수 있는 상태를 말한다 [S-000].
- **초보자 문장:** 다음 주에 이 프로젝트를 그대로 열어 이어서 작업할 수 있도록, 필요한 파일이 모두 한 폴더 안에 있고 그 폴더만 있으면 화면이 뜨는 상태로 정리해 둡니다.
- **비유①:** 이사 갈 때 짐을 상자 하나에 다 넣어 그 상자만 들면 되는 상태. [매핑: A=프로젝트 폴더=상자·B=외부 의존 없음=상자 밖에 두고 온 짐이 없음] (오해 위험: 인터넷 링크로 불러오는 폰트·이미지는 '상자 밖 짐'이라 상자만 옮기면 빠진다)
- **비유②:** 도시락처럼 먹을 것이 통 안에 다 들어 있어 다른 데서 꺼내 올 필요가 없는 상태. [매핑: A=한 폴더 자립=도시락 통·B=폴더만 있으면 화면이 뜸=뚜껑 열면 바로 먹음]
- **워크드 예시:** 폴더 안에 index.html·style.css·script.js·prd.md만 있고 index.html이 `./style.css`처럼 같은 폴더 상대경로로 참조하면, 폴더를 다른 위치로 통째 옮겨도 화면이 똑같이 뜬다. 반대로 `C:\Users\내이름\Desktop\...` 같은 절대경로나 인터넷 주소로 참조하면 폴더를 옮기거나 배포할 때 깨진다. (창작, 근거 [S-503])
- **사례(실무):** ChatGPT Sites는 로컬 프로젝트를 배포할 때 "이 프로젝트를 Sites로 배포해 달라"고 요청하면 호환 여부를 먼저 확인하고 필요한 변경을 한 뒤 배포 URL을 준다 [S-707 | 경험 진술 아님]. 다만 일부 프레임워크·비공개 네트워크·데이터베이스·백그라운드 서비스·호스팅 방식은 지원되지 않아 [S-707], 순수 정적(HTML·CSS·일반 JS) 상태로 넘겨야 인수가 매끄럽다.
- **한계·반론:** 절대경로나 전체 도메인이 박힌 링크는 파일을 옮기면 그대로 깨진다 — MDN은 이동 이식성 때문에 상대경로를 권한다 [S-503]. 따라서 내 컴퓨터에서 file://로만 잘 열리던 폴더라도 절대경로·외부 링크·프로젝트 밖 파일 의존이 섞여 있으면 3주차 인수·배포에서 문제가 될 수 있다.
- **흔한 오해→교정:** "내 컴퓨터에서 열리면 3주차 배포도 당연히 된다" ✗ → 절대경로·외부 링크·프로젝트 밖 파일 의존이 있으면 폴더를 옮기거나 배포할 때 깨질 수 있다 ✓ [S-503]
- **흔한 오해→교정:** "prd.md는 웹페이지가 실행 중에 불러오는 파일이다" ✗ → prd.md는 Codex가 제작 전에 참고하는 기준 문서이며, 브라우저가 실행 중 불러오는 데이터 파일이 아니다 ✓ [S-000]
- **verbatim:** "Some frameworks, private networks, databases, background services, and hosting patterns aren't supported." (S-707, 2026-07-21 확인)
- **PPT 소재:** '상자 하나에 다 담기' 폴더 자립 도식(폴더 안 4파일 + 화살표가 폴더 밖으로 나가지 않음); 상대경로 vs 절대경로 이동 시 깨짐 비교 그림.
- **피해야 할 표현:** "무조건 배포된다", Sites 세부 조작 단정(3주차 선행검증 영역이라 회피), "Git이 꼭 필요/불필요" 단정.
