## 1. 의미 색 시스템 ("색은 문법")
| 역할 | 색 | fill 위 글자 | 밝은 배경 위 글자·보더 |
|---|---|---|---|
| **구조·주강조** | `--blue #1D4ED8` | 흰색 | `--blue #1D4ED8` |
| **행동·성공·안전** | `--mint #14B8A6` | `--on-mint #083B36` | `--mint-deep #0F766E` |
| **주의·경고** | `--coral #F97360` | `--on-coral #5C1C12` | `--coral-deep #C2452F` |
| **오류·위험** | `--red #DC2626` | 흰색 | `--red #DC2626` |

- **한 슬라이드 강조 1개**(70/20/10) 유지. 코랄은 작은 요소·비교의 한쪽만, 넓은 면 금지.
- **색 단독 의미 금지** → 아이콘/문구/보더 병기(ui-ux-pro-max 접근성). 오류는 `role="alert"`.
- `--mint-deep`은 **옛 `--green #0F766E` 값을 그대로 재사용** → 성공 텍스트 대비가 이전과 동일(무회귀).

## 1b. 박스 표면 규칙 (2026-07-16 추가 — verify_deck.py 강제)
> 흰 캔버스 위 카드/박스 표면이 흰 fill + `--line`(#E5E8F0) 근백색 보더로만 구분되면 박스가 안 보인다(사용자 리포트, 1주차 덱). 다음 둘 중 하나로 강제한다.

1. **의미 틴트 fill** — 구조=`--blue-soft`(기본) / 행동·성공=`--mint-soft` / 주의=`--coral-soft` + **같은 계열 틴트 보더**(`--blue-line`/`--mint-line`/`--coral-line`).
2. **흰 fill + 명확한 유색 보더** — `--blue-line-strong`(#CDDBFF) / `--mint-line`(#C9EAE4·신규) / `--coral-line`(#FBD8CF). 촘촘한 그리드(rev-card 8장·린캔버스 9칸·metric 5열 등)는 블루 도배 방지를 위해 이쪽.

- **금지**: 흰 fill(+근백색 `--surface-alt` 포함) + 축약형 `border:…var(--line)` 조합. `--line`은 표 셀선·`border-top/-bottom/-left`류 **내부 구분선 전용**.
- **예외**: 코드/터미널 표면(`.viz-code`·`.cover-terminal`·`.co-bar`) · 주석 스크린샷 창(`.shot-*`) · `.pd-dot`(비활성 상태 도트) · `table.t` · `.slide` 캔버스/인쇄 body.
- **신규 토큰**: `--mint-line:#C9EAE4`(deck.css `:root`). §2 스냅샷은 v2(2026-07-13) 당시 기준이라 미포함 — 라이브 정본은 `kit/styles/deck.css`.
- **대표 매핑**: `.card`=`--blue-soft`+`--blue-line` · `.card.surface`=`--blue-panel`+`--blue-line-strong`(뮤트) · `.work-step`=`--mint-soft`+`--mint-line` · `.callout` 기본=`--blue-soft`(`--surface-alt` 폐지) · `.plain-line`/`.note`/`.reverse-card`/`.actor-card`/`.flow-step`/`.pricing-method`/`.price-detail-card`=블루 틴트 · `.rev-card`/`.cmp`/`.lc`/`.risk-card`/`.metric`/`.mapc`/`.concept-card`/`.pill`/`.venn-tag`/`.cyc-node`/`.rad-sat`/`.cc-side`/`.quad-card`=흰 fill+`--blue-line-strong` · `.risk-card.warn`=+`--coral-line` 에코 · `.cc-side.human`=+`--mint-line` 에코 · `.hint-reveal`=`--mint-line` 보더 · `.hr-tag`=`--mint` 보더.
- **정렬 규칙(같은 날 추가)**: `.work-step`·`.agenda-item`은 `align-items:center`(원형 배지 대비 텍스트 수직 중앙, `<b>`만 있어도). `.s03-slide .an-item`은 커넥터 좌표가 상단 정렬 전제라 예외. 고아 마진 방지: `.work-step b:last-child{margin-bottom:0}`(deck.css + patterns.css `.eval-steps` 스코프 양쪽).

## v2.1 템플릿 규칙 (렌더 코드 적용됨 — 조립 시 반드시 준수)

> v2 색 확정 이후 굳어진 **템플릿 리듬·배지·헤더 규칙**. 코드(`kit/styles/deck.css`)에 이미 적용됨. 아래는 정본 기록이며 조립 에이전트는 이대로 따른다.

### ⚠️ 배지 색 분리 (가장 흔한 오적용 — 절대 혼동 금지)
- **민트 fill 배지 = 오직 3종**: `.num-circle` · `.work-step .n` · `.pd-dot.is-active`. (진행·순서·활성 = 민트=행동/진행.)
- **블루 유지 = 다이어그램/플로우 노드 전부**: `.cyc-node .cn` · `.vt-root` · `.rad-hub` · `.rad-sat .tag` · `.flow-step .n` · `.rev-no` · `.quad-card .qn` · `.lc-n`, 그리고 `.timing`. (블루=구조.)
- 즉 "번호가 붙었다 → 민트"가 아니다. **진행 배지 3종만 민트**, 구조를 그리는 노드·타이밍은 블루. 이들 노드 셀렉터를 민트로 바꾸지 말 것.

### eyebrow = 태그 (rule 6)
- `.s-eyebrow`는 **`--blue-soft` 배경의 pill 태그**(블루 텍스트), **본문 슬라이드만**. 고정 슬라이드(표지·도입·아젠다·마무리)의 eyebrow는 plain(배경 없음).

### accent-bar = 슬림 (rule 7)
- `.accent-bar` = **64 × 5px** 슬림 블루 바.

### work-step 조임 (rule 8)
- `.work-step`: padding **11px** / gap **10px**.

### 헤더 파트진행 (rule 9)
- **본문 슬라이드 헤더 우측** = `PART n/N` + 진행 도트(현재 파트 도트 = 민트), divider 기준 자동 계산. JS가 `.s-part`를 주입.
- **고정 슬라이드**(표지·도입·아젠다·마무리)는 파트진행 주입 안 함(JS의 `fixed` 예외 목록). 우측 팀명은 표지·도입·마무리만 유지 — **아젠다는 팀명 제거**(로고·라인만), **파트전환은 헤더 전체 제거**(§6b, 2026-07-14 갱신).

### 하단 페이지네이션 (rule 10)
- 하단에 `n/전체` 페이지 번호, **표지·마무리 제외**, 자동. JS가 `.s-pageno` 주입.
