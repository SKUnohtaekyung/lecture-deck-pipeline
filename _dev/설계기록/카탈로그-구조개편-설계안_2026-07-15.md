## 0. 문제 한 줄

카탈로그는 **콘텐츠 의도**(비교·흐름·포함…)로만 분류돼 있어 **자기 구도 중복을 볼 수 있는 축이 없다.** 그래서 "50개·split 8% 균형"은 의도 축에선 맞지만, 관객이 실제로 경험하는 **구도 축에선 상위 3종이 64%**로 쏠려 있다. 쏠림은 문서가 단속하는 좌우가 아니라 **위·중앙(80%)이고 하단 앵커는 0개**다.

**해법: 의도 축과 직교하는 "구도(composition-shape) 축"을 심어 → (1) 반복을 측정·차단하고 (2) 중복을 접고 (3) 미탐색 구도를 채운다.**

## 1. 왜 도구를 둘로 나누나 (거친 태그 + 고운 접기맵)

| 도구 | 입도 | 목적 | 왜 이 입도 |
|---|---|---|---|
| **구도 태그** (`composition_shape`) | 거침 (8종) | 조립 시 **연속 슬라이드 반복 차단** + 덱 분포 측정 | 3×2 카드 다음에 2×2 매트릭스가 오면 관객은 "또 격자"로 느낀다 → 반복 감지는 **거칠어야** 잡힌다 |
| **접기 맵** (canonical + variant) | 고움 (변주 단위) | **카탈로그 슬림화**(잉여 ID 제거) | 무엇이 무엇의 파라미터 변주인지 세밀히 봐야 접을 수 있다 → 슬림화는 **고와야** 정확하다 |

하나의 태그로 둘 다 하려 하면 실패한다(반복 규칙엔 너무 잘게, 슬림화엔 너무 굵게). **둘은 별개 산출물.**

## 2. 구도 축(composition-shape) — 8종 정의 + 50개 태깅

### 2.1 8 구도 원형 정의

| 태그 | 정의 (무엇이 구별하나) | 무게중심 |
|---|---|---|
| `solo-center` | 정중앙 **텍스트/숫자** 단일 덩어리, 대칭 여백 | 중앙 |
| `stage-figure` | **다이어그램/도해**가 무대 전체(텍스트는 라벨·캡션) | 중앙~풀폭 |
| `band-grid` | 상단 타이틀 밴드 + 아래 **동급 격자/타일/표/2×2** 필드 | 상단→아래 |
| `band-figure` | 상단 밴드 + 아래를 **단일 차트 하나**가 지배(막대·컬럼) | 상단→아래 |
| `flow-vertical` | **세로 스택 시퀀스**(행을 위→아래, ↓/→ 커넥터) | 상단→아래(좌 레일) |
| `panels-mirror` | **동등 패널 미러**(좌우 2~3열 또는 상하 밴드), 위계 0 | 좌우/상하 균형 |
| `split-asym` | **좌우 비대칭**(한쪽 글·한쪽 시각) | 좌 또는 우 |
| `image-bleed` | **풀블리드 이미지**(+오버레이/하단 밴드) | 풀 |

### 2.2 50개 태깅 결과 (전수)

| 구도 태그 | 개수 | 소속 레이아웃 |
|---|---|---|
| `band-grid` | **14** | td-table · td-swiss-columns · td-metric-row · td-matrix · td-bento · gm-quad · gm-cards-3x2 · gm-tiles-4x2 · gm-bento · gm-gallery · gm-checklist · gm-compare-cards · gm-matrix · cs-dual-table |
| `solo-center` | 9 | fb-statement · fb-bignum · fb-quote · fb-oneword · fb-question · ct-statement · ct-question · ct-quote · ct-definition |
| `stage-figure` | 9 | ct-figure · ct-concentric · ct-pyramid · dc-hero · dc-annotated · dc-radial-hub · dc-quadrant · dc-network · dc-flow-canvas |
| `flow-vertical` | 6 | vf-spine-timeline · vf-numbered-stack · vf-funnel · vf-chevron-map · vf-cascade-map · td-mapping-rows |
| `panels-mirror` | 4 | cs-side-by-side · cs-central-contrast · cs-triptych · cs-before-after |
| `split-asym` | 4 | sp-anchor-left · sp-golden-left · sp-visual-lead · sp-rule-right |
| `band-figure` | 2 | td-compare-bars · td-column-series |
| `image-bleed` | 2 | fb-photo · fb-caption-band |

### 2.3 이 태그가 즉시 드러내는 두 편향 (측정치)

**집중도** — 상위 3종(band-grid + solo-center + stage-figure) = **32/50 = 64%.** band-grid 하나가 28%. 조립 규칙이 없으면 덱은 이 셋만 반복하게 된다.

**무게중심 쏠림** — 태그를 무게중심으로 다시 접으면:

| 무게중심 | 구도 | 개수 | 비중 |
|---|---|---|---|
| 중앙 | solo-center + stage-figure | 18 | 36% |
| 상단→아래 | band-grid + band-figure | 16 | 32% |
| 세로 하강 | flow-vertical | 6 | 12% |
| **좌우/상하 균형** | panels-mirror + split-asym | 8 | 16% |
| 풀 이미지 | image-bleed | 2 | 4% |
| **하단 앵커** | — | **0** | **0%** |

→ **위·중앙 = 80%, 하단 앵커 = 0%.** 좌우분할(단속 대상)은 8%로 오히려 균형축. **이게 개편이 겨눌 표적이다.**

## 3. 중복 접기 맵 — 50 → 30 캐노니컬 (비파괴)

**원칙:** 잉여 ID를 **삭제하지 않는다.** 캐노니컬 항목 하나 + `variant` 파라미터로 흡수하고, 흡수된 ID는 "→ 캐노니컬 참조, variant=X" 스텁으로 남긴다(커밋 이력 약함 → 보존 우선). 검증·조립이 안정된 뒤에만 스텁을 `탐색-아카이브/`로 이동.

| # | 캐노니컬 | 흡수(→ 스텁) | 변주 파라미터 | 절약 |
|---|---|---|---|---|
| F1 | `solo-display` | ct-statement · ct-question · ct-quote · ct-definition · fb-statement · fb-bignum · fb-quote · fb-oneword · fb-question | `kind`={선언·질문·인용·단어·숫자·정의}, `scale`=52–320px | **−8** |
| F2 | `matrix-2x2` | gm-quad · td-matrix · dc-quadrant | `mode`={분류·매핑·플롯} | −2 |
| F3 | `title-table` | td-table · cs-dual-table · gm-matrix | `cell`={값·✓/✕}, `cols` | −2 |
| F4 | `bento` | gm-bento · td-bento | (동일) | −1 |
| F5 | `mirror-2panel` | cs-side-by-side · cs-central-contrast | `connector`={없음·≠} | −1 |
| F6 | `vstack-rows` | vf-numbered-stack · vf-chevron-map · vf-cascade-map | `connector`={↓·→}, `right`={없음·카드} | −2 |
| F7a | `split-left` | sp-anchor-left · sp-golden-left | `ratio`={50·62} | −1 |
| F7b | `split-right` | sp-visual-lead · sp-rule-right | `divider`={없음·룰} | −1 |
| F8 | `cols-equal` | cs-triptych · td-swiss-columns | `n`=3 | −1 |
| F9 | `figure-center` | ct-figure · dc-hero | (동일) | −1 |

**합계 −20 → 50개가 30개 캐노니컬로.** 남는 20개(radial-hub·network·annotated·concentric·pyramid·funnel·spine-timeline·before-after·compare-bars·column-series·metric-row·cards-3x2·tiles-4x2·gallery·checklist·compare-cards·flow-canvas·photo·caption-band + solo/matrix/table/bento/mirror/vstack/split-l/split-r/cols/figure 캐노니컬 10)은 **진짜 서로 다른 구도**라 접지 않는다.

> ⚠️ **F1이 가장 공격적이다**(fb 초대형 + ct 중형을 한 캐노니컬로). "full-bleed와 centered는 폰트 스케일만 다른 같은 중앙 구도"라는 판단인데, 두 패밀리를 별개로 유지하고 싶으면 F1을 fb-only/ct-only 두 캐노니컬로 완화 가능. **승인 시 결정.**

## 4. 미탐색 구도 — 신규 3종 (편향 해소)

§2.3의 "위·중앙 80% / 하단 0%"를 직접 겨냥. 전부 평면·토큰 시스템 안에서 성립(레이어/그림자 남용 없음).

| 신규 ID | 구도 | 무엇 | 겨누는 편향 | 맞는 정보모양 |
|---|---|---|---|---|
| **N1 `anchor-bottom`** | 하단 앵커 | 큰 문장/결론을 **바닥에 깔고 위를 비움**(여백=무대) | 중앙·상단 독점 | declaration |
| **N2 `column-right`** | 우측 주컬럼 | 우측을 **상시 주 텍스트 컬럼**으로, 좌측은 세로 지표/이미지 레일 | 좌상단 진입 독점 | concept · comparison |
| **N3 `bands-stacked`** | 전폭 적층 밴드 | 수평 밴드 **3~4단** 적층(before-after 2단의 확장) | "밴드+격자" 단조 | flow · comparison · classification |

N1 스케치:
```
┌──────────────────────────────────────────────┐
│  s-head                                        │
│                                                │
│                (빈 무대 / 여백)                 │
│                                                │
│  측정하지 않으면                                │  ← 하단 앵커, 큰 문장
│  고칠 수 없다.  ← .hl                          │
└──────────────────────────────────────────────┘
```

N2 스케치:
```
┌──────────────────────────────────────────────┐
│  s-head                                        │
│  ┌────────┐   EYEBROW                          │
│  │ 세로   │   개념 제목 한 줄                   │
│  │ 지표   │   ───(accent)                       │
│  │ 레일   │   본문 4~5줄이 우측 주컬럼에.        │
│  │ (보조) │   [파란 콜아웃]                     │
│  └────────┘                                    │
└──────────────────────────────────────────────┘
   ← 좌: 보조 레일        우: 글(主) — 상시구도
```
> N2 vs split: split은 8% 캡의 "희소·비연속" 도구다. N2는 **좌측이 장식이 아니라 구조적 보조(진행/지표)**인 상시 구도라 캡 밖. 다만 "우측 글" 방향이 split-right와 겹치지 않게 좌측 레일의 기능성(정보 요소)으로 구별한다.

N3 스케치:
```
┌──────────────────────────────────────────────┐
│  타이틀                                        │
│ ┌──────────────────────────────────────────┐ │
│ │ 밴드 1 — 전폭 헤더 + 지표행               │ │
│ ├──────────────────────────────────────────┤ │
│ │ 밴드 2 — 전폭                            │ │
│ ├──────────────────────────────────────────┤ │
│ │ 밴드 3 — 전폭                            │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

**선택(실험적, 리스크 있어 후순위):** `offset-focus`(3분할 대각 앵커) · `rail-sidebar`(풀하이트 레일). 평면 시스템과 마찰 가능성 있어 P4 이후 별도 검토.

## 5. 조립 규칙 + verify_deck.py 강제

| 규칙 | 지금 | 개편 후 |
|---|---|---|
| 연속 반복 | "직전과 같은 **패밀리** 회피" | "직전과 같은 **구도 태그** 회피"(패밀리 달라도 둘 다 band-grid면 반복) |
| 분포 측정 | **split만** 8% 캡 측정 | **전 구도 분포** 측정 — 한 구도가 덱의 X%(예 35%) 초과 시 WARN |
| 역인덱스 | 의도 축만 | 후보마다 **구도 태그 병기**(의도로 뽑되 구도 반복 피해 고름) |

`verify_deck.py` 신규 검사(정적):
1. 각 레이아웃 항목에 `composition_shape` 필드 존재 + 값 ∈ 8종 (항목별)
2. 덱: 연속 2슬라이드 `composition_shape` 동일 → **FAIL** (덱별)
3. 덱: 단일 구도 비중 > 임계% → **WARN** (덱별)
4. split 캡(기존)은 유지하되 3의 특수 케이스로 편입

## 8. 승인 필요 결정 포인트 (당신이 고를 것)

1. **범위** — 전체(P1~P4) 승인인가, **P1만 먼저**(권장)인가?
2. **F1 공격성** — 중앙 텍스트 9개를 한 캐노니컬로 접나(fb+ct 통합), 아니면 fb/ct 두 캐노니컬로 완화하나?
3. **구도 태그 8종** — 이 8개 분할선에 동의하나? (예: `band-figure`를 `band-grid`에 합쳐 7종으로 줄일지, `dc-flow-canvas`의 가로흐름을 9번째 태그로 뗄지)
4. **신규 구도** — N1~N3 전부인가, 일부인가? (하단 앵커 N1이 편향 해소 효과 최대)
