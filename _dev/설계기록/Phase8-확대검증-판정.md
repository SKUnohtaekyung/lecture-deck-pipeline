## 2. ② 과거 로그 재생 — 신규 통제가 무엇을 잡았을 것인가

2주차 실행의 원본 트랜스크립트(워커 19 + 직접 Agent 1)를 신규 `--tool-audit`로 재생했다.
**이 실행은 통제가 없던 시절의 것이므로, 여기서 잡히는 것이 곧 신규 구조가 막았을 것들이다.**

| 발견 | 규모 | 신규 구조에서는 |
|---|---|---|
| **모델이 Opus** | **19/20** (sonnet은 1개뿐) | `model: "sonnet"` 호출 파라미터로 **구조적 고정** |
| **워커가 `Write` 사용** | **18/20** — 최대 **×37**, 그다음 **×21** | `Explore`가 `Write` 미보유 → **구조적 차단** |
| **워커가 `Edit` 사용** | 2개 (×1, ×4) | `Explore`가 `Edit` 미보유 → **구조적 차단** |
| **워커가 `Bash` 사용** | **19/20** — 최대 ×24 | ⚠️ 구조적 차단 **불가**. 감사로 검출만 |
| **워커가 브라우저 자동화 사용** | 1개 (`navigate`·`preview_start`·`get_page_text`) | ⚠️ 구조적 차단 **불가**. 감사로 검출만 |
| 리드가 4개 모델 혼용 | `<synthetic>`·`fable-5`·`opus-4-8`·`sonnet-5` | 실행 중 모델 전환 흔적 — 별개 이슈 |

**핵심**: `Write×37`·`Write×21` 워커는 **여러 워커가 산출물 파일을 직접 썼다**는 뜻이다.
Phase 4의 「단일 라이터」 규칙이 겨냥한 바로 그 상황이며, 신규 구조에서는 **도구가 없어 발생 자체가 불가능**하다.

### 모델 고정의 비용 함의 (정가 환산 · 가정 명시)

워커 토큰 프로필(캐시생성 8,194,967 · 캐시읽기 86,551,686 · 출력 917,494 · 신규입력 ≈0)이
**동일하다는 가정** 하에 단가만 Opus($5/$25) → Sonnet($3/$15)으로 바꾸면:

| | 정가 환산 |
|---|---:|
| 실측(2주차, 19/20 Opus) | **$112.59** |
| 동일 프로필을 Sonnet 단가로 환산 | **약 $70.5** |
| 차이 | **약 −$42 (−37%)** |

⚠️ **이것은 산술 환산이지 측정된 절감이 아니다.** 모델이 바뀌면 턴 수·재시도 패턴도 바뀌므로 실제 값은 다르다.
실제로 **측정된** 개선은 Phase 7의 동일 모델 조건 −6.0%뿐이다(n=3).

### 🔴 재생이 드러낸 신규 구조의 한계 — 워커 **간** 중복은 못 잡는다

재생에서 **동일 URL 재호출은 전 워커가 중단선(1) 이내**였다.
그런데 기준선은 「④ 고유 URL 초과 추가 호출 19건 · ③ 중복 URL 종류 15」를 기록하고 있다.

→ 모순이 아니다. **내 감사는 워커별로 보고, 2주차의 중복은 워커 사이에서 일어났다**(D12: 워커 간 13 URL/30건).
**per-worker 검사는 cross-worker 중복을 원리적으로 잡을 수 없다.** 전역 URL 레지스트리만이 수단이며 이번 범위 밖이다.

### 계측 주의 — `StructuredOutput`은 위반이 아니다

재생에서 18개 워커가 `StructuredOutput`으로 잡혔다. 이는 **Workflow 스키마 반환 채널**이지 조사 도구가 아니다.
신규 구조는 직접 `Agent` 호출을 쓰므로 이 도구가 나타나지 않는다. **Workflow 경로로 워커를 띄운다면 오탐이 나므로 그때 허용목록에 넣어야 한다.**

## 6. ④ 제한된 추가 청크를 실행하지 않은 이유

- ②가 **20 에이전트** 규모의 실증을 이미 제공했다 — 3청크를 6청크로 늘리는 것보다 정보량이 크다.
- 계획이 **"3개 표본으로 통계적 우월성을 주장하지 않는다"**를 명시했다. 6개도 마찬가지다.
- 비용이 3청크당 약 **4M 처리 토큰**이다.
→ **사용자 옵션으로 남긴다.** 필요하면 표본을 늘려 §0.5 중단선을 재산정할 수 있다.

**"적용 가능"이 아니라 "조건부"인 이유** (계획의 조건부 정의와 정확히 일치):

1. **비용 최적값에 추가 데이터가 필요하다** — §0.5 중단선은 워커 1명이 청크 여러 개를 담당한 분포에서 왔고, 정량 중단선은 아직 한 번도 도달하지 않아 값 자체가 미검증이다.
2. **일부 설정이 provisional이다** — 중단선 5종 전부.
3. **허용목록은 구조적으로 강제되지 않는다** — `Bash`·`PowerShell`·브라우저는 감사로 검출만 한다.
4. **D2(워커 턴 상한) 미해소** — `maxTurns`가 이 실행 경로에 없다.
5. **워커 간 URL 중복은 잡히지 않는다** — 전역 레지스트리 부재.

**"적용 불가" 사유는 하나도 없다**: 품질 회귀 0 · 계약 회귀 0 · 실행 통제 실패 0 · 비용 증가 0 · Codex 폴백 정상 · 미지원 기능 의존 0.
