## §1. 근본 원인 — 규칙이 없어서가 아니었다

이번 세션에서 사용자가 지적한 6건을 역추적하면 **전부 한 지점으로 모인다.**

| 지적 | 이미 있던 규칙 | 어디에 |
|---|---|---|
| 검은 배너 87.5% 반복 | 결정표 「직전과 다른 패밀리?」 열 | `03-레이아웃선택.md` R-DEC-01 |
| 전부 박스, 차트 0장 | 2단계 정보 모양 분류 → 3단계 element **따로** 선택 | `SKILL.md` ⑤ 2·3단계, R-LAYOUT-02a |
| 참고 레이아웃 미사용 | 역인덱스 후보 뽑기 | R-LAYOUT-01b, `kit/layouts/by-shape.md` |
| 민트 강조 미사용 | R-EMPH-01 강조 선택표 | `kit/guide/디자인시스템.md` |
| 제목 정식 용어 | 확정 결정 6번 | `SESSION_HANDOFF` §0.1 |
| 이미지 없음 | 이미지 4상태 판정 게이트 | `SKILL.md` ⑤ 이미지 판정 게이트 |

**결론: 새 규칙이 필요한 게 아니라, 있는 절차를 건너뛴 것이 원인이다.** 나는 2단계(정보 모양 분류)와 3단계(역인덱스·결정표)를 통째로 생략하고 4단계 조립로 직행했다.

**결정표 한 장만 썼어도 6건 중 5건이 사전에 걸렸다.**

## §3. 무엇이 실제로 비어 있나 (신설이 필요한 부분)

§1이 "대부분 이미 있다"였다면, 이번 왕복에서 **정말로 없던 것**은 넷이다.

| # | 비어 있던 것 | 지금 상태 |
|---|---|---|
| 1 | **산문이냐 병렬이냐**의 판별 기준 | ✅ R-FORM-01 신설(콘텐츠 SKILL + by-shape) — 「순서를 바꿔도 뜻이 유지되는가?」 |
| 2 | **강조를 집필 시점에 지정**하는 계약 | ✅ R-EMPH-02 신설(콘텐츠 SKILL) — `**결론**`·`__근거__`·`*핵심어*` |
| 3 | **동점일 때 무엇을 고르는가** | ✅ 동점 규칙 신설(by-shape 2종) — 차트주도 → 글+여백 → 카드 |
| 4 | **마무리 형태의 변주** | ❌ **미신설** — 결정표에 열이 없다 |

그리고 **어느 것도 기계로 검사되지 않는다.** `verify_deck_quality.py`는 밀도·시각자료 비율을 보지만 강조 존재·마무리 반복률·결정표 작성 여부는 보지 않는다.

## §4. 계획 — 4단계

### Phase 1. 결정표에 4열 추가 (`references/phases/03-레이아웃선택.md`)

현행 R-DEC-01 결정표는 5열이다. 이번 왕복이 드러낸 축 4개를 더한다.

| 추가 열 | 무엇을 적나 | 막는 실패 |
|---|---|---|
| **형태(산문/병렬)** | 순서 바꿔도 되는가 → 병렬/산문 | 전부 박스 · 전부 줄글 |
| **강조 배정** | 결론·근거·핵심어 구절(초안 표기에서 승계) | 민트 3종 미사용 |
| **마무리 형태** | 검은 배너 / 색 띠 / 없음 / 아웃라인 | 마무리 87.5% 동일 |
| **동점 선택 근거** | 후보가 여럿일 때 왜 이걸 골랐나 | 습관적 카드 선택 |

> ⚠️ **열을 늘리는 것 자체가 목적이 아니다.** 결정표는 "판단을 눈에 보이게 만들어 원칙을 강제"하는 장치다(R-DEC-01 원문). 열이 많아 안 쓰게 되면 역효과이므로, **9열을 넘기지 않는다.**

### Phase 2. 기계 검사 3종 추가 (`scripts/verify_deck_quality.py`)

사람이 기억해야 하는 것을 줄인다. 임계값은 **1주차 최종본 분포에서 도출**한다(발명 금지 — 기존 R-QC 방식과 동일).

| 신규 | 검사 | 판정 |
|---|---|---|
| **R-QC-12 강조 존재** | 슬라이드별 `.hl-mint-mark`≤1 · 민트 3종 합계≤3 · **0개면 WARN**("결론 미지정 의심") | WARN 기본 |
| **R-QC-13 마무리 반복률** | 마지막 블록의 형태 시그니처 분포. 최다 형태가 임계 초과면 WARN | WARN 기본 |
| **R-QC-14 구조 라벨 오염** | `display:block`이 걸린 **후손** b/span 선택자 검출(CSS lint) | FAIL |

R-QC-14는 이번에 **4회 반복**된 버그다(`.ws-warn b` → `.vd-case b` → `.mt-note b` → `.fg-card span`). 문장 안 강조가 블록이 돼 줄이 끊긴다. grep 한 줄로 잡히므로 자동화 가치가 가장 높다.

### Phase 3. 초안 단계 연동 (`scripts/verify_draft_quality.py`)

강조는 조립이 아니라 **집필에서** 정해진다(R-EMPH-02). 초안에서 이미 검사한다.

- **R-QD-08 결론 표기 존재**: 행마다 `**결론**` 표기가 있는가. 없으면 WARN(도입·전환 행은 집필노트 사유로 면제).

### Phase 4. 조립 착수 전 사전 점검 1장

단계 문서를 다 열지 않아도 **빠뜨림만은 막는** 최소 체크리스트를 `references/phases/02-슬라이드맵.md` 서두에 둔다.

```
□ 정보 모양을 12 정준 모양 중 하나로 적었는가            (2단계 · 미기재면 3단계 금지)
□ 역인덱스를 실제로 열었는가 (layouts + charts)          (3단계)
□ 레이아웃과 element를 따로 골랐는가                     (R-LAYOUT-02a)
□ 형태를 순서 판별로 정했는가 (산문/병렬)                (R-FORM-01)
□ 강조 3종을 의미로 배정했는가                           (R-EMPH-01/02)
□ 직전 슬라이드와 구도·마무리가 다른가                   (R-DEC-01)
□ 이미지 4상태를 판정했는가                              (이미지 게이트)
```

## §6. 편향 방지 — 이 계획 자체에 거는 안전장치

이 계획은 **관찰 표본이 적다**(4구간 표본 12장 + 피드백 6회). 규칙으로 굳힐 때 다음을 함께 기록한다.

| 항목 | 왜 |
|---|---|
| **근거 표본 수·출처** | "1주차 17·37번 관찰 + 피드백 6회" 식으로 명시 |
| **신뢰도 등급** | 사용자 명시 확정 / 내가 관찰에서 유도 / 1회성 잠정 |
| **비적용 조건·반례** | 예: "여백 우선 ≠ 설명량 축소", "줄글 좋음 ≠ 전부 줄글" |
| **사용자 원문 보존** | 내 해석이 원문을 대체하지 않게 |
| **반대편 극단의 실패 모습** | 내 실패 패턴이 "지적받은 방향으로 전부 이동"이므로 필수 |
| **충돌 이력** | 새 피드백이 기존 규칙과 부딪히면 덮어쓰지 않고 이력 |

### 이미 확인된 반례 2건 (반드시 함께 기록)

1. **"여백 선호" → 설명량을 깎으면 안 된다.** 1주차 37번은 여백이 넉넉하면서 내용이 얕지 않다.
2. **"줄글이 좋다" → 전부 줄글은 금지.** 8장 전부 박스 → 3장 전부 줄글로 두 번 연속 극단 이동했다.

### 메타 규칙

> **지적을 전역 규칙으로 승격시키지 않는다.** 한 슬라이드에 대한 지적은 그 슬라이드의 정보 모양에 대한 것이지, 덱 전체의 기본값 변경 요구가 아니다.

- **임계값 실측** — Phase 3~5 착수 시 1주차 최종본에서 산출한다. 지금은 숫자를 적지 않는다.
- **`skills/검토/SKILL.md` 4축 확장** — 검토 스킬이 이 신설 규칙들을 어떻게 볼지는 다음 단계.
