# UX 진단 리포트 — vibecoding-deck 디자인 시스템·레이아웃 카탈로그

> 대상: `kit/guide/`(디자인시스템·토큰·규격·taxonomy) · `kit/styles/`(deck.css·legibility·patterns) · `kit/layouts/`·`kit/charts/` 카탈로그.
> 방법: 참고 파일 정독 + 팔레트 WCAG 2.1 명암비 **실측 계산**(전 조합) + 토큰·경로 정합성 grep.
> 작성: 2026-07-15. 상태: **진단만 — 수정 미적용**(승인 후 불변 규칙 §0 안에서 반영 예정).

## 총평

성숙한 시스템이다. "색은 문법", 정보모양→레이아웃 역인덱스, split 8% 캡 + no-default 헌장, 40~50대 가독성 레이어, 정적 검증기까지 — **뜯어고칠 게 아니라 마감(마무리)을 다듬을 단계**다. 아래 발견은 전면 개편이 아니라 **일관성·접근성의 마지막 5%**다.

핵심 3줄:
1. **접근성** — 팔레트 대부분 AA를 통과하나, 실제로 쓰이는 조합 2곳이 근소하게 미달(캡션·오류색). 실측 근거 있음.
2. **토큰 규율** — "토큰만 쓴다" 헌장에 반해 `patterns.css`(코드 코어)가 radius·shadow를 하드코딩. 여기서부터 드리프트가 샌다.
3. **가독성 하한 vs 실제** — "본문 ≥22px" 하한과 다이어그램 element 본문(17~20px) 사이에 규칙과 현실의 간극이 있다.

## High — 지금 고칠 것

### 1. 캡션색이 카드 배경 위에서 접근성 미달
`--gray-400`(#6B7280)은 흰 배경 위 4.83:1로 통과하지만, **카드 배경 `--surface`(#F3F5F8) 위에서는 4.43:1로 AA(4.5) 미달**이다. 캡션은 실제로 카드 안에 자주 놓인다(`.rad-sat`·`.vt-leaf`·`.dc-cap` 등). legibility 레이어가 "캡션도 읽히게" #9A9A9A→#6B7280로 이미 올렸지만 카드 위까지는 못 넘겼다.

- **제안**: `--gray-400`을 **#5E6470**로 한 단계 더(흰 5.94 / surface 5.44, 둘 다 여유 통과). 룩은 거의 그대로, 읽힘만 확보.

### 2. 오류 텍스트가 오류 틴트 위에서 미달
`--red`(#DC2626) on `--red-soft`(#FDECEC) = **4.23:1 미달**. 오류는 놓치면 안 되는 정보라 더 엄격해야 한다. (참고로 coral은 `-deep` 텍스트색을 따로 두는데 red는 fill·틴트만 있고 텍스트 전용 딥이 없다 — 구조 비대칭.)

- **제안**: 오류 텍스트 전용 `--red-deep: #C81E1E` 신설(white 5.74 / red-soft 5.02). coral/mint가 `-deep`을 갖는 패턴과 정합.

### 3. 코드 코어(patterns.css)가 토큰을 우회
"카탈로그 코드는 이 토큰/프리미티브만 쓴다"가 헌장인데, 정작 재사용 CSS 라이브러리인 `patterns.css`가:
- **radius 하드코딩**: `border-radius:16px`(cyc-node)·`18px`(rad-sat) — 토큰은 `--r-lg 20`·`--r-md 14`·`--r-sm 10`뿐이라 16·18은 **어느 토큰에도 없음**.
- **shadow 하드코딩**: `box-shadow:0 14px 32px rgba(29,78,216,.4)` 등 **8곳이 raw rgba** — `--shadow-sm/md/lg/blue` 스케일을 안 씀.

코드 코어가 새면 여기서 복사해 조립하는 모든 덱이 같이 샌다(드리프트 진원지).

- **제안**: 16→`--r-md`(14)/18→`--r-lg`(20)로 스냅, shadow는 4토큰에 매핑. 딱 안 맞는 값(예: `...216,.4` 강한 블루 글로우)은 **토큰을 하나 추가**해서라도 raw를 없앤다(예: `--shadow-blue-strong`).

## Med — 곧 정리할 것

### 4. "본문 22px 하한"과 element 본문의 충돌
가독성 정본은 **본문 ≥22px, 표 ≥17px**를 "절대 하회 금지"로 못 박는다. 그런데 element 본문 텍스트가:
`callout` 19 · `.cc-side li` 20 · `.rad-sat p` 17 · `.cyc-node b` 18 · `.vt-leaf span` 14 — **여러 곳이 하한 아래**다. 이건 실수라기보다 규칙의 회색지대: "본문"과 "라벨/보조"의 경계가 명문화 안 됐다.

- **제안**: 하한을 **역할별로 2단계 명문화** — (a) 서술 본문 ≥22px, (b) 다이어그램 라벨/캡션 ≥17px. 그리고 `callout` 19px은 "본문급 콜아웃"이면 22로, "보조 콜아웃"이면 그대로 두되 규칙에 명시. 지금은 검증기가 뭘 FAIL 처리할지 애매하다.

### 5. spacing 스케일 토큰이 없다
radius·shadow·타이포는 토큰화됐는데 **간격만 토큰이 없다**. patterns.css의 gap이 9·10·12·18·22·30px로 흩어져 있고 근거 없이 눈대중이다. 40~50대 대상 슬라이드에서 리듬이 조금씩 어긋나는 원인.

- **제안**: 4/8 베이스 `--space-1…6`(4·8·12·16·24·32) 토큰 도입, patterns.css의 임의값을 가장 가까운 스텝으로 스냅. 카드 내부 리듬이 통일된다.

### 6. 강조색 대비 여유가 얇다
`--on-mint`(4.99)·`--on-coral`(4.69)·`--coral-deep` on soft(4.52) 모두 통과하지만 **여유 0.5 미만**. 프로젝터·저품질 디스플레이·재압축 PDF에서 체감 대비는 더 낮아진다(가독성 §은 "실측 예정"이라 명시).

- **제안**: 확정 전 **실투사 테스트 1회**로 검증. 여의치 않으면 on-mint를 아주 살짝 더 짙게(#062E2A대)로 마진 확보.

## Low — 여유 될 때

### 7. 문서 stale 경로
규격 §5 제목과 `centered.md`·`diagram-centric.md` 등 **8곳이 `charts.md`·`diagrams.md`·`charts/diagrams.md`를 참조**하지만 실제 파일은 `charts-basic.md`·`charts-ratio.md`·`diagrams-process.md`·`diagrams-relational.md`다. 새 세션 에이전트가 없는 파일을 찾다 헤맨다.

- **제안**: 참조를 `charts/by-shape.md`(역인덱스 단일 진입)로 통일하거나 실파일명으로 일괄 치환.

### 8. 죽은 레거시 토큰
`--navy`(사용 금지)·`--ice`·`--electric`(레거시 미사용)가 `:root`에 남아 있다. 정의가 남아 있으면 언젠가 누가 쓴다(특히 navy는 금지 대상).

- **제안**: 주석으로 "정의 유지" 이유가 없으면 제거, navy만 회귀검증용으로 남길 거면 검증기에 `var(--navy)` 사용 0 어서션을 명시적으로.

### 9. 타입 스케일 공백 · 블루 과부하 (관찰)
- 크기 계단이 22→27→44→52로 **30~40px 구간이 비어** 중간 위계(소제목)가 44/23 사이에서 애매하다. 모듈러 스케일(예 ×1.25)로 한 칸 채우면 위계가 매끈해진다.
- `--blue` 하나가 구조·주강조·UI·차트 메인·노드·트리루트·링크를 **전부** 진다. 문서도 "파란색 도배 금지"를 경고하지만, 구조적으로 블루의 의미가 과부하다. 민트-vs-블루 배지 규칙이 "자주 위반"되는 것(MEMORY 기록)도 구분이 너무 미세하다는 신호일 수 있다. → **개편 아님**, 다음 라운드에서 "블루의 하위 역할 분리가 필요한지" 별도 검토 권장.
