# vibecoding-deck — 구조·빌드 기록

> 이 스킬을 만든 과정·결정의 보존 기록(개발용, 스킬에 안 실림).

## 목표
채워진 슬라이드 계획서 → 1280×720 HTML 웹덱(코딩 경험이 없는 입문자 중심 혼합군). 기존 문제: 카탈로그가 없어 조립이 즉흥적이고 **"좌 글/우 시각"(center-v류)로 쏠림**.

원인 3중: ① 소스가 center-v를 "가장 흔함"으로 각인, ② 킷 레이아웃 절반이 좌우분할, ③ "판단"이 강제 아닌 권유. → **금지 없이 구조로** 고침:
- **A. no-default**: 모든 레이아웃·element 동급, "기본" 프레이밍 폐기.
- **B. 판단 먼저**: 정보 모양 분류 → 역인덱스로 후보. 조립 전 결정표.
- **C. 대안 공급**: 좌우분할 아닌 구도 대거 + 코드 차트/다이어그램. 단조는 **공급+측정**으로.

## Phase 이력
- **P0** 토대: 12 정보모양 taxonomy · 카탈로그 규격(8패밀리·균형표·검증) · 토큰 치트시트 · settings · (커스텀 에이전트 3종 — 이후 미사용, 삭제).
- **P1·P2** 레이아웃 50: 8패밀리 병렬 Workflow(build→verify). 균형 50/50, split 8%(방향 분산). 소스 WebFetch 검증. by-shape 역인덱스.
- **P3·P4** 차트/다이어그램 21: 4그룹 병렬. code-viz·element_vs_slide 분리·a11y. by-shape.
- **P5** SKILL 8단계 판단 게이트 · 스타터 덱(검증) · references · 주석스크린샷.
- **P6** 엔드투엔드: 1주차 자료로 with-skill 덱 vs baseline → **다양성·코드시각화·구조 3축 모두 우세**(with-skill PASS13/FAIL0, baseline FAIL8). 이후 그 검증 CSS를 `patterns.css`로 수확.

## 핵심 결정
- **카탈로그 깊이 = 하이브리드**: 71개 전부 MD 스펙 + 고가치 코어만 코드(patterns.css).
- **판단 축 = 12 정준 + 13 폼라벨 매핑**('정보 모양'과 '표현 형식' 분리).
- **검증 = 파이프라인 + 적대 검증**: build→verify, 소스 WebFetch, verify_deck.py로 교차.

## skill-creator 자가 감사 → 치명 결함 3건 수정
1. 재현성 공백(코드 코어 없음) → `patterns.css` + 검증덱을 "본뜰 원본"으로 지목.
2. 검증 반복작업 → `scripts/verify_deck.py`(의존성 0) 번들.
3. 판단 게이트 미강제 → SKILL 4단계에 슬라이드 결정표 산물 요구.

## 멀티에이전트 — 정직한 자기평가
- **진짜 한 것**: Workflow 팬아웃(총 27 에이전트·~1.9M 토큰), build→verify 파이프라인, 구조화 출력, effort 라우팅, verify_deck.py 교차검증.
- **정석 아니었던 것**: 커스텀 `.claude/agents` 3종을 만들고 **안 씀**(general-purpose/Explore + 인라인으로 우회) → 이후 삭제. settings.json은 세션 중 생성이라 당 세션 미적용. 파일럿이 `args` 문자열 버그로 전량 실행. 검증 단일 투표.
