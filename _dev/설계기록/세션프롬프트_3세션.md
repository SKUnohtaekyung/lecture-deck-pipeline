# Claude Code 3세션 실행 프롬프트

> 사용법: 이 저장소 루트에서 Claude Code 세션을 **순서대로** 연다(A → B → C, 각 1세션).
> 각 세션 시작에 아래 해당 블록을 통째로 붙여 넣는다. 세션 간 인수인계는 `_dev/설계기록/새세션-시작.md`가 담당하므로, 뒷 세션은 전체를 다시 안 읽는다.
> 계획 출처: `_dev/설계기록/UX진단_디자인시스템_2026-07-15.md`, `_dev/설계기록/레이아웃_매크로구조_감사_2026-07-15.md`.
> 원칙: **파괴적·되돌리기 어려운 일 = 메인 단일 스레드. 많이 읽고 조금 반환하는 일(태그·검증·초안·갭분석) = 서브에이전트(Task) 팬아웃, 결과 요약만 반환.**

## 세션 A — 계측 기반 (Phase 0 a11y + Phase 1 구도 태그)

```
이 저장소는 vibecoding-deck 스킬 개발 프로젝트다. 먼저 CLAUDE.md,
.claude/agent-memory/vibecoding-deck/MEMORY.md,
_dev/설계기록/UX진단_디자인시스템_2026-07-15.md,
_dev/설계기록/레이아웃_매크로구조_감사_2026-07-15.md 를 읽어 맥락과 규칙(§0 불변요소, navy·그라데 금지,
배지 3종 한정, 토큰만 사용, 커밋 이력 약함→삭제 대신 이동)을 파악해라.

이번 세션 목표는 두 가지다.

[Phase 0 — a11y·토큰 수정 (작고 독립적, 먼저 처리)]
UX진단 리포트 High 3건을 kit/styles에서 반영한다:
1. --gray-400 을 #6B7280 → #5E6470 로(카드 배경 위 AA 통과. legibility-40s.css의 override도 함께).
2. 오류 텍스트 전용 토큰 --red-deep:#C81E1E 신설(deck.css). 오류 '텍스트'는 --red 대신 --red-deep 사용하도록
   해당 프리미티브 정리(coral/mint의 -deep 패턴과 정합).
3. patterns.css의 하드코딩 정리: border-radius 16/18px → 토큰(--r-md/--r-lg)로 스냅, raw box-shadow 8곳 →
   --shadow-* 토큰으로 매핑(딱 안 맞는 강한 블루 글로우는 --shadow-blue-strong 토큰을 신설해 raw 제거).
각 값의 근거는 리포트 실측표를 따르고, 바꾼 값은 MEMORY.md에 한 줄씩 기록한다.

[Phase 1 — 구도 축(composition_shape) 신설·태깅]
근본 문제: 카탈로그가 '콘텐츠 의도'로만 분류돼 구도 중복을 스스로 못 본다. 정보모양과 '직교'하는
composition_shape 태그를 신설한다.
- 먼저 메인이 태그 어휘를 확정한다. 감사 리포트의 12 매크로 클러스터(C1~C12)를 근거로,
  6~9개의 깔끔한 구도 어휘로 정규화하라(예: center-standalone / top-loaded-grid / table /
  quadrant / vertical-stack / band-stack / bento / split / fullbleed-image / horizontal-flow 등 — 최종안은 네가 판단).
  어휘 정의와 근거를 kit/guide/카탈로그-규격.md §3에 "구도 균형" 절로 추가하고 설계기록·MEMORY에 남긴다.
- 그다음 50개 태깅은 서브에이전트로 팬아웃한다: kit/layouts/families/*.md 8개 파일을 2~3개 Task
  서브에이전트에 나눠 맡기고, 각 서브에이전트는 "id → composition_shape" 표만 반환하게 하라(파일 본문 덤프 금지).
  메인은 표를 취합해 각 항목에 composition_shape 필드를 실제로 써 넣는다(기존 info_shapes·필드는 보존).
- 검증: scripts/verify_deck.py 및 스키마 무결성(info_shapes 값이 taxonomy 12개 내인지, 필드 누락 없는지) 확인.
  카탈로그 개수는 이번엔 바꾸지 않는다(태그만 추가).

[마무리 — 인수인계]
_dev/설계기록/새세션-시작.md 를 갱신한다: (1) composition_shape별 분포표(=중복·쏠림의 '측정된' 수치),
(2) 세션 B가 채울 '미탐색 구도 갭 지도'(하단앵커·우측 주컬럼·적층 밴드·오프센터 중 실제 빈 칸),
(3) 다음 할 일. 파괴적 편집은 이번 세션에 하지 않는다.
```

## 세션 B — 확장 (Phase 2 신규 구도 추가, 가산·저위험)

```
이 저장소는 vibecoding-deck 스킬 개발 프로젝트다. 먼저 _dev/설계기록/새세션-시작.md(세션 A가 남긴 상태·갭 지도),
.claude/agent-memory/vibecoding-deck/MEMORY.md, kit/guide/카탈로그-규격.md, kit/guide/토큰-치트시트.md,
kit/styles/patterns.css, _dev/설계기록/레이아웃_매크로구조_감사_2026-07-15.md §6(미탐색 구도)을 읽어라.

목표: 세션 A의 갭 지도가 가리키는 '한 번도 안 쓴 구도'를 채우는 신규 레이아웃 3~5개를 추가한다
(후보: 하단 앵커 / 우측 주 컬럼 상시형 / 전폭 수평 밴드 3~4단 적층 / 오프센터·대각 초점 — 갭 지도에서 실제 빈 것 우선).

방법:
- 메인이 어떤 갭을 채울지, 각 레이아웃의 정보모양·composition_shape·when_to_use/avoid·capacity를 결정한다.
- 각 신규 레이아웃의 CSS+마크업 '초안'은 서브에이전트(Task)로 병렬 생성하라: 각 서브에이전트에
  "patterns.css 관례와 토큰만 사용, 1280×720 세로 예산(약 548px)·본문 22px 하한 준수, deck.css 프리미티브 재사용,
  결과는 patterns.css에 추가할 CSS 블록과 families/*.md 항목 마크다운 diff만 반환"하도록 지시한다(파일 전체 덤프 금지).
- 메인이 초안을 취합해 실제 반영한다: kit/styles/patterns.css(코드 코어) + 해당 kit/layouts/families/*.md 항목
  + kit/layouts/catalog.html + kit/layouts/by-shape.md 역인덱스에 등재. 각 신규에 composition_shape 태그 부여.

제약(엄수): §0 불변요소, navy·그라데이션 금지, 배지 민트 3종 한정, 토큰만(raw #hex 금지), 접근성 하한.
검증: 각 신규를 python -m http.server 렌더로 오버플로 육안(닫힘/펼침 둘 다) + scripts/verify_deck.py 통과.
이번 세션은 '가산'만 한다 — 기존 항목 삭제·병합·개수 재계산은 세션 C 몫이니 손대지 않는다.

마무리: _dev/설계기록/새세션-시작.md 갱신 — 추가한 레이아웃 목록·composition_shape, 그리고 세션 C가 접을
중복 클러스터 목록(감사 리포트 §3 기준) 확인 메모.
```

## 세션 C — 정리 + 잠금 (Phase 3 중복 접기 + Phase 4 규칙 고정, 파괴적·신중)

```
이 저장소는 vibecoding-deck 스킬 개발 프로젝트다. 먼저 _dev/설계기록/새세션-시작.md,
.claude/agent-memory/vibecoding-deck/MEMORY.md, _dev/설계기록/레이아웃_매크로구조_감사_2026-07-15.md §3(중복 클러스터)·§7,
kit/guide/카탈로그-규격.md, evals/evals.json, evals/trigger-eval.json 을 읽어라.

경고: 이 세션은 파괴적이다. 커밋 이력이 약하므로 모든 제거는 '삭제가 아니라 이동'
(kit/layouts/families/ → _dev/설계기록/탐색-아카이브/)으로 한다. 병합·재계산은 서브에이전트에 맡기지 말고
메인 단일 스레드로만 진행한다.

[Phase 3 — 중복 접기]
감사 리포트 §3의 중복 클러스터를 접어 카탈로그를 composition_shape 기준 ~20개 실질 구도로 슬림화한다:
- 큰 중앙 텍스트/숫자(C1 9개) → 대표 1개 + 파라미터(글자수·줄수·물음표)로 흡수.
- 비교 표(C4 3개) → 1개로, 2×2 사분면(C5 3개) → 1개로, 벤토(C9 2개) → 1개로 통합.
- 동급 카드 격자(C3)·세로 스택(C6)은 대표형으로 정리하되 카드 수/커넥터 변주는 파라미터로.
- 접을 때 by-shape.md 역인덱스, catalog.html, patterns.css 참조를 함께 정리하고, 옮긴 항목은 아카이브에
  '왜 접었는지' 한 줄씩 남긴다.
- 개수가 바뀌므로 kit/guide/카탈로그-규격.md §3 균형표와 evals의 개수·균형 어서션을 '이번에 한 번만' 다시 계산해 갱신한다.

[Phase 4 — 규칙 고정(재발 방지)]
- scripts/verify_deck.py 에 "연속 슬라이드가 같은 composition_shape면 경고/실패" 검사를 추가한다
  (지금은 split만 세는 것을 전체 구도 반복 측정으로 확장).
- SKILL.md 조립 워크플로우의 '직전과 같은 패밀리 회피'를 '직전과 같은 composition_shape 회피'로 개정.
- MEMORY.md에 새 규칙과 접기 결과를 기록.

검증: evals(evals.json·trigger-eval.json)와 verify_deck.py 전체 실행은 서브에이전트에 맡겨
'pass/fail + 상위 3개 이슈'만 반환받고, 메인이 수정한다.
마무리: _dev/설계기록/새세션-시작.md 최종 갱신(완료 상태·남은 것). 필요 시 scripts/inline_deck.py로 배포본 재생성 안내.
```

## 참고 — 서브에이전트 호출 요령 (토큰 절약 핵심)

- Claude Code에서 서브에이전트는 **Task 도구**로 띄운다. 팬아웃(여러 개)은 **한 메시지에 여러 Task를 동시에** 넣어 병렬 실행.
- 서브에이전트 지시엔 항상 **"무엇을 반환할지"를 좁게** 못 박는다(표/diff/pass·fail만, 파일 본문·로그 덤프 금지).
- 메인 컨텍스트에는 원본 파일을 쌓지 말 것 — 결정·계획·인수인계 메모만 유지.
- 파괴적 편집(세션 C 병합)·규격/균형표 글쓰기·최종 판단은 **메인만** 한다.
