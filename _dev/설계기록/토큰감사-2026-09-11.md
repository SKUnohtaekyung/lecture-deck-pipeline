## 4. 왜 기존 장치가 막지 못했나

1. **규칙은 문서에만 있었다.** `AGENTS.md` 「컨텍스트 예산」(250k 분리 · 긴 중단 뒤 새 세션 · Bash 출력 규율)은 매 세션 로드됐지만 강제되지 않았다 — 이 저장소의 원칙 «자연어는 설명, 설정은 강제»와 어긋난 채 방치.
2. **감사기는 사후·수동이다.** 세션 도중 아무도 경고받지 못한다. 08-06 §5가 이미 «S5·S6 기계 강제 수단 없음»으로 남겼다.
3. **훅은 `Write|Edit`에만 걸려 있다**(`.claude/settings.json`). 창 크기·간격·모델 전환·Bash 출력 크기를 보는 훅이 없다.
4. **서브에이전트 비용은 감사 대상이 아니었다.** 08-06 결론 «워커는 메인의 1.8% — 늘릴 대상»(N4)이 이번 규모(98개 · 77%)에서는 성립하지 않는다.
5. **계측기가 틀렸다(T3).** 틀린 신호로는 우선순위를 못 정한다.

### P2 세션 중 경고 훅 (관측 모드로 시작 → 오탐률 측정 후 강제)

  - 직전 응답과 모델이 다르면 → «모델 전환은 캐시 전량 재작성 — 새 세션에서 바꿀 것»
- Bash 결과가 N자(예: 4,000자) 초과면 «판정 줄만 받기» 1줄 경고(관측).
- 과목 지침 훅(`--mode course`)은 **세션·과목당 1회만** 주입(표식 파일은 `tmp/`).

### P3 서브에이전트 운영 (하네스 §3~§6 · 과정 도우미 정의)
- **수정 회차는 경량으로**: 검토자가 문구를 지정한 수정·추적 문서 동기화는 메인 직접 또는 Sonnet 정의(`maxTurns` 상한)로. Opus `writer`는 조립·판단형 수정만 · `maxTurns` 부여.
- **같은 도우미 재사용 우선**: 후속 지적은 1시간 안이면 `SendMessage`로 기존 도우미에 이어서(캐시 유지). 새 도우미는 문맥이 오염됐거나 1시간이 지났을 때만.

- **반환은 짧게**: 반환 ≤ 1,500자 · 상세는 파일에 쓰고 경로만.
- **필수 읽기 최소화**: 위임 프롬프트에 결정표 + 담당 파일 경로만 준다(하네스 §3 «결정표 핸드오프» 재확인). 도우미가 매번 `MEMORY.md` 전체·스킬 전문을 읽지 않게 과정 정의에 읽기 범위를 적는다.
