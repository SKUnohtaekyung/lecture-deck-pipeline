## 1. 슬라이드별 계획

> 아래 **블록을 슬라이드 수만큼 복사**해서 채웁니다. **필수 = ★**, 나머지는 선택.

### 슬라이드 N  *(파트: __)*
- **★ 슬라이드 목적·전달 목표**: 이 장에서 함께 이해시킬 결론·질문·근거 묶음. 관련 정보는 여러 개여도 됩니다.
- **★ 제목(헤드라인)**: 화면에 크게 뜰 문장. 결론형을 권장하지만 계획서 제목을 우선합니다.
- **본문 내용**: 실제 들어갈 텍스트·불릿·근거·사례·비교 기준. 적어주신 정보 묶음을 유지합니다.
- **묶음 유지/분할 허용(선택)**: `유지` *(기본)* / `분할 허용`. 유지인데 수용량을 넘으면 조립 전에 승인을 요청합니다.
- **★ 시각화 의도**: 이 정보의 "모양"을 하나 고르세요 → 스킬이 최적 레이아웃/차트로 구현합니다.
  아래 중 택1 (또는 `알아서`):
  | 고르기 | 이런 정보일 때 |
  |---|---|
  | `한 문장 선언` | 강한 질문·선언 한 방 |
  | `개념 설명(글 위주)` | 한 문단 설명 + 보조 그림 |
  | `비교(A vs B)` | 두 개념 정식 비교(한쪽 추천) |
  | `대비(두 주체)` | 쓰는 쪽 vs 하는 쪽 등 대립 구도 |
  | `흐름·단계(1→2→3)` | 순서·절차 |
  | `구성·포함(A는 B의 일부)` | 부분-전체 관계 |
  | `매핑(A가 B를 정한다)` | 위 항목 → 아래 항목 연결 |
  | `분류·나열` | 여러 항목 훑기(카드 여러 장) |
  | `표(정리·비교)` | 3~5개 항목 비교표 |
  | `수치·비율(차트)` | 숫자·비중·추세 → **코드 차트** |
  | `구조·관계 다이어그램` | 요소 간 관계도 → **코드 다이어그램** |
  | `체크리스트·격자` | 점검 항목·격자 |
  | `화면 조작 안내` | 실제 앱 화면 단계 → **주석 스크린샷**(번호·테두리) |

  > *참고: 여기서 고른 의도는 스킬이 내부적으로 12가지 「정보 모양」으로 옮겨 레이아웃·차트를 자동으로 고릅니다(`kit/guide/정보모양-taxonomy.md`). 채우는 분은 몰라도 됩니다 — 위에서 하나 고르거나 `알아서`만.*
- **표현 선호(선택)**: `코드 시각화 우선(차트·다이어그램)` / `스크린샷` / `이미지로` / `상관없음`
  *※ 기본값 = 코드 시각화 우선. 이미지는 꼭 필요할 때 + 배경으로만.*
- **데이터(차트·수치일 때)**: `항목 = 값` 목록. (예: 기획 40% · 개발 35% · 검증 25%)
- **화면 캡처(조작 안내일 때)**: 어느 화면의 어느 단계인지 + 강조할 위치(번호).
- **이미지 필요?(선택)**: 필요할 때만. **위치**(`배경` / `코너 스팟`) + 그리고 싶은 **장면 한 줄**.
- **주의·강조(선택)**: 오개념 방지 포인트, 강조할 단어.
- **발표 노트(선택)**: 말로 풀 설명(화면엔 안 나옴).

### ✍️ 작성 예시 — 슬라이드 7 *(파트: 1)*
- **핵심 메시지**: AI는 '답'이 아니라 '행동'을 하게 시킬 수 있다.
- **제목**: 물어보기만 하던 AI, 이제 '일'을 시킨다
- **본문 내용**: 지금까지 = 질문하고 답 받기 / 이제 = 파일 만들고·고치고·실행까지
- **시각화 의도**: `대비(두 주체)` — 왼쪽 "답하는 AI" ↔ 오른쪽 "행동하는 AI"
- **표현 선호**: 코드 시각화 우선
- **주의·강조**: "크기가 아니라 '행동하느냐'가 진짜 차이" 강조

### ✍️ 작성 예시 — 슬라이드 15 *(파트: 3, 실습)*
- **핵심 메시지**: 바탕화면에 새 폴더를 만들고 Codex에서 연다.
- **제목**: ① 바탕화면에 새 폴더 만들기
- **본문 내용**: 바탕화면 우클릭 → 새로 만들기 → 폴더 → 이름 입력
- **시각화 의도**: `화면 조작 안내` — 실제 화면 3단계
- **표현 선호**: 스크린샷
- **화면 캡처**: Windows 바탕화면 우클릭 메뉴, "새로 만들기 > 폴더" 위치에 ①②③ 번호

## 2. 작성 팁 (40~50대 대상)

- **계획서의 정보 묶음이 우선입니다.** 한 장에 관련된 여러 개념·근거·카드·차트를 둘 수 있습니다. 읽기 어려울 정도로 많으면 `분할 허용`으로 표시하거나, 스킬의 분할 제안에 승인해 주세요.
- **그릴 수 있으면 글보다 그림 먼저.** 숫자·비교·흐름·관계는 차트/다이어그램이 빠릅니다. → 코드로 제작.
- **조작 설명은 실제 화면 캡처 + 번호로.** "여기" 대신 실제 버튼명·위치.
- **이미지는 "꼭 필요할 때 + 배경"만.** 장식용 이미지는 뺍니다.
- **쉬운 말 + 친숙한 비유.** (예: 프롬프트 = 요청서, 폴더 = 서류철, 프로토타입 = 모형)
- **제목은 결론으로.** ("에이전트란?" ❌ → "에이전트는 말이 아니라 행동한다" ✅)

## 3. (참고) 이 계획서가 조립으로 이어지는 방식
1. **0번** = 표지·아젠다·파트전환·헤더(로고·팀명) 자동 채움
2. **각 슬라이드의 `시각화 의도`** → 강화된 판단 기준으로 레이아웃/차트 결정
3. **`데이터`** → CSS/SVG 코드 차트·다이어그램으로 제작
4. **`화면 캡처`·`이미지 필요?`에 적힌 것만** → 스크린샷/이미지 핸드오프
5. 브라우저 검증 → base64 단일파일 배포
