# 검토 — 강의 제작 파이프라인 산출물 검토

이 스킬은 강의 제작 5인 팀 파이프라인의 **횡단 검증자**다(준형 역할). `/리서치`(해서)·`/콘텐츠`(혜린)·`/create-slides`(태경) 세 단계가 각각 만든 산출물을 읽고, 규칙 위반·사실 오류·콘텐츠 소유권 침해·파이프라인 단절을 찾아 `sessions/N주차/검토보고_YYYY-MM-DD.md` 한 장으로 보고한다.

검토의 가치는 **고치는 게 아니라 정확히 지목하는 것**이다. 수정 권한은 산출물을 만든 담당 스킬에 있다. 검토가 산출물을 직접 고치면 담당 스킬은 다음에 무엇이 원본이고 무엇이 검토자의 손을 탄 것인지 구분할 수 없게 되고, 결함이 애초에 어디서 왔는지 감사 추적이 끊긴다. 그래서 이 스킬은 **무엇을 발견했는지, 왜 문제인지, 누가 고쳐야 하는지**만 적는다.

---

## §0. 불변 규칙 (협상 불가)

1. **읽기 전용 절대**: 이 스킬이 쓰는 파일은 검토 보고서 **1개뿐** — `sessions/N주차/검토보고_YYYY-MM-DD.md`(같은 날 재검토는 `_v2`·`_v3`… 접미사를 붙여 이전 보고서를 덮어쓰지 않는다). 검토 대상 파일(`sessions/N주차/자료/*`·`초안.md`·`강의덱.html`·`강의덱_발표자노트.html` 등)은 **절대 수정·정리·이동·삭제하지 않는다.** 고쳐야 할 것을 발견해도 직접 손대지 말고 보고서에 담당 지목과 함께 적는다. 이유: 검증자가 산출물을 건드리면 소유권 경계와 감사 추적이 무너진다 — 검증자가 무엇을 발견해서 고쳤는지와 원래 원본에 있던 결함인지 구분할 수 없게 되고, 결함이 애초에 어디서 왔는지 추적할 수 없게 된다.
   - 예외: `python scripts/verify_deck.py`는 파일을 쓰지 않고 표준출력만 내는 읽기 전용 분석 스크립트이므로 실행을 허용한다.
2. **발견 3요소 필수**: 모든 발견 항목은 다음 3요소를 반드시 갖춘다. 근거 없는 지적은 검토가 아니라 추측이며, 다음 담당자가 재현·검증할 수 있어야 실제 액션으로 이어진다.
   - ① **심각도** — `FAIL`(규칙 위반·사실 오류) / `WARN`(위험·권고) / `PASS`(확인 완료)
   - ② **근거** — 파일 경로:행 번호, 또는 URL. 근거 없는 지적 금지.
   - ③ **수정 담당 단계** — 리서치 / 콘텐츠 / 덱 / 총괄 중 하나.
3. **명시 호출 전용**: "명시 호출"의 3항 정의는 `skills/README.md`("호출 규약" 절)가 정본이다 — (a) `/검토`·`$검토` 직접 호출, (b) "검토 스킬로 ~해줘"처럼 스킬임을 지목한 자연어, (c) 오케스트레이터가 파이프라인 지시에서 이름으로 지목한 경우(스킬 체이닝). "이 덱 검토해줘"·"오탈자 좀 봐줘" 같은 보통명사 단독 요청은 발동하지 않는다 — 상세 규칙·트레이드오프는 그 문서를 그대로 따르고 여기서 복제하지 않는다.

## 호출 인자

```
/검토 [N주차] [자료|초안|덱|전체]
```

- **주차**: 인자가 없으면 사용자에게 질문한다. 최신 주차를 임의로 추정하지 않는다.
- **대상**: 기본값은 `전체`다. 단 **실제로 존재하는 산출물만** 검토한다 — 예를 들어 자료 기본 산출물 5파일 중 일부만 있으면 나머지는 검토 보고서에 `SKIP`으로 명기하고 이유(파일 없음)를 적는다. 없는 대상을 있다고 가정해 추측으로 채우지 않는다.
- **사람 작성물 포함**: 스킬이 아니라 사람이 손으로 쓴 산출물도 스키마·내용이 같으면 동일하게 검토 대상이다. 작성 주체가 아니라 파일의 형식(4열 표+아이콘 범례 = 초안, `#·슬라이드 제목·본문 문구·비유·멘트` 등)으로 식별한다 — `skills/README.md`가 명시한 "같은 스키마를 지키면 사람이 만든 산출물과 스킬이 만든 산출물은 완전히 호환된다" 원칙과 동일하다.

## 워크플로 (7단계)

### 1. 인자 해석 + 인벤토리
- 주차·대상 인자를 해석한다. 주차가 없으면 질문하고 멈춘다.
- **베이스라인 기록**: 검토 시작 즉시 `git status --porcelain`을 실행해 결과를 기록해 둔다. 이 저장소는 상시 다수 파일이 M 상태이므로, 검토 종료 후 `git status`만으로는 검토가 건드린 변경인지 원래 있던 변경인지 구분할 수 없다 — 시작 시점 스냅샷이 있어야 7단계 이후 자기검증에서 "검토 대상 파일 변경 0건"을 실제로 판정할 수 있다.
- `sessions/N주차/`를 나열해 실제로 존재하는 산출물을 확인한다: `자료/*`(리서치 기본 산출물 **5파일 패턴** — `N주차_콘텐츠리서치_결과.md`·`N주차_개념KB.md`·`N주차_출처레지스트리.md`·`N주차_실습안_검증결과.md`·`N주차_결정요청사항.md`, 주차 상세 강의설계 `N주차_강의안설계.md` 등 입력 문서도 같은 폴더 또는 주차 폴더 직하에 있을 수 있음), `초안.md`(+ `자료/N주차_콘텐츠_집필노트.md`), `강의덱.html`(+ `_발표자노트.html`).
  - 선택 산출물(`N주차_리서치_종합정리.md`·`N주차_리서치_리뷰.html`)은 사용자가 요청했을 때만 존재한다 — 없다고 FAIL로 잡지 않고, 있으면 검토 대상에 포함한다.
  - `자료/`에 리서치 중간 산출물(장문 심층리서치·워커 수확본·`_v1`류 구버전·임시 커버리지 표)이 남아 있으면 인벤토리에 별도로 적어 3단계 중복 서술 검사로 넘긴다 — 직접 옮기거나 지우지 않는다(§0-1).
- 대상=`전체`면 인벤토리에 실제로 존재하는 대상만 3~6단계를 진행하고, 없는 대상은 SKIP 처리를 예약해 7단계 보고서에 반영한다.

### 2. 규격 정본 read-path
검토 종류별로 아래 정본을 먼저 읽는다. 대조를 위해 상류 산출물도 함께 읽는다(자료 검토는 커리큘럼·주차 상세 강의설계, 초안 검토는 자료 산출물, 덱 검토는 초안.md). **대상별로 필요한 것만 읽는다** — 자료 검토 하나에 커리큘럼·강의안설계·리서치 SKILL을 통째로 읽으면 대상=덱인 짧은 검토조차 불필요하게 무거워진다.
- **자료 검토용**: 리서치 산출물 스키마의 정본은 `skills/리서치/SKILL.md`의 §0 하드 게이트·산출물 규격이며, 세습 근거는 주차 상세 강의설계 `sessions/N주차/N주차_강의안설계.md`의 **`#### C. 리서치·검증 요청`** 절과 `[총괄 확정]` 태그가 붙은 절만 grep으로 회수한다(전문 통독 대신). 커리큘럼 기준안은 **§4.1(대상)·§6(교육 원칙)·§11(개념 배치표)의 해당 주차 열**과 **그 주차 큰 설계 절**(1주차=§8·2주차=§9·3주차=§10)만 읽는다 — 주차 상세가 없는 주차는 이쪽이 유일한 기준이므로 이 경우엔 해당 절 전체를 읽는다. **`N주차_개념KB.md`는 전문을 통독하지 않는다** — 서두 「청크 인덱스」 표를 먼저 읽고, 거기서 **위험 가중으로 고른 표본 청크**(P0·제품/UI·신선도 임박·`[관점 미확보]` 표기가 있는 청크 우선)만 `[C-슬러그]`·`구간:`·`유형:`·`태그:` grep으로 회수해 본다. KB 전문을 읽으면 검토 한 건이 컨텍스트를 통째로 태우고, 정작 대조해야 할 초안·덱을 볼 여유가 없어진다.
- **초안 검토용**: `입력양식/콘텐츠초안템플릿.md` + `references/콘텐츠초안-입력형식.md` + 자료 산출물(`N주차_콘텐츠리서치_결과.md`·`N주차_개념KB.md` 등, 사실 대조용).
- **덱 검토용**: 루트 `SKILL.md`의 §0(불변 요소)·8단계(검증) + 초안.md. **리서치 SKILL·자료 산출물·커리큘럼은 읽지 않는다** — 덱 검토는 초안↔덱 대조가 핵심이고 상류 자료 정본은 필요 없다.
- **대상=`전체`이고 산출물 총량이 크면(자료에 `N주차_개념KB.md`가 있는 등) 위 read-path 전체를 한 컨텍스트로 감당하기 어려울 수 있다 — 이때는 `/하네스`(정본 `skills/하네스/SKILL.md`)로 대상별 워커를 나눠 수행한다.** 정본은 그쪽에 있으므로 규칙을 여기 복제하지 않는다.

### 3. 자료 검토
대상에 자료가 포함되고 실제 파일이 있을 때만 수행한다.
- **5개월 룰 전수**: 링크·자료 출처의 확인 날짜가 검토일 기준 5개월 이내인지 모든 항목을 검사한다. 5개월을 넘었지만 여전히 유효하다고 판단해 `[예외승인]` 태그를 붙인 항목은 태그 자체의 존재뿐 아니라 **승인 사유가 실제로 적혀 있는지**까지 확인한다 — 사유 없는 태그는 FAIL.
- **링크 생존 확인**: 표본 30% 이상을 직접 확인한다. 채택 출처의 정본 목록은 `N주차_출처레지스트리.md`의 6열 표(`ID | URL | 확인일 | 공신력 | 구간 | 접근`)이므로 **표본은 이 표에서 뽑는다.** FAIL(끊긴 링크)이 하나라도 나오면 전수 확인으로 확대한다. 403/429 응답은 삭제된 것이 아니라 접근 차단이므로 `[확인불가]`로 별도 표기해 끊김과 구분한다. **표본은 무작위가 아니라 위험 가중**으로 고른다 — 제품·UI·신선도 임박·플랫폼 의존(앱 화면·모드 구조 등) 출처를 evergreen 개념 출처보다 **먼저** 연다. 가장 자주 바뀌고 오류 위험이 큰 출처를 표본에서 빠뜨리면 검토가 통과해도 실제 오류가 남는다.
  - **병렬·시간 상한**: 링크 수가 많으면(대략 10개 초과) 순차 확인 대신 병렬로 열어 소요 시간을 줄인다. 표본·전수 확인 전체에 소요 시간 상한(대략 10분)을 두고, 상한 내 확인 불가 항목이 남으면 전수 미완료로 보고서에 명기한다 — 조용히 축소하지 않는다.
- **개념KB 대상 검사** (`N주차_개념KB.md`가 있을 때): 청크 ID 체계(`[C-슬러그]`)가 구간 종속이 아니라 개념 정체성 슬러그로 붙어 있는지, 사실 필드가 `[S-000]`(설계문서) 단독 근거인지(전사 의심 신호) 확인한다. `N주차_콘텐츠리서치_결과.md`가 같은 개념을 참조할 때 교차참조가 실제로 존재하는지(청크 ID가 죽은 참조가 아닌지) 대조한다.
- **출처레지스트리 대상 검사** (`N주차_출처레지스트리.md`가 있을 때): 6열 표(`ID | URL | 확인일 | 공신력 | 구간 | 접근`)가 갖춰졌는지, 다른 파일이 쓴 `[S-###]`가 전부 이 표에서 해소되는지(죽은 출처 ID), ID 중복·번호 누락이 없는지 확인한다. 「출처ID별 verbatim」 절이 존재하고 verbatim을 인용한 청크의 출처 ID가 실제로 그 절에 있는지 대조한다. 「접근·방법 주석」에 403·429 등 접근 특이사항이 `[확인불가]`와 함께 기록됐는지 본다. 링크 표본 검사(위 항목)의 표본도 이 표에서 뽑는다.
- **공신력 등급 표기 여부**: 리서치 SKILL의 공신력 3등급(G1) — 공식 자료 우선·UI 변경 내용의 출처+확인 날짜 기록·블로그/영상은 보조 자료로만 사용하고 사실 여부 별도 검증 — 준수 여부.
- **커버리지**: 주차 상세 강의설계(`sessions/N주차/N주차_강의안설계.md`)의 **구간별 `#### C. 리서치·검증 요청`** 절이 요청한 항목 대비 실제 자료 결과물에 누락이 없는지 대조한다. 추가로 **커리큘럼 기준안 §11 개념 배치표**의 그 주차 열(“다루지 않음”이 아닌 항목)과 **그 주차 큰 설계 절**(1주차=§8·2주차=§9·3주차=§10)도 대조한다 — 주차 상세가 아직 없는 주차는 이쪽이 유일한 기준이다.
- **관점 커버리지(G8)**: 개념 빈칸이 0이어도 공식 정의만 모였으면 수업이 사전 낭독이 된다. 리서치 SKILL §0 G8 기준으로 확인한다 — ① P0 청크가 `사례(실무)`·`대안·비교`·`한계·반론` 3필드 중 **2개 이상**, P1 청크가 **1개 이상**을 채웠는지(못 채운 곳에 `[관점 미확보: 사유]` 표기가 있으면 WARN, 표기 없이 비었으면 FAIL) ② 주차 바닥선 — `대안·비교` 보유 청크 **≥3** · `한계·반론` 보유 청크 **≥3** · `유형:사례` 청크 **≥1** ③ 채택 외부 출처의 도메인 상위 3개 비중을 세어 **최다 도메인이 40%를 넘는지**, **3급·`[경험 진술]` 출처가 0건인지**(둘 다 관점이 좁다는 신호 — 리서치 완료 보고에 사유가 밝혀졌으면 WARN, 사유가 없으면 FAIL). ②③은 `N주차_개념KB.md` 청크 인덱스 표의 관점 열과 `N주차_출처레지스트리.md` 공신력 열로 집계한다(전문 통독 불필요). `KB-스키마: v2` 표기가 없는 KB(1주차 등)는 v1이므로 G8을 WARN으로만 보고한다.
  - ⚠️ **G8 관점 검사는 `범위:인접` 청크에 적용하지 않는다.** 인접 청크(G9)는 `사례(실무)`·`대안·비교`·`한계·반론` 3필드가 애초에 **면제**이므로, 이 필드들이 비었다고 FAIL로 잡으면 오탐이다. P0/P1 최소치 판정과 주차 바닥선 집계에서도 인접 청크는 **모수에서 제외**하고 코어 청크만으로 센다.
- **인접 개념 커버리지(G9)**: 커리큘럼 밖이지만 학생이 배운 직후 묻는 개념(전제·후속·파생·혼동)을 담은 `범위:인접` 청크는 코어와 다른 규격이므로 별도로 확인한다. 리서치 SKILL §0 G9 기준 — ① 인접 청크 메타주석에 `범위:인접` 표기가 있고 청크 인덱스 표의 `범위` 열(코어\|인접)과 일치하는지(표기·열 누락은 FAIL — 하류가 코어로 오인해 본문에 쓴다) ② 얕은 최소깊이(정의·초보자 문장·연결·흔한 오해→교정 ≥1·verbatim ≥1·`[S-###]` ≥1)를 채웠는지(미달은 FAIL) ③ 인접 청크 수가 **코어 청크 수의 50% 이하**인지 — 초과면 FAIL이되, 게이트A에서 사용자가 상한을 늘린 사실이 개념KB 「변경 이력」에 남아 있으면 PASS ④ **게이트A 승인 없이 추가된 인접 청크가 있는지** — 리서치 완료 보고의 인접 개념 채택·기각 목록(및 `N주차_결정요청사항.md`)과 대조해 어느 목록에도 없는 인접 청크는 FAIL, 대조할 승인 기록 자체가 남아 있지 않으면 WARN(승인 여부 확인 불가). 수정 담당은 모두 리서치이며, 집계는 청크 인덱스 표 `범위` 열로 한다(전문 통독 불필요).
- **중복 서술 검사**: 사실의 정본은 `N주차_개념KB.md` 하나이고 나머지는 인덱스·검증·결정 층이다. ① `N주차_콘텐츠리서치_결과.md`가 개념KB의 정의·매핑·워크드예시를 **재서술하지 않고** 결론 1~2문장 + `[C-슬러그]` 포인터로 가리키는지(같은 사실이 두 파일에 물리적으로 존재하면 FAIL — 한쪽만 고쳐질 때 조용히 어긋난다) ② verbatim 원문 전문이 `N주차_출처레지스트리.md` 한 곳에만 있고 개념KB `verbatim:` 필드는 핵심 한 문장인지 ③ 증분 반영 기록이 별도 파일이 아니라 개념KB 서두 「변경 이력」 절 한 곳에만 있는지 ④ 1단계 인벤토리에서 확인한 `자료/` 잔존 중간 산출물(장문 심층리서치·`_v1`류 구버전·임시 커버리지 표)이 0건인지 — 남아 있으면 파일명을 지목해 FAIL로 보고하고, **직접 옮기거나 삭제하지 않는다**(§0-1).
- **수업 문장화**: 링크만 나열했는지 확인한다 — 주차 상세 강의설계 **`## 15. 리서치 업무 완료 기준`**의 "링크만 나열하지 않고 실제 수업 문장으로 정리했다"를 기준으로 삼는다.
- **확정사항 무단 변경**: 주차 상세 강의설계에서 **`[총괄 확정]` 태그가 붙은 절**(§2·§5.1·§5.4~5.6·§6.1~6.2 등)을 자료가 임의로 뒤집었는지 확인한다. 표제 이름이 아니라 이 태그로 찾는다 — 절 번호는 개정되지만 태그는 유지된다. 더 나은 대안을 별도 제안으로 덧붙이는 것은 허용되지만, 기존 확정안을 지우거나 대체했으면 FAIL.

### 4. 초안 검토
대상에 초안이 포함되고 `초안.md`가 있을 때만 수행한다.
- **형식 린트**: 교시별 4열 표(`#`·슬라이드 제목·본문 문구·비유·멘트) 준수 여부, 아이콘 문법(💬/👀/🗣) 오사용 여부, "0. 덱 기본 정보" 메타 존재, `(간지)`·`(표지)`·`(마무리)` 같은 고정 슬라이드 신호 확인.
- **사실 대조(핵심)**: 초안의 사실 주장을 2단계에서 읽은 자료 산출물과 하나씩 대조한다. **자료에 근거가 없는 사실 주장은 FAIL**이다.
- **인용 충실성**: 근거가 "있는지"(출처 ID 존재)가 아니라 초안 문장이 원문과 **일치하는지** 본다. 제품·구조 사실은 원문/verbatim과 대조해 압축 중 왜곡(nuance 뭉갬)이 없는지 확인 — 출처 ID가 붙어 있어도 서술이 원문과 다르면 FAIL. 경고 플래그는 "출처가 있다"로 덮지 말고 서술 정확성으로만 해소한다.
- **개념 정확성(R-ACC-01, 2026-07-27 신설)**: ① 서로 다른 개념을 편의상 하나로 합쳐 서술하지 않았는지(예: 별개 개념 두 개를 "같은 것"처럼 뭉뚱그림) — 합쳤으면 FAIL. ② 비유가 개념 정의 자체를 대체하지 않고 구분되는지, 비유의 한계(어디서부터 안 맞는지)를 문장으로 표시했는지 — 비유만 있고 정의가 없거나 한계 표시가 전혀 없으면 WARN.
- **자기투사(능력 클레임)**: "AI/Codex가 ~못 한다/한다"류는 능력(capability)인지 범위(scope)인지 구분해 검사한다 — 세션·도구 제약을 제품 사실로 확대했으면(예: "AI가 화면 캡처 불가") FAIL, 범위 한정(예: "수강생 개별 기기 원격 관찰 불가")이면 통과. 리서치 §0 G6 기준.
- **대상 적합성**: 언어 수준·비유 밀도를 **커리큘럼 기준안 §4.1(대상)**과 주차 상세 강의설계 **§1 문서 정보의 `주요 대상`·`대상 특성` 행** 기준으로 확인한다. 대상의 정본 서술은 **과목 프로필 §1의 「대상 수강생」·「대상 서술 규격」**이다 — 그 서술이 전제하지 않은 속성(예: 특정 연령대)을 깔고 쓴 표현·비유가 있으면 지적한다. 프로필이 없으면 이 항목은 WARN으로 보고하고 임의 기준으로 판정하지 않는다.
- **수용량 위험**: 본문 문구가 길어 슬라이드 1장에 넘칠 것 같은 행은 WARN으로 표시한다. 실측이 아니라 분량 감각으로 위험만 표시하며, 세로 예산(548px)·행당 줄 높이(39px/줄) 감각은 `kit/guide/토큰-치트시트.md`의 "세로 예산·행높이·글자폭 계산" 절을 참고한다.
- **소유권·관례**: 완성된 프롬프트(요청문) 전문이 `본문 문구`에 그대로 노출됐는지(`🗣`로 가야 정상) · `(선택)` 표시·관통 문장 등 템플릿 관례 준수 여부.
- **결정요청사항 반영**: 자료의 `N주차_결정요청사항.md`(있으면)에 있는 항목이 초안에 반영됐는지 확인한다.

#### 4축 판단 검토 (R-REVIEW-01 · 2026-07-29 신설 — 통합 실행 보완)

집필과 조립이 **하나의 실행 단위**로 묶이면서(루트 `SKILL.md` ③-B) 단계 간 상호검토가 약해졌다. 그 몫을 이 4축이 받는다 — **집필 주체가 스스로 못 보는 것만** 본다.

| 축 | 무엇을 보나 | 판정 |
|---|---|---|
| **① 무근거 사실** | 판단 `F` 행이 `[C-슬러그]`·`[S-###]`로 해소되는가 | 미해소 = **FAIL** |
| **② 생략 누락** | 「재료 처분표」의 보류 행 대 회수 청크. **필수 진술이 보류돼 있으면** 그 자체로 위반 | 필수 보류 = **FAIL** · 처분표에 보류 행이 **하나도 없으면** 표본 대조 후 WARN |
| **③ D2 근거** | `D2`(분류 기준·축 설계·인과 도출) 별도 행마다 도출 근거가 있는가 | 근거 없음 = **FAIL**(무근거 주장) |
| **④ 재구성 왜곡** | 시각 재구성이 원 사실의 뜻을 바꿨는가 — 축·사분면·흐름도로 옮기며 **원문에 없던 인과·순위·배타성**이 생기지 않았는가 | 왜곡 = **FAIL**, 수정 담당=집필 |

- **②가 이 4축의 존재 이유다.** 나머지 셋은 "쓴 것"을 검사하지만 ②만 **"뺀 것"**을 검사한다. 2026-07-28에 `[C-하네스구성요소]`의 유보가 화면에서 사라졌고, 어느 게이트도 잡지 못했다.
- **④는 ①과 다르다.** 인용은 정확한데 **구조가 뜻을 바꾸는** 경우가 있다 — 예: 병렬 항목을 단계 흐름도로 그리면 원문에 없던 순서가 생기고, 두 축으로 가르면 원문에 없던 배타성이 생긴다. 출처 ID로는 절대 안 잡힌다.
- 이 4축은 **판단 기록(집필노트)이 있어야 성립한다.** 없으면 "검토 불가"로 보고하고 FAIL 판정하지 않는다 — 기록 부재는 콘텐츠 담당의 R-QD-05 소관이다.

### 5. 덱 검토
대상에 덱이 포함되고 실제 덱 HTML이 있을 때만 수행한다(`sessions/N주차/강의덱.html`. 편집본 조각은 `sessions/N주차/강의덱.초안/`).
- **정적 검증 스크립트 실행**: `python scripts/verify_deck.py <덱경로>.html --parts N`을 실행하고 결과를 해석해 FAIL/WARN을 발견 항목으로 옮긴다. `--parts N`의 N은 초안의 PART 매핑 확인 결과나 실제 `part-divider` 슬라이드 수에서 가져온다.
  - 세션 자료에 `자료/이미지-에셋.json`이 있으면 `--manifest sessions/N주차/자료/이미지-에셋.json`을 함께 넘겨 이미지 계약(승인 자산 참조·prompt_only 슬롯 등)을 검증한다. 중앙 `kit/images/*/registry.json`을 대조해야 하면 `--registry <경로>`도 함께 넘긴다. 이 두 플래그 없이 실행하면 이미지 계약이 통째로 미검증 상태로 통과해버린다.
  - `--release`는 **배포 확정 판정**(expected 슬롯 미해소를 FAIL 처리)이므로 배포 직전 최종 검토에만 쓴다 — 조각 편집 중간 검토에서 쓰면 정상적인 미해소 슬롯을 조기 FAIL로 잘못 판정한다.
- **초안↔덱 diff(핵심)**: 슬라이드 제목·본문 문구를 초안과 덱에서 하나씩 대조해 **무단 재작성을 검출**한다. 콘텐츠 소유권 위반(임의 재작성·표현 변경) = FAIL.
- **아이콘 라우팅 확인**: `💬`·`👀`가 HTML 주석·발표자 노트로 갔는지, `🗣`가 `.hint-reveal`(접힘 힌트)로 갔는지, 이모지 문자가 화면에 그대로 남아있으면 FAIL(verify_deck.py도 잡지만 사람 눈으로도 재확인).
- **한 화면 한 단계(기준안 §6 원칙 9)**: 화면 조작 안내 슬라이드가 **한 장에 조작 단계 2개 이상**을 담고 있으면 FAIL. 신호 — `.shot-badge`가 한 `<figure>`에 여러 개이거나, `figcaption`이 `1. … → 2. … → 3. …`처럼 단계를 화살표로 잇는다. **단계와 지점은 다르다**: 한 단계 안에서 짚는 지점 1~3개는 정상이다. `L-vf-numbered-stack`이 조작 안내 host로 쓰였으면 지적한다(단계 목록을 보여주는 **개요 슬라이드**로 쓴 것은 정상).
- **매체 확인**: 조작 안내에 GIF·동영상이 들어갔으면 FAIL — 정적 캡처만 쓴다. 이는 기준안 §6 원칙 9의 "조작 안내는 사전에 검증한 화면 캡처를 활용한다"에 대한 해석이다(원문에 GIF·동영상 금지가 문자 그대로 있는 것은 아니다) — "화면 캡처"는 정지 이미지를 뜻하므로 동적 매체는 그 요건을 벗어난다고 본다.
- **대상 표현**: 덱 문구에 특정 연령대를 전제한 표현·비유가 있으면 지적한다(§4.1은 혼합군).
- **화면 단독 완결성(2026-07-27 신설)**: 개념설명 슬라이드가 발표자 노트·강사 멘트 없이 **화면(제목·본문·시각자료)만으로 이해 가능한지** 확인한다 — 핵심 주장·근거·예시 중 화면에 남은 게 없고 전부 노트에만 있으면 FAIL(수정 담당=콘텐츠 또는 덱). 콘텐츠 스킬의 자기선언 체크리스트(`skills/콘텐츠/SKILL.md` R-DENS-02)와 별개로, 최종 산출물에서 실제로 지켜졌는지 검토가 재확인하는 항목이다.

### 6. 교차 일관성
대상이 `전체`이거나 2개 이상일 때 수행한다 — 파이프라인 단절점을 찾는다.
- 자료에는 있으나 초안에서 누락된 핵심 내용.
- 초안에는 있으나 덱에서 빠진 슬라이드.
- 집필노트(`sessions/N주차/자료/N주차_콘텐츠_집필노트.md`, 있으면)의 추적표가 실제 자료·초안과 맞는지.
- **개념KB↔초안 인용 대조**: 콘텐츠 스킬은 `N주차_개념KB.md` 청크를 grep으로 회수해 초안을 쓴다(`skills/README.md` 계약). 초안의 핵심 사실 주장이 회수 가능한 청크 ID를 실제로 가리키는지, 그 청크가 개념KB에 존재하는지 대조한다 — 단절되면 초안이 존재하지 않는 청크를 인용하거나 개념KB의 깊이를 활용하지 못한 채 표면적으로만 썼다는 신호다.
- **인접 청크 본문 누출 검사(G9)**: `범위:인접` 청크는 슬라이드 본문 재료가 아니라 **학생이 물었을 때 강사가 꺼낼 답**이다(`skills/README.md` 계약 · 리서치 §0 G9). 초안 행의 `<!-- refs: C-… -->` 주석 중 청크 인덱스 표에서 `범위=인접`인 슬러그를 추려 그 행을 확인한다 — 인접 청크 내용이 `슬라이드 제목`·`본문 문구`에 들어갔거나 인접 개념 때문에 커리큘럼에 없던 본문 슬라이드가 생겼으면 FAIL(수정 담당=콘텐츠). 정상은 `🗣` 멘트·발표자 노트 경유다. 덱까지 대상이면 그 내용이 학생 덱 본문 `<section>`에 올라갔는지도 함께 보고, 올라갔으면 FAIL(수정 담당=덱).
- **죽은 포인터 검사**: 초안.md 행의 `<!-- refs: C-… -->` 주석은 `/create-slides`가 시각자료 소재를 회수하는 경로다(`skills/README.md` 계약). 주석이 가리키는 슬러그가 `N주차_개념KB.md`에 **실제 청크로 존재하는지** 하나씩 대조한다 — 없으면 FAIL(수정 담당=콘텐츠). 같은 방식으로 `N주차_콘텐츠리서치_결과.md`의 `[C-슬러그]` 포인터도 대조한다(수정 담당=리서치). 대조는 KB 전문 통독 없이 청크 인덱스 표와 `[C-슬러그]` grep으로 한다.
- **재료 실현 대조(2026-07-27 신설 · 2026-07-29 확장)**: 청크 ID가 존재하는지(위 항목)만으로는 부족하다 — 개념KB의 재료가 실제로 화면·부록·발표자 노트 **중 어디엔가 구현됐는지**를 집필노트의 「재료 처분표」(옛 「PPT 소재 처분표」)와 대조한다. 처분표가 없거나(→ FAIL, 수정 담당=콘텐츠) 표에 "사용"으로 적힌 재료가 실제 덱에 없으면(→ FAIL, 수정 담당=덱) 지적한다.
  - **등급별로 판정이 다르다**: `PPT 소재:`(제안)는 **대체·보류가 정당하므로 사유만 확인**한다 — 다른 시각자료로 바꿨다는 이유로 지적하지 않는다(R-LAYOUT-02가 정보 모양에 따라 고르게 한다). `필수 진술:`(내용 보존 의무)은 **보류 자체가 FAIL**이고, "대체"로 적혔는데 실현 슬라이드#가 없어도 FAIL이다.
  - **생략(판단 5분류 `S`) 대조**: 처분표에 보류 행이 **하나도 없으면** 정말 아무것도 안 뺐는지 회수 청크와 표본 대조한다 — 생략은 기록되지 않으면 검출되지 않으며, 2026-07-28에 유보 문장 1건이 그렇게 사라졌다. 청크 ID 존재는 인용의 무결성만 보장할 뿐 시각자료가 실제로 만들어졌다는 뜻은 아니다(2주차 결함 — 청크 인용은 있었으나 시각자료 42→15개로 감소).

### 7. 보고서 산출
- `sessions/N주차/검토보고_YYYY-MM-DD.md`를 작성한다. 구조는 "산출물 규격" 절을 따른다.
- 완료 응답에는 담당 단계별(리서치/콘텐츠/덱/총괄) 액션 요약을 포함한다.

## 산출물 규격

파일명: `sessions/N주차/검토보고_YYYY-MM-DD.md`. 같은 날 재검토가 필요하면 `_v2`·`_v3`… 접미사를 붙인다 — 이전 보고서를 덮어쓰지 않아 검토 이력을 보존한다.

보고서 구조 (4부):

1. **요약 표** — 대상별(자료/초안/덱) FAIL·WARN·PASS 개수.

   | 대상 | FAIL | WARN | PASS | 비고 |
   |---|---|---|---|---|
   | 자료 | … | … | … | 없으면 SKIP과 사유 |
   | 초안 | … | … | … | |
   | 덱 | … | … | … | |

2. **발견 상세** — 심각도 순(FAIL → WARN → PASS)으로 나열. 항목마다 §0의 3요소(심각도·근거·수정 담당 단계)를 모두 기재한다.
3. **종합 판정** — `통과` / `부분 통과(N개 대상 미산출)` / `조건부 통과` / `재작업` 중 하나를 명시하고 근거를 한 문장으로 요약한다. 판정 기준(검토자 간 재량 편차 방지):
   - `통과`: 검토 대상(자료·초안·덱) 전부가 실제로 존재해 검토를 수행했고, FAIL 0.
   - `부분 통과(N개 대상 미산출)`: 검토 대상 중 하나 이상이 SKIP(파일 없음)이고, 실제로 검토한 대상에서는 FAIL 0. **SKIP이 하나라도 있으면 `통과`를 쓰지 않는다** — "검사할 게 없었다"를 "파이프라인이 건전하다"로 오독시키지 않기 위함이다.
   - `조건부 통과`: FAIL이 있으나 같은 유형이 2건 이하이고 1개 대상에 국한되며, 구조 계약(형식 체계·콘텐츠 소유권 체계·파이프라인 순서) 자체는 건전한 경우 — FAIL 목록 해소를 재검토 조건으로 명시한다.
   - `재작업`: 구조 계약 위반이 있거나, 같은 유형 FAIL이 3건 이상이거나 2개 이상 대상에 걸쳐 반복되는 경우.
4. **재검토 조건** — `조건부 통과`·`재작업`일 때, 무엇이 고쳐지면 통과인지 구체적으로 적는다.

덱 검토를 수행했으면 `python scripts/verify_deck.py` 실행 결과(요약 줄 이상)를 보고서에 첨부한다.

## 파이프라인 인터페이스

- **입력**: 전 단계 산출물 전부 — `sessions/N주차/자료/*`·`초안.md`·`강의덱.html`·`강의덱_발표자노트.html` — 와 각 단계의 스키마 정본(`skills/리서치/SKILL.md`·`입력양식/콘텐츠초안템플릿.md`·루트 `SKILL.md`).
- **출력 소비자**: 각 담당 단계(리서치→해서, 콘텐츠→혜린, 덱→태경)가 보고서의 지목 항목을 받아 직접 수정하고, 총괄(승민·태경)이 종합 판정을 보고 재작업 여부·주차 간 흐름을 확인한다.
- **횡단 역할**: 파이프라인의 어느 한 단계에도 속하지 않고 전체를 가로질러 확인하는 유일한 스킬이다. 이 스킬 자신은 다음 단계의 입력을 만들지 않는다 — 보고서는 사람과 각 담당 스킬이 참고하는 진단 결과물이다.
