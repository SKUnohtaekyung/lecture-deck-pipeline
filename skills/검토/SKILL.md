# 검토 — 강의 제작 파이프라인 산출물 검토

이 스킬은 강의 제작 5인 팀 파이프라인의 **횡단 검증자**다(준형 역할). `/리서치`(해서)·`/콘텐츠`(혜린)·`/vibecoding-deck`(태경) 세 단계가 각각 만든 산출물을 읽고, 규칙 위반·사실 오류·콘텐츠 소유권 침해·파이프라인 단절을 찾아 `sessions/N주차/검토보고_YYYY-MM-DD.md` 한 장으로 보고한다.

검토의 가치는 **고치는 게 아니라 정확히 지목하는 것**이다. 수정 권한은 산출물을 만든 담당 스킬에 있다. 검토가 산출물을 직접 고치면 담당 스킬은 다음에 무엇이 원본이고 무엇이 검토자의 손을 탄 것인지 구분할 수 없게 되고, 결함이 애초에 어디서 왔는지 감사 추적이 끊긴다. 그래서 이 스킬은 **무엇을 발견했는지, 왜 문제인지, 누가 고쳐야 하는지**만 적는다.

---

## §0. 불변 규칙 (협상 불가)

1. **읽기 전용 절대**: 이 스킬이 쓰는 파일은 검토 보고서 **1개뿐** — `sessions/N주차/검토보고_YYYY-MM-DD.md`(같은 날 재검토는 `_v2`·`_v3`… 접미사를 붙여 이전 보고서를 덮어쓰지 않는다). 검토 대상 파일(`sessions/N주차/자료/*`·`초안.md`·`강의덱.html`·`강의덱_발표자노트.html` 등)은 **절대 수정·정리·이동·삭제하지 않는다.** 고쳐야 할 것을 발견해도 직접 손대지 말고 보고서에 담당 지목과 함께 적는다. 이유: 검증자가 산출물을 건드리면 소유권 경계와 감사 추적이 무너진다 — AGENTS.md "검증 담당은 산출물을 수정하지 않고 읽기 전용으로 점검한다" 규약과 같은 원칙이다.
   - 예외: `python scripts/verify_deck.py`는 파일을 쓰지 않고 표준출력만 내는 읽기 전용 분석 스크립트이므로 실행을 허용한다.
2. **발견 3요소 필수**: 모든 발견 항목은 다음 3요소를 반드시 갖춘다. 근거 없는 지적은 검토가 아니라 추측이며, 다음 담당자가 재현·검증할 수 있어야 실제 액션으로 이어진다.
   - ① **심각도** — `FAIL`(규칙 위반·사실 오류) / `WARN`(위험·권고) / `PASS`(확인 완료)
   - ② **근거** — 파일 경로:행 번호, 또는 URL. 근거 없는 지적 금지.
   - ③ **수정 담당 단계** — 리서치 / 콘텐츠 / 덱 / 총괄 중 하나.
3. **명시 호출 전용**: "명시 호출"의 3항 정의는 `skills/README.md`("호출 규약" 절)가 정본이다 — (a) `/검토`·`$검토` 직접 호출, (b) "검토 스킬로 ~해줘"처럼 스킬임을 지목한 자연어, (c) 오케스트레이터가 파이프라인 지시에서 이름으로 지목한 경우(스킬 체이닝). "이 덱 검토해줘"·"오탈자 좀 봐줘" 같은 보통명사 단독 요청은 발동하지 않는다 — 상세 규칙·트레이드오프는 그 문서를 그대로 따르고 여기서 복제하지 않는다.

## 호출 인자

```
/검토 [N주차] [자료|초안|덱|전체]
```

- **주차**: 인자가 없으면 사용자에게 질문한다. 최신 주차를 임의로 추정하지 않는다.
- **대상**: 기본값은 `전체`다. 단 **실제로 존재하는 산출물만** 검토한다 — 예를 들어 자료 3파일 중 일부만 있으면 나머지는 검토 보고서에 `SKIP`으로 명기하고 이유(파일 없음)를 적는다. 없는 대상을 있다고 가정해 추측으로 채우지 않는다.
- **사람 작성물 포함**: 스킬이 아니라 사람이 손으로 쓴 산출물도 스키마·내용이 같으면 동일하게 검토 대상이다. 작성 주체가 아니라 파일의 형식(4열 표+아이콘 범례 = 초안, `#·슬라이드 제목·본문 문구·비유·멘트` 등)으로 식별한다 — `skills/README.md`가 명시한 "같은 스키마를 지키면 사람이 만든 산출물과 스킬이 만든 산출물은 완전히 호환된다" 원칙과 동일하다.

## 워크플로 (7단계)

### 1. 인자 해석 + 인벤토리
- 주차·대상 인자를 해석한다. 주차가 없으면 질문하고 멈춘다.
- `sessions/N주차/`를 나열해 실제로 존재하는 산출물을 확인한다: `자료/*`(리서치 3파일 패턴 — `N주차_콘텐츠리서치_결과.md`·`N주차_실습안_검증결과.md`·`N주차_결정요청사항.md`, 인수인계서 등 입력 문서도 같은 폴더에 있을 수 있음), `초안.md`(+ `자료/N주차_콘텐츠_집필노트.md`), `강의덱.html`(+ `_발표자노트.html`).
- **1주차 예외**: 덱이 세션 폴더가 아니라 루트 `1주차_강의덱.html`에 있다(`sessions/README.md` "1주차 (예외)" 참고). 주차 인자가 1이면 이 경로도 함께 확인한다.
- 대상=`전체`면 인벤토리에 실제로 존재하는 대상만 3~6단계를 진행하고, 없는 대상은 SKIP 처리를 예약해 7단계 보고서에 반영한다.

### 2. 규격 정본 read-path
검토 종류별로 아래 정본을 먼저 읽는다. 대조를 위해 상류 산출물도 함께 읽는다(자료 검토는 커리큘럼·주차 상세 강의설계, 초안 검토는 자료 3파일, 덱 검토는 초안.md).
- **자료 검토용**: 리서치 산출물 스키마의 정본은 `skills/리서치/SKILL.md`의 §0 하드 게이트·산출물 규격이며, 세습 근거는 주차 상세 강의설계 `sessions/N주차/N주차_강의안설계.md`의 `§6`·`§11`(검증 원칙)·`§14`(리서치 제출 패키지)다.
- **초안 검토용**: `입력양식/콘텐츠초안템플릿.md` + `references/콘텐츠초안-입력형식.md`.
- **덱 검토용**: 루트 `SKILL.md`의 §0(불변 요소)·8단계(검증).

### 3. 자료 검토
대상에 자료가 포함되고 실제 파일이 있을 때만 수행한다.
- **5개월 룰 전수**: 링크·자료 출처의 확인 날짜가 검토일 기준 5개월 이내인지 모든 항목을 검사한다. 5개월을 넘었지만 여전히 유효하다고 판단해 `[예외승인]` 태그를 붙인 항목은 태그 자체의 존재뿐 아니라 **승인 사유가 실제로 적혀 있는지**까지 확인한다 — 사유 없는 태그는 FAIL.
- **링크 생존 확인**: 표본 30% 이상을 직접 확인한다. FAIL(끊긴 링크)이 하나라도 나오면 전수 확인으로 확대한다. 403/429 응답은 삭제된 것이 아니라 접근 차단이므로 `[확인불가]`로 별도 표기해 끊김과 구분한다. **표본은 무작위가 아니라 위험 가중**으로 고른다 — 제품·UI·신선도 임박·플랫폼 의존(앱 화면·모드 구조 등) 출처를 evergreen 개념 출처보다 **먼저** 연다. 가장 자주 바뀌고 오류 위험이 큰 출처를 표본에서 빠뜨리면 검토가 통과해도 실제 오류가 남는다.
- **공신력 등급 표기 여부**: 리서치 SKILL의 공신력 3등급(G1) — 공식 자료 우선·UI 변경 내용의 출처+확인 날짜 기록·블로그/영상은 보조 자료로만 사용하고 사실 여부 별도 검증 — 준수 여부.
- **커버리지**: 인수인계서 "# 4. 교시별 콘텐츠 리서치 요청"이 요청한 항목 대비 실제 자료 결과물에 누락이 없는지 대조한다.
- **수업 문장화**: 링크만 나열했는지 확인한다 — "리서치 완료 기준"의 "링크만 나열하지 않고 실제 수업 문장으로 정리했다"를 기준으로 삼는다.
- **확정사항 무단 변경**: 인수인계서 "# 2. 이미 확정된 사항"을 자료가 임의로 뒤집었는지 확인한다. 더 나은 대안을 별도 제안으로 덧붙이는 것은 허용되지만, 기존 확정안을 지우거나 대체했으면 FAIL.

### 4. 초안 검토
대상에 초안이 포함되고 `초안.md`가 있을 때만 수행한다.
- **형식 린트**: 교시별 4열 표(`#`·슬라이드 제목·본문 문구·비유·멘트) 준수 여부, 아이콘 문법(💬/👀/🗣) 오사용 여부, "0. 덱 기본 정보" 메타 존재, `(간지)`·`(표지)`·`(마무리)` 같은 고정 슬라이드 신호 확인.
- **사실 대조(핵심)**: 초안의 사실 주장을 2단계에서 읽은 자료 산출물과 하나씩 대조한다. **자료에 근거가 없는 사실 주장은 FAIL**이다.
- **인용 충실성**: 근거가 "있는지"(출처 ID 존재)가 아니라 초안 문장이 원문과 **일치하는지** 본다. 제품·구조 사실은 원문/verbatim과 대조해 압축 중 왜곡(nuance 뭉갬)이 없는지 확인 — 출처 ID가 붙어 있어도 서술이 원문과 다르면 FAIL. 경고 플래그는 "출처가 있다"로 덮지 말고 서술 정확성으로만 해소한다.
- **자기투사(능력 클레임)**: "AI/Codex가 ~못 한다/한다"류는 능력(capability)인지 범위(scope)인지 구분해 검사한다 — 세션·도구 제약을 제품 사실로 확대했으면(예: "AI가 화면 캡처 불가") FAIL, 범위 한정(예: "수강생 개별 기기 원격 관찰 불가")이면 통과. 리서치 §0 G6 기준.
- **대상 적합성**: 40~50대 언어 수준·비유 밀도를 인수인계서 "주요 수강생 특성"·"화면 자료 원칙" 기준으로 확인한다.
- **수용량 위험**: 본문 문구가 길어 슬라이드 1장에 넘칠 것 같은 행은 WARN으로 표시한다. 실측이 아니라 분량 감각으로 위험만 표시하며, 세로 예산(548px)·행당 줄 높이(39px/줄) 감각은 `kit/guide/토큰-치트시트.md`의 "세로 예산·행높이·글자폭 계산" 절을 참고한다.
- **소유권·관례**: 완성된 프롬프트(요청문) 전문이 `본문 문구`에 그대로 노출됐는지(`🗣`로 가야 정상) · `(선택)` 표시·관통 문장 등 템플릿 관례 준수 여부.
- **결정요청사항 반영**: 자료의 `N주차_결정요청사항.md`(있으면)에 있는 항목이 초안에 반영됐는지 확인한다.

### 5. 덱 검토
대상에 덱이 포함되고 실제 덱 HTML이 있을 때만 수행한다(1주차는 루트 `1주차_강의덱.html`).
- **정적 검증 스크립트 실행**: `python scripts/verify_deck.py <덱경로>.html --parts N`을 실행하고 결과를 해석해 FAIL/WARN을 발견 항목으로 옮긴다. `--parts N`의 N은 초안의 PART 매핑 확인 결과나 실제 `part-divider` 슬라이드 수에서 가져온다.
- **초안↔덱 diff(핵심)**: 슬라이드 제목·본문 문구를 초안과 덱에서 하나씩 대조해 **무단 재작성을 검출**한다. 콘텐츠 소유권 위반(임의 재작성·표현 변경) = FAIL.
- **아이콘 라우팅 확인**: `💬`·`👀`가 HTML 주석·발표자 노트로 갔는지, `🗣`가 `.hint-reveal`(접힘 힌트)로 갔는지, 이모지 문자가 화면에 그대로 남아있으면 FAIL(verify_deck.py도 잡지만 사람 눈으로도 재확인).

### 6. 교차 일관성
대상이 `전체`이거나 2개 이상일 때 수행한다 — 파이프라인 단절점을 찾는다.
- 자료에는 있으나 초안에서 누락된 핵심 내용.
- 초안에는 있으나 덱에서 빠진 슬라이드.
- 집필노트(`sessions/N주차/자료/N주차_콘텐츠_집필노트.md`, 있으면)의 추적표가 실제 자료·초안과 맞는지.

### 7. 보고서 산출
- `sessions/N주차/검토보고_YYYY-MM-DD.md`를 작성한다. 구조는 "산출물 규격" 절을 따른다.
- 완료 응답에는 담당 단계별(리서치/콘텐츠/덱/총괄) 액션 요약을 포함한다.

## 산출물 규격

파일명: `sessions/N주차/검토보고_YYYY-MM-DD.md`. 같은 날 재검토가 필요하면 `_v2`·`_v3`… 접미사를 붙인다 — 이전 보고서를 덮어쓰지 않아 검토 이력을 보존한다.

보고서 구조 (4부):

1. **요약 표** — 대상별(자료/초안/덱) FAIL·WARN·PASS 개수.

   | 대상 | FAIL | WARN | PASS | 비고 |
   |---|---|---|---|---|
   | 자료 | … | … | … | 없으면 SKIP과 사유 |
   | 초안 | … | … | … | |
   | 덱 | … | … | … | |

2. **발견 상세** — 심각도 순(FAIL → WARN → PASS)으로 나열. 항목마다 §0의 3요소(심각도·근거·수정 담당 단계)를 모두 기재한다.
3. **종합 판정** — `통과` / `조건부 통과` / `재작업` 중 하나를 명시하고 근거를 한 문장으로 요약한다. 판정 기준(검토자 간 재량 편차 방지):
   - `통과`: FAIL 0.
   - `조건부 통과`: FAIL이 있으나 개별 항목·슬라이드 수준(국소적)이고, 구조 계약(형식 체계·콘텐츠 소유권 체계·파이프라인 순서) 자체는 건전한 경우 — FAIL 목록 해소를 재검토 조건으로 명시한다.
   - `재작업`: 구조 계약 위반이 있거나, FAIL이 대상 전반에 걸쳐 반복되는 경우.
4. **재검토 조건** — `조건부 통과`·`재작업`일 때, 무엇이 고쳐지면 통과인지 구체적으로 적는다.

덱 검토를 수행했으면 `python scripts/verify_deck.py` 실행 결과(요약 줄 이상)를 보고서에 첨부한다.

## 파이프라인 인터페이스

- **입력**: 전 단계 산출물 전부 — `sessions/N주차/자료/*`·`초안.md`·`강의덱.html`·`강의덱_발표자노트.html` — 와 각 단계의 스키마 정본(`skills/리서치/SKILL.md`·`입력양식/콘텐츠초안템플릿.md`·루트 `SKILL.md`).
- **출력 소비자**: 각 담당 단계(리서치→해서, 콘텐츠→혜린, 덱→태경)가 보고서의 지목 항목을 받아 직접 수정하고, 총괄(승민·태경)이 종합 판정을 보고 재작업 여부·주차 간 흐름을 확인한다.
- **횡단 역할**: 파이프라인의 어느 한 단계에도 속하지 않고 전체를 가로질러 확인하는 유일한 스킬이다. 이 스킬 자신은 다음 단계의 입력을 만들지 않는다 — 보고서는 사람과 각 담당 스킬이 참고하는 진단 결과물이다.
