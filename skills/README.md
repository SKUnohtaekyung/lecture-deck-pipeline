# skills/ — 팀 워크플로 스킬 (⑤층 · 배포 제외)

> 강의 제작 5인 팀의 역할 중 일부를 스킬로 옮긴 **팀 워크플로 계층**이다. 이 스킬들은 `scripts/`·`sessions/` 규약에 하드 결합된 **이식 불가 자산**이므로, 포터블 스킬(①층) 배포 복사에서 제외한다.
> 루트 `SKILL.md`는 **create-slides의 정본**(역사적 위치·구명 vibecoding-deck)이며, 신규 팀 스킬의 정본은 이 폴더 아래 `skills/<이름>/SKILL.md`다. 플랫폼 어댑터(`.claude/skills/<이름>/`·`.agents/skills/<이름>/`)는 정본을 로드만 하고 규칙을 복제하지 않는다.

## 파이프라인 지도

```
[승민] 스토리라인·커리큘럼 (courses/<과목>/커리큘럼_기준안.md + courses/<과목>/sessions/N주차/N주차_강의안설계.md — 입력 전용, 스킬 없음)
   ↓
[해서] /리서치  ──→ courses/<과목>/sessions/N주차/자료/  (자료 5파일: 리서치결과·개념KB·출처레지스트리·실습검증·결정요청)
   ↓
[혜린·태경] /create-slides (루트 정본 · 자동 발동 유지) ──→ 강의덱.html + 발표자노트
              ⓐ 사람이 쓴 N주차_초안.md를 받거나 · ⓑ 자료만 받아 집필까지 수행
              ⓑ면 자료/N주차_콘텐츠_집필노트.md를 함께 산출(R-TRACE-01)
   ↓
[준형] /검토 (전 단계 횡단·읽기 전용) ──→ courses/<과목>/sessions/N주차/검토보고_YYYY-MM-DD.md
```

> `/하네스`는 이 화살표 흐름의 한 단계가 아니라, 위 어느 단계에서든 다파일·대규모 작업일 때 적용하는 **작업 수행 방식**(메인+워커 분담)이다. 정본은 `skills/하네스/SKILL.md`.

> ⚠️ **집필과 조립은 하나의 실행 단위다(R-EXEC-01 · 2026-07-29). `/콘텐츠` 스킬은 2026-08-03에 폐기했다.** 정보 모양·구조 재구성은 화면을 알아야 판단할 수 있고 문장은 그 구조에 맞물려 결정되므로, 둘을 갈라 왕복하면 판단이 끊긴다. 폐기 근거: 실행 이력이 **0**이었다(1주차는 별도 세션, 2주차는 create-slides ⓑ 진입).
> - **죽인 것은 «집필을 실행하는 별도 스킬»이지 «사람이 완성해 건네는 초안을 읽는 입구»가 아니다.** ⓐ 경로와 그 스키마(`입력양식/콘텐츠초안템플릿.md` 4열 표 + `references/콘텐츠초안-입력형식.md`)는 **그대로 남는다.** 다음 단계는 파일의 작성 주체가 아니라 내용·스키마로 입력을 인식한다.
> - 폐기 전에 **정본을 먼저 옮겼다**(그 파일에만 있던 규칙이 매달리지 않도록): `R-PLAN-01/02`·`R-COMP-01` → `references/phases/02-슬라이드맵.md` · `R-ANNEX-01`·`R-ACC-01/02`·`R-CAL-01`·`R-DENS-01/02` → `references/phases/04-조립.md` · `R-EMPH-02` → `kit/guide/디자인시스템.md` · `R-JUDGE-01`과 집필노트 산출물 규격 → 루트 `SKILL.md`.
> - 문장 소유권은 **없애지 않고 작성 주체로 분기**한다(R-OWN-03): 사람 작성(또는 작성 주체 필드 없음) → 재작성 금지 그대로 / 스킬 작성 → 같은 실행 안에서만 자기 문장 수정 허용 + 변경 사유를 판단 기록에.
> - 승인 지점은 **G1(조립 전 골격·정보 모양·시각 후보·결정표) · G2(조립 후 렌더 결과)** 둘로 고정한다. 통합으로 약해지는 상호검토는 `/검토`의 **4축 판단 검토**(R-REVIEW-01)가 받는다.
> - 정본: 루트 `SKILL.md` ③-B.

같은 스키마를 지키면 **사람이 만든 산출물과 스킬이 만든 산출물은 완전히 호환**된다 — 다음 단계는 파일의 작성 주체가 아니라 내용·스키마로 입력을 인식한다.

## 호출 규약 — 명시 호출 전용

팀 스킬 2종(리서치·검토)은 **명시 호출로만** 발동한다. create-slides만 기존대로 자동 발동을 유지한다.

**"명시 호출"의 정의 (3항)**:
- (a) `/리서치` `/검토` 또는 `$리서치` 형태의 직접 호출
- (b) "**리서치 스킬**로 2주차 조사해줘"처럼 **스킬임을 지목한** 자연어
- (c) 오케스트레이터가 파이프라인 지시에서 스킬을 **이름으로 지목**한 경우 (스킬 체이닝)

**비발동 확정**: 보통명사 단독 사용은 발동하지 않는다 — "덱 검토해줘", "자료 조사 좀 해줘", "이 초안 다듬어줘"는 일반 요청이지 스킬 호출이 아니다.

> ⚠️ **트레이드오프 명시**: 이 규약은 기계적 강제가 아니라 description 계약+회귀 eval에 의한 **관례적 보증(honor-system)** 이다. 기계적 차단(`disable-model-invocation`)은 (c)항 스킬 체이닝까지 죽이므로 채택하지 않았다. 운영 중 보통명사 요청에 자동 발동이 관찰되면 이 트레이드오프를 재논의한다.

## 명명 규약 예외

저장소 템플릿(`.claude/skills/_template/`)은 kebab-case 이름을 권장하지만, 팀 스킬은 **한글 보통명사**를 사용한다 — 팀 내부 용어와의 일치(협업 문서·인수인계서가 전부 한글 역할명 사용)가 우선이며, 스모크 테스트로 한글 스킬명 인식을 검증했다(2026-07-17, `claude -p` 새 세션 YES).

Codex CLI는 로컬에 설치돼 있다(2026-08-05 실측: `C:\Users\miso\AppData\Local\OpenAI\Codex\bin\d7e8094cfb76a267\codex.exe`, 버전 `codex-cli 0.146.0-alpha.9.2`, 서브커맨드에 비대화형 `exec`·진단용 `doctor`·`review`가 있다). **PATH에는 없을 뿐**이라 `$스킬명` 스모크와 지침 로드 그래프 검증은 전체 경로를 쓰거나 PATH에 추가하면 실행 가능하다 — 예: `& "C:\Users\miso\AppData\Local\OpenAI\Codex\bin\d7e8094cfb76a267\codex.exe" exec "새 세션에서 \$리서치로 2주차 조사해줘"` 형태로 새 세션을 열어 스킬 인식 여부를 관찰한다. **다만 이 스모크는 아직 실제로 돌리지 않았다 — 여기 적힌 것은 "가능하다(미실시)"이지 "통과했다"가 아니다.** Codex 어댑터(`.agents/skills/리서치/`·`.agents/skills/검토/`)는 create-slides와의 패턴 패리티를 위한 것이 아니라, 위 실측대로 Codex CLI가 로컬에서 실제로 구동 가능한 **실제 발동 대상**이기 때문에 유지한다.
