# skills/ — 팀 워크플로 스킬 (⑤층 · 배포 제외)

> 강의 제작 5인 팀의 역할 중 3개를 스킬로 옮긴 **팀 워크플로 계층**이다. 이 스킬들은 `scripts/`·`sessions/` 규약에 하드 결합된 **이식 불가 자산**이므로, 포터블 스킬(①층) 배포 복사에서 제외한다.
> 루트 `SKILL.md`는 **vibecoding-deck의 정본**(역사적 위치)이며, 신규 팀 스킬의 정본은 이 폴더 아래 `skills/<이름>/SKILL.md`다. 플랫폼 어댑터(`.claude/skills/<이름>/`·`.agents/skills/<이름>/`)는 정본을 로드만 하고 규칙을 복제하지 않는다.

## 파이프라인 지도

```
[승민] 스토리라인·커리큘럼 (sessions/바이브코딩_커리큘럼_기준안.md + sessions/N주차/N주차_강의안설계.md — 입력 전용, 스킬 없음)
   ↓
[해서] /리서치  ──→ sessions/N주차/자료/  (3파일: 리서치결과·실습검증·결정요청)
   ↓
[혜린] /콘텐츠  ──→ sessions/N주차/초안.md + 자료/N주차_콘텐츠_집필노트.md
   ↓
[태경] /vibecoding-deck (루트 정본 · 자동 발동 유지) ──→ 강의덱.html + 발표자노트
   ↓
[준형] /검토 (전 단계 횡단·읽기 전용) ──→ sessions/N주차/검토보고_YYYY-MM-DD.md
```

같은 스키마를 지키면 **사람이 만든 산출물과 스킬이 만든 산출물은 완전히 호환**된다 — 다음 단계는 파일의 작성 주체가 아니라 내용·스키마로 입력을 인식한다.

## 계약 표

| 스킬 | 팀 역할 | 입력 (읽는 것) | 출력 (파일 · 위치) | 스키마 정본 | 소비자 |
|---|---|---|---|---|---|
| `/리서치` | 해서 (콘텐츠 리서치+실습) | 커리큘럼(`sessions/바이브코딩_커리큘럼_기준안.md`(상위 기준) · `sessions/N주차/N주차_강의안설계.md`(주차 상세)) · 사용자 브리프 | `sessions/N주차/자료/N주차_콘텐츠리서치_결과.md` · `N주차_실습안_검증결과.md` · `N주차_결정요청사항.md` · `N주차_개념KB.md`(청크+ID RAG · additive) · `N주차_리서치_종합정리.md`(사람 읽기용 요약·필수) | 리서치 SKILL 산출물 규격(정본) · 세습 근거 `sessions/N주차/N주차_강의안설계.md` `§14 리서치 제출 패키지` | /콘텐츠 |
| `/콘텐츠` | 혜린 (피피티 내용) | `sessions/N주차/자료/` 리서치 산출물(특히 `N주차_개념KB.md` 청크를 grep 선택 회수) | `sessions/N주차/초안.md` · `자료/N주차_콘텐츠_집필노트.md` | `입력양식/콘텐츠초안템플릿.md` (4열 표+아이콘 범례) | /vibecoding-deck |
| `/vibecoding-deck` | 태경 (디자인) | `sessions/N주차/초안.md` | `강의덱.html` · `강의덱_발표자노트.html` | 루트 `SKILL.md` | /검토 · 수강생 |
| `/검토` | 준형 (검토) | 지정 대상(자료\|초안\|덱\|전체) + 각 스키마 정본 | `sessions/N주차/검토보고_YYYY-MM-DD.md` **1개만** (읽기 전용) | 각 단계의 스키마 정본 | 각 담당 단계 |

## 호출 규약 — 명시 호출 전용

팀 스킬 3종(리서치·콘텐츠·검토)은 **명시 호출로만** 발동한다. vibecoding-deck만 기존대로 자동 발동을 유지한다.

**"명시 호출"의 정의 (3항)**:
- (a) `/리서치` `/콘텐츠` `/검토` 또는 `$리서치` 형태의 직접 호출
- (b) "**리서치 스킬**로 2주차 조사해줘"처럼 **스킬임을 지목한** 자연어
- (c) 오케스트레이터가 파이프라인 지시에서 스킬을 **이름으로 지목**한 경우 (스킬 체이닝)

**비발동 확정**: 보통명사 단독 사용은 발동하지 않는다 — "덱 검토해줘", "자료 조사 좀 해줘", "이 초안 다듬어줘"는 일반 요청이지 스킬 호출이 아니다.

> ⚠️ **트레이드오프 명시**: 이 규약은 기계적 강제가 아니라 description 계약+회귀 eval에 의한 **관례적 보증(honor-system)** 이다. 기계적 차단(`disable-model-invocation`)은 (c)항 스킬 체이닝까지 죽이므로 채택하지 않았다. 운영 중 보통명사 요청에 자동 발동이 관찰되면 이 트레이드오프를 재논의한다.

## 명명 규약 예외

저장소 템플릿(`.claude/skills/_template/`)은 kebab-case 이름을 권장하지만, 팀 스킬 3종은 **한글 보통명사**를 사용한다 — 팀 내부 용어와의 일치(협업 문서·인수인계서가 전부 한글 역할명 사용)가 우선이며, 스모크 테스트로 한글 스킬명 인식을 검증했다(2026-07-17, `claude -p` 새 세션 YES). Codex CLI는 로컬에 없어 `$스킬명` 스모크는 미실시 — Codex 어댑터는 vibecoding-deck과의 패턴 패리티를 위해 유지한다.

## 검증·회귀

```powershell
python scripts/verify_skill_setup.py        # 팀 스킬 어댑터 정합 포함 전 항목
# evals/team-skills-eval.json — 수동 채점: 케이스별 새 세션 제시 → 발동 스킬 관찰 → expected_skill 대조
# 기존 evals/evals.json · evals/trigger-eval.json 도 SKILL.md 변경 시 함께 재확인 (AGENTS.md 규약)
```

- 스킬 정본을 바꾸면: 해당 어댑터 frontmatter 동일성 유지 + `verify_skill_setup.py` 재실행 + routing eval 재확인.
- 등재 정보(이 표)는 **이 파일이 유일한 정본**이다. `.claude/skills/README.md`·`.agents/README.md`에는 포인터 1줄만 둔다(상태 복제 금지).
