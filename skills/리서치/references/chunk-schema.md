# 산출물 규격 (리서치 기본 5파일 · 선택 산출물 · 청크 스키마)

> 이 파일이 리서치 산출물 규격의 **정본**이다. `skills/리서치/SKILL.md` 「산출물 규격」이 여기를 가리킨다.
> **읽는 시점**: 3단계(조사 계획에서 청크 슬러그·우선순위 배정) · 4단계(워커 프롬프트에 청크 템플릿·레지스트리 행 형식을 넣을 때) · 7단계(기본 5파일을 쓸 때).
> 항목명·순서·파일명은 하류(`/콘텐츠`·`/create-slides`·`/검토`)가 grep으로 회수하는 계약이다 — 임의로 추가·축소하지 않는다.

---

`sessions/N주차/자료/`에 **기본 5파일**을 쓴다. 종합 요약본(사람 읽기용)과 리뷰 HTML(사람 확인용)은 **사용자가 요청할 때만** 추가로 쓴다. 8항목/13항목 스키마의 세습 근거는 주차 상세 강의설계 §14(리서치 제출 패키지)이며, 아래 항목명은 리서치 SKILL 산출물 규격이 정본이다 — 항목을 추가·축소하지 않는다.

| # | 파일 | 성격 |
|---|---|---|
| 1 | `N주차_콘텐츠리서치_결과.md` | 구간 인덱스층(8항목×6구간 골격 유지 · 사실 재서술 금지) |
| 2 | `N주차_개념KB.md` | **사실 정본**(청크+ID RAG) |
| 3 | `N주차_출처레지스트리.md` | 출처·verbatim 원문 정본 |
| 4 | `N주차_실습안_검증결과.md` | 실습 13항목 |
| 5 | `N주차_결정요청사항.md` | 결정 6열 표 |

### 메타 헤더 (5파일 공통, 서두)
```
> 작성: 리서치 스킬
> 작성일: YYYY-MM-DD  (= G2 신선도 판정의 조사 기준일)
> 기준 문서: (커리큘럼 파일명 · 주차 상세 강의설계 파일명)
> 대상 수강생: 코딩 경험이 없는 입문자 중심의 혼합군(연령·경험 수준 다양)
```

### 파일 1. `N주차_콘텐츠리서치_결과.md` (구간 인덱스층)
교시별로 8항목을 채운다: ① 핵심 메시지 ② 초보자용 설명 문장 ③ 사실 확인 내용 ④ 사용 가능한 비유 ⑤ 비교 사례 ⑥ 출처 URL과 확인 날짜(G1 등급도 함께 표기) ⑦ 슬라이드에 넣을 표·도식·이미지 아이디어 ⑧ 피해야 할 표현과 과도한 내용. 이 8항목×6구간 골격은 `verify_session_docs.py`가 기계로 강제하는 계약이므로 그대로 **유지**한다(항목 추가·축소, 구간 수 축소 금지).

**이 파일은 사실의 정본이 아니라 구간 인덱스층이다.** ③사실·④비유·⑤비교 사례는 **결론 1~2문장 + `[C-슬러그]` 포인터**까지만 쓰고, 개념KB 청크의 정의·매핑·워크드예시·verbatim을 **재서술하지 않는다** — 같은 사실이 두 파일에 물리적으로 존재하면 한쪽만 고쳐질 때 조용히 어긋나고, 하류가 같은 내용을 두 번 읽어 토큰만 늘어난다. 깊이는 전부 개념KB 청크에 담고 여기서는 "무엇을 어느 청크에서 볼지"만 가리킨다. ⑧피해야 할 표현은 구간 단위 판단이므로 여기서 서술해도 된다.

말미에 "부록: 탈락 자료 로그" 섹션을 두고, 등급 미달(G1)·신선도 위반(G2)·확인불가(G3) 등으로 제외한 자료와 사유를 남긴다(무단 누락 금지). 탈락 항목이 없으면 "해당 없음"이라고 명시한다.

### 파일 2. `N주차_개념KB.md` (사실 정본 · 청크+ID RAG)

가르칠 개념마다 청크 1개를 만든다 — 빈 템플릿은 `sessions/_template/자료/개념KB.md`.

**서두 구성**: 메타 헤더 + `KB-스키마: v2` 표기 + 청크 규약 3~5줄(ID·메타주석·grep 검색법) + **「청크 인덱스」 표** + 「변경 이력」 절.

청크 인덱스 표는 하류(콘텐츠·덱)가 **파일 전문을 읽지 않고** 필요한 청크만 고르게 하는 RAG 진입점이다. 실제 청크 목록과 정확히 일치해야 한다(불일치는 verify FAIL).

```
## 청크 인덱스
| 슬러그 | 표시명 | 구간 | 우선 | 관점 | 범위 |
|---|---|---|---|---|---|
| C-토큰 | 토큰 | 1,3 | P0 | B,D | 코어 |
| C-컨텍스트창 | 컨텍스트 창 | 3 | P2 | — | 인접 |
```

개념마다 청크 1개:
```
## [C-<개념-슬러그>] <개념 표시명>
<!-- 구간:1,3 | 유형:개념 | 우선:P1 | 출처:S-105,S-107 | 태그:토큰,예측 -->

- **정의(정확):** … [S-###]
- **초보자 문장:** … (한 화면에 그대로 올릴 완결형 1~2문장)
- **비유①:** … [매핑: A=…·B=…] (오해 위험: …)
- **비유②:** … [매핑: …]
- **워크드 예시:** 입력 → 처리 → 결과를 실제 값으로 [S-### 또는 (창작)]
- **비교표:** (대조형 개념만) | 구분 | X | Y |
- **사례(실무):** 누가·어떤 상황에서·어떻게 썼는지 1~3문장 [S-### | 경험 진술]
- **대안·비교:** 경쟁·대안 도구/방식과의 대조 1~2문장 또는 비교표 [S-###]
- **한계·반론:** 이 개념·도구의 한계, 실무의 비판·논쟁, 언제 부적합한지 [S-###]
- **흔한 오해→교정:** "오해" ✗ → 교정 ✓ [S-###]
- **흔한 오해→교정:** "오해" ✗ → 교정 ✓ [S-###]
- **verbatim:** "원문 핵심 한 문장" (S-###, YYYY-MM-DD)
- **PPT 소재:** …
- **피해야 할 표현:** …
```

**인접 청크(G9 · `범위:인접`)**는 위 템플릿의 얕은 판이다. 메타주석에 `범위:인접`을 달고 아래만 채운다 — 비유②·워크드 예시·G8 관점 3필드는 쓰지 않는다.
```
## [C-<인접-개념-슬러그>] <인접 개념 표시명>
<!-- 구간:3 | 유형:개념 | 우선:P2 | 범위:인접 | 출처:S-121 | 태그:토큰,요금 -->

- **정의(정확):** … [S-###]
- **초보자 문장:** … (강사가 질문받았을 때 그대로 말할 1~2문장)
- **연결:** [C-토큰]을 배운 직후 "그럼 얼마나 길게 넣을 수 있나요?"로 이어질 때 필요 — 전제|후속·파생|혼동 중 무엇인지 함께 적는다
- **흔한 오해→교정:** "오해" ✗ → 교정 ✓ [S-###]
- **verbatim:** "원문 핵심 한 문장" (S-###, YYYY-MM-DD)
- **피해야 할 표현:** …
```

규칙:
- 키=개념 정체성 안정 슬러그(구간 종속 금지, 다중 구간이면 메타 `구간:`에 콤마 다중값) · 청크↔출처=N:M · 유형∈{개념,실습연계,비유,오해,사례} · 우선∈{P0,P1,P2}(메타 `우선:` 필수) · `범위:`는 선택 키이며 값은 `인접`뿐이다(없으면 코어).
- 청크 최소깊이(코어): 비유≥2(매핑)·워크드예시≥1·흔한오해→교정≥2·verbatim≥1·`[S-###]`≥1.
- 청크 최소깊이(인접): 정의·초보자 문장·연결·흔한오해→교정≥1·verbatim≥1·`[S-###]`≥1. 비유·워크드예시·G8 3필드 면제.
- 인접 청크 물량 상한: 코어 청크 수의 **50% 이하**(게이트A에서 사용자가 늘린 경우는 예외 — 승인 사실을 「변경 이력」에 남긴다).
- **G8 관점 최소치**: `사례(실무)`·`대안·비교`·`한계·반론` 3필드 중 **P0=2개 이상 · P1=1개 이상 · P2=권장**. 못 채우면 `[관점 미확보: 사유]`로 명시한다.
- `verbatim:`은 **핵심 한 문장만**(원문 전문·복수 인용은 출처레지스트리가 정본 — 물리 중복 금지).
- 사실필드가 S-000(설계문서) 단독이면 FAIL(외부 1급/2급 출처 필요, 설계·내부 확정 항목만 예외).
- grep 검색계약: `구간:`·`유형:`·`태그:`·`[C-슬러그]`로 회수 가능해야 한다.

### 파일 3. `N주차_출처레지스트리.md` (출처·원문 정본)
채택한 모든 출처를 6열 표로 등재한다: `ID | URL | 확인일 | 공신력 | 구간 | 접근`. ID는 `S-###`(3자리 이상)이며, 다른 파일이 쓴 `[S-###]`는 전부 이 표에서 해소되어야 한다(`verify_session_docs.py`가 강제).

- **「접근·방법 주석」**: 봇 차단(403·429)·리다이렉트 등 접근 특이사항을 남긴다.
- **「출처ID별 verbatim」 절**: 원문 인용 전문을 여기에만 둔다. 개념KB의 `verbatim:` 필드는 여기서 고른 핵심 한 문장의 사본이다.
- 3급·경험 진술 출처는 공신력 열에 `3급` + `[경험 진술]`을 함께 표기해 G8 관점 집계가 가능하게 한다.

### 파일 4. `N주차_실습안_검증결과.md`
실습 후보별로 13항목을 채운다: ① 실습 목적 ② 수강생 안내문 ③ 실제 요청문 ④ 준비물과 사전 설정 ⑤ 정상 진행 순서 ⑥ 완료 기준 ⑦ 예상 소요 범위 ⑧ 자주 발생하는 오류 ⑨ 복구 방법 ⑩ 정상 완성본 위치 ⑪ 최소 복구본 위치 ⑫ 디지털 도구에 익숙하지 않은 수강생의 어려움 ⑬ 채택·보류·제외 추천과 근거.

### 파일 5. `N주차_결정요청사항.md`
총괄이 결정할 항목만 6열 표로 정리한다: `결정 항목 | 후보 | 장점 | 위험 | 담당 추천 | 추천 근거`. G5에 따라 이미 확정된 사항은 올리지 않는다 — 대안 제안도 이 표를 통해서만 전달한다.

### 파일 6. `N주차_리서치_종합정리.md` (사람 읽기용 · 선택 — 사용자가 요청할 때만 산출)
파일 1~5의 핵심을 입문자도 한눈에 읽도록 **하나로 묶은 요약본**이다. **파이프라인 정본은 기본 5파일이고, 이 문서는 리뷰·회의용 읽기 자료**다(다음 단계가 소비하는 스키마 파일이 아니다). 최소 구성: ① 서두(성격=요약본·정본은 5파일·작성일·기준) ② "먼저 볼 것" 3~5줄(가장 중요한 주의·결정) ③ 강의 한눈에(구간별 한 줄) ④ 개념 설명 카드(초보자 설명·비유·피해야 할 표현·출처) ⑤ 실습 요약(완료 기준·실측 상태) ⑥ 결정요청 D표 ⑦ 출처 한눈에. 사실은 개념KB·레지스트리의 출처 표기를 그대로 인용하고, 실측 불가 항목은 `[미검증]`으로 구분한다. **스키마 검증 대상이 아니므로 형식은 가독성 우선**(표·굵게·짧은 줄). 결과.md가 포인터층이라 사람이 읽기 불편할 때 이 문서로 보완한다.

### 파일 7. `N주차_리서치_리뷰.html` (사람 확인용 자립형 HTML · 선택 — 사용자가 요청할 때만 산출)
`sessions/_template/자료/리서치_리뷰.html`을 복제해 이번 주차 청크·출처로 채운 **사람 확인용 자립형 HTML**이다. 외부 스타일시트·스크립트·이미지를 불러오지 않고 인라인 CSS/JS만으로 동작해야 한다(`grep -nE "https?://|src=|<link"` 결과가 0이어야 함). 파일 6과 마찬가지로 파이프라인 정본이 아니라 리뷰용이며, 개념 카드마다 `data-chunk-id`·`data-구간` 속성을 유지해 나중에 필터링할 수 있게 한다.
