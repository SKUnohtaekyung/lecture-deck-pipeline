# 리서치 — 콘텐츠 조사·실습 설계 검증

강의 제작 파이프라인에서 **커리큘럼 → 리서치 → 콘텐츠** 순서의 가운데 단계를 맡는다. 스토리라인·커리큘럼팀이 확정한 학습 흐름을 받아, 콘텐츠 담당이 추가 질문 없이 바로 PPT 초안을 쓸 수 있을 만큼 근거 있는 조사 결과와 검증된 실습안을 `sessions/N주차/자료/`에 3파일로 만든다. 콘텐츠를 대신 쓰지 않고, 콘텐츠가 쓸 재료를 만든다.

---

## §0. 하드 게이트 (협상 불가)

이 스킬의 산출물 문장은 강사가 현장에서 그대로 말하게 된다. 근거 없는 정보·낡은 화면 설명·출처 불명 사례가 섞이면 수업 중에 바로 신뢰가 깨진다. 아래 게이트는 예외 없이 지킨다 — 위반하며 채우느니 `[미확인]`·`[확인불가]`로 남기고 결정요청사항으로 넘긴다.

### G1. 공신력 3등급
모든 채택 사실 항목은 아래 등급 중 하나로 판정하고 항목마다 등급을 표기한다. 등급 판정 기준(OpenAI·제품 관련은 공식 자료 우선, 블로그·영상은 보조 자료로 쓰고 별도 검증)은 이 표가 정본이며, 근거는 주차 상세 강의설계 `sessions/N주차/N주차_강의안설계.md`의 `§1.1` `[리서치 검증]` 정의와 `§16`(최신 사실·실제 동작 검증) 원칙이다.

| 등급 | 정의 | 처리 |
|---|---|---|
| 1급 | 제품 공식 문서·공식 블로그·릴리스 노트 | 단독 채택 가능 |
| 2급 | 주요 언론·학술 자료 | 단독 채택 가능 |
| 3급 | 실무 블로그·영상 | 보조 전용 — 1~2급 교차 검증 없이 단독 채택 금지 |
| 금지 | 익명 포럼 단독 자료·출처 불명 AI 생성물 | 채택 금지 — 발견 시 사유와 함께 탈락 로그에 남긴다 |

### G2. 신선도 — 조사 시점 기준 5개월 이내
제품 화면과 제공 범위는 몇 주 단위로 바뀐다. 발행일 또는 최종수정일이 조사 시점(산출물의 작성일) 기준 **5개월을 넘는 자료는 채택하지 않는다.** 산출물에 작성일을 명기해 5개월 기준점을 남긴다.

바이브코딩 정의처럼 시간이 지나도 안 변하는 개념(evergreen)이 5개월 밖 자료에만 있으면, 임의로 넣지 말고 사용자 승인을 구한다:

> ○○ 개념은 5개월 이내 자료가 없고, 있는 자료는 YYYY-MM-DD 발행분입니다. 개념 자체가 안정적이라 예외로 포함해도 될까요?

승인을 받으면 `[예외승인: 사유=…·승인일=YYYY-MM-DD]` 태그를 달아서만 포함한다. 승인 없이 포함하지 않는다.

### G3. 출처 — URL + 확인 날짜, 링크는 실제로 연다
모든 사실 항목에 `출처 URL + 확인 날짜(YYYY-MM-DD)`를 붙인다. 채택 전 WebFetch로 링크를 실제로 열어 산출물에 적을 내용과 원문이 일치하는지 확인한다 — 링크만 나열하면 콘텐츠 담당이 다시 검증해야 하므로, 리서치 업무 완료 기준(주차 상세 강의설계 §15)의 "링크만 나열하지 않고 실제 수업 문장으로 정리"를 어기는 셈이다. 403·429 같은 봇 차단 응답은 죽은 링크와 다르게 `[확인불가]`로 표시하고 불채택으로 분류한다 — 내용이 틀렸다고 단정하진 않되, 확인 못 한 채로 수업 문장에 쓰지 않는다.

**인용 존재 ≠ 인용 충실.** 제품·UI·구조처럼 압축 중 왜곡되기 쉬운 사실은 출처 ID만 붙이지 말고 원문의 **짧은 verbatim 인용(핵심 한 문장)**을 사실 항목 옆에 함께 남긴다 — 리드가 수업 문장으로 압축할 때 nuance가 뭉개져도 대조할 근거가 남는다. 서브에이전트·deep-research가 캡처한 원문 인용은 버리지 말고 산출물로 옮긴다.

### G4. 물량·커버리지 — 빈칸 0
게이트A에서 합의한 조사 범위표의 전 항목에 응답한다. 항목당 출처 1개 이상을 확보하고, 가능하면 공식 자료·실무 자료·사례를 교차시켜(3각 커버) 한쪽 출처만으로 결론 내지 않는다. 최종 커버리지 매트릭스(교시 × 조사 항목)에 빈칸이 있으면 콘텐츠 담당이 PPT를 쓰다 다시 물어보게 되므로, 빈칸 항목은 `[미확인]`으로 표시하고 결정요청사항에 올린다 — 조용히 건너뛰지 않는다.

가르칠 각 개념은 `N주차_개념KB.md`에 청크로 만들고 청크 최소깊이(비유≥2·워크드예시≥1·흔한오해≥2·verbatim≥1)를 채운다. 청크 사실필드가 설계문서(S-000) 단독 근거면 전사이므로 FAIL — 개념 실체는 외부 1급/2급 출처로 판다.

### G5. 확정사항 불변
주차 상세 강의설계의 `[총괄 확정]` 항목(`sessions/N주차/N주차_강의안설계.md` §2·§7) 같은 기존 확정안은 조사 중 임의로 바꾸지 않는다 — 임의로 바꾸면 이미 합의된 스토리라인이 깨지고 재조정 비용이 커진다. 더 나은 대안을 찾아도 확정안을 지우거나 덮어쓰지 말고 `N주차_결정요청사항.md`에 "별도 제안"으로 추가한다. 최종 결정은 스토리라인·총괄 담당의 몫이다.

### G6. 자기투사 금지 — "AI/제품이 ~한다/못 한다" 클레임
"AI가 화면을 못 본다"·"Codex는 스크린샷을 못 한다"·"실측은 AI가 못 함" 같은 **AI·제품의 능력·한계 주장**은 이 세션·이 도구의 제약을 제품 사실로 확대한 것일 수 있다(자기투사). 이 클래스는 외부 인용이 없어 G1~G3가 적용되지 않고 "겸손하게 들려서" 그대로 통과하기 쉽다. 반드시:
> ① **능력(capability)** 부정인지 **범위(scope)** 한계인지 구분한다 — 예: "Codex는 화면 캡처를 못 한다"(틀림·능력 부정) vs "이 세션의 AI가 수강생 개별 기기를 원격 관찰할 수 없다"(맞음·범위 한계).
> ② 능력·한계 단정은 제품 공식 출처로 확인한다. 확인이 안 되면 능력을 단정하지 말고 **범위만 명시**한다.
> ③ 확인 불가한 능력 클레임은 결정요청/사람 확인으로 넘긴다 — 기계·동일 세션 검증이 구조적으로 약한 지점이다.

### G7. 매트릭스 자기감사 금지 — 원문과 직접 대조
G4의 "빈칸 0" 점검은 3단계에서 리서치 담당 스스로 만든 매트릭스를 기준으로 한다. 그런데 매트릭스 자체를 만드는 단계에서 이미 개념이 빠졌다면, 그 빈칸 점검은 통과해도 실제로는 커버리지가 뚫려 있다 — 매트릭스가 자기 자신을 감사하는 구조적 맹점이다(실제로 1주차에서 Plan First·Task 분할·Self Review·환각·저작권·개인정보·웹과 앱·정적 웹사이트·file:// 9개 개념이 이렇게 누락된 적이 있다 — "행동 후 이름 붙임"으로 설계된 항목을 "진행 기법이라 조사 대상이 아니다"로 오판하거나, 단순히 매트릭스 작성 시 옮겨 적기를 빠뜨려서였다). 이를 막기 위해 산출 직전(8단계 자기검증)에 **매트릭스를 보지 않고 원문만 다시 훑는 독립된 재대조**를 수행한다:

1. 주차 상세 강의설계의 §14(리서치 제출 패키지)·§15(리서치 업무 완료 기준), 그리고 구간별 서술에 언급된 모든 개념·용어명을 매트릭스를 보지 않고 원문에서 새로 뽑아 별도 목록을 만든다.
2. 이 목록을 개념KB 청크 목록과 1:1 대조한다. "행동 후 이름 붙임"·"진행 기법이라 개념이 아님"·"다른 청크에 이미 포함됨" 같은 이유로 청크를 만들지 않기로 판단한 항목은, 그 판단 근거를 완료 보고나 결정요청사항에 명시한다 — 조용히 제외하지 않는다.
3. 이 재대조는 G4의 매트릭스 빈칸 검사와 다른 절차다. 매트릭스가 완전해 보여도 이 원문 재대조를 생략하지 않는다.

### 발동 조건 — 명시 호출 전용
리서치 스킬은 **명시 호출**로만 시작한다. 아래 3항 중 하나에 해당해야 한다 — 상세 정의는 `skills/README.md`가 정본이다.

- (a) `/리서치` 또는 `$리서치` 형태의 직접 호출
- (b) "리서치 스킬로 2주차 조사해줘"처럼 **스킬임을 지목한** 자연어
- (c) 오케스트레이터가 파이프라인 지시에서 스킬을 이름으로 지목한 경우(스킬 체이닝)

"자료 조사해줘"·"이 자료 좀 찾아줘" 같은 보통명사 단독 요청은 발동 조건이 아니다. 팀 워크플로 스킬 3종(리서치·콘텐츠·검토) 공통 규약이며, vibecoding-deck만 예외적으로 자동 발동을 유지한다.

## 조립 전 read-path

작업을 시작하기 전에 아래를 순서대로 읽는다 — 건너뛰면 스키마가 다른 산출물을 만들어 콘텐츠 담당이 다시 물어보게 된다.

1. **주차 상세 강의설계**: `sessions/N주차/N주차_강의안설계.md`. 1주차는 `sessions/1주차/1주차_강의안설계.md`(v4)이며, 특히 `§6`(강의 범위·공통 운영 원칙)·`§11`(실습 검증 방법·기록 기준)·`§14`(리서치 제출 패키지 = 산출물 스키마의 세습 근거)·`§15`(리서치 업무 완료 기준)을 읽는다.
2. `skills/README.md` — 계약 표·명시 호출 3항 정의·파이프라인 전체 지도.
3. `sessions/README.md` — 세션 폴더 규약, 산출물을 어디에 쓰는지.
4. 상위 커리큘럼 기준안 `sessions/바이브코딩_커리큘럼_기준안.md` — 전 주차 공통 상위 기준. 주차 상세 강의설계(read-path 1)가 아직 없는 주차는 이 기준안에서 조사 범위를 역산해 게이트A로 합의한다.
5. 기존 `sessions/N주차/자료/`(있으면) — 같은 주차에 이미 쌓인 조사가 있는지 확인해 중복 조사를 피한다.

## 워크플로 (8단계)

### 1. 입력 파악
다룰 주차(N)를 확정하고 위 read-path를 순서대로 읽는다. 주차 상세 강의설계가 있으면 그 범위를, 없으면 커리큘럼과 사용자 브리프를 조사 범위의 출발점으로 삼는다.

### 2. ★게이트A: 조사 범위 확인
교시 목록·교시별 핵심 질문·실습 후보·결정요청 후보를 표로 정리해 사용자에게 제시하고 **확인을 받은 뒤에만 조사를 시작한다.** 주차 상세 강의설계가 없는 주차는 이 표가 사실상 그 역할을 하므로 특히 꼼꼼히 합의한다. 범위 합의 없이 조사부터 시작하지 않는다 — 범위를 잘못 짚고 다시 조사하는 비용이 먼저 확인받는 비용보다 훨씬 크다.

- **범위표 형식**: ①교시 목록 ②교시별 핵심 질문 ③실습 후보 ④결정요청 후보 — 4요소를 이 순서로, 각각 절 또는 표로 제시한다.
- **커리큘럼에 교시별 상세안이 없는 주차**(개요만 있는 2·3주차 등): 핵심 질문·실습 후보를 커리큘럼 개요에서 역산해 **'제안'임을 명시**하고 제시한다. 스토리라인 확정이 필요한 항목은 지어내지 말고 결정요청 후보로 분류하며, 상세안 부재 사실을 표 서두에 밝힌다 — 역산 제안은 합의를 위한 초안이지 확정이 아니다.

### 3. 조사 계획
합의된 범위를 교시 × 조사 항목의 검색 태스크 매트릭스로 쪼갠다. 이 매트릭스가 4단계 실행 목록이자 G4 커버리지 확인의 기준표가 된다.

### 4. 심층 조사
**deep-research 스킬의 가용성을 먼저 확인**한다.
- **있으면**: 게이트A에서 합의된 범위를 명확한 질문으로 정제해 전달한다(모호한 질문을 넘기면 deep-research가 재확인 루프를 도는데, 범위는 이미 합의됐으므로 그 루프가 불필요하다). args에 이 스킬의 제약(공신력 등급·5개월 신선도·URL+확인날짜 필수)을 명시한다. 반환물은 그대로 채택하지 않고 **§0 게이트로 다시 필터링**한다 — deep-research는 이 스킬 고유의 3등급·5개월 기준을 모르기 때문이다. 게이트에서 탈락한 항목은 사유와 함께 로그에 남긴다(무단 누락 금지). deep-research 자체가 내부적으로 병렬 팬아웃하므로 이 경로는 추가 조치가 필요 없다.
- **없으면(예: Codex 환경)**: 내장 폴백을 쓴다 — 조사 항목별로 웹검색을 팬아웃하고, 후보를 원문에서 직접 확인(WebFetch)한 뒤 동일한 §0 게이트를 적용한다.

**병렬 조사(기본)**: 3단계 매트릭스의 행(교시×조사 항목 또는 개념 단위)은 서로 독립적이다. 항목이 여럿이면 한 스레드가 순서대로 웹검색→WebFetch 원문확인→verbatim 추출을 반복하지 말고, **Workflow 도구(parallel/pipeline)나 다중 서브에이전트 병렬 호출로 항목별 조사를 동시에 실행**한다 — 예: 구간별로 묶어 각 구간을 별도 에이전트에 위임하고, 각 에이전트가 "사실·출처 URL·확인 날짜·등급·verbatim"을 반환하게 한 뒤 리드가 결과를 모아 한 번에 §0 게이트로 일괄 필터링한다. 이렇게 하면 항목 수가 늘어도 총 소요 시간이 순차 실행처럼 선형으로 늘지 않는다. Task/Workflow 도구를 못 쓰는 환경(병렬 실행 수단이 없는 경우)에서만 순차 폴백으로 돌아가고, 그 사실을 8단계 완료 보고에 명시한다.

### 5. 실습 검증
실습 후보마다 파일2(실습) 13항목 스키마를 채우고, 주차 상세 강의설계 `sessions/N주차/N주차_강의안설계.md` §11(실습 검증 방법·기록 기준)(처음 보는 사람이 지시문만 보고 시작할 수 있는가, 5~7분 안에 복구되는가 등)으로 판정한다. 직접 재현할 수 없는 항목은 그럴듯하게 추측해 채우지 말고 `[미검증]`으로 표시한다 — 검증 안 된 실습안이 검증된 것처럼 남으면 현장에서 그대로 사고로 이어진다. 실습 후보가 여럿이고 서로 독립적이면(한 후보의 검증이 다른 후보 결과에 영향을 주지 않으면) 4단계와 마찬가지로 병렬로 검증한다.

### 6. 게이트 필터·수업 문장화
조사·검증 결과를 §0 게이트로 채택/탈락 분류한 뒤, 채택분을 코딩 경험이 없는 입문자가 한 번에 읽고 이해할 수 있는 수업 문장으로 정리한다. 링크와 등급 표기만 나열하고 끝내지 않는다. **단순화가 부정확으로 넘어가지 않게** 한다 — 제품·구조 사실(예: 플랫폼별 진입 경로 차이)을 초보자용으로 압축할 때 nuance를 임의로 뭉개면 오개념이 된다. 압축본을 G3의 원문 인용과 대조해 "쉬워졌지만 여전히 맞는지" 확인한다. 채택분은 개념별 청크로 정리하고, 청크 최소깊이(비유≥2·워크드예시≥1·흔한오해→교정≥2·verbatim≥1)를 충족시킨다.

청크를 확정하기 전에 **G7 재대조**를 수행한다 — 3단계에서 만든 매트릭스를 보지 말고, 주차 상세 강의설계 §14·§15와 구간별 서술을 처음부터 다시 훑어 언급된 모든 개념·용어명을 새 목록으로 뽑은 뒤 지금 만든 청크 목록과 1:1 대조한다. 원문에는 있는데 청크가 없는 개념을 발견하면 이 시점에 추가한다.

### 7. 산출
아래 **산출물 규격**대로 3파일 + **개념 지식베이스(`N주차_개념KB.md`, 청크+ID RAG · additive)**를 `sessions/N주차/자료/`에 쓴다. 이 4파일이 기본 산출물이다. 각 파일 서두에 메타 헤더(작성=리서치 스킬·작성일·기준 문서·대상 수강생)를 `sessions/1주차/초안.md`의 관례 그대로 붙인다.

**사람 읽기용 종합 요약본(`N주차_리서치_종합정리.md`)과 사람 확인용 리뷰 HTML(`N주차_리서치_리뷰.html`)은 기본 산출물이 아니다** — 사용자가 게이트A 확인 시점이나 완료 보고 이후 명시적으로 요청할 때만 만든다. 요청받으면 아래 산출물 규격의 파일 4·파일 5대로 만든다.

### 8. 자기검증 → 완료 보고
아래 **자기검증 체크리스트**를 스스로 통과한 뒤, 사용자에게 보고한다: 산출 파일 목록(기본 4파일 — 3파일 + 개념KB)·커버리지 요약(빈칸 수)·결정요청 항목 수·예외승인 목록(G2)·탈락 로그 요약·병렬/순차 실행 여부(순차 폴백이었다면 사유)·다음 단계 안내(`/콘텐츠`로 이어받으면 된다는 안내, 그리고 "종합 요약본·리뷰 HTML이 필요하면 요청하라"는 안내).

## 산출물 규격

`sessions/N주차/자료/`에 3파일 골격 + **개념 지식베이스(청크 KB)**를 기본으로 쓴다. 종합 요약본(사람 읽기용)과 리뷰 HTML(사람 확인용)은 **사용자가 요청할 때만** 추가로 쓴다. 3파일 8항목/13항목 스키마의 세습 근거는 주차 상세 강의설계 §14(리서치 제출 패키지)이며, 아래 항목명은 리서치 SKILL 산출물 규격이 정본이다 — 항목을 추가·축소하지 않는다.

### 메타 헤더 (3파일 공통, 서두)
```
> 작성: 리서치 스킬
> 작성일: YYYY-MM-DD  (= G2 신선도 판정의 조사 기준일)
> 기준 문서: (커리큘럼 파일명 · 주차 상세 강의설계 파일명)
> 대상 수강생: 코딩 경험이 거의 없는 입문자 중심 혼합군(연령·경험 수준 다양)
```

### 파일 1. `N주차_콘텐츠리서치_결과.md`
교시별로 8항목을 채운다: ① 핵심 메시지 ② 초보자용 설명 문장 ③ 사실 확인 내용 ④ 사용 가능한 비유 ⑤ 비교 사례 ⑥ 출처 URL과 확인 날짜(G1 등급도 함께 표기) ⑦ 슬라이드에 넣을 표·도식·이미지 아이디어 ⑧ 피해야 할 표현과 과도한 내용. 이 8항목×6구간 골격은 `verify_session_docs.py`가 기계로 강제하는 계약이므로 그대로 **유지**한다(항목 추가·축소, 구간 수 축소 금지). ④비유·⑤비교 사례·⑧피해야 할 표현은 한 줄 요약에 그치지 말고 리치하게 확장한다(비유는 매핑·오해 위험까지, 비교 사례는 대조 포인트까지, 피해야 할 표현은 근거까지). 각 개념 서술에는 `N주차_개념KB.md`의 해당 청크를 `[C-슬러그]`로 교차참조해 단다.

말미에 "부록: 탈락 자료 로그" 섹션을 두고, 등급 미달(G1)·신선도 위반(G2)·확인불가(G3) 등으로 제외한 자료와 사유를 남긴다(무단 누락 금지). 탈락 항목이 없으면 "해당 없음"이라고 명시한다.

### 파일 1b. `N주차_개념KB.md` (청크+ID RAG 정본 · additive)

파일 1의 8항목/6구간 골격을 대체하지 않는 **추가 심화층**이다. `sessions/N주차/자료/N주차_개념KB.md`에 가르칠 개념마다 청크 1개를 만든다 — 빈 템플릿은 `sessions/_template/자료/개념KB.md`.

서두: 메타 헤더(작성=리서치 스킬·작성일 YYYY-MM-DD·기준 문서·대상 입문자) + 청크 규약 3~5줄(ID·메타주석·grep 검색법).

개념마다 청크 1개:
```
## [C-<개념-슬러그>] <개념 표시명>
<!-- 구간:1,3 | 유형:개념 | 우선:P1 | 출처:S-105,S-107 | 태그:토큰,예측 -->

- **정의(정확):** … [S-###]
- **초보자 문장:** … (한 화면에 그대로 올릴 완결형 1~2문장)
- **비유①:** … [매핑: A=…·B=…] (오해 위험: …)
- **비유②:** … [매핑: …]
- **워크드 예시:** 입력 → 처리 → 결과를 실제 값으로 [S-### 또는 (창작)]
- **비교표:** (대조형 개념만) | 구분 | X | Y |
- **흔한 오해→교정:** "오해" ✗ → 교정 ✓ [S-###]
- **흔한 오해→교정:** "오해" ✗ → 교정 ✓ [S-###]
- **verbatim:** "원문 핵심 한 문장" (S-###, YYYY-MM-DD)
- **PPT 소재:** …
- **피해야 할 표현:** …
```

규칙: 키=개념 정체성 안정 슬러그(구간 종속 금지, 다중 구간이면 메타 `구간:`에 콤마 다중값) · 청크↔출처=N:M · 유형∈{개념,실습연계,비유,오해,사례} · 우선∈{P0,P1,P2} · 청크 최소깊이 비유≥2(매핑)·워크드예시≥1·흔한오해→교정≥2·verbatim≥1·[S-###]≥1 · 사실필드가 S-000(설계문서) 단독이면 FAIL(외부 1급/2급 출처 필요, 설계·내부 확정 항목만 예외) · grep 검색계약: `구간:`·`유형:`·`태그:`·`[C-슬러그]`로 회수 가능.

### 파일 2. `N주차_실습안_검증결과.md`
실습 후보별로 13항목을 채운다: ① 실습 목적 ② 수강생 안내문 ③ 실제 요청문 ④ 준비물과 사전 설정 ⑤ 정상 진행 순서 ⑥ 완료 기준 ⑦ 예상 소요 범위 ⑧ 자주 발생하는 오류 ⑨ 복구 방법 ⑩ 정상 완성본 위치 ⑪ 최소 복구본 위치 ⑫ 디지털 도구에 익숙하지 않은 수강생의 어려움 ⑬ 채택·보류·제외 추천과 근거.

### 파일 3. `N주차_결정요청사항.md`
총괄이 결정할 항목만 6열 표로 정리한다: `결정 항목 | 후보 | 장점 | 위험 | 담당 추천 | 추천 근거`. G5에 따라 이미 확정된 사항은 올리지 않는다 — 대안 제안도 이 표를 통해서만 전달한다.

### 파일 4. `N주차_리서치_종합정리.md` (사람 읽기용 · 선택 — 사용자가 요청할 때만 산출)
파일 1~3의 핵심을 입문자도 한눈에 읽도록 **하나로 묶은 요약본**이다. **파이프라인 정본은 파일 1~3이고, 이 문서는 리뷰·회의용 읽기 자료**다(다음 단계가 소비하는 스키마 파일이 아니다). 최소 구성: ① 서두(성격=요약본·정본은 3파일·작성일·기준) ② "먼저 볼 것" 3~5줄(가장 중요한 주의·결정) ③ 강의 한눈에(구간별 한 줄) ④ 개념 설명 카드(초보자 설명·비유·피해야 할 표현·출처) ⑤ 실습 요약(완료 기준·실측 상태) ⑥ 결정요청 D표 ⑦ 출처 한눈에. 사실은 파일 1의 출처 표기를 그대로 인용하고, 실측 불가 항목은 `[미검증]`으로 구분한다. **스키마 검증 대상이 아니므로 형식은 가독성 우선**(표·굵게·짧은 줄).

### 파일 5. `N주차_리서치_리뷰.html` (사람 확인용 자립형 HTML · 선택 — 사용자가 요청할 때만 산출)
`sessions/_template/자료/리서치_리뷰.html`을 복제해 이번 주차 청크·출처로 채운 **사람 확인용 자립형 HTML**이다. 외부 스타일시트·스크립트·이미지를 불러오지 않고 인라인 CSS/JS만으로 동작해야 한다(`grep -nE "https?://|src=|<link"` 결과가 0이어야 함). 파일 4(종합정리.md)와 마찬가지로 파이프라인 정본이 아니라 리뷰용이며, 개념 카드마다 `data-chunk-id`·`data-구간` 속성을 유지해 나중에 필터링할 수 있게 한다.

- [ ] 채택한 모든 사실 항목에 출처 URL과 확인 날짜(YYYY-MM-DD)가 있는가
- [ ] 5개월 신선도 위반이 0건인가 — 예외는 전부 `[예외승인]` 태그가 있는가
- [ ] 모든 링크를 실제로 열어 내용을 확인했는가 — `[확인불가]`와 죽은 링크를 구분했는가
- [ ] 커버리지 매트릭스(교시 × 조사 항목)에 빈칸이 0인가
- [ ] **(G7) 매트릭스가 아니라 주차 상세 강의설계 §14·§15·구간별 서술 원문을 다시 훑어서** 언급된 모든 개념·용어명을 청크 목록과 1:1 대조했는가 — 매트릭스 빈칸 검사만으로 끝내지 않았는가. "행동 후 이름 붙임"류 항목을 진행 기법이라는 이유로 청크 없이 넘기지 않았는가

## 파이프라인 인터페이스

- **입력(앞 단계)**: 커리큘럼(`sessions/바이브코딩_커리큘럼_기준안.md` 상위 기준 · `sessions/N주차/N주차_강의안설계.md` 주차 상세, 스토리라인·총괄 담당·스킬 없음) · 사용자 브리프.
- **출력 소비자(뒤 단계)**: `/콘텐츠`가 이 3파일과 `N주차_개념KB.md`·커리큘럼을 읽어 `sessions/N주차/초안.md`를 쓴다. 파일명·항목 스키마가 바뀌면 `/콘텐츠`가 못 읽으므로 산출물 규격을 임의로 바꾸지 않는다. /콘텐츠는 개념KB.md의 청크 메타주석(구간·유형·태그·`[C-슬러그]`)을 grep해 슬라이드별로 필요한 청크만 선택 회수한다.
- **사람 산출물과의 호환**: 같은 스키마를 지키면 사람이 직접 쓴 조사 결과와 이 스킬이 쓴 조사 결과는 완전히 호환된다(`skills/README.md`) — 다음 단계는 작성 주체가 아니라 파일 내용·스키마로 입력을 인식한다. 1주차처럼 이미 사람이 쓴 주차 상세 강의설계가 있는 주차를 스킬이 다시 쓸 필요는 없다.
