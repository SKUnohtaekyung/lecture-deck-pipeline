# 리서치 — 콘텐츠 조사·실습 설계 검증

강의 제작 파이프라인에서 **커리큘럼 → 리서치 → 콘텐츠** 순서의 가운데 단계를 맡는다. 스토리라인·커리큘럼팀이 확정한 학습 흐름을 받아, 콘텐츠 담당이 추가 질문 없이 바로 PPT 초안을 쓸 수 있을 만큼 근거 있는 조사 결과와 검증된 실습안을 `sessions/N주차/자료/`에 3파일로 만든다. 콘텐츠를 대신 쓰지 않고, 콘텐츠가 쓸 재료를 만든다.

---

## §0. 하드 게이트 (협상 불가)

이 스킬의 산출물 문장은 강사가 현장에서 그대로 말하게 된다. 근거 없는 정보·낡은 화면 설명·출처 불명 사례가 섞이면 수업 중에 바로 신뢰가 깨진다. 아래 게이트는 예외 없이 지킨다 — 위반하며 채우느니 `[미확인]`·`[확인불가]`로 남기고 결정요청사항으로 넘긴다.

### G1. 공신력 3등급
모든 채택 사실 항목은 아래 등급 중 하나로 판정하고 항목마다 등급을 표기한다. 등급 판정은 인수인계서 `# 5. 리서치·실습 검증 원칙`의 `## 정보 조사 원칙`(OpenAI 제품은 공식 자료 우선, 블로그·영상은 보조 자료로 쓰고 별도 검증)을 기준으로 삼는다.

| 등급 | 정의 | 처리 |
|---|---|---|
| 1급 | 제품 공식 문서·공식 블로그·릴리스 노트 | 단독 채택 가능 |
| 2급 | 주요 언론·학술 자료 | 단독 채택 가능 |
| 3급 | 실무 블로그·영상 | 보조 전용 — 1~2급 교차 검증 없이 단독 채택 금지 |
| 금지 | 익명 포럼 단독 자료·출처 불명 AI 생성물 | 채택 금지 — 발견 시 사유와 함께 탈락 로그에 남긴다 |

### G2. 신선도 — 조사 시점 기준 3개월 이내
제품 화면과 제공 범위는 몇 주 단위로 바뀐다. 발행일 또는 최종수정일이 조사 시점(산출물의 작성일) 기준 **3개월을 넘는 자료는 채택하지 않는다.** 산출물에 작성일을 명기해 3개월 기준점을 남긴다.

바이브코딩 정의처럼 시간이 지나도 안 변하는 개념(evergreen)이 3개월 밖 자료에만 있으면, 임의로 넣지 말고 사용자 승인을 구한다:

> ○○ 개념은 3개월 이내 자료가 없고, 있는 자료는 YYYY-MM-DD 발행분입니다. 개념 자체가 안정적이라 예외로 포함해도 될까요?

승인을 받으면 `[예외승인: 사유=…·승인일=YYYY-MM-DD]` 태그를 달아서만 포함한다. 승인 없이 포함하지 않는다.

### G3. 출처 — URL + 확인 날짜, 링크는 실제로 연다
모든 사실 항목에 `출처 URL + 확인 날짜(YYYY-MM-DD)`를 붙인다. 채택 전 WebFetch로 링크를 실제로 열어 산출물에 적을 내용과 원문이 일치하는지 확인한다 — 링크만 나열하면 콘텐츠 담당이 다시 검증해야 하므로, 인수인계서의 완료 기준("링크만 나열하지 않고 실제 수업 문장으로 정리")을 어기는 셈이다. 403·429 같은 봇 차단 응답은 죽은 링크와 다르게 `[확인불가]`로 표시하고 불채택으로 분류한다 — 내용이 틀렸다고 단정하진 않되, 확인 못 한 채로 수업 문장에 쓰지 않는다.

### G4. 물량·커버리지 — 빈칸 0
게이트A에서 합의한 조사 범위표의 전 항목에 응답한다. 항목당 출처 1개 이상을 확보하고, 가능하면 공식 자료·실무 자료·사례를 교차시켜(3각 커버) 한쪽 출처만으로 결론 내지 않는다. 최종 커버리지 매트릭스(교시 × 조사 항목)에 빈칸이 있으면 콘텐츠 담당이 PPT를 쓰다 다시 물어보게 되므로, 빈칸 항목은 `[미확인]`으로 표시하고 결정요청사항에 올린다 — 조용히 건너뛰지 않는다.

### G5. 확정사항 불변
인수인계서 `# 2. 이미 확정된 사항` 같은 기존 확정안은 조사 중 임의로 바꾸지 않는다 — 임의로 바꾸면 이미 합의된 스토리라인이 깨지고 재조정 비용이 커진다. 더 나은 대안을 찾아도 확정안을 지우거나 덮어쓰지 말고 `N주차_결정요청사항.md`에 "별도 제안"으로 추가한다. 최종 결정은 스토리라인·총괄 담당의 몫이다.

### 발동 조건 — 명시 호출 전용
리서치 스킬은 **명시 호출**로만 시작한다. 아래 3항 중 하나에 해당해야 한다 — 상세 정의는 `skills/README.md`가 정본이다.

- (a) `/리서치` 또는 `$리서치` 형태의 직접 호출
- (b) "리서치 스킬로 2주차 조사해줘"처럼 **스킬임을 지목한** 자연어
- (c) 오케스트레이터가 파이프라인 지시에서 스킬을 이름으로 지목한 경우(스킬 체이닝)

"자료 조사해줘"·"이 자료 좀 찾아줘" 같은 보통명사 단독 요청은 발동 조건이 아니다. 팀 워크플로 스킬 3종(리서치·콘텐츠·검토) 공통 규약이며, vibecoding-deck만 예외적으로 자동 발동을 유지한다.

## 조립 전 read-path

작업을 시작하기 전에 아래를 순서대로 읽는다 — 건너뛰면 스키마가 다른 산출물을 만들어 콘텐츠 담당이 다시 물어보게 된다.

1. **인수인계서(있는 주차)**: `sessions/N주차/자료/N주차_콘텐츠리서치_실습설계_인수인계서_*.md`. 1주차 원본은 `sessions/1주차/자료/1주차_콘텐츠리서치_실습설계_인수인계서_해서_준형.md`이며, 특히 `# 5. 리서치·실습 검증 원칙`(하위 `## 정보 조사 원칙` = 공신력 기준의 근거)·`# 7. 제출 형식`(3파일 스키마 정본)·"리서치 완료 기준"을 읽는다.
2. `skills/README.md` — 계약 표·명시 호출 3항 정의·파이프라인 전체 지도.
3. `sessions/README.md` — 세션 폴더 규약, 산출물을 어디에 쓰는지.
4. 커리큘럼 `_dev/강의자료/`의 해당 주차 상세안 — 인수인계서가 없는 주차(2·3주차 등)에서는 이 문서가 조사 범위의 1차 근거가 된다.
5. 기존 `sessions/N주차/자료/`(있으면) — 같은 주차에 이미 쌓인 조사가 있는지 확인해 중복 조사를 피한다.

## 워크플로 (8단계)

### 1. 입력 파악
다룰 주차(N)를 확정하고 위 read-path를 순서대로 읽는다. 인수인계서가 있으면 그 범위를, 없으면 커리큘럼과 사용자 브리프를 조사 범위의 출발점으로 삼는다.

### 2. ★게이트A: 조사 범위 확인
교시 목록·교시별 핵심 질문·실습 후보·결정요청 후보를 표로 정리해 사용자에게 제시하고 **확인을 받은 뒤에만 조사를 시작한다.** 인수인계서가 없는 주차는 이 표가 사실상 그 주차의 인수인계서 역할을 하므로 특히 꼼꼼히 합의한다. 범위 합의 없이 조사부터 시작하지 않는다 — 범위를 잘못 짚고 다시 조사하는 비용이 먼저 확인받는 비용보다 훨씬 크다.

- **범위표 형식**: ①교시 목록 ②교시별 핵심 질문 ③실습 후보 ④결정요청 후보 — 4요소를 이 순서로, 각각 절 또는 표로 제시한다.
- **커리큘럼에 교시별 상세안이 없는 주차**(개요만 있는 2·3주차 등): 핵심 질문·실습 후보를 커리큘럼 개요에서 역산해 **'제안'임을 명시**하고 제시한다. 스토리라인 확정이 필요한 항목은 지어내지 말고 결정요청 후보로 분류하며, 상세안 부재 사실을 표 서두에 밝힌다 — 역산 제안은 합의를 위한 초안이지 확정이 아니다.

### 3. 조사 계획
합의된 범위를 교시 × 조사 항목의 검색 태스크 매트릭스로 쪼갠다. 이 매트릭스가 4단계 실행 목록이자 G4 커버리지 확인의 기준표가 된다.

### 4. 심층 조사
**deep-research 스킬의 가용성을 먼저 확인**한다.
- **있으면**: 게이트A에서 합의된 범위를 명확한 질문으로 정제해 전달한다(모호한 질문을 넘기면 deep-research가 재확인 루프를 도는데, 범위는 이미 합의됐으므로 그 루프가 불필요하다). args에 이 스킬의 제약(공신력 등급·3개월 신선도·URL+확인날짜 필수)을 명시한다. 반환물은 그대로 채택하지 않고 **§0 게이트로 다시 필터링**한다 — deep-research는 이 스킬 고유의 3등급·3개월 기준을 모르기 때문이다. 게이트에서 탈락한 항목은 사유와 함께 로그에 남긴다(무단 누락 금지).
- **없으면(예: Codex 환경)**: 내장 폴백을 쓴다 — 조사 항목별로 웹검색을 팬아웃하고, 후보를 원문에서 직접 확인(WebFetch)한 뒤 동일한 §0 게이트를 적용한다.

### 5. 실습 검증
실습 후보마다 `# 7` 파일2의 13항목 스키마를 채우고, 인수인계서 `# 5. 리서치·실습 검증 원칙`의 `## 실습 검증 원칙`(처음 보는 사람이 지시문만 보고 시작할 수 있는가, 5~7분 안에 복구되는가 등)으로 판정한다. 직접 재현할 수 없는 항목은 그럴듯하게 추측해 채우지 말고 `[미검증]`으로 표시한다 — 검증 안 된 실습안이 검증된 것처럼 남으면 현장에서 그대로 사고로 이어진다.

### 6. 게이트 필터·수업 문장화
조사·검증 결과를 §0 게이트로 채택/탈락 분류한 뒤, 채택분을 40~50대 초보자가 한 번에 읽고 이해할 수 있는 수업 문장으로 정리한다. 링크와 등급 표기만 나열하고 끝내지 않는다.

### 7. 산출
아래 **산출물 규격**대로 3파일을 `sessions/N주차/자료/`에 쓴다. 각 파일 서두에 메타 헤더(작성=리서치 스킬·작성일·기준 문서·대상 수강생)를 `sessions/1주차/초안.md`의 관례 그대로 붙인다.

### 8. 자기검증 → 완료 보고
아래 **자기검증 체크리스트**를 스스로 통과한 뒤, 사용자에게 보고한다: 산출 파일 목록·커버리지 요약(빈칸 수)·결정요청 항목 수·예외승인 목록(G2)·탈락 로그 요약·다음 단계 안내(`/콘텐츠`로 이어받으면 된다는 안내).

## 산출물 규격

`sessions/N주차/자료/`에 3파일을 쓴다. 스키마 정본은 인수인계서 `# 7. 제출 형식`이며, 아래 항목명은 그 원문을 그대로 옮긴 것이다 — 항목을 추가·축소하지 않는다.

### 메타 헤더 (3파일 공통, 서두)
```
> 작성: 리서치 스킬
> 작성일: YYYY-MM-DD  (= G2 신선도 판정의 조사 기준일)
> 기준 문서: (커리큘럼 파일명 · 인수인계서 파일명)
> 대상 수강생: 40~50대 중심, 코딩 경험이 거의 없는 초보자
```

### 파일 1. `N주차_콘텐츠리서치_결과.md`
교시별로 8항목을 채운다: ① 핵심 메시지 ② 초보자용 설명 문장 ③ 사실 확인 내용 ④ 사용 가능한 비유 ⑤ 비교 사례 ⑥ 출처 URL과 확인 날짜(G1 등급도 함께 표기) ⑦ 슬라이드에 넣을 표·도식·이미지 아이디어 ⑧ 피해야 할 표현과 과도한 내용.

말미에 "부록: 탈락 자료 로그" 섹션을 두고, 등급 미달(G1)·신선도 위반(G2)·확인불가(G3) 등으로 제외한 자료와 사유를 남긴다(무단 누락 금지). 탈락 항목이 없으면 "해당 없음"이라고 명시한다.

### 파일 2. `N주차_실습안_검증결과.md`
실습 후보별로 13항목을 채운다: ① 실습 목적 ② 수강생 안내문 ③ 실제 요청문 ④ 준비물과 사전 설정 ⑤ 정상 진행 순서 ⑥ 완료 기준 ⑦ 예상 소요 범위 ⑧ 자주 발생하는 오류 ⑨ 복구 방법 ⑩ 정상 완성본 위치 ⑪ 최소 복구본 위치 ⑫ 40~50대 초보자 관점의 어려움 ⑬ 채택·보류·제외 추천과 근거.

### 파일 3. `N주차_결정요청사항.md`
총괄이 결정할 항목만 6열 표로 정리한다: `결정 항목 | 후보 | 장점 | 위험 | 담당 추천 | 추천 근거`. G5에 따라 이미 확정된 사항은 올리지 않는다 — 대안 제안도 이 표를 통해서만 전달한다.
