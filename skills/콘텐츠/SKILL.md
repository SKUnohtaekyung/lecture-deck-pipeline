# 콘텐츠 — 슬라이드 글·비유·멘트 집필

리서치 산출물(`sessions/N주차/자료/`)을 근거로 슬라이드에 올라갈 글·비유·강사 멘트를 집필해 `sessions/N주차/N주차_초안.md`(레거시 `초안.md` 폴백 인식 · 콘텐츠 초안 4열 표)를 산출하는 팀 워크플로 스킬이다. 5인 팀에서 이 스킬이 맡는 자리는 "피피티 내용" — 자료 조사(`/리서치`)와 덱 조립(`/create-slides`) 사이, 리서치 결과를 실제 슬라이드 문장으로 옮기는 단계다.

**이 스킬의 문장이 곧 화면 최종 문장이다.** 하류(`/create-slides`)는 콘텐츠 초안의 `슬라이드 제목`·`본문 문구`를 재작성하지 않는다 — 콘텐츠 소유권 경계(`references/콘텐츠초안-입력형식.md` §2)로 보호되어 있다.

> **통합 실행 시의 예외(R-OWN-03 · 2026-07-29 · 정본 루트 `SKILL.md` ③-B).** 이 스킬과 조립이 **하나의 실행 단위**로 돌 때, 초안 메타 헤더의 작성 주체가 **스킬**이면 같은 실행 안에서 자기 문장을 고칠 수 있다(변경 사유를 판단 기록에 남긴다). **사람이 쓴 초안이거나 작성 주체 필드가 없으면 경계는 그대로**이며, 고칠 곳은 고치지 말고 보고한다. 실행이 끝나면 그 문장은 확정된다 — 다음 세션이 지난 실행의 산출물을 자기 것으로 여기지 않는다. 즉 여기서 쓴 문장은 오타 하나까지 그대로 수강생 화면에 올라간다. "나중에 다듬어지겠지"는 이 파이프라인에서 성립하지 않는다 — 초고가 아니라 최종고를 쓴다는 전제로 집필한다.

이 문서가 콘텐츠 스킬의 정본이다 — 어댑터(`.claude/skills/콘텐츠/`·`.agents/skills/콘텐츠/`)는 이 문서를 로드만 하고 규칙을 복제하지 않는다.

## §0. 불변 규칙 (협상 불가)

1. **형식 = `입력양식/콘텐츠초안템플릿.md` 그대로.** 교시(또는 섹션)별 4열 표(`#`(교시-순번, 예 `3-7`)·`슬라이드 제목`·`본문 문구`·`비유·멘트`) + 아이콘 범례 서두(💬 농담→발표자 노트 / 👀 시연→발표자 노트 / 🗣 막힐 때 예시→접힘 힌트) + `0번` 덱 기본 정보 표(강의명·주차·발표자·대상·톤) + `(간지)`·`(표지)`·`(마무리)` 고정 슬라이드 신호 + 분량 감축 시 `(선택)` 태그. **0번 표에 팀명은 넣지 않는다** — 팀명은 하류가 파트 진행률로 자동 표시한다. **0번의 "파트 구조" 표는 기본적으로 비워 둔다** — PART 묶음은 조립 직전 하류가 사용자에게 확인받아 정하는 구조·연출 결정이라(`references/콘텐츠초안-입력형식.md` §4) 콘텐츠 스킬이 임의로 정하지 않는다. 사용자가 이미 묶음을 지정했다면 그대로 받아 적는다.
   - **`분할 허용` 필드는 없다.** 하류가 수용량을 넘긴다고 판단하면 조립 전에 스스로 분할을 제안한다(`입력양식/콘텐츠초안템플릿.md` "작성 팁"). 콘텐츠 스킬이 임의로 슬라이드를 쪼개 번호를 늘리지 않는다 — 초과가 예상되면 집필노트에 **분할 제안**만 남기고, 표 자체는 한 행으로 유지한다.
2. **사실은 근거만.** 사실 주장(정의·수치·제품 동작·비교)은 `sessions/N주차/자료/`의 리서치 산출물(기본 5파일 — 그중 **사실의 정본은 `N주차_개념KB.md` 청크**다) 또는 같은 폴더의 사람이 작성한 자료에 근거가 있는 것만 쓴다. 비유·농담은 창작해도 되지만 사실을 단정하는 문장으로 위장하지 않는다. **근거 없는 사실이 필요해지면 집필을 밀어붙이지 말고** "리서치 필요 목록"으로 보고한다(워크플로 2단계 게이트A).
   - **근거는 행에 남긴다(refs 주석).** 사실 근거가 있는 행은 어느 청크에서 왔는지를 행 말미 HTML 주석 `<!-- refs: C-… -->`로 표시한다 — 형식·위치·예외는 "산출물 규격 → `N주차_초안.md`"가 정본이다.
3. **실습 완성 프롬프트는 본문 노출 금지.** 수강생이 그대로 복붙하면 안 되는 완성 요청문은 반드시 `🗣`로만 적는다 — `본문 문구`에 절대 두지 않는다. 수강생이 생각 없이 복붙하는 것을 막는 팀 원칙이며, 하류는 `🗣`를 접힌 힌트(`.hint-reveal`)로만 화면에 올린다.
4. **톤 — 대상은 과목 프로필 §1의 「대상 수강생」이 정한다.** 그 대상이 한 번에 읽고 이해할 수 있는 말로 쓰고(전문용어를 쓸 땐 반드시 비유 동반), 겁주지 않고, 가끔 웃긴다. 프로필 §1에 **관통 문장**이 있으면 회차마다(적어도 은근히) 반복해 톤을 통일한다. 프로필이 없거나 관통 문장이 비어 있으면 이 항목은 WARN이며, 임의로 관통 문장을 지어내지 않는다.
5. **명시 호출 전용.** 다음 3항 중 하나로만 발동한다 — (a) `/콘텐츠`·`$콘텐츠` 직접 호출 (b) "콘텐츠 스킬로 ~"처럼 스킬임을 지목한 자연어 (c) 오케스트레이터가 파이프라인 지시에서 이름으로 지목(스킬 체이닝). "초안 써줘"·"글 다듬어줘" 같은 보통명사 단독 요청은 발동하지 않는다. 상세·트레이드오프는 `skills/README.md` "호출 규약"이 정본이다.
6. **밀도 = 슬라이드당 정보 단위 3~6개.** 정보 단위 = 본문 개념 블록·비유/예시 카드·비교표·오해→교정·체크/콜아웃 각 1단위. **근-빈 슬라이드 금지**(단위 1개 이하 지양). 물리 한도(22px 하한·548px 세로 예산·kit 용량식) 안에서 담고, **초과 깊이는 발표자 노트·리서치 청크 KB로** 넘긴다(슬라이드에 욱여넣지 않는다). 문자수 목표는 두지 않는다 — 참조 덱의 리치함은 글자수가 아니라 단위 수다.
   - ⚠️ **검증 스크립트의 글자수 검사는 대리 신호일 뿐 이 규칙과 모순이 아니다(2026-07-27 명확화).** `verify_draft_quality.py`(R-QD-01)·`verify_deck_quality.py`(R-QC-01)의 본문 글자수 하한은 목표치가 아니라 "정보 단위가 부족할 가능성"을 값싸게 근사하는 대리 신호다 — 실제 판정 기준은 여전히 정보 단위 수(R-QD-02/R-QC-02)이고, WARN이 뜨면 글자를 채우지 말고 단위를 더한다.
   - ⚠️ **화면 조작 안내 슬라이드는 이 하한에서 제외한다.** 커리큘럼 기준안 §6 원칙 9가 "한 화면에는 한 단계만 보여준다"고 규정하므로, 조작 안내는 **한 슬라이드 = 조작 단계 1개**가 정답이고 단위 1개도 근-빈 슬라이드가 아니다. 단계가 여럿이면 슬라이드 번호를 나눠 쓰고(이 경우는 §0-1의 임의 분할 금지에 해당하지 않는다), 각 행의 `본문 문구`에 그 한 단계만 쓴다. 검증 스크립트는 이 예외를 제목·본문 어휘(열기/켜기/누르기·버튼/메뉴/권한 요청)로 자동 인식해 R-QD-01/02·R-QC-01/02에서 뺀다(수동 표시 불필요).
   - ⚠️ **화면:노트 배분 — 주장은 화면에, 비유·근거·예시 중 최소 하나도 화면에 남긴다(R-DENS-02).** 노트(`비유·멘트`)는 화면 본문의 보강이지 본체의 이주처가 아니다. 측정 가능한 형태로 표현하면: 그 행의 노트 글자수가 본문 글자수를 크게 웃돌면(대략 노트:본문 비율이 1에 근접하거나 넘으면) 화면이 아니라 노트에 내용을 몰아넣고 있다는 신호다 — `scripts/verify_draft_quality.py`(R-QD-03)가 이 비율을 초안 단계에서 측정해 WARN한다. 비유·근거·예시를 전부 `🗣`/`💬`로 빼고 화면에는 결론 한 줄만 남기지 않는다.
7. **장수는 시간예산 역산이 아니라 설명 단위에서 결정한다(R-PLAN-01, 협상 불가).** "270분 ÷ 원하는 슬라이드당 시간 = N장" 같은 시간예산 역산은 **명시적 안티패턴**이다 — 2주차 계획서(`sessions/2주차/2주차_최종수정계획.md:16`) 스스로도 "장수를 먼저 정하지 않는다. 270분을 개념·실습·확인·전환으로 배분한 뒤 CORE를 계산한다"고 이 원칙을 이미 명시했다(같은 원칙의 재확인이지 새 발견이 아니다). ⚠️ **정정(2026-07-27)**: 이전 버전이 "2주차가 106장(17.7장/교시)을 역산해 크게 이탈했다"고 적었으나 이는 사실 오류다 — 106장은 CORE(전원 필수) 73장 + FLEX(여유 시) 26장 + RECOVERY 7장의 **총 준비량**이고, 전원 필수 장수는 73장(1주차 75장과 비슷한 규모)이다. 실제 벗어난 지점은 §3(`교시별 장수 배분`)이 규약하는 **프로필 §2의 회차당 장수 범위**(당시 값 기준) 대비 계획서 `:113-118`의 **교시당 CORE 13·13·8·13·12·13**(교시 6개 중 5개가 상한 초과)이며, 이 정도는 "크게"가 아니라 **완만한 이탈**이다. 계획서 `:120`은 이 이탈을 이미 인지하고 대응책까지 적어 뒀다 — "다른 교시 13장은 45분 상한 근처 → 완화 밸브: 인접 개념 병합(예 1-2+1-3·4-1+4-2) 또는 CORE→FLEX 강등." 실패 지점은 계획이 무모했던 게 아니라 **이 밸브를 실행하지 않은 것**이다(집필노트에 사유도 안 남았다 — R-PLAN-01a). 장수는 "몇 분을 채울지"가 아니라 "설명하는 데 필요한 단위가 몇 개인지"에서 나온 **결과**여야 한다는 원칙 자체는 유효하다.
   - ⚠️ **교시당 장수 규약(§3 "교시별 장수 배분") 이탈 시 사유를 집필노트에 반드시 남긴다(R-PLAN-01a).** 이미 §3에 있던 문장의 강제력을 높인 것이다(중복 신설 아님) — `scripts/verify_draft_quality.py`(R-QD-04)가 **프로필 §2의 회차당 장수 범위** 이탈을 자동 검출하고, 집필노트 파일 자체가 없으면 사유 확인이 불가능하므로 **FAIL**한다. "이유를 남긴다"는 권고가 아니라, 남기지 않으면 게이트가 막는 강제 조항이다.
   - ⚠️ **필수 계층(CORE)의 깊이를 시간예산에 맞춰 깎지 않는다(R-PLAN-02, 협상 불가).** 2주차 저밀도의 실제 기제는 장수 역산이 아니라 이것이었다 — 계획서 `:13`이 명시적으로 "**CORE는 270분에 맞춰 얕게**, 초과 깊이는 FLEX로 분리한다"고 정해, 전원이 보는 화면을 의도적으로 얕게 만들고 깊이를 소수만 보는 FLEX·발표자 노트로 옮겼다. 시간이 부족하면 **다루는 범위를 줄이지, 화면에 남는 정보의 밀도를 깎지 않는다** — 깊이를 노트·FLEX로 옮기는 것은 시간 절약이 아니라 화면 완결성의 손실이다(R-DENS-02). 실측 결과가 그 손실을 그대로 보여준다: 노트:본문 글자수 비율 W2 1.19 대 W1 0.30(행 중앙값 1.13 대 0.32), 설명 슬라이드 본문 글자수 중앙값 W2 85자 대 W1 176자(2.07배 격차), 저밀도(<120자) 비율 W2 91.8% 대 W1 12.1%.
8. **부록·예비 강등 금지 대상(R-ANNEX-01, 협상 불가).** 예시·근거·주의점은 어떤 분류 체계(예: 2주차의 `CORE`/`FLEX`/`REC`류 자체 분류)로도 본류 밖(예: 마무리 슬라이드 뒤 별도 구획)으로 빼지 않는다 — 2주차에서 이 강등이 예시 7건·주의점 8건·근거 1건을 부록으로 밀어냈다(`reports/create-slides-quality/content_pipeline_audit.md` §F). **심화(더 깊은 원리·확장 논의)만 강등 후보**가 될 수 있다. `scripts/verify_deck_quality.py`(R-QC-11)가 종결 슬라이드 뒤 부록에서 예시/근거/주의점 마커를 탐지해 WARN한다.
9. **목적별 구성(R-COMP-01, 2026-07-27 신설).** 밀도 규칙(§0-6·R-QC-01/02)은 "양"만 잰다 — 이 규칙은 "무엇"을 정한다. 개념설명 슬라이드는 핵심 주장/정의를 **반드시** 담고, 그 위에 학습 목적에 필요한 만큼만 골라 더한다: 풀어주는 설명·예시·비교·비유·주의점·관계 시각구조·기억할 결론 중에서. **모든 요소를 매 장에 기계적으로 넣지 않는다** — 개념 하나를 정의만으로 충분히 이해시킬 수 있으면 그걸로 끝이고, 오해가 잦은 개념이면 오해→교정을 반드시 더한다. 조합은 사람이 판단한다(자동 게이트 없음).
10. **개념 정확성(R-ACC-01, 2026-07-27 신설).** ① 서로 다른 개념을 편의상 하나로 합쳐 서술하지 않는다 — 비슷해 보여도 실제로 다른 개념이면 각각 정의하고 관계를 밝힌다. ② 비유는 개념 자체를 대체하지 않는다 — 비유를 쓴 다음엔 반드시 원래 개념의 정의로 돌아오고, 비유가 어디서부터 안 맞는지(한계)를 필요하면 한 문장으로 표시한다.

## 조립 전 read-path

건너뛰면 형식 위반·무근거 사실·톤 이탈이 반복된다. 매번 이 순서로 읽는다.

0. **`sessions/과목프로필.md`** — 이 과목의 대상·관통 문장·회차 구조·장수/밀도 기준선·커리큘럼 정본 경로. **이 스킬 본문에는 과목 고유 값이 없다** — 전부 여기서 읽는다(스키마 `입력양식/과목프로필템플릿.md`). 파일이 없으면 오류가 아니라, 기준선을 요구하는 항목이 전부 WARN으로 내려가고 그 사실을 완료 보고에 적는다. **다른 과목의 실측치를 빌려 채우지 않는다.**
1. `skills/README.md` — 계약 표·파이프라인 지도·명시 호출 3항 정의. 이 스킬이 팀의 어디에 있고 입력·출력이 무엇인지 먼저 확인한다.
2. `입력양식/콘텐츠초안템플릿.md` — **출력 형식의 정본.** 4열 표·아이콘 범례·0번 메타 구조를 그대로 따른다. 이 문서가 스킬보다 우선이다 — 스킬이 형식을 변형하지 않는다.
3. `references/콘텐츠초안-입력형식.md` — 하류(`/create-slides`)가 이 초안을 어떻게 읽는지(아이콘 라우팅·콘텐츠 소유권 경계·PART 매핑). 하류가 못 고치는 실수(예: 완성 프롬프트를 본문에 쓰는 것)를 여기서 미리 막는다.
4. **직전 주차의 `sessions/N-1주차/N-1주차_초안.md`가 있으면** 톤·분량·메타 헤더 관례의 실전 예시로 읽는다 — 문장 길이·비유 밀도·관통 문구 반복 빈도가 크게 어긋나지 않는지 대조한다. **없으면 건너뛴다**(파일 부재는 오류가 아니다). 형식의 정본은 어디까지나 2번 `입력양식/콘텐츠초안템플릿.md`이며, 예시가 없어도 집필을 시작할 수 있어야 한다.
5. `kit/guide/토큰-치트시트.md`의 세로 예산·행높이 계산 — 슬라이드 하나에 얼마나 담을 수 있는지의 감각. 세로 예산 약 548px, 본문 22px 하한×1.78 ≈ 줄당 39px(2줄≈78px·3줄≈117px)이라는 숫자 자체보다, 이 **물리 한도 안에서 정보 단위 3~6개**(§0-6)를 담는 감각이 중요하다.
6. `sessions/N주차/자료/` **전체** — 이번 주차의 리서치 산출물. 기본 5파일(`N주차_콘텐츠리서치_결과.md`·`N주차_개념KB.md`·`N주차_출처레지스트리.md`·`N주차_실습안_검증결과.md`·`N주차_결정요청사항.md`)을 우선 찾되, 파일명이 이 규약과 다를 수 있으므로 **파일명이 아니라 내용으로** 리서치 산출물인지 식별한다. 사람이 직접 쓴 메모·자료가 같은 폴더에 섞여 있을 수 있으니 폴더 전체를 훑는다. 다만 **개념KB만은 통독하지 않는다** — 아래 두 항을 지킨다.
   - ⚠️ **`N주차_개념KB.md`는 통째로 Read 하지 않는다.** 서두 「청크 인덱스」 표(슬러그·표시명·구간·우선·관점·**범위**)만 읽어 무엇이 있는지 파악한 뒤, 슬라이드별로 필요한 청크만 `[C-슬러그]`·`구간:`·`유형:`·`태그:` grep으로 회수해 그 청크의 정의·초보자 문장·비유·워크드예시·오해→교정·사례/대안/한계·**PPT 소재·비교표·피해야 할 표현**으로 채운다(예: `rg -A 20 "\[C-토큰\]" sessions/N주차/자료/N주차_개념KB.md`). **`PPT 소재:`는 형태 제안이고 `필수 진술:`은 내용 보존 의무다(2등급 · 정본 `skills/리서치/references/chunk-schema.md`).** `PPT 소재`는 정보 모양 판단에 따라 **자유롭게 대체**할 수 있고 대체하면 사유만 남긴다 — 이전 판(“지정한 소재를 쓰라”)은 create-slides의 R-LAYOUT-02(“정보 모양이 고른다”)와 충돌해 폐기됐다. 반면 `필수 진술`은 **뜻을 빼는 것만 불가**하며 표현·배치는 자유다. 다만 소재를 **회수조차 하지 않으면** 시각자료 없이 텍스트로만 채우게 된다 — 대체는 자유지만 **읽지 않는 것은 자유가 아니다.** **KB 전문을 읽으면 첫 문장을 쓰기도 전에 컨텍스트가 포화된다** — 개념KB는 통독용 문서가 아니라 회수용 지식베이스이고, 인덱스 표가 그 진입점이다.
   - ⚠️ **회수할 때 인덱스 표의 `범위` 열(코어\|인접)을 반드시 구분한다.** `범위:인접` 청크(리서치 G9)는 커리큘럼 **밖**의 인접 개념(전제·후속·파생·혼동)을 게이트A 승인분만 얕게 담은 것이라, 코어 청크와 같은 재료가 아니다 — 비유·워크드예시·G8 관점 필드가 애초에 면제라 본문용 깊이도 없다. 골격 설계·본문 집필의 재료는 **코어 청크로만** 잡고, 인접 청크는 5단계의 라우팅 규칙에 따라 `🗣` 멘트·발표자 노트로 보낸다.
   - **`N주차_콘텐츠리서치_결과.md`는 이제 사실의 정본이 아니라 구간 인덱스층이다.** 사실·비유·비교의 실체는 개념KB 청크에 있으므로, 결과.md에서 `[C-슬러그]` 포인터를 발견하면 결과.md의 요약 한두 문장만 보고 쓰지 말고 **그 청크를 회수해 집필 재료로 쓴다.** 원문 인용 전문이 필요하면 `N주차_출처레지스트리.md`의 「출처ID별 verbatim」에서 `[S-###]`로 찾는다.

## 워크플로 (8단계)

### 1. read-path 수행, 주차 확정
사용자 지시나 기존 `sessions/N주차/` 존재로 주차를 정한다. **세션 폴더가 없어도 이 단계에서 만들지 않는다** — 폴더 생성(`sessions/_template/` 복사, `sessions/README.md` 규약)은 게이트A를 통과해 집필이 확정된 뒤(5단계 직전)에 한다. 게이트A에서 중단될 작업이 빈 폴더를 남기지 않게 하기 위함이다. 위 read-path 6개 항목을 전부 훑는다 — 특히 6번(`자료/` 전체)은 이번 집필의 유일한 사실 근거이므로 빠짐없이 확인한다(개념KB만은 통독이 아니라 「청크 인덱스」 표 + 필요한 청크 grep 회수다).

### 2. ★게이트A: 자료 충분성 판정
교시(또는 섹션)마다 "쓸 내용이 있는가"를 매트릭스로 점검한다 — 느낌으로 판단하지 않는다.

| 교시 | 핵심 메시지·설명 문장 | 사실 근거(수치·제품 동작 등) | 비유·비교 사례 (교시당 ≥2 필요) | 실습 절차(요청문·완료 기준·복구) |
|---|---|---|---|---|
| 1교시 | 있음 | 있음 | 있음 | 해당 없음 |
| 3교시 | 있음 | 있음 | 부족 | **부족** |

- **"사실 근거" 열은 `N주차_개념KB.md` 「청크 인덱스」 표부터 확인한다** — 해당 개념 청크(`[C-슬러그]`)가 표에 있고 회수해 보니 정의·verbatim·`[S-###]`가 채워져 있으면 그 열은 "있음"으로 본다. 인덱스 표에 없으면 나머지 파일(결과·출처레지스트리·실습안·결정요청)에서 직접 확인하고, 그래도 없으면 "부족"으로 표시한다.
  - ⚠️ **`범위:인접` 청크는 본문 근거로 세지 않는다.** 인접 청크가 아무리 많아도 그 교시의 본문을 뒷받침하지 못한다 — 커리큘럼 밖 개념을 얕게 담은 강사 답변용 재료이기 때문이다. 인덱스 표의 `범위` 열이 `인접`인 청크를 빼고 세어 코어 청크만으로 "있음"을 판정한다. 인접 청크로 칸을 메우면 자료 부족이 충분으로 둔갑해 게이트A가 무력해진다.
- 표에 **부족**이 하나라도 있으면 그 교시는 자료 부족이다. **집필을 강행하지 않는다.**
- 부족하면 "리서치 필요 목록"을 보고하고 중단한다 — 목록은 **무엇이 부족한지 · 왜 필요한지(그 슬라이드에서 어떤 주장·비유를 뒷받침해야 하는지) · 어느 교시인지** 세 가지를 슬라이드/교시 단위로 적고, `/리서치` 호출을 제안한다.
- 사용자가 "그래도 부분적으로 써줘"라고 승인하면, 부족한 교시의 관련 슬라이드에 `[자료 부족]` 마킹을 남기고 그 부분만 부분 집필한다. 마킹은 초안과 집필노트 양쪽에 남겨 하류·검토가 놓치지 않게 한다.
- 승인 없이 임의로 "이 정도면 되겠지"라며 채워 넣지 않는다 — 이 게이트가 없으면 무근거 사실(§0-2 위반)이 조용히 섞여 들어간다.

### 3. 골격 설계
자료가 충분하다고 판단된 범위에서 슬라이드 골격을 짠다.
- **회차별 장수 배분** — **과목 프로필 §2의 「회차당 장수 범위」**를 기준점으로 삼되, 이번 주차 분량에 맞게 조정한다. 프로필에 그 값이 없거나 「출처」 열이 비어 있으면 **기준선이 아니라 추측이므로 게이트로 쓰지 않고 WARN으로 보고**한다 — 다른 과목의 실측치를 빌려 채우지 않는다. **시간예산을 역산해 장수를 정하지 않는다**(§0-7 R-PLAN-01) — 장수는 설명 단위 수의 결과여야 한다. 크게 벗어나면(예: 한 교시가 3장뿐이거나 20장을 넘으면) **반드시** 이유를 집필노트에 남긴다(§0-7a R-PLAN-01a — 남기지 않으면 `verify_draft_quality.py`가 FAIL한다).
- **슬라이드별 핵심 한마디** — 아직 완성 문장이 아니라, 그 슬라이드가 전달할 단 하나의 메시지.
- **고정 슬라이드** — `(간지)`(교시 시작)·`(표지)`(0번)·`(마무리)`(종료)의 위치를 확정한다.
- **`(선택)` 후보** — 시간이 부족하면 뺄 수 있는 슬라이드를 미리 표시해 둔다.

### 4. ★게이트B: 골격 표 사용자 확인
3단계 골격 표(교시·슬라이드 수·핵심 한마디·고정 슬라이드 위치·`(선택)` 후보)를 사용자에게 보여주고 **확인받는다.** 확인 전에는 5단계(집필)로 넘어가지 않는다 — 골격이 틀리면 그 위에 쓴 문장 전부를 다시 써야 하므로, 문장을 쌓기 전에 구조부터 승인받는다.

### 5. 집필
확인된 골격을 따라 실제 `본문 문구`·`비유·멘트`를 쓴다.
- **수용량을 의식한다** — 세로 예산 548px·본문 22px 하한·kit 용량식(`kit/guide/토큰-치트시트.md`)은 물리 한도로 지키되, **슬라이드당 정보 단위 3~6개**(§0-6)를 목표로 담는다. 물리 한도를 넘기면 분량을 줄이기보다, 표 안에는 그대로 한 행으로 두고 **집필노트에 "분할 제안"** 각주를 남기거나 초과분을 발표자 노트로 뺀다. 임의로 슬라이드 번호를 쪼개지 않는다(§0-1).
- **비유 밀도** — 교시당 비유·사례 2개 이상을 목표로 한다. 없으면 억지로 만들지 말고, 근거가 없는 교시는 게이트A로 돌아가 자료 부족을 다시 점검한다.
- **1주차 인간 보정 원리(R-CAL-01)** — 18회 개정을 거친 1주차 최종본에서 승격된 저작 습관이다: ① 중복 절차 슬라이드는 병합한다(같은 준비 단계를 여러 슬라이드에 나눠 반복하지 않는다). ② 실습 슬라이드는 하위 동작마다 별도 행(카드 단위)을 주고, 여러 동작을 한 문장으로 압축하지 않는다. ③ 개념 슬라이드는 정보 단위마다 완결된 문장으로 채우고(라벨·키워드 나열이 아니라), 정보 단위 3개 이상을 목표로 한다(§0-6).
- **아이콘 문법을 정확히 쓴다** — 농담·애드리브는 `💬`, 강사 시연·관찰 유도는 `👀`, 막힐 때만 보여줄 완성 요청문은 `🗣`. 한 셀에 여러 아이콘이 섞여도 된다.
- **강조를 집필 시점에 지정한다 (R-EMPH-02 · 2026-07-28 신설)** — 어느 구절이 결론이고 어느 것이 근거인지는 **글을 쓰는 사람이 안다.** 조립 단계에서 즉흥으로 굵게 처리하면 반드시 빠뜨린다(실제로 4구간 표본 12장에서 `kit`의 민트 강조 3종이 **한 번도 쓰이지 않았다**). 그래서 `본문 문구` 셀에 아래 표기를 직접 남긴다.
  - `**결론**` — 그 슬라이드가 남길 한 문장. **행당 최대 1개.** 조립에서 `.hl-mint-mark`가 된다.
  - `__근거__` — 그 결론을 떠받치는 조건·이유 구절. 조립에서 `.hl-mint-underline`.
  - `*핵심어*` — 기억시킬 용어·수치. 조립에서 `.hl-mint-text`.
  - 강조 표기 합계는 **행당 3개 이하**(R-EMPH-01 「슬라이드당 강조 합계 ≤ 3」과 같은 한도).
  - **결론 표기가 없는 행은 미완성으로 본다** — 그 슬라이드가 무엇을 남기는지 정하지 않았다는 뜻이다. 정말 결론이 없는 도입·전환 슬라이드면 집필노트에 사유를 적는다.
  - 의미 배정은 `kit/guide/디자인시스템.md` **R-EMPH-01 강조 선택표**가 정본이다 — "문맥에 맞게"가 아니라 **의미로** 고른다.
- **한 형태로 통일하지 않는다 (R-FORM-01 · 2026-07-28 신설)** — 판별 질문은 하나다: **「항목의 순서를 바꿔도 뜻이 유지되는가?」**
  - **바꿔도 됨 → 병렬 항목**(카드·블록). 훑어 읽는 게 맞는 정보다.
  - **바꾸면 깨짐 → 산문**(줄글). 인과·논리 사슬이라 처음부터 읽어야 한다.
  - ⚠️ **지적을 전역 규칙으로 승격시키지 않는다.** "박스가 많다"는 지적에 전부 줄글로 가거나, "줄글이 좋다"에 전부 줄글로 가면 같은 실패다 — 실제로 4구간 표본에서 8장 전부 박스 → 3장 전부 줄글로 두 번 연속 넘어갔다. 판정은 **슬라이드마다** 한다.
- **인접 청크는 본문이 아니라 멘트·노트로 라우팅한다** — `범위:인접` 청크(리서치 G9)의 내용은 `슬라이드 제목`·`본문 문구`에 쓰지 않는다. 학생 화면에 올릴 재료가 아니라 **학생이 그 개념을 배운 직후 물었을 때 강사가 꺼낼 답**이므로, 관련 슬라이드 행의 `비유·멘트` 셀에 `🗣`(막힐 때·질문받을 때 꺼낼 답) 형태로 적어 발표자 노트로 흘려보낸다. 인접 청크 때문에 슬라이드를 새로 만들지 않는다.
  - **커리큘럼 흐름을 인접 개념으로 밀어내지 않는다** — 인접 개념이 흥미롭다고 본문 자리를 내주면, 스토리라인이 확정한 학습 순서가 커리큘럼 밖 곁가지에 밀린다. 인접 개념이 본문에 꼭 필요해 보이면 임의로 승격하지 말고 **집필노트의 검토 포인트에 별도 제안으로 남긴다**(범위 확대는 커리큘럼·총괄 결정 사항이다).
- **행마다 refs 주석을 그 자리에서 단다** — 그 행을 쓰며 회수한 청크 슬러그를 행 말미에 `<!-- refs: C-… -->`로 남긴다(형식·위치는 "산출물 규격 → `N주차_초안.md`"). 집필이 끝난 뒤 되짚으면 어느 청크를 봤는지 복원하기 어렵고, 하류(덱)가 그 행의 근거를 찾을 통로가 사라진다.
- **확정사항을 존중한다** — 스토리라인·리서치 인수인계서에 이미 확정된 사항은 임의로 뒤집지 않는다. 더 나은 대안이 떠올라도 기존안을 지우지 말고 별도 제안으로 표시한다(집필노트에 남긴다).

### 6. 출처 추적표
집필과 병행해 슬라이드# ↔ 리서치 항목·출처를 매핑하는 표를 만든다.
- **사실을 담은 슬라이드는 전수 매핑** — 어느 리서치 파일의 어느 항목(교시·항목명 또는 소제목)에서 왔는지 적는다.
- **`[C-슬러그]` 열을 따로 둔다** — 개념KB 청크에서 회수한 재료는 그 청크 슬러그를 적는다(복수면 콤마). 이 열의 값은 초안 그 행의 `<!-- refs: … -->` 주석과 **같아야 한다** — 어긋나면 린트 실패다(7단계).
- 이 표가 나중에 §0-2("사실은 근거만")를 스스로 증명하는 자료가 된다 — 표에 없는 사실 문장이 있으면 그 자체로 린트 실패다(7단계).

**판단 기록 5분류 (R-JUDGE-01 · 2026-07-29 신설 — 기존 `사실/창작` 2분류를 대체)**

리서치 결과를 슬라이드로 옮기는 일은 옮겨 적기가 아니라 **판단의 연속**이다. 무엇을 고르고, 무엇을 빼고, 어떻게 묶고, 어떤 축으로 가를지를 정한다. 2분류는 이 판단들을 담을 칸이 없어서 **재구성이 통째로 추적 밖**에 있었다.

| 부호 | 무엇인가 | 자유도 | **기록 위치** | 검증 | 틀렸을 때 되돌아갈 곳 |
|---|---|---|---|---|---|
| **F** | **사실** — 정의·수치·제품 동작·인용 | 없음 | 추적표 **슬라이드 행** (`[C-슬러그]`·`[S-###]` 필수) | 리서치 게이트(G1~G9) | `/리서치` |
| **S** | **선택·생략** — 어느 사실을 쓰고 **무엇을 뺐는지** | 높음 | **「재료 처분표」** (추적표에 중복 금지) | 회수한 청크와 전수 대조 | 집필 단계 |
| **D1** | **재배열** — 여러 사실의 묶음·순서 바꾸기 | 높음 | 추적표 **슬라이드 행** (원 청크만 표기) | 원문 역대조로 충분 | 집필 단계 |
| **D2** | **신규 명제** — 분류 기준 생성·축 설계·인과 도출 | 있음 | 추적표 **별도 행** + 도출 근거 한 줄 | **F와 같은 강도** — 원 사실에 없던 주장이다 | 근거 없으면 `/리서치` |
| **E·V** | **표현·시각** — 문장·비유·예시·강조·배치 | **완전 자유** | 추적표 슬라이드 행(근거 불필요) | 불필요 | 없음 |

> 기록 위치를 나눈 이유는 **중복을 없애기 위해서**다. 같은 생략을 추적표와 처분표 양쪽에 적으면 한쪽만 고쳐질 때 조용히 어긋난다. 부호 체계는 하나고, 사는 곳만 둘이다.

- **S(생략)가 이 분류의 핵심이다.** 추가는 눈에 띄지만 생략은 안 띈다. 기존 표는 **쓴 것만** 검사하고 안 쓴 것은 검사하지 않았다 — 2026-07-28에 `[C-하네스구성요소]`의 유보가 화면에서 사라진 것이 그 결과다. **생략은 기록하지 않으면 검출되지 않는다.**
- **D2를 D1이나 E·V로 적지 않는다.** 「되돌릴 수 있나 / 바로 알아채나」 두 축으로 항목을 가르는 것은 재배열도 창작도 아니라 **새 주장**이다. 원 청크에 그 기준이 없으면 근거를 대거나 `/리서치`로 돌아간다.
- **E·V는 자유다.** 표현을 다듬는 데 근거를 요구하면 기록이 형식화되고, 정작 F·S·D2가 묻힌다. **자유를 늘리는 것과 검증을 약화하는 것은 다르다.**
- `필수 진술`(개념KB)에 해당하는 내용을 뺐다면 그것은 S가 아니라 **위반**이다 — 표현만 바꿔 화면에 남긴다.

### 7. 자기검증 린트
산출 전에 스스로 점검한다(체크리스트는 "자기검증 체크리스트" 참조):
- 형식(4열·아이콘 범례·0번 메타·고정 슬라이드 신호·`(선택)` 태그)이 템플릿과 어긋나지 않는가.
- 무근거 사실이 0건인가 — 출처 추적표와 대조.
- 완성 프롬프트가 `본문 문구`에 노출된 곳이 0건인가 — 전부 `🗣`인가.
- 관통 문장이 교시마다 존재하는가(직접 등장 또는 은근한 변주).
- 장수가 프로필 §2의 회차당 장수 범위 대비 크게 벗어나지 않았는가, 벗어났다면 사유가 집필노트에 있는가.

## 산출물 규격

### `sessions/N주차/N주차_초안.md`
`입력양식/콘텐츠초안템플릿.md`이 구조의 정본이다 — 이 스킬은 그 템플릿을 채워 넣을 뿐 형식을 바꾸지 않는다. 최소 구성:
- 메타 헤더(작성=콘텐츠 스킬·작성일·기준 문서·대상 수강생) — `입력양식/콘텐츠초안템플릿.md`의 0번 메타 구조를 따른다.
- "읽고 시작해" 아이콘 범례 서두.
- `0. 덱 기본 정보` 표(팀명 없이) + 파트 구조 표는 기본 공란(§0-1).
- 교시(또는 도입부·마무리)별 4열 표.

**refs 주석 (근거 추적 메타데이터).** 사실 근거가 있는 행은 **그 행의 마지막 셀(`비유·멘트`) 맨 끝**, 셀을 닫는 `|` 바로 앞에 `<!-- refs: C-슬러그1,C-슬러그2 -->`를 붙인다. 열은 4열 그대로이며 새 열을 만들지 않는다.

```
| 3-7 | 실습 ③ 첫 파일 만들기 | Codex에게 **첫 파일 하나를 만들어 달라**고 요청합니다. | 🗣 요청문: "…" <!-- refs: C-파일,C-요청문 --> |
| 3-9 | 허용창이 뜨면?      | 연습 폴더 안 작업 → **확인하고 진행**            | <!-- refs: C-승인창 -->                        |
```

- **왜 마지막 셀인가**: 행 전체의 근거이지 특정 문장의 각주가 아니고, 화면 문장이 담기는 `본문 문구` 셀을 건드리지 않으며, 뒤에 셀이 더 없어 표 파싱을 흔들 여지가 가장 작다. 행당 **한 개**만 두고 여러 셀에 나눠 붙이지 않는다.
- **파싱 제약**: 주석 안에 `|`(표 구분자)·줄바꿈을 넣지 않는다. 슬러그는 콤마로만 구분하고 대괄호 없이 `C-…` 형태로 적는다(회수는 `rg "C-슬러그"`로 한다).
- **의미**: 화면에 표시되지 않는 **근거 추적용 메타데이터**다. 하류(`/create-slides`)가 비교표·워크드예시·PPT 소재 같은 시각자료 소재를 만들 때 개념KB에서 **그 청크만** 집어 읽는 통로가 된다. 콘텐츠 소유권 경계가 보호하는 "무단 재작성 금지" 대상 문장이 아니므로 하류가 지우거나 갱신해도 콘텐츠 훼손이 아니다(`references/콘텐츠초안-입력형식.md` §2).
- **생략 가능**: 근거 청크가 없는 행(전환 문구·인사말·`(간지)`·`(표지)`·`(마무리)`·순수 창작 비유)은 붙이지 않는다. 주석이 하나도 없는 초안도 유효하다 — 사람이 직접 쓴 초안과 완전히 호환된다.

### `sessions/N주차/자료/N주차_콘텐츠_집필노트.md`
스킬이 아닌 사람(검토·조립 담당)이 바로 참고할 수 있는 Markdown 문서로 만든다.
1. **출처 추적표** — `슬라이드# | 슬라이드 제목 | 판단 | 근거(파일·항목) | [C-슬러그] | 비고` 열. `판단` 열은 **5분류 부호**를 적는다(R-JUDGE-01, 6단계). `[C-슬러그]` 열에는 개념KB에서 회수한 청크 슬러그를 적고(복수면 콤마·`E·V` 단독이면 `—`), 초안 그 행의 `<!-- refs: … -->` 주석과 값을 일치시킨다.

   **행을 나누는 규칙** — 부호를 한 행에 콤마로 뭉치면 **어느 내용이 D2인지 특정되지 않는다.** 그래서 셋을 갈라 적는다.

   | 무엇 | 어디에 | 행 모양 |
   |---|---|---|
   | `F`·`D1`·`E·V` | 출처 추적표의 **슬라이드 행** | 슬라이드당 1행. 부호 여럿이면 콤마 |
   | **`D2`** | 출처 추적표의 **별도 행** | 슬라이드# 칸에 적용된 슬라이드(복수면 콤마) · `판단`=`D2` · **비고에 도출 근거 한 줄** |
   | **`S`** | **「재료 처분표」**(아래 5번) | 출처 추적표에 적지 않는다 |

   - **`D2`를 별도 행으로 두는 이유**: 분류 기준·축 설계·인과 도출은 원 사실에 없던 **새 주장**이라 F와 같은 강도로 검증해야 하는데, 슬라이드 행에 묻히면 검증 대상인지 아무도 모른다. 별도 행이면 `판단` 열로 전수 회수된다(`rg "\| D2 \|"`).
   - **도출 근거를 못 적으면 그 행은 D2가 아니라 무근거 주장이다.** 어느 사실들에서 그 기준을 끌어냈는지 적을 수 없으면 근거를 대거나 `/리서치`로 돌아간다.
2. **분할 제안** — `슬라이드# | 사유(수용량 초과 근거) | 제안(어떻게 나누면 좋을지)`.
3. **`[자료 부족]` 목록** — 게이트A에서 부족 판정된 교시·슬라이드와, 승인 하에 부분 집필한 경우 어느 부분이 비어 있는지.
4. **검토 포인트** — 별도 제안으로 남긴 항목, 톤·수치가 불확실해 사람 확인이 필요한 부분.
5. **「재료 처분표」(필수 · 옛 「PPT 소재 처분표」를 2026-07-29에 확장·개명)** — `재료 | 출처 청크 | 등급 | 처분 | 사유 | 실현 위치(슬라이드#)` 열.

   회수한 청크에서 **화면에 올릴 수 있었던 재료를 전부** 한 행씩 적고 처분을 남긴다. 옛 판은 `PPT 소재:`만 다뤘으나, 그러면 본문 내용의 생략이 어느 표에도 안 남는다.

   | 등급 | 무엇 | 처분 |
   |---|---|---|
   | **필수** | 청크의 `필수 진술:` | 사용 / 대체만 가능 — **보류 불가.** 표현은 바꿔도 뜻이 화면에 남아야 하고, 실현 슬라이드# 없이 "대체"로 적을 수 없다 |
   | **제안** | 청크의 `PPT 소재:` | 사용 / 대체 / 보류 모두 가능(대체·보류는 사유 필수) |
   | **일반** | 청크 본문에서 화면에 올릴 수 있었으나 **안 올린** 내용 단위 | 보류 + 사유 |

   - **판단 5분류의 `S`(선택·생략)는 이 표에만 기록한다** — 출처 추적표에 중복해서 적지 않는다. 두 곳에 적으면 한쪽만 고쳐질 때 조용히 어긋난다.
   - 이 표가 없으면 재료가 조용히 누락돼도 아무도 모른다 — 2026-07-28에 `[C-하네스구성요소]`의 유보("이 목록은 확정된 표준이 아닙니다")가 완성 슬라이드에서 사라졌고 기록이 없어 사후 추적조차 불가능했다. **현 파이프라인은 「쓴 것」만 검사하고 「뺀 것」은 검사하지 않으며, 이 표가 유일한 생략 검사기다.** (`scripts/verify_draft_quality.py` R-QD-05가 섹션 존재를 확인한다 — 옛 이름도 통과)

### `sessions/N주차/N주차_콘텐츠_리뷰.html`
`sessions/_template/콘텐츠_리뷰.html`을 복제해 슬라이드 미리보기·정보 단위 배지로 채운 **사람 확인용 자립형 HTML**이다(필수). 외부 스타일시트·스크립트·이미지를 불러오지 않고 인라인 CSS/JS만으로 동작해야 한다(`grep -nE "https?://|src=|<link"` 결과가 0이어야 함). 슬라이드(표 1행)마다 카드 1개, `data-info-units` 값에 그 슬라이드의 정보 단위 수(§0-6)를 채워 근-빈 슬라이드(단위 ≤1)가 요약 바에 드러나게 한다.

## 자기검증 체크리스트

- [ ] 형식: 4열 표(`#`·`슬라이드 제목`·`본문 문구`·`비유·멘트`) + 아이콘 범례 서두 + `0번` 덱 메타(팀명 없음) + `(간지)`·`(표지)`·`(마무리)` 신호 + `(선택)` 태그가 템플릿과 일치.
- [ ] 무근거 사실 0건 — 모든 사실 문장이 출처 추적표에 매핑됨.
- [ ] 출처 추적표의 `판단` 열이 5분류 부호로 채워졌는가(R-JUDGE-01).
- [ ] `D2`(분류 기준·축 설계·인과 도출)가 **별도 행**으로 분리됐고 행마다 비고에 도출 근거가 한 줄 있는가 — 없으면 무근거 주장이다. 회수 명령: `rg "\| D2 \|" 집필노트`.
- [ ] 생략(`S`)이 **「재료 처분표」에만** 기록됐는가(추적표 중복 없음) — **보류 행이 하나도 없다면 정말 아무것도 안 뺀 것인지** 회수한 청크와 대조해 확인했는가.
- [ ] 개념KB `필수 진술:` 항목이 전부 화면에 남았는가 — 표현은 바꿔도 되지만 **보류는 불가능**하다(처분표에 보류 행이 있으면 위반).
- [ ] 사실 근거가 있는 행에 `<!-- refs: C-… -->` 주석이 마지막 셀 끝에 있고, 값이 출처 추적표 `[C-슬러그]` 열과 일치하는가 — 주석 안에 `|`가 섞여 표 파싱을 깨지 않는가.
- [ ] 개념KB를 통독하지 않고 「청크 인덱스」 표 + 필요한 청크 grep 회수로만 읽었는가.
- [ ] `범위:인접` 청크의 내용이 `슬라이드 제목`·`본문 문구`에 섞이지 않았는가 — 전부 `🗣` 멘트·발표자 노트로만 갔는가, 인접 개념 때문에 새 본문 슬라이드가 생기지 않았는가(게이트A의 "사실 근거"도 코어 청크만으로 셌는가).
- [ ] 실습 완성 프롬프트가 `본문 문구`에 노출된 곳 0건 — 전부 `🗣`로만 존재.
- [ ] 프로필 §1의 관통 문장이 회차마다 존재(직접 등장 또는 은근한 변주). 프로필에 없으면 해당 없음.
- [ ] 장수가 프로필 §2 회차당 장수 범위 대비 크게 벗어나지 않음, 벗어났다면 사유 기록 — 시간예산 역산으로 장수를 정하지 않았는가(§0-7 R-PLAN-01).
- [ ] 노트가 화면 본문의 이주처가 되지 않았는가 — 주장은 화면에 있고, 비유·근거·예시 중 최소 하나는 화면에 남았는가(§0-6 R-DENS-02).
- [ ] 예시·근거·주의점을 부록·예비 구획으로 강등하지 않았는가 — 강등은 심화(더 깊은 원리·확장 논의)만 가능하다(§0-8 R-ANNEX-01).
- [ ] 개념설명 슬라이드가 핵심 주장/정의는 반드시 담고, 목적에 필요한 요소만 골라 더했는가 — 모든 요소를 기계적으로 채우지 않았는가(§0-9 R-COMP-01).
- [ ] 서로 다른 개념을 편의상 합치지 않았는가, 비유를 쓴 뒤 개념 정의로 돌아왔고 필요하면 비유의 한계를 표시했는가(§0-10 R-ACC-01).
- [ ] 회수한 재료(`PPT 소재:`·`필수 진술:`·화면에 올릴 수 있었던 본문 내용)를 전량 집필노트의 「재료 처분표」에 등급·처분으로 기록했는가.
- [ ] 비유·사례 밀도 교시당 2개 이상.
- [ ] 슬라이드당 정보 단위 3~6개(§0-6)를 충족하고 근-빈 슬라이드(단위 ≤1)가 없는가 — 리뷰 HTML의 `data-info-units`로 확인. **화면 조작 안내 슬라이드는 제외**(§0-6 예외 — 한 슬라이드 = 조작 단계 1개).
- [ ] 화면 조작 안내가 한 슬라이드에 여러 단계를 묶고 있지 않은가(기준안 §6 원칙 9).
- [ ] 확정 사항을 삭제하지 않고, 대안은 별도 제안으로만 표시.
- [ ] 사람 확인용 `N주차_콘텐츠_리뷰.html`을 산출했는가(정보 단위 배지 포함).

- **입력(앞 단계)**: `/리서치`가 만든 `sessions/N주차/자료/` **기본 5파일**(콘텐츠리서치 결과·개념KB·출처레지스트리·실습안 검증결과·결정요청사항) + 같은 폴더의 사람 작성 자료. 파일명이 아니라 내용으로 식별한다(read-path 6번). **사실의 정본은 개념KB 청크**이고 결과.md는 그 포인터를 가진 구간 인덱스층이며, 개념KB는 「청크 인덱스」 표로 진입해 필요한 청크만 회수한다(전문 Read 금지).

- **사람/AI 호환 원칙**: 같은 스키마(`입력양식/콘텐츠초안템플릿.md`)를 지키면 사람이 쓴 초안과 이 스킬이 쓴 초안은 완전히 호환된다. 다음 단계는 파일의 작성 주체가 아니라 내용·스키마로 입력을 인식한다(`skills/README.md`). 이 원칙을 지키려면 형식을 스킬 임의로 확장·축소하지 않는다.
