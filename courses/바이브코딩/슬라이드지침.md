## 1. 대상 — **혼합군**이 축이다

커리큘럼 정본 §4.1이 규정한 넷:

- 20대부터 60대까지의 다양한 연령대
- 코딩을 처음 접하는 입문자와 디지털 도구 경험이 서로 다른 수강생
- 대학생·일반인·대학 및 교육기관 관계자·교육자·연구자·기업·기관 종사자 등이 함께하는 혼합군
- 학업·교육·연구·업무·개인 활동 등 활용 목적이 다양한 수강생

### 쓸 표현

| 용도 | 표현 |
|---|---|
| **정식형** — 계약값·메타 헤더·산출물 머리말 | `코딩 경험이 없는 입문자 중심의 혼합군(연령·경험 수준 다양)` |
| **축약형** — 서술 문장·description | `코딩 경험이 없는 입문자 중심의 혼합군` |
| **최소형** — 슬라이드 화면 문구처럼 길이가 빠듯한 곳 | `입문자 중심의 혼합군` |

세 형태 모두 **`혼합군`을 반드시 포함한다.** 그게 이 정의의 핵심이다.

### ⚠️ 쓰지 말 것

- **정본보다 좁은 연령 표현** — `40~50대`·`중장년`·`2030` 등. 정본은 20대부터 60대까지를 명시하므로 그보다 좁혀 쓰지 않는다. 표기의 축은 연령이 아니라 혼합군이다.
- **`코딩 경험이 없는 입문자` 단독** — "혼합군"이 빠져 **경험 축 하드코딩**이 된다. 연령 하드코딩을 경험 하드코딩으로 바꾸는 것일 뿐이라 같은 오류다.

### 가독성 하한의 근거

본문 22px·표 17px·코드 20px 하한과 고대비는 유지한다. 근거는 연령이 아니라 둘이다 — ① 정본 §4.1의 "디지털 도구 경험이 서로 다른 수강생"과 "20대부터 60대까지" ② 강의장 뒷자리 판독(프로젝터·거리).

> 이 수치는 아직 **실측 확정 전**이다(`kit/guide/디자인시스템.md` 참조).

## 2. 범위 — 이 밖의 것을 슬라이드에 가르치지 않는다

**포함(§5.1)**: ChatGPT 데스크톱 앱과 Codex · 자연어 제작 요청 · 로컬 폴더/파일 확인 · **HTML·CSS·JavaScript** 기반 간단한 웹 결과물 · 브라우저에서 실행되는 한 페이지 또는 소규모 서비스 · 요청문 작성과 수정 요청 · 기획 문서 `prd.md` · 화면 구성과 디자인 방향 · 핵심 기능 하나가 작동하는 MVP · 브라우저 로컬 저장 · 사용성 점검 · **Netlify** 정적 사이트 공개 · 피드백 반영과 재배포 · URL·QR 공유와 발표

**제외(§5.2 · 16항 전량)**: 서버 구축 · 데이터베이스 · 로그인/회원가입 · 결제 · 서버 API 연결 · **AI API 연결** · **React 등 프레임워크** · **패키지 설치와 빌드 과정** · **터미널 명령어 실습** · 별도 코드 편집기 설치·사용 교육 · 상용 서비스 수준 보안·인프라 · **Git·GitHub** · 여러 배포 도구 비교 실습 · **별도 정상본·ZIP·복구 패키지 제공** · **별도 기기·노트북 폴백** · **별도 빠른 트랙**

> 제외 기술은 "질문이나 범위 설명에 필요한 경우 한두 문장" 수준으로만 언급할 수 있다(§5.2 말미). 실습·예시·코드 견본으로 등장시키지 않는다.

**코드 예시를 만들 때**: 언어는 HTML·CSS·JavaScript뿐이다. 배포 도구는 Netlify 하나다. AI 도구는 ChatGPT 데스크톱 앱의 Codex다. 다른 언어·프레임워크·배포처·AI 도구를 견본에 넣지 않는다.

## 3. 이 과목의 슬라이드 구조 관례

### 관통 문장 (원칙 6)

**"AI가 작성하고, 사람이 검토하고, 사람이 결정한다."** 회차마다 직접 등장 또는 은근한 변주로 반복한다. 3주차에는 "사람이 공개를 결정하며, 공개의 책임도 사람이 진다"로 확장된다.

### 수정 요청은 3단 구조 (원칙 5)

**무엇을 유지할지 → 무엇을 바꿀지 → 바뀐 뒤 무엇을 확인할지.** 수정 관련 슬라이드는 이 순서를 따른다.

### 오류는 4단 구조로 (원칙 7)

**어디에서 → 무엇을 했는데 → 실제로 어떻게 됐고 → 원래 무엇을 기대했는지.** 버그 사냥이 아니라 협업 과정으로 다룬다.

### 문법보다 경험, 개념은 필요한 순간에 (원칙 1·3)

코드 문법을 가르치지 않는다. 코드 설명은 결과물을 이해하는 데 필요한 수준으로 제한하고, 개념은 그것이 실제로 필요해지는 지점에서 꺼낸다.

## 4. 이 과목에서 확정된 화면 판단

`profile.md` §4가 정본이며 여기서는 적용 방법만 적는다.

- **레이아웃 동점 시**: ① 차트·다이어그램 주도 → ② 글 + 여백 → ③ 카드. 합격선 예시는 1주차 덱 17·37번이다 — **실제로 열어 보고 맞춘다.**
- **출처는 화면에 표시하지 않는다.** 근거 확인은 정확한 내용을 넣기 위한 절차이지 표시용이 아니다.
- **슬라이드 제목은 직관적으로** — 그 장이 무엇을 다루는지 제목만 보고 알 수 있게. 과목 무관 원리라 킷으로 승격됐다(`kit/guide/교육원칙-요약.md` §3-B). 이전 판의 "서술형 금지"는 2026-07-31 실측(합격 덱 제목의 61%가 서술형)으로 폐기됐다.
- **전부 박스도, 전부 줄글도 같은 실패다.** 판정은 슬라이드마다 한다(R-FORM-01).
