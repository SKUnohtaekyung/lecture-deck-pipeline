## 0. 사실과 판단의 분리 (요약)

### 확인된 사실 (파일·공식 출처로 직접 확인)
- 현 초안은 54장, 6교시, 실습 5장(각 교시 **끝**에 1장씩: 1-9·2-9·3-8·4-8·5-10). 전 페이지 `visual_structure=1`로 자기평가돼 있음(초안 풍부도 표).
- 1주차 강의덱은 75장. **실습(X00~X02)이 덱 맨 끝에 몰려 있음**(설명→준비연습→후반 연속 프로젝트). → 사용자 §4의 "실습 후반집중 반복 금지"는 근거 있음.
- 1주차 PART3는 **개념 1장 압축 + 적용 여러 장 분산**, 로드맵(S3MAP)·반례 예방접종(S3PE→S3LM→S3CE)·문제→대응 분리(S3SY→S3SYP)·콜백(해줘./해.)·정직성 경계·기대먼저-점검(31→S39)을 씀.
- **3주차 전용 설계 문서는 없음.** 3주차 근거는 커리큘럼 §10(그마저 `[잠정]`)뿐. 3주차 소유 = 저장·배포·공개 URL·피드백·재배포·발표.
- 개념KB 55청크에 **사용자가설·대표사용흐름·prd·전문PRD·AGENTS문서·디자인시스템토큰**은 있으나 **페르소나·IA·User Flow(별도)·리팩터링·MEMORY.md·CLAUDE.md 전용 청크는 없음.**
- 웹검증(공식): PRD는 조직마다 형식 다름(단일 표준 없음, Atlassian·Wikipedia) · PRD(개념) vs prd.md(스펙주도개발 구현) 구분 타당(GitHub spec-kit) · MVP "조악한 게 아님"(Eric Ries 원문) · 디자인 시스템 ⊃ 스타일가이드(NN/g) · 페르소나=proto-persona=검증 전 가정(NN/g) · 리팩터링=동작불변 구조개선(Fowler) · LLM 공감="공감하는 듯하나 정서 경험 없음"(JMIR 리뷰).

### 근거 기반 판단
- 현 초안은 **사실은 정확하고 구조는 깨끗하나, 교육학적으로 평탄하다** — 개념 단계화 얕음, 실습 후반집중, 도구(ChatGPT/Codex) 역할 미분화, 강사 확장 근거(멘트) 빈약. → **최소 수정이 아니라 재구조화가 타당.**
- 단, 재구조화의 방향은 "사용자가 나열한 개념을 다 넣기"가 **아니다.** 1주차 PART3의 단계화 규율 + 실습 교차 + 도구 분담 + 강사 근거 강화를 적용하되 **과부하 개념은 흡수·강등·기각**한다.

### 잠정 가설 (실측·운영 확인 필요)
- 6시간 배분(설명:실습:전환:휴식)의 정확한 분(分)은 정본에 없음 → 아래 §6은 근거 있는 추정.
- 교시당 마이크로 실습 반복 횟수(1~2회)의 현실성은 12명·보조강사 1명 운영 실측이 최종 확인.

### 사용자 결정 사항 (객관적 정답 없음 · 운영자 몫)
- 배포 예고 채널 문구: **Netlify vs ChatGPT Sites** (총괄 미확정 + Sites 개인 Plus 실현성 `[미확인]`).
- "사용자 관찰" 정의: 2주차 **자체 점검**만인지, 커리큘럼 §11의 "다른 사람 관찰"까지인지(양 문서 `[잠정]`).
- 재설계 강도/슬라이드 예산 상한(§6 권장안 채택 여부).

## 3. 재설계 원칙 (내부 확정)

1. **척추 = §3 9단계 흐름**을 6교시에 매핑: 불편/필요 발견 → 대상 좁히기 → 최소 기능 → AI 기획 초안 → 인간 판단·수정 → 문서로 맥락 고정 → 파일·폴더 구성 → 작은 기능 구현 → 확인·재수정.
2. **실습 교차(교시1부터).** 각 교시 = 짧은 개념(단계화) → 개인 판단 → (ChatGPT 대화 또는 Codex 구현) → 브라우저·문서 확인 → 다시 판단, **손에 남는 산출물** 1개. 교시 끝 단일 실습이 아니라 1~2회 마이크로 루프.
3. **1주차 PART3 패턴 이식(§11).** 교시별 로드맵 · 짝개념 동일 레이아웃 · 반례 예방접종 · 문제→대응 분리 · 콜백 · 기대먼저-점검 · 정직성 경계 · 밀도 변주.
4. **도구 역할 분담.** ChatGPT=아이디어·가설·MVP 축소·PRD 초안·비판·레퍼런스 분석 / Codex=폴더·파일·구현·오류·수정. "기본 구분"(절대 아님), 외부 도구 추가 없음.
5. **개념 규율(과부하 방지, §4).** 핵심만 단계화, 나머지 흡수·맛보기·노트.
6. **사실 우선.** PRD vs prd.md 명시 · AI=가설 · "최소 문서→갱신"(길게 아님) · 단일 진실원.
7. **3주차 침범 금지.** 자체 점검 + 저장 대상 "정의"까지. 저장 구현·배포·공개 URL·발표는 3주차.
8. **경계 플래그.** 배포 채널·"사용자 관찰" 정의는 총괄/사용자 결정(§10).

## 4. 개념 3단계 분류

## 5. 교시별 Before → After

> 각 교시: **기존 / 재설계 / 핵심 변화 / 산출물.** 로드맵 = 교시 도입 어드밴스 오거나이저(PART3 S3MAP 패턴).

### 1교시 — 아이디어를 사용자 가설로 (기존 1-1~1-9 · 9장)
- **기존:** 가설·한줄정의·일상발굴·기술경계·안전·앵커·실습①(끝). 대부분 선언형, 실습 1회(끝).
- **재설계:** 지난주 콜백(요청·확인·수정 재사용) → [로드맵: 오늘의 5단계] → **사용자 가설**(타깃·페인포인트·페르소나 흡수 / "AI는 공감하는 듯하나 경험 안 함 → 내 느낌도 가설, 검증은 나") → **[실습A: 내 불편·필요 1개 → `idea.md` 한 문장]** → 한 줄 정의 템플릿 → **주제 선정 8기준 + 유형별 후보**(기록/계산/변환/선택추천/타이머/비교/체크리스트/불편해결) → 안전·기술경계(반례: 서버 필요 아이디어를 정적으로 축소) → **[실습B: 한 줄 정의 확정 + 새 폴더 생성(Codex)]**.
- **핵심 변화:** 실습 2회(초반+말) · 페르소나/페인포인트를 가설로 흡수 · 주제 선정 기준 강화 · 공감/가설 정확 프레이밍.
- **산출물:** `idea.md`(한 줄 정의) + 새 프로젝트 폴더.

### 2교시 — 최소 기능과 완료 모습 (기존 2-1~2-9 · 9장)
- **기존:** 결과/기능 구분·MVP·기능유형·범위·완료기준·실습②(끝).
- **재설계:** [로드맵] → 핵심 결과 vs 핵심 기능(대조) → **MVP**(정직성 경계: "대충 아님" · Ries) → **[실습: 결과 하나·기능 하나]** → 기능 유형 골격(입력1~3→결과1→외부 없음) → **범위 3칸**(반례: 기능 다섯 개면 결과 다섯 배? → 아무것도 안 끝남) → 완료 기준(good/bad, 눈으로 확인) → **[실습: prd 재료 = 결과·기능·흐름·범위·완료 각 한 줄]**.
- **핵심 변화:** 문제→대응(범위 팽창) 명시 · MVP 정직성 경계 · 실습이 prd 재료로 이어짐.
- **산출물:** MVP 정의 카드(= 3교시 prd 입력).

### 3교시 — 결정을 prd.md로 고정 (기존 3-1~3-8 · 8장)
- **기존:** 대화vs문서·prd.md·Markdown·맥락·PlanFirst·문서우선변경·실습③(끝).
- **재설계:** [로드맵] → **콜백(1주차 컨텍스트·중간 유실)** → 대화(흐름) vs 문서(보존) → **PRD(개념: 조직마다 다름·회사는 30쪽) vs prd.md(우리 최소 5줄)** [신규·KB근거] → **각 항목이 왜 AI 결과를 바꾸나**(대상없음→흔들림 / 핵심기능없음→AI 임의확장 / 제외없음→커짐 / 완료없음→끝 모름) [신규] → Markdown 최소(맛보기) → **[실습: ChatGPT로 prd.md 초안 → 사람이 읽고 1개 수정 → Codex로 프로젝트에 저장]** → 문서 우선 변경 → **"최소→갱신, 길게 아님"**(오해 교정) + 단일 진실원.
- **핵심 변화:** PRD/prd.md 구분·"왜 항목이 결과를 바꾸나" 신설 · 도구 분담 첫 등장 · 과다문서 오해 교정.
- **산출물:** `prd.md`(검토·수정됨).

### 4교시 — 화면 흐름과 표현 기준 (기존 4-1~4-8 · 8장)
- **기존:** 정보순서·버튼문구·접근성·레퍼런스·design.md·실습④(끝).
- **재설계:** [로드맵] → 대표 흐름 → 화면 정보 순서 → 버튼·라벨·결과·오류 문구(good/bad) → 기본 접근성(색만으로 X) → **레퍼런스 = 복사 아님**(복사/분위기/구조/사용성/조합 구분 + "무엇은 안 따라 하나") → **디자인 시스템 초보 정의**(맛보기: "같은 제품처럼 보이게 하는 반복 규칙"; 예시 Material/Polaris/Laws of UX/Mobbin은 노트) → design.md(선택) → **[실습: 화면 순서 + 문구 3줄 (+선택 design.md)]**.
- **핵심 변화:** 레퍼런스 관찰 4구분 명시 · 디자인 시스템 경량 정의(기업급 아님).
- **산출물:** 화면 순서·문구 기준 (+선택 design.md).

### 5교시 — 분리 파일로 첫 작동 (기존 5-1~5-10 · 10장)
- **기존:** 계획재확인·세파일역할·상대경로·브라우저열기·기술제한·반복절차·한단계씩·입력실행결과·실습⑤(끝).
- **재설계:** [로드맵] → 계획 재확인(Plan First) → **단일 파일 → 다중 파일: 왜/어떻게**[강화](폴더·index/css/js·assets·문서 역할 + 상대경로 + **파일명 변경 시 깨짐** + 브라우저 직접 vs 서버 필요) → 기술 제한(module/fetch 금지 **이유**) → **[실습: Codex로 세 파일 생성 → 한 단계씩 구현 → 브라우저 확인]** → **마지막 작동 상태 보호**(첫 작동 직후 · D10 경량) → **리팩터링/중복 인지**(맛보기: 반복코드·긴파일·수정하니깨짐·AI중복 → 확인·요청법) → 반복절차/Skill(선택)+AGENTS.md(맛보기·D7).
- **핵심 변화:** 다중 파일 구조 본격화 · 리팩터링 인지 경량 추가 · 상태 보호 위치 확정.
- **산출물:** 작동하는 핵심 기능(세 파일).

### 6교시 — 확인·수정·3주차 인수 (기존 6-1~6-9 · 9장)
- **기존:** 시나리오점검·정상/다른값·5질문·prd대조·SelfReview·한문제수정·인수폴더·마무리.
- **재설계:** [로드맵] → **대표 시나리오 자체 점검(≠ 사용자 테스트)** → 정상값·다른값 → 5질문 체크 → prd 대조(제외가 몰래 들어왔나) → AI Self Review=보조 → **가장 중요한 한 문제 수정(유지→변경→확인)** → 재실행 → **복구 흐름**(수정하다 깨짐 → 마지막 작동 복원) → 3주차 인수 폴더 + **저장 대상 "정의"만**(구현 X) → 마무리 + **THANK YOU**[신설].
- **핵심 변화:** 복구 흐름 명시 · THANK YOU 신설 · 3주차 경계 재확인.
- **산출물:** 수정된 MVP + 인수 폴더 + 저장 대상 메모.

## 6. 슬라이드·시간 예산 (근거)

> **원칙: 장수는 시간에서 나온다.** 정본에 교시별 분 배정은 없음 → 아래는 6시간 전제의 근거 있는 추정.

- 360분 − 휴식 2×15 − 오프닝/셋업 15 − 마무리 10 ≈ **실질 305분 / 6교시 ≈ 50분/교시**.
- 교시 50분 = 개념·설명 ~22분 + 실습·판단 ~23분 + 전환·버퍼 ~5분 (2주차는 실습중심이라 실습 비중 ↑).
- 개념 22분 ÷ 1.5~2.5분/슬라이드(단계화 개념은 느림) ≈ 교시당 개념·전환 10~13장 + 실습 2~3장 + 로드맵 1장 ≈ **교시당 13~16장**.
- 6교시 ≈ 78~96 + 표지·간지·마무리 ~8.

**권장: ~80±6장(74~86).** 현 54장 대비 증가분은 전부 교육적 이유가 있다:

| 추가 유형 | 대략 | 이유 |
|---|---|---|
| 교시별 로드맵 | +6 | 어드밴스 오거나이저(PART3 S3MAP) |
| 교차 마이크로 실습 | +6~8 | 실습 초반화(§4) |
| PRD/prd.md + 왜-항목 | +2~3 | 개념 갭·사실 정확 |
| 도구 역할 분담 | +2 | 도구 실체 반영 |
| 다중 파일 구조 강화 | +3~4 | 2주차 신규 핵심 |
| 반례/문제→대응 | +4~6 | PART3 예방접종 |
| 기대먼저-점검 | +2~3 | 자체 점검 습관 |
| 디자인시스템·리팩터링(경량) | +2~3 | 경량 인지 |
| 복구·빠른/느린 분기 | +2~3 | 운영 안전 |
| THANK YOU | +1 | 덱 관례 |

**주의:** 이 범위는 상한이 아니라 근거 추정이다. **75를 넘겨야 한다는 목표는 기각**했다(§2). 최종 장수는 마이크로 실습·체크포인트를 몇 개 두느냐로 정해지며, 장마다 이유가 있어야 한다.

## 11. PART3에서 차용한 교육 패턴

1. 개념 도입 직후 **로드맵 1장**(색 3그룹 청크화 + 다음 함정 키워드 예고).
