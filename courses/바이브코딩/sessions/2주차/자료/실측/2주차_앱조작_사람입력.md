## 이 파일은 무엇인가

리서치 스킬은 ChatGPT 데스크톱 앱·Codex·Sites를 **실제로 조작할 수 없어** 아래 항목을 `[미확인]`·`[미검증]`으로 남겼다. 추측으로 채우면 현장에서 그대로 사고가 되므로 비워 두었다. **사람이 실제 앱에서 확인한 뒤 이 파일에 기록하면**, 그 내용이 `2주차_실습안_검증결과.md`와 `2주차_결정요청사항.md`의 빈칸을 대체한다.

기록 형식은 상세강의설계 §11.2 검증 기록 양식을 따른다. 확인한 항목은 `상태`를 `확인`으로 바꾸고 날짜·환경을 반드시 남긴다.

## A. P0 — 확인되지 않으면 2주차·3주차가 위험한 항목

### A1. 개인 Plus 계정에서 ChatGPT Sites 사용 가능 여부 `[미확인]`

- **왜 필요한가**: 3주차 공식 배포 경로가 Sites로 확정돼 있어, 개인 Plus에서 못 쓰면 3주차 설계가 흔들린다.
- **막힌 이유**: 공식 문서가 "Availability can depend on your plan, region, and workspace settings"로만 서술하고(S-751), help.openai.com 원문은 403 봇차단이었다.
- **확인 방법**: 개인 Plus 계정으로 로그인 → Sites 진입 경로가 보이는지 → 새 사이트 생성이 되는지.

| 확인할 것 | 상태 | 결과 기록 |
|---|---|---|
| Sites 진입 경로가 화면에 보이는가 | `[미확인]` | |
| 새 사이트 생성이 가능한가 | `[미확인]` | |
| 베타 사용량 제한 문구가 뜨는가 | `[미확인]` | |
| 진입 경로(메뉴 이름·위치) | `[미확인]` | |

### A2. 개인(비워크스페이스) 계정의 공개 배포·공유 경로 `[미확인]`

- **왜 필요한가**: 3주차 공유 활동 설계의 전제.
- **막힌 이유**: 공식 서술이 워크스페이스(Work) 기준에 치우쳐 개인 계정 경로가 불명확.

| 확인할 것 | 상태 | 결과 기록 |
|---|---|---|
| 공개 범위 선택지에 "인터넷의 누구나"가 있는가 | `[미확인]` | |
| 생성되는 공개 URL 형태 | `[미확인]` | |
| 배포 후 수정 → 재배포 절차의 단계 수 | `[미확인]` | |

### A3. 2주차 프로젝트 폴더를 Sites로 연결 가능한지 `[미검증]`

- **왜 필요한가**: 2주차 산출물(루트 `index.html`+`style.css`+`script.js`)이 그대로 3주차로 인수되는지가 전체 서사의 연결 고리다.
- **참고**: 공식 문서에 "For an existing project, ask Sites to prepare and publish the current app"이 있으나 로컬 폴더 업로드 경로는 명시돼 있지 않다(S-751).

| 확인할 것 | 상태 | 결과 기록 |
|---|---|---|
| 로컬 폴더를 어떤 경로로 올리는가(끌어놓기·연결·재생성 중 무엇) | `[미검증]` | |
| 세 파일 구조가 그대로 유지되는가 | `[미검증]` | |
| 실패 시 증상과 최소 복구 | `[미검증]` | |
