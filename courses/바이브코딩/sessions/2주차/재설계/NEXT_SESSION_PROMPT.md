## 2. 이번 세션의 할 일 — 우선순위 순

### A. 필수 진술 보류 3건 해소 (가장 먼저 · 미해소 위반)

`필수 진술`은 표현을 바꿔도 되지만 **보류가 불가능**하다. 아래 3건이 화면에 없다.

## 3. 작업 규율 (예외 없음)

- **서브에이전트의 "완료" 보고를 파일 증거로 인정하지 마라.** 존재·크기·필수 섹션을 메인이 직접 확인한다.
  이 저장소에서 자기보고가 이미 세 번 틀렸다.
- **시각 판정은 메인이 직접 렌더링해서 본다.** 헤드리스 Chrome을 쓴다
  (Browser 패널은 화면에 표시돼 있지 않으면 캡처가 5초 타임아웃된다).
  `file://`로 열지 말고 `python -m http.server` 후 http로 연다.
- **슬라이드 표본 CSS에는 발표모드 해제 블록이 필요하다.** 없으면 `deck.css`가
  `.slide{display:none}`로 두어 전 장이 검은 사각형으로만 캡처된다.
- **파일 쓰기 전 대소문자 무시 이름 충돌을 검사한다.**
- **1주차는 읽기만 하고 수정하지 않는다**(동결·프로필 §7 면제 등재).
- **새 슬라이드는 결정표를 먼저 채운다** — 정보 모양 12종 판정 → 역인덱스(layouts·charts 둘 다)
  → 레이아웃과 element를 따로 선택 → 순서 판별(줄글/카드) → 강조 3종 의미 배정 → 직전과 다른
  구도·마무리. 원본 결정표 예시는 `reports/create-slides-quality/samples_v5A|v5B/DECISION.md`.
- **골격 중복은 class 이름이 아니라 DOM 구조로 확인한다.** 이름만 세면 쌍둥이를 놓친다(실제 발생).
- **강조를 얹는 것은 재설계가 아니다.** 재설계는 정보 모양 재판정부터 시작한다.
- **규칙을 많이 추가하는 것이 품질 향상이 아니다.** 형태·수치를 규칙으로 승격하지 마라(R-PROMO-01).

## 이 파일을 쓰는 이유

새 세션은 이 대화의 문맥을 갖지 않는다. 위 블록은 **읽을 순서 · 확정 사항 · 다음 할 일 · 작업 규율 · 검증 명령 · 손대면 안 되는 것**을 한 번에 넘겨 재탐색 비용을 줄인다. 특히 3번(작업 규율)은 이번 세션에서 실제로 겪은 실패에서 나온 것이라 빠뜨리면 같은 실수가 반복된다.
