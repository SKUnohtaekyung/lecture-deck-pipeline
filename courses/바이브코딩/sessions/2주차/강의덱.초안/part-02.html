MVP

MVP는 대충 만든 게 아닙니다

MVP (Minimum Viable Product)
가설을 확인하려고 범위를 의도적으로 줄여, 실제로 써 볼 수 있게 만든 첫 작동 버전입니다.

기능을 다 넣으면 무엇이 진짜 통했는지 알 수 없습니다 — 그래서 핵심 하나만 제대로 작동시켜 반응부터 확인합니다. 실험용 모형이 아니라, 작아도 실제로 쓸 수 있는 첫 버전입니다.

MVP (Minimum Viable Product)

위 — 틀린 방법

자동차를 만들려고 부품부터 내놓으면 사용자는 아무것도 못 합니다. 바퀴 2개, 프레임, 차체는 부분 완성일 뿐 가치가 아닙니다.

아래 — 맞는 방법

같은 목적(이동)을 위해 처음부터 쓸 수 있는 형태로 만듭니다.
스케이트보드 → 킥보드 → 자전거 → 오토바이 → 자동차
매 단계마다 사용자는 이동을 실제로 경험합니다.

결론

MVP는 가장 작은 기능이 아니라, 핵심 가치가 통하는지 가장 빨리 확인할 수 있는 최소한의 형태입니다.

User Flow란?

User Flow(사용자 흐름)는 사용자가 하나의 목표를 완료하기 위해 제품 안에서 밟는 화면과 행동의 순서를 나타낸 지도입니다.

우리 수업에서는 무엇을 입력·선택하고 → 어떤 버튼을 누르고 → 무엇을 보는지의 순서로 이 지도를 표현합니다.

잘못된 입력도 흐름의 일부

User Flow를 정의할 때 반드시 넣어야 하는 필수 요소는 아니지만, 실제로 화면을 만들다 보면 자주 부딪히는 상황입니다. 이런 상황을 다루는 것을 예외 처리(exception handling)라고 부르며, 내 기능에 해당할 때만 다룹니다.

상황잘못된 예잘된 예
빈 입력안 넣고 누르면 무엇이 문제인지 알 수 없습니다.안내 문구로 무엇을 넣을지 보여줍니다.
오류예상과 다른 값이 들어오면 결과가 깨집니다.오류 문구로 잘못된 점을 알려줍니다.
재시도 분기한 번 실패했다고 처음부터 다시 하면 사용자가 떠납니다.다시 시도할 길을 남겨둡니다.
중복 실행버튼을 두 번 누르면 같은 결과가 두 번 생길 수 있습니다.한 번 처리 중엔 버튼을 잠가 둡니다.
