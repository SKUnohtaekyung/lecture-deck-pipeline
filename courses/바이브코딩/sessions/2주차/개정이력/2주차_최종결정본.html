1.이 주차가 하는 일

한 줄 정의

관심사나 불편을 사용자 문제로 좁히고, AI와 한 장 기획서를 작성해 핵심 기능 하나가 작동하는 MVP를 만든다.

학생이 품고 가는 질문

내 아이디어를 AI가 이해하고 만들 수 있는 기획과 작동하는 서비스로 어떻게 바꿀까?

수업이 끝났을 때 학생의 손에 있는 것

한 문장

누구의 어떤 문제를 해결하는 서비스인지 말로 설명할 수 있다

기획 문서

prd.md — 만드는 내내 다시 읽는 기준 문서

작동하는 MVP

화면과 핵심 기능 하나가 실제로 돈다

작업 환경 파일

AI가 지킬 규칙 5개 · 완료 기준 3개를 담은 파일

관찰 기록

짝이 어디서 막혔는지 본 기록

수정 경험

가장 중요한 문제 하나를 골라 고친 경험

전 주차를 관통하는 한 문장

AI가 작성하고, 사람이 검토하고, 사람이 결정한다.
1주차의 「요청 → 확인 → 수정」 사이클은 재사용하되 다시 가르치지 않는다. 저장·배포·공개·발표는 3주차 몫이라 건드리지 않는다 — 2주차는 “무엇을 저장할지 정의”하는 데서 멈춘다.

배치의 핵심 세 가지

① 첫 작동을 3구간으로 앞당겼다 — 학생이 “되는 걸” 보는 시점이 수업 절반 전에 온다.
② 화면 기준을 구현 직전에 둔다 — 예전엔 화면(3구간)과 구현(5구간) 사이에 한 구간이 끼어 기준이 식었다. 지금은 정하자마자 쓴다.
③ 1~3구간은 기획, 4구간은 전환, 5구간이 메인 실습 — 5구간 90분은 전체의 27%로, 학생이 자기 서비스를 만드는 시간이 이 주차의 중심이다.

에이전트 vs 워크플로 카드 2장을 나란히 놓는 게 아니라 가운데 “제어권을 누가 갖나” 라벨을 붙인 연결선으로 관계를 드러낸다. 각 측 주장 최소 3개(제어·예측가능성·비용) + 아래 종합 한 줄
하네스 엔지니어링 연표 앞에 “왜 이걸 먼저 말하는가”라는 경고를 둔다. 2026-02 등장 → 04 정리 → 05 “합의 없음” 선언 → 06 최초 정의 시도. 저자·URL은 노트로
★ 규칙 vs 기술적 강제 정의 → 판단 기준 → 나쁜 예 / 좋은 예 3단. 공식 문서가 스스로 “컨텍스트일 뿐 강제가 아니다”라고 밝힌 문장 + 우리 저장소가 그 간극을 인정한 실제 사례. “부탁 메모 vs 잠금장치” 이미지는 장식이 아니라 개념의 핵심 대비
인간 승인·감독 값을 표로 나열하지 않고 색 분류 카드 + 판단 원칙 배너. 실제 승인 다이얼로그 스크린샷이 필요하다(공식 문서에 화면 인용이 없어 대체 불가 — 강사 준비 항목)
★ 서브·멀티에이전트와 한계 구조도는 번호+제목+설명문 3요소. 한계는 각 측 3개 주장 + 종합 한 줄. 실제로 3회 일어난 “완료 보고 실패” 사고 기록을 그대로 화면에 — 학생은 규칙을 설명하는 실패를 기억한다
대화로 하네스 만들기 순환 앞에 “왜 파일로 고정해야 하는가(대화만 하면 휘발된다)”를 두고, 7단계가 4→5→6구간과 겹쳐 보이게 배치. “사람이 검토한다” 단계를 시각적으로 강조
하네스 실습AI와 대화해 규칙을 만들고 파일로 고정하기FAST 12분 / NORMAL 18분

학생 안내문: “지금까지는 AI에게 하나씩 부탁했습니다. 이번에는 AI가 일하는 방식 자체를 먼저 정해 보겠습니다. 내 프로젝트를 AI가 살펴보게 하고, 앞으로 지킬 규칙과 ‘다 됐다’의 기준을 AI가 초안으로 써 주면, 여러분이 그걸 고쳐서 파일로 저장합니다. 그 파일이 다음 시간부터 계속 쓰입니다.”

형태
단일 에이전트에게 탐색자 → 기획자 → 구현자 → 검증자 역할을 순서대로 시킨다. 병렬 실행은 요구하지 않는다(추가 설치·유료 플랜·실험 기능 없이 12명 전원 동일 재현이 가능한 게 이 방식을 택한 이유)
요청문
1차(진단) “내 프로젝트 폴더를 먼저 읽고, 지금 어떤 파일이 있고 무엇이 부족한지 알려줘. 아직 코드는 고치지 마.”
2차(초안) “앞으로 지킬 규칙 5개와 ‘기능이 완성됐다’고 볼 확인 기준 3개를 초안으로 써 줘.”
3차(고정) “내가 고친 내용을 반영해서 AGENTS.md로 저장해 줘.”
4차(검증) “방금 만든 확인 기준으로 지금 화면을 점검하고 통과/실패를 항목별로 알려줘.”
필수 단계
학생이 초안을 직접 고치는 단계에 최소 4분. 여길 건너뛰면 실습의 학습 목표가 통째로 사라진다
완료 기준
① 규칙 파일이 실제로 저장돼 있다(학생이 파일을 열어 확인) ② 직접 고친 흔적이 최소 1군데 있다 ③ 완료 기준 1개로 실제 점검을 돌려 통과/실패를 말할 수 있다
흔한 오류
AI가 진단 없이 바로 코드를 고침 · 초안이 너무 추상적이라(“좋은 코드를 쓴다”) 점검 불가 · 저장했다고 했는데 파일이 실제로 없음 · 학생이 초안을 그대로 승인하고 넘어감(가장 흔하고, 학습 목표를 정면으로 놓침)
복구
“읽기만 하고 수정하지 마”를 첫 문장에 두고 재요청 · “이 기준으로 통과/실패를 판정할 수 있어?”로 되물어 구체화 · 파일 목록을 직접 확인하고 없으면 재저장(“만들었다”는 답을 증거로 인정하지 않는 습관을 여기서 가르친다) · 강사가 “이 규칙 중 하나는 우리 프로젝트에 안 맞습니다. 어느 걸까요?”로 개입
정답 파일
학생용 정답 파일은 만들지 않는다 — 프로젝트마다 규칙이 달라야 하는 것이 이 실습의 요지

실습 진행 방식 — 90분 단일 블록 2026-07-29 확정

이 구간의 실습은 쪼개지 않고 하나의 블록으로 돌린다. 학생은 계속 만들고 있고, 강사가 중간중간 짧게 끼어들어 필요한 정보를 준다. “90분 드릴 테니 알아서 하세요”가 아니고, 그렇다고 설명할 때마다 전원을 멈추지도 않는다.

② “지금 필요한 것”만 넣는다. 배경·연혁·비교는 발표자 노트나 FLEX로.
③ 말로 하고 넘기지 않는다. 놓친 학생이 따라올 수 있게 화면에 남긴다.

이 방식이 요구하는 슬라이드 유형 — 지금 덱에는 “설명”과 “실습 지시” 두 가지뿐이라 두 종류가 더 필요하다.

  • 상시 참조판 — 작업 내내 띄워두는 판. 완료 기준 3개 · 요청문 예시 · 막혔을 때 확인 순서. 이 구조의 핵심 장치다. 끼어들기를 놓친 학생도 이걸 보고 따라오고, 강사가 순회하며 가리킬 수 있다.
  • 정렬 슬라이드 — “여기까지 됐나” 체크 항목. 전원을 세우는 게 아니라 각자 확인용.

학습 목표를 딱 4가지로 제한한다 — 좁은 화면에서 깨질 수 있음을 안다 / 폭을 줄여 한 번 확인한다 / 텍스트 겹침·가로 넘침·버튼 크기를 관찰한다 / 큰 수정은 3주차 후보로 기록한다. 범위 밖: 미디어 쿼리 문법 · 반응형 그리드 · 디자인 시스템 · 전 기기 테스트.

4.실습 체인 전체 — 앞의 산출물이 다음의 입력

모든 실습은 자유 주제와 템플릿 주제가 동일한 흐름이다. 템플릿 주제(오늘의 활동 기록) 사용자는 실습 ①②에서 주어진 한 줄 정의를 채택해 정의하는 시간만 아끼고, ③부터는 자유 주제와 완전히 동일하게 진행한다 — 완료 기준·검증도 같다.

5.사람이 판단하는 3지점

“AI가 작성하고, 사람이 검토하고, 사람이 결정한다”가 말이 아니라 실습으로 박히는 자리다. 세 지점 모두 학생이 실제로 무언가를 바꿔야 완료로 인정한다.

CP1 · 3구간 실습 ⑤

AI가 쓴 prd.md 초안 중 1개를 고친다
가정이 실제로 바뀌고 그 이유가 기록돼야 완료

CP2 · 2구간 실습 ③

AI가 제안한 기능 중 1개를 지운다
제외 이유가 있고 기능이 실제로 빠져야 완료

CP3 · 6구간 실습 ⑫

가장 중요한 문제를 스스로 고른다
표현만 바꾸면 반려 — 판단이 들어가야 한다

4구간의 하네스 실습도 같은 계열이다 — “AI가 만든 규칙은 초안이고, 사람이 검토해 결정한다”를 파일에 남는 형태로 경험시킨다. 그래서 초안을 그대로 승인하고 넘어가는 것이 이 실습의 가장 흔한 실패다.

강사가 미리 준비할 것

Codex 승인 다이얼로그 실물 캡처 — 학생이 화면에서 보게 될 문구와 버튼 라벨은 공식 문서 어디에도 없다. 문서 인용만으로 화면을 설명하면 현장에서 어긋나므로, 교육일 전에 강사가 직접 캡처해야 한다.

9.확정·미확정 요약

이번 버전에서 바뀐 것

  • 4구간이 새로 생겼다 — “AI에게 큰 작업을 맡기는 시스템”. 개념 20개(신규 19청크)와 하네스 실습이 들어간다.
  • 화면 구조가 5구간 앞단으로 이동했다 — 실습 ⑦~⑪ 체인이 통째로 함께 움직여서 기준을 정한 직후 구현으로 이어진다.
  • 짝 점검이 6구간에 신설됐다 — 3주차가 전제하던 “타인 관찰 경험”의 공백을 메운다.
  • 분리 파일·상대경로는 3구간에 그대로 둔다 — 실습 ⑥에서 세 파일을 만들어야 하므로 되돌리지 않는다.
  • 개념 재료가 60 → 79청크, 출처가 138 → 175개로 늘었다.
  • 5구간 실습을 90분 단일 블록으로 확정했다(2026-07-29) — 쪼개지 않고 한 번에 돌리되, 강사가 중간에 3분짜리 끼어들기와 정렬 지점으로 정보를 넣는다. 시간표도 이에 맞춰 확정(총 330분).
