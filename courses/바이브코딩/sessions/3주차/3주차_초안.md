## 읽고 시작해

- 표 1행 = authored page 1장. `본문 문구`는 화면 최종 문장(검토용), `**굵게**`·`<br>`은 그대로 반영된다.
- `💬` 농담·애드리브, `👀` 시연·관찰 지시, `🗣` 완성 요청문 예시는 **전부 발표자 노트로** 간다. **학생 화면에 접힘 힌트·「막힐 때만 보기」를 두지 않는다**(MEMORY 「콘텐츠·학생 화면」).
- `🖼️`는 조립자에게 주는 **시각 방향 메모**다. 화면 문구가 아니다.
- 고정 슬라이드 표기는 `(표지)` · `(파트 전환)` · `(마무리)` 셋뿐이다. 인쇄·편집 쪽 은어는 쓰지 않는다.
- **설명·근거·예시는 본문에 둔다.** 노트로 내리는 것은 농담·시연 지시·요청문뿐이다(R-DENS-02·R-ANNEX-01).
- **실습은 하루 전체 연속 번호 ①~⑮.**

### 용어 원칙

- **정해진 용어를 그대로 쓴다.** 임의로 풀어 쓰지 않는다 — 「되돌아갈 지점」이 아니라 **백업**, 「기록으로 묶기」가 아니라 **커밋**, 「연결 담당」이 아니라 **Client**.
- 쉽게 만들 때는 **용어를 바꾸는 게 아니라 비유·예시를 덧붙인다.** 용어 한 줄 + `<small>` 정의 한 줄 + 비유 한 줄이 기본 형태다.
- 화면에 쓰는 표준 용어: 하네스 · **싱글 에이전트** · **서브에이전트** · **멀티에이전트** · 오케스트레이터 · 단일 작성자 · 결과 충돌 · 채택/부분 채택/기각/확인 불가 · 독립 QA · 회귀 · 플러그인 · Skill · 커넥터 · MCP(Host·Client·Server / Tools·Resources·Prompts) · 저장소 · 커밋 · URL · 공유 범위 · 마우스 오버 효과.
- **역할명**: **HTML 담당(구조) · CSS 담당(스타일) · JS 담당(동작) · QA 담당(검증)**. 사람 이름은 쓰지 않는다. QA 담당은 파일을 갖지 않고 **화면**을 담당한다.
- **예시 원칙**: 슬라이드 예시("활동 기록 도구")는 **강사의 설명용 예시**다. 수강생은 이를 참고해 **각자 2주차 MVP**에 적용한다. 공용 샘플 앱은 없다.
- **관통 문장(3주차 확장)**: AI가 작성하고, 사람이 검토하고, **사람이 공개를 결정하며, 공개의 책임도 사람이 진다.**
- **출처는 화면에 표시하지 않는다**(`profile.md` §4).

### v5에서 바뀐 것 (사용자 지시 · 2026-08-07)

- **5 PART → 6 PART.** v2의 PART-01(워밍업)을 되살려 넣고, 개념과 실습이 한 PART에 몰려 있던 구간을 갈랐다.
- **하네스는 PART 1에 배치.** v2 PART-01과 v4 PART-01이 둘 다 하네스를 다뤄 겹쳤다. 하네스·MVP 실행 확인·백업·`AGENTS.md`·공개 금지 파일을 전부 PART 1로 모았다.
- **PART 2는 싱글·서브·멀티 에이전트 개념 전용.** 「싱글 에이전트」가 새로 들어온다 — 지금까지 학생이 써 온 방식에 이름을 붙여 주고, 서브·멀티와 나란히 비교한다(3열 비교표 근거는 심층리서치 §3.2).
- **PART 3은 담당 나누기 실습.** 개념(PART 2)과 실제 배정(PART 3)을 분리했다. 담당 명칭은 **HTML·CSS·JS·QA** 그대로다.
- **⚠️ 워밍업 실습의 위치를 v2와 다르게 잡았다.** v2는 「움직임 넣기」가 백업보다 **앞**이었는데, 백업 전에 코드를 고치는 셈이라 PART 1의 논지와 어긋난다. **MVP 실행 확인 → 백업 → 워밍업 실습** 순으로 옮겼다. 첫 수정을 백업 이후에 한다는 것을 실습으로 보여 주는 효과가 덤으로 생긴다.
- 실습은 14개 → **15개**(워밍업 1개 추가).
