# AI 개발팀 설정 예제

이 폴더는 2주차에 만든 정적 웹 프로젝트에 기능 하나를 추가할 때 바로 복사해 쓰는 예제다. 대상 프로젝트에는 `prd.md`, `index.html`, `style.css`, `script.js`가 있다고 가정한다.

## 1. 복사와 인식 확인

1. 이 폴더 안의 `AGENTS.md`와 `.codex` 폴더를 프로젝트 최상위에 그대로 복사한다.
2. 프로젝트를 Codex에서 다시 열거나 새 작업을 시작한다. 기존 작업에서 설정이 보이지 않으면 Codex를 다시 시작한다.
3. 다음과 같이 각 에이전트를 이름으로 호출해 정체성을 확인한다.

```text
sujin 에이전트에게 “너는 무슨 역할이야?”라고 질문해줘.
minho 에이전트에게 “너는 무슨 역할이야?”라고 질문해줘.
jihun 에이전트에게 “너는 무슨 역할이야?”라고 질문해줘.
doyun 에이전트에게 “너는 무슨 역할이야?”라고 질문해줘.
```

정상이라면 네 응답은 다음 문장과 정확히 일치한다.

- 나는 프론트엔드 개발자 수진이야.
- 나는 백엔드 개발자 민호야.
- 나는 데이터베이스 설계자 지훈이야.
- 나는 QA 엔지니어 도윤이야.

## 2. 추가 기능 선택 규칙

`prd.md`의 나중 아이디어 또는 지금 불편한 점에서 기능 하나를 고른다. 검색, 필터, 정렬, 즐겨찾기, 최근 기록, 입력 초기화처럼 HTML, CSS, 일반 JavaScript만으로 만들 수 있어야 한다. 대표 사용자 흐름도 하나만 정한다. 외부 API, 실제 서버, 실제 데이터베이스, 패키지 설치, 빌드는 제외한다.

## 3. 정확한 작업 순서

1. 사람이 추가 기능과 대표 사용자 흐름을 한 줄로 결정한다.
2. 메인이 `jihun`을 호출해 데이터 형태, 상태 변화, 저장 규칙, `localStorage` 필요 여부를 묻는다.
3. 메인이 DOM ID, 함수 이름과 입출력, 파일 소유권을 확정한다.
4. 메인이 `sujin`에게 `index.html`·`style.css`를, `minho`에게 `script.js`를 맡긴다. 두 에이전트는 서로 다른 파일만 작업한다.
5. 메인이 결과를 통합하고 충돌이나 계약 불일치를 바로잡는다.
6. 메인이 `doyun`을 호출해 추가 기능 전체 흐름과 기존 기능 회귀를 확인한다.
7. 실패가 있으면 해당 파일 담당자에게만 수정 요청하고 도윤의 QA와 메인의 직접 확인을 반복한다.

## 4. 완료 증거

- 네 에이전트의 정확한 정체성 응답
- 선택한 추가 기능과 대표 사용자 흐름 한 줄
- 에이전트별 요청·담당 파일·결과 표
- 기능이 작동하는 화면
- 도윤의 테스트 결과와 메인의 직접 확인 결과

## 5. 실패 복구

- 에이전트가 보이지 않으면 파일이 프로젝트 최상위의 `.codex/agents/`에 있는지 확인하고 새 작업을 연다.
- 정체성 문장이 다르면 해당 TOML의 `developer_instructions`를 원본과 비교한다.
- 수진과 민호가 같은 파일을 고쳤다면 작업을 멈추고 메인이 파일 소유권부터 다시 확정한다.
- 기능이 깨졌다면 도윤의 재현 절차를 기준으로 실패 파일 담당자에게만 수정 요청한다.
- 설정에 실제 비밀값을 넣지 않는다. 역할 분리는 교육용 지침이며 보안상 완전한 격리가 아니다.
