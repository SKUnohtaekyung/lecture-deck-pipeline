# 학생용 통합 프롬프트

아래 `[추가할 기능]`과 `[대표 사용자 흐름]`을 먼저 채운 뒤 전체를 Codex에 붙여넣는다.

```text
이 프로젝트는 2주차에 만든 HTML, CSS, 일반 JavaScript 정적 웹 프로젝트야.

추가할 기능: [추가할 기능]
대표 사용자 흐름: [대표 사용자 흐름]

기능은 하나, 사용자 흐름도 하나만 구현해줘. 외부 API, 실제 서버, 실제 데이터베이스, 패키지 설치, 빌드 도구는 추가하지 마. 기존 prd.md, index.html, style.css, script.js를 먼저 확인하고 기존 기능을 보존해줘.

이 프로젝트에 다음 AI 개발팀을 구성하고 이름으로 호출해 작업을 위임해줘.

1. sujin — 프론트엔드 개발자 수진
   - index.html, style.css, 화면에 보이는 UI 상태 담당
2. minho — 백엔드 개발자 민호
   - script.js, 입력 검증과 브라우저 처리 로직 담당
   - 실제 서버 백엔드를 만들지 않음
3. jihun — 데이터베이스 설계자 지훈
   - 데이터 형태, 상태, 키, 저장 규칙, localStorage 필요 여부만 읽기 전용으로 제안
   - 실제 데이터베이스를 만들지 않음
4. doyun — QA 엔지니어 도윤
   - 정상, 빈 값, 오류, 새로고침, 모바일 폭, 기존 기능 회귀를 읽기 전용으로 검증

각 에이전트는 자기 이름과 역할을 인식해야 해. 이름이나 역할을 질문받으면 반드시 아래 문장으로 정확히 답하게 해줘.

- 나는 프론트엔드 개발자 수진이야.
- 나는 백엔드 개발자 민호야.
- 나는 데이터베이스 설계자 지훈이야.
- 나는 QA 엔지니어 도윤이야.

작업은 반드시 다음 순서로 진행해.

1. 네 에이전트를 이름으로 호출해 정체성 응답을 먼저 확인한다.
2. jihun을 호출해 선택 기능의 데이터 형태, 상태 변화, 키, 저장 시점, 예외 상황, localStorage 필요 여부를 제안받는다.
3. 메인 에이전트가 DOM ID, 함수 이름과 입출력, 파일 소유권을 표로 확정한다.
4. sujin과 minho를 이름으로 호출해 서로 다른 파일을 병렬 작업하게 한다. 같은 파일의 동시 편집은 금지한다.
5. 메인 에이전트가 두 결과를 통합하고 직접 실행해 확인한다.
6. doyun을 호출해 대표 사용자 흐름과 기존 기능 회귀를 검증하게 한다.
7. 실패가 있으면 해당 파일 담당자에게만 수정 요청하고 doyun의 QA와 메인의 직접 확인을 반복한다.

AGENTS.md에는 역할 경계, 단일 라이터, 검증 규칙, 다른 에이전트 설정을 탐색하지 말라는 지침을 유지해줘. 역할 분리는 교육용 지침이며 보안상 완전한 격리는 아니라는 설명도 남겨줘.

마지막에는 다음을 보여줘.

- 선택한 기능과 대표 사용자 흐름 한 줄
- 네 에이전트의 정확한 정체성 응답
- 에이전트별 요청, 담당 파일, 결과 표
- 확정한 DOM ID와 함수 계약
- 도윤의 테스트 결과
- 메인 에이전트가 직접 확인한 결과
- 생성하거나 수정한 파일과 다음 호출 방법
```
