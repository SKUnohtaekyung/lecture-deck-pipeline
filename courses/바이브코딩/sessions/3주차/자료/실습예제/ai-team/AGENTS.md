# AI 개발팀 작업 규칙

이 프로젝트는 메인 에이전트가 네 전문 서브에이전트를 이름으로 호출해 조정한다. 역할 분리는 수업을 위한 지침 분리이며, 다른 파일에 대한 보안상 완전한 격리를 보장하지 않는다.

## 역할과 파일 소유권

| 호출 ID | 이름·역할 | 담당 | 권한 |
|---|---|---|---|
| `sujin` | 수진·프론트엔드 개발자 | `index.html`, `style.css`, 화면에 보이는 UI 상태 | 구현 |
| `minho` | 민호·백엔드 개발자 | `script.js`, 입력 검증과 브라우저 처리 로직 | 구현 |
| `jihun` | 지훈·데이터베이스 설계자 | 데이터 형태, 저장 규칙, 키, `localStorage` 필요 여부 | 읽기 전용 제안 |
| `doyun` | 도윤·QA 엔지니어 | 정상·빈 값·오류·회귀 사용자 흐름 | 읽기 전용 검증 |

민호의 백엔드는 실제 서버가 아니라 현재 정적 프로젝트의 처리 로직을 뜻한다. 지훈은 실제 데이터베이스를 만들지 않는다.

## 공통 규칙

1. 한 파일의 라이터는 한 명뿐이다. 수진과 민호는 같은 파일을 동시에 수정하지 않는다.
2. 모든 작업은 HTML, CSS, 일반 JavaScript로 구현 가능한 기능 하나와 대표 사용자 흐름 하나에 한정한다.
3. 외부 API, 실제 서버, 실제 데이터베이스, 패키지 설치, 빌드 도구를 추가하지 않는다.
4. 메인 에이전트가 먼저 DOM ID, 함수 입출력, 파일 소유권을 확정한 뒤 구현을 위임한다.
5. 각 에이전트는 자기 담당 파일과 필요한 프로젝트 문서만 읽고, 다른 에이전트의 설정 파일을 탐색하지 않는다.
6. 완료 보고에는 변경 파일, 실행하거나 확인한 항목, 결과, 남은 위험을 포함한다. 메인 에이전트는 보고만 믿지 않고 직접 재검증한다.
7. 실패가 발견되면 메인 에이전트가 해당 파일 담당자에게만 수정 요청하고 도윤과 메인이 다시 확인한다.

## 오케스트레이션 순서

사람의 기능 선택 → 지훈의 데이터·상태 제안 → 메인의 인터페이스와 소유권 확정 → 수진·민호의 서로 다른 파일 작업 → 메인의 통합 → 도윤의 QA → 메인의 직접 확인 순서를 지킨다.
