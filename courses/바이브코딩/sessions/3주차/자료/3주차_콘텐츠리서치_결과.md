## 1구간 — 하네스 리마인드와 시작 상태 보호

① **핵심 메시지** — 오늘은 바로 기능을 더하지 않는다. 여러 에이전트가 **같은 기준을 읽고** 현재 작동 상태를 깨뜨리지 않도록 작업 환경부터 다시 묶는다.

② **초보자용 설명 문장** — "AI에게 다시 일을 맡기기 전에, 무엇을 먼저 읽게 할지·무엇은 건드리지 말지·끝나면 무엇으로 확인할지를 정해 둡니다. 그리고 망가졌을 때 돌아갈 지점을 남깁니다."

③ **사실 확인 내용**
- 하네스는 **합의된 표준 용어가 아니다.** 2026년 상반기부터 일부 실무자가 쓰기 시작한 말이다 [S-301][S-302] → `[C-하네스]`
- 규칙 파일은 **강제가 아니라 조언**이며, 사후 검증이 없으면 하네스가 아니다 [S-303][S-304] → `[C-하네스]` `[C-AGENTS규칙파일]`
- "최소형이 낫다"는 **연구가 확정한 사실이 아니라 이 강의의 설계 원칙**이다 [S-307] → `[C-AGENTS규칙파일]`
- 도구의 되돌리기가 **대화만 되돌리고 파일 변경은 남길 수 있다** [S-311][S-312] → `[C-시작상태보호]`
- 한 번 올라간 것은 지워도 **기록·복사본에 남는다** [S-317] → `[C-공개전점검]`

④ **사용 가능한 비유** — 신입 온보딩 패키지 / 정비소 체크리스트+감독관 → `[C-하네스]` · 시험 전 답안지 사본 / 게임 세이브 → `[C-시작상태보호]` · 게시판에 붙인 종이 / 복사기로 뿌린 문서 → `[C-공개전점검]`

⑤ **비교 사례** — 컨텍스트 엔지니어링(좁음) ↔ 하네스(넓음) → `[C-하네스]` · 폴더 복제 ↔ 버전 관리 스냅샷 → `[C-시작상태보호]` · 제외 목록(사전 차단) ↔ 전송 차단(사후 그물) → `[C-공개전점검]`

⑥ **출처 URL과 확인 날짜** — S-301(2급)·S-302(2급)·S-303(1급)·S-304(1급)·S-305(1급)·S-306(1급)·S-307(2급)·S-308(3급)·S-309(3급)·S-310~S-319. 전부 확인일 2026-08-06. 상세는 `3주차_출처레지스트리.md`.

⑦ **슬라이드에 넣을 표·도식·이미지 아이디어** — "모델 vs 하네스" 대조 도해 · `AGENTS.md` 4절 최소형 빈 표 · 파일 탐색기 좌우 비교(작업 폴더 / 백업 폴더) · 커밋 전 체크리스트 카드

## 2구간 — 작업 그래프와 위임 설계

① **핵심 메시지** — 일을 **몇 명에게 나눌지**가 아니라, 어떤 작업이 독립적이고 어떤 작업이 앞 결과를 기다려야 하는지부터 설계한다.

② **초보자용 설명 문장** — "동시에 시킬지 순서대로 시킬지는 **같은 파일을 건드리는가**만 보면 됩니다. 그리고 각자에게 무엇을 읽고·무엇까지 하고·무엇을 돌려줄지를 한 줄씩 적어 줍니다."

③ **사실 확인 내용**
- 서브에이전트의 실제 차이는 이름표가 아니라 **별도 컨텍스트·독립 도구 권한·요약 반환**이다 [S-361] → `[C-서브에이전트]`
- 멀티에이전트는 **제품명이 아니라 작업 패턴**이며, 수를 늘리는 것 자체는 심화가 아니다 [S-391] → `[C-멀티에이전트]`
- 오케스트레이터는 **정보 병목**이 되고, 병렬화하지 않으면 비용만 는다 [S-363] → `[C-오케스트레이터]`
- 컨텍스트 격리는 **보안 격리가 아니다** [S-365] → `[C-컨텍스트격리]`
- 역할 충실도는 **대화가 길어질수록 저하된다** [S-368] → `[C-정체성확인]`
- 전문가 페르소나는 **사실 정확도를 떨어뜨린다**(71.6% → 68.0%) [S-370] → `[C-역할이름부여]`
- 위임 계약의 제약이 쌓이면 준수율이 **96% → 20%**로 급락한다 [S-374] → `[C-위임계약]`
- 읽기 전용은 **프롬프트가 아니라 도구 허용 목록으로 강제**된다 [S-361] → `[C-읽기전용권한]`

④ **사용 가능한 비유** — 파견 조사원 / 외주 검토 → `[C-서브에이전트]` · 여러 팀의 종합 보고 → `[C-멀티에이전트]` · 편집장과 기자 → `[C-오케스트레이터]` · 회의실 칸막이 → `[C-컨텍스트격리]` · 명찰 vs 자격증 → `[C-역할이름부여]` · 같은 도마 → `[C-작업그래프]` · 다섯 가지 동시 주문 → `[C-위임계약]` · 팻말 vs 유리 진열장 → `[C-읽기전용권한]`

⑤ **비교 사례** — 서브에이전트 ↔ 메인에서 직접 처리 → `[C-서브에이전트]` · 멀티 ↔ 단일 에이전트 → `[C-멀티에이전트]` `[C-단일AI기준선비교]` · 서브에이전트(메인에만 보고) ↔ 팀(서로 대화) → `[C-오케스트레이터]` · 매크로 ↔ 에이전트 → `[C-에이전트vs워크플로]`(인접)

⑥ **출처 URL과 확인 날짜** — S-321~S-324 · S-361~S-375 · S-382 · S-387 · S-391~S-393. 전부 확인일 2026-08-06.

⑦ **슬라이드에 넣을 표·도식·이미지 아이디어** — **"동시에 읽을 것 / 기다릴 것 / 한 명이 쓸 것" 3칸 표**(v3가 지정한 시작 형태) · 제약 개수 대비 준수율 급락 곡선(96% → 20% 두 점만) · 본부 vs 파견 조사원 도해 · 역할표 4행(이름 · 권한 · 담당 · 산출물)

## 3구간 — 병렬 검토와 결과 충돌 판정

① **핵심 메시지** — 결과가 다를 때 **다수결이 아니라 근거와 재현**으로 판정한다. 근거가 부족하면 **"확인 불가"로 남기는 것이 안전장치다.**

② **초보자용 설명 문장** — "의견이 갈리면 누가 더 많이 그렇게 말했는지가 아니라, **누구 말을 실제로 화면에서 재현할 수 있는지**로 정합니다."

③ **사실 확인 내용**
- 의견이 갈린 사례 **4건 중 1건은 소수가 정답**이었다 [S-376] → `[C-결과충돌판정]`
- 다수결은 공유된 오류를 **걸러내는 게 아니라 증폭한다** [S-376][S-381] → `[C-결과충돌판정]`
- 검토 역할을 늘려도 **근거가 겹치면 이득이 거의 없다** [S-377] → `[C-검토역할설계]`
- 단일 AI 기준선과 역할 기반 결과는 **같은 조건으로 통제해야 비교가 성립한다** [S-322] → `[C-단일AI기준선비교]`

④ **사용 가능한 비유** — 같은 뉴스만 본 배심원 / 같은 소문을 들은 증언 → `[C-결과충돌판정]` · 같은 목격자를 다섯 번 부르기 → `[C-검토역할설계]` · 요리사 한 명 vs 넷 → `[C-단일AI기준선비교]`

⑤ **비교 사례** — 다수결 ↔ 근거 기반 판정 → `[C-결과충돌판정]` · 단일 실행 ↔ 역할 기반 재수행 → `[C-단일AI기준선비교]`

⑥ **출처 URL과 확인 날짜** — S-321·S-322·S-323·S-324·S-376·S-377·S-381. 전부 확인일 2026-08-06.

⑦ **슬라이드에 넣을 표·도식·이미지 아이디어** — **판정값 4개**(채택 / 부분 채택 / 기각 / 확인 불가) 결정 도해 · 결과 비교표 6열(후보 · 제안한 역할 · 근거 · 실제 관찰 · 비교 기준 · 판정) · 기준선 ↔ 역할 기반 좌우 대조

⑧ **피해야 할 표현과 과도한 내용** — "의견이 갈리면 다수를 따르면 된다" · "역할을 더 붙이면 더 안전해진다" · "멀티에이전트가 항상 우월하다" · 통계 평가·형식 논리로 확장하지 않는다

## 4구간 — 단일 작성자 구현

① **핵심 메시지** — 승인된 기준만, **한 명이**, 한 번 고친다. 그리고 **구현에 참여하지 않은 역할**이 다시 확인한다.

② **초보자용 설명 문장** — "고치기 전에 무엇을 바꾸고 무엇은 안 건드릴지 먼저 적어 확인받습니다. 실제로 파일을 고치는 사람은 한 명뿐이고, 확인은 다른 사람이 합니다."

③ **사실 확인 내용**
- AI 변경의 병합 충돌률 **27.67%**, 서로 다른 에이전트끼리는 **41.7%** [S-372][S-373] → `[C-단일라이터]`
- 파일 전체를 다시 쓰면 **경고 없이** 상대 작업이 사라진다 [S-382] → `[C-단일라이터]` `[C-작업그래프]`
- 요청 범위를 넘는 수정은 **거의 모든 주요 모델에서 관찰되는 체계적 패턴**이다 [S-325] → `[C-변경계약]`
- 계획 모드가 **모든 작업에 이득인 것은 아니다**(작은 수정엔 순손실) [S-326] → `[C-변경계약]`
- 회귀는 **직접 안 건드린 공유 부분**에서 더 잘 생긴다 [S-328] → `[C-독립QA회귀]`
- "자기 검증은 원천 불가"는 **과장**이다 — 역할 라벨을 바꾸면 정정률이 크게 올랐다 [S-329] → `[C-독립QA회귀]`

④ **사용 가능한 비유** — 한 문서를 둘이 각자 저장 → `[C-단일라이터]` · 리모델링 견적서 → `[C-변경계약]` · 자기 채점 vs 타인 채점 → `[C-독립QA회귀]` · 고치다 다른 데가 깨짐 → `[C-회귀]`(인접)

⑤ **비교 사례** — 동시 편집 ↔ 단일 작성자 → `[C-단일라이터]` · 계획 먼저 ↔ 바로 실행 → `[C-변경계약]` · 자체 확인 ↔ 독립 QA → `[C-독립QA회귀]`

⑥ **출처 URL과 확인 날짜** — S-303·S-320·S-325~S-330·S-364·S-372·S-373·S-382·S-385. 전부 확인일 2026-08-06.

⑦ **슬라이드에 넣을 표·도식·이미지 아이디어** — **다섯 칸 계획 양식**(파일명 / 이유 / 예상 변경 / 유지할 연결 / 확인 방법) 빈 표 + 채운 예시 · 충돌률 막대(27.67% · 41.7% vs 19.8%) · 수진(구현) ↔ 도윤(QA) 분리 도해 · "기존 흐름 / 새 흐름 / 다른 값 / 오류 조건" 네 칸

## 5구간 — 플러그인·MCP와 실제 화면 QA

① **핵심 메시지** — 플러그인·Skill·Connector·MCP는 **층이 다르다.** 그리고 파일만 읽은 게 아니라 **실제 화면에서 확인했다는 증거**를 남긴다.

② **초보자용 설명 문장** — "MCP는 기능이 아니라 **연결 규격**입니다. 플러그인은 그 연결과 절차를 묶어 설치하게 해 주는 상자이고요. 그리고 마지막엔 실제 화면에서 눌러 봅니다."

③ **사실 확인 내용**
- **설치 ≠ 권한 부여** — 로그인은 이름·이메일·프로필 사진만 공유하고 권한은 별도 승인이다 [S-331] → `[C-플러그인]`
- Connector는 **MCP 위에 얹힌 관리형 형태**이지 동의어가 아니다 [S-335] → `[C-Connector]`
- Skill은 절차일 뿐 **스스로 외부에 접속할 힘이 없다** [S-334] → `[C-Skill]`
- MCP 클라이언트 다수에 **중대한 보안 문제**가 있었고 tool poisoning이 최다 위협이다 [S-378] → `[C-MCP]`
- **Computer Use는 표면이 셋**이며, 브라우저 확장과 데스크톱 앱은 **Windows를 지원한다**(CLI만 macOS 전용) [S-338][S-339] → `[C-ComputerUse]`
- 화면 QA 7항목 중 반응형·키보드·모션 축소는 **접근성 표준의 성공 기준에 대응**한다 → `[C-화면QA체크리스트]`

## 6구간 — 개인 고도화와 GitHub 기록

① **핵심 메시지** — 같은 사이클을 자기 프로젝트에 다시 적용하고, 변경을 **확인 가능한 기록**으로 남긴다. 완료는 **`push` 성공 메시지가 아니라 웹 화면의 최신 커밋**으로 판정한다.

② **초보자용 설명 문장** — "`add`는 담고, `commit`은 기준점을 만들고, `push`는 보냅니다. 그리고 GitHub 화면을 새로고침해 **실제로 올라갔는지 눈으로** 확인합니다."

③ **사실 확인 내용**
- `push`는 **원격에 아직 없는 데이터만** 보낸다 — 커밋 안 한 변경은 전송 대상이 아니다 [S-349] → `[C-Git기록]`
- 이 강의가 쓰는 도구의 **AI 생성 커밋 메시지 고품질 비율이 31.3%로 가장 낮았다** [S-360] → `[C-커밋메시지]`
- 커밋 규약(접두사 강제)에 대한 **비판**이 있으며, 입문자에겐 자연어가 낫다 [S-357] → `[C-커밋메시지]`
- 비공개 전환·삭제는 **과거에 이미 복제된 것을 회수하지 않는다** [S-353] → `[C-저장소공개범위]`
- 로컬과 원격은 **대등한 저장소**이며 `push`를 눌러야만 동기화된다 [S-352] → `[C-GitHub저장소]`
- 완료는 **파일 변경·브라우저 실행·QA 기록·커밋** 넷으로 판정한다 [S-303][S-388] → `[C-완료증거]`

④ **사용 가능한 비유** — 이삿짐 / 게임 저장 → `[C-Git기록]` · 택배 포장 전 확인 → `[C-git상태확인]` · 사진첩 설명 / 약봉투 → `[C-커밋메시지]` · 서랍과 서버함 → `[C-GitHub저장소]` · 뿌린 전단지 / 보낸 이메일 → `[C-저장소공개범위]` · 숙제 확인 / 배송 완료 알림 → `[C-완료증거]` · 장바구니 → `[C-스테이징영역]`(인접) · Ctrl+S vs 커밋 → `[C-워킹트리vs커밋]`(인접)

⑤ **비교 사례** — 명령줄 ↔ 화면 도구 → `[C-Git기록]` · `add .` ↔ 파일 지정 → `[C-git상태확인]` · 접두사 규약 ↔ 자연어 메시지 → `[C-커밋메시지]` · 공개 저장소 삭제 ↔ 비공개 저장소 삭제 → `[C-저장소공개범위]`

⑥ **출처 URL과 확인 날짜** — S-303·S-315~S-319·S-349~S-360·S-383·S-388~S-390. 전부 확인일 2026-08-06.

⑦ **슬라이드에 넣을 표·도식·이미지 아이디어** — 작업 영역 → 스테이지 → 로컬 → 원격 **4단 도해** + 명령어 라벨 · 변경 목록 화면 캡처 3영역 색칠 · ✗"수정"·"최종"·"완료" → ✓"3주차: 빈 검색어에 안내 문구 표시" 전환 · **완료 증거 네 칸 체크박스** · "비공개로 전환" 옆 "이미 존재하는 사본은 그대로 공개" 잔상

⑧ **피해야 할 표현과 과도한 내용** — "저장 = 커밋" · "commit만 하면 GitHub에도 반영된다" · "비공개로 바꾸면 안전하다" · "삭제하면 깨끗이 없어진다" · "AI가 통과했다고 하면 끝" · "AI가 쓴 커밋 메시지는 항상 정확하다" · **브랜치·pull request·merge·rebase·충돌 해결로 확장하지 않는다** · `git init`·원격 연결·인증은 **수업 전 사전 조건**이므로 수업 중 처음부터 다루지 않는다 · **GitHub 화면의 저장소 주소·계정 정보는 마스킹한다**
