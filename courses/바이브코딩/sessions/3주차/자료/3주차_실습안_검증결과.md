## 실습1 — 시작 상태 확인·보호·복구 (1구간)

① **실습 목적** — 에이전트에게 맡기기 전에 현재 MVP가 실제로 작동하는지 확인하고, 망가졌을 때 돌아갈 복구 지점을 만든다.
② **수강생 안내문** — "2주차 프로젝트 폴더를 엽니다. `index.html`을 브라우저에서 열어 대표 흐름을 한 번 끝까지 실행하고 화면을 캡처합니다. 그다음 폴더 전체를 복사해 이름에 오늘 날짜를 붙이고, **프로젝트 폴더 바깥**에 둡니다."
③ **실제 요청문** — (Codex에 요청하지 않는다. 사람이 파일 탐색기로 직접 수행) 
④ **준비물과 사전 설정** — 2주차 프로젝트 폴더 · 브라우저 · 파일 탐색기
⑤ **정상 진행 순서** — 폴더 열기 → `index.html` 실행 → 대표 흐름 1회 → 화면 캡처 → 폴더 선택 후 복사·붙여넣기 → 이름을 `프로젝트_백업_MMDD`로 변경 → 상위 폴더 밖으로 이동 → 작업은 원본에서만
⑥ **완료 기준** — 시작 화면 캡처가 있고, 백업 폴더가 **작업 폴더 밖**에 존재하며, 학습자가 어느 쪽이 작업 중인지 말할 수 있다.
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 5~10분(v3 §8.3 「오전 00:00–00:20 시작 상태 보호」 구간 내)
⑧ **자주 발생하는 오류** — 2주차 페이지가 안 열림 · 백업 폴더와 현재 폴더 혼동 · 백업을 프로젝트 폴더 **안에** 만듦(→ 함께 망가짐) · AI가 먼저 기능을 추가해 버림
⑨ **복구 방법** — 페이지가 안 열리면 추가 작업을 중단하고 파일 경로·스크립트 연결부터 최소 복구 · 폴더 혼동 시 이름을 명확히 구분해 재정리
⑩ **정상 완성본 위치** — 해당 없음(각자의 2주차 결과물)
⑪ **최소 복구본 위치** — 해당 없음 — v3 §11이 **"실패해도 완성본으로 교체하지 않고 현재 프로젝트의 최소 복구를 우선"**한다고 명시
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — 「폴더 밖에 둔다」의 의미를 화면으로 보여 줘야 한다 · 복사본을 열어 고치는 실수가 잦을 것으로 예상됨
⑬ **채택·보류·제외 추천과 근거** — **채택 추천.** 도구의 되돌리기가 파일 변경까지 되돌린다는 보장이 없고(`[C-시작상태보호]`), 이 강의는 버전 관리를 안 쓰므로 **폴더 복제가 유일한 안전망**이다. 다만 D3(복제 vs 앱 되돌리기)은 실기기 비교 후 총괄이 확정해야 한다.

## 실습2 — `AGENTS.md` 최소 보완 (1구간)

① **실습 목적** — 모든 역할이 반복해서 지킬 공통 규칙을 4절 최소형으로 남긴다.
② **수강생 안내문** — "Codex에게 3주차 공통 규칙을 제안하게 하고, 사람이 **네 절만 남기고 짧게 정리**합니다 — 먼저 읽을 자료 / 반드시 유지할 것 / 에이전트 작업 방식 / 완료 전 확인."
③ **실제 요청문** — "이 프로젝트의 `AGENTS.md`에 다음 네 절만 짧게 제안해 줘: (1) 먼저 읽을 자료 (2) 반드시 유지할 것 (3) 에이전트 작업 방식(읽기 전용 역할은 파일을 수정하지 않는다 / 같은 단계에서는 한 작성자만 쓴다) (4) 완료 전 확인. 각 절은 3줄을 넘기지 마."
④ **준비물과 사전 설정** — 프로젝트 폴더가 Codex에 열려 있을 것
⑤ **정상 진행 순서** — 요청 → 제안 확인 → 사람이 줄이기 → 저장 → **에이전트에게 읽은 규칙을 짧게 다시 말하게 함**
⑥ **완료 기준** — 파일에 네 절이 있고, 각 절이 짧으며, 에이전트가 규칙을 되말할 수 있다.
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 15~25분(v3 §8.3 「오전 00:20–00:45 하네스 보완」)
⑧ **자주 발생하는 오류** — 규칙 파일이 장문의 규정집이 됨 · 코드를 보면 아는 내용을 규칙에 또 적음 · 규칙을 썼는데 지켜지지 않음
⑨ **복구 방법** — 먼저 읽을 자료·유지할 것·역할 권한·확인 방법만 남기고 나머지 삭제
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — 마크다운 파일 편집 자체가 낯설 수 있어 화면 안내가 필요하다
⑬ **채택·보류·제외 추천과 근거** — **채택 추천.** 단, **"최소형이 낫다"를 정답처럼 말하지 않는다** — 파일 구조 변수의 효과가 실증되지 않았고(`[C-AGENTS규칙파일]`), 규칙은 조언이지 강제가 아니다. 이 실습의 가치는 "짧게 쓰기"가 아니라 **완료 전 확인 절을 갖는 것**이다.

## 실습3 — 네 역할 이름 호출·자기소개·동료 역할 비공개 (2구간)

① **실습 목적** — 이름으로 호출했을 때 각 역할이 자기 담당만 답하고 동료 정보를 모르는지 확인한다.
② **수강생 안내문** — "수진·민호·지훈·도윤을 각각 이름으로 부르고 **'너는 무슨 역할이야?'**라고 묻습니다. 자기 역할을 정확히 답하는지, 그리고 **다른 역할의 이름·담당을 아는지** 확인합니다."
③ **실제 요청문** — 역할별로: "너는 무슨 역할이야?" / "다른 팀원의 이름과 담당을 아는 대로 말해 줘."
④ **준비물과 사전 설정** — 네 역할이 설정된 Codex 프로젝트 · 새 세션
⑤ **정상 진행 순서** — 역할 설정 → 이름 호출 → 자기소개 확인 → 동료 정보 질문 → **모른다고 답하는지 확인** → **새 세션에서 3회 반복**(v3 §9.2 B)
⑥ **완료 기준** — 네 역할의 자기소개가 정확하고, 동료 정보를 발설하지 않는다. **통과하지 않으면 명시적 역할 프롬프트 폴백을 쓰고 그 차이를 기록한다.**
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 5~10분
⑧ **자주 발생하는 오류** — 이름 호출이 통과하지 않음 · 역할 간 정보가 섞임 · 대화가 길어지며 역할이 흐려짐
⑨ **복구 방법** — 역할 프롬프트를 **한 번 다시 주입(앵커)**해 되돌린다(`[C-정체성확인]`)
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — 여러 세션을 오가는 조작 자체가 부담 · 어느 창이 누구인지 혼동
⑬ **채택·보류·제외 추천과 근거** — **채택 추천이되 폴백 필수.** ⚠️ **이 실습이 통과하지 못할 위험이 실재한다** — 역할 충실도가 대화 진행에 따라 저하된다는 실증 연구가 있고(`[C-정체성확인]`), 컨텍스트 격리는 **보안 격리가 아니다**(`[C-컨텍스트격리]`). 슬라이드에 **"이 분리는 교육용 지침 분리이며 보안상 완전한 격리가 아니다"**를 반드시 표시해야 한다. **P0 통과 표면에서 새 세션 3회 재현은 사람이 반드시 수행해야 하는 검증이다.**

## 실습4 — 단일 AI 기준선 ↔ 역할 기반 재수행 비교 (2·3구간)

① **실습 목적** — "나누면 낫다"를 믿지 않고 같은 조건에서 비교해 관찰한다.
② **수강생 안내문** — "같은 브리프로 (1) 한 세션이 전부 수행한 결과와 (2) 네 역할로 나눈 결과를 만들고, 나란히 놓고 항목별로 비교합니다."
③ **실제 요청문** — (경로1) 공통 브리프 그대로 / (경로2) 역할별 위임 계약 4건
④ **준비물과 사전 설정** — **동일한 공통 브리프** · **동일한 시작 상태** — 이 둘이 같지 않으면 비교가 성립하지 않는다
⑤ **정상 진행 순서** — 기준선 실행 → 문제 분석표 작성 → 역할별 병렬 검토 → 오케스트레이터 취합 → **결과 비교표 6열** 작성 → 채택·부분 채택·기각·확인 불가 판정
⑥ **완료 기준** — 비교표에 **최소 한 가지 이상의 관찰 가능한 차이와 근거**가 있고, 사람이 채택 범위와 제외 범위를 승인했다.
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 45~70분(v3 §8.3 「오전 00:45–02:00」)
⑧ **자주 발생하는 오류** — 두 경로의 조건이 달라 비교 불가 · 역할별 결과를 섞음 · 근거 없이 "역할 기반이 더 좋다"로 결론
⑨ **복구 방법** — 브리프·시작 상태를 먼저 맞춘 뒤 다시 실행 · 원문과 취합 기록을 분리 보관
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — 표 작성 부담이 크다 — **빈 표를 미리 배포**해야 한다
⑬ **채택·보류·제외 추천과 근거** — **채택 추천.** 이 실습이 v3의 핵심이며, "에이전트가 많을수록 좋다"는 오개념을 **직접 반증할 유일한 자리**다. 다만 소규모 단발 과제이므로 결과를 일반 법칙으로 말하지 않도록 `필수 진술`을 슬라이드에 남긴다(`[C-단일AI기준선비교]`).

## 실습5 — 변경 계약 기반 단일 작성자 구현 + 독립 QA (4구간)

① **실습 목적** — 승인된 기준만 한 명이 구현하고, 구현에 참여하지 않은 역할이 재확인한다.
② **수강생 안내문** — "수진에게 승인된 기준만 전달합니다. 수진은 **고치기 전에 다섯 칸 계획**을 먼저 제출합니다. 구현 뒤에는 도윤이 네 갈래로 확인합니다."
③ **실제 요청문** — 수진: "다음 다섯 칸을 먼저 제출해: 파일명 / 바꾸는 이유 / 예상 변경 / 유지할 연결 / 확인 방법. 승인 전에는 파일을 고치지 마." / 도윤: "구현에 참여하지 말고, 기존 흐름·새 흐름·다른 값·오류 조건 넷을 확인해."
④ **준비물과 사전 설정** — 오케스트레이터의 승인 기록 · 수진만 쓰기 권한 · 도윤은 읽기 전용
⑤ **정상 진행 순서** — 승인 기준 전달 → 다섯 칸 계획 제출 → 계획이 승인 범위를 넘지 않는지 확인 → 구현 → 변경 파일 확인 → 도윤 독립 QA → 승인된 수정만 반영 → 재확인
⑥ **완료 기준** — 변경이 승인 범위 안이고, 기존 흐름과 새 흐름이 모두 실행되며, QA 기록이 남았다.
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 35~60분(v3 §8.3 「오전 02:00–02:35」 · §9.4 B는 40~60분 검증을 요구)
⑧ **자주 발생하는 오류** — 승인 밖 기준을 구현 · 전체 파일을 재작성 · 도윤이 구현 파일을 수정 · 기존 흐름이 깨짐
⑨ **복구 방법** — 승인 기록에 없는 변경은 되돌린다 · 핵심 흐름이 깨지면 추가 변경을 **중단하고 시작 상태로 복구**
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — "승인 범위"의 경계를 스스로 판정하기 어려움 — 보조강사 개입 지점
⑬ **채택·보류·제외 추천과 근거** — **채택 추천.** 요청 범위를 넘는 수정이 거의 모든 주요 모델에서 관찰되는 체계적 패턴이므로(`[C-변경계약]`) 계약 없이 진행하면 실습이 무너진다. 단 **계획 모드가 작은 수정엔 순손실**이라는 반론도 함께 알린다.

## 실습6 — Computer Use 화면 QA 7항목 (5구간)

① **실습 목적** — 파일만 읽은 게 아니라 실제 화면에서 확인했다는 증거를 남긴다.
② **수강생 안내문** — "민감한 탭과 알림을 모두 닫고 내 MVP만 열어 둡니다. 대상 창과 허용할 작업을 명확히 전달한 뒤, 7항목을 통과/실패/해당없음으로 기록합니다."
③ **실제 요청문** — "이 탭의 화면에서 기존 흐름·새 흐름·다른 값·오류 조건을 실행해 결과를 알려 줘. 다른 탭은 건드리지 마."
④ **준비물과 사전 설정** — **⚠️ 계정에서 이 기능이 제공되는지 사전 확인 필수** · 민감 탭·알림·자동완성 종료 · MVP가 열린 창 하나만
⑤ **정상 진행 순서** — 민감 탭 정리 → 권한 승인 → 대상 창 지정 → 4항목 실행 → 반응형(창 폭 320px 상당까지)·키보드(Tab·초점 표시·Enter)·모션 축소(OS 설정 변경 후 새로고침)는 **사람이 직접** → 기록
⑥ **완료 기준** — 7항목이 각각 통과/실패/해당없음으로 기록되고, 실패·해당없음에 **이유와 증거 경로**가 있다.
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 20~25분(v3 §8.3 「오전 02:35–03:00」)
⑧ **자주 발생하는 오류** — **기능을 쓸 수 없음** · 다른 창을 조작함 · 권한 요청을 무조건 승인 · 실제 계정 정보가 화면에 보임 · 화면 QA가 디자인 감상으로 끝남
⑨ **복구 방법** — 대상 창을 하나로 제한 · 이해 안 되는 권한은 거절하고 더 좁게 재요청 · 계정 정보가 보이면 **실습 중지**
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — OS 접근성 설정을 여는 것 자체가 어려움 — **Windows 경로를 화면으로 안내**해야 한다(`설정 > 접근성 > 시각 효과 > 애니메이션 효과`)
⑬ **채택·보류·제외 추천과 근거** — **⚠️ 보류 — 총괄 결정 필요(D4).** 이유: ① **한국 내 이용 가능 여부를 공식 문서에서 확인하지 못했다(`[확인불가]`)** ② 기능이 **연구 미리보기·베타**라 사양이 자주 바뀐다 ③ 프롬프트 주입 취약점이 실제로 보고된 이력이 있다. **다만 표면 구분은 확인됐다 — 브라우저 확장과 데스크톱 앱은 Windows를 지원하므로 "맥 전용이라 불가"는 틀린 판단이다**(`[C-ComputerUse]`). **반응형·키보드·모션 축소 세 항목은 도구 없이도 사람이 직접 할 수 있으므로, 도구가 막혀도 7항목 수동 폴백으로 같은 학습 목표를 유지할 수 있다.**

## 실습7 — `status → add → commit → push → GitHub 확인` (6구간)

① **실습 목적** — 변경을 확인 가능한 기록으로 남기고, 완료를 **웹 화면의 커밋**으로 판정한다.
② **수강생 안내문** — "먼저 무엇이 담기는지 확인합니다. 개인정보·비밀값이 없으면 담고, 무엇을 왜 고쳤는지 한 문장으로 메시지를 씁니다. 보낸 뒤 **GitHub 화면을 새로고침**해 실제로 올라갔는지 봅니다."
③ **실제 요청문** — `git status` → `git add .`(확인 후) → `git commit -m "3주차: <행동 또는 해결한 문제>"` → `git push`
④ **준비물과 사전 설정** — **⚠️ 사전 조건: Git 실행 가능 · GitHub 로그인 · 원격 저장소 생성·연결 · 인증·기본 브랜치 확인.** 수업 중 처음부터 처리하지 않는다.
⑤ **정상 진행 순서** — 변경 목록 확인 → 공개 금지 파일 점검 → 담기 → 메시지 작성 → 커밋 → 전송 → **GitHub 웹에서 최신 커밋과 변경 파일 확인**
⑥ **완료 기준** — GitHub 화면에 방금 쓴 메시지의 커밋이 보이고 변경 파일이 반영돼 있다. **전송 성공 메시지만으로는 완료가 아니다.**
⑦ **예상 소요 범위** — `[미검증]` 설계 추정 20분(v3 §8.3 「오후 02:25–02:45」)
⑧ **자주 발생하는 오류** — **인증 실패**(Windows 대표 실패, v3 §6.3이 `[리서치 검증]`으로 지정) · `git add .`에 불필요한 파일 포함 · 메시지가 모호함 · GitHub에 커밋이 안 보임 · QA 전에 커밋하려 함
⑨ **복구 방법** — 불필요한 파일은 빼고 다시 담기 · 인증 실패는 보조강사 지원 후 재시도, 해결 안 되면 **로컬 커밋을 보존하고 강사 시연으로 대체**(D8) · 커밋이 안 보이면 원격·브랜치·전송 결과를 확인하고 **성공으로 보고하지 않는다**
⑩ **정상 완성본 위치** — 해당 없음(각자의 프로젝트가 대상)
⑪ **최소 복구본 위치** — 해당 없음 — 실패 시 완성본으로 교체하지 않고 현재 프로젝트를 최소 복구한다
⑫ **디지털 도구에 익숙하지 않은 수강생의 어려움** — 터미널 자체가 낯설다 — **화면 도구(GUI)로도 같은 3단계가 가능하므로**(`[C-Git기록]`) 폴백 경로로 준비할 수 있다
⑬ **채택·보류·제외 추천과 근거** — **채택 추천.** 단 **Windows 인증 실패·복구 재현은 사람이 반드시 검증해야 한다**(v3 §6.3). 그리고 **AI가 제안한 커밋 메시지를 그대로 쓰지 않게** 해야 한다 — 이 강의 도구의 AI 생성 커밋 메시지 고품질 비율이 31.3%로 가장 낮았다(`[C-커밋메시지]`).
