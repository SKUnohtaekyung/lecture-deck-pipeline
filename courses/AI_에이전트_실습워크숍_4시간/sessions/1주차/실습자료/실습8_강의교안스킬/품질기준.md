# 스킬 만들기 실습 · 품질 기준

이 폴더에는 `품질기준.md`(이 문서) · `규칙예시.md` · `디자인시스템_틀.md` 세 파일이 있습니다. 스킬 폴더는 비어 있고, 오늘 사용자와 함께 직접 만듭니다.

- 사용자는 코딩을 모릅니다. 쉬운 말로 설명하고, 전문 용어를 쓰면 한 줄로 풀이합니다. 풀이는 정의를 먼저, 비유를 그 다음에 씁니다.
  - 스킬: 에이전트가 일하는 순서와 규칙을 적어 둔 폴더입니다. 주방 벽에 붙여 둔 조리 순서표와 같습니다.
  - 디자인 시스템: 색 · 글자 크기 · 간격을 덱(발표 슬라이드 묶음) 전체에서 같게 쓰려고 미리 정해 둔 값의 모음입니다. 가게 직원의 복장 규정과 같습니다.
  - memory: 사용자가 고치고 고른 것을 적어 두어 새 대화에서도 다시 읽는 파일입니다. 단골 손님의 취향을 적어 둔 장부와 같습니다.
- 사실 · 숫자 · 이름 · 날짜는 사용자가 말한 것과 출처를 확인한 웹 검색 결과만 씁니다. 모르는 것은 「미확인」으로 적고 지어내지 않습니다.

## 일하는 순서

폴더에 `.agents/skills/lecture-deck/SKILL.md`가 없으면 A1부터 시작합니다. 요청받은 단계만 하고, 다음 단계는 사용자가 청할 때 시작합니다. 한 단계는 질문 → 정리나 초안 보이기 → 승인 → 저장까지이고, 저장한 내용은 다시 승인받지 않습니다.

### A. 스킬 만들기

**A1. 스킬 인터뷰.** 세 묶음으로 묻습니다.
1. 어떤 강의를 자주 만드나요 · 누가 듣나요 · 보통 몇 분에 몇 장인가요
2. 꼭 들어가는 장은 무엇인가요 · 절대 넣지 않을 것은 무엇인가요 · 말투는 어떤가요
3. 덱(발표 슬라이드 묶음)을 받을 때 내가 꼭 확인하고 싶은 것 세 가지는 무엇인가요

답을 항목별로 보이고 승인받은 뒤 `.agents/skills/lecture-deck/SKILL.md`로 저장합니다. 구성은 아래와 같습니다. Claude Code를 쓰면 같은 폴더를 `.claude/skills/lecture-deck/`에도 복사합니다.

```
---
name: lecture-deck
description: (한두 문장. 어떤 강의를 · 누구에게 · 어떤 분량으로 만들 때 쓰는지. 첫 묶음 답으로 씁니다)
---
# 강의 교안 덱
## 내 강의
- 자주 만드는 강의 · 듣는 사람 · 분량(분, 장):
- 꼭 들어가는 장:
- 절대 넣지 않을 것:
- 말투:
- 덱(발표 슬라이드 묶음)을 받을 때 확인할 것 세 가지:
## 디자인 시스템
(A2에서 고르면 「기본 디자인 시스템: 0N」 한 줄. 후보 파일은 references/design-systems/)
## 일하는 순서
(아래 B1~B7과 「점검 조건」을 그대로 옮깁니다)
## 내 규칙
(비어 있음. A3에서 채웁니다)
## memory
(A4의 두 줄)
```

**A2. 디자인 시스템 후보 3개.** 디자이너로서 묻습니다. 질문은 되묻기까지 10개 이내입니다. 항목은 분위기 · 주 색 · 글꼴 느낌 · 여백 · 움직임 · 하지 않을 것입니다. 색은 사용자가 말합니다. 사용자가 「모르겠다」 · 「예를 들어 줘」라고 하면 세 조합(이름 · 색 코드(hex) · 인상 한 줄 · 대비 값)을 보기로 보입니다.
- 답으로 `디자인시스템_틀.md`의 모든 항목을 채운 후보 세 개를 스킬 폴더 안 `references/design-systems/01.md` · `02.md` · `03.md`로 저장합니다. 세 후보는 사용자의 답을 모두 지키는 안에서 색 조합 · 글꼴 느낌 · 여백의 정도 가운데 한두 가지만 다르게 합니다. 인터뷰에서 묻지 않은 항목은 에이전트가 인터뷰 답에 맞춰 채우고 후보 파일과 승인 요청에 「(기본값)」으로 표시합니다. 사용자는 어느 값이든 바꿀 수 있습니다. 어느 후보가 좋은지는 말하지 않습니다.
- 후보마다 한 장짜리 시안 `01.html` · `02.html` · `03.html`을 같은 폴더에 만듭니다. 시안은 그 후보 파일의 값만 쓰고, 사용자가 열어 봅니다.
- 사용자가 기본 하나를 고르면 SKILL.md에 「기본 디자인 시스템: 0N」 한 줄을 적습니다. 나머지 후보는 지우지 않습니다. 강의마다 다른 번호를 고를 수 있습니다.
- 글자와 배경의 대비는 (밝은 쪽 L + 0.05) ÷ (어두운 쪽 L + 0.05)로 계산합니다. L = 0.2126R + 0.7152G + 0.0722B이고, R · G · B는 WCAG 방식으로 선형화한 0~1 값입니다. 두 색과 값을 후보 파일에 적습니다.

**A3. 내 규칙 3~5개.** `규칙예시.md`의 다섯 규칙을 한 줄씩 읽어 주고, 사용자가 3~5개를 정합니다. 규칙마다 「규칙 한 줄 + 왜 + 확인 방법」으로 적습니다. 예시를 그대로 가져가도 됩니다. 적어도 하나는 사용자 자신의 규칙이어야 합니다. 어느 규칙이 좋은지는 말하지 않습니다.
- 말투 규칙을 정할 때는 먼저 에이전트가 자기가 글을 쓸 때 자주 쓰는 말버릇 열 가지를 적어 보입니다. 예: 느낌표 · 「핵심」으로 문장 시작 · 제목 끝의 「모든 것」 · 구호 · 물건을 사람처럼 말하기 · 교훈으로 끝맺기 · 이모지 · 「놀라운」 같은 과장 · 질문으로 시작하기 · 「지금 바로」. 사용자가 이 가운데 금지할 것을 고릅니다.
- 승인받아 SKILL.md의 「내 규칙」 절에 사용자의 말 그대로 저장합니다. 두 위치에 스킬이 있으면 같은 내용으로 맞춥니다.

**A4. memory.** SKILL.md의 「memory」 절에 아래 두 줄을 적고, 스킬 폴더 안 `memory/README.md`에도 같은 두 줄을 만듭니다.
1. 강의 주제마다 `memory/<주제>.md` 한 파일을 둔다. 사용자가 고친 것 · 고른 것 · 싫다고 한 것을 사용자 말 그대로 적는다. 파일 이름은 처음 정한 주제 이름을 띄어쓰기 없이 쓴다. 새 강의를 시작할 때는 memory 폴더의 파일 목록을 먼저 보여 주고 같은 주제가 있는지 묻는다.
2. 장을 만들기 전에 그 파일을 먼저 읽는다. 다른 주제의 파일은 읽지 않는다.

### B. 스킬로 교안 만들기

SKILL.md의 「일하는 순서」에 B1~B7을 그대로 옮깁니다. 단계마다 승인을 받고, 요청받은 단계만 합니다. 결과물은 스킬 폴더 밖, 이 작업 폴더에 저장합니다.

**B1. 강의 전반 인터뷰.** 자세히 묻습니다. 먼저 memory 폴더의 파일 목록을 보여 주고 같은 주제가 있는지 묻습니다. 묶음은 아래와 같습니다.
1. 누가 듣나요 · 왜 듣나요 · 듣고 나서 할 일은 무엇인가요
2. 몇 분에 몇 장인가요 · 어디서 하나요
3. 꼭 넣을 내용 · 빼고 싶은 것 · 쉬운 예
4. 말투 · 첫 장 · 마지막 장에서 듣는 사람이 할 행동

**B2. 챕터 구축.** 전체 챕터 3~6개를 표로 보입니다. 표의 칸은 챕터 · 다루는 내용 · 장 수 · 듣는 사람이 가져갈 한 가지입니다. 장 수의 합이 B1의 장 수와 같은지 표 아래에 한 줄로 알립니다. 승인받아 `개요.md`로 저장합니다.

**B3. 리서치.** 챕터마다 사실 1~3개를 웹에서 찾고, 「출처 URL · 확인한 문장 · 날짜」를 `개요.md`의 해당 챕터 아래에 적습니다. 검색 전에는 검색어를 보이고 승인을 기다립니다. 사용자가 말한 사실은 「사용자가 말함」으로 적습니다. 찾지 못한 것은 「미확인」으로 적고 지어내지 않습니다.

**B4. 디자인 초안 1~2개.** 기본 디자인 시스템(사용자가 다른 번호를 고르면 그것)으로 1장짜리 시안을 1~2개 만들어 보입니다. 시안은 `강의덱.html`에 첫 장만 담고, 시안이 둘이면 둘째는 `강의덱_시안2.html`에 담습니다. 만들기 전에 `memory/<주제>.md`가 있으면 먼저 읽습니다.

**B5. 수정.** 사용자가 시안을 본 뒤 고칠 것을 말하면 반영하고 다시 보입니다.

**B6. memory 기록.** 수정에서 들은 것 전부를 `memory/<주제>.md`에 사용자 말 그대로 적고 보여 줍니다.

**B7. 나머지 장.** `memory/<주제>.md`와 승인된 1장의 틀로 나머지를 만듭니다. 10장을 넘으면 10장씩 만들고 「이어서 다음 장을 만들어 줘」라고 안내합니다. 다 만들면 아래 「점검 조건」으로 확인하고 결과표를 보입니다.

### 점검 조건

결과표의 칸은 항목 · 결과(맞음 / 고침 / 미확인) · 고친 곳입니다. 브라우저를 직접 볼 수 없으면 ①~③은 코드 값으로 계산해 알리고, 화면 모양은 사용자가 열어 보고 알려 달라고 청합니다. 「내 강의」에 적은 확인 세 가지도 같은 꼴로 표 끝에 더합니다.

| 항목 | 기준 |
|---|---|
| ① 화면이 깨지지 않는다 | 모든 장이 1280×720 안에 들어가고 스크롤이 없다(화면 밖으로 넘친 곳 0) |
| ② 본문 글자 하한 | 모든 본문 글자가 디자인 시스템의 하한 이상이다(기본 22px, 사용자가 정한 값이 있으면 그 값) |
| ③ 글자와 배경 대비 | 모든 글자와 배경의 쌍이 4.5:1 이상이다 |
| ④ 말투 | 「내 규칙」의 말투 금지가 한 곳도 없다 |
| ⑤ 디자인 | 고른 디자인 시스템의 색 · 글꼴 · 크기 · 간격과 같다 |
| ⑥ 개요 | `개요.md`의 챕터 · 장 수와 같다 |
| ⑦ 인쇄 | Ctrl+P 미리보기에서 장마다 한 쪽이다 |

## 인터뷰 규칙

- 에이전트는 묻고 · 되짚고 · 적습니다. 대신 정하거나 추천하지 않습니다.
- 한 번에 세 개까지 묻고, 꼬리 질문을 포함해 최대 10차례 묻습니다. 질문 하나는 결정 하나입니다. 같은 대상의 짝(분량의 분과 장)만 둘까지 묻습니다. 10차례가 차면 정하지 못한 것을 알리고 멈춥니다.
- 질문마다 쉬운 비유를 한 줄 붙입니다. 비유는 상황만 말하고, 답 후보나 한쪽으로 이끄는 말을 넣지 않습니다.
- 들은 것은 다시 묻지 않습니다. 답이 모호하면 꼬리 질문으로 확인합니다.
- 첫 장의 문장과 마지막 장의 행동 문장은 사용자가 먼저 말합니다. 에이전트는 후보를 먼저 내지 않습니다.
- 기본값은 **묻지 않은 값**에만 쓰고, 계획이나 승인 요청에 「기본값」으로 표시합니다. 사용자가 「모르겠다」 · 「예를 들어 줘」라고 하면 보기 두세 개를 보이고 **사용자가 고릅니다**. 추천하지 않습니다. 빈 답은 한 번 되묻고, 그래도 비면 보기를 보입니다. 사용자가 결정을 넘기면(「네가 정해」 「아무렇게나」 같은 말) 「모르겠다」와 같이 처리합니다.

## 승인과 안전

- 파일을 만들거나 고치기 전에 바꿀 내용을 여덟 줄 이내로 보이고 승인을 기다립니다. 인터뷰 정리 · 후보 · 개요처럼 저장할 내용 자체를 보일 때는 줄 수 제한이 없습니다.
- 개인정보 · 비밀번호 · 키를 파일에 쓰지 않습니다.
- 스킬이나 규칙이 반영되지 않은 것 같으면 사용자에게 새 대화를 열라고 안내합니다. 새 대화에서는 「`.agents/skills/lecture-deck/SKILL.md`를 읽고 그 순서대로 해 줘」라고 말합니다.
