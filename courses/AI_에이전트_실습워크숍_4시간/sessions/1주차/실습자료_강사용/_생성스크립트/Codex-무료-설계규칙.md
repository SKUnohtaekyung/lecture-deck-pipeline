# Codex 무료 요금제 설계 규칙 (실습 준비물 공통)

> 2026-10-20 신설 · **2026-10-21 2판**(사용자 「html 코드를 주면 그냥 붙여넣기 하게 되는거잖아. 처음부터 학생들이 만들게 해야지」 · 공식 문서 대조로 「에이전트는 브라우저를 못 본다」 서술 폐기). 근거 `plans/FRAME-실습강화/P3-P4-P7-설계.md` §0 · `P5-설계.md` §10 · `sessions/1주차/자료/출처.md` S66~S74.
> 새 실습을 만들거나 기존 실습의 준비물을 고칠 때 이 표를 먼저 본다. 기준선(턴 수 · 시간)은 `../드라이런_기록.md`의 사용자 실측으로만 바꾼다.

## 왜 필요한가

Codex 무료는 ChatGPT 데스크톱 앱에서 쓰고, 한도 수치가 공개되지 않았다(5시간 창 + 주간 상한 구조만 공개). 참가자 모델은 Claude보다 덜 강하다. 그래서 두 가지를 함께 줄인다.

- **결정** — 디자인 · 타이밍 · 호출 주소처럼 모델이 스스로 정하면 무너지는 것을 준비물 md에 이름과 문장으로 고정한다. 완성 코드를 주지 않는다(학생이 처음부터 만든다).
- **토큰** — 모델이 읽는 양과 대화 턴 수를 설계로 줄인다.

## 규칙 7가지

| # | 규칙 | 준비물에서 지키는 방법 | 점검 |
|---|---|---|---|
| 1 | 에이전트가 읽는 파일 합계 15KB 이하 | 준비물은 md(품질기준 · 이름표 · 자료 설명)와 데이터 `.js`뿐이다. **완성 도구 HTML · 코드 틀을 넣지 않는다.** 큰 데이터 파일은 「통째로 읽지 않는다」를 적고 모양은 설명 md에 둔다 | 품질기준 + 이름표 + 설명 md 크기 합 |
| 2 | 결정은 이름으로 고른다 | 이름표 문서 3KB 이하(이름과 한 줄 뜻). 호출 주소 · 지도 그림 주소처럼 틀리면 막히는 값은 설명 md에 미리 채워 둔다 | 대리 시험에서 지어낸 이름 · 주소를 센다 |
| 3 | 인터뷰는 한 번에 질문 세 개 · 최대 10번(2026-10-07) · 질문마다 쉬운 비유 한 줄 · 결과물의 설계 결정을 묻는다 · 디자이너 인터뷰는 질문 모두 합쳐 10개(2026-10-21) | 질문표를 세 개씩 「묶음」으로 짠다. 괄호 예시는 사용자가 청할 때만 | 대리 시험과 드라이런에서 차례 수 · 질문 수 · 비유 수를 센다 |
| 4 | 첫 단계만 만들고 승인받은 뒤 나머지 · 파일을 바꾸기 전에 여덟 줄 이내 계획 · 인터넷 명령 전에 주소 | 장면 1 · 장 1 · 화면 1 · 카드 두 장부터 | 품질기준 「승인」 · 「일하는 순서」 |
| 5 | 화면 확인은 학생이 하고, 에이전트는 파일로 대조한다 | 브라우저 기능을 켜면 에이전트도 화면을 볼 수 있다(S69 · S71). 수업에서는 켜지 않으므로 학생이 본 것을 말로 전하고, 에이전트는 화면의 숫자 · 사실을 자료 파일과 대조한다 | 마지막 단계에 대조 한 가지 |
| 6 | 설치 0 · 더블클릭으로 열림 · 한 파일로 되면 한 파일(profile §9) | 데이터는 `.js`로 둔다 — 더블클릭(file://)으로 연 페이지는 옆의 `.json` · `.csv`를 못 읽는다. 외부 스크립트는 지도 라이브러리(Leaflet) 한 벌까지. 지도 그림은 Referer 없이도 되는 주소(`tile.openstreetmap.fr/hot` · S74 실측) · Windows 명령은 `curl.exe` · `Invoke-RestMethod` | 대리 시험 산출물의 외부 스크립트 수 |
| 7 | 한도가 다 되면 다른 도구로 이어 간다 | 상태는 전부 폴더 안 파일에 있다. 품질기준 끝에 「이어가기」 절을 둔다 | 드라이런 기록의 한도 경고 열 |

## 품질기준 첫머리에 넣을 문장(공통)

```
이 폴더에서 에이전트가 읽는 파일은 품질기준.md와 이름표 · 설명 문서, 사용자가 준 자료입니다.
결과물은 사용자와 인터뷰한 내용으로 처음부터 만듭니다. 화면은 사용자가 브라우저로 보고, 본 것을 말로 전해 줍니다.
```

## 대리 시험 프로토콜(메인 실행 · 연기 시험)

참가자 도구로 돌린 결과가 아니다. 동작 · 읽기량 · 턴 수가 설계대로인지만 본다.

1. 서브에이전트에게 실습 폴더 사본(`tmp/frame-실습강화/dry/<실습>/`)과 학생 답안지를 준다. 에이전트 역은 폴더의 품질기준(또는 AGENTS.md)만 따른다.
2. 센다: 읽은 파일 이름과 KB · 인터뷰 차례 · 질문 수 · 비유 수 · 강사 세팅이 분석 답에 나왔는지 · 만든 파일 · 외부 스크립트 수 · 지어낸 사실.
3. 기준을 넘으면 준비물을 고친다. 모델 탓으로 넘기지 않는다.
4. 통과해도 「검증 완료」로 적지 않는다. 사용자 드라이런(Codex 무료 · Antigravity)이 검증이다.
