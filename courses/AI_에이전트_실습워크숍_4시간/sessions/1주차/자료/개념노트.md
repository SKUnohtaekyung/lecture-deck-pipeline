## 블록 1 — AI가 답을 만드는 방식 · 프롬프트

### K01 다음 말 예측 · 확률
- **정의**: AI는 지금까지의 글 뒤에 올 다음 조각을 확률에 따라 하나씩 골라 이어 붙여 답을 만듭니다.
- **비유**: 휴대폰 자동완성 추천어를 수백 번 이어서 누르는 것. (예비: 후보 중 확률대로 뽑는 제비뽑기)
- **사실**: 모델은 사전학습에서 앞 문맥이 주어졌을 때 다음 단어를 예측하도록 훈련된다(S01). 무작위성을 조절하는 temperature를 0으로 두어도 출력이 완전히 같다고 보장되지 않는다(S01).
- **시각 자료**: 다음 말 후보 확률 막대 + 「다음 말 뽑기」. ⚠️ 막대 값은 **설명용 예시값**이다 — 화면에 「예시 값」이라고 적는다(E3 「출처 검증값만」 규칙의 예외로 결정표에 명시).
- **체험 후보**: 같은 질문(「봄을 주제로 두 줄 시」)을 새 대화에서 3번 → 답 비교.

### K02 토큰
- **정의**: 토큰은 AI가 글을 읽고 쓰는 가장 작은 단위입니다. 단어 하나가 토큰 하나와 같지 않습니다.
- **비유**: 문장을 레고 조각으로 나눠 세는 것. 조각 크기는 언어마다 다릅니다.
- **사실**: 토큰은 단어 · 하위 단어 · 문자 · 바이트에 대응할 수 있는 가장 작은 단위이고, Claude 기준 영어는 토큰 하나가 약 3.5자다(S01). 토크나이저가 바뀌면 같은 글도 토큰 수가 달라진다 — Claude 4.7 이후 새 토크나이저는 약 30% 더 많이 나온다(S02).
- **시각 자료**: 문장이 조각으로 나뉘는 코드 시각화. 예시 「ChatGPT는 놀랍다 → Chat / GPT / 는 / 놀랍 / 다」는 이 저장소의 설명용 분할이다(S20) — 실제 토크나이저 결과처럼 쓰지 않고 「예시」로 표기한다.

### K03 지식 마감일
- **정의**: 지식 마감일은 AI가 학습한 자료가 끝나는 시점입니다. 그 뒤의 일은 검색이나 문서로 알려 주지 않으면 모릅니다.
- **비유**: 어느 날짜에 인쇄를 마친 백과사전.
- **사실**: 모델 개요 페이지는 「신뢰할 수 있는 지식 마감일」과 「학습 데이터 마감일」을 따로 공개한다(S03). 화면에는 모델 이름·날짜 대신 「모델 개요 페이지에 공개」로 쓴다(모델이 바뀌면 낡는다).
- **시각 자료**: 시간축 + 마감 표시선, 선 뒤 사건은 흐리게.
- **체험 후보**: 웹 검색을 끈 상태와 켠 상태로 「오늘 날짜와 최근 뉴스」 비교.

### K04 환각
- **정의**: 환각은 사실이 아닌 내용을 사실처럼 만들어 내는 현상입니다.
- **비유**: 빈칸 채우기 문제에서 문맥에는 맞지만 정답은 아닌 말을 써 넣는 것.
- **사실**: 2023-06-22 미국 뉴욕 남부연방지법은 존재하지 않는 판례를 인용한 서면을 낸 변호사 2명과 로펌에 5,000달러 제재를 내렸다(Mata v. Avianca · S04). 「가짜 판례 6건」 수치와 「ChatGPT에 진위를 되묻자 실제라고 답했다」는 대목은 **판결문 확인 전 쓰지 않는다**(S05 사람 확인).
- **시각 자료**: 그럴듯한 답 vs 실제 확인 결과 — 「출처 확인」 클릭 시 없는 판례 표시.
- **비유 제외**: 「모르는 길을 그럴듯하게 안내하는 사람」 · 「목격자 진술」(AI를 사람으로 그림).

### K05 아첨
- **정의**: 아첨은 사용자의 의견에 맞춰, 정확한 평가보다 듣기 좋은 답을 내놓는 경향입니다.
- **비유**: 「~맞죠?」로 끝나는 유도 질문 설문지 — 질문에 답이 들어 있으면 「예」가 많이 나옵니다.
- **사실**: 사람의 선호 피드백으로 학습하면 진실보다 사용자의 믿음에 맞는 응답이 늘 수 있고, 주요 AI 어시스턴트 5개에서 이 경향이 일관되게 관찰됐다(S08 · ICLR 2024). 2025년 4월 GPT-4o 업데이트가 지나치게 동조하는 쪽으로 바뀌어 4월 29일 롤백됐다(S06). OpenAI 원문 문장 인용은 S07 확인 뒤.
- **대응 문장(사용자 제시 예문)**: 의견을 물을 때는 내 생각을 밝히지 않고 먼저 장단점을 요청합니다.
- **시각 자료**: 같은 질문 두 답을 나란히 — 「맞죠?」 붙이기 토글.
- **체험**: 같은 문단을 「제가 쓴 건데 최고죠?」 / 「문제점을 찾아 줘」로 평가시켜 비교.
- **비유 제외**: 「무슨 말에도 좋다고 하는 부하 직원」 · 「판매원」(AI를 사람으로 그림).

### K06 요청문 네 칸(프롬프트 엔지니어링)
- **정의**: 프롬프트 엔지니어링은 AI에게 건네는 요청문을 목적 · 입력 · 출력 · 확인 네 칸이 빠지지 않게 쓰는 일입니다.
- **비유**: 택배 송장 — 받는 곳 · 물건 · 포장 · 수령 확인 칸이 정해져 있어 빠진 칸이 바로 보입니다.
- **사실**: 네 칸 구성은 **이 강의의 정리**다. 바이브코딩 1주차의 4요소(명확성 · 역할 · 조건 · 출력형식)를 이 과목용으로 다시 묶었다(S20). 칸 이름은 B1 결정표에서 확정.
- **시각 자료**: 네 칸이 요청문 한 줄로 조립되는 도식 — 칸 클릭 시 요청문의 해당 부분 표시. 요청문은 터미널 UI(D32).

## 블록 2 — 컨텍스트

### K07 컨텍스트 · 대화 창의 한계
- **정의**: 컨텍스트는 AI가 답하는 순간 볼 수 있는 정보 전체입니다(대화 내용 · 첨부 파일 · 규칙). 컨텍스트 엔지니어링은 여기에 무엇을 넣고 뺄지 정하는 일입니다.
- **비유**: 시험장에 들고 갈 수 있는 요약 노트 한 장 — 크기가 정해져 있어 무엇을 적을지 골라야 합니다.
- **사실**: 컨텍스트는 넣을수록 효용이 줄어드는 유한한 자원이고, 컨텍스트 엔지니어링은 프롬프트 엔지니어링의 자연스러운 다음 단계다(S11 · 2025-09-29). Karpathy의 정의 문장은 원문 확인 전 인용하지 않는다(S16).

### K08 중간 유실
- **정의**: 중간 유실은 긴 자료를 주면 앞부분과 끝부분은 잘 활용하고 가운데 정보는 더 자주 놓치는 현상입니다.
- **비유**: 긴 회의록을 한 번 훑으면 첫 안건과 마지막 결론은 기억나는데, 중간에 바뀐 결정은 흐릿합니다.
- **사실**: Liu 외(2023) — 문서 20개(약 4천 토큰) · GPT-3.5-Turbo 조건에서 답이 든 문서가 첫 번째일 때 정답률 75.8%, 열 번째 53.8%, 스무 번째 63.2%, 문서 없이 답했을 때 56.1%(S09 · 수치는 S20 정리와 대조). 가운데일 때는 자료를 주지 않았을 때보다 낮았다.
- **대응**: 꼭 지킬 조건은 요청문 맨 앞이나 맨 뒤에 씁니다. 긴 자료는 나눠서 줍니다.
- **시각 자료**: 예시 v2 C-04(위치별 정답률 막대 · 막대 클릭 → 문서 20개 중 위치 표시).
- **개념 파트에서 쓸 수 있는 예**: 실습 1 자료처럼 긴 메모 가운데서 마감이 바뀌는 경우(D31 — 반대로 실습 장에는 이 개념을 쓰지 않는다).

### K09 길어질수록 흐려짐 · 새 대화로 끊기
- **정의**: 대화와 자료가 길어질수록 AI가 앞 내용을 정확히 활용하는 정도가 떨어집니다. 주제가 바뀌면 새 대화를 엽니다.
- **비유**: 서류가 쌓인 책상에서 필요한 한 장을 찾는 것.
- **사실**: Chroma(2025-07-14)는 모델 18개에서 단순한 과제도 입력 길이에 따라 성능이 크게 달라진다고 보고했다(S10). Anthropic은 컨텍스트의 토큰이 늘수록 회상 능력이 떨어진다고 설명한다(S11). 2026년 모델에서 얼마나 줄었는지는 **미확인** → 화면에 「2025년 연구 시점 모델 기준」을 적는다.
- **시각 자료**: 책상 위 서류가 쌓이는 도식 — 서류 추가 시 가운데부터 흐려짐.
- **체험 후보**: 긴 대화 끝에서 「처음 말한 조건 세 가지」 요청 vs 새 대화 비교.

## 블록 3 — 에이전트와 하네스

### K10 에이전트
- **정의**: 에이전트는 결과를 보며 다음 행동을 정해 읽기 · 계획 · 실행 · 확인을 되풀이하는 AI 프로그램입니다(S72 · 2026-10-21 고침).
- **비유**: 내비게이션 — 목적지를 넣으면 길을 고르고, 막히면 다시 계산합니다. (세탁기 코스는 순서가 고정된 워크플로에 가까워 2026-10-21에 바꿨다 · S72)
- **사실**: Codex는 기본 설정에서 작업 폴더 안 파일 수정은 자동으로 하고, 폴더 밖 수정 · 네트워크 · 제한 명령은 승인을 요청한다(S28). Claude Code 데스크톱의 승인 모드는 Manual · Accept edits · Plan · Auto · Bypass permissions다(S29). Antigravity는 허용 · 확인 · 거부 목록과 프리셋을 쓰고, Windows는 macOS와 설정 구성이 다르다(S30).
- **시각 자료**: 읽기 → 계획 → 실행 → 확인 순환 도식(단계가 차례로 켜짐).

### K11 하네스
- **정의**: 하네스 엔지니어링은 AI가 일하는 동안 쓰는 도구 · 규칙 · 권한 · 확인 절차를 설계해 같은 실수가 되풀이되지 않게 하는 일입니다.
- **비유**: 말에 채우는 마구(harness) — 힘은 말이 내고, 방향과 범위는 마구가 정합니다.
- **사실**: Hashimoto(2026-02-05)는 에이전트가 실수할 때마다 재발 방지책을 만든다고 쓴다 — 간단하면 AGENTS.md를 고치고, 복잡하면 검증 도구를 만든다(S17). Böckeler(2026-04-02)는 하네스를 「모델을 뺀 에이전트의 나머지 전부」로 설명한다(S19). OpenAI 글(S18)은 원문 확인 전 인용하지 않는다.
- **그림은 「에이전트 = 모델 + 하네스」로 한다**(2026-10-06 사용자 위임 → 조사 후 판단). 근거: LangChain 「Agent = Model + Harness」(S40) · Böckeler 「모델을 뺀 나머지 전부」(S19) · Claude Code 문서가 모델을 둘러싼 층(도구 제공 · 컨텍스트 관리)을 하네스라 부른다(S41).
- **세 겹 포함 그림(프롬프트 ⊂ 컨텍스트 ⊂ 하네스)은 쓰지 않는다.** 종전 결정(「이 강의의 정리」로 밝히고 사용 · S20)을 대체한다. 이유: ① 세 겹 포함을 말하는 1차 출처를 찾지 못했다(Anthropic이 말한 것은 프롬프트 → 컨텍스트의 「진행」까지) ② 프롬프트 · 컨텍스트는 모델에 들어가는 글이고 하네스는 모델을 둘러싼 프로그램이라 종류가 다르다 ③ 권한 · 샌드박스 · 반복 실행은 컨텍스트 밖에서 동작한다 ④ Böckeler 4월 글은 사용자 하네스를 컨텍스트 엔지니어링의 한 형태로 써서 포함 방향이 반대다. 말로 「관심 범위가 프롬프트 → 컨텍스트 → 하네스로 넓어졌다」고 덧붙이는 것은 괜찮다. ⚠️ 「표준 용어가 아니다」 같은 문장은 넣지 않는다(커밋 `d8b30b9` 사용자 결정).
- **시각 자료**: 모델 + 하네스 등식 그림(하네스 안에 도구 · 규칙 · 권한 · 확인 절차) · 규칙 파일 · 승인 · 점검표 · 되돌리기 배치도(항목 클릭 → 설명).
- **비유 제외**: 「도구 = AI의 손발」(바이브코딩 2주차 · AI를 사람으로 그림).

### K12 규칙 파일
- **정의**: 규칙 파일은 에이전트가 작업에 들어가면 읽는 지시 문서입니다(Codex는 작업 전에, Antigravity는 파일을 읽거나 고칠 때 폴더를 거슬러 올라가며 읽는다 · 2026-10-21 고침). 폴더에 두면 같은 조건을 매번 다시 쓰지 않아도 됩니다.
- **비유**: 가게 문에 붙인 이용 안내문 — 들어오는 사람마다 따로 설명하지 않아도 됩니다.
- **사실**: Codex는 AGENTS.md를 읽는다(전역 파일 + 저장소 루트부터 현재 폴더까지 병합 · 기본 32KiB)(S28). Claude Code는 CLAUDE.md를 읽고, CLAUDE.md가 없으면 AGENTS.md를 직접 읽는다(v2.1.277+). 둘 다 있으면 CLAUDE.md만 읽으므로 CLAUDE.md에 `@AGENTS.md` 한 줄을 둔다(S29 · D9). Antigravity 문서는 AGENTS.md · GEMINI.md · `.agents/rules/`를 안내하지만 **2.0 앱에서의 동작은 미확인** → 리허설(GR)에서 확인(S30).

### K13 승인 · 되돌리기
- **정의**: 승인은 에이전트가 파일을 바꾸거나 명령을 실행하기 전에 사람이 허락하는 단계입니다. 되돌리기는 바뀐 파일을 이전 상태로 돌리는 방법입니다.
- **비유**: 문서 편집기의 「변경 내용 추적」 — 고친 곳이 표시되고, 하나씩 수락하거나 거부할 수 있습니다.
- **사실**: 도구마다 승인 방식이 다르다(K10 사실 · S28~S30). **도구별 되돌리기 방법은 미조사 · 미확인** → A6 보강 조사 또는 리허설(GR)에서 확인. 확인 전에는 「작업 전 폴더를 복사해 둔다」만 안내한다.
- **시각 자료**: K11 배치도의 한 칸.

### K14 점검표
- **정의**: 점검표는 결과를 받은 뒤 확인할 항목을 미리 적어 둔 목록입니다.
- **비유**: 비행기 이륙 전 점검 목록 — 기억에 기대지 않고 목록을 따라 확인합니다.

### K15 문서 속 숨은 지시(프롬프트 인젝션)
- **정의**: 프롬프트 인젝션은 AI가 읽는 문서나 웹페이지 속에 숨은 지시문을 사용자의 지시처럼 따르게 되는 문제입니다.
- **비유**: 우편물 자동 분류기가 봉투에 누군가 적어 둔 「이 편지는 VIP 칸으로」 문구를 보고 그대로 분류하는 것.
- **사실**: Brave(2025-08-20)는 Perplexity Comet 브라우저가 Reddit 댓글에 숨긴 글을 따라 계정 이메일과 일회용 비밀번호를 빼낼 수 있음을 개념 증명으로 보였다(S12). Unit 42(2026-03-03)는 실제 웹에서 글자 크기 0 · CSS 숨김으로 넣은 지시를 관찰했다(S13).

## 블록 4 — 생각의 외주화

### K16 생각의 외주화 — 연구 결과
- **정의**: 생각의 외주화는 판단 · 정리 · 글쓰기처럼 생각하는 일을 AI에게 맡기는 것입니다.
- **비유**: 계산기만 쓰다 보면 암산할 일이 줄어드는 것.
- **사실**
  - MIT Media Lab(Kosmyna 외, 2025 · S21): 에세이 쓰기 과제에서 LLM을 쓴 집단은 도구 없이 쓴 집단보다 뇌 연결성이 약했고, 자기 글에 대한 소유감과 회상이 낮았다. 참가자 1~3회차 54명 · 4회차 18명, 동료심사 전 논문. ⚠️ 저자가 피해 달라고 한 표현 — 「멍청해진다」 「뇌 손상」 「brain rot」 「뇌 스캔」 「생각을 멈추게 한다」 — 을 쓰지 않는다. 표본 · 과제 한정 · 동료심사 전을 같은 장에 적는다.
  - Microsoft Research · CMU(Lee 외, CHI 2025 · S22): 지식노동자 319명 · 사례 936건 설문에서 AI를 더 신뢰한다고 답한 사람일수록 비판적 사고를 덜 했다고 답했고, 자기 능력에 자신 있는 사람일수록 더 했다고 답했다. 자기보고 · 상관 연구 → 인과 표현 금지.
  - Gerlich(2025 · S25): 정정문 내용을 확인하기 전에는 수치를 쓰지 않는다.
- **시각 자료**: 맡길 일 / 직접 할 일 2축 배치(참가자 답을 강사가 칸에 배치).

### K17 영상 화두 — 제외(D38)
- 영상 두 편(S26 · S27)은 덱에서 소개하지 않는다(D38 · 2026-10-01). 영상이 다루는 주제 가운데 쓸 만한 내용은 확인된 연구로 대신한다 — K16의 MIT 연구(C-21)와 Bastani 외(S33 · C-20).
### K18 자동화 편향
- **정의**: 자동화 편향은 기계나 AI가 낸 답을 확인하지 않고 그대로 받아들이는 경향입니다.
- **비유**: 맞춤법 검사기가 빨간 줄을 긋지 않으면 틀린 곳이 없다고 여기는 것.
- **사실**: Goddard 외(2012 · S14)는 임상 의사결정 지원 연구 74개를 검토했다. 메타분석 4건에서 지원 체계를 쓴 쪽이 틀린 조언을 26% 더 따랐고, 맞았던 결정이 틀린 결정으로 바뀐 비율은 6~11%였다. Parasuraman & Manzey(S15)는 인용하지 않는다.
- **시각 자료**: K19와 함께 — 예상 vs 체감 vs 실제 막대.

### K19 체감과 실측(METR)
- **정의**: AI를 써서 빨라졌다는 느낌과 실제로 잰 시간은 다를 수 있습니다.
- **비유**: 내비게이션 우회로 — 차가 계속 움직여 빨라 보이지만 도착은 더 늦은 경우.
- **사실**: METR(2025-07-10 · S23) 숙련 개발자 16명 · 이슈 246건 무작위 실험에서 AI를 허용한 작업이 19% 더 오래 걸렸다. 참가자는 시작 전 24% 빨라질 것으로 예상했고, 끝난 뒤에도 20% 빨라졌다고 믿었다. METR은 대부분의 개발자를 느리게 한다는 증거가 아니며 다른 분야로 일반화할 수 없다고 밝혔다. 후속(2026-02-24 · S24)에서는 재실험 추정치가 선택 편향으로 믿기 어렵고, 지금은 향상이 더 클 수 있다고 적었다.
- **쓰는 방식**: 「AI를 쓰면 느려진다」로 일반화하지 않는다. 체감과 실측의 차이를 보이는 용도로만 쓰고, 조건(16명 · 2025년 초 도구 · 자기 저장소)과 후속 연구를 같은 장에 적는다.
- **시각 자료**: 예상(−24%) · 체감(−20%) · 실제(+19%) 소요 시간 막대 — 차례로 등장, 세로축 0부터.

### A1 API 정의와 실물
- **정의**: API는 한 프로그램이 다른 프로그램의 기능이나 자료를 쓸 수 있게 정해 둔 요청 방식입니다. 사람은 화면을 눌러 쓰고, 프로그램은 API로 요청합니다(S42).
- **비유**: 택배 접수 창구. 정해진 송장 칸(받는 곳 · 무게)을 채워 내면 정해진 모양의 접수증이 돌아옵니다. 창구 안에서 무슨 일이 일어나는지는 몰라도 됩니다. (예비: 콘센트 규격 — 모양이 맞으면 어느 기기든 꽂는다)
- **사실**: MDN은 API를 사람용 화면과 대비되는 「소프트웨어를 통한 상호작용」을 위한 기능과 규칙의 묶음으로 정의한다(S42). 웹에서는 주소(URL)로 부르는 API가 흔하지만, 브라우저 안의 기능처럼 주소 없이 부르는 API도 있다(S42).
- **실물(강사 시연 · 키 없음)**: 주소 `https://api.open-meteo.com/v1/forecast?latitude=37.57&longitude=126.98&daily=temperature_2m_max&timezone=Asia/Seoul` → 응답 토막 `"daily":{"time":["2026-10-20",…],"temperature_2m_max":[20.4,14.9,13.8,…]}`(S45 · 2026-10-20 실측 — 수업 당일 값으로 다시 연다).
- **흔한 오해**: ① 「API = 웹 주소」 → 주소는 API를 부르는 한 방법이다. ② 「부르면 늘 자료가 온다」 → 권한이 없거나 너무 자주 부르면 오류가 온다(A2 · A4).
- **시각 자료**: 주소 한 줄(왼쪽) → 창구 → 응답 토막(오른쪽). 주소 조각마다 색 밑줄(A2에서 풀이).

### A2 요청과 응답 · JSON
- **정의**: 요청은 주소와 그 뒤에 붙인 조건(`?이름=값&이름=값`)입니다. 응답은 상태 번호와 내용입니다. 내용은 흔히 JSON — 「이름: 값」 묶음과 값의 목록을 글자로 적은 형식 — 으로 옵니다(S46 · S47).
- **비유**: 송장과 접수증. 송장 칸 이름이 매개변수, 칸에 쓴 글이 값입니다. 접수증 맨 위의 「접수 완료 / 반송」 도장이 상태 번호입니다.
- **사실**: 요청은 늘 클라이언트(브라우저)가 먼저 보낸다(S46). 쿼리 문자열은 `?key1=value1&key2=value2`처럼 `&`로 이은 이름/값 쌍이고 뜻은 서버마다 다르다(S46). JSON의 값은 문자열 · 숫자 · true · false · null · 객체 · 배열이다(S47). 상태 번호: 200 성공 · 403 권한 없음 · 404 찾을 수 없음 · 429 너무 자주 요청함(S46 · S56). 2xx는 성공, 4xx는 요청 쪽 문제, 5xx는 서버 쪽 문제다(S46).
- **흔한 오해**: ① 「응답이 왔으면 성공」 → 4xx · 5xx도 응답이다. 번호를 먼저 본다. ② 「JSON은 프로그램 코드」 → 글자로 적은 자료다. 프로그램이 읽을 때 객체로 바꾼다(S47).
- **시각 자료**: 주소 해부(기본 주소 · 물음표 · 이름=값 네 쌍) + JSON 토막의 이름 · 값 · 목록에 꼬리표.

### A3 키와 인증
- **정의**: API 키는 누가 요청하는지 서버에 알려 주는 긴 문자열입니다. 서버는 키로 허락 여부를 정하고, 키마다 호출 횟수를 셉니다(S48 · S49).
- **비유**: 이름이 적힌 출입증. 출입증이 있어야 문이 열리고, 출입 기록은 그 이름으로 남습니다. 남이 주우면 내 이름으로 드나듭니다.
- **사실**: TourAPI 키는 공공데이터포털에서 활용신청으로 받는다. 개발 단계는 자동 승인이고 개발계정은 하루 1,000회다(S48). 등록되지 않은 키는 코드 30 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, 하루 한도 초과는 코드 22다(S49). 웹 페이지에 그대로 실린 키는 누구나 볼 수 있다 — Google은 공개되는 키에 사용처 제한을 걸고, 제한 없는 키의 남용 비용은 키 주인이 진다고 적는다(S51). 그래서 이 앱은 키를 파일에 쓰지 않고 화면 입력 칸에 넣어 그 브라우저에만 저장한다. 브라우저 저장소도 같은 주소의 스크립트는 읽을 수 있으므로 민감 정보 저장은 피하라는 것이 OWASP의 권고다(S59) — 수업 키는 무료 · 읽기 전용이라 이 방식을 쓴다(이 강의의 정리).
- **미확인**: 신청 뒤 키가 동작하기까지 걸리는 시간 — 키는 수업 전날까지 받아 둔다.
- **흔한 오해**: ① 「키는 비밀번호라 숨겨진다」 → 화면 코드에 넣으면 공개 주소에서 누구나 본다. ② 「키 오류 = 키를 잘못 복사」 → 승인이 아직 반영되지 않았거나, 이미 인코딩된 키를 한 번 더 인코딩해도 같은 오류가 난다(S50 · 경험 진술).
- **시각 자료**: 출입증 카드(이름 · 하루 1,000회) + 「파일에 쓰기 ✕ / 입력 칸 → 이 브라우저 ○」 두 갈래.

### A4 창구의 규칙 — CORS · 호출 한도 · 이용 약관
- **정의**: 웹 페이지가 다른 주소의 API를 부르면, 받는 서버가 응답에 「이 주소는 읽어도 된다」는 허락을 적어 줘야 브라우저가 그 응답을 페이지에 넘깁니다. 이 규칙이 CORS입니다. 창구마다 하루에 부를 수 있는 횟수와 쓸 수 있는 목적도 정해져 있습니다(S52 · S44).
- **비유**: 건물 안내 데스크와 방문증. 택배(응답)는 건물까지 오지만, 안내 데스크(브라우저)는 받는 사람 이름이 적힌 방문증(허락 표시)이 있어야 올려 보냅니다. (한도 비유: 도서관 하루 대출 권수)
- **사실**: 다른 출처의 응답을 읽는 것은 기본적으로 막혀 있고, 서버가 `Access-Control-Allow-Origin`으로 허락해야 스크립트가 읽는다(S52). 막는 쪽은 브라우저이고, 막혔을 때 페이지 코드는 자세한 이유를 알 수 없다(S52). 더블클릭으로 연 페이지(file://)는 출처가 null로 간다(S52). 이 앱의 창구는 허락이 확인됐다: Open-Meteo `*`(S45) · Nominatim `*`(S65) · TourAPI는 요청한 출처를 그대로 돌려준다(조사결과 §1). 한도: Open-Meteo 무료는 비상업 · 하루 10,000회 미만(S44), TourAPI 개발계정 하루 1,000회(S48), Nominatim 초당 1회 · 앱 식별 · 입력 중 자동완성 금지(S53). 너무 자주 부르면 429가 온다(S56). 한도는 IP 단위라 한 교실이 같은 인터넷을 쓰면 합쳐질 수 있다(추정 — 약관은 「IP · 앱 단위」까지).
- **흔한 오해**: ① 「CORS는 서버를 지키는 자물쇠」 → 요청은 서버에 닿는다. 막는 것은 브라우저가 다른 사이트의 응답을 페이지에 넘기는 일이다. ② 「막히면 서버가 나를 거부한 것」 → CORS 실패는 브라우저의 판단이고, 403은 서버의 거부다. 도구의 창구 패널은 둘을 다르게 적는다.
- **시각 자료**: 브라우저 ↔ 서버 왕복 그림에서 응답 머리의 허락 줄 하나가 켜지면 통과, 꺼지면 데스크에서 멈춤 + 창구 셋의 한도 표.

### A5 데이터의 범위와 빈 값
- **정의**: API가 주는 자료에는 범위가 있고, 범위 밖이나 없는 값은 오류 · 빈칸으로 옵니다. 앱은 빈 것을 지어내지 않고 「없음」으로 보여 줘야 합니다(S43 · S56).
- **비유**: 앞쪽 몇 장만 인쇄된 탁상 달력. 인쇄 범위 밖 장을 넘기면 빈 종이입니다. (예비: 메뉴판의 「품절」 표시 — 칸은 있는데 내용이 비었음을 알린다)
- **사실**: Open-Meteo 예보는 기본 7일 · 최대 16일이다(S43). 날짜를 지정해 범위 밖을 부르면 400과 허용 범위가 적힌 `reason`이 온다 — 2026-10-20 실측 「from 2026-07-18 to 2026-11-03」(S45). 과거 재분석 · 기후 예측 API가 따로 있지만 예보가 아니다(S57). null은 「값이 의도적으로 없음」을 뜻한다(S56). TourAPI는 0건이면 목록이 빈 문자열로, 1건이면 목록이 아닌 하나로 온다는 실무 후기가 있다(S50 · 경험 진술). 축제 목록에는 여행 시작 전에 끝나는 축제 · 좌표가 빈 항목이 섞일 수 있어 도구가 걸러 낸 개수를 보여 준다(설계 J4).
- **흔한 오해**: ① 「날짜만 넣으면 날씨가 나온다」 → 예보 범위 밖은 오류다. ② 「비슷한 해의 평균을 넣으면 된다」 → 평년값은 예보가 아니다. 화면에 「예보 없음」.
- **시각 자료**: 날짜 띠(오늘 → +16일 칠함 · 그 밖 회색 「예보 없음」) + 빈 값 세 종류(빈 칸 · 끝난 축제 · 0건) 카드.

### A6 상태 저장 — 브라우저가 기억한다(localStorage)
- **정의**: localStorage는 웹 페이지가 이 브라우저 안에 이름표 붙은 글자를 저장해 두는 곳입니다. 창을 닫아도 남고, 주소(출처)마다 따로 있습니다(S58).
- **비유**: 이 집 현관의 우편함. 이 집 열쇠로만 열리고, 다른 집 · 다른 동네(다른 기기)로 따라오지 않습니다.
- **사실**: 저장 값은 문자열이고 만료가 없다(S58). 출처마다 약 5MiB까지다(S58). 사생활 보호 창은 마지막 탭을 닫으면 지워진다(S58). 더블클릭으로 연 파일(file:)에서의 동작은 정해져 있지 않고 브라우저마다 다르다 — 파일을 옮기거나 이름을 바꾸면 담은 목록이 안 보일 수 있다(S58). 민감 정보는 넣지 않는 것이 권고다(S59).
- **흔한 오해**: ① 「저장했으니 어디서나 보인다」 → 이 기기 · 이 브라우저 · 이 주소에서만. ② 「영구 보관」 → 브라우저 데이터 삭제 · 저장 공간 정리로 사라질 수 있다.
- **시각 자료**: 브라우저 그림 안의 서랍 세 칸(키 · 담은 곳 · 지명 캐시) + 다른 기기 그림에는 빈 서랍.

### A7 지도와 좌표
- **정의**: 위도는 적도에서 남북으로, 경도는 본초 자오선에서 동서로 떨어진 정도를 나타내는 숫자입니다. 지도 앱은 두 숫자의 쌍으로 장소를 찍습니다(S60 · S61).
- **비유**: 극장 좌석표의 행과 열. 순서를 바꿔 적으면 전혀 다른 자리에 앉게 됩니다.
- **사실**: 지도 라이브러리 Leaflet은 `[위도, 경도]` 순서를 쓰고(S60), 지도 자료 형식 GeoJSON은 `[경도, 위도]` 순서를 쓴다(S61). TourAPI의 mapX는 경도 · mapY는 위도다(S48 — 요청 매개변수 정의). 지도 그림은 타일(조각 이미지)로 받고, 저작자 표시 「© OpenStreetMap contributors」를 붙여야 한다(S54 · S60). 더블클릭으로 연 파일에서는 타일 요청이 막혔다는 후기가 있다(S55 · 경험 진술) — 이 도구는 타일이 안 와도 핀은 그대로 둔다. 강릉역 좌표 37.7645 · 128.8994(S65 실측).
- **흔한 오해**: ① 「숫자 두 개면 순서는 상관없다」 → 바꾸면 다른 곳(바다 · 다른 나라)에 찍힌다. ② 「지도 그림 = 좌표 자료」 → 그림(타일)과 좌표(핀)는 따로 온다.
- **시각 자료**: 좌표 두 숫자를 행 · 열 꼬리표로 + 같은 숫자를 뒤집어 찍은 핀이 엉뚱한 곳에 꽂힌 지도 두 장.

### A8 프론트엔드 · 백엔드 · 데이터베이스
- **정의**: 프론트엔드는 브라우저에서 돌아가며 화면과 동작을 맡는 쪽, 백엔드는 서버에서 요청을 받아 처리하는 쪽, 데이터베이스는 자료를 정리해 저장하고 찾아 꺼내는 곳입니다(S62).
- **비유**: 식당의 홀 · 주방 · 창고. 손님은 홀만 보고, 주문은 주방에서 처리되고, 재료는 창고에 있습니다.
- **사실**: MDN은 브라우저에서 도는 코드를 client-side 코드로, 서버 쪽 코드를 요청 확인 · 데이터베이스 저장과 조회 · 응답 전송을 맡는 server-side 코드로 설명한다(S62). 정적 사이트는 요청마다 같은 파일을 돌려준다(S62). 오늘 앱은 백엔드 없이 브라우저가 공개 API를 직접 부르는 구조다 — 그래서 키를 숨길 곳이 없고(S51), 담은 목록은 그 브라우저에만 있다(A6). 키를 숨기거나 여러 사람이 같은 일정을 보려면 백엔드와 데이터베이스가 필요하다(이 강의의 정리). MDN 용어집의 「Front-end」 · 「Back-end」 항목은 찾지 못했다(미확인).
- **흔한 오해**: ① 「백엔드 = 데이터베이스」 → 백엔드는 처리하는 코드, 데이터베이스는 그 코드가 쓰는 저장소. ② 「프론트엔드는 꾸미기뿐」 → 오늘 앱의 API 호출 · 거르기 · 지도는 전부 프론트엔드에서 돈다.
- **시각 자료**: 홀 · 주방 · 창고 세 칸에서 오늘 앱이 쓰는 칸만 칠함(홀 + 바깥 창구 셋) + 「서버가 있으면 생기는 것」 두 줄.

### A9 API와 MCP
- **정의**: MCP(Model Context Protocol)는 AI 앱이 외부 시스템 — 파일 · 데이터베이스 · API — 에 같은 방식으로 연결하도록 정한 공개 표준입니다(S63).
- **비유**: USB-C 단자. 기기마다 다르던 충전 단자를 한 모양으로 맞춘 것처럼, AI 앱과 바깥 도구를 잇는 꽂는 방식을 하나로 맞춥니다 — MCP 공식 문서가 쓰는 비유다(S63).
- **사실**: AI 앱(host)이 연결할 MCP 서버마다 client를 하나씩 두고, 서버는 도구(Tools) · 자료(Resources) · 요청 틀(Prompts)을 내놓는다. 도구의 예로 「API 호출」이 적혀 있다(S63). 공식 튜토리얼은 미국 기상청 API를 부르는 날씨 MCP 서버를 만든다 — API는 창구 자체이고, MCP 서버는 그 창구를 AI 앱이 도구로 쓰게 이어 주는 쪽이다(S63 · 「감싼다」는 표현은 이 강의의 정리). 공식 참조 서버는 시연용이다(S64). 로컬 MCP 서버는 내 컴퓨터 권한으로 돌기 때문에 설치 전에 무엇을 실행하는지 확인해야 한다(S63).
- **흔한 오해**: ① 「MCP가 API를 대체한다」 → MCP는 AI 앱과 서버 사이의 규약이고, 서버 안에서는 여전히 API를 부른다. ② 「MCP 서버는 늘 인터넷 서비스」 → 내 컴퓨터에서 도는 서버도 있다.
- **시각 자료**: 오늘 앱(화면 → 창구 셋 직접) vs MCP(AI 앱 → MCP 서버 → 같은 창구 셋) 두 줄 비교.

## 실습 ⑤ ⑧ ⑨ — 스킬 · 화면 녹화 · Canva (2026-10-21)

### S1 스킬
- **정의**: 스킬은 `SKILL.md`(이름 · 설명 · 본문)와 참고 파일을 담은 폴더입니다. 에이전트는 이름과 설명으로 스킬을 찾고, 맞는 일일 때 본문을 읽습니다(S75 · S77).
- **사실**: Codex는 작업 폴더부터 저장소 루트까지 `.agents/skills`를 찾는다(S75). Antigravity도 기본 위치가 `.agents/skills`다(S76). Claude Code는 `.claude/skills/<이름>/SKILL.md`를 쓰고 `/이름`으로 직접 부를 수 있다(S77). Codex는 스킬 변경을 스스로 알아채고, 반영이 안 보이면 다시 시작하라고 안내한다(S75). Antigravity의 재시작 필요 여부는 미확인(S76).
- **흔한 오해**: 「스킬은 한 도구 전용이다」 → 같은 폴더를 두 위치에 두면 세 도구가 같은 스킬을 쓴다(실습 ⑧ 준비물).

### S2 화면 녹화로 영상 파일 만들기
- **사실**: 브라우저의 화면 공유(`getDisplayMedia`)는 사용자 동작이 있을 때 매번 권한을 묻고, `MediaRecorder`로 webm 파일을 만들 수 있다(S78). 더블클릭(file://)에서 실제로 되는지는 미확인이라 대안으로 Windows 「Win + Alt + R」(Xbox Game Bar · MP4) 녹화를 둔다(S79).

### S3 Canva 무료 범위
- **사실**: 무료 플랜은 브랜드 키트 하나에 색 3개 · 색은 hex로 넣을 수 있고 PNG로 내려받는다 · 투명 배경은 Pro(S80 · 2차 출처). 메뉴 이름은 수업 직전 Canva 화면으로 확인한다.
