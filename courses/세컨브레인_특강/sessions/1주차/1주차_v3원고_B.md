## 읽는 법

- 장 하나가 `###` 하나다. 칸: 유형 · 제목 · 화면 요소 · 그림 지시 · (요청문 원문) · (③결과 모습) · 시간. 해당 없는 칸은 생략했다.
- **제목**은 한 문장 요지이고 화면 제목 그대로다. 숫자로 시작하는 제목은 없다.
- **화면 요소**는 한 장에 3개 이하다. 요청문 상자 · 단계 목록 · 그림 하나가 각각 1개다. 문장 덩어리는 3줄 이하다(요청문 상자는 예외로 줄 수를 제한하지 않는다).
- **그림 지시**는 SVG로 무엇을 그릴지다. 문법은 디자인 §20을 따른다: 검정 선 2~2.5px · 흰 면 · 끝이 둥근 선 · 스티커 색은 점 하나 · 약간 느슨한 손그림 곡선 · 단순한 선화. 얼굴이 있는 인물은 그리지 않는다. ChatGPT와 노션의 로고는 쓰지 않는다(ChatGPT는 둥근 말풍선 윤곽과 글자, 노션은 종이 한 장 윤곽과 글자로 그린다). 표는 실제 노션 표 보기를 보여 줄 때만 쓴다.
- **요청문 원문**: `> [요청]` 줄과 `> [지침]` 줄이 원문이다. 대괄호 표지는 화면에 쓰지 않는다. 사람이 채팅창에 직접 입력한다. 결과물은 ChatGPT가 노션에 직접 쓴다.
- **시간**은 분 단위 숫자다(화면에 쓰지 않는다). 실습 첫 진행 장의 숫자는 `n-timer data-min` 값이다. 설명 장의 시간은 발표 노트에 있다.
- 화면에 쓰지 않는 것: 출처와 상표 고지 · 확인을 시키는 문장 · 시간 표기 · 이미지 출처. 강사가 말로 한다(발표 노트).
- 단계 번호는 실습 전체 번호를 이어 쓴다(진행 장이 나뉘어도 번호는 1부터 이어진다). 사이드바 모형의 워크스페이스 이름은 「태경님의 워크스페이스」다.
- 노션 · ChatGPT 화면 모형은 모형이다. 버튼 이름과 카드 문구는 실제 화면과 다를 수 있다(미확인 U1).

### C3-3 · 개념 정의 장 (데이터베이스 · 노션 구조)

- 유형: concept · 정의 장
- 제목: RAG는 답을 쓰기 전에 바깥 문서를 찾아 덧붙이는 방식입니다
- 화면 요소: ① 정의 콜아웃 「RAG(검색 증강 생성)는 언어 모델이 답을 만들기 전에 바깥 문서에서 관련 내용을 찾아 입력에 덧붙이고, 그 내용을 바탕으로 답을 생성하는 방식입니다.」(영문 Retrieval-Augmented Generation은 작은 글자) ② 구조 그림
- 그림 지시: 가로 흐름. 왼쪽 「질문」 → 「검색기」(돋보기 박스) ↔ 「문서 색인」(서가 선화) → 「찾은 조각」(작은 카드 셋) → 「생성기(언어 모델)」(둥근 사각형) → 「답」. 검색기와 문서 색인 사이는 양방향 화살표, 나머지는 단방향. 부품 이름 세 개(검색기 · 문서 색인 · 생성기)만 굵게 쓴다.

## 결정 근거

1. **장 수 70**: v3 §19의 「넘치면 장을 나눈다」를 따랐다. 개념 하나를 장면 · 정의 · 비유(· 영상)로 나누고(§21), 실습 진행 장을 한 장에 요청문 하나 또는 두 단계로 나눴다.
2. **실습 진행 장 분할**: 한 장에 단계 목록(1) + 요청문 상자(1) + 모형(1)이 최대다. 요청문 원문은 길어도 한 단위로 센다. 단계 번호는 실습 전체에서 이어 써서 발표 노트와 맞춘다.
3. **③결과 장 분할**: 실습 5 2장 · 실습 6 4장 · 실습 7 3장 · 실습 8 1장. 실습 5는 행이 없어서 머리 칸과 고르는 칸 두 장으로 풍부하게 보인다. 실습 7의 일정표는 시간대별 세 장으로 나눠 글자를 22px 이상으로 둔다.
4. **유지 · 변경 · 확인의 자리**: 실습 7 앞에 둔다. 실습 7의 요청문(R7-2)이 세 구절을 모두 가지고 있어 개념 장의 도식 예문과 문자 그대로 같다.
5. **RAG 10장**: 사용자 요청(정의 → 파이프라인 → 컨텍스트 창 → 비유 → 영상 → 고전 RAG와 에이전트형 검색의 같은 점 · 다른 점 → 한계)을 그대로 따랐다. 비유(C4-9)는 정의 · 파이프라인 · 컨텍스트 창보다 뒤다. 파이프라인은 다섯 단계를 한 장에 담으면 글자가 작아져서 두 장으로 나눴다(준비 · 질문할 때).
6. **RAG 전문 낱말**: 임베딩 · 벡터 · top-k는 v2 용어표의 「쓰지 않는 말」이었으나, v3 요청 「RAG를 더 전문적으로」에 따라 파이프라인 그림에만 쓰고 낱말 옆에 쉬운 풀이를 붙였다(「숫자 묶음(벡터)으로 바꾸기」). 용어표의 쓰지 않는 말 목록은 빌더가 이 장들에 한해 해제한다.
7. **고전 RAG와 에이전트형 검색의 같은 점은 추론이다**: 사실표가 Azure의 두 구분(사전 색인 + 단일 질의 / 하위 질의를 계획해 도구로 검색)과 「ChatGPT + 노션 MCP는 에이전트형 쪽」을 주었고, 「같은 점이 찾기 → 붙이기 → 만들기」는 사실표 스스로 추론이라고 적었다. 화면은 이 구분을 단정 문장으로 쓰지 않고 그림으로 보인다. 노트에 「추론」을 적었다.
8. **데이터베이스 정의**: 일반 정의는 IBM, 노션 정의는 노션 도움말(사실표). 화면에는 출처 줄을 쓰지 않고 노트에 둔다.
9. **실습 8의 모형**: 내 여행지는 참가자마다 달라서 결과 모습에 실제 곳 이름을 쓰지 않았다(사실표에 없는 곳의 사실을 만들지 않기 위해서다). 강사가 참가자 한 명의 화면을 빌려 보여 준다(노트).
10. **확인을 시키는 문장 삭제**: 확인 장을 「③ 결과」로 바꿨고 결과 모습을 크게 보여 준다. 노션을 열어 견주게 하는 일은 강사가 말로 시킨다(발표 노트의 「결과」 줄).
11. **고치기 요청문의 마지막 수단**: 요청을 두 번 보내도 안 되면 사람이 노션에서 직접 고친다(설계 Q2). 화면에는 쓰지 않고 노트에 둔다.
12. **영상 낱말**: C4-10의 낱말 열은 확정 낱말(나누기 · 찾기 · 붙이기 · 만들기)과 같고, 영상의 질문과 켜지는 조각(불국사 · 대릉원 · 황리단길)을 그림 지시에 그대로 옮겼다.
