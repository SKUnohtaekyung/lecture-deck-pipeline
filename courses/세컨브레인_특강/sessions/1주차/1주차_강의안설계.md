## 집필 공통 규칙

### 말투와 표기

- 화면 글은 합니다체의 담백한 설명문이다. 한 문장에 동작 하나. 대상은 55세 이상, 코딩 경험 없음.
- 금지 7종: 동사구 슬로건 · AI 의인화 · 방법 안내형 제목 · 숫자로 시작하는 제목 · 뒤집기 대구 · 끝의 교훈 한 줄 · 추상 명사 선언. ChatGPT의 동작은 적는다 · 읽는다 · 저장한다 · 묻는다처럼 기계 동작 동사로 쓴다.
- 개념 장은 **정의 한 줄 → 비유** 순서다. 비유가 정의보다 앞서지 않는다. 라벨은 「정의」「비유」로 쓴다.
- 영어 화면 용어는 한글을 먼저 쓴다. 영문은 처음 나오는 곳에 한 번만 괄호로 병기한다(예: 플러그인(Plugins)). 용어는 아래 「용어표」만 쓴다.
- 메뉴 · 버튼 · 페이지 · 파일 이름은 「 」로 감싼다. 메뉴 이름은 이 문서 「[경로장] 목록」과 캡처 README에 있는 표기만 쓴다.
- 요청문은 존댓말 한 줄이다(한 줄 안에 문장 1~4개). 요청문 줄은 줄 맨 앞에 대괄호 표지(요청)를 붙이고, 노션 페이지 이름(「걷기 모임」「받은함」「내 자료함」 중 하나 이상)을 반드시 넣는다. 프로젝트 지침 문장에는 대괄호 표지(지침)를 붙인다.
- 요청문은 사람이 채팅창에 직접 입력하는 입력값이다. 결과물은 ChatGPT가 노션에 직접 쓰고, 사람이 결과를 옮기는 단계를 만들지 않는다. 파일은 「올리기」, 문장은 「채팅창에 넣기」라고 쓴다.
- 예시 주제는 「동네 걷기 모임」이다. 참가자가 자기 주제로 바꿔도 되고, 정하지 못하면 예시를 따라간다.
- 노션 · OpenAI 로고와 화면 모사 장식은 쓰지 않는다. 표지에 「Notion·OpenAI와 무관한 교육 자료」 한 줄을 넣는다.
- 이모지는 원고 표지로만 쓴다(아래 아이콘 범례). 화면에 올라가는 문구에는 넣지 않는다. 노션 페이지 아이콘은 「그림 하나」라고만 적는다.

### 실습 셸 서식 (FRAME 실습 서식을 따른다)

실습 1~8은 각각 **4장**(목표 · 진행 · 확인 · 고치기)이다. 장 ID는 `P{실습번호}-{1~4}`이고 1 = 목표 장, 2 = 진행 장, 3 = 확인 장, 4 = 고치기 장이다. 실습 4와 실습 8은 4장 모두 제목 끝에 「(선택)」을 붙인다.

| 장 | 본문 문구 구성 | 비유·멘트 칸 |
|---|---|---|
| 목표 장 (P*-1) | 실습 이름 · 만들 것 · 받는 것 · 시간(장별 분) · **전 → 후** 두 줄(결과물 전후 미리보기) · 선택 실습이면 「건너뛰어도 됩니다」 | 👀 허브 카드를 눌러 들어오는 것 · 💬 |
| 진행 장 (P*-2) | 첫 줄: 실습 번호와 이름, 이어서 네 장 이름(목표 · 진행 · 확인 · 고치기)을 한 줄로 두고 현재 장을 강조 → 단계 줄 `N 동작 · M분` → 요청문 앞에 「요청문」 라벨 → 요청문 줄 → 승인 단계 · 상시 한 줄 「승인 전에 카드의 내용을 읽습니다」(실습 2부터, 번호 없는 안내 문구) | 👀 타이머 M분 시작 · ⚠ (강사 확인) · 🗣 요청을 줄여 쓴 한 문장 · 경로가 나오면 ⚠ [경로장] |
| 확인 장 (P*-3) | 첫 줄 「노션에서 열어 대조합니다」 · 열 것 · 견줄 것 · 체크 줄 `☐ …`(5줄 이하) | 👀 강사가 한 줄씩 짚는 순서 · ⚠ |
| 고치기 장 (P*-4) | 어긋남 2~3개 `증상 → 고치는 곳` · 고쳐 보낼 요청문 줄 · 마지막 줄 「허브로」 | 👀 · ⚠ · 🗣 |

- 단계 번호는 진행 장에서 **8개 이하**다. 단계 하나는 동작 하나다. 「요청문을 보냅니다」는 채팅창에 문장을 입력하고 보내는 하나의 동작으로 센다.
- 승인 카드에 응답하는 일(「승인」 누르기 · 버튼 이름은 미확인 U1)은 요청문을 보내는 단계 다음 번호의 별도 단계로 둔다. 번호 없는 후속 동작을 만들지 않는다. 카드의 내용을 읽는 일은 동작 단계에 넣지 않고 진행 장의 상시 한 줄(「승인 전에 카드의 내용을 읽습니다」)로 둔다. 화면을 눈으로 보는 일도 주석으로 적고 단계로 세지 않는다.
- 진행 장의 요청문은 이 문서의 원문과 **문자 그대로** 같아야 한다(요청문 카드와 대조한다). 고치기 장의 요청문도 같다.
- 확인 장은 노션 화면을 열어 원본이나 요청문과 견주는 장이다. 대조선(원본 줄 ↔ 노션 줄)을 그릴 수 있게 「열 것」과 「견줄 것」을 한 쌍으로 쓴다.
- 허브 카드는 목표 장으로 들어가고, 고치기 장의 「허브로」가 허브로 돌아온다. 실습 0은 허브 카드에 넣지 않는다(카드는 8개).

- 받는 것: 앞 실습의 결과 전부, 내 주제 한 줄. 바꿀 주제는 시작 전에 정한다(정하지 못하면 예시 주제를 따라간다).
- 시간: 12분 = 목표 1 · 진행 7 · 확인 2 · 고치기 2.
- 전 → 후: 전 = 요청문 틀을 걷기 모임 안내문에만 써 봄 / 후 = 내 주제 페이지 1개 + 주간 정리 지침 + 「내 자료함」 행 증가.
- 선택 실습이다. 건너뛰어도 되고, 건너뛴 사람은 Codex 시연(B4-D1)으로 간다(C4-3 연결).
- 내 주제로 바꿀 때: 요청문의 「회원 모집 글」을 내가 쓸 글 이름으로, 「모임 소개와 신청 방법」을 내 글에 맞는 두 가지로 바꾼다. 부모 페이지는 계속 「걷기 모임」이다.

## 개념 장 목록 (11장)

개념 장은 블록당 3개 이하다. 한 장은 **정의 한 줄 → 비유** 순서로 쓰고, 시각 자료 1개와 박스 1개 이하를 둔다. 정보 모양 · 시각 자료 · 조작은 계획서 §6 표를 따르고, §6 표에 없는 개념(C2-1 · C4-2)은 이 문서가 같은 방식으로 추가했다. 조작하기 전의 첫 상태만으로 정보가 읽혀야 한다(PDF에서는 첫 상태로 남는다).

### 블록 1 · 새 개념 3

#### C1-1 세컨브레인 · 머리 밖에 두는 기록 보관소 (3분)

- 정보 모양: 구조
- 시각 자료: 서랍이 세 칸인 서랍장 — 모으기 · 정리하기 · 다시 찾기
- 조작: 칸을 누르면 오늘 할 실습 번호가 뜬다(모으기 = 실습 3 · 4 / 정리하기 = 실습 5 · 6 / 다시 찾기 = 실습 7 · 8 / 서랍장 놓기 = 실습 1 · 2)
- 정의: 세컨브레인은 기억해 둘 것을 머리 밖의 한곳에 모아 두고, 필요할 때 다시 꺼내 보는 개인 기록 보관소입니다.
- 비유: 서랍이 세 칸 있는 서랍장과 같습니다. 첫째 칸에 모으고, 둘째 칸에서 정리하고, 셋째 칸에서 다시 찾습니다.

#### C1-2 두 도구의 자리 · 프로젝트는 책상, 노션은 서랍장 (3분)

- 정보 모양: 비교
- 시각 자료: 책상(ChatGPT 프로젝트)과 서랍장(노션)을 나란히 둔 그림
- 조작: 토글로 어느 쪽에 무엇이 남는지 바꿔 본다(책상: 지침 · 파일 · 대화 / 서랍장: 페이지 · 표)
- 정의: ChatGPT 프로젝트는 지침과 파일과 대화를 한곳에 묶어 두는 작업 공간이고, 노션은 쓴 글을 페이지로 쌓아 두는 보관 공간입니다.
- 비유: 책상 위에서 일하고, 끝난 것은 서랍장에 넣습니다.
- 한 주제는 프로젝트 하나와 노션 페이지 하나로 짝을 짓는다.
- 지침은 실습 1에서 처음 쓰므로 이 장의 책상 쪽 항목에 한 줄 풀이를 붙인다: 지침 = 이 프로젝트의 모든 대화가 먼저 읽는 안내문(설정 세 가지의 정식 정의는 C2-2). 새 개념으로 세지 않는다.

#### C1-3 플러그인 · ChatGPT와 노션을 잇는 MCP 연결과 승인 카드 (6분)

- 정보 모양: 구조(승인 카드는 이 장 안의 보조 전후 조작)
- 시각 자료: ChatGPT ─ 규격 플러그 ─ 노션 도식. 플러그 위에 승인 카드가 놓인다. 동의 화면 캡처 08을 박스 1개로 곁들인다
- 조작: 플러그를 누르면 동의 화면에 적힌 할 수 있는 일 네 가지가 설명으로 뜬다(캡처 08의 네 항목 — 두 가지는 확인, 나머지 두 가지는 미확인 U10). 「승인」을 누르면 노션 쪽에 페이지가 나타난다(버튼 이름은 미확인 U1).
- 정의: 플러그인은 ChatGPT와 노션을 MCP라는 공통 규격으로 이어 주는 연결이며, 노션에 쓰기 전에는 내 허락을 받는 승인 카드가 화면에 나타납니다.
- 비유: 전기 콘센트 규격과 같습니다. 같은 모양이면 어떤 앱이든 꽂히고, 스위치를 켜는 일이 승인 카드입니다.
- 이 장은 플러그인(MCP 연결)과 승인 카드를 **한 개념**으로 묶은 장이다(잠긴 결정 L9). 캡처 08을 쓴다. 동의 화면의 제목이 「Notion MCP에 연결하기」라서 참가자가 MCP라는 단어를 화면에서 먼저 보게 된다.
- 승인 장면은 실습 2에서 두 번 연습한다(연결 때 동의 화면 · 첫 쓰기 때 승인 카드).

### 블록 2 · 새 개념 2

#### C2-1 받은함 · 아직 정리하지 않은 자료를 먼저 쌓는 자리 (3분)

- 정보 모양: 순서
- 시각 자료: 사진 · 파일 · 글이 노션 「받은함」 한 곳으로 모이는 흐름 도식(프로젝트에 올릴 수 있는 것: 사진 · 글 파일 · PDF, 무료는 다섯 개까지)
- 조작: 자료 아이콘을 누르면 「받은함」에 줄이 하나 생긴다
- 정의: 받은함은 아직 정리하지 않은 자료를 일단 쌓아 두는 노션 페이지입니다.
- 비유: 현관 옆 우편 바구니와 같습니다. 들어온 우편을 열어 보기 전에 한곳에 둡니다.

#### C2-2 프로젝트 설정 세 가지 · 지침, 메모리, 파일 (5분)

- 정보 모양: 구조
- 시각 자료: 지침 · 메모리 · 파일 세 칸을 가진 설정창 모형(화면 이름은 미확인 U3)
- 조작: 항목을 누르면 설명이 뜬다(지침: 모든 대화가 먼저 읽는다 / 메모리: 대화에서 남겨 두는 내용 / 파일: 무료는 프로젝트당 5개)
- 정의: 프로젝트 설정은 지침(모든 대화가 먼저 읽는 안내문), 메모리(대화에서 남겨 두는 내용), 파일(올려 둔 자료) 세 가지입니다.
- 비유: 책상 위의 메모지와 수첩과 서류철과 같습니다.
- 지침이 내 전체 설정보다 먼저 적용된다는 사실은 발표자 노트에 둔다(계획서 §3). 화면 본문은 3가지로 끝낸다.

### 블록 3 · 새 개념 3

#### C3-1 페이지와 데이터베이스 · 글 한 장과 표 (4분)

- 정보 모양: 비교
- 시각 자료: 문서 한 장과 표 한 개를 나란히 둔 그림
- 조작: 같은 자료가 두 모양으로 바뀐다(글 한 장 ↔ 표의 한 줄)
- 정의: 페이지는 글을 적는 문서 한 장이고, 데이터베이스는 같은 모양의 페이지를 표로 모아 둔 묶음입니다.
- 비유: 공책 한 장과 색인 카드 상자와 같습니다. 카드 상자에서는 카드를 한꺼번에 늘어놓고 골라 볼 수 있습니다.

#### C3-2 태그 · 자료에 붙이는 종류 이름표 (3분)

- 정보 모양: 포함
- 시각 자료: 자료 6건을 태그 3개로 나누는 칩 위젯
- 조작: 칩을 누르면 해당 자료만 남는다
- 정의: 태그는 자료의 종류를 알려 주는 이름표이고, 같은 이름표가 붙은 자료끼리 모아 볼 수 있습니다.
- 비유: 서랍 안 칸막이에 붙인 이름표와 같습니다.
- 발표자 노트: 태그는 세 개에서 다섯 개일 때 찾기 쉽다는 설명을 넣는다(실습 5의 종류 태그는 다섯 개).

#### C3-3 @멘션 · 페이지에서 다른 페이지로 가는 링크 (3분)

- 정보 모양: 구조
- 시각 자료: 두 페이지를 잇는 선
- 조작: 선을 누르면 반대쪽 페이지에서 보이는 링크가 뜬다
- 정의: @멘션은 글 속에서 다른 페이지의 이름을 불러 그 페이지로 가는 링크를 거는 기능입니다.
- 비유: 책 사이에 끼워 둔 쪽지와 같습니다. 쪽지를 따라가면 관련된 책이 나옵니다.
- 관계(relation) 속성은 다루지 않는다. @멘션까지만 한다.

### 블록 4 · 새 개념 3

#### C4-1 검색과 필터 · 낱말로 찾고 조건으로 추리기 (3분)

- 정보 모양: 전후
- 시각 자료: 필터를 걸기 전의 표와 건 뒤의 표
- 조작: 조건을 고르면 행이 줄어든다
- 정의: 검색은 낱말로 자료를 찾는 일이고, 필터는 조건(예: 종류가 안내문)에 맞는 행만 남기는 일입니다.
- 비유: 도서관에서 책 제목으로 찾는 일과 분류표로 책장을 추리는 일과 같습니다.

#### C4-2 유지 · 변경 · 확인 · 요청을 세 칸으로 나눠 쓰는 틀 (3분)

- 정보 모양: 구조
- 시각 자료: 요청문 한 줄이 그대로 둘 것 · 바꿀 것 · 알려 줄 것 세 칸으로 갈라지는 도식
- 조작: 칸을 누르면 요청문의 해당 부분에 형광펜이 칠해진다
- 정의: 유지·변경·확인은 요청을 그대로 둘 것, 바꿀 것, 끝나고 알려 줄 것의 세 칸으로 나눠 쓰는 틀입니다.
- 비유: 이사 업체에 남기는 쪽지와 같습니다. 이건 그대로 두고, 이건 옮기고, 끝나면 알려 달라고 적습니다.

#### C4-3 주간 루틴 · 일주일에 한 번 같은 정리 요청을 보내는 습관 (2분)

- 정보 모양: 순서
- 시각 자료: 한 주 달력과 요청문 한 줄
- 조작: 요일을 누르면 그날 할 일이 뜬다(받은함 비우기 → 자료함에 행 추가 → 태그 확인)
- 정의: 주간 루틴은 일주일에 한 번, 정해 둔 같은 정리 요청을 보내는 습관입니다.
- 비유: 주말 서랍 정리와 같습니다. 새로 들어온 것만 제자리에 넣습니다.

## 부록 · 분기 대체 셸 (실습 2 · 경로 ③ 앱 설치 · 연결)

계획서 §8-1 쓰기 시험이 실패할 때 쓴다(제2부 §4 ③). 사용자의 §8-1 결과가 아직 없어(PROGRESS A6) 본 설계는 경로 ①②를 전제로 하고, 이 부록은 **실습 2의 4장(P2-1 ~ P2-4)만** 바꿔 끼운다. 장 ID와 장수는 그대로이고 입장은 40분으로 늘린다. 이 부록의 내용은 대부분 미확인이다. 데스크톱 앱의 화면 이름과 설치 경로가 계획서에 없다.

- 무료로 쓸 수 있는 근거: Codex는 Free와 Go를 포함한 ChatGPT 플랜에 들어 있다. 데스크톱 앱은 전화 인증으로 쓸 수 있고, 플러그인을 Codex 작업 화면에서도 쓴다(계획서 §3). 한도는 비공개다.
- 이후 실습 3~8에서 「프로젝트의 채팅창」은 「Codex의 작업 화면」으로 읽는다. 이 앱에 프로젝트 파일과 지침에 해당하는 기능이 있는지는 미확인 U17이며, 없으면 실습 3과 4를 다시 설계한다.
- 이 부록의 소제목은 본문 실습 소제목과 구분하려고 「대체」를 붙였다.

### 대체 목표 장 (P2-1 · 1분)

- 만들 것: 데스크톱 앱 설치와 노션 플러그인 연결 1개, 「걷기 모임」 맨 아래의 할 일 세 줄.
- 받는 것: 보조가 입장 전에 내려받아 둔 설치 파일(가정 · 설치 파일의 위치는 미확인 U17), 전화 인증이 가능한 휴대전화, 실습 1의 노션 「걷기 모임」.

- 전 → 후: 전 = 앱 없음 · 연결 없음 / 후 = 앱 열림 · 연결됨 · 맨 아래에 세 줄.

### 대체 진행 장 (P2-2 · 11분)

1. 설치 파일을 실행합니다. · 2분 (미확인 U17)

3. 사전 안내문의 계정으로 로그인합니다. · 1분

## 결정 근거

가정과 판단을 한 줄씩 적는다. 계획서의 잠긴 결정(L1~L12)은 다시 저울질하지 않았다.

1. **부제 채택**: 「노션 + ChatGPT 실습 · 4시간」을 그대로 쓴다. 도구 두 개와 형식이 한눈에 보이고, 금지 7종에 걸리는 말이 없다.
2. **관통 문장 변경**: 이전 제안 「모은 것을 ChatGPT가 노션에 적고, 노션에서 열어 확인하고 다시 찾는다」는 동사가 세 번 이어져 동사구 슬로건에 가깝고 주어가 둘로 갈린다. 계획서 §5-A의 10항(결과 확인은 원본 대조)이 이 수업의 중심 행동이므로 「ChatGPT가 노션에 적은 것은 노션에서 열어 직접 확인합니다」로 바꿨다. 실습 확인 장 8개와 같은 행동을 말하고, 합니다체는 덱 본문과 맞춘 것이다. 쓰는 자리는 아젠다와 간지로 한정해 끝의 교훈 한 줄이 되지 않게 했다.
3. **워드마크 채택**: 「세컨브레인」을 그대로 쓴다. 한글 다섯 글자라 헤더 로크업에 들어가고, 노션 · OpenAI 로고를 쓰지 않는 규칙(§5-G)과 충돌하지 않는다.
4. **프로필 §4**: 계획서 §6의 지시대로 FRAME 프로필을 따르고 차이 세 가지(색 토큰 · 모노 폰트 · 본문 24px)만 적었다. 이 과목 고유의 내용 규칙(예시 주제 · 용어 · 정보 단위)은 같은 절의 별도 표로 두었다.
5. **개념과 실습을 번갈아 배치**: 개념 장을 그 개념을 쓰는 실습 바로 앞에 둔다. 시니어는 설명이 길면 손이 멈춘다. 블록별 설명 합계(12 · 8 · 10 · 8)는 계획서 §2-2와 같다.
6. **개념 장 11개**: 계획서 §2-3의 추정(약 4장 × 4블록)보다 적다. 성공 기준 「블록당 3개 이하」(P1-S5)를 따랐다.
7. **블록 정리 장 4개 추가**: 계획서 §2-2가 블록마다 정리 5~7분을 잡았다. 시간을 붙잡을 장이 없어 B*-9를 두었다. 새 개념과 새 요청문은 넣지 않는다.
8. **총 65장**: 실습 셸 32 + 허브 1 + 개념 11 + 표지와 아젠다 2 + 입장 4 + 간지 4 + 휴식 3 + 정리 4 + 시연 2 + 마무리 2. 계획서의 58~68 범위 안이다.
9. **실습 0은 입장 4장**: 같은 4장 틀을 쓰되 허브 카드와 32장 계수에서 뺐다. 캡처 04는 확인 장에, 가입 화면 캡처 01~03은 고치기 장에 둔다. 사전 가입이 원칙(계획서 D1)이라 가입 화면은 예외 흐름이고, 이렇게 하면 진행 장의 단계가 5개로 줄어 한 단계 한 동작을 지킨다.
10. **허브는 아젠다 다음**: 실습 장은 PART 안에 순서대로 있고 허브는 이동과 진행 표시용이다. 위치는 조립 단계에서 FRAME 방식으로 연결한다.
11. **요청문은 존댓말 한 줄**: 계획서의 예시는 「적어 줘」 형이다. 시니어가 AI에게 쓰는 말투로 존댓말이 자연스러워 바꿨고, 줄마다 노션 페이지 이름을 넣었다.
12. **FRAME 서식 유지**: 초안 템플릿은 완성 요청문을 🗣에만 두라고 하지만, 계획서와 FRAME 선례는 요청문을 진행 장 본문의 요청문 상자에 둔다. 후자를 따랐고, 🗣에는 입력이 어려운 사람을 위해 줄인 요청문을 둔다.
13. **승인 단계**: 「승인」 누르기(버튼 이름은 미확인 U1)는 모든 실습에서 별도 단계 번호를 받는다. 번호 없는 후속 동작은 두지 않는다. 카드를 읽는 일과 워크스페이스를 눈으로 보는 일은 동작 단계에 넣지 않고 상시 안내 문구와 캡처 주석으로 둔다.
14. **샘플 자료 해석**: 계획서 §6은 「코스 안내 · 사진 2 · 명단 · 지난 안내문」, Phase 3 표는 「코스 안내 · 지난 안내문 · 명단 · 메모 2」와 사진 2장이다. 합치면 7건이어서 프로젝트 5개 한도를 넘는다. 동시에 올리는 파일을 5개 이하로 두는 해석으로 위 샘플 표를 만들었다. 사진 1장과 메모 1건은 예비다.
15. **노션 페이지 수**: 계획서 §2-2는 마무리를 「페이지 4개 + 데이터베이스 1개」로 적는다. 실습 8이 선택이라 F-01은 「페이지 3개 + 데이터베이스 1개, 실습 8을 한 사람은 페이지 1개 추가」로 적는다.
16. **주소 입력**: 실습 4는 노션 주소를 지침에 넣어야 해서 사람이 키보드로 한 번 옮긴다(Ctrl과 C, Ctrl과 V). 옮기는 것은 지침 입력값 한 줄이고 결과물은 옮기지 않는다(사용자 결정 필요 Q1). 잠긴 결정 L3은 산출물에 대한 것이라 이 한 줄과 충돌하지 않는다고 판단했다.
17. **영문 경로와 한글 캡처**: 계획서 §3의 경로(Settings → Plugins → Notion → Connect/Install)와 캡처 README의 한글 표기(「플러그인」 → 「+ 플러그인 설치」 → 「Notion 연결 ↗」)는 같은 흐름이다. 화면에 보이는 한글 표기를 쓴다.
18. **보기 바꾸기 이동**: 계획서는 표 · 갤러리 보기를 실습 5에 두었다. 행이 없는 데이터베이스는 두 보기가 같게 비어 보여 실습 6의 확인 장으로 옮겼다.
19. **행 본문에 파일 내용 적기**: 실습 7이 노션에서 찾아 쓰는 실습이 되려면 노션에 지난 안내문의 말투와 순서가 있어야 한다. 실습 6의 첫 요청문에 행 본문 기록을 넣었다.
20. **Codex 시연은 개념 장이 없다**: 정의와 비유 문장을 쓰지 않고 장면만 보여 주어 블록 4의 새 개념을 3개로 유지한다.
21. **승인 장면 두 번**: 실제 흐름이 연결 때 동의 화면(캡처 08)과 첫 쓰기 때 승인 카드로 나뉘어 이 둘을 승인 장면 1과 2로 정했다.
22. **미확인 표기**: 계획서와 캡처 README에 없는 화면 이름은 지어내지 않고 U번호로 올렸다. 웹 검색은 하지 않았다.

### 이 절의 장에 모두 적용하는 지시

- 장 안 순서는 제목 → 정의 콜아웃(📌 · `n-callout cl-blue n-def`) → 비유 콜아웃(💡 · `n-callout cl-gray`) → 시각 자료 → 나머지다. 정의가 비유보다 먼저 읽힌다. 라벨은 「정의」 · 「비유」다.
- 한 장의 정보 단위는 4개 이하다. 이 절의 단위는 **정의 · 비유 · 시각 자료(영상과 낱말 열, 또는 도식 한 덩어리) · 표나 토글이나 체크리스트 한 덩어리**다. 장마다 계수를 적었다.
- 영상 장의 배치 제안(측정 후 빌더가 조정): 위 줄에 정의와 비유 콜아웃을 가로 두 칸으로 두고, 아래 줄 왼쪽에 영상 틀(`n-frame` + `n-video`, 가로 480 안팎), 오른쪽에 영상 낱말 열을 둔다. 디자인 §6의 개념-영상 유형(영상 가로 880)은 정의 · 비유 콜아웃과 한 장에 들어가기 어려워 개념 유형으로 맞췄다. 넘칠 때 줄이는 순서는 토글 → 캡션 → 낱말 열의 보조 글자 순이고, 정의 · 비유 · 영상은 줄이지 않는다.
- 영상 낱말 열의 낱말은 영상에 박는 자막과 **같은 낱말**이다(「영상 정합 메모」 참조). 영상이 안 돌 때와 인쇄에서는 마지막 프레임 포스터가 보인다. 포스터만으로 정보가 읽혀야 한다.
- 화면 글은 합니다체다. 아래 인용 문장은 화면 글 원문이다. 이 절의 지시 문장(한다체)은 화면에 올리지 않는다.
- 영문은 처음 나오는 곳에 한 번 괄호로 병기한다. 제품 이름(ChatGPT · Notion · Obsidian · Sync · Publish)은 영문 그대로 쓴다.

### C4-4 · RAG · 찾아서 쓰는 AI — 새로

- 유형: 개념(concept) · 영상 틀 포함 · 블록 4 · 3분
- 아이콘: 🔎
- 속성 줄: ⏱ 3분 · 블록 4 · 태그 「개념」(tg-blue)
- 정의 콜아웃: RAG(Retrieval-Augmented Generation)는 AI가 답을 쓰기 전에 바깥의 자료를 먼저 찾아 읽고, 그 내용을 바탕으로 답을 쓰게 하는 방식입니다.
- 비유 콜아웃: 걷기 모임 총무가 단톡방에서 질문을 받으면 노션의 모임 기록을 먼저 열어 보고 답하는 것과 같습니다.
- 시각 자료: 영상 V3 `rag`(14~16초 반복, 자료/video/rag.mp4, 포스터 자료/video/rag.png). 장면은 질문 말풍선, 돋보기가 「내 자료함」 표를 훑으며 관련 행 3개가 파랑으로 켜지는 모습, 켜진 행이 질문 옆 상자로 붙는 모습, 답이 써지며 문장 끝에 출처 칩(📄 지난 안내문 · 📄 코스 안내)이 달리는 모습, 출처 칩을 누르면 원본 행이 다시 켜지는 모습 순서다. 영상 캡션: 「출처 칩을 누르면 원본 행이 다시 켜집니다」
- 본문 블록 — 영상 낱말 열(영상 자막과 같은 낱말 3개):

| 순번 | 굵은 낱말 | 한 줄 뜻 |
|---|---|---|
| 1 | 찾기(Retrieval) | 질문과 관련된 자료를 찾습니다 |
| 2 | 보태기(Augmented) | 찾은 내용을 질문 옆에 붙입니다 |
| 3 | 만들기(Generation) | 그 내용을 바탕으로 답을 씁니다 |

- 본문 블록 — 토글 「RAG로 좋아지는 것」(열면 세 줄):
  - AI를 다시 학습시키지 않아도 최신 자료와 내 자료를 답에 반영할 수 있습니다.
  - 그럴듯하지만 거짓인 답(환각)을 줄입니다.
  - 답에 출처를 붙일 수 있습니다.
- 정보 단위(4): 정의 · 비유 · 영상과 낱말 열 · 토글
- 💬 강사 멘트: 총무가 질문을 받고 노션 모임 기록을 먼저 열어 보듯이, RAG는 답을 쓰기 전에 자료를 먼저 찾는 방식입니다. 영상은 찾기, 보태기, 만들기 세 단계이고, 답 끝의 출처 칩을 누르면 원본이 다시 켜집니다. 잠시 뒤 실습 7이 이 세 단계를 직접 해 보는 시간입니다.
- 출처: Lewis 외, "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks", arXiv:2005.11401 (2020 · NeurIPS 2020) · https://arxiv.org/abs/2005.11401

- 속성 줄: ⏱ 3분 · 블록 4 · 태그 「개념」(tg-blue) · 「대조」(tg-green)
- 정의 콜아웃: 세컨드 브레인과 RAG를 합치면, 내가 노션에 모아 둔 기록을 ChatGPT가 먼저 찾아 읽고 그 내용을 바탕으로 답을 쓰는 흐름이 됩니다.
- 비유 콜아웃: 총무 수첩에 적어 둔 기록을, 질문을 받은 총무가 먼저 펼쳐 보고 답하는 것과 같습니다.
- 시각 자료: 노션 블록으로 만든 가로 도식 하나. 왼쪽 `n-db` 미니 표 「📚 내 자료함」(행 2개: 지난 안내문 · 코스 안내) → 가운데 화살표 위에 낱말 「찾기 · 보태기」 → 가운데 `n-chat` 한 칸(ChatGPT가 읽은 내용으로 쓰는 중) → 화살표 위에 낱말 「만들기」 → 오른쪽 `n-mention` 「📄 다음 달 안내문」. 맨 아래에 오른쪽에서 왼쪽으로 가는 점선 화살표와 낱말 「노션에서 열어 대조」. 도식 옆에 멘션 칩 「📄 실습 7 · 찾아서 쓰기」(`data-go="P7-1"`)를 둔다. 낱말은 C4-4 영상과 같다.
- 본문 블록 — 한계 콜아웃(⚠️ · `cl-yellow`): 「한계」 라벨 뒤에 두 문장. 자료가 낡았거나 찾기가 빗나가면 답도 틀립니다. 그래서 ChatGPT가 노션에 적은 것은 노션에서 열어 직접 확인합니다.
- 본문 블록 — 체크리스트 「AI 답을 노션 원문과 대조합니다」(`n-todo`, 3줄, 처음에는 모두 비어 있다):
  - ☐ 답에 나온 날짜 · 장소 · 이름이 노션 원문 행과 같다
  - ☐ 원문에 없는 내용이 답에 들어 있지 않다
  - ☐ 원문 행의 날짜가 낡지 않았다
- 관통 문장은 한계 콜아웃의 둘째 문장이고, 장의 맨 끝 줄이 아니다. 체크리스트가 장의 마지막 블록이다. 관통 문장을 맺음 줄로 쓰지 않는 앞 본문 규칙을 따른다.
- 정보 단위(4): 정의 · 비유 · 도식 · 한계와 체크리스트(한 덩어리)
- 💬 강사 멘트: 오늘 실습 7이 바로 이 흐름입니다. 노션 「내 자료함」의 지난 안내문과 코스 안내를 읽게 하고 다음 달 안내문을 새 페이지로 쓰게 합니다. 엄밀히는 논문의 RAG가 미리 만든 검색 색인을 쓰고 오늘의 플러그인은 필요할 때 노션 검색 기능을 실행하므로 세부는 다르지만, 찾고 보태고 만드는 흐름은 같습니다.

### V2 결정 근거

1. **이름**: 정식 이름은 세컨드 브레인이고 수업 이름은 세컨브레인이다. 둘이 같다는 것을 C1-1 영상 캡션 한 줄로 밝힌다. 용어표의 「세컨브레인(두 번째 뇌)」은 그대로다.
2. **정의 문장**: 리서처 제안 「머릿속에 다 담지 않고 … 적어 두었다가」는 부정 뒤 긍정으로 이어지는 대구라 금지 7종에 가깝다. 긍정문 하나로 고쳤다. 앞 본문의 용어 「기록 보관소」를 이어 썼다.
3. **네 단계와 서랍 세 칸**: 서랍 세 칸은 이 수업이 CODE 네 단계를 실습 순서에 맞게 묶은 이름이다(포르테의 용어가 아니다). 추리기와 꺼내 쓰기를 셋째 칸 「다시 찾기」에 함께 건 것은 실습 7 · 8이 찾아서 새 글을 쓰는 실습이기 때문이다. 실습 3의 요약 세 줄도 추리기에 가깝지만 한 낱말을 두 칸에 걸지 않았다.
4. **유형**: 영상 장은 개념(concept) 유형에 영상 틀을 아래 줄 왼쪽에, 낱말 열을 오른쪽에 두는 변형이다. 디자인 §6의 개념-영상(영상 880)은 정의 · 비유 콜아웃을 같은 장에 두기 어렵다. 정의 → 비유 순서는 지켰다.
5. **비유 고르기**: C1-1 총무 수첩 · C4-4 총무 · C4-5 총무 수첩은 이어 읽히게 한 장면으로 맞췄다. 옵시디언은 책꽂이의 공책, 노션은 서랍장이다(노션의 서랍장은 C1-2 그대로). 책 사이 쪽지(C3-3) · 색인 카드 상자(C3-1)와 겹치지 않게 골랐다.
6. **관통 문장의 자리**: 앞 본문 규칙(맺음 줄 금지) 때문에 C1-5의 이유에는 쓰지 않는다. C4-5의 한계 콜아웃 둘째 문장에 둔다. 한계 → 확인이 한 호흡으로 이어지고, 체크리스트가 맨 끝 블록이다.
7. **C4-4와 C4-5의 정의 분리**: C4-4는 일반 정의(바깥의 자료), C4-5는 내 노션 기록으로 좁힌 정의다. 오늘 플러그인과 RAG 논문의 구현 차이는 사실표의 한 줄을 강사 멘트에 넣었고 화면에는 쓰지 않았다.
8. **「재학습」**: 사실표의 재학습을 「다시 학습시키지 않아도」로 풀었다. 「환각」은 「그럴듯하지만 거짓인 답」을 먼저 쓰고 낱말을 괄호에 둔다.
9. **옵시디언 「플러그인」 이름 충돌**: 커뮤니티 플러그인 수치를 쓰되 「추가 기능」이라 풀고 강사 멘트에서 구분한다. 「추가 기능」이라는 풀이는 일반 의미이며 사실표 문장은 아니다.
10. **PARA · memex**: 사실표에 한글 옮김이 없고 시니어 화면에서 쓸 곳이 없어 넣지 않았다. 필요하면 C1-1 토글에 영문 그대로 한 줄을 더할 수 있다.
11. **시간**: 블록 1의 개념 · 정리 분은 앞 본문에서 17분이다(C1-1 3 · C1-2 3 · C1-3 6 · B1-9 5). 실습 33분이 고정이라 이 17분을 여섯 장이 나눈다. 새 장 C1-4 3 + C1-5 2 = 5분을 C1-2 −1 · C1-3 −2 · B1-9 −2에서 얻었다(C1-1 3 · C1-4 3 · C1-5 2 · C1-2 2 · C1-3 4 · B1-9 3 = 17). 블록 4의 개념 · 정리 분은 앞 본문에서 13분이다(C4-1 3 · C4-2 3 · C4-3 2 · B4-9 5). 실습 7을 2분 줄여 15분으로 늘렸다(C4-1 2 · C4-4 3 · C4-5 3 · C4-2 2 · C4-3 2 · B4-9 3). 실습 7을 20분으로 되돌리면 C4-5를 2분, C4-3을 1분으로 줄이면 합이 맞는다(대안).
12. **P7의 줄이는 자리**: 확인 장은 이 수업의 중심 행동이라 4분을 지켰고 어긋난 사람만 쓰는 고치기 장(3 → 2)과 승인 대기 1분을 줄였다. 「실습 7을 2분까지 줄여도 된다」는 지시를 최대 2분 감축(20 → 18)으로 읽었다.
13. **블록당 개념 3개 이하 기준과 충돌**: 앞 본문(P1-S5, 「개념 장 한눈에」)은 블록당 3개 이하다. 이 절은 블록 1 · 4가 5개다. 사용자 지시가 앞서므로 기준 문구의 갱신이 필요하다.
14. **실습 1 전의 설명 연속 10분**: C1-1 3 + C1-4 3 + C1-5 2 + C1-2 2. 앞 본문은 6분이었다. 영상 반복(12~14초)과 낱말 열로 말을 줄이도록 짰다. 뒤처진 사람은 B1-9가 3분으로 줄어 BR-1 휴식 10분에 따라잡는다고 가정했다(보조의 지원은 미확인).
15. **노션 표의 「보드」**: 사실표는 데이터베이스(표 · 보드)지만 수업이 쓰지 않는 보기라 「표」만 썼다.
16. **체크리스트 3줄**: 사실표의 한계(낡은 자료 · 빗나간 검색)를 확인 줄 셋으로 옮겼다. 줄 서식은 앞 본문 확인 장처럼 상태 문장이다. 첫째 줄이 빗나간 검색이나 틀린 답, 둘째 줄이 원문에 없는 내용, 셋째 줄이 낡은 자료다.

- 위쪽 구체 장면: 왼쪽에 캡처 `05_플러그인_디렉터리.png`의 왼쪽 목록 조각을 크게(조각 = 원본의 가로 0~23.6% · 세로 7.5~56.5%, 폭 400 안팎), 오른쪽에 채팅 모형(`n-chat`): 내 말풍선 「걷기 모임 공지를 써 주세요」 → 아래 글 답 세 줄(모형 문장: 「이번 달 걷기 모임 안내입니다. 토요일 아침에 공원 앞에서 모여 한 바퀴 걷습니다. 편한 신발을 신고 오세요.」). 모형임을 작은 글씨로 밝힌다(「화면 모형」).
- 정의 콜아웃: ChatGPT는 문장으로 요청을 입력하면 글로 답을 보여 주는 채팅 화면입니다.
- 비유 콜아웃: 문자 메시지 창과 같습니다. 보낸 말은 오른쪽에, 돌아온 답은 왼쪽에 쌓입니다.
- 동그라미와 라벨(조각 기준 좌표 · 눈으로 잰 값):

| 번호 | 중심 x% y% (가로×세로) | 라벨 |
|---|---|---|
| ① | 「새 채팅」 15% 5.8% (30%×9%) | 「새 채팅」 · 누르면 새 대화 창이 열립니다 |
| ② | 「프로젝트 ›」 13% 79.6% (28%×9%) | 「프로젝트」 · 한 주제의 지침과 파일과 대화를 모아 두는 곳입니다 |

- 본문 한 줄(채팅 모형 아래): 답은 채팅 화면 안에만 쓰입니다. 노션에는 아무것도 생기지 않습니다.
- 정보 단위(4): 정의 · 비유 · 캡처 조각과 채팅 모형 · 한 줄
- 「프로젝트」를 여는 방법과 새 프로젝트 만들기는 미확인(U2)이라 화면 문구에 쓰지 않는다. 화면에 보이는 위치만 짚는다.

### K-3 · 에이전트 · ChatGPT가 노션에 직접 적는 것

- 유형: 기초(concept) · 파트 1 · 아이콘 ✍️ · 속성 줄: 「파트 1」 + 태그 「기초」(tg-gray)
- 위쪽 구체 장면: 가로 두 칸(전 · 후). 각 칸은 작은 화면 모형 두 개와 화살표 한 개다.
  - 왼쪽 칸 제목 「답을 읽고 사람이 노션에 다시 적던 방식」: ChatGPT 채팅 모형(답 글 세 줄) → 화살표 위 글 「사람이 읽고 적습니다」 → 노션 「걷기 모임」 페이지 모형(같은 세 줄).
  - 오른쪽 칸 제목 「ChatGPT가 노션에 바로 적고 사람은 확인만 하는 방식」: ChatGPT 채팅 모형(내 말풍선 「내 노션 「걷기 모임」 페이지 맨 아래에 오늘 할 일 세 줄을 적어 주세요.」) → 화살표 위 승인 카드 모형(`n-approve` 축소판, 「승인」) → 노션 「걷기 모임」 페이지 모형(세 줄이 이미 있음 · 맨 아래에 체크 「노션에서 열어 확인」).
- 정의 콜아웃: 에이전트(agent)는 ChatGPT가 내 허락을 받은 뒤 노션 같은 다른 앱에 직접 적어 두는 쓰임새입니다.
- 비유 콜아웃: 인쇄 버튼과 같습니다. 누르면 글이 종이에 바로 찍혀 나오고, 내 손은 종이를 확인하기만 합니다.
- 정보 단위(4): 정의 · 비유 · 전/후 두 칸 · 승인 카드 한 줄(오른쪽 칸 아래 「적기 전에 승인 카드가 먼저 뜹니다」)
- 화면 문구는 사람이 글을 옮기는 일을 뜻하는 낱말 없이 「적습니다」 · 「입력합니다」만 쓴다. 캡처 06의 영어 소개문에 agent가 나온다는 것은 노트에서만 말한다.

- 출처: https://obsidian.md (옵시디언 쪽). 노션 쪽 비교 항목은 「개념 보강 v2」 사실표의 비교 문장이며 별도 URL은 미확인.
- v2 대비: 표의 「(클라우드)」 표기를 뺐다(외래어 풀이가 더 필요해서). 이전의 작은 그래프 이미지도 뺐다.

#### C1-2 · 두 도구의 자리 · 프로젝트는 책상, 노션은 서랍장

- 비유 콜아웃: 책상 위에서 일하고, 끝난 것은 서랍장에 넣는 것과 같습니다.
- 풀이 한 줄(책상 칸 안): 지침은 이 프로젝트의 모든 대화가 먼저 읽는 안내문입니다.

- 정보 단위(4): 정의 · 비유 · 책상과 서랍장 그림(풀이 포함) · 짝 한 줄

#### C1-3 · 플러그인 · ChatGPT와 노션을 잇는 연결과 승인 카드

- 비유 콜아웃: 전기 콘센트와 같습니다. 같은 모양의 플러그면 꽂히고, 켜는 스위치가 승인 카드입니다.
- 낱말 열(영상 자막과 같은 낱말 4개 · 오른쪽 회색은 실습 2에서 하는 곳):

| 순번 | 굵은 낱말 | 한 줄 뜻 | 오른쪽 회색 |
|---|---|---|---|
| 1 | 연결 | ChatGPT와 노션 사이에 플러그를 꽂습니다 | 실습 2 · 1~6단계 |
| 2 | 요청 | 채팅창에 요청문을 보냅니다 | 7단계 |

- 정보 단위(4): 정의 · 비유 · 영상과 낱말 열 · 이동 한 줄

#### C4-4 · RAG · 자료를 먼저 찾아 읽고 쓰는 AI

- 유형: 개념 · 영상 틀(V3 `rag`) · 파트 4 · 아이콘 🔎 · 속성 줄: 「파트 4」 + 태그 「개념」(tg-blue)
- 위쪽 구체 장면: 장면 문장 한 줄 「ChatGPT에 「다음 달 걷기 안내문을 써 주세요」라고 보냅니다」 + 영상 V3(`자료/video/rag.mp4`, 포스터 `rag.png`). 영상은 질문 → 노션 「내 자료함」에서 「지난 안내문」 · 「코스 안내」가 켜짐 → 답 끝에 이름표가 달림 → 이름표를 누르면 원본이 다시 켜지는 장면이다. 영상 캡션: 「이름표를 누르면 원본 줄이 다시 켜집니다」(영상 속 낱말 「출처 칩」은 화면 글에서 「이름표」로 쓰지 않고 영상 자막 그대로 둔다 · 결정 근거 8).
- 정의 콜아웃: RAG(Retrieval-Augmented Generation)는 ChatGPT 같은 AI가 답을 쓰기 전에 자료를 먼저 찾아 읽고, 그 내용을 바탕으로 답을 쓰는 방식입니다.
- 비유 콜아웃: 책을 펴 놓고 푸는 시험과 같습니다. 답을 쓰기 전에 책에서 관련된 쪽을 먼저 찾아 읽습니다.
- 낱말 열(영상 자막과 같은 낱말 3개):

| 순번 | 굵은 낱말 | 한 줄 뜻 |
|---|---|---|
| 1 | 찾기(Retrieval) | 「내 자료함」에서 「지난 안내문」과 「코스 안내」를 찾습니다 |
| 2 | 보태기(Augmented) | 찾은 글을 질문 옆에 붙입니다 |
| 3 | 만들기(Generation) | 붙인 글을 바탕으로 안내문을 씁니다 |

- 토글 「RAG로 좋아지는 것」(열면 세 줄): AI를 다시 학습시키지 않아도 최신 자료와 내 자료를 답에 반영할 수 있습니다. / 그럴듯하지만 거짓인 답(환각)을 줄입니다. / 답에 출처를 붙일 수 있습니다.
- 정보 단위(4): 정의 · 비유 · 영상과 낱말 열 · 토글
- 출처: Lewis 외, "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks", arXiv:2005.11401 (2020 · NeurIPS 2020) · https://arxiv.org/abs/2005.11401
- v2 대비: 비유의 총무를 시험 상황으로 바꿨다(결정 근거 7).

#### C4-5 · 세컨드 브레인 + RAG · 내 기록이 AI의 자료가 되는 모습

- 유형: 개념 · 도식 + 체크리스트 · 파트 4 · 아이콘 📚 · 속성 줄: 「파트 4」 + 태그 「개념」(tg-blue) · 「대조」(tg-green) · 좌우 두 열(왼쪽: 정의 · 비유 · 도식 / 오른쪽: 한계 콜아웃 · 체크리스트)
- 위쪽 구체 장면: 노션 조각으로 만든 가로 그림 하나. 왼쪽 미니 표 「📚 내 자료함」(행 2개: 지난 안내문 · 코스 안내) → 화살표 위 낱말 「찾기 · 보태기」 → 채팅 한 칸(ChatGPT가 읽은 내용으로 쓰는 중) → 화살표 위 낱말 「만들기」 → 오른쪽 멘션 「📄 다음 달 안내문」. 맨 아래 오른쪽에서 왼쪽으로 점선 화살표와 낱말 「노션에서 열어 대조」. 도식 옆에 멘션 칩 「📄 실습 7 · 찾아서 쓰기」(`data-go="P7-1"`).
- 정의 콜아웃: 세컨드 브레인과 RAG를 합치면, 내가 노션에 모아 둔 기록을 ChatGPT가 먼저 찾아 읽고 그 내용을 바탕으로 답을 쓰게 됩니다.
- 비유 콜아웃: 내 수첩을 펴 놓고 푸는 시험과 같습니다. 펴 보는 책이 내가 적어 둔 기록입니다.
- 한계 콜아웃(⚠️ · `cl-yellow`): 「한계」 라벨 뒤 두 문장. 자료가 낡았거나 찾기가 빗나가면 답도 틀립니다. 그래서 ChatGPT가 노션에 적은 것은 노션에서 열어 직접 확인합니다.
- 체크리스트 「AI 답을 노션 원문과 대조합니다」(`n-todo` 3줄 · 처음에는 모두 비어 있다): ☐ 답에 나온 날짜 · 장소 · 이름이 노션 원문 줄과 같다 / ☐ 원문에 없는 내용이 답에 들어 있지 않다 / ☐ 원문 줄의 날짜가 낡지 않았다
- 정보 단위(4): 정의 · 비유 · 도식 · 한계와 체크리스트(한 덩어리). 관통 문장은 한계 콜아웃의 둘째 문장이고 장의 맨 끝 줄이 아니다. 체크리스트가 마지막 요소다.
- 출처: https://arxiv.org/abs/2005.11401 · https://fortelabs.com/blog/basboverview/

#### C4-2 · 유지 · 변경 · 확인 · 요청을 세 칸으로 나눠 쓰는 틀

- 유형: 개념 · 파트 4 · 아이콘 📦 · 속성 줄: 「파트 4」 + 태그 「개념」(tg-blue)
- 위쪽 구체 장면: 실습 7의 요청문 한 줄이 세 칸으로 갈라지는 그림. 한 줄 안의 세 구절을 요청문 원문 그대로 가져온다: 「지난 안내문의 말투와 순서는 그대로 두고」 → 유지 / 「날짜와 코스 이름만 새로 바꾸고」 → 변경 / 「끝나면 바꾼 곳을 알려 주세요」 → 확인. 칸을 누르면 그 구절에 형광이 칠해진다.
- 정의 콜아웃: 유지·변경·확인은 요청을 그대로 둘 것, 바꿀 것, 끝나고 알려 줄 것의 세 칸으로 나눠 쓰는 틀입니다.
- 비유 콜아웃: 이사 업체에 남기는 쪽지와 같습니다. 이건 그대로 두고, 이건 옮기고, 끝나면 알려 달라고 적습니다.
- 정보 단위(3): 정의 · 비유 · 세 칸으로 갈라지는 요청문 그림
- 이 장은 요청문 원문을 고치지 않는다. 구절만 가리킨다.

#### C4-3 · 주간 루틴 · 일주일에 한 번 같은 정리 요청을 보내는 습관

- 유형: 개념 · 파트 4 · 아이콘 🗓 · 속성 줄: 「파트 4」 + 태그 「개념」(tg-blue)
- 위쪽 구체 장면: 한 주 달력(월~일 일곱 칸)의 토요일 칸에 칩 「주간 정리」. 달력 아래 요청문 한 줄을 원문 그대로: 주간 정리입니다. 노션 「받은함」에서 아직 노션 「내 자료함」에 없는 항목을 찾아 행으로 추가하고, 종류를 붙여 주세요. 요일을 누르면 그날 할 일이 뜬다(받은함 비우기 → 자료함에 행 추가 → 태그 확인).

- 정보 단위(3): 정의 · 비유 · 달력과 요청문

### V2.1 결정 근거

1. **기초 장 3장을 파트 1 맨 앞에 두었다.** §15의 지시이고, 실습 0에서 두 탭을 이미 열었으므로 K-1 · K-2는 「이미 본 화면에 이름을 붙이는 장」이라 각 1~2분으로 짧다.
2. **파트 안내 장의 카드 수**: 「할 일 카드 3개」를 「카드마다 항목 3개(실습 이름 · 만드는 노션 페이지 · 이동 ID)」로 읽었다. 카드 수는 실습 수(2)이고, 파트 4만 강사 시연이 더해져 3이다. 3칸 격자가 필요하면 빈 칸 대신 파트 정리 장(B*-9)으로 가는 카드를 셋째로 둘 수 있다(대안).
3. **「지금 내 노션」의 워크스페이스 이름은 「PULSE님의 워크스페이스」다.** 캡처 04와 같은 화면을 이어 보는 학생에게 같은 이름이 보이는 쪽이 헷갈리지 않는다고 판단했다(학생 화면은 각자의 이름).
4. **시간**: 파트 1의 설명 16분 · 정리 1분이 가장 빡빡하다. 실습 분은 그대로 두고 개념 장 · 정리 분에서 맞췄다(표 A). 장당 평균은 약 1.5분이다. 줄이는 순서는 정리(따라잡기는 쉬는 시간으로 보냈다) → C1-5 · C1-2 · K-2 → C1-4a이고, 장 자체는 하나도 빼지 않았다.
5. **C1-4a는 C1-4 뒤에 둔다.** C1-4의 영상이 「위쪽 구체 장면」이고, 실제 앱 화면은 그 확인이다. 앞에 두면 [[링크]]가 설명되기 전에 점과 선을 보게 된다.
6. **옵시디언 화면을 C1-4와 C1-5에 작게 넣지 않는다.** 한 장에 표와 큰 화면이 같이 들어가지 않아서 화면 장을 새로 만들었다. 백링크 이미지는 영어 글이 길어 쓰지 않았다.
7. **C4-4 · C4-5의 비유를 「총무」에서 「펴 놓고 푸는 시험」으로 바꿨다.** §15의 「사물 · 상황 비유(AI를 사람처럼 그리지 않는다)」를 적용했다. C1-1의 수첩은 사물이어서 유지했다. C4-5는 「내 수첩」으로 C1-1과 이어 읽히게 했다.
8. **영상 속 낱말 「출처 칩」**: 영상 자막 그대로 두고 화면 글에서는 새 낱말을 만들지 않았다. 영상이 이름표로 바뀌면 같이 고친다(영상 정합 메모 V3 항목).
9. **C1-1 정의의 「기록 보관소」를 「기록 노트」로**: 비유(총무의 수첩)와 바로 이어지고, 「보관소」는 추상 문장에 가깝다고 판단했다. 용어표의 「개인 기록 보관소」 뜻은 그대로다.
10. **C1-3의 정의에서 MCP를 뒤로 뺐다.** 동의 화면 제목에 MCP가 보이므로(캡처 08) 낱말은 남기되 앞에 쓰지 않았다. 콘센트 「규격」은 「콘센트」로 풀었다.
11. **「쉬는 시간 전 여기까지」 한 줄은 파트 2~4에만 있다.** 파트 1은 입장 바로 뒤여서, 실습 0의 탭 두 개를 그대로 둔다는 한 줄로 바꿨다.
12. **B*-9의 따라잡기 한 줄을 「쉬는 시간에 이어서」로 바꿨다.** 정리 분이 1~6분으로 줄어 장 안에서 따라잡을 시간이 없다. 파트 4는 쉬는 시간이 없어 수업 뒤 집에서로 썼다(F-02의 「집에서 이어 쓰는 순서」와 이어진다).
13. **OP-2에서 서랍 세 칸 그림을 뺐다.** 서랍 세 칸은 C1-1이 처음 보여 주도록 옮겼다(「화면 먼저, 낱말은 나중」).
14. **P2-2 4분 · 7~8단계**: 7 · 8단계는 화면 장 뒤에 한다. 화면 장 4장이 진행 장 7분(1+1+1+1+1+2)을 가져가고 진행 장은 요청문 단계로 4분이 남는다(표 C).
15. **E0-2a~c는 입장 구간(수업 밖)**이므로 사전 가입을 마친 사람은 보지 않는다. 시간표의 입장 30분은 그대로다.
