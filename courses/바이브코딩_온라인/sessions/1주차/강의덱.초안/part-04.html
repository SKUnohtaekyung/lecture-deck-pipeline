작업 방식

한 번에 끝내려 하지 않습니다

첫 요청은 구체적으로, 결과는 반복 수정

처음부터 짧고 모호하게 요청하면 방향부터 잘못 잡습니다.

반대로 첫 요청만으로 완벽한 결과를 기대하는 것도 현실적이지 않습니다.

→

요청 비교

확인할 수 있는 요청

기준이 있으면 결과를 따져 볼 수 있습니다

구체적인 요청

단어 수 · 제한 시간 · 점수 규칙 · 글자 크기를 말합니다.

결과 범위 · 필요 내용 · 완료 기준이 보입니다.

요청하지 않은 기능(순위표 · 로그인)은 만들지 말라고 적습니다.

모호한 요청

“예쁘게 · 깔끔하게 · 알아서”처럼 기준이 없습니다.

결과물 범위와 검수 방법이 없습니다.

사람마다 다른 해석이 생깁니다.

예«예쁘고 재미있게» 대신 «단어 5개 · 맞으면 1점 · 제한 시간 30초»처럼 확인할 수 있는 말로 적습니다.

좋은 요청은 길어서가 아니라, 원하는 결과와 실제 결과를 비교할 수 있어서 좋습니다.

필수 조건

첫 결과물에서 반드시 지킬 것

세 조건은 생략하지 않습니다

01

추가 설치 없음

설치 · 빌드 · 서버 · 프레임워크 없이 시작합니다.

02

HTML · CSS · JavaScript 한 파일

프로젝트 폴더 바로 안의 index.html에 함께 씁니다.

03

외부 라이브러리 없이

게임 동작은 같은 파일 안의 JavaScript로만 만듭니다.

반드시 요청문에 포함“index.html 한 파일로 만들고, 브라우저에서 직접 열 수 있게 해 주세요.”

왜 지키나요?세 조건은 단순해서가 아니라, 파일 위치와 실행 결과를 직접 확인하기 위한 약속입니다.

03번이 «외부 라이브러리 없이»인 이유타자 게임은 JavaScript가 있어야 동작하기 때문입니다.

프론트엔드

브라우저에 보이는 화면

오전에는 프론트엔드를 배웁니다

프론트엔드는 사용자가 브라우저에서 직접 보고 누르는 화면을 만드는 영역입니다.

구조

HTML

제목 · 문장 · 입력칸처럼 화면에 무엇이 들어갈지 정합니다.

비유 집의 뼈대처럼 무엇이 어디에 놓일지 정합니다.

표현

CSS

색 · 글자 크기 · 여백 · 배치처럼 어떻게 보일지 정합니다.

비유 옷과 인테리어처럼 화면의 인상을 만듭니다.

반응

JavaScript

입력 · 클릭 같은 행동에 화면이 반응하게 만듭니다.

비유 스위치처럼 행동을 화면의 변화로 연결합니다.

역할이 다르다고 파일이 반드시 나뉘는 것은 아니며, 오전에는 index.html 한 파일 안에 함께 둡니다.
