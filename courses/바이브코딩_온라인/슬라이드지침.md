# 슬라이드 지침 — 코딩 에이전트와 함께하는 바이브코딩

> **이 과목의 슬라이드를 만들 때 알아야 할 것**만 담는다. 운영 파라미터는 [`profile.md`](profile.md), 과정 상위 기준은 [`커리큘럼_기준안.md`](커리큘럼_기준안.md)(충돌하면 기준안이 이긴다), 슬라이드 단위 원본 대응은 `../../plans/바이브코딩_온라인/PLAN.md`.

## 1. 대상 — 온라인의 고연령 비중 입문자

- 코딩 경험이 없고, 연령대가 높은 편이다. 강사 옆자리 도움 없이 **화면공유만 보고 따라온다.**
- 그래서 화면이 설명을 받쳐야 한다 — 정보량을 줄이지 않는다. 시간 조절은 강사가 한다.
- 가독성 하한(본문 22px · 표 17px · 고대비)은 그대로 지키고, 조작 안내는 **번호 배지 주석 스크린샷**을 우선한다.

## 2. 이 과정은 재구성이다 — 원본 다루는 법

- 원본 4개(바이브코딩 1·2주차 · AI 코딩 에이전트 입문 1·2차시)의 문장·구성을 가져온다. **원본 파일은 수정하지 않는다.**
- 초안 메타는 `> 작성 주체: create-slides(재구성)`. 가져온 장은 집필노트 출처 추적표에 원본(과목·주차·번호/ID)을 남긴다.
- 원본끼리 겹치는 장은 **보강 병합**을 기본으로 하고, 결정은 G1 결정표에 남긴다.

## 3. 반드시 걷어낼 원본 표기

| 원본 표기 | 이 과정에서 |
|---|---|
| Google Antigravity · 가짜 목업 · `WORKSPACE`·`EXPLORER` 라벨 | **Codex 데스크톱 앱** 실제 캡처와 실제 화면 명칭 |
| 검정 «터미널» 모양 요청문 상자 · `REQUEST TERMINAL` 라벨 | «Codex 입력창» 표기(CLI로 오해하지 않게) |
| `/plan` 같은 명령식 표현 | 앱에서 쓰는 자연어 문장(«먼저 계획을 보여 주세요» 등) |
| ChatGPT로 기획 + Codex로 저장하는 두 도구 분업 | Codex 하나로 진행 |
| 원본 과정의 N차시·N주차 표기 · 차시/주차 예고·연결 멘트 · 과정 시간표(50+10+50…) | **이 과정의 1차시·2차시**. 연결은 «1차시에 만든 타자 게임»까지만 |
| 뉴스 Agent·CSV·대시보드 예시 | 타자 게임(1차시) · 나를 소개하는 웹사이트(2차시) 예시 |
| 배포·공개 URL·QR | 다루지 않는다. 필요한 곳은 «공유 전 점검»으로 바꾼다 |

⚠️ **Codex 앱의 화면 사실은 캡처로 확인하기 전에 단정하지 않는다** — 폴더(프로젝트) 선택 방식 · 권한/승인 모드 명칭 · 계획 표시 · 되돌리기 · 미리보기 · AGENTS.md 자동 읽기. 확인 전에는 학생 화면에 «미확인» 문구를 노출하지 않고 캡처 대기 목록으로만 관리한다.

## 4. 이 과목의 구조 관례

- **관통 문장**(제안): «AI가 작성하고, 사람이 검토하고, 사람이 결정한다.» — 1차시·2차시에 한 번 이상.
- **수정 요청은 3단**: 무엇을 유지할지 → 무엇을 바꿀지 → 바뀐 뒤 무엇을 확인할지.
- **오류 보고는 4단**: 어디에서 → 무엇을 했는데 → 실제로 어떻게 됐고 → 원래 무엇을 기대했는지.
- **전문용어는 한 번 정확히, 그다음 쉽게.** 하네스(Harness)는 2차시 B2에서 한 번 정의(프롬프트·컨텍스트·하네스 세 겹 + 말과 마구 비유)하고, 이후에는 «AI에게 일을 맡기는 틀»로 풀어 쓴다.
- **대비 구도를 살린다**: 1차시 «말로 바로» / 2차시 «기준 먼저». «말로만 요청할 때의 한계»는 강사가 화면공유로 보여 주므로 별도 보완 장을 만들지 않는다.
- 작업 폴더 경로 표기는 `C:\VibeCoding\…`로 통일한다.
