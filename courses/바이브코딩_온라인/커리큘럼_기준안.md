# 커리큘럼 기준안 — 코딩 에이전트와 함께하는 바이브코딩

> 2026-09-14 사용자 합의로 확정. 슬라이드 단위 원본 대응표·캡처 목록·진행 상태는 `../../plans/바이브코딩_온라인/PLAN.md`가 정본이다. 이 문서는 과정의 **상위 기준**만 담는다.

## 1. 과정 목표

코딩 경험이 없는 수강생이 하루 동안 Codex 데스크톱 앱으로

1. **1차시** — 말로 요청해 웹 결과물(타자 게임)을 만들고, 한 번에 하나씩 고쳐 본다.
2. **2차시** — 원하는 결과의 기준을 Markdown 문서로 먼저 세우고, 그 기준으로 나를 소개하는 웹사이트를 만들고 확장한다.

대비 구도: 1차시 «말로 바로» → 2차시 «기준 먼저».

## 2. 운영

| 항목 | 기준 |
|---|---|
| 형식 | 온라인 · 같은 날 같은 수강생 |
| 시간 | 오전 2시간 · 점심 · 오후 4시간 |
| 진행 | 강사 강의 비중이 크다. 설치는 사전 공지, 강사가 화면공유로 단계를 한 번씩 보여 준다 |
| 요금제 | ChatGPT Go 또는 Plus(사전 공지 완료) |
| 작업 폴더 | `C:\VibeCoding\…` |

## 3. 구성

### 1차시 — 말로 바로 만들고 고치기

| PART | 내용 |
|---|---|
| A1 | 바이브코딩이란 — AI·LLM·에이전트·Codex의 역할 |
| A2 | AI를 믿는 방법 — 할루시네이션 · 아첨 · 결과 변동성 · 정보 노출 |
| A3 | Codex 작업 환경 — 설치 확인 · 로그인 · 폴더 · 권한 |
| A4 | 좋은 요청의 재료 · 웹페이지의 구조(HTML·CSS·JavaScript) |
| A5 | 실습: 내 단어로 타자 게임 만들기 |
| A6 | 실습: 같은 게임을 한 번에 하나씩 고치기(유지할 것 · 바꿀 것 · 확인할 것) |
| A7 | 오류 대응과 마무리 |

### 2차시 — 기준을 먼저 세우고 만들기

| PART | 내용 |
|---|---|
| B1 | 1차시 되짚기 |
| B2 | Prompt · Context · Markdown — 하네스(Harness) 용어 정의 1회 |
| B3 | 기획 — 누가 볼 사이트인가 · 꼭 넣을 섹션 · 보여 주는 순서 · 완료 기준 |
| B4 | 실습: prd.md · design.md · AGENTS.md 작성 |
| B5 | 실습: md를 기준으로 나를 소개하는 웹사이트 만들기 |
| B6 | 실습: md를 먼저 고쳐 사이트 확장하기 |
| B7 | 검토 · 오류 대응 · 공유 전 점검 · 마무리 |
