### 4.3 모델 계약 호환성 Task의 실행 순서

1. T01은 콘텐츠 리서치가 아닌 설치 환경 진단이다. `claude --version`, 해당 설치본의 도움말·설정 스키마·모델 선택 목록과 공식 문서를 실행 시점에 확인한다. 로컬 증거로 충분하지 않으면 공식 Claude Code 환경 문서 확인을 담당 Opus 진단 역할로 제한한다. 제품 강의 콘텐츠 조사는 여전히 /리서치만 사용한다.
2. Fable 5·Opus 5의 정확한 식별자, 메인/서브 모델 지정 방법, agent frontmatter 허용 표기, 모델별 effort 지원값·설정 우선순위·버전 호환성을 각각 증거와 기록한다. `opus`·`inherit`가 원하는 버전을 뜻한다고 추정하지 않는다. 초기 부트스트랩은 모델을 호출하지 않는 CLI 진단으로 수행하고, 검증된 ID가 생기기 전 이름을 조합해 에이전트를 띄우지 않는다.
3. T02에서 실행 한정 설정·명시 모델 지정·과정 전용 agent 경로/overlay가 현재 설치본에서 실제 지원되는지 검증한다. 과정 디렉터리 아래 .claude를 놓기만 하면 루트 실행에 로드된다고 가정하지 않는다.
4. 우선안은 **공유 스킬 원문을 유지하는 과정 전용 모델·도구 실행 계약**이다. 연구 청크 워커는 여전히 읽기 전용, S-ID는 Opus 연구 리드만 부여한다. 감사 `--expect-model`은 T01에서 검증한 **실제 모델 ID**를 전달한다. 범용 감사가 HTML 작성 워커까지 연구 워커로 잘못 세지 않는지 세션·타입 선택 범위도 확인한다.
5. 격리 불가능하면 T02에서 수정 필요한 공통 파일의 정확한 목록과 패치를 제시한다. 후보는 위 충돌 표의 CLAUDE.md, 두 Claude agent 정의, 리서치/하네스 정본·Claude 어댑터·지시문 템플릿이다. `scripts/analyze_agent_usage.py`는 기존 옵션으로 충분하면 수정 대상에서 뺀다. 정본 frontmatter 변경 시 `.agents/skills/리서치/SKILL.md`, `.agents/skills/하네스/SKILL.md`와 라우팅 eval까지 짝으로 검토한다. `.claude/settings.json`은 실제로 필요한 키가 검증된 때만 목록에 추가한다.

## 5. 오케스트레이터·에이전트·effort 계약

Fable 5는 목표·잠긴 결정, DAG/Wave, 담당자·입력/allowlist 배정, 모델/effort 적용 확인, 파일 잠금, 상태·검증 증거, 적대적 검토 호출, PASS/FAIL/BLOCKED 판정과 반려·재위임·진입 판단을 맡는다. 직접 쓰기는 `A/상태장부.md`의 최소 상태·승인 원문·증거 포인터에 제한한다. 단순 상태 조회와 검증 명령 실행은 허용한다.

원본 대량 통독·슬라이드 본문·HTML/SVG/CSS·리서치·CSV 분석표·실습 문서·작업자 산출물 직접 수정은 Opus 5 담당자에게 위임한다. 통합 수정은 T56 전담 Opus 통합 담당이 한다. Fable은 리뷰어 대신 결함을 고쳐 통과시키지 않는다. 브라우저가 메인 세션에만 귀속될 경우 Fable은 Opus가 지정한 읽기 전용 측정 명령의 전달·실행만 할 수 있다. 시각 분석·수정은 Opus가 담당하며 증거를 넘길 수 없으면 T03에서 BLOCKED다.

리서치 리드는 Fable이 아니라 **Opus 5**다. 플랫폼이 서브에이전트의 중첩 Agent 호출을 지원하지 않으면 Fable이 Opus 리드의 청크 계약을 받아 검증된 Opus 연구 워커를 직접 호출하고, 반환을 리드에 전달한다. Fable은 검색하거나 결과를 집필하지 않는다. deep-research의 내부 모델까지 확인할 수 없으면 그 실행 경로를 가용으로 간주하지 않고, /리서치 정본의 승인된 내부 폴백 가능 여부를 T02에서 확정한다.

### 5.1 Astra가 설계한 effort 배정 정책

**아래 E0~E4는 API effort 문자열이 아닌 난이도 배정 변수다.** 현재 Claude Code 지원값을 확인하지 않았으므로 Task 표의 `미확인(E2)` 같은 셀을 실행 인자로 보내면 안 된다. 사용자 요청의 “실제 지원값”과 “추측 금지”를 동시에 지키기 위해 T01이 확인한 지원 집합으로만 구체화한다. 이 구체화 전에는 제작 Task가 RUNNING으로 바뀔 수 없다.

### 5.2 위임 계약과 단일 라이터

각 위임은 표의 18필드, 원 사용자 요구·잠긴 결정, 루트·과목 환경, 필요한 정본, 기존 변경 기준선, 명시 allowlist와 금지 경로, 완료/성공 기준, 증거 위치, 실패 처리로 구성한다. “다른 에이전트와 같은 저장소를 쓴다. 다른 담당자의 변경을 되돌리지 말고 충돌을 보고한다. 임시 파일은 저장소 tmp/에만 둔다”를 프롬프트에 직접 넣는다.

파일 쓰기 잠금은 Task ID·작성자·경로·시작/종료 시각으로 장부에 남긴다. 차시별 작성자 세 명은 서로 다른 S1/S2/S3만 쓴다. 공통 profile·커리큘럼·보존 매트릭스·레지스트리·검증 스크립트는 병렬 작성자에게 주지 않는다. 각 작성자는 자기 차시 보존 반영표만 쓰고 전역 병합은 T51/T56 담당이 순차 수행한다.

Task가 너무 크면 실행 전에 안정적인 `T31-W-청크슬러그` 같은 child ID를 장부에 등록하고 18필드를 모두 채운다. 각 실질 child에도 새 독립 검토를 배정한다. “워커 내부 작업”이라는 이유로 검토를 생략하지 않는다. 동시성은 기본 최대 3개 실행 작업으로 제한하며 리뷰어도 슬롯을 소비한다. 총 호출·수정 시도 수는 G00/G30에서 제시하고 승인된 상한을 초과하면 재승인한다. 무제한 재시도하지 않는다.

## 7. 전수 원본 감사·보존 설계

### 7.1 인벤토리와 계보

T10은 B의 1·2·3주차 전체 파일 및 이들이 참조하는 자산·출처·리서치·계약·검증 설정을 목록화한다. 새 과정의 O1/O2·참고 PDF/PPTX·DATA·현재 폴더 구조도 포함한다. gitignored 내보내기 파일도 탐색하되 유사 worktree의 사본은 중복 후보로만 기록한다.

파일 필드: `file_id, 상대경로, 크기, SHA-256, 확장자/실제 형식, 원본 주차, Git 상태, 작성/수정 근거, 참조 대상, 분류, 부모 file_id, 판정 근거, 미확인 사유`. 분류는 **편집 정본·조립 결과물·내보내기 결과물·참고자료·템플릿·중복본·상태 확인 필요** 중 하나다. 수정 시각만으로 정본을 결정하지 않는다.

T11은 shard↔조립본↔배포본↔발표본↔PDF/PPTX↔노트의 계보를 확인한다. 동일 해시는 중복의 강한 근거지만, 다른 해시는 인라인 폰트·런타임·노트 차이일 수 있으므로 DOM·슬라이드 ID·본문·시각 구조를 함께 비교한다. 조립 결과물만 최신이면 원본을 재조립해 덮지 않고 불일치를 기록한다. 계보 확정 전에 슬라이드 수를 합산하지 않는다.

### 7.2 텍스트와 렌더를 결합한 추출

T12-A/B/C는 각 원본 주차 전담, T12-D는 O1/O2·참고 파일·새 템플릿/CSV 메타데이터 전담이다. 계보 확정본에서 다음을 전수 추출한다.

- 안정 ID, 실제 DOM 순서·페이지 번호, 제목·본문·유보·경고·강조 문구.
- SVG와 도표의 노드/선/화살표/축/범례/단위, 원본 이미지·캡처·색 강조와 그 의미.
- 배치·읽기 순서·비교 대상·강조 순서, 단계 공개 전/후 상태, 인터랙션 의도.
- 앞뒤 슬라이드의 연결, 예시의 동일성, 발표자 노트와 별도 강사대본.
- PDF의 페이지 화면과 추출 텍스트, PPTX의 슬라이드·노트·미디어·숨김·애니메이션 의도. 내보내기에서 소실된 동작은 원본 HTML과 대조.
- 원본 캡처 경로·뷰포트·파일 해시·측정 상태. 읽을 수 없는 미디어는 `[확인불가]`와 BLOCKED 사유.

텍스트 없는 시각 슬라이드도 필수 대상이다. “제목 0개”는 “슬라이드 0장”이 아니다. T13 독립 대조자는 작성자의 목록을 기준 정답으로 쓰지 않고 원파일·DOM·렌더·노트에서 별도 수를 뽑는다. 계수 일치·미판정 수와 빠진 ID를 대조한 뒤 G10으로 간다.

### 7.3 슬라이드 보존 매트릭스

최소 필드는 다음 21개이며 `file_id/원본해시/시각증거/검토증거`도 추가한다.

`안정적인 원본 ID, 원본 주차, 원본 파일, 원본 슬라이드 번호, 제목, 핵심 메시지, 교육적 역할, 시각 자료 유형, 주요 예시, 앞뒤 맥락, 새 처리 상태, 새 차시, 새 위치, 본편·실습·노트·부록 구분, 통합 대상, 변경 이유, 반드시 보존할 유보·주의점, 리서치 필요 여부, 구현 상태, 검토 상태, file_id`.

안정 ID는 `VC-Wn-기존data-slide`를 기본으로 하며 원본 해시를 별도 저장한다. ID가 없거나 중복이면 파일 계보 ID와 최초 위치를 조합한 고정 surrogate ID를 T11에서 발급한다. 출력 페이지가 바뀌어도 원본 ID를 다시 매기지 않는다. 새 덱은 `AC3-Ln-일련번호`와 같은 별도 ID를 쓴다. PDF/PPTX가 동일 슬라이드를 재표현하면 같은 원본 ID의 표현물로 연결한다.

새 처리 상태는 **새 강의 본편 / 실습 안내 / 발표자 노트 / 부록 / 수강생 참고자료 / 다른 슬라이드와 통합 / 현재 사실에 맞게 수정 / 제외** 중 하나다. 통합·수정 행도 최종 매체와 실제 대상 ID를 반드시 가진다. 한 원본의 분할은 같은 행의 복수 목적지 또는 별도 연결표로 표현한다. 여러 원본의 통합은 모든 원본 ID의 메시지·유보가 실현되는지 각각 확인한다.

제외·통합·대폭 수정은 학습목표·시간·중복·현재 사실·제외 조건 중 구체 근거와 검토 증거를 갖춘다. GitHub 실습은 새 필수 본편에서 제외하더라도 원본 행과 이유를 삭제하지 않는다. 시각 형태를 바꿔 병렬 항목에 순서·인과·우열·배타성을 추가하면 D2로 기록하고 근거를 검토한다.

- **추적률** = 처리 상태·유효 목적지 또는 승인된 제외 근거가 있는 고유 원본 슬라이드 수 / 계보 확정된 고유 원본 슬라이드 수. 목표 100%.
- **본편 채택률** = 새 본편에서 실현된 고유 원본 슬라이드 수 / 같은 모수. 목표 고정 없음. 통합한 원본 여러 개는 각 원본의 실제 의미 보존 확인 후 각각 센다.
- 미확인 원본·미해결 계보가 있으면 분모를 줄여 100%라고 선언하지 않는다. 확인 모수의 잠정률과 미확인 수를 함께 표시하고 전체 판정 BLOCKED.
- 과거 삭제 이력은 현존 원본 모수와 분리한다. 이미 미복구가 확정된 V1-04 등을 자동으로 살리지 않는다.

## 9. 미래 리서치의 유일한 경로

**이번에는 콘텐츠 리서치를 수행하지 않았다.** 실제 제작 때도 Astra와 Fable이 웹을 직접 검색해 강의 사실을 채우지 않는다. 신규·최신 제품 사실의 조사는 반드시 명시 호출한 **/리서치 스킬**의 책임이다.

T30은 원본에서 충족된 내용을 먼저 표시한 뒤 실제 공백만 등록한다. 갭 필드: `Gap-ID, 학습목표/L-ID, 원본 충족 증거, 미충족 내용, 필요성, 우선순위 P0/P1/P2, 예상 사용 차시·슬라이드/실습, 최신성 위험, 필요한 검증, 범위 내/인접, 채택·기각, 승인 근거, 대응 C-ID/S-ID`.

후보는 Antigravity 설치·현재 UI·무료 범위/제한·권한·스킬/MCP/플러그인 지원·실제로 시연할 기능·기존에 없는 신규 개념이다. 주변 트렌드·분량 늘리기·기존 자료의 단순 재작성·미승인 인접 개념·본문/수업에 쓰지 않을 정보는 제외한다. 기존 안정 개념의 근거가 충분하면 재사용 포인터로 연결하고 재검색하지 않는다. 최신성이 필요한 기존 사실은 “이미 있다”만으로 조사 면제하지 않는다.

### 9.1 Gate A와 기본 5파일

G30에서 /리서치 Gate A의 순서를 그대로 따른다.

1. 교시 목록.
2. 교시별 핵심 질문.
3. 실습 후보.
4. 결정요청 후보.
5. 인접 개념 후보: `본 개념 / 인접 개념 / 종류 / 왜 필요한가(학생이 언제 묻는가)`.

주차 상세설계가 없다는 사실과 역산 제안임을 표기하고, **사용자의 범위 확인 후에만** /리서치 실행으로 넘어간다. G7 재대조에서 범위 밖 누락이 발견돼도 자동 추가 조사하지 않고 결정요청에 올린다.

저장소 정본 기본 5파일을 각 차시 `Sn/자료/`에 다음 **파일명 그대로** 쓴다. 화면의 “차시” 명칭과 달리 파이프라인 파일명은 “주차”다.

|---|---|

### 9.2 검증 절차

정본 G1~G9를 적용한다. 조사 시점 5개월 신선도, 사실별 URL·확인 날짜·원문 열기, 제품 사실과 경험 진술 구분, 짧은 verbatim, 능력/범위 구분, 기존 확정 유지, 매트릭스와 독립한 원문 재대조가 필요하다. 안정 개념의 오래된 출처는 예외 승인을 기록한다. G8의 코어 관점 최소치와 G9 승인·깊이·물량 제한을 임의로 완화하지 않는다.

$env:CREATE_SLIDES_COURSE='AI_코딩_에이전트_입문_3차시'
python scripts/verify_research_chunks.py N주차

N=1,2,3 각각 실행한다. 마지막 감사 명령은 **T02에서 해당 호출의 모델·감사 계약을 승인받은 후에만 유효**하며 현재 스킬 기본 명령의 Sonnet 기대값을 몰래 우회하는 용도가 아니다. 정본 기본 감사 명령은 `python scripts/analyze_agent_usage.py --tool-audit --session <세션ID>`이고 기본 기대값이 Sonnet인 충돌을 별도로 해결해야 한다.

검사 종료코드·판정 건수·미판정 건수·원문 대조 범위를 기록한다. 0개 대상은 입력 부재인지 계수 실패인지 구분한다. 이어 각 차시 `/검토 N주차 자료`를 명시 호출하고 독립 적대적 검토 PASS 후에만 /create-slides로 전달한다. /검토의 링크 재확인은 기존 근거 검증이며 신규 개념 수집이 아니다. 신규 사실이 필요하면 T30/G30으로 되돌린다.

## 10. Task DAG·Wave와 전체 Task 표

## 11. 적대적 검토·정규 /검토·실패 처리

### 11.1 독립성 및 15개 필수 질문

매 실질 Task의 작성자와 **다른 새로운 Opus 5**를 호출한다. 수정 후에는 이전 검토자도 재사용하지 않는다. 읽기 전용으로 도구를 제한하고 Write/Edit/NotebookEdit 및 쓰기 가능한 범용 셸을 주지 않는다. 검증 명령이 필요하면 오케스트레이터가 확정된 읽기 전용 명령을 실행해 원문 결과를 제공한다. 검토자는 산출물·원 요청·잠긴 결정·Task 계약을 직접 읽고 작성자의 자기평가나 이전 검토 결론을 정답으로 삼지 않는다.

지적을 억지로 만들지 않고 치명적 실패 가능성을 먼저 탐색한다. 모든 지적에 파일 경로와 행/slide ID·재현 절차·실제 관찰·기대 조건·수정 담당을 붙인다. 발견이 없더라도 실제 본 대상 수·못 본 대상 수를 함께 반환한다.

모든 적대적 검토는 아래 질문을 해당/비해당 사유와 대조한다.

1. 잘못된 작업공간이나 파생본을 원본으로 사용했는가?
2. 요청된 입력 자료를 빠짐없이 확인했는가?
3. 원본 슬라이드 또는 핵심 개념이 조용히 누락됐는가?
4. 통합하면서 원래 의미·유보·주의점이 사라졌는가?
5. 시각 구조가 원본에 없던 인과·순위·배타성을 만들었는가?
6. 새 사실을 /리서치 산출물 없이 작성했는가?
7. 과거 4차시 내용이나 템플릿 잔재가 3차시에 섞였는가?
8. 실제 강의 시간이 120분을 초과하는가?
9. 초보자가 수행하기 어려운 숨은 선행지식이 있는가?
10. 실습 실패 시 복구 경로가 있는가?
11. CSV 분석과 대시보드 숫자가 일치하는가?
12. 모바일·온라인 환경에서 화면을 사용할 수 있는가?
13. 허용 경로 밖 파일을 수정했는가?
14. 검증기가 실제 대상 전체를 검사했는가?
15. 완료 주장만 있고 증거가 없는 사용자 요구가 있는가?

검토 반환 판정은 정확히 하나다.

| 판정 | 뜻 / 다음 처리 |
|---|---|
| PASS | Task 완료 기준과 성공 기준 모두 충족. 의존 Task 진입 가능 |
| FAIL | 수정 없이는 해당 결과를 다음 단계에 사용 불가 |
| BLOCKED | 외부 정보·지원 환경·사용자 결정 필요 |
| INCONCLUSIVE | 증거 부족. PASS가 아니며 증거 확보 전 다음 의존 Task 중지 |

Task 장부 상태는 PENDING/RUNNING/PASS/FAIL/BLOCKED다. INCONCLUSIVE는 **검토 판정 필드**에 그대로 보존하고 Task 상태는 검증 미완료 PENDING 또는 외부 증거가 필요한 BLOCKED로 둔다. PASS로 매핑하지 않는다.

### 11.2 /검토와의 역할 분리

Task 단위 R-검토와 별도로, 다음 지점에 반드시 스킬 이름을 명시한다. `N주차` 인자와 함께 **C의 해당 Sn 절대경로 및 CREATE_SLIDES_COURSE**를 전달하여 다른 과목을 추측하지 않게 한다.

| 시점 | Task / 명시 호출 |
|---|---|
| 리서치 기본5파일 후 | T33: 각 차시 `/검토 N주차 자료` |
| 차시 초안 후 | T40-Q/T42-Q/T44-Q: 각 `/검토 N주차 초안` |
| 차시 덱·발표자노트 조립 후 | T41/T43/T45: 각 `/검토 N주차 덱` |
| 세 차시 교차 일관성 | T55: 각 `/검토 N주차 전체`, 다른 두 차시와의 연결도 입력 |
| 최종 릴리스 직전 | T57: 통합 수정 후 최신 버전으로 각 `/검토 N주차 전체` |

/검토는 한 호출당 Qn 보고서 **1개만** 쓴다. 같은 날 재호출은 접미사로 보존한다. 대상 파일을 수정·정리·이동·삭제하지 않는다. 3차시 전체를 한 보고서로 쓰기 위해 스킬 출력 경로를 임의로 변경하지 않는다. 교차 결과는 각 보고서 교차 일관성 절에 넣고 Fable 장부에서 세 보고서를 연결한다.

**보고서의 정확성 PASS와 보고 대상의 품질 PASS는 별도 필드**다. 예컨대 /검토가 정확한 FAIL 보고서를 만들었다면 그 보고서 작성 Task의 검토는 PASS일 수 있다. 그러나 해당 덱의 FAIL은 남으며 조립 후속·배포로 진행할 수 없다. 허용되는 다음 동작은 지정 수정 Task와 증거 보강뿐이다. T40-P·G31·G40~42·G50·G51은 보고 대상 FAIL/미판정도 반드시 0인지 확인한다.

### 11.3 FAIL 이후 경로

1. Fable이 결함·재현·영향 파일·성공 기준을 원 작성자 또는 별도 Opus 수정 담당에게 전달한다.
2. 파일 잠금을 회수·재발급하고 **해당 결함에 필요한 경로만** 수정한다. 리뷰어·Fable이 콘텐츠를 고치지 않는다.
3. 수정 후 변경 영향의 정적 검사·숫자 검산·렌더·노트·보존 대조와 필요한 /검토를 다시 수행한다.
4. 새 Opus 적대적 검토자를 호출한다. 이전 검토자의 PASS를 재사용하지 않는다.
5. 두 번 연속 FAIL이면 원인을 입력 부족 / 계약 충돌 / 실행 결함 / 검증 사각 / 시간·범위 초과로 분류한다. 세 번째 시도 전에 사용자 결정 필요성과 예산 상한을 판단한다.
6. 범위·정본·모델 정책 충돌은 BLOCKED. 변경 허용 범위 확대는 G00/G21/G30 중 해당 게이트로 다시 제출한다.
7. 상태 장부에는 `Task ID, attempt, author instance, reviewer instance, requested/effective model, requested/effective effort, input/output hash, evidence, task status, 대상 품질 판정, next action`을 남긴다.

재작업은 정상 DAG의 다음 단계 진입이 아니다. `Task-ID/attempt-02` 같은 시도 장부로 관리하고 미래 DAG에 역방향 의존을 추가해 순환을 만들지 않는다. 내용이 바뀌면 해당 산출물에 의존한 이전 PASS를 stale로 표시하고 영향 범위만 다시 검증한다. 영향 판단 없이 전체를 무조건 다시 만들거나, 반대로 관련 검증을 생략하지 않는다.

## 12. 검증 방법과 증거 규격

아래는 **미래 제작 검증 명령**이며 이번 계획 세션에서 실행한 것이 아니다. 실행 시 T04의 `A/검증명령.md`에 설치 버전·실제 옵션·입출력 경로를 확정한다. 각 검사에는 종료코드 외에 **입력 대상 수 / 판정 수 / 미판정 수 / FAIL·WARN / 오탐·미탐 확인 범위**를 남긴다. 대상 0과 입력 부재를 구분하고 검증이 보지 못한 범위를 성공 계수에 넣지 않는다.

### V-SOURCE / V-TRACE / V-TIME / V-DRAFT

- V-SOURCE: 독립 파일 목록과 참조 그래프, 원본 HTML DOM·shard·PDF/PPTX·노트·시각 상태를 대조한다. 렌더 실패·암호화·누락·변환 미지원은 명시한다. PDF/PPTX 열람 시 실행 환경의 PDF/프레젠테이션 도구와 런타임을 확인하고 원본을 수정하지 않는다.
- V-TRACE: 원본 ID 집합과 보존 매트릭스의 집합 일치, ID 유일성, 목적지 파일/slide ID 존재, 통합의 모든 역참조, 제외·수정 근거, 필수 유보와 실제 화면을 전수 대조한다. 프로그램 계수와 의미 검토를 분리한다.
- V-TIME: 시간용량 CSV의 각 차시 합=120, 블록합=50/10/50/10, 학습목표≤3, 설치·사람 입력·질문·복구 시간 포함을 계산한다. 리허설 실측과 분 단위 계획을 비교한다.
- V-DRAFT: 4열 표·저자 메타·refs·필수 진술·집필노트 추적표/재료처분표·D2 근거·원문 소유권을 검사한다. 빈 템플릿은 미완성으로 판정한다.

~~~powershell
$env:CREATE_SLIDES_COURSE='AI_코딩_에이전트_입문_3차시'

~~~

N=1,2,3이며 `--parts`는 차시 수나 슬라이드 수가 아니다. manifest·필요한 중앙 registry를 명시하고 배포 확정 검토에서만 `--release`를 쓴다. 생성물 직접 편집 대신 shard를 수정한다. 이동/삭제가 있으면 R-MOVE-01의 노트·divider·family·목차·실습번호·manifest를 함께 대조하며 노트 snapshot/baseline은 T04에서 실제 저장 옵션과 안전한 경로를 확정한다.

**run_deck_checks·렌더 수신 절차는 B03 해소 전 실행 금지**다. 현재 기본 `sessions/_verify/N주차`에 새 과정 JSON을 쓰지 않는다. T04는 Vn으로 수신·판정이 일치하는 실제 명령을 확정해야 한다. 기존 레거시 증거를 잠시 덮고 복원하는 우회도 사용하지 않는다.

로컬 HTTP 서버에서 모든 슬라이드를 순회한다. `document.fonts.ready`, 이미지 로드 완료·naturalWidth, CSS 로드, viewport·DPR·user-agent를 확인하고 `audit_all.js`를 캐시버스터와 no-store로 호출한다. 반환 JSON을 전사하지 않고 그대로 저장한다. evidence에는 덱 hash·slideCount·환경·측정 도구 버전·시각을 남긴다. 정확한 shape·시각물 의미는 사람이 아닌 **담당 Opus 시각 분석자**가 원본과 대조하고 Fable은 증거·판정을 관리한다.

강의 캔버스는 1280×720을 유지하고 정규 감사는 그 이상 뷰포트에서 수행한다. 모바일 검증은 별도로 390px·768px 폭 등 G21에서 정한 작은 화면에서 제목·차트·표·조작·노트를 확인한다. 전체를 작게 축소해 글자가 읽히지 않는 상태, scale=0의 결함0, overflow:hidden으로 숨긴 잘림은 PASS가 아니다. 차시 shell의 과목 전용 읽기 모드·확대/이동 등으로 해결할 수 있는지 T03에서 설계하고, 의미·사용성을 유지할 수 없으면 미검증/차단으로 남긴다. 공용 kit·기존 동결 덱을 고치지 않는다.

### V-DATA

원본 CSV는 byte hash로 잠그고 정제·분석 결과를 X3 별도 파일에 쓴다. 다음 정의를 **사람이 승인한 분석계획**에 고정한 뒤 계산한다.

- 한 행의 단위, 주문행 수와 고유 order_id 수의 차이.
- 중복 판단 키·완전중복/부분중복, 결측 처리, 타입 변환, 이상값 처리와 보류 규칙.
- 취소·반품·환불·배송비·할인·수량의 매출/원가/마진 포함 여부.
- 날짜 범위·월 집계·카테고리·브랜드 기준, 평균의 분모, 비율의 분자/분모, 금액 반올림 시점.
- 원본 행 → 제외/보류/채택 행의 조정표. 모든 행의 행방을 설명한다.
- 답할 수 있는 질문과 데이터만으로 답할 수 없는 질문·인과 한계.

T46은 승인 정의에 따른 기준값을 만든다. T53은 원본에서 별도 구현·계산 경로로 검산하고 작성자 계산 결과를 정답으로 복사하지 않는다. 원본 행·분석행, 주문·매출, 월별 합계, 상품군 매출·마진, 배송 기간·평점 및 표시된 모든 핵심 숫자를 dashboard DOM·차트 tooltip·필터 상태·분석 Markdown과 대조한다. 표시 반올림은 승인 규칙과 같아야 하며 미설명 허용오차를 두지 않는다. 불일치 0은 실제 대조한 지표 수와 필터 조합 수를 동반한다. 계산 코드가 만든 값을 AI 문장이 다른 숫자로 바꾸지 못하도록 값→근거 포인터를 둔다.
