### 5-1. 세션 종류별 `--allow` 프리셋

**목적: 모델 위반(Fable 누출)이 도구 소음에 묻히지 않게 한다.** 세션 타입과 다른 좁은 allowlist로 돌리면
정당한 `Write`·`Edit`가 전부 ⛔로 찍혀 exit 3이 되고, 그 안에 섞인 **진짜 위반인 모델 불일치**를 사람이
구분하지 못한다. 그래서 세션 종류마다 프리셋을 **미리 고정**한다.

```powershell
# ① /리서치 세션 — 기본 6종(WebSearch,WebFetch,Read,Grep,Glob,ToolSearch) · --allow를 주지 않는다
python scripts/analyze_agent_usage.py --tool-audit --session <세션ID> --expect-model claude-opus-5

# ② writer 세션(ac3-writer)
python scripts/analyze_agent_usage.py --tool-audit --session <세션ID> --expect-model claude-opus-5 --allow Read,Grep,Glob,Edit,Write,Bash,ToolSearch

# ③ clerk 세션(ac3-clerk)
python scripts/analyze_agent_usage.py --tool-audit --session <세션ID> --expect-model claude-opus-5 --allow Read,Grep,Glob,Bash

# ④ reviewer 세션(ac3-reviewer)
python scripts/analyze_agent_usage.py --tool-audit --session <세션ID> --expect-model claude-opus-5 --allow Read,Glob,Grep
```

- 각 프리셋은 §3 매핑표의 `tools:` 문자열과 **같은 철자**다. 정의를 고치면 이 프리셋도 같이 고친다.
  ①의 기본 6종은 스크립트의 `WORKER_TOOL_ALLOWLIST` 기본값이므로 `--allow`를 **생략하는 것이 정본**이다.
- 프리셋을 여러 타입의 **합집합으로 넓히지 않는다.** 넓히면 clerk의 `Write` 같은 **진짜 위반이 통과**한다.
- **혼합 세션**(이 세션처럼 writer·clerk·reviewer가 한 세션에 섞인 경우)은 프리셋 하나로 판정할 수 없다.
  둘 중 하나를 쓴다 — **ⓐ 타입별로 세션을 분리해 실행**(권장 · §4 ⑧과 같은 방향), 또는 **ⓑ 한 번 돌린 뒤
  `<세션>/subagents/agent-*.meta.json`의 `agentType`을 워커별로 수기 대조**해 ⛔로 찍힌 도구가 그 워커
  타입의 허용 도구인지 판정한다. ⓑ를 쓰면 **대조 결과를 장부에 적는다** — 감사기는 `agentType`을 읽지
  않으므로 ⓑ의 정확성은 전적으로 사람의 대조에 달려 있다(§4 ⑧).

### 5-2. 종료코드 — **모드마다 다르다**

**`--tool-audit` 모드에서 나올 수 있는 코드는 아래 4개뿐이다.**

| 종료코드 | 의미 | 처리 |
|---|---|---|
| `0` | 판정했고 위반 없음 | 통과 |
| `2` | **입력 오류** — `--session` 누락. 인자 검사에서 끝났고 **감사는 시작조차 하지 않았다** | 세션 ID를 주고 다시 돌린다. 통과·실패 어느 쪽으로도 읽지 않는다 |
| `3` | 판정했고 **위반 있음**(허용목록 외 도구 · 기대 모델 불일치 · 동일 URL 재호출 상한 초과) | 해당 워커 산출물을 **채택하지 않는다**. 먼저 §5-1 프리셋이 세션 타입과 맞는지 확인한다 |
| **`4`** | **미판정** — 대상 워커 로그가 0개라 아무것도 판정하지 못했다 | **통과가 아니다.** `--projects-dir`·`--session`을 확인하고 실제 `Agent` 호출 수와 대조한다. 「입력이 아예 없어서 0」이면 그 사실을 증거로 장부에 적는다 |

**비-audit 모드(계측·기준선 대조) 전용 코드** — `--tool-audit` **없이** 돌릴 때만 나온다:

| 종료코드 | 의미 | 처리 |
|---|---|---|
| `1` | 집계 대상 없음(에이전트 로그를 하나도 찾지 못함) | 입력을 확인한다. **`--tool-audit`에서는 이 코드가 나오지 않는다** — 같은 상황이 audit 모드에서는 `4`(미판정)다 |
| `2` | **기준선 불일치**(`--no-baseline` 없이 돌렸고 값이 어긋났다) | 임의 채택하지 않는다. audit 모드의 `2`(입력 오류)와 **의미가 다르다** |

- **`2`는 두 모드에서 뜻이 갈리는 유일한 코드다.** 보고에 코드만 적지 말고 **어느 모드로 돌렸는지** 함께 적는다.
- 코드 4는 2026-09-09 신설(C-3 (d)안 · `AGENTS.md` 「눈먼 0 방지」). **「위반 3」과 섞지 않는다** —
  섞으면 래칫이 흔들린다.
- 같은 원리로 `--no-baseline` 없이 돌렸는데 **워커가 0**이면 기준선 대조도 `4`(미판정)로 끝난다.
  종전에는 `statistics.mean([])`로 **트레이스백**했다(원본에도 있던 잠복 버그).

## 부록 A. `ac3-auditor` 정의 초안 (§3-1 ㉡ 선택지 ⓐ · **아직 만들지 않았다**)

아래는 **사용자 승인 요청용 초안**이다. `.claude/agents/ac3-auditor.md`는 **생성하지 않았다** — 5번째 정의
신설은 G00 D4(4종 승인)의 범위를 넘으므로 **재승인 사항**이다. 사용자가 ⓐ를 택하면 이 frontmatter 그대로
파일을 만들고, 본문 규율은 `ac3-writer.md`의 「지켜야 할 것」에 「판정 근거를 산출물 파일에 남긴다」와
「검산은 원자료를 다시 읽어 재계산한다 — 앞 Task의 요약을 근거로 쓰지 않는다」를 더해 쓴다.

```yaml
---
name: ac3-auditor
description: AI_코딩_에이전트_입문_3차시 전용 — 데이터 교차 검증·검산·최종 누락/왜곡 감사 담당(Opus 5·최대 추론). 판정과 함께 검산 CSV·감사 기록 파일을 직접 쓴다. 이 과정 밖에서는 호출하지 않는다.
tools: Read, Grep, Glob, Edit, Write, Bash, ToolSearch
model: opus
effort: max
---
```

- `ac3-writer`와 `tools`가 같고 **`effort`만 `max`** 다 — E4의 요구(§2)를 만족시키면서 쓰기 권한을 준다.
  E4 쓰기 14건이 이 정의로 옮겨가면 §3 매핑표의 `ac3-reviewer` 대응은 **읽기 전용 48건 그대로** 남는다.
- 감사 프리셋은 writer와 동일하다: `--allow Read,Grep,Glob,Edit,Write,Bash,ToolSearch`(§5-1 ②).
- 채택되면 ① §3 매핑표에 5번째 행 추가 ② §3-1 ㉡을 「해소」로 변경 ③ §5-1에 auditor 프리셋 추가
  ④ 이 부록 삭제 — 네 가지를 **한 번에** 한다. 채택되지 않으면 ⓑ/ⓒ 결정을 §3-1 ㉡에 적고 이 부록을 지운다.
