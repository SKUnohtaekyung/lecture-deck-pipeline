### 1-1. 충돌의 성질 요약

- **구조적 충돌은 2건뿐**(C1·C2)이고, 둘 다 **호출부 `model` 인자 또는 새 정의 파일로 우회 가능**하다(T01 §5 실측: `Agent(subagent_type="instruction-reviewer", model="opus")` → 로그 `"model":"claude-opus-5"`, `tools` 계약 유지).
- **나머지 문서 충돌 12건 중 실제로 이번 과정을 막는 것은 C3·C5·C6 세 줄**이다(전부 `.claude/skills/리서치/SKILL.md`). 하네스 6건(C14~C19)은 **`/하네스`를 호출하지 않으면 발화하지 않는다** — 계획서 §5·§10은 Fable이 자체 DAG로 오케스트레이션하므로 하네스 스킬 호출이 계약에 없다.
- **감사층 결함 3건(C9·C10·C11)은 모델 정책과 무관하게 이미 존재하던 결함**이며, `--expect-model`로 해결되지 않는다.
- **정의 파일로 닫을 수 없는 세 번째 구멍이 있다(C26~C28).** `.claude/agents/`는 «그 이름으로 부를 때»만 발화한다. 내장 타입은 그 registry 밖이라 **어떤 정의 파일로도 모델을 고정할 수 없고**, 해결안 B는 opt-in이므로 `Agent(subagent_type:"general-purpose")` 호출 자체를 막지 못한다. 실제로 이 세션의 스모크 로그 `aef00c9d…`는 **메인 모델 `claude-fable-5-1`로 돌았고**, `--expect-model claude-opus-5` 감사에서 모델 불일치로 잡혔다(§5-2 · 2026-09-08 15:27). **막는 수단은 규율과 사후 감사뿐이므로 G00 승인 항목으로 올린다**(§7-2 ⑫).

- `Agent` 도구 스키마의 인자는 `description`·`isolation`·`model`·`prompt`·`run_in_background`·`subagent_type` **6개뿐이고 effort가 없다**(T01 §4).

- 따라서 A만 쓰면 **모든 하위 에이전트가 Fable 메인의 effort 한 값을 그대로 받는다.** §5.1의 E0(`low`)~E4(`max`) 5단계 차등은 **0% 구현된다.**
- ⚠️ **이것은 「`Agent` 도구 경로의 한계」이지 「B만이 유일한 해결책」이라는 뜻이 아니다.** effort를 실제로 실을 수 있는 경로는 두 개다 — **B**(정의 frontmatter `effort:`) 와 **B′**(`Workflow` 스크립트의 `agent(prompt, {effort})`). B′는 §3-9에서 따로 다룬다. attempt-01의 「effort 정책은 B로만 구현된다」는 이 지점에서 과잉 단정이었다.
- 특히 **E4(`max`) — 적대적 검토·최종 누락 감사**가 메인과 같은 값으로 떨어진다. 계획서가 R-Task 전부에 E4를 배정한 이유(독립 재계산·반례 탐색)가 무력화된다.

> **A는 «모델만 맞추고 effort 정책은 포기하는 안»이다.** 계획서 §5.1이 「이 구체화 전에는 제작 Task가 RUNNING으로 바뀔 수 없다」고 못박았으므로, A 단독은 그 조건을 만족시키지 못한다. (A + B′ 조합은 effort를 실을 수 있으나 **도구 화이트리스트를 잃는다** — §3-9 비교표.)

### 2-5. 세션 분리와의 결합

A를 쓰든 B를 쓰든, **/리서치는 전용 세션에서 돌려야 감사가 성립한다**(§5). 세션 분리는 A의 대안이 아니라 A·B 공통 전제다.

# ac3-research-worker

이 서브에이전트는 `/리서치` 스킬 4단계(심층 조사)의 **이 과정 전용** 실행 수단이다. 조사 규칙의

## 지켜야 할 것

- **파일을 만들지 마라.** 기본 5파일도, 임시 파일도 쓰지 않는다. 조사 결과는 오직 반환값으로만 리드에게 간다 — 예외 없다. (`tools` 목록에 `Write`·`Edit`가 없어 구조적으로도 막혀 있다.)
- **`S-###` 출처 ID를 스스로 붙이지 마라.** URL과 서지 정보만 반환한다. 최종 ID 확정과 중복 병합은 리드가 한다.
- **접근 실패를 숨기지 마라.** 403·429·JS 렌더링·PDF 초과·DNS 실패는 URL과 사유를 함께 그대로 보고한다. 조용히 빼면 리드가 커버리지 구멍을 볼 수 없다.
- **`WebSearch`·`WebFetch`가 deferred면 `ToolSearch`로 그 둘의 스키마만 먼저 로드한다.** 다른 도구는 로드하지 않는다 — 로드해서 쓰면 사후 감사에 그 이름으로 잡힌다.
- **반환은 청크 본문과 레지스트리 행만.** 산문 요약·"조사했습니다"류 보고문·받은 템플릿 되풀이를 쓰지 않는다. 판정 기준은 「리드가 재작성 없이 그대로 병합할 수 있는가」다.
- **임시·중간 파일이 필요해 보이면 그 자체가 신호다.** 이 워커는 쓰기를 하지 않는다. 시스템 임시 폴더에는 더더욱 쓰지 않는다.

`skills/리서치/SKILL.md` 4단계가 지시하는 개념KB 청크 템플릿(메타주석 + G8 3필드 포함)과

반환한다. 템플릿·지시문 자체를 되풀이하지 않는다.

### 5-3. 판정

> **`--expect-model`은 모델 축만 고친다. 도구 축의 오탐은 그대로 남는다.** 혼합 세션에서 이 감사는 **연구 워커의 규율을 증명하지 못한다.**

**그러므로 이 과정의 /리서치는 다음 세션 구조로 실행해야 한다:**

1. **/리서치 전용 세션을 새로 연다.** 그 세션에서는 `ac3-research-worker`(또는 승인된 워커) **외의 서브에이전트를 띄우지 않는다.** 분석·집필·검토 워커는 다른 세션에서 돌린다.
2. 감사는 항상 `--projects-dir`를 **명시**한다(C-2가 적용되기 전에는 필수, 적용 후에도 습관으로 유지):
   ```powershell
   python scripts/analyze_agent_usage.py --tool-audit `
     --projects-dir "$env:USERPROFILE\.claude\projects\C--Users-miso-Desktop-Project-template" `
     --session <리서치 전용 세션 ID> --expect-model claude-opus-5
   ```
3. **`대상 로그 : 직접 Agent N개`의 N을 보고서에 옮겨 적고, 실제 `Agent` 호출 횟수와 대조한다.** N=0이면 PASS가 아니라 **미판정**이다.
4. 전용 세션이 불가능하면 **C-4(agentType 필터)를 G00에서 함께 승인**해야 한다. 그 전에는 혼합 세션 감사 결과를 「연구 워커 규율 통과」의 증거로 쓰지 않는다.
5. `/리서치` 이외의 Task(집필·검토·분석)에는 **이 감사를 적용하지 않는다.** 허용목록이 연구 워커용이라 구조적으로 맞지 않는다. 그 Task들의 모델 확인은 **meta.json + jsonl의 `model`·`effort` 직접 대조**로 한다(§3-5의 절차).

### 6-2. 갈래 ㉠ — 중첩 가능한 경우 (Opus 리드가 워커를 직접 호출)

- 구조: Fable → `ac3-research-lead`(Opus, depth 1, `Skill`·`Agent` 보유) → `/리서치` 호출 → `ac3-research-worker`(Opus, depth 2) ×N.
- **스킬 정본 정합**: 리드가 `skills/리서치/SKILL.md`의 8단계·§0 게이트를 직접 수행하고 기본 5파일을 **단독으로** 쓴다 → `:226`·`:230` 「단일 라이터」 완전 충족. 계획서 §5 「리서치 리드는 Fable이 아니라 Opus 5」도 충족.
- **감사 경로 위험 ★**: `discover_worker_logs`는 `<세션>/subagents/agent-*.jsonl`과 `workflows/*/agent-*.jsonl`만 본다. **depth 2 로그가 그 두 경로 밖(예: 리드 에이전트 폴더 하위)에 쌓이면 감사는 워커를 한 명도 보지 못하고 exit 0을 낸다** — C-3을 적용하지 않으면 그것이 **거짓 PASS**로 보고된다. 계획서 §12가 지목한 「감사 0워커 거짓 PASS」의 정확한 발생 경로다.
- **T04/G01 필수 실측**: 중첩 스모크 1회 → depth 2 로그의 실제 절대 경로를 기록 → 그 경로가 감사 glob에 잡히는지 확인. 안 잡히면 **C-4 확장(재귀 glob) 또는 갈래 ㉡ 전환**.

### 6-3. 갈래 ㉡ — 중첩 불가한 경우 (Fable이 워커를 대행 호출)

- 구조: Opus 리드가 청크 계약(프롬프트 전문)을 반환 → **Fable이 그대로 `Agent(subagent_type:"ac3-research-worker", …)`로 호출** → 반환물을 리드에게 전달 → 리드가 병합·5파일 작성.
- **스킬 정본 정합**: 「단일 라이터」는 유지된다(쓰는 주체는 여전히 리드 하나). 계획서 §5의 「Fable은 검색하거나 결과를 집필하지 않는다」도 지켜진다 — 전달만 한다.
- **감사 경로**: 워커가 **메인 세션 직속(depth 1)** 이 되므로 로그가 `<세션>/subagents/agent-*.jsonl`에 쌓인다 → **현재 감사기가 그대로 본다.** ㉠보다 감사 안전성이 높다.
- **대가 ★**: 워커 반환물 전량이 **Fable의 컨텍스트를 통과한다.** 2주차 실측 참고치는 워커 반환 17건 155,962자(`skills/리서치/SKILL.md:236`). AGENTS.md 「컨텍스트 예산」·하네스 §「메인 창이 뚱뚱해지면 이득이 사라진다」와 정면으로 부딪힌다. 완화책: 리드를 **`run_in_background: false`로 순차 실행**하고 Fable은 반환물을 요약하지 않고 **원문 그대로** 넘긴다(요약하면 §5의 「Fable은 집필하지 않는다」 위반이자 압축 왜곡).
- 이 갈래에서는 `ac3-research-lead.md`가 **필요 없다** — 리드는 여전히 Opus 서브에이전트여야 하지만 `Agent`·`Skill` 도구가 필요 없다면 `ac3-writer`류 정의로 충분하다. G00에서 확정.

### 6-4. deep-research 폴백의 가용 판정

- `skills/리서치/SKILL.md:212~215`는 4단계에서 **deep-research 스킬의 가용성을 먼저 확인**하라고 한다(있으면 위임 / 없으면 내장 팬아웃 폴백).
- **이 T02 워커 컨텍스트의 스킬 목록에 `deep-research`는 없다**(관측). 메인 Fable 세션의 목록은 이 Task에서 확인할 수 없었다 → **미확인**.
- **판정(계획서 §5 규칙 적용)**: deep-research는 **가용으로 간주하지 않는다.** 이유는 두 가지다 — ① 이 컨텍스트에서 관측되지 않았고, ② 설령 있어도 **내부 실행 모델을 확인할 수 없어** 「모든 하위 에이전트 Opus 5」를 증명할 방법이 없다. 계획서 §5는 정확히 이 경우를 「가용으로 간주하지 않는다」고 규정한다.
- **따라서 이 과정의 4단계 실행 경로는 `Agent(ac3-research-worker)` 팬아웃 하나로 고정한다.** 어댑터 `.claude/skills/리서치/SKILL.md:22`가 말하는 「있을 때/없을 때 폴백」 중 **「없을 때」 분기**로 진행하되, Claude Code에서는 정본의 내장 웹검색 폴백 대신 어댑터 「워커 실행 통제」의 워커 팬아웃을 쓴다(현행 어댑터 설계 그대로).

## 7. 권고안 + G00 승인 요청 항목

### 7-1. 권고안 (1개)

**「B(과정 전용 정의 4~5종 신설) + C-1(리서치 어댑터 문서 예외·정정·내장 타입 금지) + C-2/C-3(감사기 결함 2건 · C-3은 (d) 종료코드 4안) + 전용 세션 운영 + 내장 타입 사용 규율」**, effort 폴백은 **B′(Workflow)**.

이유:
1. **effort 정책은 `Agent` 도구 인자로 구현할 수 없다**(A는 0% · §2-4). 실을 수 있는 경로는 **B(정의 frontmatter `effort:`)** 와 **B′(Workflow `agent({effort})`)** 둘이며, **도구 화이트리스트·`maxTurns`는 B에만 있으므로** `ac3-*` 정의는 어느 쪽이든 필요하다. B를 먼저 세우고 U1이 깨지면 B′로 간다(§3-9).
2. **다른 과정의 기본 Sonnet 경로가 한 글자도 안 바뀐다**(C-5 기각).
3. **복구가 «파일 삭제»로 끝난다**(기존 파일 무수정).
4. C-1은 A·B 어느 쪽을 택하든 필요한 **최소 문서 정합**이며, 「승인 없는 호출부 재지정」을 오히려 더 강하게 금지한다.
5. C-2/C-3이 없으면 **G01의 「모델 실효값 감사 통과」 증거가 성립하지 않는다** — 지금 정본 명령은 0건을 보고 통과를 찍는다(§5-2① · 15:27 재확인).
6. **내장 타입 경로는 정의 파일로 막을 수 없다**(C26~C28). 예방이 불가능하므로 «규율 + 매 세션 `--expect-model` 감사»가 유일한 방어선이고, 그 감사가 실제로 검출한다는 것은 §5-2③에서 실증됐다.
