## 2. 렌더 증거 격리안

전제(모두 계획서가 잠근 것): ① 기존 `sessions/_verify/{1,2,3}주차` 5파일은 **불변** ② 덮었다 복원하는 우회 금지 ③ kit·공유 스킬·공유 검사기는 승인 없이 수정 금지 ④ 새 과정 증거는 새 namespace ⑤ 수신기와 러너가 **같은 증거**를 읽어야 한다.

### 2.0 왜 「과목이면 무조건 신경로」가 틀리는가 (설계 함정 3종)

**함정 1 — 과목 기반 무조건 라우팅.** 가장 자연스러운 규칙(`resolve_course()`가 과목을 찾으면 `courses/<과목>/sessions/_verify/N주차`)은 **바이브코딩을 깨뜨린다.** 바이브코딩의 세션도 `courses/바이브코딩/sessions/`에 있으므로 같은 규칙이 적용되고, 러너는 존재하지 않는 `courses/바이브코딩/sessions/_verify/1주차`를 보고 **증거 없음 FAIL**을 낸다. 기존 증거를 옮기면 「불변」이 깨지고, 복사하면 같은 증거가 두 곳에 생겨 어느 쪽이 정본인지 사라진다.

**함정 2 — 존재 기반 폴백.** 「신경로가 있으면 신경로, 없으면 구경로」도 틀린다. 구경로 `sessions/_verify/1주차`는 **모든 과목에 대해 존재**하므로 새 과정도 그리로 떨어져 충돌이 그대로 남는다.

**함정 3 — «선언하지 않았다»를 위험 신호로 쓰기.** *(v2 신설 · R-T03 C1이 v1에서 실제로 잡아낸 함정)* 「마커를 선언하지 않은 채 과목을 지정했으면 중단」은 언뜻 안전해 보이지만, **마커를 선언한 과목이 지금 저장소에 0개**다(`courses/*/sessions/_verify` 실측 0). 게다가 `MEMORY.md:320`은 「스크립트를 실행할 때 과목을 밝혀라(`CREATE_SLIDES_COURSE=<과목>`)」를 표준으로 못 박았다. 두 사실을 겹치면 그 조건은 **모든 과목의 모든 실행**에 걸린다 — `CREATE_SLIDES_COURSE=바이브코딩 python scripts/receive_audit.py 2주차`가 exit 2가 되어 기존 과목이 재측정을 못 한다. 안내대로 바이브코딩에 마커를 만들면 이번엔 러너가 **빈 namespace**를 읽어 함정 1(증거 없음 FAIL)로 굴러떨어진다.
> 교훈: **선언의 부재는 위험이 아니라 무정보다.** 무정보를 위험으로 취급하면 게이트가 아니라 정지 버튼이 된다.

갈라야 하는 축은 두 개이고, **서로 다른 질문에 서로 다른 축을 써야 한다**:

| 질문 | 쓰는 축 | 이유 |
|---|---|---|
| **어디에 쓸 것인가**(라우팅) | «이 과목이 `courses/<과목>/sessions/_verify/`를 만들어 두었는가» | 마커 없는 과목은 종전 경로 그대로 → 기존 과목 동작 불변 |
| **써도 되는가**(파괴 방지) | «덮어쓸 파일이 **누구의 덱**을 잰 것인가»(§1.5의 `url`) | 선언을 요구하지 않으므로 선언한 적 없는 과목이 멈추지 않는다 |

v1은 두 질문에 **같은 축**(마커)을 썼고, 그래서 기존 과목이 멈췄다. ⓐ(v2)는 축을 분리한다.

### ⓐ (권고) 라우팅은 마커로, 파괴 방지는 **증거 소유 대조**로

**규칙 1(라우팅)**: `courses/<과목>/sessions/_verify/` 디렉터리가 **존재하면** 그 과목의 증거 루트는 거기다. 없으면 구경로 `sessions/_verify/`다. 마커는 새 과목이 자기 폴더 안에 만드는 것이므로 **다른 과목의 경로는 한 글자도 바뀌지 않는다.**
**규칙 2(파괴 방지)**: 파괴적 쓰기(`receive_audit`) 직전과 증거 읽기(`run_deck_checks`) 직전에, **그 자리에 이미 있는 `deck-audit.json`의 `url`이 가리키는 과목**과 지금 실행 중인 과목을 대조한다. 다르면 쓰지도 판정하지도 않는다. 소유를 새로 선언시키지 않으므로 **선언 여부와 무관하게 기존 과목은 종전대로 동작한다.**

### ⓑ 환경변수로 증거 루트 지정 — `CREATE_SLIDES_VERIFY_ROOT`

두 스크립트가 `os.environ.get("CREATE_SLIDES_VERIFY_ROOT", "sessions/_verify")`를 읽게 한다.

- **장점**: 해석기 의미 변경 0. diff가 가장 작다(2파일 2줄).
- **치명적 단점**: 격리가 **호출자의 기억**에 걸린다. `CREATE_SLIDES_COURSE`는 C인데 `CREATE_SLIDES_VERIFY_ROOT`를 빠뜨리면 그 즉시 남의 증거를 덮어쓰고, **아무도 그 사실을 모른다**(미탐). 계획서 §4.1이 지적한 「환경변수만 지정해서는 출력 격리 미해결」을 **환경변수를 하나 더 얹어** 반복하는 구조다. 두 변수의 정합을 검사하는 주체도 없다.
- 채택하려면 「두 변수가 모두 있거나 모두 없어야 한다」는 fail-closed 가드가 필요한데, 그러면 diff 크기는 ⓐ와 비슷해지면서 안전성은 낮다.

- **장점**: 공유 파일 수정 **0**. G00이 공유 수정을 거절해도 진행 가능. 다른 과목 영향 0.

- ⚠️ **결정적 단점(v2 추가 · R-T03 N3)**: **공유 `receive_audit.py`의 파괴적 덮어쓰기가 손대지 않은 채 그대로 열려 있다.** 래퍼는 «규율을 지킨 호출»만 보호할 뿐이고, 누군가(다음 세션·다른 담당·손이 미끄러진 한 번) 절차 정본에 적힌 원본 명령 `python scripts/receive_audit.py 1주차`를 그대로 치면 바이브코딩 동결 증거가 **바이트 그대로 소실**된다. 즉 ⓒ는 **C 과정이 B03에 걸리지 않게 할 뿐, B03의 근본 위험(공유 수신기의 무조건 덮어쓰기)을 해소하지 않는다.** ⓒ를 채택한다면 이 사실을 G00 승인 기록과 검토 보고에 그대로 남기고, 최소한 A9(동결 해시 pre-commit)와 **A10(발표본 사이드카 fail-closed)** 은 함께 승인받아야 한다. **A10은 특히 래퍼로 대체할 수 없다** — 발표본 절차 정본(`references/phases/10-발표자모드.md:36~41`)이 `scripts/inject_presenter.py`를 **직접 부르는 명령**이라, 래퍼를 만들어도 사람이 정본을 그대로 복사하는 순간 동결 사이드카가 소실된다(§1.4-4 · §2.4-5).

2. 뷰포트 에뮬레이트: 390×844 → 그다음 768×1024. 각 폭에서 **전 슬라이드 순회**.
3. 각 슬라이드에서 실행(읽기 전용):

```js
(() => {
  const el = document.querySelector('.slide.is-active');
  const k = parseFloat(getComputedStyle(document.documentElement)
              .getPropertyValue('--scale')) || 1;
  const leaves = [...el.querySelectorAll('*')]
    .filter(e => !e.children.length && e.textContent.trim());

                   .sort((a, b) => a - b);
  const r = el.getBoundingClientRect();
  return {

    screenW: screen.width, dpr: devicePixelRatio,
    vv: self.visualViewport
        ? [visualViewport.width, visualViewport.height, visualViewport.scale] : null,
    slideRect: [Math.round(r.width), Math.round(r.height)],
    fontMin: px[0], fontMedian: px[px.length >> 1], n: px.length,
    overflowX: document.scrollingElement.scrollWidth > innerWidth + 1
```

> ⚠️ **환산식은 아직 미확정이다.** `--scale`만으로는 브라우저의 초기 축소(meta viewport `width=1280` → initial-scale ≈ 기기폭/1280)를 포착하지 못한다. 위 스니펫이 `innerWidth`·`screen.width`·`visualViewport.scale`을 **함께** 남기는 이유다. 「물리 CSS px = 선언 폰트 × `--scale` × (기기폭 / `innerWidth`)」라는 가설은 **1회 실측으로 검증한 뒤** 판정식으로 승격한다. 검증 전 수치를 PASS/FAIL 근거로 쓰지 않는다.

### 5.4 「의미·사용성 유지 불가」일 때의 규칙

아래 중 하나라도 해당하면 **PASS로 쓰지 않고 「모바일 미검증」 또는 「모바일 차단」으로 기록**한다(계획서 §12).

- 본문 물리 크기 중앙값이 판정 임계 미만(임계는 5.3 검증 후 **사용자 승인으로 확정** — 지금 숫자를 만들지 않는다).
- `overflowX = true` 이거나 `--scale`이 0/음수(측정 무효).
- `overflow:hidden`으로 잘림을 가린 상태.
- 읽기 모드가 슬라이드의 **정보 순서·대응 관계**를 바꾸는 경우(차트 축·범례 분리, 표 열 붕괴 등).

기록 위치: 각 차시 `조립_보고.md` + `A/최종검증.md`. **「측정하지 않았다」와 「측정했는데 미달이다」를 다른 문장으로 적는다.**

### 5.5 브라우저 귀속 제약이 해소되지 않을 때

계획서 §5는 「증거를 넘길 수 없으면 T03에서 BLOCKED」라고 규정했다. **현재 판정: BLOCKED 아님.** 위 5.3은 ① Opus가 명령·판정 기준을 문자열로 지정하고 ② Fable이 실행해 ③ **JSON 원문**을 그대로 반환하는 형태라, 시각 분석·판정은 Opus가 수행하고 Fable은 전달만 한다.

### 6.2 B03 해제 증거의 정의

**아래 5가지를 모두 충족해야 해제다.** *(v2: 4 → 5. 1에 기계 강제를 붙이고 4에 음성시험 3종을 추가했다. **v3: 조건 수는 5 그대로이고, 1에 「A9는 사후 탐지」 단서를, 4에 A10의 양성 2·음성 2를 더했다.**)*

1. **기존 증거 불변** — 다음 5파일의 SHA-256이 작업 전후 동일(측정 2026-09-08 · 앞 16자 · attempt-03에서 재측정해 값·크기 전부 일치 — §7.1 실행 18). **v1은 여기까지가 전부였고 그것은 사람이 손으로 대조하는 절차였다**(R-T03 N4) — v2는 **A9가 pre-commit에서 같은 대조를 기계로 수행**하는 것을 해제 조건에 포함한다. 즉 「작업 전후 같았다」로 끝나지 않고 **「앞으로도 달라지면 커밋이 막힌다」**까지가 조건이다.
   - ⚠️ **A9는 «사후 탐지»이지 «파괴 방지»가 아니다**(v3 신설 · R-T03 attempt-02 C-A). A9가 발화하는 시점은 **다음 커밋**이고, 그때 파일은 **이미 덮여 있다.** 되돌릴 근거는 git뿐이며 「덮었다가 복원」은 계획서가 금지한 우회다. 아래 5파일 중 **사이드카 2개**(1주차 7,814B · 2주차 11,173B)에 대해 **쓰기 시점에 막는 장치는 A10뿐**이고, `deck-audit.json` 3개에 대해서는 A3(수신기 exit 2)·A2(러너 FAIL)다. 따라서 조건 1은 **A9 단독으로는 충족되지 않는다** — A3·A10과 함께여야 「불변」이 사전 보장된다.

2. **새 namespace** — C의 증거가 `courses/AI_코딩_에이전트_입문_3차시/sessions/_verify/N주차/` 아래에만 생성되고, `sessions/_verify/`에는 **새 파일이 0개** 생긴다(`git status --short`로 확인).
3. **수신기와 러너가 같은 증거를 읽는 재현** — `receive_audit.py`의 `[저장] <경로>` 줄과 `run_deck_checks.py`의 `=== 렌더 증거 경로 ===` 줄이 **같은 상대경로 문자열**이고, 러너가 그 파일로 장수·신선도 판정까지 간다(exit 0 또는 실제 결함 FAIL — 「증거 없음」이 아니다). 러너 출력의 소유 표기가 **「(과목 전용 namespace)」이고 「소유 유도 불가」가 아니다.**
4. **양성 4종 + 음성 10종 통과** *(v3: 음성 8 → 10 · 양성 2 → 4 · A10의 시험 4개가 늘었다)*(§2 ⓐ 검증 — 특히 **음성 6(러너 오귀속)** · **음성 7(과목 미지정 exit 0)** · **음성 8(동결 훼손 차단)** · **음성 9(발표본 사이드카 덮어쓰기 차단)**) + **12모듈 회귀 exit 0** + 각 시험의 **판정/미판정 건수 기록**. 「대상 0건」은 통과가 아니라 미판정으로 센다.
   - ⚠️ 음성 6은 **장수·신선도가 통과하도록 조작한 상태**에서 돌려야 한다. 그렇게 하지 않으면 「우연히 다른 이유로 FAIL」이 통과로 기록되고 C3가 증명되지 않는다.
   - ⚠️ 음성 9는 **`--force`를 붙인 재시도까지** 확인해야 한다. 「막혔으니 `--force`」가 이 저장소에서 실제로 일어나는 우회이며, 그것을 확인하지 않은 통과는 C-A를 증명하지 않는다.
   - ⚠️ **음성 10은 저장소의 실제 두 주차에서는 관측되지 않는다**(`--output`이 먼저 막는다). 그러므로 이 한 줄은 **「관측 0건 = 미판정」**으로 기록하고 통과 계수에 넣지 않는다 — 픽스처로 재현하면 판정으로 승격한다.
5. **기존 과목 동작 불변의 실측 재현**(v2 신설 · T04 성공 기준 「다른 과정 기본 동작·레거시 폴백 유지」의 증거) — §2 재현 시나리오 표의 **1·2·6·8·9번**을 실제로 돌려 기대 경로·기대 종료코드가 일치함을 기록한다. 특히 6번은 `MEMORY.md:321`의 기준선(러너 1·2·3주차 **전부 exit 0** · WARN 래칫 구조 8/2/1 · 품질 7/8/5 · 렌더 83/198/9 **전부 불변**)과 대조한다. **바뀐 것이 있으면 해제하지 않는다.**
   - 시나리오 3(likelionSKU)은 «불변»이 아니라 «의도된 변경»이므로, 해제 기록에 **변경으로 분류해 적는다** — 불변 항목에 섞어 세지 않는다.
