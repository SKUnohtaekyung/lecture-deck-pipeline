## 4. 보존·수정 규칙 (「꼭 필요한 것만」의 정의)

유지 슬라이드는 원본 HTML을 **그대로 복사**한다(구조·CSS 클래스·SVG 불변). 허용되는 수정은 다음 6종뿐이며 매트릭스 `변경이유`에 유형 코드를 적는다:
- **M1 표기**: 「N주차」→「N차시」, 과정명·날짜·회차 문구.
- **M2 도구**: 기존 덱의 도구(Codex 등) 고유 명칭·메뉴 문구 → **Google Antigravity**. UI 캡처가 도구 특정이면 캡처를 빼고 «강사 시연 화면» 자리표시(텍스트)로 바꾼다. Antigravity의 실제 UI·메뉴 이름은 **원문 2파일에 있는 것만** 쓰고, 없으면 일반 표현으로 쓰고 `결정요청`에 «미확인 · 강사 시연» 등재(웹 리서치 금지).
- **M3 제외 주제 제거**: Git/GitHub·Netlify 배포·백엔드·DB·API·MCP 실연동 슬라이드는 제외 또는 «소개 1장»으로 축약(원본 ID와 사유 기록).
- **M4 상호참조**: 다른 주차·다음 주차 언급을 새 차시 구조로.
- **M5 통합**: 같은 메시지의 슬라이드 여러 장 → 1장(모든 원본 ID의 메시지·유보가 살아 있는지 확인).
- **M6 신규**: 새 커리큘럼에만 있는 내용(타자 게임 · 뉴스 Agent · CSV/대시보드 전부 · 문서/발표 확장·배포 소개) — kit 레이아웃·차트 element로 새로 쓴다. 원문 2파일과 CSV 분석 결과만 근거로.
- 학생 덱에 hint-reveal 없음 · 강사 멘트는 발표자노트로 · 브랜드 VIBECODING · 테마 default · CSS 상대경로는 `../../../../kit/…`(4단계) · 그라데이션 금지 · 차트에 축·단위·범례.

## 5. 매핑 산출물 스키마 (`보존매트릭스_N차시.csv` · UTF-8)

`원본ID,원본파일,원본번호,제목,핵심메시지,교육적역할,시각유형,새처리상태,새차시,새part,새순서,변경유형,변경내용,보존유보,예상분,판정근거`
- `새처리상태` ∈ 본편 / 실습안내 / 발표자노트 / 부록 / 수강생참고 / 통합 / 수정 / 제외. `변경유형` ∈ M1~M6 / 없음. `예상분`은 본편 슬라이드의 강의 시간(분, 소수 허용).
- 원본 슬라이드 **전부**가 한 행씩 있어야 한다(추적률 100%). 제외에도 사유. 합계는 매트릭스 밖 `매핑_N차시.md`의 시간표에서만.

`매핑_N차시.md`: ① 원본 PART별 요약(장수·주제) ② 새 차시 구조안(PART 목록 · part별 슬라이드 순서 · 앞 50/뒤 50 배치 · 분 단위 시간표 = 개념·시연·따라하기·수정·확인·복구 여유 포함, 합 100 이내) ③ 수정 목록(M1~M5 · 원본 ID · 정확한 문구 전/후) ④ 신규 슬라이드 목록(M6 · 1줄 사양 · 정보 모양 · kit 레이아웃 후보) ⑤ 제외 목록과 사유 ⑥ 발표자노트 대응(원본 노트 재사용/신규) ⑦ 결정요청(미확인 사실·판단 보류) ⑧ 계수: 원본 총장수 · 본편/노트/부록/제외 건수 · 추적률.

## 6. 절차 (압축 DAG)

A 매핑(차시별 writer 3 · 병렬 · 관리 폴더에만 쓰기) ∥ CSV 분석(writer 1 · `실습예제/CSV/`) → 오케스트레이터 검토·독립 검토 → B 조립(차시별 writer 3 · 각자 `sessions/N주차/`만) → 정적 검증(`verify_deck --parts`·`verify_notes`·`verify_deck_quality --strict`·`check_title_survival`) → C 브라우저 실측(오케스트레이터 · `receive_audit` 새 namespace) → `run_deck_checks` → 독립 적대적 검토 → 수정 → 최종.
