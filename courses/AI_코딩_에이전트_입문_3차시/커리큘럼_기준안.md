## 3차시 · 데이터에서 다양한 결과물까지

### 개념

> 이 차시의 주인공은 데이터 분석이 아니라 **하나의 데이터를 여러 형식의 결과물로 바꾸는 경험**이다. 데이터 확인·승인·대조는 결과물을 믿을 수 있게 하는 최소 절차로 둔다.

- Coding Agent가 다루는 파일: HTML · CSV · Markdown · DOCX · PPTX · JSON
- 같은 근거, 다른 독자: 대시보드는 훑어보는 사람 · 발표자료는 듣는 사람 · 보고서는 읽는 사람
- 확인 → 계획 → 승인 → 실행
- 원본과 파생 결과물의 분리
- 원본에서 확인할 수 있는 내용만 쓰기
- 도구 설치·실행 요청과 권한 확인
- 하나의 근거를 여러 결과물에 재사용

### 실습

1. `mock_ecommerce_orders.csv` 구조·품질 확인(2,424행 · 20개 컬럼 · 중복·결측·이상값 · 수정 금지)
2. 작업 계획 승인과 원본 CSV 보존(사본 `분석대상.csv` · 원본 행 수 그대로 확인)
3. 단일 HTML 데이터 대시보드 제작
4. 자연어로 대시보드를 한 가지씩 수정
5. 대시보드 숫자로 분석 Markdown 작성
6. 분석 Markdown으로 PPTX 발표자료 생성
7. 발표자료에 발표자 노트 추가
8. 같은 근거로 DOCX 분석 보고서 생성
9. 네 결과물의 숫자 일치 확인과 공유 전 점검
10. 정적 HTML 배포 방식 소개(시연)

### 필수 대시보드 요소

- 원본 행과 분석 대상 행
- 핵심 주문·매출 지표
- 월별 매출
- 상품군별 매출과 마진
- 배송 기간과 평점
- 핵심 요약
- 데이터 정제 기준과 확인이 필요한 데이터
- 분석의 한계

### 필수 발표자료 요소

- 문제와 데이터
- 핵심 지표
- 대시보드 핵심 차트
- 발견한 특징
- 확인이 필요한 부분과 데이터의 한계
- 슬라이드별 발표자 노트

### 필수 보고서 요소

- 핵심 요약
- 주요 지표
- 발견한 특징
- 개선이 필요한 부분
- 데이터의 한계

### 결과물

- 원본 CSV(수정 없음)
- 데이터 품질 확인
- HTML 데이터 대시보드
- 분석 Markdown
- PPTX 발표자료와 발표자 노트
- DOCX 분석 보고서
- 네 결과물의 숫자 일치 확인
