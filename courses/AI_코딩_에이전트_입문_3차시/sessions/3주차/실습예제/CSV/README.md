# 3차시 실습 예제 — CSV 분석과 대시보드

원본 CSV 하나에서 **품질 진단 → 계획 승인 → 계산 → 대시보드 → 분석 문서**까지 가는 전체 경로의 완성 예시다.
강사 기준값이자 학생 결과물의 참조본으로 쓴다.

> **관통 메시지** — AI가 작성하고, 사람이 검토하고, 사람이 결정한다.
> 이 폴더는 그 문장을 파일 구조로 보여 준다: 계획서에 **승인란**이 있고, 정할 수 없는 것은 **보류**로 남아 있으며, 모든 숫자에 **되짚을 포인터**가 붙어 있다.

## 1. 파일 역할

| 파일 | 역할 | 누가 읽나 |
|---|---|---|
| `분석계획.md` | **사람이 승인하는 계획서.** 한 행의 단위·중복·결측·이상값·매출 포함 범위·분모·반올림·조정표·답할 수 없는 질문. **승인란과 가정 6건**이 있다 | 강사·학생 |
| `정제기준.md` | 20열 사전 + 품질 진단 결과 + 판정 단계 상세 + 임계값 근거 | 강사 |

| `dashboard.html` | **단일 HTML 대시보드.** 필수 요소 8 + 필터 3 + 자기검증 배너 | 학생 |
| `복구/dashboard.html` | **최소 복구본.** 핵심 지표 4 + 표 1 | 학생(막혔을 때) |
| `분석결과.md` | 근거·해석·한계가 있는 분석 문서 | 강사·학생 |
| `분석결과_요약.md` | 실습⑤ 결과와 **칸을 비교**하는 한 쪽 요약(핵심 요약·주요 지표·발견한 특징·개선이 필요한 부분·데이터의 한계) | 학생 |
| `만들기_발표자료.py` | `지표기준값.json` → `발표자료.pptx`. `--recovery`면 `복구/발표자료.pptx`를 만든다. python-pptx 필요 | 강사 |
| `발표자료.pptx` | 실습⑥⑦ **강사용 완성본.** 16:9 · 문제와 데이터 → 핵심 지표 → 핵심 차트(월별 매출 · 상품군별 매출과 마진) → 발견한 특징 → 확인이 필요한 부분과 한계 · 장마다 발표자 노트 | 강사·학생 |
| `복구/발표자료.pptx` | **복구본.** 문제와 데이터 · 핵심 지표 · 한계 · 발표자 노트 포함 | 학생(막혔을 때) |
| `만들기_보고서.py` | `지표기준값.json` → `분석보고서.docx`(차트는 Pillow로 그린다). `--recovery`면 `복구/분석보고서.docx`를 만든다. python-docx·Pillow 필요 | 강사 |
| `분석보고서.docx` | 실습⑧ **강사용 완성본.** 제목 + 다섯 칸 + 표(상품군별 매출·마진율) + 차트(월별 총매출) | 강사·학생 |
| `복구/분석보고서.docx` | **복구본.** 한 쪽 · 다섯 칸 | 학생(막혔을 때) |
| `결과물_대조.py` | 실습⑨ 강사 일치표. 발표자료·보고서·요약·복구본·`dashboard.html`의 숫자를 `지표기준값.json`과 대조하고 PPTX 넘침·겹침·글자 크기를 추정 검사한다. 판정·미판정 건수를 출력하고 위반이나 미판정이 있으면 exit 1 | 강사 |
| `README.md` | 이 파일 | 강사 |

**원본은 이 폴더에 없다.** `../../../../자료/데이터/mock_ecommerce_orders.csv`에 있고 **읽기만 한다.**
원본과 파생을 분리하는 것이 3차시의 핵심 개념 중 하나다(`원본과 파생 결과물의 분리`).

## 2. 실행 순서

```
① 원본 확인      mock_ecommerce_orders.csv  (읽기 전용 · 2,424행 20열)
        ↓
② 품질 진단      정제기준.md      ← 중복·결측·이상값·보류
        ↓
③ 계획 작성      분석계획.md      ← ★ 사람이 승인 (가정 6건)
        ↓
④ 규칙 확정      지표정의.json    ← 계산 전에 못 박는다
        ↓
⑤ 계산          python 계산.py   → 지표기준값.json · 분석대상.csv
        ↓                         → dashboard.html·복구/dashboard.html에 데이터 주입
        ↓
⑥ 대시보드       dashboard.html   ← 브라우저에서 열어 자기검증 배너 확인
        ↓
⑦ 분석 문서      분석결과.md      ← 값마다 포인터
```

**③이 ⑤보다 먼저다.** 계산 결과를 보고 규칙을 고치면 «결과에 맞춰 기준을 깎는 것»이 된다.

### 실행 명령

```bash
cd courses/AI_코딩_에이전트_입문_3차시/sessions/3주차/실습예제/CSV
python 계산.py            # 계산 + 산출물 갱신 + 대시보드 주입 + 자기검증
python 계산.py --check    # 파일을 쓰지 않고 기존 산출물과 비교만
python 만들기_발표자료.py              # 발표자료.pptx 생성 (python-pptx 필요)
python 만들기_발표자료.py --recovery   # 복구/발표자료.pptx 생성
python 만들기_보고서.py                # 분석보고서.docx 생성 (python-docx·Pillow 필요)
python 만들기_보고서.py --recovery     # 복구/분석보고서.docx 생성
python 결과물_대조.py                  # 결과물 숫자 = 지표기준값.json 대조 + PPTX 넘침 추정 (0 = 통과 / 1 = 위반·미판정)
```

- 파이썬 3.7+ · `계산.py`·`결과물_대조.py`의 계산 부분은 **외부 패키지 불필요**(표준 라이브러리만). PPTX·DOCX 생성과 그 파일 읽기는 python-pptx·python-docx(보고서 차트는 Pillow)가 필요하다.
- 종료코드 **0 = 통과 / 1 = 검증 실패**. 실패 사유는 `FAIL`로 시작하는 줄에 나온다.
- `계산.py`는 **멱등**이다. 두 번 돌리면 두 번째는 `dashboard=unchanged`가 나온다.
- 대시보드는 **파일을 더블클릭**해 연다. 서버가 필요 없고 **외부 네트워크 요청이 0건**이다.

### 3-2. 아직 실행하지 않은 검증

| 검증 | 왜 |
|---|---|
| **브라우저 실측** — 대시보드를 실제로 열어 자기검증 배너·차트·필터 확인 | 이 작업은 정적 검증까지가 범위다. 화면 확인은 별도로 수행해야 한다 |

> ⚠️ **종료코드가 통과했다고 화면이 멀쩡한 것은 아니다.** 대시보드는 브라우저에서 한 번 열어 봐야 한다. 열면 상단에 «자기검증 통과 — 화면 값 N항이 지표기준값.json과 일치» 배너가 떠야 한다.

### 3-3. 직접 검증하는 법

**대시보드 숫자를 못 믿겠다면** — 그게 정상이다. 3차시가 가르치는 태도다.

1. `dashboard.html`을 브라우저로 연다 → 상단 배너가 **통과**인지 본다.
   배너는 화면에 그린 숫자를 인라인 데이터에서 **다시 계산**해 `지표기준값.json`과 대조한 결과다.
2. `python 계산.py --check`가 **exit 0**인지 본다 → `지표기준값.json`이 코드 재실행 결과와 같다는 뜻.
3. 스프레드시트로 교차 검증한다: `분석대상.csv`를 열어 `net_revenue_krw` 열을 전부 더하면 **205,274,700**이 나와야 한다(`REV-01`).
4. 원본이 안 바뀌었는지 본다:
   ```bash
   python -c "import hashlib;print(hashlib.sha256(open(r'../../../../자료/데이터/mock_ecommerce_orders.csv','rb').read()).hexdigest())"
   # 3502d6b4bcc78d28b5797566a6dbe8da5fc85d00c066bb0a3fef709e537d5192
   ```

## 5. 수업에서 짚을 지점

| 지점 | 왜 중요한가 |
|---|---|
| **행 수 ≠ 주문 수** | 2,424행이지만 고유 주문은 2,400건. 이걸 안 보면 뒤 숫자가 전부 틀린다 |
| **중복에도 두 종류가 있다** | 완전 중복(23건)은 지울 수 있지만 **값이 충돌하는 중복(1건)은 지울 수 없다.** 자동으로 하나를 고르면 근거 없는 값이 조용히 생긴다 |
| **제외 ≠ 불량** | 제외 219건의 83%는 «틀린 데이터»가 아니라 «아직 매출이 아닌» 취소·대기 주문이다 |
| **결측을 채우지 않는다** | 평점 무응답 64건을 0점으로 채우면 평균이 4.44 → 4.31. 없는 불만이 생긴다 |
| **분모를 항상 말한다** | 평균 배송일 3.45일의 분모는 2,203이 아니라 **2,199**다 |
| **제외와 보류를 나눈다** | 배송 45일은 «불가능»이 아니라 «확인 필요». 매출에는 넣고 배송 분모에서만 뺐다 |
| **0건의 뜻** | 「검사했는데 0건」과 「검사하지 않아서 0건」은 다르다. 검사기가 본 행 수를 남긴다(`QUAL-01`) |
| **상관 ≠ 인과** | 배송 6~9일 구간의 평점이 낮지만(`분석결과.md` §7) 원인은 이 데이터로 알 수 없다 |
| **마진 ≠ 이익** | 인건비·마케팅비 열이 없다. 53.2%를 이익률로 읽으면 안 된다 |
| **대시보드는 스스로 증명한다** | 화면 숫자를 기준값과 대조해 배너로 보여 준다 — 「대시보드의 숫자는 원본 데이터와 비교한다」의 구현 |

## 6. 학생이 막혔을 때

`복구/dashboard.html`을 연다. 핵심 지표 4개 + 상품군 표 1개만 있는 최소본이며 **5~7분이면 따라잡는다.**
데이터는 `지표기준값.json` 전문이 인라인으로 들어 있어 `계산.py`를 돌리지 않아도 열린다.
거기서 ① 월별 매출 막대그래프 ② 배송·평점 분포 ③ 필터 순서로 붙여 본편에 근접시킨다.

## 7. 규칙을 바꾸고 싶을 때

1. `지표정의.json`을 고친다 (**정본**).
2. `계산.py`의 해당 부분을 고친다 (집행부 · 임계값 상수는 파일 상단에 모여 있다).
3. `python 계산.py` → exit 0 확인.
4. `분석계획.md`의 조정표·가정과 `정제기준.md`의 판정표를 함께 고친다.
5. `분석결과.md`·이 README의 수치를 갱신한다.

> 정의만 고치고 코드를 안 고치면 **문서와 값이 어긋난다.** 그 어긋남이 이 저장소가 반복해서 겪은 사고다 — 그래서 `계산.py`가 매 실행마다 17항을 스스로 검사하고, 대시보드가 화면 값을 기준값과 대조한다.
