## 3. 품질 진단

### 3-1. 중복

`order_id` 중복 그룹 24개(각 2행 = 24행 초과). 그런데 **성격이 둘로 갈린다** — 이걸 구분하지 않고 «중복 24건 제거»라고 하면 틀린다.

| 종류 | 그룹 | 행 | 판단 키 | 처리 |
|---|---|---|---|---|
| **완전 중복** | 23 | 23행 초과 | `order_id` 같고 **20열 전부 동일** | 첫 행만 채택, 나머지 제외 `D1` — 정보 손실 없음 |
| **부분 중복(값 충돌)** | 1 | 2행 전부 | `order_id` 같은데 `quantity`가 다름 | **양쪽 다 보류** `H1` — 사람 승인 필요 |

- 충돌 건: `ORD00852` (원본 853행 `quantity=0` / 2425행 `quantity=2`, 나머지 19열 동일)
- **왜 «첫 행 채택»으로 넘기지 않았나** — 첫 행을 고르면 `quantity=0`이 채택돼 매출 0원이 되고, 뒤 행을 고르면 2개가 된다. 어느 쪽이 참인지 데이터 안에 근거가 없다. 규칙을 자동 적용해서 **근거 없는 값을 조용히 만들어 내는 것**이 여기서 가장 위험한 일이므로 양쪽 다 뺐다.
- 전체 20열이 같은 «완전 동일 행»은 별도로 세어도 23그룹 23행으로 위와 일치한다(중복 판단 키를 `order_id`로 잡든 전체 열로 잡든 결론이 같음을 교차 확인).

### 3-2. 결측

| 열 | 결측 | 구조적 원인 | 처리 |
|---|---|---|---|
| `delivery_days` | 184 | Cancelled 112 + Pending 72 = **184로 정확히 일치** — 배송이 시작되지 않아 값이 없는 것 | 결측을 채우지 않는다. 해당 행은 어차피 `S1`로 매출 집계에서 빠진다 |
| `rating` | 248 | Cancelled 112 + Pending 72 + **Completed 64** = 248 | Completed 64건은 «고객이 평가하지 않음». **0점으로 세지 않고 분모에서 뺀다** |
| `return_reason` | 2,320 | `returned=No`인 행 수와 **정확히 일치** | 결측이 아니라 «해당 없음». 불일치 0건 |

> 결측을 0이나 평균으로 채우지 않았다. 채우면 «측정하지 않은 것»이 «측정해서 그 값이 나온 것»으로 둔갑한다. 평점 무응답 64건을 0점으로 넣었다면 평균 평점이 4.44에서 4.31로 내려간다 — **없는 불만을 만들어 내는 것**이다.

### 3-3. 이상값

임계값은 계산 결과를 보기 **전에** 정했고, 결과가 마음에 안 든다고 바꾸지 않았다.

| 플래그 | 조건 | 건수 | 근거 | 판정 |
|---|---|---|---|---|
| `A1` | `quantity = 0` | 6 | 수량 0은 주문으로 성립하지 않는다 | **제외** `E1` |
| `A2` | `quantity ≥ 50` | 6 | 실측 분포가 0~4에 몰려 있고 **99만 뚝 떨어져 있다**. 연속 분포의 꼬리가 아니라 입력 오류 표식 | **제외** `E2` |
| `A3` | `unit_price_krw = 999999` | 4 | 같은 상품의 다른 행 단가가 **모두 단일 값**인데 이 4건만 999999 | **제외** `E4` |
| `A6` | `delivery_days < 0` | 4 | 음수 배송일은 물리적으로 불가능 | **제외** `E5` |
| `A7` | `delivery_days ≥ 30` | 4 | 45일. **불가능하지는 않다**(예약·해외배송이면 성립) | **보류** — 제외하지 않음 |
| `A4` | `unit_price_krw ≤ 0` | 0 | 2,424행 전부 검사함 | 해당 없음 |
| `A5` | `cost > unit_price` | 0 | 2,424행 전부 검사함 | 해당 없음 |
| `A8` | 미래 주문일 | 0 | 2,424행 전부 검사함 (최댓값 2025-12-30) | 해당 없음 |
| `A9` | 평점 1~5 밖 | 0 | 값이 있는 2,176행 검사함 (실측 2~5) | 해당 없음 |
| `A10` | `returned`↔`return_reason` 불일치 | 0 | 2,424행 전부 검사함 | 해당 없음 |

> **0건의 뜻을 분명히 한다.** 위 A4·A5·A8·A9·A10의 0은 «검사하지 않았다»가 아니라 «2,424행을 다 보고 한 건도 없었다»는 뜻이다. 검사기별로 실제로 본 행 수를 `QUAL-01`에 남겼고(전부 2,424), **미판정은 0건**이다. 검사 범위를 밝히지 않은 0은 통과가 아니라 미판정이다.

## 4. 판정 단계와 우선순위

단계 순서가 곧 우선순위다. **앞 단계에서 판정된 행은 뒤 단계가 다시 만지지 않는다** — 그래야 합계가 원본 행수와 맞는다.

| 순서 | 단계 | 판정 | 조건 | 배정 행수 |
|---|---|---|---|---|
| 1 | `D1` | 제외 | 완전중복 그룹의 2번째 이후 행 | 23 |
| 1 | `H1` | 보류 | 값이 충돌하는 중복 그룹의 **모든** 행 | 2 |
| 2 | `E1` | 제외 | `quantity = 0` | 5 |
| 2 | `E2` | 제외 | `quantity ≥ 50` | 6 |
| 2 | `E3` | 제외 | `unit_price ≤ 0` | 0 |
| 2 | `E4` | 제외 | `unit_price = 999999` | **0** |
| 2 | `E5` | 제외 | `delivery_days < 0` | 4 |
| 2 | `E6`~`E9` | 제외 | 미래일 · 평점 범위 밖 · 원가>단가 · 반품 불일치 | 0 |
| 3 | `S1` | 제외 | `order_status ≠ Completed` | 181 |
| 4 | `K1` | **채택** | 나머지 | **2,203** |
| | | | **합계** | **2,424** ✔ |

> ⚠️ **`E4` 배정 0건과 `E3` 배정 0건은 뜻이 다르다.**
> - `E3`(단가 0 이하)는 **해당 행이 아예 없다** — 플래그 `A4`도 0건.
> - `E4`(단가 999999)는 **플래그 `A3`로 4건이 잡혔는데** 그 4행이 모두 수량 0(2건)·수량 99(2건)에 **먼저 걸려 `E1`·`E2`로 배정**됐다. 즉 «못 봤다»가 아니라 «앞 단계가 이미 가져갔다»이다.
> - 같은 이유로 `E1` 배정이 6이 아니라 5다 — 수량 0인 6행 중 1행(853행)이 1단계에서 `H1` 보류로 먼저 빠졌다.
> - 이래서 **플래그 계수와 단계 배정 계수를 둘 다** 남긴다. 하나만 보면 «4건 있었는데 0건 처리됐다»로 잘못 읽는다.

`S1` 181행의 내역: 취소·대기는 원본에 184행이지만, 그중 2행은 1단계에서 완전중복으로, 1행은 2단계에서 수량 0으로 이미 빠져 181행이 남았다.
