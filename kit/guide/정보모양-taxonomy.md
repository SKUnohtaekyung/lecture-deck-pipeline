# 정보 모양 분류축 (Information-Shape Taxonomy)

> **이 문서는 모든 카탈로그의 척추다.** 레이아웃·차트·다이어그램은 전부 이 축으로 색인된다.
> 조립할 때 **레이아웃을 고르기 전에** 이 축으로 "이 슬라이드 정보가 무슨 모양이냐"를 먼저 분류한다(원칙 B).
> 핵심 구분: **정보 모양(축) ≠ 표현 형식(표·차트·스샷).** 형식은 힌트일 뿐, 모양이 축이다.
> — 예: "비교"라는 *모양*은 표로도, 대칭 2패널로도, 막대쌍으로도 표현될 수 있다.
> **직교 축 주의:** 이 축(정보 모양 = 콘텐츠 의도)과 **별개로**, 각 레이아웃은 `composition_shape`(관객이 보는 매크로 구도, 8종)를 갖는다 — 의도로 고르되 **구도 반복은 그 축으로 막는다**. 정의: `카탈로그-규격.md` §2b.

## 12 정준 정보 모양

| id | 한국어 | 무엇을 전달하나 | 판단 신호 (이런 문장/구조면) | 표현 힌트 |
|---|---|---|---|---|
| `declaration` | 선언 | 하나의 강한 주장·질문·선언 | "X는 Y다", "정말 Z할까?" — 한 문장이 곧 슬라이드 | 텍스트 중심(full-bleed·centered), 차트 없음 |
| `concept` | 개념 설명 | 하나의 개념 + 보조 시각 하나 | "A란 무엇인가"를 한 문단 + 그림 하나 | 다이어그램/이미지 보조 가능 |
| `comparison` | 비교 | 두(이상) 대안의 정식 비교, 보통 한쪽 추천 | "A vs B, B를 택하라", 항목별 우열 | 표 · 대칭 2패널 · comparison-bars |
| `contrast` | 대비 | 두 주체/입장의 대립(추천 아닌 긴장) | "쓰는 쪽 ↔ 하는 쪽", "전 ↔ 후" | 대칭 2블록 + 가운데 커넥터(≠) |
| `flow` | 흐름·단계 | 순서·절차 1→2→3 | "먼저…다음…마지막", 단계·절차 | flow-h · flow-v · cycle · funnel · timeline |
| `containment` | 구성·포함 | 부분-전체·중첩 | "A는 B의 일부", "B는 이 요소들로 구성" | venn · concentric · tree |
| `mapping` | 매핑 | A↔B 대응·연결 | "이 모델 → 이 지표", "위 항목이 아래를 정한다" | 매핑 카드 · 화살표 다이어그램 · matrix |
| `classification` | 분류·나열 | 동급 항목 여러 개 훑기 | "종류/옵션 나열", 병렬 항목 3개↑ | grid/mosaic 카드 |
| `numeric` | 수치·비율 | 양·비중·추세 | "40% vs 35%", "매년 증가", 숫자 강조 | bar · column · line · pie · donut · progress · big-number |
| `structure` | 구조·관계 | 요소 + 관계(위계·네트워크·매트릭스) | "이 시스템은 이렇게 얽혀 있다" | tree · matrix · network · pyramid |
| `checklist` | 체크리스트·격자 | 점검 항목·격자 | "확인할 것들", "해당되면 체크" | grid + 체크마크 |
| `screen-operation` | 화면 조작 | 실제 UI 화면 단계 | "권한 창에서 [허용] 버튼" | 주석 스크린샷(번호·테두리) |

> **힌트는 강제가 아니다.** "이 형식이 자연스럽다"일 뿐, 최종 표현은 `by-shape.md` 역인덱스 후보 중에서 판단해 고른다.
> **한 슬라이드에 모양이 둘 이상**이면(예: 개념 + 수치) 주된 모양으로 분류하고 보조는 element로 얹는다.

## 정보 모양 추론 절차 (항상 스킬이 판단)

공식 입력(`입력양식/콘텐츠초안템플릿.md`)엔 `시각화 의도`를 사람이 지정하는 칸이 **없다** — 정보 모양 판단은 **언제나 스킬 몫**이다. 각 슬라이드마다 **제목 + 본문의 동사·구조**를 보고 모양을 추론한다:

- "vs / 차이 / 낫다" → `comparison`, 두 주체 대립이면 `contrast`
- "먼저 / 다음 / 단계 / 순서" → `flow`
- "구성 / 포함 / 일부 / 안에" → `containment`
- "% / 증가 / 감소 / 비중 / 배" (숫자 강조) → `numeric`
- 여러 항목 병렬 나열(3개↑) → `classification`(점검이면 `checklist`)
- 관계도 / 얽힘 / 위계 → `structure`, A→B 연결이면 `mapping`
- 화면·버튼·클릭·메뉴 → `screen-operation`
- 위 어디에도 안 걸리는 강한 한 문장 → `declaration`, 한 개념 설명이면 `concept`

추론 결과가 애매하면 **후보를 2개까지** 잡고 `by-shape.md`에서 각 후보 레이아웃을 견줘 고른다.
