## 2. 컬러 (v2 — 3색 순정)
> 옛 코발트 파생 시스템을 전면 개명해 확정한 **v2 팔레트**. 이 문서가 shipped 운영 정본이다(설계 배경·전체 명세: `_dev/설계기록/색시스템-v2-명세.md` — 배포 제외).

| 역할 | 토큰·값 | 용도 |
|---|---|---|
| **구조·주강조** | `--blue #1D4ED8` | 구조·주 강조로 보이는 텍스트·선·박스·카드·차트의 메인 계열. fill 위 글자=`--white` |
| **행동·성공·안전** | `--mint #14B8A6`(fill) / `--mint-deep #0F766E`(텍스트·보더) / `--mint-soft #E9F8F5`(틴트) | 행동·성공·안전 |
| **주의·경고** | `--coral #F97360`(fill) / `--coral-deep #C2452F`(텍스트·보더) / `--coral-soft #FEF0ED`(틴트) | 주의·경고 |
| **오류·위험** | `--red #DC2626` / `--red-soft #FDECEC` | 오류·위험 |
| fill 위 글자 | `--on-mint #083B36` / `--on-coral #5C1C12` | 민트·코랄 fill 위 짙은 글자 |
| 비강조 | `--periwinkle #93A7E8` | 차트의 비강조 데이터 계열만 |
| 잉크·중립 | `--ink #141821` / `--black #000000` / `--surface #F3F5F8` / `--line #E5E8F0` | 본문·중립 표면(코드/터미널 등 비카드)·**내부 구분선 전용**(`--line`으로 박스 외곽 단독 구분 금지) |
| 박스 보더 | `--blue-line #DCE4FF` / `--blue-line-strong #CDDBFF` / `--mint-line #C9EAE4` / `--coral-line #FBD8CF` | 카드/박스 외곽 유색 보더(틴트 fill 동반 또는 흰 fill 단독 구분) |

- **색은 문법이다** — 구조·주 강조의 블루는 `--blue` 하나로 통일한다. `--blue-soft`는 배경 면, `--periwinkle`는 비강조 데이터에만 쓴다. 민트=행동·성공·안전·일반 강조 · 코랄=주의·경고 · 레드=오류.
- ⚠️ **민트·코랄 fill 위 흰 글자 금지** → `--on-mint`/`--on-coral` 짙은 글자 필수(대비).
- ⚠️ **navy 최대한 금지** — `--navy` 토큰 정의는 남기되 `var(--navy)` 사용 0. 어두운 배경/텍스트는 `--ink`.
- ⚠️ **그라데이션 금지**(템플릿 전반, cover 포함) — 단색만.
- **민트 강조**: 텍스트는 `.hl-mint-text`(색)·`.hl-mint-underline`(밑줄)·`.hl-mint-mark`(글자폭 배경) 중 문맥에 맞게 고른다. `.hl-mint-mark`은 **흰 글자**·inline-block·좌우 3px·상 0px/하 1px·각진 모서리이며, 한 줄 전체를 채우지 않는다. 이 컴팩트 텍스트 강조만 민트 fill 위 흰 글자 규칙의 예외다. 강조 도형은 `.shape-mint`를 쓴다.
- 전체 토큰은 `deck.css` §1 및 `kit/guide/토큰-치트시트.md`.

## 2-b. 폼·타이포 토큰 (v2)
- **라운드**: `--r-lg 20px`(큰 카드) · `--r-md 14px`(카드/콜아웃) · `--r-sm 10px`(버튼) · `--r-pill 999px`(배지). **카드 = r-lg + soft shadow.**
- **박스 표면 규칙(2026-07-16, verify 강제)**: 흰 캔버스 위 카드/박스는 ① 의미 틴트 fill(구조=`--blue-soft` 기본 / 행동=`--mint-soft` / 주의=`--coral-soft`) + 같은 계열 보더, 또는 ② 흰 fill + 유색 보더(`--blue-line-strong`/`--mint-line`/`--coral-line`) 중 하나. **흰 fill + `--line` 근백색 보더 단독 조합 금지.** 기본 `.card`=`--blue-soft`+`--blue-line`, 뮤트 `.card.surface`=`--blue-panel`+`--blue-line-strong`, `.work-step`=`--mint-soft`+`--mint-line`. 예외: 코드/터미널 표면·주석 스크린샷 창·`.pd-dot`·표.
- **넘버 행 수직 중앙(2026-07-16)**: `.work-step`·`.agenda-item`은 `align-items:center`(원형 배지 대비 텍스트 중앙, verify 강제). 예외: `.s03-slide .an-item`(커넥터 좌표 전제).
- **섀도우**: `--shadow-sm` / `--shadow-md`(카드) / `--shadow-lg`(큰 카드) / `--shadow-blue`(블루 요소).
- **코드폰트**: `--font-mono` = JetBrains Mono — 인라인/블록 코드·터미널에 적용.
- **eyebrow = 태그**: `.s-eyebrow`는 `--blue-soft` 배경 pill(본문 슬라이드만; 고정 슬라이드는 plain).

## 4. 헤더 (v2.1 — 파트진행)
- 구조는 `.s-head` 유지: **[로고] · [브랜드명] · [라인] · [우측 슬롯]**.
- **본문 슬라이드 헤더** = 로고 · 브랜드 · 라인 · **파트진행**(우측): `PART n/N` + 진행 도트(현재 파트 도트 = 민트). JS가 `.s-part`로 주입, divider 기준 자동 계산.
- **고정 슬라이드**는 파트진행 미주입 — **표지·도입·마무리**는 우측 **팀명 유지**, **아젠다(`.s03-slide`)는 팀명 제거**(로고+브랜드+라인만, 본문=노드-타임라인 `.an-item`×4·번호 블루 fill), **파트전환(`.part-divider`)은 헤더 전체 제거**(풀캔버스 아이소 큐브 히어로 `.dv-hero`). 설계 배경: `_dev/설계기록/색시스템-v2-명세.md` §6b(배포 제외).
- 하단 페이지네이션 `n/전체`는 JS가 `.s-pageno`로 주입(표지·마무리 제외).
- ✅ 상단 로고 확정(2026-07-13): V-마크 인라인 `<svg class="s-logo">`(토큰색·26°). 표지 한글 타이틀 등 텍스트는 슬라이드 계획서(0번)에서 주입.

## 5. 발표 조작 UI
- 하단 리모컨은 Apple Liquid Glass 원칙을 응용한다. `--glass-white`는 낮은 불투명도를 유지하고, `backdrop-filter`의 blur·saturate·brightness와 빛 테두리·inset highlight·깊은 그림자를 함께 사용한다. 단순한 불투명 흰색 패널로 대체하지 않는다.
- 작은 내비게이션과 큰 상세 메뉴는 재질 두께가 달라 보여야 한다. 메뉴는 옅은 쿨그레이 반투명 토큰 `--glass-thick: rgba(232,235,240,.76)`과 더 강한 blur·그림자를 사용해 배경과 분리한다. 완전 투명이나 순백 불투명 패널은 피한다.
- 상세 메뉴는 현재 제목, 한 줄 조작부(홈·페이지 이동·PDF·도움말), 슬라이드 목록만 둔다. 메인 블루는 호버·포커스·현재 목록 항목처럼 상태를 알려야 할 때만 쓴다.
