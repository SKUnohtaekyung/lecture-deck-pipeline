# 카탈로그 규격 (Catalog Spec)

> 레이아웃·차트/다이어그램 카탈로그를 만들고 검증하는 **규칙**. P0에서 동결, 이후 전 Phase가 이걸 따른다.
> 판단 축은 [`정보모양-taxonomy.md`](정보모양-taxonomy.md).

---

## 1. "no default" 헌장 (원칙 A·B·C)

- **A. 동급.** 모든 레이아웃·차트·다이어그램은 **동등한 도구**다. **어떤 레이아웃도 "기본/가장 흔한/주로 쓰는/go-to 레이아웃"으로 서술하지 않는다** — 특히 좌우분할(split)을 기본으로 프레이밍 금지. (주의: '기본'이 *CSS 기본 스타일*을 뜻하거나 *이 헌장 자체*를 가리키는 등 **레이아웃 우위와 무관한 용례는 허용**. 금지 대상은 *레이아웃을 기본/최다로 규정하는 문장*이다.)
- **B. 판단 먼저.** 레이아웃을 고르기 전에 **정보 모양을 분류**하고, `by-shape.md` 역인덱스로 후보를 뽑는다. 즉흥 선택 금지.
- **C. 대안 공급.** 좌우분할이 아닌 구도를 대거 확보(§3 균형표) + 코드 차트/다이어그램 라이브러리로 도망갈 이유를 없앤다.

> 단조 방지는 **금지 조항이 아니라 공급 + 측정**으로 한다. split은 캡으로 희소하게, 역인덱스에서 후순위, 산출 덱은 분포를 측정.

## 2. 8 구도 패밀리 (composition family)

패밀리는 **연구·빌드 단위이자 균형 감사 단위**다. 각 레이아웃은 정확히 한 패밀리에 속한다.

| 패밀리 | 정의 (무엇이 구별하나) | deck.css 기반 |
|---|---|---|
| `full-bleed` | 여백 없이 화면을 꽉 채우는 **단일 요소**(큰 문장·큰 숫자·인용·풀블리드 배경). 컬럼 분할 없음. | `.s-full` 확장 · `.cover`류 |
| `centered` | 중앙 무대에 **하나의** 메시지/다이어그램. 좌우 대칭 여백. | `.center-msg`/`.cm-title` |
| `top-down` | **상단 타이틀 밴드 + 하단이 콘텐츠를 꽉 채움**(세로 분할, 좌우 아님). | `.s-full` + `.canvas-fill` |
| `grid-mosaic` | 동급 카드 **격자**(2×2·3×2·4×2·bento·gallery). | `.grid-2/3` · card-grid |
| `diagram-centric` | **시각물이 주인공**, 텍스트는 라벨/캡션 최소. | `.s-full` + 코드 다이어그램 element |
| `vertical-flow` | 세로로 흐르는 **스텝/타임라인**(위→아래). | 세로 스텝 스택 |
| `comparison-symmetric` | **2~3개 동등 패널**(주/부 강조 없음). | 대칭 grid |
| `split` | **좌우 비대칭**(한쪽 글·한쪽 시각). ⚠️ 드물게·연속 금지. | `.s-body-wrap`(좌 컬럼) + 우 시각 |

## 2b. 구도 원형 (composition shape) — 의도·패밀리와 직교하는 측정 축

패밀리(§2)는 **콘텐츠 의도**로 나뉜다(연구·빌드 단위). 그런데 **관객은 구도(모양)로 경험**하므로, 같은 2×2가 grid·top-down·diagram 세 패밀리에 흩어져도 관객 눈엔 한 모양이다. 이를 보려면 의도와 **직교하는** 축이 필요하다. 각 레이아웃 항목은 `composition_family`(의도) 외에 `composition_shape`(관객이 보는 매크로 모양) 하나를 **반드시** 갖는다.

**용도:** (1) 조립 시 **직전 슬라이드와 같은 구도 반복 차단**(사람 판단 · 조립 중 적용) (2) 덱의 **구도 분포 측정**. 판정 기준: "직전 옆에 놓았을 때 관객이 「또 같은 거네」 하면 같은 구도." → 반복 감지가 목적이라 **거칠게 8종**으로 유지(잘게 쪼개면 규칙이 안 걸림).

> ⚠️ **2026-08-03 정정 — 용도 (2)의 「측정」을 수행하는 스크립트는 존재하지 않는다.** `composition_shape`를 읽는 코드가 `scripts/` 전체에 **0건**이다. 이 축은 카탈로그 메타데이터로만 존재하며, `composition_family` 필드를 읽는 코드도 **0건**이다. 현재 자동 집계되는 유일한 반복 신호는 `verify_deck.py`의 `family_signature()`인데, 이것은 카탈로그 메타데이터를 읽는 게 아니라 **슬라이드의 CSS class 이름으로 family를 독자 추정하는 별도 휴리스틱**이다(미등재 클래스는 전부 `full`/제네릭으로 뭉개진다). 그마저 R-QC-05는 방향 역전으로 `[사람검토]`로 강등돼 있다. 「분포를 측정한다」를 이미 되고 있는 일로 인용하지 마라 — 하려면 스크립트를 먼저 만들어야 한다.

| 구도 태그 | 정의 | 무게중심 |
|---|---|---|
| `solo-center` | 정중앙 텍스트/숫자 단일 덩어리, 대칭 여백 | 중앙 |
| `stage-figure` | 다이어그램/도해가 무대 전체(텍스트는 라벨·캡션) | 중앙~풀폭 |
| `band-grid` | 상단 밴드 + 아래 동급 격자/타일/표/2×2 필드 | 상단→아래 |
| `band-figure` | 상단 밴드 + 아래를 단일 차트 하나가 지배 | 상단→아래 |
| `flow-vertical` | 세로 스택 시퀀스(행 + ↓/→ 커넥터) | 상단→아래 |
| `panels-mirror` | 동등 패널 미러(좌우 2~3열 또는 상하 밴드), 위계 0 | 좌우/상하 균형 |
| `split-asym` | 좌우 비대칭(한쪽 글·한쪽 시각) | 좌 또는 우 |
| `image-bleed` | 풀블리드 이미지(+오버레이/하단 밴드) | 풀 |

**분포(2026-07-15 · 접기+확충 후):** 물리 **54**항목 = 캐노니컬 **50** + 변주(`variant_of`) **4**. **캐노니컬 구도 분포**: band-grid 13 · solo-center 9 · stage-figure 9 · flow-vertical 7 · panels-mirror 4 · split-asym 4 · band-figure 2 · image-bleed 2. 중복 band-grid 4종을 캐노니컬로 접고(표 3→1·2×2 2→1·벤토 2→1) 콘텐츠 레이아웃 4종을 순증해 **band-grid 14→13(28%→26%)로 편중을 완화**하면서 커버리지를 올렸다. 배경: `_dev/설계기록/카탈로그-구조개편-설계안_2026-07-15.md`.

## 3. 구도 균형 목표 (50 콘텐츠 레이아웃)

고정 구조 슬라이드 6종(표지·도입·아젠다·파트전환·클로징·리캡)은 **별도**로 세지 않는다.

| 패밀리 | 목표 수 |
|---|---|
| full-bleed | 7 |
| centered | 7 |
| top-down | 8 |
| grid-mosaic | 8 |
| diagram-centric | 6 |
| vertical-flow | 6 |
| comparison-symmetric | 4 |
| **split** | **4 (≈8% 캡)** — 좌글 2 + 우글 2 |
| **합계(캐노니컬)** | **50** |

> **2026-07-15 접기+확충:** 물리 항목은 **54**(신규 4: `L-td-glossary`·`L-td-claim-rationale`·`L-vf-case-acts`·`L-gm-pitfalls`), 그중 4개가 `variant_of`로 캐노니컬에 귀속(`L-cs-dual-table`·`L-gm-matrix`→`L-td-table`, `L-td-matrix`→`L-gm-quad`, `L-td-bento`→`L-gm-bento`) → **균형 카운트는 50 유지**. vertical-flow 5→6·comparison-symmetric 5→4(dual-table 접힘)·top-down·grid-mosaic는 신규+접힘 상쇄로 8 유지. split은 4/50=8% 불변.

> split 4개는 방향(좌/우)까지 분산해 "항상 우측 시각" 편향을 원천 차단.

### split을 아낄 때 가는 곳은 박스 격자가 아니다 (2026-07-31 신설)

split(좌우 비대칭)은 캡으로 희소하게 쓴다. 그런데 **split을 피한 자리를 박스 격자로 메우면** 시각 구도를 아낀 것이 아니라 시각자료 자체를 버린 것이 된다. 실측(2026-07-31): 한 덱에서 박스 기반 슬라이드 비율이 5.6% → 22.6%로 늘어나는 동안 시각자료 보유 비율은 50.0% → 20.8%로 떨어졌다.

**시각 구도의 대안은 다른 시각 구도다.** split이 안 맞으면 `stage-figure`(무대형 · 9종)·`band-figure`(띠+도해 · 2종)·`flow-vertical`·`image-bleed` 를 먼저 본다. 박스 격자(`band-grid`)로 도망가지 않는다 — 격자는 항목이 실제로 병렬일 때 고르는 구도이지, 시각자료가 없을 때 채우는 수단이 아니다.

관련 게이트: `verify_deck_quality.py` R-QC-08(시각자료 보유 비율 하한)·R-QC-16(박스 기반 슬라이드 비율 상한).

| 필드 | 뜻 | 예 |
|---|---|---|
| `id` | 고유 ID `L-<family>-<slug>` | `L-fullbleed-statement` |
| `name` | KO / EN 이름 | 큰 선언 / Full-bleed Statement |
| `composition_family` | 8패밀리 중 1 | `full-bleed` |
| `composition_shape` | 8 구도 원형 중 1(§2b · 의도와 직교 · 반복 감지·분포 측정용) | `band-grid` |
| `variant_of` | (선택) 구도 중복 접기 시 캐노니컬 id — 균형은 캐노니컬로 집계(§3), 본문은 보존 | `L-td-table` |
| `info_shapes[]` | 이 레이아웃이 맞는 정준 모양(역인덱스 구동) | `[declaration]` |
| `when_to_use` | 언제 쓰나 | 한 문장으로 좌중을 멈출 때 |

## 7b. family 레지스트리 (R-LAYOUT-03)

구도 다양성 검사(`verify_deck.py`)는 슬라이드의 클래스를 `family_signature()`로 패밀리에 매핑해 판정한다. 새 구도를 만들면 **반드시 레지스트리에 등록**해야 한다.

- **`family_signature()`는 레이아웃 컴포넌트 레지스트리다.** 새 구도를 만들면 그 클래스를 **실제 family에 등록**해야 한다 — 등록하지 않으면 전부 `full`로 뭉개져 3연속 FAIL이 뜬다(실제로 겪음: `S3PE`·`S3LM`·`S3CE`). 단, **회피용으로 세부 클래스마다 고유 시그니처를 만들지 마라.** 2026-07-23에 `chart`(플롯 차트) family를 신설하고 `eng-four`·`privacy-tiers`→grid, `human-compare`→compare, `sy-cases`→bands로 등록했다.
- **의도된 연작은 `data-series` 속성으로 표시한다.** `같은 구도 3연속 금지`는 시그니처 단계에서 `series:<값>`으로 치환해 예외 처리하며, 예외 적용 구간을 로그로 출력한다. **예외를 "런 전체가 같은 series일 때만" 방식으로 구현하면 안 된다** — 연작 옆에 같은 패밀리의 비연작 슬라이드가 붙으면 런이 커져 예외가 통째로 무력화된다(실제로 겪음).

## 8. 소스 정확성 규칙 (리서치 단계)

- 항목당 **열리는 신뢰 소스 ≥ 1** — 리서치 에이전트가 `WebFetch`로 실재 확인, 못 여는 소스는 항목 **기각**.
- 웹 소스는 **영감**일 뿐 — 원본 복제 금지. deck.css 토큰으로 **재표현** + adaptation note 필수.
- 차트 적합성 규칙 준수(예: pie는 부분-전체 ≤~6조각, line은 시계열/연속량).
