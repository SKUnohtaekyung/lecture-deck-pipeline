## 0. 왜 다시 짜나

- **사용자 설계 의도(2026-09-11 대화)**: 3차시의 주인공은 CSV 분석이 아니다. «Coding Agent는 코드만 쓰는 게 아니라 데이터를 Markdown·DOCX·PPTX·HTML 결과물로 바꾼다»는 경험이 주인공이다. HTML은 이해하기 쉬운 대시보드, PPTX는 발표·브리핑 준비까지.
- **원문과 일치**: `courses/AI_코딩_에이전트_입문_3차시/자료/원문/01_교육계획서_구조형_원문.txt` 3차시 절(462행~) — «데이터 분석 전문 지식을 깊게 배우는 것이 목적이 아니라 업무 흐름 경험이 핵심», 10번 «하나의 데이터를 다양한 결과물로 확장», 스토리 `CSV → 정리 → 분석 → 검증 → Dashboard → DOCX / PPTX → 공유`.
- **현행 덱(75장 · 커밋 `1c970f8`)의 쏠림**: 데이터 절차 62.5분 · 결과물 30.5분 · DOCX·PPTX·배포 3분(강사 시연 1장 `6-N-30`).
- **쏠린 원인**: ① `커리큘럼_기준안.md`에서 DOCX·PPTX가 «확장 시연»으로 격하 ② 바이브코딩 3주차 덱의 검토·멀티에이전트 슬라이드 보존 ③ D-03(DOCX/PPTX 도구) 미결로 시연 처리.

## 3. 새 흐름 — 결과물 사슬

```
mock_ecommerce_orders.csv  (원본 · 읽기 전용)
  → ① 구조·품질 확인표            대화 · 파일 수정 없음
  → ② 계획 승인 + 분석대상.csv     사본에서만 정리
  → ③④ dashboard.html            «훑어보는 사람» — 한눈에 이해
  → ⑤ 원본 숫자 대조               결과물로 넘기기 전에 한 번
  → ⑥ 분석결과.md                  검증된 숫자의 근거 문서 = PPTX·DOCX의 공통 입력
  → ⑦ 발표자료.pptx + 발표자 노트   «듣는 사람» — 발표·브리핑
  → ⑧ 분석보고서.docx              «읽는 사람» — 보고
  → ⑨ 네 결과물 숫자 일치표 · 공유 전 점검 → 정적 HTML 배포 소개(시연)
```
