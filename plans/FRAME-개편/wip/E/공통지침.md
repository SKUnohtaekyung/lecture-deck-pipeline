### 실습이 주 내용이다 (사용자 지시)
이 강의의 중심은 **실습(메인 과제 M* · 에이전트 실습 P* · 허브)** 이다. 개념 장은 실습을 받쳐 준다.
- 실습 장이 덱에서 가장 공들인 장이어야 한다 — 참가자가 화면만 보고 따라 할 수 있게: 지금 몇 단계인지(여정 지도 · 단계 점) · 무엇을 열고 무엇을 붙여 넣는지(파일 · 앱 화면 모형) · 끝나면 무엇이 생기는지(결과 모형) · 막히면 어디를 펼치는지가 한눈에.
- 실습 장의 그림은 **실제 할 행동의 모형**이다(폴더 · 파일 · 앱 창 · 붙여 넣는 요청문 · 생기는 결과). 장식 그림을 넣지 않는다.
- 요청문 터미널 창 · 타이머 · 단계 완료 표시 · 복사 버튼은 실습 장에서 가장 잘 보이는 자리에 둔다.
- 개념 장은 실습 사이 짧은 설명이다 — 그림 하나로 요점을 보이고 길게 붙들지 않는다.

### 설명하기 편하게 (강사 관점)
1. 한 장 = 한 메시지. 시선 순서가 제목 → 그림 → 보조 글로 한 방향이다.
2. 그림의 요소마다 짧은 이름표가 있어 강사가 「여기 읽기, 여기 계획」처럼 가리킬 수 있다. 번호가 있으면 발표자 노트 순서와 같다.
3. 한 장의 덩어리는 5개 이하. 본문 22px 이상 · 한 문단 3줄 이하.
4. 조작 위젯은 조작 전 상태만으로도 설명이 된다(PDF · 배포본).
5. 바닥 20% 안쪽(666px 아래)은 비워 둔다 — 발표 조작 막대 · 바닥 줄 자리.

### 한국어 줄바꿈 기준
- 셸이 `word-break:keep-all`(어절 단위) · 제목 `text-wrap:balance` · 본문 `text-wrap:pretty`를 건다.
- **제목**: 두 줄까지. 18자가 넘으면 의미 경계에서 `<br>`로 직접 나눈다 — 「주어/목적어 덩어리」 뒤, 「—」 앞뒤. 조사는 앞 낱말에 붙인다. 한 줄에 한 어절만 남기지 않는다(외톨이 금지).

## ★ 시각 우선 (사용자 지시 · 2026-10-01 — 아래 모든 규칙보다 먼저)

사용자 판정: 「각 정보에 맞는 최적의 형태의 시각 자료로 구성하라고 했는데 지금은 너무 다 줄글이다」. 그래서 **모든 장은 그림이 주인공**이다.

1. 장마다 정보 모양을 먼저 정한다 — 순서 · 비교 · 전후 · 구조 · 포함 · 위치 · 순환 · 분포 · 목록(`kit/guide/정보모양-taxonomy.md`).
2. 그 모양에 맞는 시각 자료를 장의 **절반 이상 면적**에 둔다. 초안 문구는 그림 안의 **라벨 · 캡션 · 노드 글자**로 배치한다(문구는 그대로 — 줄을 나눠 노드마다 나눠 싣는 것은 허용).
   - 순서(단계 · 진행) → 아이콘이 있는 가로 흐름도 / 화살표 노드 / 타임라인. **번호 붙은 줄글 목록으로 끝내지 않는다.**
   - 전후 · 결과물 → 전후 미니 모형(흩어진 메모 → 표, 흩어진 파일 → 폴더 트리, 문의 12통 → 답장 목록, 메모 5개+표 → 보고서).
   - 비교 → 좌우 대비 도식 · 막대 · 두 화면 나란히.
   - 구조 · 포함 → 동심원 · 계층 · 배치도.
   - 목록(점검 항목 · 준비물 · 조건) → 아이콘 + 짧은 라벨의 격자 / 체크 표시 목록(각 항목 앞에 그림 기호).
   - 파일 · 폴더 · 앱 → 파일 아이콘 · 폴더 트리 · 공통 화면 모형(D27).
   - 확인(대조) → 원문 줄 ↔ 결과 칸을 잇는 대조선 · 돋보기 표시 · ✕/✓ 표식.
3. 줄글 문단(두 줄 이상 이어지는 문장 덩어리)은 **한 장에 최대 1개**. 나머지 문장은 그림 속 라벨로.
4. 아이콘은 인라인 SVG로 그린다 — 선 두께 2.5 · 둥근 끝 · `viewBox="0 0 24 24"` 또는 48 · 색은 `var(--blue)`(개념) / `var(--pr-deep)`(실습) · 면은 `var(--mint)` / `var(--pr-fill)`. 이모지 · 이미지 파일 · 외부 아이콘 폰트 0.
5. 박스 예산은 그대로 지킨다 — 그림은 박스가 아니다(SVG · 선 · 아이콘 · 모형은 박스로 세지 않는다. 글을 담은 테두리 카드를 늘리지 말 것).
6. 요청문 터미널 창은 그대로 두되, 터미널이 장을 다 차지하면 옆이나 위에 그 요청으로 **무엇이 생기는지**를 보여 주는 작은 결과 모형을 둔다.

- 박스: 허용 목록(요청문 · 앱/결과 화면 모형 · 표 · 위젯 조작 영역 · 코드/파일 인용)에서만, 결정표 박스 예산 이내. 정의 · 비유 · 단계 목록 · 요약은 박스 없이 타이포 · 여백 · 세로선 · 큰 번호로.
- 폰트 하한: 본문 22px · 표 17px · 라벨 14px · 32px 이상은 자간 −0.02em 이하. 1280×720 안에 들어가야 한다(바닥선 666px · 넘침 0 · 단어 중간 줄바꿈 0 — 한국어는 `word-break: keep-all`이 셸에 있다).
- 위젯: 조작 전 초기 상태만으로 정보가 읽혀야 한다(PDF · 배포본은 초기 상태로 남는다) · 키보드(Enter/Space)로도 동작 · 셸의 위젯 훅 API 사용.
- 머리(`s-head`) · 등장 연출(`.rv` · `--i`)은 카탈로그 예시 그대로.
