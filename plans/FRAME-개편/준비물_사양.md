### 1-4. 연락처와 개인정보 형식

- 전화번호는 `010-0000-00xx`(xx는 두 자리 숫자)만 쓴다. 다른 형식은 0건이다. 지역번호 · 사업자 번호 · 계좌는 위 1-1의 0 채움 표기만 쓴다.
- 이메일은 전부 `@example.com`이다. 로컬 파트는 이름의 영문 표기로 쓴다(예: `seo.hajun@example.com`).
- 회사 · 브랜드 · 사람 이름은 이 문서의 표에 적은 것만 쓴다. 실제 회사명, 실존 인물명, 상표 이름은 0건이다.
- PDF · PNG · JPG 안의 글자와 그림도 같은 규칙이다. 사진은 단색 배경에 도형과 글자를 얹은 합성 이미지로 만들고, 실제 촬영본과 얼굴은 쓰지 않는다.
- 파일 메타데이터(PDF 작성자 · XLSX 작성자 · 이미지 EXIF · zip 항목의 시스템 정보)는 「도담수납」으로 통일한다. 제작 PC의 사용자 이름과 PC 이름이 남으면 안 된다. D7에서 파일마다 열어 확인한다.

### 1-5. 파일 작성 공통 규칙

- 문자 인코딩은 UTF-8(BOM 없음), 줄바꿈은 LF.
- 「줄 번호」는 파일의 물리 줄이다. 빈 줄도 센다. 한 줄은 100자 이내로 써서 화면의 자동 줄바꿈이 줄 번호를 흐리지 않게 한다.
- 이 문서의 줄 지도(2-2 · 5-1)에서 「고정 문장」으로 표시한 줄은 문장을 그대로, 표시한 줄 번호에 둔다. 다른 줄은 요지에 맞게 쓰되, 요지에 없는 날짜 · 담당 · 마감 표현을 새로 만들지 않는다. 파일을 쓴 뒤 clerk가 줄 번호를 대조한다. 어긋나면 파일과 정답 기준값을 같이 고친다.
- 파일 이름은 NFC로 저장하고, Windows 금지 문자(`\ / : * ? " < > |`)를 쓰지 않는다. 공백과 괄호는 02의 쌍 파일에만 쓴다.
- 파일 수정 시각은 2026년 3월 안의 날짜로 정해 zip에 기록한다. 제작일(2026-10)이 노출되면 안 된다.
- 생성 스크립트는 `plans/FRAME-개편/gen/`에 두고 난수 시드를 고정한다. 같은 스크립트를 두 번 돌려 파일별 sha256 목록이 같아야 한다. PDF · XLSX 도구가 작성 시각을 고정하지 못하면 미확인으로 두고 D3 때 확인한다.
- 이미지는 800×600 이하 · 파일당 200KB 이하, PDF는 1쪽 · 파일당 100KB 이하.

### 3-3. 규칙 파일

`AGENTS.md` (16줄, 고정 문장)

```
# 받은자료 폴더 정리 규칙

이 폴더의 파일을 정리할 때 아래 규칙을 따른다.

1. `삭제금지` 폴더 안의 파일은 옮기지 않고, 이름을 바꾸지 않고, 지우지 않는다.
2. 파일을 지우지 않는다. 남길 필요가 없어 보이는 파일은 `보류` 폴더로 옮긴다.
3. 파일 이름은 바꾸지 않는다.
4. 분류 폴더는 아래 여섯 개만 쓴다.
   - 01_견적서
   - 02_계약서
   - 03_현장사진
   - 04_영수증
   - 05_도면
   - 06_기타
5. 파일을 옮길 때마다 `이동기록.md`에 「원래 위치 → 새 위치 | 이유」를 한 줄씩 적는다.
6. 같은 파일이 둘 이상이면 하나만 분류 폴더에 두고 나머지는 `보류`로 옮긴다.
```

`CLAUDE.md`는 `@AGENTS.md` 한 줄이다(D9). 두 파일의 규칙 내용은 같고, 검사는 `CLAUDE.md`의 본문이 `@AGENTS.md`와 일치하는지와 `AGENTS.md`의 존재다.
도구별 인식은 미확인이다. Codex가 `AGENTS.md`를, Claude Code가 `CLAUDE.md`의 가져오기를 읽는 것은 이 저장소 문서 기준이고, Antigravity는 조립 중 확인 항목이다(PLAN O-3, 리허설 GR).

### 4-8. 확인 거리가 약할 때의 조정(D6)
