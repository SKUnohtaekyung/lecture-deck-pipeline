# 새 세션 실행 프롬프트 — likelionSKU 테마 등재 (메인: Opus 5 · 최대 추론)

> 아래 전문을 새 세션 첫 메시지로 붙여넣는다. 이 파일은 그 사본이다.

---

likelionSKU 테마 등재 작업을 실행한다. 계획은 이미 수립·승인됐다 — 정본은
`plans/likelionSKU-theme/PLAN.md`이고, 너는 그 계획의 **실행자**다. 계획을 재설계하거나
재저울질하지 마라(§1 「사용자 확정 결정사항」은 재론 금지). 계획과 현실이 어긋나는 지점을
발견하면 즉석에서 계획을 고치지 말고, 어긋남·판단·근거를 보고하고 계획 문서에 추기한 뒤 진행하라.

## 0단계 — 읽기 (다른 무엇보다 먼저)

1. `.agents/agent-memory/create-slides/MEMORY.md`의 `## 미해결` — 무조건.
2. `plans/likelionSKU-theme/PLAN.md` **전문 정독** — 이 작업의 유일한 계획 정본이다.
   (300줄 초과 파일 워커 위임 규칙의 예외: 지금 실행할 계획서다.)
3. `kit/guide/테마-계약.md` — 등재 조건 2종(§4)과 어휘 동결(§2)의 정본.
4. `references/검증-명령-지도.md` — 필요한 절(§2·§3·§6)만. 전문 정독 불요.

이 프롬프트에는 계획 내용을 복제하지 않는다 — 값·매핑표·기준은 전부 PLAN.md가 정본이다.
프롬프트와 PLAN.md가 어긋나면 PLAN.md를 따른다.

## 1단계 — 이슈 등록

`gh issue create`로 GitHub 이슈를 등록한다(원격: `SKUnohtaekyung/lecture-deck-pipeline`).
- 제목: `likelionSKU 테마 등재 — 색 49토큰 + 과목 프로필 + 등재 관문 2종`
- 본문: PLAN.md의 §4 완료 기준 8항을 체크박스로, §5 성공 기준 ⓐ~ⓔ를 표로, 계획 경로를 링크로.
- 이슈 등록과 진행/최종 코멘트 작성은 이 프롬프트로 승인된 외부 쓰기 범위다.
  **그 외의 외부 쓰기(push · PR 생성 · 이슈 close)는 금지** — 사용자 승인 후에만.

## 2단계 — 실행 (PLAN.md §3의 단계 0 → A → B∥C → E → F → G 순서 그대로)

- 각 단계의 종료 조건 = 해당 단계 검증(PLAN.md §8) **종료코드 확인** + §9의 커밋.
  커밋 메시지 끝에 이슈 번호(`#N`)를 참조로 남긴다.
- 단계 B·C는 병렬 워커(모델 sonnet · effort는 §6 배정: B=medium, C=low), 단계 E①-1은
  워커(sonnet · high). **워커 프롬프트에 PLAN.md §7 워커 규율 4항을 그대로 복사해 넣는다**
  (tmp/ 강제 · 단일 라이터 allowlist · 원본 읽기 전용 · 3천 자 반환).
- 단계별로 이슈에 짧은 진행 코멘트(체크박스 갱신)를 남긴다.

## 3단계 — 최종 보고

성공 기준 ⓐ~ⓔ 각각에 대해 **실행한 명령과 실제 결과 원문**(판정 줄·종료코드)을 붙인
보고를 작성한다. 실행하지 못한 검증은 그 사실과 이유를 적는다. 통과하지 않은 것을 통과로
보고하지 않는다. 같은 내용을 이슈 최종 코멘트로도 남긴다(이슈는 열어 둔다 — close는
main 병합 승인 뒤 사용자 몫). `RESULTS.md`·memory 갱신은 PLAN.md 단계 G 그대로.

## ⚠️ 메인 모델(Opus 5 · 최대 추론) 전용 가드 — 이 저장소의 실측 사고에서 나온 제약이다

1. **팬아웃 상한 고정.** 이 작업의 워커는 계획에 명시된 **3개**(B·C·E①-1)가 전부다.
   추가 서브에이전트·Workflow·병렬 탐사대를 띄우지 마라. 근거: 이 저장소에서 오퍼스
   메인의 대량 팬아웃이 한 주차 작업에 196만 토큰을 태운 실측 사고가 있다
   (memory: opus-fanout-cost-and-model-switch-orphan).
2. **실행 중 모델 전환 금지.** 워커 실행 중 /model 전환은 워크플로 고아·중복 실행을
   유발했다(같은 memory). 시작한 모델로 끝내라.
3. **조사 재수행 금지.** likelionSKU 원본 폴더 전수 조사는 이미 끝났고 그 결과가 PLAN.md에
   반영돼 있다(§0·§3-A 매핑표). 원본은 워커가 필요한 파일만 다시 연다 — 메인이 원본을
   재전수조사하면 창만 비대해진다(실측: 비용의 72%가 뚱뚱한 메인 창의 재독이었다).
4. **범위 밖 개선 금지.** 최대 추론은 개선 기회를 많이 본다 — 보되 고치지 마라.
   PLAN.md §2 「제외」와 §11 「부수 발견」이 경계다. 새로 발견한 범위 밖 이슈는
   보고에 한 줄 기록만 한다. `git status --short`에 범위 밖 변경 0건이 완료 조건이다.
5. **깊이는 판단에, 분량은 보고에 쓰지 마라.** 결정을 담지 않는 턴을 만들지 않는다.
   보고는 판정·근거·수치·다음 행동만 — 사고 과정 서술로 창을 채우지 않는다.
   Bash 출력은 판정 줄만 받는다(`| tail`, `| grep -E "RESULT|FAIL"`, 종료코드만).
6. **막혔을 때 기준을 낮추지 마라.** 최대 추론 모델은 막힌 검증을 「우회할 영리한 방법」을
   잘 찾는다 — 그게 함정이다. 뮤테이션 미탐 발견 → 게이트를 고친다(결함 제거·기준 인하 금지).
   `AmbiguousCourseError` → 예외를 삼키지 말고 호출부에 과목을 명시한다. 테스트 충돌 →
   테스트가 다중 테마·다중 과목을 올바르게 다루도록 고친다. `--no-verify`·`SKIP_DECK_GATES`
   류 탈출구 사용 금지.
7. **멈출 곳.** main 병합·push·PR·이슈 close는 어떤 경우에도 스스로 하지 않는다.
   그 외에는 사용자에게 되묻지 말고 계획대로 완주하라 — ◇ 파생값 4건의 확정은 네 판단으로
   하되 근거를 PLAN.md에 추기하면 된다.
