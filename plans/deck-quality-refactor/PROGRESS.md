## P0.5b — 지표 재정의 검증 · **통과(폐기 판정 포함)** (2026-07-31)

### R-QC-14 — **최종 폐기**

재정의한 3개 variant가 **전부 방향 역전**됐다.

| variant | W1 | W2 |
|---|---|---|
| A 서술형 종결(`~다`·`~요`) | **0.614** | 0.208 |
| B 서술형 + 대구 구조 | **0.629** | 0.208 |
| C 명사구로 끝나지 않음 | **0.614** | 0.217 |

**1주차가 서술형 제목을 3배 더 많이 쓴다.** 사용자가 합격으로 본 덱이 그렇다.

사용자가 문제 삼은 제목을 다시 보면 이유가 분명하다 — "한 줄 정의는 제작 나침반"·
"화면에 보이는 메뉴는 빙산의 일각"·"완료 기준은 눈으로, 테스트는 방법"은 전부 **명사구**다.
문제는 서술형이 아니라 **비유/은유**이고, 비유는 의미 판단이라 과목 무관한 정규식으로
잡을 수 없다(도메인 밖 명사를 잡으려면 과목별 어휘 사전이 필요 → §0-3 위반).

**두 번의 정의 시도가 모두 실패했으므로 출하하지 않는다.** 세 번째 정의를 만들어 숫자를
맞추는 것은 "게이트가 자기에게 맞춰지는" 실패다(§8-3 주석). R-QC-05 강등 선례와 같은
판단이다.

> **후속 세션 주의**: 「제목 비유 검출」을 정규식으로 재시도하지 마라. 서술형 종결·대구
> 구조·비유 표지 패턴 3종이 모두 방향 역전으로 확인됐다(2026-07-31 실측).

## P3.5b — 어절 잘림 탐지 버그 · **수정 완료** (2026-07-31)

### ★ 이 버그는 wordBreaks만의 문제가 아니었다

`measureRender({all:true})`가 숨은 슬라이드를 재려고 `s.style.display='block'`으로
인라인 스타일을 줬다. 그런데 `deck.css`에 이렇게 돼 있다:

```css
.slide{ display:none !important }
.slide.is-active{ display:block !important }
```

**`!important`라 인라인 스타일이 못 이긴다.** 슬라이드는 실제로 0×0으로 숨은 채였고,
`Range.getClientRects()`가 모든 문자에서 빈 배열을 반환해 lineStarts가 쌓이지 않았다.
**활성 슬라이드 1장만 우연히 정상 측정됐다.**

→ 따라서 **2주차의 belowFloor·overlaps·overflow·figureMismatch 기준선도 전부 무효**다.
(2주차 overflow=1, belowFloor=0은 "문제 없음"이 아니라 "1장만 쟀음"이었다)

**수정**: `style.display` 토글 → `is-active` 클래스 토글로 변경. 실제 CSS 규칙과 같은
경로로 슬라이드를 보이게 했다.
