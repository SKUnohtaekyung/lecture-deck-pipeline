## §1. 왜 배치 규칙을 새로 만드는가

기존 승인 기준(`이미지-디렉션-프롬프트.md` §9)에 이런 항목이 있다.

> - 1280×720에서 제목·본문·헤더·페이지 번호·컨트롤과 겹침이 없는가?

**맞는 말인데 수치가 없고 기계 검사도 없다.** 사람 눈 판정에 맡겨져 있어서 실제로 지켜지지
않았다. 그리고 현재 덱의 이미지 배치는 **슬라이드마다 CSS를 따로 박는 방식**이다
(`patterns.css`에 `[data-slide="07"]`·`[data-slide="18"]`처럼 1주차 슬라이드 ID가
하드코딩돼 있고, 2주차는 `.ps-mid-img`·`.c2-10-figure`·`.c3-1-figure`를 각각 새로 정의했다).
장마다 손으로 좌표를 잡으니 겹침·과소·이탈이 구조적으로 발생한다.

→ **표준 슬롯 4종을 정의하고, 슬롯마다 이미지 기하와 본문 인셋을 짝으로 고정한다.**
좌표를 매번 새로 잡지 않으면 겹칠 수 없다.

## §2. 안전영역 (실측 확정)

`kit/styles/deck.css` 실측값에서 유도했다.

| 요소 | 값 | 출처 |
|---|---|---|
| 캔버스 | 1280 × 720 | `.slide{width:var(--sw);height:var(--sh)}` |
| 헤더 `.s-head` | top 34, height 40 → **바닥 74** | `deck.css:178` |
| 본문 `.s-full` | left 64 · right 64 · **top 118** | `deck.css:375` |
| 본문 바닥 | bottom 54 → **666** | `.canvas-fill .s-full{bottom:54px}` |
| 페이지 번호 | 666 아래 | 하단 666px 침범 금지(누적 규칙) |

### 이미지 안전영역 (불변)

```
x ∈ [64, 1216]      가로 1152
y ∈ [118, 666]      세로 548
```

**이미지의 렌더 bbox가 이 사각형을 1px이라도 벗어나면 FAIL이다.**
- `y < 118` → 헤더·브랜드와 겹친다 ("너무 위에 올라간" 경우)
- `y > 666` → 페이지 번호·컨트롤을 침범한다 ("슬라이드 번호 밑까지" 내려간 경우)

## §3. 표준 슬롯 4종 — 이미지 기하와 본문 인셋을 짝으로 고정

각 슬롯은 **이미지 좌표 + 그 슬롯을 쓸 때의 본문 인셋**을 함께 정의한다.
본문을 같이 줄이지 않으면 반드시 겹친다 — 기존 `.has-character-art .s-full{right:420px}`가
쓰던 방식이고, 그 방식이 옳다.

| 슬롯 | 용도 | 이미지 기하 | 본문 인셋 | 간극 |
|---|---|---|---|---|
| **SLOT-R** | 좌 글 / 우 이미지 | `right:64 top:150 width:404 height:460`<br>→ x[812,1216] y[150,610] | `.s-full{right:500}`<br>→ 본문 우단 780 | **32px** |
| **SLOT-L** | 좌 이미지 / 우 글 | `left:64 top:150 width:404 height:460`<br>→ x[64,468] y[150,610] | `.s-full{left:500}`<br>→ 본문 좌단 500 | **32px** |
| **SLOT-B** | 상 글 / 하 이미지 | `left:64 right:64 top:392 height:268`<br>→ x[64,1216] y[392,660] | `.s-full{bottom:360}`<br>→ 본문 하단 360 | **32px** |
| **SLOT-C** | 이미지가 주인공 | `left:190 right:190 top:196 height:424`<br>→ x[190,1090] y[196,620] | 제목만 위(top 118~180)<br>`.s-full{bottom:...}` 미사용 | **16px** |
| **SLOT-B2** | 상 글 / 하 이미지 **2장** | 좌: `left:64 top:392 width:560 height:268`<br>우: `right:64 top:392 width:560 height:268`<br>→ 좌 x[64,624] · 우 x[656,1216] | `.s-full{bottom:360}` | 이미지 사이 **32px** |

> **SLOT-B2는 7p(IMG-03·04)처럼 한 슬라이드에 이미지가 2장인 경우 전용이다.**
> 한 슬라이드에 이미지가 3장 이상이면 슬롯이 없다 — 새 좌표를 만들지 말고 보고한다(§9).

**최소 크기 하한**
- `explanatory`·`mnemonic` 이미지: **면적 ≥ 67,200 px²** (= 280×240 상당)이고 **짧은 변 ≥ 240px**
- 위 4개 슬롯은 전부 이 하한을 넉넉히 넘는다(SLOT-B가 최소 268px).
- 카드 안 인라인 소형(`spot`)은 예외 — 하한 미적용. 단 `spot`은 설명 이미지로 쓰지 않는다.

**금지**
- 슬롯 좌표를 슬라이드마다 새로 잡지 않는다. 4종 중 하나를 고른다.
- 4종으로 안 되는 구도가 나오면 **새 좌표를 발명하지 말고 보고**한다(중단 조건).

## §6. 검토 기준 — 한 번에 통과시키기 위한 3단

> 사용자 요구: "한 번만에 최고의 이미지들이 나올 수 있게."
> → **생성 전 게이트를 두껍게** 만든다. 생성 후 재시도는 1회뿐이므로(R-IMG-06),
> 걸러야 할 것은 프롬프트 단계에서 걸러야 한다.

### 6-A. 프롬프트 게이트 (생성 **전** · 19장 전수 · 전부 기계 검사 가능)

### ⚠️ A16·A17 — 기계로 못 잡는 두 가지 (Opus가 전수 판정)

형식이 완벽해도 **내용이 그 슬라이드와 무관할 수 있다.** A1~A15는 형식만 본다.

**A1~A17 전부 통과해야 생성을 시작한다.** 하나라도 FAIL이면 그 이미지는 생성 큐에 넣지 않는다.

| **C1** | 안전영역 이탈 | 이미지 bbox가 `x∈[64,1216] y∈[118,666]`에 완전히 포함 | **0건** |
| **C2** | 다른 요소와 겹침 | 이미지 bbox ∩ (텍스트·도형 요소 bbox) 면적 > 0 | **0건** |
| **C3** | 과소 크기 | `explanatory`·`mnemonic`의 짧은 변 < 240px 또는 면적 < 67,200px² | **0건** |
| **C4** | 헤더 침범 | 이미지 top < 118 | **0건** |
| **C5** | 페이지번호 침범 | 이미지 bottom > 666 | **0건** |
| **C6** | 슬롯 준수 | 이미지 기하가 §3의 4종 중 하나와 일치(±2px) | **0건 이탈** |
| **C7** | 본문 인셋 짝 | 슬롯을 쓴 슬라이드의 `.s-full` 인셋이 §3 표와 일치 | **0건 이탈** |

**C1~C7은 전부 임계 0이다.** §0-1(임계 0 금지)의 예외 — 겹침·이탈은 표현 선택이 아니라
명백한 결함이다(PLAN §0-1의 「표현 선택 vs 명백한 결함」 구분).

#### C2 판정 대상 한정 (오탐 방지)

**겹침 판정에서 래퍼를 제외한다.** `.s-full`·`.dv-hero` 같은 전면 배경 래퍼는 원래 이미지를
품는 컨테이너라 그대로 재면 전부 오탐이다(누적 규칙의 실측 교훈).

- **대상**: 자기 텍스트를 가진 말단 노드 + `IMG` + `SVG`
- **제외**: 자식이 있으면서 자기 텍스트가 없는 노드(= 래퍼)
- 이미지 자신의 `figure`와 그 안의 `img`는 서로 겹침으로 세지 않는다
