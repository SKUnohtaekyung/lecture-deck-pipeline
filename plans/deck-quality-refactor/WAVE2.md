## 1. 폰트 위계 — 전 슬라이드 적용 (사용자 결정)

> 지적: "제목과 설명 폰트 사이즈가 똑같은데, 달라야지. 설명이 더 작아야지."
> "전체적으로 다 볼드에다 글씨 크기 똑같잖아. 폰트 시스템 잘 쓰자. bold를 미디움
> 정도로 낮춰 써도 된다 — 본문이나 설명 글씨는."

| 역할 | 크기 | 굵기 |
| --- | --- | --- |
| 슬라이드 제목 `.s-title` | 38px | 800 |
| **박스·카드 제목** | **26px** | **800** |
| 슬라이드 본문 문장 `.s-body`·`.s-lead` | **22px 하한 유지** | 500~700 |
| **박스 안 보조 설명문**(`.desc` 등) | **20px** | **500** |

⚠️ **자기 스코프 CSS에 직접 써라.** 메인이 `.slide .desc{font-size:20px}` 전역 규칙을 넣었지만,
1차에서 너희가 만든 `.slide[data-slide="X"] ...` 규칙이 명시도가 더 높아 **전역 규칙을 이긴다**
(실측: 제목 23px·설명 22px로 위계가 안 생겼다). 각자 자기 슬라이드 셀렉터로 다시 지정한다.

### 슬롯 기하 계약 — 어기면 즉시 반려

사용자가 직접 지적한 사고다: *"이미지가 다른 요소와 겹치면 안 되고, 너무 작아도 안 되고,
너무 위에 올라가거나 슬라이드 번호 밑까지 내려가면 안 된다."* 실제로 C5-13에서
`asset-slot--hero`(절대배치)와 shell CSS(`--support` 정적배치)가 어긋나 이미지가 y=738까지
내려가 페이지번호를 침범하고 좌우 본문과 겹쳤다.

```
안전영역   x ∈ [64, 1216]   y ∈ [118, 666]
SLOT-R     right:64  top:150  340×390      (본문 우측 인셋 필수)
SLOT-L     left:64   top:150  340×390      (본문 좌측 인셋 필수)
SLOT-C     left:254  top:196  500×424
SLOT-B2    좌 left:64 / 우 right:64  top:392  340×268
```

- **이미지를 넣으면 본문 컨테이너를 반드시 같이 좁힌다.** 안 좁히면 100% 겹친다.
  `has-img-r`/`has-img-l` 같은 클래스가 있으면 쓰고, 없으면 스코프 CSS로 `.s-full{right:420px}`.
- `asset-slot--hero`와 `--support`는 배치 방식이 다르다. **shell.html의 정의를 확인하고 쓴다.**
- 최소 크기 340×268 미만 금지.

## 4. 하네스 정확 사실 (C4-2·C4-4·C4-11 공통)

정본: `자료/하네스_엔지니어링_교육자료.md`

- **정의(§2.1)**: 하네스는 모델이 사용자 입력을 받아 **도구를 선택·실행하고, 결과를 관찰하고,
  다음 행동을 결정하고, 최종 결과를 반환**하게 만드는 **실행·제어 시스템**이다.
- **골격(§3)**: `에이전트 시스템 = 모델 + 하네스 + 작업 환경`. 모델 혼자서는 파일 보관·명령
  실행·결과 확인을 못 한다.
- **최초 출처(§2.3)**: **Mitchell Hashimoto**가 **2026년 2월**, 에이전트가 잘못할 때마다 같은
  잘못을 반복하지 않도록 환경을 개선하는 활동을 `harness engineering`이라 불렀다. 이후 OpenAI·
  LangChain 등이 기술 문서에 쓰며 확산됐다.
- ⚠️ **§26.3 금지**: "특정 개인이 개념을 최초로 발명했다"고 단정하지 마라. 자료는 **"개념의
  발명이 아니라 용어의 대중화"**로 설명하라고 명시한다. 화면 문구도 그렇게 쓴다.
- 수정요청서가 지우라 한 것은 **2·4·5·6·7월 5개 날짜 연표**이지 최초 출처가 아니다.
  **출처 1건은 정확히 넣고, 연표 나열은 하지 않는다.**
