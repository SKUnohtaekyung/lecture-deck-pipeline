## ⚠️ "44px·27px는 전부 스테일"이 아니다 — 이 작업의 핵심
2026-07-26 실측: `44px|27px` 매치 **9곳 / 5파일**(full-bleed 2 · top-down 3 · vertical-flow 2 ·

- `top-down.md:97` "큰 숫자는 가독성 하한 위(**≥44px**)" — `.s-title`이 아니라 **큰 수치 표시의 하한**.
  스테일이 아니다.
- `full-bleed.md:140` "제목 1줄(≤10어, **34~44px**)" — 허용 **범위** 서술이지 현재 값 단정이 아니다.
- `split.md:137` "제목은 `.s-title` **44px** 2줄까지" — `.s-title` 값 단정 → 스테일 후보.
- `vertical-flow.md:212` "`.s-lead` 35px(**27px**×렌더 행높이 ≈1.3)" — 계산 입력값 → 스테일 후보이고
  결론 수치까지 파급된다.

따라서 **일괄 치환 금지**. 각 매치를 아래로 분류해라.

```
CURRENT_VALUE          현재 CSS 선언값을 정확히 인용 → 유지
COMPUTED_VALUE         line-height 반영 렌더 높이 → 입력값이 맞는지만 확인
HISTORICAL_MEASUREMENT 과거 검증 시점 실측 기록 → 유지(고치면 기록 훼손)
ALLOWED_RANGE          설계 허용 범위 → 유지
DERIVED_CALCULATION    다른 값에서 산출 → 입력이 스테일이면 결론까지 재산출
STALE_REFERENCE        현재 정본처럼 쓰였으나 실제 CSS와 불일치 → 정정 대상
AMBIGUOUS              어느 셀렉터를 가리키는지 불명 → 나에게 물어라
```

**`STALE_REFERENCE`로 판정된 것만 수정한다.**

## 계산식 파급 (DERIVED_CALCULATION 처리)
`capacity`·`density_note`에 수치가 **계산식 입력으로** 들어 있다. 예: `grid-mosaic.md:279`는

입력만 바꾸고 결론을 두면 문서가 자기모순에 빠진다.

- 재계산으로 용량 상한이 바뀌면(예: 4행 → 5행) 정정표에 명시한다.
- 이 레이아웃들은 2026-07-15 브라우저 검증 완료로 기록돼 있다. 산술만으로 확신이 안 서면
  임의로 정하지 말고 `scripts/measure_render.js` 실측을 제안해라
  (절차: `references/phases/08-검증.md` 「렌더 실측 실행 절차」).

     레이어가 다른 것이 설계라면 누락이 아니다.
