## 1. 작업 범위 (건드리는 곳)

| 위치 | 내용 |
|---|---|
| `courses/바이브코딩_온라인/` | `profile.md` · `sessions/1주차/`(오전) · `sessions/2주차/`(오후) · **`sessions/_verify/`(필수)** |
| `plans/바이브코딩_온라인/` | 이 계획 · 진행 기록 |
| `.agents/agent-memory/create-slides/MEMORY.md` `## 미해결` | 인계용 상태 한 절 |

- 루트 `sessions/`는 **수정하지 않는다** — `_template/`은 복사 원본, `_verify/1~3주차`는 기존 바이브코딩 동결 증거.
- ⚠️ `courses/바이브코딩_온라인/sessions/_verify/`를 만들지 않으면 렌더 증거가 루트 `sessions/_verify/N주차`(기존 바이브코딩 자리)로 해석된다(`scripts/_course_paths.py` `verify_root`).
- 과목이 3개가 되므로 검사 스크립트는 `CREATE_SLIDES_COURSE=바이브코딩_온라인`으로 과목을 지정해 돌린다.
- 테마: 기본(default) — 테마 링크 없음.

## 5. 초안·조립 방식

- **작성 주체**: 원본 문장을 재배치·교체해 새 초안을 만드므로 초안 메타에 `> 작성 주체: create-slides(재구성)`를 적는다(R-OWN-03 — 같은 실행 안에서 문장 수정 가능, 변경 사유는 집필노트에 기록). 원본 초안 파일은 수정하지 않는다.
- **근거 추적**: 슬라이드마다 원본 출처(과목·주차·번호/ID)를 집필노트 출처 추적표에 남긴다(R-TRACE-01).
- **발표자 노트**: 원본 멘트(💬·👀·🗣)를 가져오고 차시 연결 멘트는 정리한다 → 덱마다 `강의덱_발표자노트.html` 산출.
- **순서**: 오전 덱 먼저 끝까지(초안 → G1 결정표 → 조립 → 검증 → G2) → 오후 덱.
- **승인 게이트**: G1(조립 전 결정표 — 택1·병합 확정) · G2(조립 후 렌더 결과)는 **각 덱마다** 사용자에게 제출하고 답을 기다린다.
- **실습 예시 결과물**: 타자 게임 · md 3종 · 웹사이트 예시는 슬라이드용 참고본을 `실습예제/`에 둔다. Codex 실제 결과는 사용자가 수업 전 한 번 돌려 확인한다.
- **조립 전략(오전) — 원본 조각 재사용**: 오전 장 대부분이 AC1 조각(`AI_코딩_에이전트_입문_3차시/sessions/1주차/강의덱.초안/part-01~05` · `shell.html`)에 **같은 ID·렌더 검증된 구도**로 있다(인벤토리 `원본조각-인벤토리.md`). 새로 짜지 않고 복사 후 문구만 초안대로 바꾼다.
  - 복사 대상: `shell.html`(kit-additions CSS 320줄 포함) · `revision.css`(1465줄 — 링크 경로 `강의덱.초안/revision.css`) · `자료/images/`의 paper-cut PNG(재사용 장이 참조하는 것만) · `deck.contract.json`의 `layout_families`(AC1 등재 구도 13종).
  - VC1·VC2·AC2에서 오는 장은 해당 원본 조각 `<section>`을 옮기되, 그 원본 shell의 CSS가 필요하면 함께 이식한다(누락 시 렌더 붕괴 선례 — AC1 조립_보고 §0-2).
  - ⚠️ AC1 덱에는 등재된 렌더 결함 waiver(`render_below`·`lap`·`ovf`·`slots`·`occl`·`wideEmpty`·`stretchX/Y`·`lowFill`)가 있다. **새 과목 계약은 0에서 시작**하므로 재사용 장의 기존 결함은 조립 후 렌더 감사에서 고치거나 사유를 적어 새로 등재한다.
  - `data-slide`는 새 초안 ID(`A1-02` 등)로 부여한다 — 원본 ID를 그대로 쓰지 않는다(R-SLIDE-ID-01 · 과목 간 혼동 방지). 원본 ID는 집필노트 추적표가 기록한다.
  - `must_keep`: AC1 계약의 절대사수 11장(M6-02·S3SY·M6-07·24·S59·19·S36·S3HUM·07·S3PRV·S50)이 새 덱에 대응하는 장을 G1에서 확인해 이관 여부를 정한다.
