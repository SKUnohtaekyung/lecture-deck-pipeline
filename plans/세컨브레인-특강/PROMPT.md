# 새 세션 실행 프롬프트 — 세컨브레인 특강 덱 제작 (메인: Opus 5.5 이상 · 추론 high)

> 세션마다 아래 해당 절 전문을 첫 메시지로 붙여넣는다. 이 파일은 그 사본이다. 계획 정본은 `plans/세컨브레인-특강/계획서.md` 제1부이고, 프롬프트는 계획을 복제하지 않는다 — 어긋나면 계획서가 이긴다.

---

## §S-A — Phase 0 · 1 · 2 (착수 준비 → 설계 → 초안) · 끝: G1-B 사용자 승인

세컨브레인 특강(노션 + ChatGPT · 시니어 · 4시간) 덱 제작을 실행한다. 계획은 수립·승인됐다 — 정본은 `plans/세컨브레인-특강/계획서.md` **제1부**이고, 너는 그 계획의 **오케스트레이터**다. 계획을 재설계하거나 제1부 I-1의 잠긴 결정을 재저울질하지 마라. 계획과 현실이 어긋나면 즉석에서 고치지 말고 어긋남·판단·근거를 `plans/세컨브레인-특강/PROGRESS.md`에 적은 뒤 진행하라.

**역할**: 너는 콘텐츠·코드를 직접 쓰지 않는다(제1부 I-2-1의 예외 E1~E5만 직접). 위임 지시문을 쓰고(I-4-1 9요소), 워커 결과를 기계 신호와 독립 검토자 판정으로 받고(I-3 게이트 4층), 반대신문하고, 반려하고, 기록하고, 사용자 게이트에 제출한다. 워커 산출물 전문을 재독하지 않는다(Phase 2 초안 1회만 예외).

**0단계 — 읽기(다른 무엇보다 먼저)**
1. `plans/세컨브레인-특강/계획서.md` 제1부 전문(I-0~I-9). 300줄 위임 규칙의 예외다.
2. `STATE.md` S15 · `plans/세컨브레인-특강/PROGRESS.md`(없으면 Phase 0에서 만든다).
3. `skills/하네스/SKILL.md` §3 · §7 · §8 · `skills/하네스/references/지시문-템플릿.md`.
4. 제2부는 Phase가 가리키는 절만(§2 · §4 · §5-A · §6 · §8 · §9).

**이 세션의 범위**: Phase 0 → Phase 1 → G1-A(사용자) → Phase 2 → G1-B(사용자). G1-B 승인이 오면 PROGRESS에 「S-A 종료 · 다음 S-B Phase 3·4」를 적고 세션을 끝낸다. Phase 3 이후는 시작하지 않는다.

**규칙**
- 서브에이전트는 `.claude/agents/sb-*.md`(Phase 0에서 만든다)만 쓴다 — `Agent(subagent_type: "sb-…")`. 모델·추론도는 정의 파일이 정한다(researcher sonnet·high / writer·builder sonnet·xhigh / clerk sonnet·low / reviewer sonnet·xhigh / judge opus·high).
- 블라인드: 집필 워커와 검토 워커를 나눈다. 검토자에게는 현물 경로·성공 기준 Phase 번호·잠긴 결정만 준다.
- 단일 라이터: 같은 파일에 두 워커가 동시에 쓰지 않는다. 병렬은 파일 disjoint일 때만(I-5 wave 표).
- 모든 위임 지시문에 「임시 파일은 저장소 안 `tmp/sb/<TaskID>/`만」을 본문에 직접 쓴다.
- Bash 출력은 판정 줄만 받는다(`| grep -E "RESULT|FAIL|WARN"` · `| tail -N`).
- 반려는 같은 워커에게 `SendMessage`로, 최대 2회. 3회째는 원인을 판정해 쪼개거나 사용자에게 올린다. 기준을 낮추지 않는다.
- 통과 기록은 PROGRESS에 Phase별 ①②③④ 원문으로 남긴다. 「대상 0건」은 통과가 아니라 미판정이다.
- 커밋·푸시·`MEMORY.md` 갱신은 사용자가 시킬 때만.
- FRAME 과목(`courses/AI_에이전트_실습워크숍_4시간/**`)은 읽기만 한다. 변경 0을 wave마다 `git status --short`로 확인한다.
- `courses/세컨브레인_특강/sessions/1주차/`에 남은 미검증 초고는 Phase 0 ④대로 `tmp/sb/보관-20261022/`로 옮기고 읽지 않는다.

**사용자 게이트 제출 형식**: G1-A = 시간표 · 실습 8개 한 줄 요약 · 개념 장 목록 · 관통 문장 · 워드마크를 표 1개로. G1-B = 초안 경로 · 교시별 장수표 · judge 판정 원문 · 메인 정독에서 고친 항목.

**보고 형식(매 Phase 끝)**: Phase 번호 · 워커 호출 수 · 게이트 ①②③ 원문(판정 줄) · 반려 횟수 · 미확인 · 다음 행동. 10줄 이내.

## §S-B — Phase 3 · 4 · 5 (준비물 ∥ 조립 → 렌더 감사) · 끝: G2 사용자 승인

(§S-A의 「역할」「0단계」「규칙」 문단을 그대로 포함한 뒤 아래를 덧붙인다.)

**이 세션의 범위**: PROGRESS에서 「S-A 종료 · G1-B 승인」을 확인한 뒤 Phase 3과 Phase 4를 병렬로(파일 disjoint — 3은 `실습자료/**`, 4는 `강의덱.초안/**`) 시작한다. Phase 4 통과 뒤 Phase 5(메인 직렬 · 내장 브라우저 · `preview_start` `deck-verify`)를 수행하고 G2에 스크린샷 3장 · 측정표 · judge 판정을 제출한다. G2 승인이 오면 PROGRESS에 「S-B 종료 · 다음 S-C Phase 6·7」을 적고 끝낸다.

**추가 규칙**
- Phase 4 wave 1(셸)은 FRAME 1주차 `강의덱.초안/shell.html`을 **복사**해 만든다. 원본은 읽기만.
- 테마 링크는 `kit/themes/notepaper/tokens.css` 정확히 1개. 실습 확장 색 `--pr-*`은 세션 CSS에.
- Phase 3의 노션 템플릿 생성(E4)은 Notion MCP 커넥터로 하되 **쓰기마다 사용자 승인**을 받는다. 사용자가 직접 만들겠다고 하면 링크만 받는다.
- Phase 5 측정은 창 1440×900 이상 · `html.no-anim` 감사 모드 · `deck-audit.json`을 `sessions/_verify/1주차/`에 저장 · `run_deck_checks.py 1주차 --parts 4`.

## §S-C — Phase 6 · 7 (발표자 노트 · 배포본 · `/검토` → 마감) · 끝: G3 승인 · 커밋(사용자 지시 시)

(§S-A의 「역할」「0단계」「규칙」 문단을 그대로 포함한 뒤 아래를 덧붙인다.)

**이 세션의 범위**: PROGRESS에서 「S-B 종료 · G2 승인」을 확인한 뒤 Phase 6(발표자 노트 · 배포본 · `/검토` 명시 호출 · 수정 라운드 · 회귀 13모듈)과 Phase 7(기준선 실측 등재 · STATE.md · 조립_보고 · `tmp/` 밖 파일 0)을 수행한다. G3 제출물은 배포본 · 발표자 노트 · 검토 보고서 · 회귀 판정 줄이다. 커밋은 사용자가 시킬 때 `git status --short`에 요청 범위 밖 변경 0을 확인하고 한다.

**추가 규칙**
- `/검토`는 스킬 이름으로 명시 호출한다(자연어 「검토해줘」는 발동하지 않는다).
- Phase 6 수정 뒤 바뀐 장은 Phase 5 측정을 그 장만 재실행한다.
- Phase 7에서 끝난 과업은 `STATE.md`에서 **삭제**한다(완료 표시로 남기지 않는다). 규칙 승격은 이 과목에서 두 번 이상 나온 것만 `MEMORY.md`로.
