# 새 창 실행 프롬프트 (Opus 5.5 · 높음 · 저장소 루트에서)

아래 코드 블록을 통째로 붙여 넣는다.

```
FRAME 과목(courses/AI_에이전트_실습워크숍_4시간/sessions/1주차/)의 수정 작업을 한다. 작업 지시서는 plans/FRAME-수정-1025/PLAN.md 이고, 너는 그 문서의 「메인」이다.

[처음에 할 것 — 이 순서로, 이것만]
0. git fetch → 새 커밋이 있으면 git pull --ff-only. 사용자는 두 PC에서 작업한다. 문서가 말하는 파일·장 수가 이 PC에 없으면 추측하지 말고 멈춰서 다른 PC의 푸시를 청한다.
1. plans/FRAME-수정-1025/PLAN.md 전문. §0 사용자 결정 U1~U14는 확정이다 — 다시 따지지 않는다. §1 토큰 규칙이 이 작업의 가장 중요한 조건이다.
2. plans/FRAME-실습강화/재개_인계.md 의 §3 「지킬 것」과 §4 「함정」만: sed -n '/^## 3/,/^## 5/p'
3. plans/FRAME-수정-1025/PROGRESS.md 를 만든다(40줄 이내 · Phase · 상태 · 검토 ✗ 수 · 반영 수 · 남은 것). 이미 있으면 거기서 이어 간다.
그 밖의 문서는 열지 않는다. profile.md는 훅이 주입한다. AGENTS.md는 이미 읽혀 있다.

[일하는 방식]
- 너는 읽지 않고 시킨다. part-0N.html · shell.html · gen_*.py · templates · 생성물(강의덱*.html · *_발표*.html)은 열지 않는다. 위치는 rg -n 한 줄만. 편집은 전부 워커(frame-builder · frame-writer · frame-clerk · frame-researcher · frame-reviewer)가 한다.
- 워커 브리프는 PLAN.md의 해당 「워커 브리프」 절을 §1-1 공통 머리말과 함께 그대로 붙여 넣는다. 새로 쓰지 않는다. 워커 보고는 10줄, 검토자는 25줄 이내로 받는다.
- Phase 1과 Phase 2는 한 메시지에서 두 워커(builder · writer)를 동시에 띄운다. frame-researcher(1-A)도 같은 메시지에. 나머지 Phase는 순차.
- Phase마다 끝에 frame-reviewer 적대적 독립 검토 1회(PLAN.md의 판정표를 그대로 준다 · 결론을 주지 않는다). ✗ 항목은 워커에게 그대로 넘겨 고치고, 재검토 없이 rg -c · build_notes --check 같은 기계 계수로만 확인한 뒤 다음 Phase로 간다.
- 브라우저 측정은 PLAN.md §1-2 스니펫으로 Phase당 1회(javascript_tool). 스크린샷은 설치 장 4 · MHUB · P5-1 · P8 2장에만, scale 0.5. preview_start {name:"deck-verify"}. 캐시 함정과 숨은 장 함정(인계 §4)을 지킨다.
- 명령 출력은 판정 줄만(| tail -n 12 · | rg "RESULT|FAIL|ERROR|OK|Traceback"). PYTHONIOENCODING=utf-8. 임시 파일은 tmp/frame-수정-1025/<phase>/ 에만 — 워커 브리프에도 적는다.
- 화면이 깨지거나 기존 디자인과 다른 스타일이면 안 된다. 새 장은 지정된 기존 장을 본뜨고, 새 CSS 규칙 ≤3 · 새 색 hex ≤1(PLAN §Phase 1-B). 슬라이드 어디에도 「시간 초과」류 문구를 쓰지 않는다. 「A가 아니라 B」 꼴은 말투 린트(FLIP)에 걸린다 — 데스크톱 앱 강조는 PLAN에 적힌 두 문장 그대로 쓴다.
- PLAN.md §0에 없는 결정이 필요하면 멈추고 사용자에게 한 줄로 묻는다(임의 판단 금지). 멈춤 지점은 PLAN의 STOP-1(Claude Code의 AGENTS.md 폴백 · Codex 여는 경로)뿐이고, 묻는 동안 다른 작업은 계속한다.
- Phase가 끝날 때마다 PROGRESS.md를 갱신하고 사용자에게 세 줄(끝난 것 · 검토 ✗→반영 수 · 다음 Phase)만 보고한 뒤 멈추지 않고 다음 Phase로 간다. 긴 중단 뒤나 창이 250k를 넘으면 새 세션에서 PROGRESS.md → PLAN.md 순으로 재개한다.
- 커밋하지 않는다. 2h 덱 · deck.contract.json · kit · 러너 판정은 손대지 않는다.

[끝낼 때]
PLAN.md Phase 5-B의 최종 검토(U1~U14 대조)를 받고, 실행한 명령과 실제 결과 · 하지 못한 검증과 이유 · 「사용자 몫」 목록을 보고한다. 통과하지 않은 것을 통과로 적지 않는다.

Phase 1 · 2 · 1-A를 지금 시작한다.
```

## 메모(붙여 넣지 않음)

- 이 프롬프트가 짧은 이유: 메인이 처음 읽는 것은 이 블록 + PLAN.md + 인계 §3·§4뿐이어야 한다. 요구 사항은 PLAN.md에 다 있다.
- 세션이 끝나면 `PROGRESS.md`와 `git status --short`만 보면 상태를 알 수 있게 되어 있다.
