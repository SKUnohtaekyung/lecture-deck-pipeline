## 4. plans/theme-ui-expansion/REQUIREMENTS.md 충돌·선행조건 후보 (5건 이내)

1. **결정표↔shard 동기화가 수작업·비강제** — 본 감사에서 결정표가 8개 신설 ID(§2-A)와 2개 소실(§2-B)을 전혀 모르는 상태로 "정본"을 자처하고 있음을 발견. REQUIREMENTS §5가 전제하는 "카탈로그 규격 신설"·"검증기 확대"는 이 수작업 동기화 관행 위에 얹히면 과목 수만큼 드리프트가 배가된다. **선행조건**: 결정표 ID ⊂ shard ID 자동 대조 스크립트가 다중 테마 착수 전에 필요.
2. **슬라이드 ID·`layout_families` 임시 증번(V3-10~13, V5-12~15)이 레지스트리 갱신 없이 이뤄짐** — D-2(카탈로그+AI 선택)는 `deck.contract.json`의 `layout_families` 신뢰를 전제하는데, 단일 과목에서도 이미 등재 누락 전례가 확인됨(결정표 152-164행에 신규 8장 미등재). **충돌 지점**: 카탈로그 자동 선택이 이 레지스트리를 신뢰원으로 삼을 계획이라면 먼저 신뢰성을 복구해야 한다.
3. **"절대 사수" 콘텐츠(V1-04)가 조용히 소실된 전례** — D-3("현 규칙을 이어간다")은 콘텐츠 보존 규율(R-OWN-01/02)이 실효적이라는 전제인데, 본 감사가 정반대 사례를 발견함. **선행조건**: 초안 필수 항목 ↔ 최종 shard 존재를 기계적으로 검사하는 게이트가 다과목 확장 전에 필요 — 그렇지 않으면 검토자 인력이 과목 수만큼 옅어질 때 동일 소실이 반복된다.
4. **이미지/자산 슬롯의 미해결 TODO가 이미 존재**(V3-03 "실제 캡처 확보되면 교체 가능", 결정표 171행 "V6-03·V6-04는 실계정 확인 전까지 채울 수 없다") — REQUIREMENTS §4가 이미 지적한 "로고 인라인 → 재조립 필요" 문제와 같은 부류. **선행조건**: 자산-결정 재정합 프로세스가 로고·팔레트 다중화 전에 정립돼야, 테마별 미해결 자산 TODO가 곱해지지 않는다.
5. **`scripts/_course_paths.py`의 단일-과목 가정**(REQUIREMENTS §4 기지 사실) — 본 감사가 다룬 3주차 파이프라인 전체가 이 `course` 훅(과목 지침 주입)에 의존한다. 과목이 2개 이상이면 훅이 조용히 죽는다는 기존 기록과, 본 감사에서 확인한 "조용한 소실이 이미 한 과목 안에서도 발생"이라는 사실을 합치면, 다과목 전환 시 **조용한 실패가 이중으로 겹칠 위험**이 가장 큰 선행조건이다.
