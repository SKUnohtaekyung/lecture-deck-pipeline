## 반복 오답 → 정답

- 오답: 박스 폭을 줄여 긴 문장을 여러 줄로 밀어 넣는다.
  - 정답: 문장에 먼저 충분한 가로폭을 주고, 구·절 경계에서만 줄바꿈한다. **박스를 좁혀 강제 줄바꿈하지 않는다.**
- 오답: 글자가 넘치면 18–20px까지 줄인다.
  - 정답: 보조 설명 22px 하한을 지키고, 카드 수·열 수·이미지 위치·슬라이드 구도를 바꾼다.
- 오답: 정보가 적은 슬라이드를 빈 카드와 큰 여백으로 채운다.
  - 정답: GUI, 실제 캡처, 관계 다이어그램, 설명 이미지로 정보 이해를 보강한다.
- 오답: 모든 장을 좌측 설명·우측 이미지 또는 같은 카드 격자로 만든다.
  - 정답: 정보 모양에 따라 흐름, 타임라인, 비교 밴드, 브라우저 프레임, 폴더 트리, breadcrumb, 터미널, 대형 이미지, 비대칭 편집 구도를 번갈아 쓴다.
- 오답: 카탈로그 레이아웃에 내용을 억지로 맞춘다.
  - 정답: 카탈로그는 후보군이다. 인상적인 결과물·특수 정보는 색·가독성 계약만 유지하고 독립 레이아웃을 만든다.
- 오답: 이미지 확대 요청을 배율 그대로 적용해 다른 요소와 겹친다.
  - 정답: 안전영역 안에서 가능한 최대 크기로 키우되, 겹침 0을 우선한다.
- 오답: "이미지가 작다"는 지적에 figure의 **높이**를 키운다.
  - 정답: `object-fit:contain`은 박스보다 비율이 넓은 그림을 폭에 맞춰 그리고 위아래를 레터박스로 비운다. **높이를 키우면 빈 여백만 커진다** — 조정 전에 `naturalWidth/naturalHeight`와 박스 비율을 비교하고, 시각적으로 키우려면 **가로**를 늘린다(옆 텍스트 컬럼을 그만큼 줄여서). 실측 사례: figure 330×340에 1692×930(1.82:1) 이미지 → 실제 그림은 330×181, 나머지 159px가 빈 공간이었다.
- 오답: `figure`에 고정 높이만 주고 안의 `img` 높이를 방치한다.
  - 정답: figure가 `overflow:hidden`이면 더 큰 `img`의 하단이 조용히 잘린다. `img{width:100%;height:100%;object-fit:contain}`을 함께 명시하고, figure와 img의 `getBoundingClientRect().height`가 같은지 실측한다. 실측 사례: figure 128 vs img 144 → 하단 16px 상시 클리핑.
- 오답: `kit/layouts/families/*.md`의 `capacity`·`density_note`를 **토큰 기본값**(`.s-title` 40/38px, `.s-body` 22px 등)으로 산정한다.
  - 정답: `coded: yes` 레이아웃은 `kit/styles/patterns.css`가 셀렉터별로 값을 **덮어쓴다**. 산정 전에 그 오버라이드를 확인하고, 확신이 없으면 `scripts/measure_render.js`로 실측한다(`references/phases/08-검증.md`). 2026-07-26 감사 실측: `.ca-act .s-lead`는 22px(전역 23px 아님)·`.ca-act .s-body`는 19px이라 `L-vf-case-acts`의 density_note가 **"본문 2줄 3막이 여유 19px로 들어간다"고 승인했지만 실제로는 한 막만 2줄이어도 19.6px, 세 막 모두면 87.2px 오버플로**였다. `L-gm-pitfalls`는 반대로 타이틀 블록을 80px로 과소계상(실측 139.9)해 밴드 상한을 실제보다 좁게 잡고 있었다.
- 오답: `overflow:hidden`으로 잘린 요소를 숨기고 통과한다.
  - 정답: DOM rect, scrollWidth/scrollHeight, 텍스트 클리핑을 측정해 원인을 제거한다.
- 오답: 카드·박스 안 항목을 위에서부터 쌓고 남는 하단 공백을 그대로 둔다.
  - 정답: 캔버스의 "하단 여백 금지"를 **박스 안쪽에도** 적용한다. `display:flex;flex-direction:column` + `justify-content:space-between`/`space-evenly`로 항목 간격을 **균등하게 유지한 채 늘려** 박스를 채운다. 나란한 박스는 전부 같은 방식으로 처리한다.
- 오답: 콘텐츠가 페이지번호 위를 덮어도 캔버스만 벗어나지 않으면 통과시킨다.
  - 정답: `.s-pageno`(right:56/bottom:22) 띠는 침범 금지 영역이다. 콘텐츠 하단 상한은 **666px**이며 `getBoundingClientRect().bottom`으로 실측한다. 모자라면 폰트를 줄이지 말고 행 수·이미지 크기·레이아웃을 다시 잡는다.
- 오답: 아젠다 항목이 5개 이상이면 자동으로 2열(`an-2col`)로 쪼갠다.
  - 정답: 아젠다는 "배울 순서"를 전달하는 시퀀스라 2열이 되면 `::after` 세로 연결선이 꺼지고 흐름이 끊긴다. **N≤6은 1열 연속이 기본**(6개 = 476px < 밴드 514px). `an-2col`은 7개 이상 오버플로 시 탈출구다. `.an-h`에 수동 `<br>`을 넣지 않는다 — 줄바꿈은 컬럼 폭이 정한다.
- 오답: 보이는 페이지 번호로 CSS를 지정한다.
  - 정답: 보이는 번호와 내부 `data-slide` ID를 함께 관리하고 CSS·검증은 안정적인 ID와 전용 클래스로 지정한다.
- 오답: 줄 수가 늘어난 텍스트의 높이를 그 요소의 `line-height`로 조절한다.
  - 정답: **줄 높이는 line box를 소유한 블록이 정한다.** `.terminal-copy`처럼 `display:inline`인 요소에 `line-height`를 줘도 부모 블록(`.terminal-body`)의 값이 이긴다. 2026-07-26 실측: 스코프 규칙에 `line-height:1.5`를 줬는데 실제 행간은 부모의 **34px**였고, 프롬프트가 9줄→14줄이 되자 터미널이 561px로 부풀어 캔버스(720) 밖 801px까지 나갔다. 조정은 **블록 쪽**에 하고, 세로 예산(`밴드 높이 - bar - padding` ÷ 줄 수)으로 상한을 먼저 계산한다.
- 오답: 같은 프롬프트·문구가 덱에 한 번만 있다고 가정하고 한 슬라이드만 고친다.
  - 정답: 실습 프롬프트는 **입력하는 장**과 **회상하는 장**에 중복되기 쉽다. 고치기 전에 조각 전체를 grep해 등장 위치를 세고, 학생이 실제로 타이핑하는 장을 반드시 포함시킨다. 1주차 자기소개 프롬프트는 49(`32`)·52(`S39A`) 두 곳에 있었고 52만 고치면 결과물이 안 바뀐다.
- 오답: 광역 CSS override로 여러 슬라이드를 한꺼번에 고친다.
  - 정답: 공통 타이포그래피 외에는 `data-slide` 또는 페이지 전용 클래스로 범위를 잠근다.

- 내부 분류명, 제작 메타, 검수 용어를 학생 화면에 노출하지 않는다. 학생이 실제로 말하고 확인할 자연어로 바꾼다.
- 일반 슬라이드는 3–6개의 의미 있는 정보 단위를 권장하되, 물리 한도를 넘기지 않는다.
- 학생 덱에 `.hint-reveal`, `강사 힌트`, `막힐 때만 보기`, `완성 예시 보기` 같은 접힘·강사용 힌트를 두지 않는다. 필요한 내용은 처음부터 보인다.
- 가짜 버튼, 실제로 동작하지 않는 테마 변경·접기·토글·애니메이션을 결과물 예시에 넣지 않는다.
- 완료 기준은 “무엇이 열리고, 어떤 내용이 보이며, 무엇을 확인하면 끝인지”로 작성한다.
- 제공하지 않은 경력·연락처·링크·민감 정보를 만들지 않는다. 개인정보·API 키·비밀번호는 요청에 넣지 않는다.

## 이미지·GUI

- **실제 UI 조작은 실제 캡처**를 쓴다. 생성 이미지나 CSS 모형으로 실제 버튼 위치를 가르치지 않는다.
- 실제 캡처는 전체를 `object-fit:contain`으로 보여 주고 crop하지 않는다. 계정·개인정보를 가리고 캡션까지 안전영역 안에 둔다.
- CSS GUI는 개념 설명·상태 설명·경로 구조를 직관적으로 보여 줄 때만 사용한다. 실제 제품 화면이라고 오해시키지 않는다.
- 설명 이미지는 장식이 아니라 관계·원리·변화·순서를 직접 설명해야 한다. 정보 부족은 이런 시각자료로 보강한다.
- 이미지의 투명 여백 때문에 작아 보이면 캔버스와 실제 피사체 경계를 확인한다. 단순 width 확대 전에 여백·object-fit·figure min-height를 점검한다.
- figure 안에서 `img{height:100%}`와 캡션을 함께 쓰면 캡션 높이가 추가되어 이탈할 수 있다. figure에 `min-height:0`, 명시적 grid row, overflow 계약을 둔다.

## 텍스트 폭·폰트·여백

- 한글 큰 글자의 대략적인 폭은 `글자 수 × 폰트 px`로 먼저 계산한다. 가용 폭을 넘기면 크기보다 구도와 줄 경계를 조정한다.
- 본문 22px에서 줄높이 1.5–1.7을 기준으로 실제 세로 예산을 계산한다. 줄 수를 50px 정도로 과소평가하지 않는다.
- 수동 `<br>`은 조사·어미가 앞줄에 매달리지 않는 구·절 경계에서만 쓴다.
- `.s-body`, `.s-lead`, 캡션을 `<p>`에 직접 붙이면 UA 기본 margin을 명시적으로 재설정한다.
- 제목–본문, 이미지–캡션, 카드–카드 사이에 눈에 보이는 간격을 둔다. 빈 공간은 남은 자리가 아니라 정보 그룹을 구분하는 역할이어야 한다.
- 원형 번호 배지와 텍스트 행은 수직 중앙 정렬한다. 배지가 글줄과 겹치거나 행 높이를 밀어내지 않게 별도 열을 둔다.

## 브랜드·터미널·마무리

- 헤더가 있는 모든 본문 슬라이드의 `.s-head`에는 표준 V `.s-logo`와 `VIBECODING` 브랜드를 넣는다. 파트 전환·완전 중앙형 도입 슬라이드는 예외다.
- 표지 터미널은 흰 배경·짙은 본문을 사용한다.
- 검정 터미널은 `var(--ink)` 배경과 `var(--white)` 기본 본문을 쓴다. 프롬프트와 커서만 밝은 민트로 강조한다.
- 마지막 `THANK YOU`는 덱에서 가장 큰 볼드 타이포그래피여야 한다. 다른 제목이 크기를 추월하지 않는다.
- recap·마무리의 헤더 브랜드는 배경과 충분한 대비를 확보한다.

## 브라우저 전수검증

- 조립 후 전체 장을 1280×720에서 순회하고, 실제 인앱 브라우저 크기에서도 다시 확인한다.
- 각 장에서 다음을 측정한다: 자식 요소의 캔버스 이탈, 형제 정보 요소 교차, scrollWidth/scrollHeight 초과, 텍스트 잘림, 이미지 crop, 숨은 캡션, 콘솔 오류.
- 자동 overlap 탐지는 장식·중첩 컴포넌트 오탐이 있으므로, 경고 좌표를 실제 정보 요소 기준으로 판정한다. 오탐을 이유로 전체 감사를 생략하지 않는다.
- 브라우저 캐시를 피하려면 CSS 링크 버전을 갱신한다. `file://`가 아니라 로컬 HTTP 서버로 검사한다.
- 전체 장 검사와 대표 스크린샷 확인이 끝나기 전에는 “완료”라고 보고하지 않는다.
- **`getBoundingClientRect()` 값은 `--scale`로 나눠 덱 좌표(1280×720)로 환산한 뒤 판정한다.** 덱 루트에 `--scale = min(w/1280, h/720)` 변환이 걸려 있어, 창이 작으면 모든 rect가 축소돼 **하단 666px 기준을 자동으로 통과한다**. 실측 사례(2026-07-22): 같은 스크립트가 축소 뷰포트에서 "문제 0"을 냈고, `scale=1`에서 다시 재니 30장이 잡혔다. 스크립트 반환값에 `scale`을 같이 실어 1인지 확인하라.
- **래퍼를 빼고 말단 요소만 잰다.** `.s-full`·`.dv-hero` 같은 전면 배경 래퍼는 원래 720px까지 차지하므로 그대로 재면 전부 오탐이다. 자식 엘리먼트가 있으면서 자기 텍스트가 없는 노드는 제외하고, 텍스트를 가진 노드와 `IMG`만 판정 대상으로 삼는다.

- **사실 정본은 `자료/N주차_개념KB.md` 하나다.** `결과.md`는 `[C-슬러그]` 포인터만 가진 구간 인덱스층이고, verbatim 원문 전문은 `출처레지스트리.md`가 정본이다. 같은 사실을 두 파일에 물리적으로 쓰면 한쪽만 고쳐질 때 조용히 어긋난다.
