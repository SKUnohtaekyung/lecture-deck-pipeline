이 파일은 계속 유효한 재발 방지 규칙과 실제 미해결만 남긴다. 작업일지·완료 역사·커밋 기록·폐기된 산출물은 남기지 않는다.

## 운영 계약

- 작업 시작 전 `## 미해결`을 먼저 읽고, 덱 조립·규칙 변경이면 관련 절 전체를 읽는다.
- 사용자가 명시한 수정은 템플릿·카탈로그·콘텐츠 초안보다 우선한다. 충돌하면 사용자 지시를 적용하고 관련 계약을 함께 갱신한다.
- 관련 작업을 끝낼 때 해결된 항목은 삭제한다. 취소선, 완료 표시, 날짜별 작업 기록으로 보존하지 않는다.
- 대규모 다파일 작업은 하네스의 단일 라이터·allowlist·별도 검수 원칙을 따른다. 수용 전 `git status --short`로 스코프를 확인한다.
- 편집본은 `sessions/N주차/강의덱.초안/`의 `shell.html`·`part-NN.html` 조각이고, 조립본·배포본을 직접 고쳐 정본으로 삼지 않는다.
- **환류 규칙**: 같은 지적이 서로 다른 슬라이드에서 2회 이상 나오면 슬라이드 문제가 아니라 규칙 문제로 판정해 킷·메모리로 승격한다.
  - 2주차 실측(2026-08-03 정정 — 옛 표현 「8종 지적이 90회 반복」은 수치 오귀속이었다. 90건+는 **회의 6회분에서 추린 페이지별 지적 총수**이고, 8종은 그것을 사후에 묶은 **분류 카테고리**다. 두 수를 곱해 읽지 마라):

## 반복 오답 → 정답

- 오답: 박스 폭을 줄여 긴 문장을 여러 줄로 밀어 넣는다.
  - 정답: 문장에 먼저 충분한 가로폭을 주고, 구·절 경계에서만 줄바꿈한다. **박스를 좁혀 강제 줄바꿈하지 않는다.**
- 오답: 글자가 넘치면 18–20px까지 줄인다.
  - 정답: 보조 설명 22px 하한을 지키고, 카드 수·열 수·이미지 위치·슬라이드 구도를 바꾼다.
- 오답: 정보가 적은 슬라이드를 빈 카드와 큰 여백으로 채운다.
  - 정답: GUI, 실제 캡처, 관계 다이어그램, 설명 이미지로 정보 이해를 보강한다.
- 오답: 모든 장을 좌측 설명·우측 이미지 또는 같은 카드 격자로 만든다.
  - 정답: 정보 모양에 따라 흐름, 타임라인, 비교 밴드, 브라우저 프레임, 폴더 트리, breadcrumb, 터미널, 대형 이미지, 비대칭 편집 구도를 번갈아 쓴다.
- 오답: 카탈로그 레이아웃에 내용을 억지로 맞춘다.
  - 정답: 카탈로그는 후보군이다. 인상적인 결과물·특수 정보는 색·가독성 계약만 유지하고 독립 레이아웃을 만든다.
- 오답: 이미지 확대 요청을 배율 그대로 적용해 다른 요소와 겹친다.
  - 정답: 안전영역 안에서 가능한 최대 크기로 키우되, 겹침 0을 우선한다.
- 오답: "이미지가 작다"는 지적에 figure의 **높이**를 키운다.
  - 정답: `object-fit:contain`은 박스보다 비율이 넓은 그림을 폭에 맞춰 그리고 위아래를 레터박스로 비운다. **높이를 키우면 빈 여백만 커진다** — 조정 전에 `naturalWidth/naturalHeight`와 박스 비율을 비교하고, 시각적으로 키우려면 **가로**를 늘린다(옆 텍스트 컬럼을 그만큼 줄여서). 실측 사례: figure 330×340에 1692×930(1.82:1) 이미지 → 실제 그림은 330×181, 나머지 159px가 빈 공간이었다.
- 오답: `figure`에 고정 높이만 주고 안의 `img` 높이를 방치한다.
  - 정답: figure가 `overflow:hidden`이면 더 큰 `img`의 하단이 조용히 잘린다. `img{width:100%;height:100%;object-fit:contain}`을 함께 명시하고, figure와 img의 `getBoundingClientRect().height`가 같은지 실측한다. 실측 사례: figure 128 vs img 144 → 하단 16px 상시 클리핑.
- 오답: `kit/layouts/families/*.md`의 `capacity`·`density_note`를 **토큰 기본값**(`.s-title` 40/38px, `.s-body` 22px 등)으로 산정한다.
  - 정답: `coded: yes` 레이아웃은 `kit/styles/patterns.css`가 셀렉터별로 값을 **덮어쓴다**. 산정 전에 그 오버라이드를 확인하고, 확신이 없으면 `scripts/measure_render.js`로 실측한다(`references/phases/08-검증.md`). 2026-07-26 감사 실측: `.ca-act .s-lead`는 22px(전역 23px 아님)·`.ca-act .s-body`는 19px이라 `L-vf-case-acts`의 density_note가 **"본문 2줄 3막이 여유 19px로 들어간다"고 승인했지만 실제로는 한 막만 2줄이어도 19.6px, 세 막 모두면 87.2px 오버플로**였다. `L-gm-pitfalls`는 반대로 타이틀 블록을 80px로 과소계상(실측 139.9)해 밴드 상한을 실제보다 좁게 잡고 있었다.
- 오답: `overflow:hidden`으로 잘린 요소를 숨기고 통과한다.
  - 정답: DOM rect, scrollWidth/scrollHeight, 텍스트 클리핑을 측정해 원인을 제거한다.
- 오답: 카드·박스 안 항목을 위에서부터 쌓고 남는 하단 공백을 그대로 둔다.
  - 정답: 캔버스의 "하단 여백 금지"를 **박스 안쪽에도** 적용한다. `display:flex;flex-direction:column` + `justify-content:space-between`/`space-evenly`로 항목 간격을 **균등하게 유지한 채 늘려** 박스를 채운다. 나란한 박스는 전부 같은 방식으로 처리한다.
- 오답: 콘텐츠가 페이지번호 위를 덮어도 캔버스만 벗어나지 않으면 통과시킨다.
  - 정답: `.s-pageno`(right:56/bottom:22) 띠는 침범 금지 영역이다. 콘텐츠 하단 상한은 **666px**이며 `getBoundingClientRect().bottom`으로 실측한다. 모자라면 폰트를 줄이지 말고 행 수·이미지 크기·레이아웃을 다시 잡는다.
- 오답: 아젠다 항목이 5개 이상이면 자동으로 2열(`an-2col`)로 쪼갠다.
  - 정답: 아젠다는 "배울 순서"를 전달하는 시퀀스라 2열이 되면 `::after` 세로 연결선이 꺼지고 흐름이 끊긴다. **N≤6은 1열 연속이 기본**(6개 = 476px < 밴드 514px). `an-2col`은 7개 이상 오버플로 시 탈출구다. `.an-h`에 수동 `<br>`을 넣지 않는다 — 줄바꿈은 컬럼 폭이 정한다.
- 오답: 보이는 페이지 번호로 CSS를 지정한다.
  - 정답: 보이는 번호와 내부 `data-slide` ID를 함께 관리하고 CSS·검증은 안정적인 ID와 전용 클래스로 지정한다.
- 오답: 줄 수가 늘어난 텍스트의 높이를 그 요소의 `line-height`로 조절한다.
  - 정답: **줄 높이는 line box를 소유한 블록이 정한다.** `.terminal-copy`처럼 `display:inline`인 요소에 `line-height`를 줘도 부모 블록(`.terminal-body`)의 값이 이긴다. 2026-07-26 실측: 스코프 규칙에 `line-height:1.5`를 줬는데 실제 행간은 부모의 **34px**였고, 프롬프트가 9줄→14줄이 되자 터미널이 561px로 부풀어 캔버스(720) 밖 801px까지 나갔다. 조정은 **블록 쪽**에 하고, 세로 예산(`밴드 높이 - bar - padding` ÷ 줄 수)으로 상한을 먼저 계산한다.
- 오답: 같은 프롬프트·문구가 덱에 한 번만 있다고 가정하고 한 슬라이드만 고친다.
  - 정답: 실습 프롬프트는 **입력하는 장**과 **회상하는 장**에 중복되기 쉽다. 고치기 전에 조각 전체를 grep해 등장 위치를 세고, 학생이 실제로 타이핑하는 장을 반드시 포함시킨다. 1주차 자기소개 프롬프트는 49(`32`)·52(`S39A`) 두 곳에 있었고 52만 고치면 결과물이 안 바뀐다.
- 오답: 광역 CSS override로 여러 슬라이드를 한꺼번에 고친다.
  - 정답: 공통 타이포그래피 외에는 `data-slide` 또는 페이지 전용 클래스로 범위를 잠근다.
- 오답: 조각에서 블록을 옮길 때 `s.index('<div class="w2-prompt …"')`처럼 **파일 첫 일치**를 잡는다.
  - 정답: 같은 컴포넌트가 한 조각 안에 여럿 있으므로 **먼저 `data-slide`로 섹션 범위를 자르고 그 안에서** 찾는다. 2026-08-01 실측: C5-10의 인라인 프롬프트를 떼려다 part-05의 첫 `pr-prompt`인 **A4R1(복구 장)의 프롬프트를 잘라** 다른 슬라이드로 옮겼고, C5-10은 그대로 남았다. **증상이 조용하다** — 조립·`verify_deck`이 통과했고 「같은 구도 3연속 FAIL」이 유일한 신호였다. 옮긴 뒤 **출발지에 없고 도착지에 있는지 양쪽을 대조**하라.
- 오답: 원본에서 회수한 블록을 그대로 되돌려 놓고 끝낸다.
  - 정답: 그 블록이 **이번 세션에서 이미 고친 문구를 담고 있으면 복원과 함께 되돌아간다.** 위 사고에서 A4R1 프롬프트를 원본에서 복원하자 같은 세션에 통일해 둔 관찰 항목(`구조`→`문구`)이 되살아났다. 복원 후 그 세션의 치환 목록을 다시 한 번 훑어라.

## 디자인 판단

- 조립 순서: `정보 모양 분류 → 역인덱스 후보 → 레이아웃과 element 별도 선택 → 직전 장과 구도 비교`.
- 좌우분할과 카드 반복은 금지한다. 같은 레이아웃 패밀리를 연속 사용하지 않고, 같은 패밀리라도 비율·축·시선 흐름·시각 유형을 바꾼다.
- 박스 크기는 정보량에 맞춘다. 짧은 문장에 과도하게 넓거나 높은 상자를 만들지 않고, 긴 문장에는 폭을 먼저 준다.
- 색=의미 → R-COLOR-05 · 토큰만·navy·그라데이션 금지 → R-COLOR-01 · on-민트/on-코랄 → R-COLOR-02 · 박스 표면 → R-COLOR-04 (전부 `kit/guide/디자인시스템.md`)
- 이미지가 큰 장에서는 텍스트와 이미지가 경쟁하지 않게 안전영역과 명확한 간격을 먼저 정한다.
- **게이트 임계를 합격한 이전 덱의 하위 분위수에서 뽑지 마라.** 그러면 그 덱 수준으로 수렴한다. 2주차 R-QC-08 임계 0.35는 1주차 실측 0.500보다 낮아 1주차만 못한 덱도 통과시켰다. 임계는 넘어서야 할 값으로 잡는다.
- **밀도를 올리라는 요구를 박스 확대로 처리하지 마라.** 정보량이 그대로인 채 박스만 커지면 화면은 찼는데 밀도는 낮아진다. 실측: 박스 기반 슬라이드 5.6%→22.6%로 4배가 되는 동안 시각자료 보유는 50.0%→20.8%로 떨어졌다.

## 콘텐츠·학생 화면

- 내부 분류명, 제작 메타, 검수 용어를 학생 화면에 노출하지 않는다. 학생이 실제로 말하고 확인할 자연어로 바꾼다.
- 일반 슬라이드는 3–6개의 의미 있는 정보 단위를 권장하되, 물리 한도를 넘기지 않는다.
- 학생 덱에 `.hint-reveal`, `강사 힌트`, `막힐 때만 보기`, `완성 예시 보기` 같은 접힘·강사용 힌트를 두지 않는다. 필요한 내용은 처음부터 보인다.
- 가짜 버튼, 실제로 동작하지 않는 테마 변경·접기·토글·애니메이션을 결과물 예시에 넣지 않는다.
- 완료 기준은 “무엇이 열리고, 어떤 내용이 보이며, 무엇을 확인하면 끝인지”로 작성한다.
- 제공하지 않은 경력·연락처·링크·민감 정보를 만들지 않는다. 개인정보·API 키·비밀번호는 요청에 넣지 않는다.
- **제목의 비유를 정규식으로 검출하려 하지 마라.** 서술형 종결·대구 구조·비유 표지 3종이 모두 방향 역전으로 폐기됐다(2026-07-31). 합격 판정된 덱이 서술형 제목을 3배 더 많이 쓴다(0.61 vs 0.21).
- **용어 정의 누락을 문자열 표지로 재시도하지 마라.** 정의 신호 3종이 7.1%/92.9%/90.5%로 전부 극단이었다. 한국어 정의는 표지 없이 병치로도 성립해 원리적으로 부정확하다. 사람검토 참고치로만 둔다.

## 이미지·GUI

- **실제 UI 조작은 실제 캡처**를 쓴다. 생성 이미지나 CSS 모형으로 실제 버튼 위치를 가르치지 않는다.
- 실제 캡처는 전체를 `object-fit:contain`으로 보여 주고 crop하지 않는다. 계정·개인정보를 가리고 캡션까지 안전영역 안에 둔다.
- CSS GUI는 개념 설명·상태 설명·경로 구조를 직관적으로 보여 줄 때만 사용한다. 실제 제품 화면이라고 오해시키지 않는다.
- 설명 이미지는 장식이 아니라 관계·원리·변화·순서를 직접 설명해야 한다. 정보 부족은 이런 시각자료로 보강한다.
- 이미지의 투명 여백 때문에 작아 보이면 캔버스와 실제 피사체 경계를 확인한다. 단순 width 확대 전에 여백·object-fit·figure min-height를 점검한다.
- figure 안에서 `img{height:100%}`와 캡션을 함께 쓰면 캡션 높이가 추가되어 이탈할 수 있다. figure에 `min-height:0`, 명시적 grid row, overflow 계약을 둔다.

## 텍스트 폭·폰트·여백

- 한글 큰 글자의 대략적인 폭은 `글자 수 × 폰트 px`로 먼저 계산한다. 가용 폭을 넘기면 크기보다 구도와 줄 경계를 조정한다.
- 본문 22px에서 줄높이 1.5–1.7을 기준으로 실제 세로 예산을 계산한다. 줄 수를 50px 정도로 과소평가하지 않는다.
- 수동 `<br>`은 조사·어미가 앞줄에 매달리지 않는 구·절 경계에서만 쓴다.
- `.s-body`, `.s-lead`, 캡션을 `<p>`에 직접 붙이면 UA 기본 margin을 명시적으로 재설정한다.
- 제목–본문, 이미지–캡션, 카드–카드 사이에 눈에 보이는 간격을 둔다. 빈 공간은 남은 자리가 아니라 정보 그룹을 구분하는 역할이어야 한다.
- 원형 번호 배지와 텍스트 행은 수직 중앙 정렬한다. 배지가 글줄과 겹치거나 행 높이를 밀어내지 않게 별도 열을 둔다.
- **어절 중간 줄바꿈은 조립 후 전수로 잡는다.** 컨테이너가 좁으면 한글이 낱글자 단위로 끊겨 `가장 흔한 실 / 패`처럼 렌더된다(2026-07-30 2주차 실측: 사용자가 64p에서 지적). 바닥선 초과가 없어도 이건 따로 안 잡히므로, 전수검증 항목에 **줄바꿈 위치 판정**을 넣고 컨테이너 폭·`word-break`·글자 크기 중 하나를 장마다 골라 고친다.

## 브랜드·터미널·마무리

- 헤더가 있는 모든 본문 슬라이드의 `.s-head`에는 표준 V `.s-logo`와 `VIBECODING` 브랜드를 넣는다. 파트 전환·완전 중앙형 도입 슬라이드는 예외다.
- 표지 터미널은 흰 배경·짙은 본문을 사용한다.
- 검정 터미널은 `var(--ink)` 배경과 `var(--white)` 기본 본문을 쓴다. 프롬프트와 커서만 밝은 민트로 강조한다.
- 마지막 `THANK YOU`는 덱에서 가장 큰 볼드 타이포그래피여야 한다. 다른 제목이 크기를 추월하지 않는다.
- recap·마무리의 헤더 브랜드는 배경과 충분한 대비를 확보한다.
- **슬라이드 하단 마무리 한 줄을 습관처럼 붙이지 않는다.** 장마다 `callout`·`compare-foot`·`ch-note`로 결론 한 줄을 다는 버릇이 있는데, 사용자가 반복 지적한 항목이다(2026-07-30 2주차: 10개 장에서 일괄 삭제 지시 — 23·26·27·32·44·57·61·63·65·66p). **그 문장이 없으면 장의 뜻이 안 통하는 경우에만** 남기고, 나머지는 강사 멘트·발표자 노트로 내린다. 판정은 장마다 한다.

## 브라우저 전수검증

- 조립 후 전체 장을 1280×720에서 순회하고, 실제 인앱 브라우저 크기에서도 다시 확인한다.

- 자동 overlap 탐지는 장식·중첩 컴포넌트 오탐이 있으므로, 경고 좌표를 실제 정보 요소 기준으로 판정한다. 오탐을 이유로 전체 감사를 생략하지 않는다.
- 브라우저 캐시를 피하려면 CSS 링크 버전을 갱신한다. `file://`가 아니라 로컬 HTTP 서버로 검사한다.

## 파이프라인 상류 (리서치·콘텐츠)

- **사실 정본은 `자료/N주차_개념KB.md` 하나다.** `결과.md`는 `[C-슬러그]` 포인터만 가진 구간 인덱스층이고, verbatim 원문 전문은 `출처레지스트리.md`가 정본이다. 같은 사실을 두 파일에 물리적으로 쓰면 한쪽만 고쳐질 때 조용히 어긋난다.
- **개념KB는 통째로 읽지 않는다.** 서두 「청크 인덱스」 표로 필요한 청크를 고르고 `[C-슬러그]`·`구간:`·`유형:`·`태그:` grep으로 그 청크만 회수한다. 콘텐츠·덱·검토 공통 규율 — 156KB짜리 KB를 전문 Read하면 작업 시작 전에 컨텍스트가 포화된다.
- **"넓게 조사"는 두 축이다.** 관점의 폭(G8 — 한 개념을 공식정의·실무사례·대안비교·한계반론 4각도로)과 개념 목록의 폭(G9 — 커리큘럼 밖이라도 학생이 배운 직후 묻는 전제·후속·혼동 개념)은 서로 대신하지 못한다. G9 인접 청크는 게이트A 승인분만, `범위:인접` 얕은 깊이로, 코어의 50% 이하로 만들고 **슬라이드 본문이 아니라 강사 답변용**(멘트·발표자 노트)으로 쓴다 — 본문에 넣으면 커리큘럼 학습 흐름이 밀려난다.
- **품질 게이트에 금지만 적으면 실행자는 회피로 해석한다.** G1의 3급 "보조 전용"이 실무 사례·대안 비교·반론 수집을 0건으로 만들었다(1주차: 채택 26개 중 23개가 1급 공식문서). G8을 신설해 같은 자리에 "관점 B·C·D에서는 **적극 수집 의무**"를 함께 적어 해소했다. 새 게이트를 쓸 때 "무엇을 막는가"와 "무엇을 여전히 해야 하는가"를 함께 적는다.
- **조사 산출물 세대를 누적하지 않는다.** 중간 산출물(장문 심층리서치·`_v1`류 구버전·임시 커버리지표)은 기본 5파일에 흡수한 뒤 `_dev/설계기록/탐색-아카이브/N주차/`로 옮긴다. 증분 반영 기록은 새 파일·새 청크가 아니라 개념KB 「변경 이력」 절 한 곳에 남긴다.
- **Workflow `args`는 JSON 객체로 넘긴다. 문자열로 넘기면 `args.foo`가 전부 `undefined`가 되고 워커는 그 사실을 모른 채 완주한다.** 2주차 1차 팬아웃에서 `args`를 JSON 인코딩된 **문자열**로 넘겨(`args: "{\"checked\": …}"`) 16개 워커 전원이 조사 기준일·신선도 컷을 `undefined`로 받았다. 워커들은 실패하지 않고 "판단으로 대체"하며 완주했고, 리드가 워커 notes를 읽고서야 발견했다 — **게이트가 조용히 통째로 빠진 것**이라 산출물만 봐서는 드러나지 않는다. 재발 방지: ① 팬아웃 직후 워커 notes에서 `undefined` 문자열을 grep한다 ② 프롬프트에 치환된 값이 실제로 들어갔는지 첫 워커 프롬프트를 한 번 눈으로 확인한다.

### 2026-07-30 새로 얻은 재발 방지

- **워커 산출물에서 `<style>` 블록을 정규식으로 뽑을 때, 문서 «설명문» 안의 `<style>` 글자에 먼저 걸린다.** 실측: 인수인계 주석에 "`<style>` 블록은 …에 추가한다"가 있어 `re.search(r"<style>(.*?)</style>")`가 파일 본문 전체(figure·주석 포함)를 잡았고, 그대로 shell head에 삽입돼 CSS 블록이 깨졌다. 증상은 조용하다 — CSS 오류 복구가 뒤따르는 규칙 하나를 통째로 삼켜서 「override를 썼는데 적용이 안 되는」 형태로만 나타난다. **삽입 후 `<style>`/`</style>` 개수가 1쌍인지, head에 `<figure>`가 0인지 세라.**
- **측정용으로 `.slide`에 `display:block`·`position:relative`를 강제하면 그 자체가 레이아웃을 부순다.** 헤더 로고 SVG가 크기를 잃고 부풀어 헤더가 1285px가 되는 등, 실제 덱과 무관한 «가짜 위반»이 대량 발생한다. **덱 CSS를 건드리지 말고 덱 자신의 표시 메커니즘(`.is-active` 토글)으로 한 장씩 활성화해 재라.**
- **`.s-pageno`를 바닥선 666 검사에서 제외하라.** 그 요소는 bottom:22(=698)에 있는 «침범 대상 띠» 자신이라, 안 빼면 전 슬라이드가 위반으로 잡힌다(실측 104건 전량 오탐).
- **발표자노트를 덱과 다시 맞출 때 «제목으로» 짝지으면 안 된다.** 표지처럼 제목이 `<h2>`가 아닌 슬라이드가 하나라도 있으면 첫 칸부터 어긋나 이후 전부가 「신설」로 오판된다(2026-07-30 실제 발생 — 노트 121블록이 전부 빈 블록으로 덮였고 백업으로 복구했다). **«이번에 넣은 ID»를 빼면 노트와 덱의 순서가 1:1이라는 사실로 맞춰라.** 그리고 노트를 덮어쓰기 전에 사본을 뜬다.
- **표시 페이지 번호 = DOM 인덱스 + 1이다.** 제외 클래스(cover·closing)도 배열 자리는 차지한다 — 건너뛰며 세지 마라.
- **이미지 슬롯의 겹침은 «글자 범위»가 아니라 «요소 박스»로 판정하라.** 글자가 지금 짧아 안 겹치는 것은 보장이 아니다 — 문구가 길어지면 그때 겹친다. 텍스트 컨테이너의 `max-width`를 슬롯 좌변에서 끊어야 안전하다(실측: `center-msg` 박스가 figure 밑으로 20~80px 들어가 있었다).

0. **2주차 리서치 완료(2026-07-22) — 사람 실측 9건이 남아 있다.** 자료 5파일 산출·verify 2종 PASS. 다만 ChatGPT 앱·Codex·Sites 실조작이 불가해 **개인 Plus의 Sites 사용 가능 여부(P0·3주차 확정 경로)·Skills 플랜 요건(D6)·마지막 작동 상태 보호 3후보(D10)** 등이 `[미확인]`이다. 빈 양식은 `sessions/2주차/자료/실측/2주차_앱조작_사람입력.md`에 있고, 채우면 실습 5·7의 **보류** 판정과 D6·D10 추천 근거를 갱신해야 한다. 콘텐츠 단계(`/콘텐츠`)는 이 실측 없이도 진행 가능하다.

2. **초안↔덱 콘텐츠 diff — «부재»가 아니라 «정렬이 약하다».** `scripts/report_draft_sync.py <주차>`가 이미 있고 읽기 전용으로 초안 행↔덱 슬라이드를 대조해 `[일치]`·`[제목불일치]`·`[초안에만]`·`[덱에만]`을 찍는다. 다만 **위치 기반 순차 정렬**이라 한 곳이 어긋나면 뒤가 줄줄이 오정렬돼 노이즈가 크다(2주차 실측: 초안 108행 ↔ 덱 110장에서 `[제목불일치]`가 대량 발생하나 상당수가 정렬 artifact). ⚠️ **2026-08-03 정정 — 「LCS 등 순서보존 정렬로 교체하라」는 낡았다.** 코드는 이미 `difflib.SequenceMatcher(autojunk=False)`로 순서보존 정렬을 한다(`report_draft_sync.py:22·99`). 정렬 방식은 남은 일이 아니다.
  **실제로 남은 일 두 가지**: ① 이 도구는 `sys.exit(0)`이 3곳뿐이고 **`sys.exit(1)`이 코드에 없어 항상 통과**한다 — 게이트가 아니라 리포트다. ② 필요한 검사는 이 도구가 하는 「초안 표 행 ↔ 덱 제목 **시퀀스 대조**」가 아니라 **「각 슬라이드의 초안 제목 문자열이 그 슬라이드 화면 텍스트 안에 있는가」**다. 제목이 `.s-eyebrow`로 밀리거나 본문에 자리를 내준 유형(2주차 실측 4건)은 시퀀스 대조로는 `[제목불일치]`로만 보인다 — **두 도구는 다르다.** 오탐률을 20% 미만으로 낮춘 뒤에만 게이트화한다.
