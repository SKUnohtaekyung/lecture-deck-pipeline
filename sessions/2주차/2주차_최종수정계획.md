## §0. 최종 결론

- **가장 큰 문제:** 현 초안은 사실·구조는 정확하나 **교육학적으로 평탄**하다 — 실습이 교시 끝에만 몰리고(1주차 후반집중 반복), 개념이 선언형에 머물며(정의→왜→반례→적용→판단 단계화 부족), ChatGPT/Codex 역할이 안 나뉘고, 강사 확장 근거(멘트)가 얇고, 첫 작동 결과가 늦다.
- **최종 재설계 방향:** 1주차 PART3의 설계 규율(로드맵·짝개념·반례 예방접종·문제→대응·콜백·기대먼저점검·정직성 경계·밀도 변주)을 이식하고, **각 교시에 실습을 교차**하며, **ChatGPT↔Codex 역할을 분담**하고, **첫 작동을 3교시로 앞당긴다.** 개념은 §7 확정 깊이대로 넓히되 **CORE는 270분에 맞춰 얕게, 초과 깊이는 FLEX**로 분리한다.
- **2주차 핵심 학습성과:** "새 아이디어를 작게 정의 → AI와 구현 → 결과를 사람이 판단해 다시 수정"하는 절차를 **다른 주제에도 재사용**할 수 있게 하는 것(문서·슬라이드 수가 아니라 절차 재사용 가능성이 성과 기준).
- **1주차↔3주차 사이 역할:** 1주차의 요청·확인·수정 사이클을 **재사용**(재교육 금지)하고, PRD·MVP·화면구조·User Flow·분리파일을 **본격화**하며, 저장·배포·공개·발표는 **3주차로 이월**(침범 금지). 2주차는 "문제 한 문장 + prd.md + 화면·기능 하나 작동 + 자체 점검 + 한 문제 수정 + 저장 대상 정의"까지.
- **분량 산정 방식:** 장수를 먼저 정하지 않는다. 270분을 개념·실습·확인·전환으로 배분한 뒤 CORE를 계산한다 → **CORE ≈ 73장**(프레이밍 15: 표지1+간지6+로드맵6+마무리2 · 본문 58), **FLEX ≈ 26장**(§7 초과 깊이·추가 사례), **RECOVERY ≈ 7장**(이탈재현 카드). 총 준비 ≈ 106장이나 **전원 필수(CORE)는 73장**이며(3교시 축소 반영) 승인 범위 ~80±6의 하단이다. 6시간 충분성: CORE가 270분에 맞고 FLEX가 여유분을 흡수하므로 **충분하며 남는 쪽**이 정상.

## §10. 본선·확장·복구 분류

- **CORE(≈73):** 표지1 + 6교시×[간지1+로드맵1+본문] + 마무리2. 전원 필수. 위 §5의 `CORE` 행. (3교시 8 · 5교시 12 · 나머지 13; 13장 교시는 45분 상한 근처 → §4 완화 밸브.)
- **FLEX(≈25):** §5의 `FLEX` 행. **사용 조건:** 교시 실습이 예상보다 빨리 끝나거나 추가 설명 필요 시. **생략 조건:** 시간 압박 시 먼저 생략(새 필수 개념 아님). 순서: 레퍼런스 자유 탐색 → AGENTS 작성 → design.md 파일 → assets → 복수 디자인 비교 → 초기화·모바일 폭(상세설계 §6.7).
- **RECOVERY(≈7):** §5의 `REC` 행 7개(3-REC1·4-REC1·5-REC1~4·6-REC1). pick undefined 결함은 별도 카드가 아니라 6-5(CORE)의 사례. **사용 조건:** 해당 오류 실제 발생 시. **상시 3종**: 파일명(5-REC1)·하위폴더(5-REC2)·절대경로(5-REC3). **예비 1종**: 모듈·fetch(5-REC4, **실브라우저 재확인 선행**). 첫 작동 실패(3-REC1)·레퍼런스 복사(4-REC1)·수정 후 깨짐(6-REC1)은 상시.
