실습별 13항목을 v4 §9 설계에 근거해 채운다. **실측(설치 타이밍·반복 생성 성공률·실제 화면·오류 빈도)은 AI가 대신할 수 없으므로 `[미검증]`으로 표시**하고, 사람 테스터(해서 역할)가 실제 Windows·Codex에서 확인해 `자료/실측/1주차_실습_실측_사람입력.md`에 채운다(이 파일은 사람 전용 — AI가 쓰지·덮지 않는다). 실측 양식은 v4 §11.2를 따른다.

## 사람 실측 인계 양식 (v4 §11.2 — `자료/실측/1주차_실습_실측_사람입력.md`에 복사해 채움)

```
## 검증 항목
- 우선순위: P0 / P1 / P2
- 검증 목적:
- 검증일:
- 기기·운영체제:  ChatGPT 앱 환경:  계정 조건:
- 시작 폴더 상태:  사용한 정확한 요청문:
### 정상 흐름 / 실제 결과(생성 파일·위치·브라우저 실행·조건 충족)
### 실패·이상 흐름(증상·추정 원인·재현 여부)
### 복구(요청/조작·소요 단계·현재 프로젝트 유지·수업 적용 가능)
### 최종 판단: 채택 / 수정 후 채택 / 제외 · 추천 이유 · 총괄 결정 필요 여부
```

**실측 우선순위(v4 §10.1 P0):** 설치·로그인·Codex 진입 → 첫 생성 반복 성공률(≥3회) → 브라우저 직접 실행 → 범위 이탈·복구 → 폴더/파일 분실 복구 → 1회 수정 → 보조강사 지원 순서.

## 실습0 — 설치·로그인·Codex 진입 확인 (1구간)

**①** 실습 목적: 전원이 실습 가능한 환경(인터넷·개인 계정·Plus·데스크톱 앱·로그인·Codex 진입)인지 수업 시작부에 확인한다.
**②** 수강생 안내문: "인터넷, 개인 ChatGPT 로그인, Plus 요금제, 데스크톱 앱, Codex 진입까지 함께 확인합니다. 안 되면 손을 들어 주세요."
**③** 실제 요청문: 요청문 없음 — 설치·로그인·Codex 진입 상태를 눈으로 확인하는 준비 단계다.
**④** 준비물과 사전 설정: Windows 노트북·충전기, 인터넷 연결, 개인 ChatGPT 계정+Plus, ChatGPT 데스크톱 앱 설치(사전 공지).
**⑤** 정상 진행 순서: 앱 실행 → 로그인 확인 → Plus 확인 → Codex 화면 진입 → 작업 폴더를 만들 수 있는 상태 확인.
**⑥** 완료 기준: 준비된 수강생은 Codex 진입, 미완료자는 보조강사 지원 중. 전원 준비까지 본 흐름 무기한 중단하지 않음.
**⑦** 예상 소요 범위: [미검증] 본 흐름 전환 약 15분(v4 §6.3 잠정) — 실제 설치·로그인·진입 소요 실측 필요(D1).
**⑧** 자주 발생하는 오류: [미검증] 앱 설치·업데이트 지연, 로그인·계정 혼동, Codex 위치 못 찾음 — 실제 빈도·유형 실측 필요.
**⑨** 복구 방법: 보조강사 개별 지원, 개인 계정·Plus 상태 함께 확인, 최신 검증 화면을 한 단계씩 안내. 준비 완료자는 자기소개 재료 정리하며 대기.
**⑩** 정상 완성본 위치: 해당 없음 — 별도 정상본·ZIP 제공하지 않음(v4 §6.2).
**⑪** 최소 복구본 위치: 해당 없음 — 현재 계정·앱에서 Codex 진입까지 지원.
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 앱 설치·업데이트 절차, 로그인·요금제 상태 확인, Codex 위치 찾기.
**⑬** 채택·보류·제외 추천과 근거: 채택. 전환 시점(D1)은 실측 후 확정, 병목 크면 "인원 비율" 전환 대안 병기.

## 실습1 — 첫 제작 요청문 작성 (2구간)

**①** 실습 목적: 막연한 생각을 요청의 네 요소(할 일·넣을 것·지킬 것·끝난 모습)로 바꿔 실제 사용할 첫 요청문을 완성한다.
**②** 수강생 안내문: "긴 문장이 아니라 네 칸을 채우면 됩니다. 내 소개로 할 일·넣을 것·지킬 것·끝난 모습을 적어요."
**③** 실제 요청문(예시 틀): "내 소개 웹페이지를 만들어줘. 넣을 것: 이름/활동명, 한 줄 소개, 관심사 2~3개. 지킬 것: [고정 기술조건]. 끝난 모습: 브라우저로 열면 내 내용이 보이는 한 페이지." — 최종 문장은 D2에서 확정.
**④** 준비물과 사전 설정: 자기소개 재료(이름/활동명·한 줄 소개·관심사 2~3), 개인정보 제외 원칙(실번호·비공개 이메일 금지).
**⑤** 정상 진행 순서: 재료 정리 → 네 요소 이해(좋은·나쁜 예 비교) → 자기 정보로 요청문 작성 → "열리고 내 내용 보이면 성공" 완료 기준 적기 → 짝/강사 확인.
**⑥** 완료 기준: 네 요소와 고정 기술조건이 반영된 요청문 + 첫 생성 완료 기준이 적혀 있음.
**⑦** 예상 소요 범위: 약 10~15분(설계 추정) — 이해도 편차는 실측 참고.
**⑧** 자주 발생하는 오류: 무엇을 소개할지 막힘, 프롬프트를 길게 써야 한다는 오해, 실제 연락처 입력, 기능을 많이 넣으려 함, 디자인 요구가 추상적.
**⑨** 복구 방법: 선택형 문장 틀·예시 제공, 네 요소로 축소, 공개 가능 문구로 교체, 첫 목표를 "페이지 실행"으로 되돌림, 개인화는 5구간으로.
**⑩** 정상 완성본 위치: 요청문 예시 세트(D2 후보) — 별도 파일 배포 아님.
**⑪** 최소 복구본 위치: 네 요소만 채운 최소 요청문 틀.
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 자기 표현의 막막함, '프롬프트' 개념의 낯섦.
**⑬** 채택·보류·제외 추천과 근거: 채택. 완성 요청문은 초안에서 🗣(막힐 때만 노출), 최종 문장은 D2.

## 실습2 — Codex 연습 폴더·파일·권한 (3구간)

**①** 실습 목적: 본 프로젝트 전에 작은 연습으로 폴더 열기·파일 생성·수정·권한 판단을 경험해 도구 불안을 줄인다.
**②** 수강생 안내문: "연습 폴더를 만들고 Codex로 열어, 작은 파일을 만들고 한 줄만 고쳐봅니다. 권한 창이 뜨면 함께 판단해요."
**③** 실제 요청문: "이 폴더에 간단한 메모 파일 하나 만들어줘"(연습) → 이어 "그 문장에서 이 한 줄만 이렇게 바꿔줘".
**④** 준비물과 사전 설정: 바탕화면 영문 폴더 `codex-practice`, Codex 진입 완료 상태(실습0).
**⑤** 정상 진행 순서: 폴더 생성 → Codex에서 그 폴더 열기 → (Plan First) 할 일 먼저 확인 요청 → 파일 생성 요청 → 파일 탐색기로 위치 확인 → 한 줄 수정 → 결과 확인 → 권한창 뜨면 4질문 적용.
**⑥** 완료 기준: 파일이 생성되고 실제 위치를 확인, 한 번 수정하고 결과 확인.
**⑦** 예상 소요 범위: [미검증] 실측 필요 — 폴더 열기·파일 확인 흐름의 실제 소요.
**⑧** 자주 발생하는 오류: [미검증] 폴더 만든 위치 잊음, 다른 폴더를 Codex에서 엶, 파일 생성됐는데 못 찾음, 권한창 무조건 승인 — 최신 흐름·빈도 실측 필요.
**⑨** 복구 방법: 교육용 기본 위치·이름 규칙(D3) 사용·다시 찾기, 현재 작업 폴더 확인 캡처, Codex 답변보다 파일 탐색기 우선, 권한 4질문 재적용, 한 문구 수정으로 범위 축소.
**⑩** 정상 완성본 위치: 해당 없음 — 현재 연습 폴더 안에서 복구(v4 §6.2).
**⑪** 최소 복구본 위치: 현재 `codex-practice` 폴더에서 최소 수정.
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 폴더·경로 개념, 권한창에서 승인 판단.
**⑬** 채택·보류·제외 추천과 근거: 채택. 권한창은 강제 체험이 아니라 판단 원칙만(v4 §9.3). 기본 폴더 위치는 D3.

## 실습3 — 첫 자기소개 페이지 생성·브라우저 실행 (4구간)

**①** 실습 목적: 요청문을 실제 단일 `index.html`과 브라우저 화면으로 바꾸는 1주차 첫 큰 성취를 만든다.
**②** 수강생 안내문: "새 프로젝트 폴더에서 내 요청문을 전달하고, 생긴 index.html을 브라우저로 엽니다. 예상과 실제 화면을 비교해요."
**③** 실제 요청문: D2 최종 후보(고정 기술조건 포함) — 초안 본문 노출 금지, 🗣로만 안내.
**④** 준비물과 사전 설정: 바탕화면 영문 프로젝트 폴더 `my-page-01`, 실습1의 요청문·자기소개 재료.
**⑤** 정상 진행 순서: 폴더 생성 → Codex에서 정확한 폴더 열기 → 요청문 전달 → 생성 파일 확인 → 프로젝트 루트의 `index.html` 찾기 → 브라우저로 열기 → 예상↔실제 비교 → HTML·CSS·JS 역할 설명.
**⑥** 완료 기준: `index.html`이 프로젝트 루트에 있고 별도 설치 없이 브라우저에서 열리며 필수 콘텐츠 3종이 표시된다.
**⑦** 예상 소요 범위: [미검증] 실측 필요 — 생성·확인·실행 전체 소요.
**⑧** 자주 발생하는 오류: [미검증] 다른 폴더에 생성, 다중 파일·프레임워크 생성, `index.html` 못 찾음, 다른 프로그램으로 열림, 빈·깨진 화면, 필수 내용 누락 — 빈 폴더 ≥3회 반복 성공률·유형 실측 필요(D2).
**⑨** 복구 방법: 고정 기술조건 재제시로 단일 `index.html` 정리, 파일 탐색기로 루트 확인, 브라우저로 여는 검증된 조작 안내, 저장·새로고침 확인, 누락 항목 하나만 추가 요청.
**⑩** 정상 완성본 위치: 별도 배포 없음 — 최소형 자기소개 페이지 예시 2~3개는 참고용(P2).
**⑪** 최소 복구본 위치: 현재 프로젝트 안에서 최소 재요청(완성본 갈아끼우기 금지, v4 §6.2).
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 폴더·파일 위치 찾기, 브라우저로 여는 조작.
**⑬** 채택·보류·제외 추천과 근거: 채택. 반복 성공률·복구는 실측 후 D2(최종 요청문) 확정.

## 실습4 — 한 번에 하나씩 수정 (5구간)

**①** 실습 목적: 생성 결과에서 유지할 것과 바꿀 것을 구분해 한 가지씩 수정하고 전후를 확인한다.
**②** 수강생 안내문: "유지할 것 → 바꿀 것 → 바뀐 뒤 확인할 것 순서로, 한 번에 하나만 바꿉니다."
**③** 실제 요청문(예시): "지금 배경색은 그대로 두고, 한 줄 소개 문구만 '○○'로 바꿔줘. 바뀌면 브라우저에서 확인할게."
**④** 준비물과 사전 설정: 실습3에서 열린 페이지, 기본 수정 예시 후보(D5).
**⑤** 정상 진행 순서: 유지/변경 표시 → 가장 먼저 바꿀 하나 선택 → 3구조로 수정 요청 → 어떤 파일이 어떻게 바뀌었는지 확인 → 브라우저 확인 → 유지/재수정/완료 선택 → (여유 시) 두 번째 수정·선택 기능.
**⑥** 완료 기준: 원하는 변화가 최소 한 번 반영되고 브라우저에서 전후를 직접 확인.
**⑦** 예상 소요 범위: [미검증] 실측 필요 — 수정 요청→반영→확인 소요.
**⑧** 자주 발생하는 오류: [미검증] 무엇 바꿀지 못 정함, 여러 개 한꺼번에 요청, 차이가 안 보임, 유지할 부분까지 바뀜, 레퍼런스 복제 시도 — 대표 수정별 성공/실패 실측 필요.
**⑨** 복구 방법: 문구·색·글자·간격·배치 중 하나 선택, 가장 중요한 하나로 축소, 파일·저장·새로고침·변경항목 순 확인, 유지 부분 명시해 재요청, 레퍼런스는 특성만 추출.
**⑩** 정상 완성본 위치: 없음 — 현재 프로젝트 안. 수정 예시 카드(D5)만 제공.
**⑪** 최소 복구본 위치: 직전 상태로 되돌리는 최소 재요청.
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 무엇을 바꿀지 결정, 변경 결과 확인.
**⑬** 채택·보류·제외 추천과 근거: 채택. 기본 제시 수정 예시 묶음은 D5, 선택 기능 범위도 D5.

## 실습5 — 오류 대응·최종 점검·마무리 (6구간)

**①** 실습 목적: 문제가 있는 수강생은 자기 프로젝트에 오류 대응 순서를 적용하고, 없는 수강생은 점검·다듬기로 완성한다. 강제 오류 실습은 하지 않는다.
**②** 수강생 안내문: "고장을 일부러 만들지 않습니다. 문제가 있으면 순서대로 확인하고, 없으면 점검하고 다듬습니다."
**③** 실제 요청문(문제 있을 때): "어디서 / 무엇을 했는데 / 실제로 이렇게 되고 / 원래 이걸 기대했어. 한 가지만 고쳐줘." Self Review는 선택적으로 사용.
**④** 준비물과 사전 설정: 각자 현재 페이지, 최종 점검 체크리스트, 레퍼런스 2~3(특성 설명용).
**⑤** 정상 진행 순서: 오류/예상차이/취향 구분 → 기본 확인 순서(폴더·저장·새로고침·화면·기대) → 네 요소로 설명 → 한 가지 재요청 / 문제 없으면 다듬기 → 개인정보·저작물·사실 점검 → 공식 최소 완료 확인 → 회고·다음 주 예고.
**⑥** 완료 기준: 공식 최소 완료 도달 여부 확인, 사람이 완료를 결정.
**⑦** 예상 소요 범위: 약 15~20분(설계 추정).
**⑧** 자주 발생하는 오류: 디자인 불만을 오류로 표현, "안 돼요"만 전달, 문제가 여러 개 겹침, 할 일을 모름, 수정 무한 반복, 최소 완료 미도달.
**⑨** 복구 방법: 작동/누락/취향 구분, 네 요소 문장 틀, 가장 중요한 하나부터, 레퍼런스·체크리스트 제공, 사람이 종료 결정, 보조강사는 실행→내용 표시→첫 수정 순 지원.
**⑩** 정상 완성본 위치: 없음 — 현재 프로젝트. 최종 체크리스트·레퍼런스 세트(P2).
**⑪** 최소 복구본 위치: 현재 프로젝트에서 실행→내용 표시→첫 수정 최소선.
**⑫** 디지털 도구에 익숙하지 않은 수강생의 어려움: 문제를 구체적으로 설명, 완료 판단(언제 끝낼지).
**⑬** 채택·보류·제외 추천과 근거: 채택. 강제 오류 실습 없음(v4 §6.2·§9.6). 오류·레퍼런스 수량·범위는 D6.
