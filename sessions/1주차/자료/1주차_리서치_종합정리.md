| 구간 | 한 줄 목표 | 핵심 경험 |
|---|---|---|
| **1구간** AI 이해 | AI에서 코딩 에이전트까지, 오늘 목표·3주 지도 | LLM·에이전트 차이 이해, Codex가 뭔지 앎 |
| **2구간** 요청하기 | 막연한 생각 → 첫 요청문 | 요청 네 칸으로 자기소개 요청문 완성 |
| **3구간** Codex·폴더·권한 | 도구에 적응 | 연습 폴더에서 파일 생성·수정·권한 판단 |

## 2. 개념 리서치 — 강의에서 쓸 설명 카드

각 개념: **초보자용 설명 / 비유 / 피해야 할 표현 / 출처(등급·날짜)**. 사실 문장은 모두 아래 출처ID로 검증됨.

### 2.1 AI에서 코딩 에이전트까지 (1구간)

| 개념 | 초보자용 한 문장 | 피해야 할 표현 | 출처 |
|---|---|---|---|
| **AI** | 사람이 하던 일을 흉내 내는 프로그램 | — | [S-101] AWS(1급·예외) |
| **생성형 AI** | 분류·예측을 넘어 **새 결과물을 만들어냄** | — | [S-103] Google 2026-07-15(1급) |
| **LLM** | 글을 **토큰**으로 나눠 **다음 조각을 예측**해 문장 생성 | — | [S-104][S-105] Google(1급) |
| **토큰** | AI가 글을 다루는 **작은 단위**(단어와 딱 같지 않음) | **"토큰 = 단어"** | [S-105] 2026-07-10(1급) |
| **에이전트** | LLM + **도구로 직접 일하는 능력** | **"에이전트 = LLM"**(도구 자율성이 차이) | [S-106][S-107](1급) |
| **코딩 에이전트 = Codex** | 폴더의 **파일을 직접 만들고 고침** | **"완전 자동, 사람 개입 없음"**(승인 있음) | [S-201] 2026-07-16(1급) |
| **바이브코딩** | 자연어로 **대화하듯** 만들고 확인 | **"아무렇게나 막 코딩"** | [S-111] Karpathy 2025-02(2급·예외) |
| **에이전틱 코딩** | 목표를 단계로 쪼개 실행·자기수정 | **"자동완성과 같다"** | [S-112] 2025-10(1급·예외) |
| **Chat·Work·Codex** | 한 앱 안 세 공간, 오늘은 Codex | **"모두 똑같이 본다"**(⚠️화면 다를 수 있음) | [S-201][S-206] |

**LLM vs 에이전트 비유 3종 (각 오해 위험):**
1. **요리법 설명 vs 실제 요리** — 오해: 에이전트가 알아서 척척 판단한다고 과신(정해진 루프대로 도구 씀, 중간 확인 필요).
2. **전화 상담원 vs 은행 창구 직원** — 오해: 사람 수준 책임·판단이 있다고 착각(승인 없이 맡기면 잘못된 작업도 실행).
3. **길안내 vs 대신 운전** — 오해: 절대 실수 안 한다고 믿기(엉뚱한 길·잘못된 파일 가능, 최종 확인은 사람).

### 2.2 Codex·폴더·권한·컨텍스트 (3구간)

| 개념 | 초보자용 한 문장 | 비유 / 피해야 할 표현 | 출처 |
|---|---|---|---|
| **폴더 / 파일** | 폴더=작업 범위, 파일=결과물 | 폴더=서류철 | v4[S-000] |
| **권한(승인)** | **폴더 안은 자동, 폴더 밖·인터넷은 물어봄** | 피해야: "파일마다 매번 승인 팝업"(경계 넘을 때만) | [S-202] OpenAI/ChatGPT Learn(1급·발행일 확인불가) |
| **컨텍스트** | 지금 참고하는 **대화·요청·파일**(토큰으로 처리) | 책상에 펼쳐둔 자료 | [S-109][S-105](1급) |
| **메모리** | AI가 **모든 걸 영구 기억하진 않음** | 피해야: "AI가 다 기억한다" | [S-110] 2025-09(1급·예외) |

**권한 판단 4질문:** ① 이 폴더 안인가 ② 내가 시킨 일인가 ③ 뭘 하려는지 아는가 ④ 모르면 멈췄는가.

### 2.4 요청·수정·오류 (2·5·6구간, 설계 기반 [S-000])

- **요청 네 칸:** ① 할 일 ② 넣을 것 ③ 지킬 것 ④ 끝난 모습. ("예쁘게"는 기준 없어 금지)
- **수정 3구조:** 유지할 것 → 바꿀 것 → 바뀐 뒤 확인할 것. **한 번에 하나씩.**
- **레퍼런스:** 복제 아님 — 분위기·색·글자·여백·배치 특성으로 나눠 설명.
- **오류 설명 네 줄:** 어디서 / 무엇을 했는데 / 실제로 어떻게 / 원래 기대. (강제 오류 실습 없음)
- **오류·예상차이·취향** 구분. 기본 확인: 폴더·저장·**새로고침**.

## 3. 실습 설계 (6개) — 요청문 예시는 "막힐 때만" 힌트

| 실습 | 구간 | 목적 | 완료 기준 | 실측 상태 |
|---|---|---|---|---|
| **0** 설치·로그인·Codex 진입 | 1 | 실습 가능 환경 확인 | 준비된 사람 Codex 진입 | 🧪 [미검증] 소요·실패율 |
| **1** 첫 요청문 작성 | 2 | 네 칸으로 요청문 완성 | 네 요소+고정조건 반영 | 설계 완료 |
| **2** 연습 폴더·파일·권한 | 3 | 폴더 열기·생성·수정·권한 판단 | 파일 생성+위치 확인+1회 수정 | 🧪 [미검증] 흐름·실패 |
| **3** 첫 페이지 생성·실행 | 4 | 요청 → index.html 브라우저 | 루트에 index.html, 브라우저 열림, 필수 3종 | 🧪 [미검증] **≥3회 성공률** |
| **4** 한 번에 하나씩 수정 | 5 | 유지·변경 구분해 1회 수정 | 원하는 변화 1회+전후 확인 | 🧪 [미검증] 수정별 성공 |
| **5** 오류 대응·최종 점검 | 6 | 자기 프로젝트 대응·회고 | 공식 최소 완료 확인 | 설계 완료 |

> **복구 원칙:** 완성본으로 갈아끼우지 않음 — **현재 프로젝트 안에서 5~7분 내 최소 수정.** 폴더는 바탕화면 **영문 이름**(codex-practice·my-page-01) 권장.
