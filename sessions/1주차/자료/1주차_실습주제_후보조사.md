## 2. 최종 6개 상세

### ① 나만의 행사 초대장 페이지 (난이도: 쉬움)
- **선정 이유**: JavaScript가 전혀 없어도 완성되는 정적 페이지라, 4시간 동안 태그·색·레이아웃만으로도 "완성했다"는 성취감을 준다. 겁먹은 수강생이 첫 문턱을 넘기게 하는 안전판 역할.
- **난이도 근거**: HTML 구조 + CSS 꾸미기만으로 끝나 로직·상태 관리가 없다. GeeksforGeeks가 HTML 입문 섹션에 명시적으로 분류.
- **화면에 들어갈 것**: 행사 제목(생일파티/동창회/집들이 등 자유 선택) · 날짜·시간·장소 텍스트 · 한줄 소개 문구 · (선택) 참석 여부를 묻는 버튼
- **꼭 되어야 하는 것**: 제목·날짜·장소·소개 문구가 화면에 보인다 / 배경색·글자색·글꼴 크기 등 최소 1가지 이상 CSS로 꾸며져 있다
- **다 됐는지 보는 법**: 더블클릭으로 열었을 때 흰 배경에 기본 글씨만 보이는 게 아니라 색·정렬이 적용돼 있다 / 화면에 정보 4가지가 빠짐없이 보인다
- **예상 실패 지점**: 너무 쉬워서 일부 수강생이 "이게 다예요?"라며 빨리 끝내고 남는 시간에 방황할 수 있다 — 강사가 "참석 여부 버튼 눌렀을 때 문구 바뀌기" 같은 선택 미션을 미리 준비해두면 좋다.

### ② 오늘의 한마디 뽑기 (랜덤 명언/문장 생성기) (난이도: 쉬움)
- **선정 이유**: 버튼 클릭 → 화면 문구가 바뀌는 즉각적 피드백이 있어 "프로그램이 반응한다"는 성취감을 주면서도 로직은 배열에서 하나 뽑는 수준이라 부담이 적다.
- **난이도 근거**: freeCodeCamp의 입문용 quote generator 튜토리얼이 "절대 초보"를 명시적 대상으로 삼음. 단, API 호출판이 아니라 배열 하드코딩판으로 한정해야 쉬움 등급 유지.
- **화면에 들어갈 것**: "오늘의 한마디" 같은 제목 · 문장이 보이는 카드 영역 · "다음 문장" 버튼 · (선택) 문장 배경색이 매번 바뀌는 효과
- **꼭 되어야 하는 것**: 버튼을 누르면 문장이 바뀐다 / 문장은 최소 5개 이상 미리 준비돼 있다 / 새로고침해도 페이지는 정상적으로 열린다(에러 없음)
- **다 됐는지 보는 법**: 버튼을 여러 번 눌러 화면 문구가 실제로 달라지는지 확인 / 페이지를 새로 열어도 첫 화면이 깨지지 않는지 확인
- **예상 실패 지점**: 유명인 명언을 그대로 복사하면 출처 표기 문제가 생길 수 있으니, 수강생이 직접 쓴 응원 문구·다짐 문장으로 채우도록 강사가 미리 안내해야 한다.

### ③ 나의 BMI 계산기 (난이도: 보통)
- **선정 이유**: 키·몸무게라는 익숙한 실생활 값을 넣고 결과를 받는 구조라 20~60대 모두에게 "내 얘기"로 와닿는다. 계산 결과가 숫자로 명확히 나와 완성 여부 판정이 쉽다.
- **난이도 근거**: 입력 2개(키·몸무게) → 공식 계산 → 결과 문구 표시라는 3단 구조. 여러 튜토리얼(Medium, foolishdeveloper, 100jsprojects)이 입문 프로젝트로 공통 지목.
- **화면에 들어갈 것**: 키 입력칸(cm) · 몸무게 입력칸(kg) · "계산하기" 버튼 · 결과 문구(수치 + 저체중/정상/과체중 등 한마디)
- **꼭 되어야 하는 것**: 숫자를 넣고 버튼을 누르면 결과가 뜬다 / 결과에 BMI 수치와 판정 문구가 함께 보인다 / 값을 다시 넣고 눌러도 결과가 새로 계산된다
- **다 됐는지 보는 법**: 서로 다른 키·몸무게 두 세트를 넣어봤을 때 결과 수치가 각각 다르게 나오는지 확인 / 빈 칸으로 눌렀을 때 화면이 깨지지 않는지 확인
- **예상 실패 지점**: 빈 입력이나 0을 넣었을 때 `NaN`이나 `Infinity`가 그대로 보이는 경우가 흔하다 — "확인 기준"에 "이상한 값이 아니라 안내 문구가 뜬다"를 넣도록 강사가 짚어줄 필요가 있다.

### ④ 가위바위보 게임 (난이도: 보통)
- **선정 이유**: 규칙을 모두가 이미 알고 있어 "무엇을 만들지" 설명이 필요 없고, 이기고 지는 결과가 바로 눈에 보여 완성 판정이 쉽다. 게임이라는 재미 요소가 있어 실습 후반부 집중력 유지에 좋다.
- **난이도 근거**: 버튼 3개(가위/바위/보) → 컴퓨터 랜덤 선택 → 승패 조건 비교 → 결과 문구. freeCodeCamp·hackr.io 등 다수 목록에 공통 등장하는 정석 입문 게임.
- **화면에 들어갈 것**: 가위/바위/보 선택 버튼 3개 · 내가 낸 것과 컴퓨터가 낸 것을 보여주는 영역 · 승/패/무 결과 문구 · (선택) 누적 점수
- **꼭 되어야 하는 것**: 버튼을 누르면 컴퓨터도 무작위로 하나를 낸다 / 승/패/무가 규칙대로 정확히 판정된다 / 낼 때마다 결과가 새로 갱신된다
- **다 됐는지 보는 법**: 같은 버튼을 여러 번 눌러 승/패/무 결과가 각각 나오는 경우를 직접 확인 / 컴퓨터가 낸 것이 매번 바뀌는지(항상 같은 걸 내지 않는지) 확인
- **예상 실패 지점**: 랜덤 로직이나 승패 조건문(if/else)에서 오류가 나면 화면에 아무 반응이 없어 "고장났다"고 오해하기 쉽다 — 브라우저 개발자도구 콘솔 확인법을 짧게라도 안내하면 도움이 된다.

### ⑤ 나의 할 일 목록 (To-Do 리스트) (난이도: 보통~어려움)
- **선정 이유**: 입력 → 추가 → (완료/삭제) 라는 실용 앱의 기본 패턴을 처음으로 경험하게 해 다음 주차(더 복잡한 상태 관리)로 넘어가는 다리 역할을 한다. "내가 쓸 만한 걸 만들었다"는 실용적 성취감이 크다.
- **난이도 근거**: 목록(배열) 상태를 다루고 항목을 동적으로 추가·삭제하는 DOM 조작이 들어가 앞의 후보들보다 로직이 한 단계 더 필요하다. hackr.io가 "이상적인 첫 실습"으로 소개.
- **화면에 들어갈 것**: 할 일 입력칸 · "추가" 버튼 · 추가된 항목이 쌓이는 목록 · 각 항목의 완료 체크 또는 삭제 버튼
- **꼭 되어야 하는 것**: 입력하고 추가 버튼을 누르면 목록에 새 줄이 생긴다 / 항목을 완료 처리하거나 지울 수 있다 / 목록이 여러 개 쌓여도 순서대로 보인다
- **다 됐는지 보는 법**: 서로 다른 할 일을 3개 이상 추가해 목록에 다 쌓이는지 확인 / 하나를 지우거나 완료 표시했을 때 그 항목만 바뀌고 나머지는 그대로인지 확인
- **예상 실패 지점**: 새로고침하면 목록이 사라지는 것이 "고장"이 아니라 이번 실습 범위(백엔드·저장 없음) 밖이라는 점을 미리 설명해야 한다. 또한 흔한 튜토리얼은 `localStorage`로 저장까지 넣는 경우가 많은데, 이번 실습에서는 그 부분을 요구하지 않는다고 명확히 선을 그어야 범위가 새지 않는다.

### ⑥ 카운트다운 타이머 (난이도: 보통~어려움)
- **선정 이유**: 숫자가 매초 줄어드는 시각적 변화가 뚜렷해 "프로그램이 살아있다"는 인상을 강하게 준다. 운동·요리·공부 등 실생활에 바로 쓸 수 있어 만든 뒤에도 애착이 생기는 주제.
- **난이도 근거**: 시간 값을 입력받아 매초 갱신하는 반복 로직(setInterval류)이 필요해 앞의 계산기·게임류보다 상태 관리 난도가 높다. hackr.io·freeCodeCamp 목록에 공통 등장.
- **화면에 들어갈 것**: 분/초 입력칸 · "시작" 버튼 · 남은 시간이 크게 보이는 표시 영역 · 시간이 다 됐을 때 보이는 안내 문구
- **꼭 되어야 하는 것**: 시작을 누르면 숫자가 1초마다 줄어든다 / 0이 되면 자동으로 멈추고 안내 문구가 뜬다 / 다시 시작을 누르면 처음부터 다시 센다
- **다 됐는지 보는 법**: 짧은 시간(예: 10초)을 넣고 실제로 화면 숫자가 매초 줄어드는지 눈으로 확인 / 0이 됐을 때 숫자가 음수로 계속 내려가지 않고 멈추는지 확인
- **예상 실패 지점**: `setInterval`을 멈추는 코드를 빠뜨리면 여러 번 시작 버튼을 눌렀을 때 타이머가 여러 개 겹쳐 돌아가는 흔한 버그가 난다 — 강사가 "확인 기준"에 "시작을 두 번 눌러도 숫자가 이상하게 빨리 줄지 않는다"를 넣어 미리 걸러지게 하면 좋다.

### 6개 세트의 난이도·JS 사용 수위 분포
| 주제 | 난이도 | JavaScript 수위 |
|---|---|---|
| 행사 초대장 페이지 | 쉬움 | 없음(선택 시 버튼 클릭 정도만) |
| 오늘의 한마디 뽑기 | 쉬움 | 최소 — 배열에서 랜덤 하나 꺼내 텍스트만 교체 |
| BMI 계산기 | 보통 | 입력값 읽기 + 공식 계산 + 조건 분기(if/else) |
| 가위바위보 게임 | 보통 | 랜덤 선택 + 조건 분기(if/else) |
| 할 일 목록 | 보통~어려움 | 배열 상태 관리 + 동적 DOM 추가/삭제 |
| 카운트다운 타이머 | 보통~어려움 | 반복 실행(setInterval) + 상태 관리 |

JS 없이도 완성되는 주제가 1개(행사 초대장), 반응은 있으나 로직은 아주 가벼운 주제가 1개(한마디 뽑기)로 "JavaScript는 반응이 꼭 필요할 때만" 원칙과 "겁먹지 않고 완주" 요건을 함께 만족한다.

## 3. 아깝지만 뺀 주제

- **사칙연산 계산기**: 제약은 모두 통과하고 실용성도 높지만, BMI 계산기가 같은 "입력→계산→출력" 패턴을 더 실생활 친화적으로 대표하고 있어 중복을 피해 뺐다. 반 규모가 크거나 재수강반이 있으면 대체 주제로 바로 쓸 수 있다.
- **다지선다 퀴즈 앱**: 게임성과 완성 판정 용이성이 좋지만, 문제·보기·정답을 미리 여러 개 준비해야 해 "넣을 내용" 분량이 다른 후보보다 많고 4시간 실습에서 콘텐츠 작성에 시간을 뺏길 우려가 있어 제외했다.
- **색상 생성기(랜덤 팔레트)**: 쉬움 등급 후보로 유력했으나, "오늘의 한마디 뽑기"와 난이도·로직 구조(버튼→랜덤 값 하나 표시)가 거의 같아 대표 하나만 남기고 뺐다. 시각적 재미를 더 원하는 반이면 한마디 뽑기 대신 넣어도 무방하다.
- **틱택토**: 인지도와 완성 판정 명확성은 높으나, 승리 조건(가로·세로·대각선 8가지) 판정 로직이 가위바위보보다 한 단계 더 복잡해 "보통" 등급 게임 자리를 가위바위보에 양보했다.
