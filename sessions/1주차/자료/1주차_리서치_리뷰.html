[C-ai] 구간 1 유형: 개념 P0

AI

정의(정확)

AI(인공지능)는 학습·추론·문제해결·지각·의사결정 등 인간 지능과 결부된 과업을 수행하는 계산 시스템의 능력이다. [S-102]

초보자 문장 (화면 노출 문장)

AI(인공지능)는 사람이 학습하고 판단하고 문제를 해결하던 일을 컴퓨터가 흉내 내도록 만든 기술이다. 스팸 메일을 걸러내는 것부터 글을 새로 써주는 것까지 모두 AI의 한 종류다.

비유①

AI는 수많은 문제를 풀어보며 패턴을 익힌 학생과 같다.매핑: A=학생이 문제집을 많이 풀며 유형을 익힘 · B=AI가 방대한 데이터를 학습해 패턴을 찾음오해 위험: 학생처럼 내용을 '이해'하며 의미를 안다고 착각하기 쉽다 — 실제로는 통계적 패턴 인식과 확률 계산에 가깝다.

비유②

AI는 수많은 책을 읽고 질문에 답해주는 만능 사서와 같다.매핑: A=사서가 책에서 찾은 내용을 근거로 답변함 · B=AI가 학습한 데이터에서 패턴을 찾아 답을 내놓음오해 위험: 사서가 항상 정확한 사실만 말해준다고 믿듯, AI도 항상 맞는 말만 한다고 과신하기 쉽다 — 실제로는 그럴듯하지만 틀린 답을 내놓을 수 있다.

입력: 받은 메일 제목 "무료 상품권 100% 당첨!!!" → 처리: AI가 과거에 학습한 스팸 메일의 문구 패턴(과장된 표현·느낌표 반복 등)과 비교 → 결과: "스팸함으로 분류"라고 판단해 자동으로 이동시킴. (창작)

  • "AI는 사람처럼 완전히 이해하고 판단한다" → AI는 학습한 데이터의 패턴에 기반해 확률적으로 그럴듯한 결과를 내놓는 것이며 틀릴 수 있다 [S-102]

생성형 AI

정의(정확)

생성형 AI는 분류와 예측에 집중하던 전통적 AI를 넘어서는 유형의 AI로, 파운데이션 모델을 사용해 텍스트·이미지·오디오·영상 같은 새 콘텐츠를 생성한다. [S-105]

초보자 문장 (화면 노출 문장)

생성형 AI는 기존 자료를 분류하거나 다음 값을 예측하는 것을 넘어, 글·이미지·영상 같은 새로운 결과물을 직접 만들어내는 AI다.

비유①

생성형 AI는 냉장고 속 재료를 조합해 없던 요리를 만들어내는 셰프와 같다.매핑: A=셰프가 있는 재료를 조합해 새 요리를 만듦 · B=생성형 AI가 학습한 데이터 패턴을 조합해 새 글·이미지를 만듦오해 위험: 셰프가 완전히 무(無)에서 요리를 창조한다고 여기듯, 생성형 AI도 아무 근거 없이 완전히 새로 창작한다고 착각하기 쉽다 — 실제로는 학습 데이터의 패턴을 재조합·변형하는 것에 가깝다.

비유②

생성형 AI는 원본을 그대로 찍어내는 복사기가 아니라, 요청을 듣고 매번 새로 초안을 써주는 글쓰기 비서와 같다.매핑: A=비서가 매번 새로 문장을 구성해 초안을 씀 · B=생성형 AI도 저장된 데이터를 그대로 복사하지 않고 매번 새 문장·이미지를 구성함오해 위험: "AI가 인터넷에서 본 글을 그대로 복사해온다"는 오해는 바로잡히지만, 그렇다고 완전히 독창적이라고 과신해서도 안 된다 — 결과는 학습 데이터의 영향을 받는다.

  • "생성형 AI가 만든 글은 인터넷에서 그대로 복사해온 것이다" → 학습한 패턴을 참고해 매번 새로 문장을 구성하는 것이지 원문을 그대로 복사하지 않는다 [S-103]

[C-llm] 구간 1 유형: 개념 P0

LLM

정의(정확)

LLM(거대언어모델)은 방대한 데이터로 학습된 텍스트 기반 파운데이션 모델이다. [S-105] 언어 모델은 더 긴 토큰 시퀀스 안에서 하나의 토큰 또는 토큰 시퀀스가 나타날 확률을 추정하는 방식으로 동작한다. [S-104]

초보자 문장 (화면 노출 문장)

LLM(거대언어모델)은 엄청나게 많은 글을 미리 학습해서, 다음에 올 말(토큰)을 확률적으로 예측하며 문장을 만들어내는 AI다.

비유①

LLM은 재료와 순서를 글로 자세히 설명해주는 요리법 책과 같다.매핑: A=요리법 책이 말로 설명만 할 뿐 직접 요리하지 않음 · B=LLM이 다음에 올 말을 예측해 텍스트로 답할 뿐 파일을 열거나 실행하지 않음오해 위험: 요리법을 읽었으니 요리가 저절로 완성된다고 여기듯, LLM이 뭔가 실제로 '실행'까지 해준다고 착각하기 쉽다 — 실제로는 말(텍스트)만 만들고, 실행은 도구를 쓰는 에이전트의 몫이다.

비유②

LLM은 말로만 길을 알려주는 안내원과 같다.매핑: A=안내원이 "왼쪽으로 가서 두 번째 건물"이라고 말로만 알려줌 · B=LLM도 다음에 올 적절한 말(토큰)을 예측해 텍스트로 안내할 뿐임오해 위험: 안내원이 직접 데려다준다고 착각하듯, LLM이 직접 어떤 작업을 수행해준다고 여기기 쉽다 — 실제 수행은 도구를 쓰는 에이전트가 한다.

입력: "오늘 " → 처리: LLM이 학습한 수많은 문장 패턴에서 다음에 올 확률이 가장 높은 토큰을 차례로 예측("날씨가" → "좋네요" → ".") → 결과: "오늘 날씨가 좋네요."라는 문장이 완성됨. (창작, 원리는 [S-104] 기반)

흔한 오해 → 교정

  • "LLM은 답을 만드는 것을 넘어 알아서 실행까지 해준다" → LLM은 다음 토큰을 예측해 텍스트를 만들 뿐이고, 파일을 열고 고치는 실행은 도구를 쓰는 에이전트가 한다 [S-106]
verbatim

"A large language model (LLM) is a text-driven foundational model that's trained on a vast amount of data."
(한국어 요약: LLM은 방대한 데이터로 학습된 텍스트 기반 파운데이션 모델이다.)(S-105, 2026-07-18)

[C-토큰] 구간 1 유형: 개념 P1

토큰

정의(정확)

토큰은 파운데이션 모델이 처리하는 데이터의 기본 단위다. [S-105] 언어 모델링 관점에서는 토큰이 가장 작은 단위(원자 단위)로 취급된다. [S-104]

초보자 문장 (화면 노출 문장)

토큰은 AI가 글을 처리할 때 쪼개는 가장 작은 조각으로, 단어 전체일 수도 있고 단어의 일부나 글자 하나일 수도 있다.

비유①

토큰은 문장을 이루는 레고 블록과 같다.매핑: A=레고 블록 하나하나가 완성품의 최소 단위임 · B=토큰이 문장을 이루는 최소 단위임오해 위험: 레고 블록이 항상 같은 크기라고 여기듯 "토큰=한 단어"라고 오해하기 쉽다 — 실제로는 블록 크기가 제각각이라 글자 하나·단어 일부·단어 전체가 모두 토큰이 될 수 있다.

비유②

토큰은 김밥을 써는 조각 크기와 같다.매핑: A=같은 김밥이라도 써는 굵기에 따라 조각 수가 달라짐 · B=같은 문장도 토크나이저 방식에 따라 나뉘는 토큰 개수가 달라질 수 있음오해 위험: 김밥 한 재료가 항상 한 조각이라 여기듯 "토큰 하나=단어 하나"라고 단정하기 쉽다 — 실제로는 긴 단어 하나가 여러 토큰으로 쪼개지기도 한다.

비유①

HTML은 집의 구조(뼈대·방 배치)와 같다.매핑: A=뼈대와 방 배치가 "거실은 여기, 방은 저기"라는 공간의 의미와 구조를 정함 · B=HTML이 "제목은 여기, 문단은 저기"라는 콘텐츠의 의미와 구조를 정함오해 위험: 뼈대 공사를 하면서 동시에 벽지·조명까지 고른다고 여기듯, HTML을 쓰면서 색이나 디자인도 함께 정해진다고 착각하기 쉽다 — 실제로는 겉모습(표현)은 CSS의 몫으로 명확히 분리된다.

비유②

HTML은 책의 원고(글의 순서·목차·제목 구분)와 같다.매핑: A=원고가 "1장은 여기서 시작, 소제목은 여기"처럼 글의 뼈대를 정할 뿐 표지 디자인이나 종이 질감은 정하지 않음 · B=HTML이 "이 부분은 제목, 이 부분은 목록"처럼 콘텐츠 구조를 정할 뿐 색이나 폰트 꾸밈은 정하지 않음오해 위험: 원고만 봐도 완성된 책의 느낌을 알 수 있다고 여기듯, HTML 코드만 봐도 최종 화면의 디자인까지 짐작할 수 있다고 오해하기 쉽다 — 실제로는 같은 HTML도 다른 CSS를 입히면 완전히 다른 인상을 준다.

CSS

정의(정확)

CSS(Cascading Style Sheets)는 HTML(또는 XML)로 작성된 문서의 표현(presentation)을 기술하는 스타일시트 언어다. 화면·인쇄물·음성 등 다양한 매체에서 요소가 어떻게 렌더링될지를 CSS가 정한다. [S-204]

초보자 문장 (화면 노출 문장)

CSS는 이미 만들어진 내용(HTML) 위에 "어떻게 보이게 할지"를 입히는 도구다. 색·글자 크기·간격·배치처럼 눈에 보이는 꾸밈을 담당하고, 애초에 무슨 내용이 들어갈지는 정하지 않는다.

비유①

CSS는 인테리어(색·가구·배치)와 같다.매핑: A=인테리어가 이미 지어진 뼈대 위에 벽지 색·가구 배치·조명을 입혀 분위기를 바꿈 · B=CSS가 이미 만들어진 HTML 구조 위에 색·글자·간격을 입혀 화면 인상을 바꿈오해 위험: 인테리어 업체를 부르면 방 개수나 구조 자체도 새로 짜줄 거라 여기듯, CSS를 바꾸면 화면에 없던 내용(글·목록)까지 새로 생긴다고 착각하기 쉽다 — 실제로는 이미 있는 구조 위의 표현만 바뀌고, 내용을 새로 넣는 것은 HTML의 몫이다.

비유②

CSS는 같은 원고를 어떤 판형·서체로 인쇄할지 정하는 편집 디자인과 같다.매핑: A=같은 원고(글 내용)라도 편집 디자인에 따라 표지 색·글꼴·여백이 완전히 달라짐 · B=같은 HTML 구조라도 CSS에 따라 화면의 색·글꼴·배치가 완전히 달라짐오해 위험: 편집 디자인만 바꾸면 원고 내용 자체도 저절로 좋아진다고 여기듯, CSS만 화려하게 바꾸면 콘텐츠 구조의 허점(빠진 내용 등)도 같이 해결된다고 오해하기 쉽다 — 실제로는 CSS가 손대지 못하는 "무슨 내용이 있는지"는 HTML이 이미 정해놓은 대로다.

JavaScript

정의(정확)

JavaScript(JS)는 first-class 함수를 지원하는 가볍고 인터프리터 방식(또는 JIT 컴파일)의 프로그래밍 언어다. 웹페이지용 스크립팅 언어로 가장 잘 알려져 있지만 Node.js 같은 브라우저 밖 환경에서도 쓰인다. [S-205] HTML 정의 문서는 웹페이지의 겉모습·표현은 CSS가, 기능·동작은 JavaScript가 담당한다고 역할을 나눠 명시한다. [S-203]

초보자 문장 (화면 노출 문장)

JavaScript는 화면에 "움직임과 반응"을 더하는 역할이다. 버튼을 클릭했을 때 뭔가 바뀌거나, 입력한 값에 따라 화면이 달라지는 것처럼 사용자와 주고받는 동작을 담당한다. 1주차 자기소개 페이지는 JavaScript 없이 HTML·CSS만으로도 정상적으로 완성된 결과다.

비유①

JavaScript는 집 안의 움직이는 장치(스위치·자동문)와 같다.매핑: A=스위치·자동문이 사람이 누르거나 다가갈 때 반응해 불이 켜지고 문이 열림 · B=JavaScript가 사용자가 클릭하거나 입력할 때 반응해 화면이 바뀌거나 동작함오해 위험: 스위치나 자동문이 없으면 집이 아니라고 여기듯, JavaScript가 없으면 완성된 웹페이지가 아니라고 착각하기 쉽다 — 실제로는 뼈대(HTML)와 인테리어(CSS)만으로도 온전한 집이자 페이지다.

비유②

JavaScript는 이미 완성된 매장에 추가로 설치하는 무인 안내 키오스크와 같다.매핑: A=매장은 진열(구조)과 인테리어(표현)만으로도 영업이 가능하고, 키오스크는 손님이 버튼을 누르면 반응하는 추가 서비스임 · B=페이지는 HTML·CSS만으로도 완성되고, JavaScript는 사용자가 뭔가 할 때 반응하는 추가 상호작용임오해 위험: 키오스크가 매장의 핵심 설비라고 여기듯, JavaScript가 페이지의 필수 기반이라고 오해하기 쉽다 — 실제로는 콘텐츠(HTML)·표현(CSS) 위에 얹는 추가 기능이다.

공식 최소 완료 기준의 핵심은 페이지가 브라우저에서 열리고, 이름·한 줄 소개·관심사가 표시되며, 원하는 부분을 최소 한 번 수정한 상태다. [S-000] 1구간에서 오늘의 목표로 미리 제시되고 6구간에서 이 기준으로 최종 확인하는, 1주차 전체를 관통하는 목표다.
