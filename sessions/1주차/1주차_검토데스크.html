상세 근거 보기

고정 조건: 현재 폴더 바로 안에 단일 index.html, HTML+CSS 한 파일, 필요 시에만 JS 내장, 브라우저 직접 실행, 설치·빌드·서버 없음, React·프레임워크·DB·API 금지, 필수 콘텐츠 3종 포함. 동일 조건 요청문을 빈 폴더에서 ≥3회 반복해 생성 성공률·범위 이탈 유형을 실측한 뒤(실습3 [미검증]), 성공률이 가장 높은 표현을 1안으로, 이탈 방지 문구를 붙인 대안 1개를 병기합니다. 현재 초안 2-7의 완성 요청문이 후보 1안입니다.

반영됨

리서치가 외부 검증한 비유 3안 중 오해 위험이 낮은 것으로 이미 초안 1-6에 반영.

장점정확한 비유는 이해도를 높임
위험부정확한 비유는 오해를 고착시킴

상세 근거 보기 (비유 3종 전체)

① 요리법 설명 vs 실제 요리 — 오해 위험: 에이전트가 알아서 척척 판단한다고 과신(실제로는 정해진 루프대로 도구를 씀, 중간 확인 필요).
② 전화 상담원 vs 은행 창구 직원 — 오해 위험: 사람 수준의 책임·판단이 있다고 착각(승인 없이 맡기면 잘못된 작업도 그대로 실행).
③ 길안내 vs 대신 운전 — 오해 위험: 절대 실수하지 않는다고 믿기(엉뚱한 길·잘못된 파일 가능, 최종 확인은 여전히 사람).

4-2이제 진짜 내 페이지
연습은 끝. 이제 내 자기소개 페이지를 만듭니다.
2교시에서 쓴 요청문을 씁니다.
💬"드디어 본편입니다."
4-3실습 ⑤ 프로젝트 폴더 만들기
바탕화면에 새 영문 폴더를 만들어요.
(예: my-page-01)
👀폴더 만들고 Codex에서 여는 화면 캡처
4-4요청문 전달하기
그 폴더를 Codex에서 열고, 2교시 요청문을 전달합니다.
어떤 파일이 생기는지 지켜봐요.
막힐 때 힌트 보기

2-7의 완성 요청문(내 정보로 채운 것)을 그대로 사용

4-5index.html 찾기
폴더 안에 index.html이 생겼는지 탐색기로 확인합니다.
💬"AI가 '만들었어요' 해도, 눈으로 확인하는 게 우리 일이에요."
4-6브라우저로 열기
index.html을 더블클릭해 브라우저로 엽니다.
내 소개가 화면에 떴나요?
👀브라우저로 여는 조작을 캡처로 안내
4-7예상과 실제 비교
내가 기대한 내용과 실제 화면을 나란히 봅니다.
다르면, 그게 다음에 고칠 거리예요.
💬"이게 열렸으면 오늘 가장 큰 고비 넘긴 겁니다. 축하해요!"
4-8이 화면, 세 역할로 되어 있어요
HTML = 구조(무엇이 있는지)
CSS = 디자인(색·글자·배치)
JavaScript = 동작(클릭·변화)
💬"집으로 치면 HTML은 뼈대, CSS는 인테리어, JavaScript는 자동문. 문법은 안 배웁니다."
4-9한 파일이어도 정상
오늘은 셋을 한 파일(index.html)에 담습니다.
2주차부터 파일을 나눠요. 동작(JS) 없어도 정상!
4-10안 되면? 이 순서로
다른 폴더에 생겼나 / 여러 파일이 생겼나 / 빈 화면인가 —
현재 폴더 안에서 한 가지씩 다시 요청해 복구합니다.
막힐 때 힌트 보기

"파일이 여러 개 생겼는데, 지금 이 폴더 안에 index.html 한 파일로 합쳐 줘. 설치나 다른 도구 없이 브라우저로 바로 열리게."

💬"완성본으로 갈아끼우지 않습니다. 내 프로젝트를 살려요."
5-1간지
대화하며 내 페이지로 발전시키기
5-2첫 화면은 '출발점'
지금 화면은 끝이 아니라 출발점입니다.
여기서 내 취향대로 고쳐 나갑니다.
💬"AI가 준 첫 결과, 그대로 안 끝냅니다. 여기서부터가 진짜예요. AI가 고쳐줘도 — 됐는지 검토하고 완료를 결정하는 건 사람이고요."
5-3고칠 땐 세 가지 순서
① 유지할 것 → ② 바꿀 것 → ③ 바뀐 뒤 확인할 것
이 순서로 말하면 원하는 대로 바뀝니다.
5-4실습 ⑥ 문구 바꾸기
가장 쉬운 것부터 — 한 줄 소개 문구를 바꿔봐요.
막힐 때 힌트 보기

"배경은 그대로 두고, 한 줄 소개만 '천천히, 그러나 꾸준히'로 바꿔 줘. 바뀌면 브라우저에서 확인할게."

5-5색·글자도 바꿔보기
배경색이나 글자 크기도 한 번에 하나씩 바꿉니다.
막힐 때 힌트 보기 (색)

"다른 건 그대로 두고, 배경색만 연한 하늘색으로 바꿔 줘."

막힐 때 힌트 보기 (글자)

"다른 건 그대로 두고, 이름 글자만 조금 더 크게 키워 줘."

5-6한 번에 하나씩
여러 개를 한꺼번에 바꾸면 뭐가 바뀐지 몰라요.
하나 바꾸고 → 확인 → 다음.
💬"옷 수선처럼요. 소매만 줄이고 거울 보고, 그다음."
5-7수정 전후 확인
바꾼 뒤 브라우저를 새로고침해 전후를 비교합니다.
맘에 들면 유지, 아니면 다시.
👀새로고침 전후를 나란히 보여준다
5-8레퍼런스는 '복제'가 아니에요
맘에 드는 페이지가 있어도 그대로 베끼지 않습니다.
분위기·색·글자·여백·배치 특성만 뽑아 설명해요.
💬"'이거랑 똑같이'가 아니라 '이런 차분한 느낌으로'가 요령입니다."
5-9한 걸음 더선택
여유 있으면 두 번째 수정이나 간단한 버튼 하나를 더해봐요.
💬"안 해도 됩니다. 오늘 완주가 먼저예요."
6-1간지
확인·수정·다듬기와 1주차 정리
6-2오류는 당연한 과정
예상과 다른 결과가 나와도 실패가 아닙니다.
확인하고 고치면 되는, 협업의 한 과정이에요.
💬"오늘은 버그 잡기 수업이 아니라, 확인하고 다듬어 완성하는 수업입니다."
6-3이 셋을 구분해요
오류(작동 안 함) / 예상 차이(생각과 다름) / 취향 차이(그냥 마음에 안 듦)
대응이 다릅니다.
6-4문제는 '네 줄'로 설명
어디서 / 무엇을 했는데 / 실제로 어떻게 됐고 / 원래 뭘 기대했는지
💬"병원에서 증상 말하듯이요. '그냥 안 돼요'로는 못 고칩니다."
6-5그 전에 기본 확인부터
올바른 폴더인가 / 저장했나 / 새로고침했나
이 셋부터 확인하면 의외로 많이 풀려요.
💬"'저장'과 '새로고침', 오늘의 숨은 주인공입니다."
6-6문제 있으면 / 없으면
있으면: 네 줄로 정리해 한 가지만 다시 요청
없으면: 레퍼런스 보며 더 다듬기
👀문제 있는 수강생과 없는 수강생을 나눠 안내
6-7공개 전 최종 점검
개인정보 들어갔나 / 남의 저작물 그대로 썼나 / 사실이 맞나
최종 확인은 사람이 합니다.
💬"AI가 작성하고, 사람이 검토하고, 사람이 결정합니다 — 마지막까지요."
6-8오늘 완료 확인
① 브라우저에서 열린다 ② 내 내용이 보인다 ③ 최소 한 번 고쳤다
세 개면 오늘 성공!
💬"끝내는 시점은 사람이 정합니다. 오늘은 여기까지, 다음에 또 고치면 돼요."
6-9회고와 다음 주 예고
오늘 한 것: 요청 → 확인 → 수정.
다음 주: 내 아이디어를 기획서와 서비스(MVP)로.
💬"오늘 익힌 이 사이클, 3주 내내 씁니다."
6-10Self Review선택
원하면 AI에게 스스로 한 번 점검해 달라고 부탁해볼 수 있어요.

💬"사람이 마지막에 한 번 더 보는 건 그대로예요."
