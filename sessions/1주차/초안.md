| 1-10 | AI 할 일 / 내 할 일 | **AI:** 파일 만들기·고치기<br>**나:** 무엇을 만들지 정하고, 결과를 확인하고, 완료를 **결정**하기 | 💬 "AI가 작성하고, 사람이 검토하고, 사람이 결정합니다. 오늘 계속 나올 말이에요." |

# 2교시 · AI에게 제대로 요청하기

| # | 슬라이드 제목 | 본문 문구 | 비유·멘트 |
|---|---|---|---|
| 2-1 | (간지) 2교시 | **AI에게 제대로 요청하기** | |
| 2-2 | 프롬프트, 어렵지 않아요 | '프롬프트'는 그냥 **AI에게 주는 요청문**입니다.<br>길게 쓸 필요 없어요. | 💬 "시공사에 '방 세 개, 밝은 색으로' 적어주는 요구사항 메모랑 똑같아요." |
| 2-3 | 좋은 요청, 네 칸이면 돼요 | **① 할 일 ② 넣을 것 ③ 지킬 것 ④ 끝난 모습**<br>이 네 칸만 분명하면 좋은 요청입니다. | |
| 2-4 | 자기소개로 네 칸 채우기 | **할 일:** 내 소개 페이지<br>**넣을 것:** 이름·한 줄 소개·관심사 2~3개<br>**끝난 모습:** 브라우저로 열면 내 내용이 보임 | 👀 강사가 자기 예시로 네 칸을 채워 보인다 |
| 2-5 | "예쁘게"의 함정 | "그냥 예쁘게"는 **기준이 없어** 원하는 게 안 나옵니다.<br>대신 **무엇을·어떻게**를 적어요. | 💬 "미용실에서 '알아서 예쁘게요' 했다가 놀란 경험, 다들 있으시죠." |
| 2-6 | 개인정보는 넣지 않기 | 실제 전화번호·비공개 이메일은 **넣지 않습니다.**<br>공개해도 되는 정보나 연습용 문구만. | 💬 "화면에 올라갈 글이니까요. 안전하게 갑시다." |
| 2-7 | 실습 ① 첫 요청문 쓰기 | 이제 **네 칸을 내 정보로** 채워 첫 요청문을 만듭니다.<br>막히면 힌트를 열어보세요. | 🗣 요청문 예시: "내 소개 웹페이지를 만들어 줘. 넣을 것: 이름(홍길동), 한 줄 소개('배우는 걸 좋아하는 사람'), 관심사(등산·요리). 지킬 것: 지금 이 폴더 안에 index.html 한 파일로, HTML과 CSS는 그 안에 함께, 브라우저로 바로 열리게, 설치 없이. 끝난 모습: 브라우저로 열면 내 내용이 보이는 한 페이지." |
| 2-8 | 완료 기준을 미리 정하기 | **"열리고, 내 내용이 보이면 첫 성공"**<br>보기 전에 성공 기준을 정해두면 흔들리지 않아요. | 💬 "AI가 만들어도, 됐다/아니다는 사람이 정합니다." |
| 2-9 | (선택) 분위기 키워드 | 원하면 분위기 한두 개만 메모해 두세요.<br>(예: 차분한 · 밝은 · 깔끔한) | 💬 "지금은 안 넣어도 돼요. 5교시에서 씁니다." |

# 3교시 · Codex로 폴더·파일·권한 익히기

| # | 슬라이드 제목 | 본문 문구 | 비유·멘트 |
|---|---|---|---|
| 3-1 | (간지) 3교시 | **Codex로 폴더·파일·권한 익히기** | |
| 3-2 | Codex가 하는 일 | Codex는 **내 컴퓨터의 폴더를 열어**, 그 안 파일을 만들고 고칩니다.<br>먼저 작은 연습부터 해봐요. | 💬 "실전 전에 몸풀기 한 번. 부담 없이." |
| 3-3 | 폴더와 파일 | **폴더 = 작업하는 범위**(서류철)<br>**파일 = 결과물**(서류 한 장) | 💬 "Codex는 우리가 '열어준 서류철' 안에서 일합니다." |
| 3-4 | 실습 ② 연습 폴더 만들기 | 바탕화면에 **영문 이름 폴더**를 하나 만듭니다.<br>(예: codex-practice) | 👀 폴더 만드는 화면을 캡처로 안내 💬 "한글·띄어쓰기 폴더는 나중에 헷갈려요. 영문이 편합니다." |
| 3-5 | Codex에서 그 폴더 열기 | 만든 폴더를 **Codex에서 엽니다.**<br>이제 Codex의 작업 범위가 그 폴더예요. | 👀 Codex에서 폴더 여는 조작을 한 단계씩 캡처로 |
| 3-6 | 실습 ③ 작은 파일 만들기 | Codex에게 **간단한 메모 파일 하나**를 만들어 달라고 해요.<br>그다음 **탐색기에서 진짜 생겼는지** 확인합니다. | 🗣 요청문 예시: "지금 이 폴더에 memo.txt 파일을 만들고, 첫 줄에 '코덱스 첫 연습'이라고 써 줘." 💬 "AI 답만 믿지 말고 폴더를 직접 열어 확인하세요." |
| 3-7 | 실습 ④ 한 줄 고치기 | 방금 그 문장을 **한 줄만** 바꿔 달라고 해봐요.<br>바뀌었는지 다시 확인합니다. | 🗣 요청문 예시: "memo.txt의 그 문장을 '코덱스랑 친해지는 중'으로 바꿔 줘." |
| 3-8 | 지금 이 대화가 '컨텍스트' | AI는 **지금까지의 대화와 열어둔 파일**을 참고해 일합니다. 이걸 컨텍스트라고 해요.<br>그래서 **중요한 조건은 다시 짚어주는 게** 도움이 됩니다. | 💬 "책상에 자료를 잔뜩 펼쳐두면, 중요한 건 다시 짚어줘야 하는 것처럼요." |
| 3-9 | 허용창이 뜨면? | Codex는 **폴더 안 작업은 알아서**, **폴더 밖·인터넷은 물어봅니다.**<br>모르면 승인하지 말고 강사에게 확인하세요. | 💬 "이게 바로 '권한'을 판단하는 거예요. 네 가지만 자문: 이 폴더 안인가 / 내가 시킨 일인가 / 뭘 하려는지 아는가 / 모르면 멈췄는가." |
| 3-10 | (선택) 메모리 | AI가 **모든 걸 영구히 기억하진 않습니다.**<br>기억하는 기능이 있어도, 다 기억하는 건 아니에요. | 💬 "'아까 말했잖아요'가 늘 통하진 않는 이유입니다." |

| 4-6 | 브라우저로 열기 | index.html을 **더블클릭해 브라우저로** 엽니다.<br>내 소개가 화면에 떴나요? | 👀 브라우저로 여는 조작을 캡처로 안내 |
| 4-7 | 예상과 실제 비교 | 내가 **기대한 내용**과 **실제 화면**을 나란히 봅니다.<br>다르면, 그게 다음에 고칠 거리예요. | 💬 "이게 열렸으면 오늘 가장 큰 고비 넘긴 겁니다. 축하해요!" |
| 4-8 | 이 화면, 세 역할로 되어 있어요 | **HTML = 구조**(무엇이 있는지)<br>**CSS = 디자인**(색·글자·배치)<br>**JavaScript = 동작**(클릭·변화) | 💬 "집으로 치면 HTML은 뼈대, CSS는 인테리어, JavaScript는 자동문. 문법은 안 배웁니다." |
| 4-9 | 한 파일이어도 정상 | 오늘은 **셋을 한 파일(index.html)**에 담습니다.<br>2주차부터 파일을 나눠요. 동작(JS) 없어도 정상! | |
| 4-10 | 안 되면? 이 순서로 | 다른 폴더에 생겼나 / 여러 파일이 생겼나 / 빈 화면인가 —<br>**현재 폴더 안에서 한 가지씩** 다시 요청해 복구합니다. | 🗣 복구 요청 예시: "파일이 여러 개 생겼는데, 지금 이 폴더 안에 index.html 한 파일로 합쳐 줘. 설치나 다른 도구 없이 브라우저로 바로 열리게." 💬 "완성본으로 갈아끼우지 않습니다. 내 프로젝트를 살려요." |

|---|---|---|---|
| 5-1 | (간지) 5교시 | **대화하며 내 페이지로 발전시키기** | |
| 5-2 | 첫 화면은 '출발점' | 지금 화면은 끝이 아니라 **출발점**입니다.<br>여기서 내 취향대로 **고쳐** 나갑니다. | 💬 "AI가 준 첫 결과, 그대로 안 끝냅니다. 여기서부터가 진짜예요. AI가 고쳐줘도 — 됐는지 검토하고 완료를 결정하는 건 사람이고요." |
| 5-3 | 고칠 땐 세 가지 순서 | **① 유지할 것 → ② 바꿀 것 → ③ 바뀐 뒤 확인할 것**<br>이 순서로 말하면 원하는 대로 바뀝니다. | |
| 5-4 | 실습 ⑥ 문구 바꾸기 | 가장 쉬운 것부터 — **한 줄 소개 문구**를 바꿔봐요. | 🗣 요청문 예시: "배경은 그대로 두고, 한 줄 소개만 '천천히, 그러나 꾸준히'로 바꿔 줘. 바뀌면 브라우저에서 확인할게." |
| 5-5 | 색·글자도 바꿔보기 | 배경색이나 글자 크기도 한 번에 **하나씩** 바꿉니다. | 🗣 요청문 예시(색): "다른 건 그대로 두고, 배경색만 연한 하늘색으로 바꿔 줘." 🗣 요청문 예시(글자): "다른 건 그대로 두고, 이름 글자만 조금 더 크게 키워 줘." |
| 5-6 | 한 번에 하나씩 | 여러 개를 한꺼번에 바꾸면 **뭐가 바뀐지 몰라요.**<br>하나 바꾸고 → 확인 → 다음. | 💬 "옷 수선처럼요. 소매만 줄이고 거울 보고, 그다음." |
| 5-7 | 수정 전후 확인 | 바꾼 뒤 **브라우저를 새로고침**해 전후를 비교합니다.<br>맘에 들면 유지, 아니면 다시. | 👀 새로고침 전후를 나란히 보여준다 |
| 5-8 | 레퍼런스는 '복제'가 아니에요 | 맘에 드는 페이지가 있어도 **그대로 베끼지 않습니다.**<br>**분위기·색·글자·여백·배치** 특성만 뽑아 설명해요. | 💬 "'이거랑 똑같이'가 아니라 '이런 차분한 느낌으로'가 요령입니다." |
| 5-9 | (선택) 한 걸음 더 | 여유 있으면 두 번째 수정이나 **간단한 버튼** 하나를 더해봐요. | 💬 "안 해도 됩니다. 오늘 완주가 먼저예요." |

# 6교시 · 확인·수정·다듬기와 1주차 정리

| # | 슬라이드 제목 | 본문 문구 | 비유·멘트 |
|---|---|---|---|
| 6-1 | (간지) 6교시 | **확인·수정·다듬기와 1주차 정리** | |
| 6-2 | 오류는 당연한 과정 | 예상과 다른 결과가 나와도 **실패가 아닙니다.**<br>확인하고 고치면 되는, 협업의 한 과정이에요. | 💬 "오늘은 버그 잡기 수업이 아니라, 확인하고 다듬어 완성하는 수업입니다." |
| 6-3 | 이 셋을 구분해요 | **오류**(작동 안 함) / **예상 차이**(생각과 다름) / **취향 차이**(그냥 마음에 안 듦)<br>대응이 다릅니다. | |
| 6-4 | 문제는 '네 줄'로 설명 | **어디서 / 무엇을 했는데 / 실제로 어떻게 됐고 / 원래 뭘 기대했는지** | 💬 "병원에서 증상 말하듯이요. '그냥 안 돼요'로는 못 고칩니다." |
| 6-5 | 그 전에 기본 확인부터 | 올바른 폴더인가 / 저장했나 / **새로고침**했나<br>이 셋부터 확인하면 의외로 많이 풀려요. | 💬 "'저장'과 '새로고침', 오늘의 숨은 주인공입니다." |
| 6-6 | 문제 있으면 / 없으면 | **있으면:** 네 줄로 정리해 **한 가지만** 다시 요청<br>**없으면:** 레퍼런스 보며 더 다듬기 | 👀 문제 있는 수강생과 없는 수강생을 나눠 안내 |
| 6-7 | 공개 전 최종 점검 | 개인정보 들어갔나 / 남의 저작물 그대로 썼나 / 사실이 맞나<br>**최종 확인은 사람이** 합니다. | 💬 "AI가 작성하고, 사람이 검토하고, 사람이 결정합니다 — 마지막까지요." |
| 6-8 | 오늘 완료 확인 | **① 브라우저에서 열린다 ② 내 내용이 보인다 ③ 최소 한 번 고쳤다**<br>세 개면 오늘 성공! | 💬 "끝내는 시점은 사람이 정합니다. 오늘은 여기까지, 다음에 또 고치면 돼요." |
| 6-9 | 회고와 다음 주 예고 | 오늘 한 것: **요청 → 확인 → 수정.**<br>다음 주: 내 **아이디어를 기획서와 서비스(MVP)**로. | 💬 "오늘 익힌 이 사이클, 3주 내내 씁니다." |
| 6-10 | (선택) Self Review | 원하면 AI에게 **스스로 한 번 점검해 달라**고 부탁해볼 수 있어요. | 🗣 요청문 예시: "내가 처음에 말한 조건(단일 index.html·필수 내용 3가지)을 다 지켰는지, 빠뜨린 게 있는지 스스로 점검해서 알려 줘." 💬 "사람이 마지막에 한 번 더 보는 건 그대로예요." |
